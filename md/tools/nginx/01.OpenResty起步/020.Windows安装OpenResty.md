# 概述

OpenResty **没有官方原生 Windows 二进制**——自始至今作者只发布 Linux、macOS、FreeBSD 的包与源码。在 Windows 上跑 OpenResty，本质上是选一个能跑 Linux ELF 的宿主：**WSL2**（与生产环境一致，推荐日常开发）、**Docker Desktop**（隔离干净，CI/CD 一致）、或退而求其次的 **MSYS2/Cygwin 源码编译**（不推荐，性能差、坑多）。

三条路线取舍：

| 路线 | 版本新鲜度 | 与生产一致性 | 上手成本 | 适用 |
|------|-----------|-------------|---------|------|
| WSL2 内按 [030.Ubuntu 安装](./030.Ubuntu安装OpenResty.md) | 跟随官方 APT | **最高**（真 Linux 内核） | 中（首次装 WSL 要重启） | 日常开发首选 |
| Docker Desktop | 跟随官方镜像 | 高（Linux 容器） | 低 | 快速试验 / CI 一致 |
| MSYS2/MinGW 源码编译 | 手动 | 低（Win32 API，epoll→IOCP 语义差） | 高 | 必须原生服务形态的极端场景 |

> [!warning]
> GitHub 上一些"OpenResty-Windows"第三方仓库本质是 Cygwin 移植，版本滞后、`epoll` 语义缺失、cosocket 部分能力受限，**不要用于生产**。

# 操作步骤

## 路线 A：WSL2 + Ubuntu（推荐）

```powershell
# 1) 启用 WSL2 并安装 Ubuntu 24.04（管理员 PowerShell）
wsl --install -d Ubuntu-24.04

# 2) 进入 WSL 后，直接执行 030 章的 apt 流程即可
wsl -d Ubuntu-24.04
```

WSL 内：

```bash
# 见 030.Ubuntu安装OpenResty.md 第 1-4 步
curl -fsSL https://openresty.org/package/pubkey.gpg | sudo gpg --dearmor -o /usr/share/keyrings/openresty.gpg
echo "deb [signed-by=/usr/share/keyrings/openresty.gpg] http://openresty.org/package/ubuntu $(lsb_release -sc) main" \
  | sudo tee /etc/apt/sources.list.d/openresty.list
sudo apt update && sudo apt install -y openresty
openresty -v          # nginx version: openresty/1.31.8.1
```

Windows 侧浏览器打开 `http://localhost/` 就能看到默认页——WSL2 的 `localhost` 会自动转发。

## 路线 B：Docker Desktop

```powershell
# 拉取匹配版本的镜像（jammy = Ubuntu 22.04 基底，还有 noble/alpine/bookworm 变体）
docker pull openresty/openresty:1.31.8.1-jammy

# 起一个映射 8080 端口的容器
docker run -d --name ors -p 8080:80 openresty/openresty:1.31.8.1-jammy

# 进容器改配置
docker exec -it ors bash
```

浏览器访问 `http://localhost:8080/`。详细镜像 tag 与挂载见 [040.Docker 运行 OpenResty](./040.Docker运行OpenResty.md)。

## 路线 C：MSYS2 源码编译（可选）

只在**必须原生 Windows 服务**时才走。核心步骤：

```powershell
# 1) 装 MSYS2 + 开发工具
pacman -S mingw-w64-x86_64-gcc make pcre2 zlib openssl

# 2) 下载 openresty-1.31.8.1.tar.gz 并解压
wget https://openresty.org/download/openresty-1.31.8.1.tar.gz
tar xzf openresty-1.31.8.1.tar.gz
cd openresty-1.31.8.1

# 3) 配置时手工指定依赖路径
./configure --prefix=C:/openresty --with-openssl=C:/msys64/mingw64 \
            --with-pcre-jit --with-http_ssl_module

# 4) 编译（gmake 而非 make）
gmake -j4
gmake install
```

编译过程会踩一堆坑：`ngx_epoll_module` 需要 disable、`ngx_eventport` 需要屏蔽、部分 `lua-resty-*` 里的 `posix` 依赖会缺失；社区维护案例已很少，出问题基本靠自救。**能选 WSL2/Docker 就不要选这条路。**

# 验证

任选一条路线后，以下三项要都过：

```powershell
# 1) 版本正确
openresty -v
# 期望：nginx version: openresty/1.31.8.1

# 2) 配置能加载
openresty -t
# 期望：nginx: the configuration file ... syntax is ok / test is successful

# 3) HTTP 200
curl.exe http://localhost/       # Windows 自带 curl
# 或 WSL 内 curl http://localhost/
```

Windows 服务视角的验证：WSL2/Docker 都是**宿主进程**（`vmmem` / `com.docker.backend`），Windows 服务列表里看不到 `nginx` 才对——看到说明你走的是路线 C。

# 避坑

- **WSL2 里 `sudo service openresty start` 报"System has not been booted with systemd"**：Ubuntu WSL 默认没 systemd；`wsl --shutdown` 后在 `/etc/wsl.conf` 加 `[boot] systemd=true` 再重启 WSL；或直接 `openresty`（前台）+ `openresty -s reload`（信号）。
- **`localhost` 打不开**：Windows 防火墙拦了 WSL 端口转发，或 WSL2 用了 NAT 模式且 IPv6 优先。用 `wslconfig` 设 `networkingMode=mirrored`（Win11 23H2+ 支持）可解。
- **文件放 `/mnt/c/` 极慢**：WSL2 跨系统 I/O 走 9P，`nginx.conf` 与 Lua 文件请放 WSL 原生文件系统（`~/ors/`）；生产部署也是 Linux 原生路径。
- **Docker Desktop 商用许可**：大型企业（>250 人 或 >1000 万美元年营收）商用需要付费订阅；替代方案是 Rancher Desktop / Podman Desktop，都能直接跑 `openresty/openresty` 镜像。
- **端口冲突**：Windows 上 IIS 或 Hyper-V 会占 80/443；`netstat -ano | findstr :80` 找到 PID 后要么停服务要么改 `-p 8080:80`。
- **MSYS2 编译不要走 Cygwin 分支**：Cygwin 的 POSIX 层会让 Nginx 的性能与稳定性都打折，社区基本已弃；MSYS2 的 `mingw-w64-x86_64-*` 才是可用路径。

# 总结

Windows 上跑 OpenResty，绝大多数场景应该选 **WSL2 + Ubuntu 流程**——它是"最像生产环境"的开发形态，`cosocket`、`shared dict`、`timer` 全部一致；跑不了 WSL（如公司禁止）就退到 **Docker Desktop**；只有真的必须"原生 Windows 服务"（如工控机上没法装 Docker）才走 MSYS2 源码编译，且要为后续维护付双倍代价。装完之后统一走 `-v / -t / curl` 三连验证，再进 [050.目录结构与配置文件](./050.目录结构与配置文件.md)。
