# 概述

Nginx 处理一个请求要穿过一系列**阶段（phase）**，`ngx_http_lua_module` 在**每个关键阶段都埋了 Lua 挂点**。理解这些挂点等于理解 OpenResty 的编程模型——什么逻辑该写在哪、哪些 API 在哪些阶段可用、哪些阶段禁止 IO。本文给出完整的阶段地图 + 每个挂点的典型用法 + 一张可用性矩阵。

# 阶段总览

HTTP 请求（`http{}`）生命周期，按处理顺序：

```
        ┌────────────────────────────────────────────────────────────┐
        │                     master 启动                            │
        │  init_by_lua_block        (config 加载时跑一次)             │
        │  init_worker_by_lua_block (每个 worker 启动各跑一次)         │
        └────────────────────────────────────────────────────────────┘
                                    │
   每个请求 ─────────────────────────┼────────────────────────────
                                    ▼
        ┌────────────────────────────────────────────────────────────┐
        │ 1. POST_READ     ngx.timer 常见挂载点，很少用 lua           │
        │ 2. rewrite       rewrite_by_lua_block / _file              │
        │ 3. preaccess    （一般给 access 模块）                      │
        │ 4. access        access_by_lua_block / _file               │
        │ 5. content       content_by_lua_block / _file              │
        │                  （也可 proxy_pass / fastcgi_pass）         │
        ├────────────────────────────────────────────────────────────┤
        │ 响应过滤阶段（每个 filter chunk 都会跑）：                   │
        │ 6. header_filter  header_filter_by_lua_block / _file       │
        │ 7. body_filter    body_filter_by_lua_block / _file         │
        ├────────────────────────────────────────────────────────────┤
        │ 8. log            log_by_lua_block / _file                 │
        └────────────────────────────────────────────────────────────┘

   与请求并行、独立触发的：
   ├─ balancer_by_lua_block         upstream 选机器前，每次尝试都跑
   ├─ ssl_certificate_by_lua_block  TLS 握手时动态加载证书
   ├─ ssl_session_fetch/store       会话票证的动态读写
   ├─ set_by_lua_block              同步、表达式风格、给变量赋值
   └─ ngx.timer.*                   任意阶段创建异步定时器
```

## 各挂点职责与红线

| 挂点 | 阶段 | 典型用法 | 能做什么 | 不能做什么 |
|-----|------|---------|---------|-----------|
| `set_by_lua_*` | rewrite | 变量派生 | 同步、纯计算、返回字符串 | **禁止** IO / `ngx.sleep` / `cosocket`（阻塞 worker） |
| `rewrite_by_lua_*` | rewrite | URL 改写、请求头预处理、鉴权前置 | 全部 Lua API，可发子请求、`ngx.exec`、`ngx.redirect` | 别在这里输出响应体（除非 `ngx.say`+`ngx.exit`） |
| `access_by_lua_*` | access | JWT 校验、限流、灰度分流、路由决策 | 同上；`ngx.exit(403)` 就中断 | 别做重活，会拖慢 `proxy_pass` 首字节 |
| `content_by_lua_*` | content | 自己产出响应（`ngx.say`、`cjson.encode`） | 完整 API | 与 `proxy_pass` / `fastcgi_pass` 互斥 |
| `header_filter_by_lua_*` | 响应过滤 | 加/改/删响应头（CORS、Set-Cookie 改写） | 只改 `ngx.resp.*` / `ngx.header.*` | **禁止** IO / `cosocket` / `ngx.timer`；只能改 header 不能改 body |
| `body_filter_by_lua_*` | 响应过滤 | 响应体切片改写（如注入水印、模板变量替换） | `ngx.arg[1]` 是当前 chunk；`ngx.arg[2]` 标记最后一片 | **禁止** IO；对性能极敏感，慎用大字符串拼接 |
| `log_by_lua_*` | log | 埋点、异步上报、错误统计 | 可以 `ngx.timer.at(0, ...)` 甩异步 | **禁止** `ngx.say` / `cosocket`（响应已发出） |
| `balancer_by_lua_*` | upstream | 动态选后端（服务发现、加权、熔断） | `balancer.set_current_peer(host, port)` | 只能改 peer，不能改请求内容 |
| `ssl_certificate_by_lua_*` | TLS 握手 | 从 etcd/Redis 动态取证书、SNI 分流 | `ssl.set_der_cert`、`ssl.set_ciphers` | 只在 `listen 443 ssl` 上有效 |
| `init_by_lua_*` | master 加载 config | 一次性初始化全局表、加载库 | 只做纯计算与 `require` | **禁止** IO / `cosocket` / `ngx.timer`（此时 worker 还没起） |
| `init_worker_by_lua_*` | 每个 worker 启动 | 注册 timer、订阅 Redis、启动后台心跳 | 完整 API 除 content | 别做长时阻塞，会拖 worker 就绪 |

## 四层 stream（`stream{}`）

`stream_lua_module` 提供对称的一整套挂点，只是没有 header_filter/body_filter：

| 挂点 | 阶段 | 用途 |
|-----|------|------|
| `preread_by_lua_block` | 拿到首包后 | sniffing 协议、SNI 分流 |
| `access_by_lua_block` | 建连时 | 白名单、鉴权 |
| `content_by_lua_block` | 建立 socket 后 | 完全接管 TCP/UDP（例：Memcached 前置代理，见 03 章 100） |
| `balancer_by_lua_block` | upstream 选机器 | 服务发现 |
| `ssl_certificate_by_lua_block` | TLS 握手 | 四层证书动态签发 |
| `log_by_lua_block` | 断连时 | 会话统计 |

## 一次典型请求的路径

以「API 网关转发」为例，各阶段做了什么：

```
Client ──HTTP──▶
  init_by_lua          (启动时) 加载路由表到 shared dict
  init_worker_by_lua   (每 worker) 注册 5s timer 拉取配置
  rewrite_by_lua       读取 $uri，标准化路径（去尾斜杠）
  access_by_lua        JWT 校验 + 限流（shared dict 令牌桶）
  balancer_by_lua      根据 host 从服务发现表里挑一个上游
  proxy_pass           转发到上游（不由 Lua 处理）
  header_filter_by_lua 加 X-Gateway: openresty/1.31.8.1
  body_filter_by_lua   (可选) 注入 trace id
  log_by_lua           异步上报 metric（timer 里发 UDP）
◀── Response ── Client
```

**记忆要点**：**读**在 `rewrite/access`、**写**在 `content/*_filter`、**观测**在 `log`、**外围**（TLS/上游/timer）在独立挂点。

# 常用配套 API

- `ngx.ctx`：**当前请求独占**的 Lua 表，跨同一请求的多个挂点。生命周期到 log 阶段结束，**不跨 worker、不跨请求**。
- `ngx.var.xxx`：读写 Nginx 变量；写变量前要在 `nginx.conf` 声明 `set $my_var '';`。
- `ngx.on_abort(...)`：注册客户端断连回调，配合 `ngx.thread.spawn` 处理长任务取消。
- `ngx.thread.spawn/wait/kill`：同一请求内并行发多路 cosocket（详见 03 章 cosocket 篇）。
- `ngx.timer.at(delay, handler, ...) / ngx.timer.every(interval, handler)`：**fire-and-forget** 后台任务，不能读写请求，但能读 `ngx.shared.DICT`。

# 阶段与 API 可用性矩阵

| API | set | rewrite | access | content | header_f | body_f | log | balancer | ssl_cert | init | init_worker | timer |
|-----|-----|---------|--------|---------|----------|--------|-----|----------|----------|------|-------------|-------|
| `ngx.say/print` | ❌ | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| `ngx.exit` | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ |
| `cosocket` (tcp/udp) | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ | ✅ | ✅ |
| `ngx.timer.at` | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ | ✅ | ✅ |
| `subrequest` (`ngx.location.capture`) | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| `ngx.exec` / `ngx.redirect` | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 读 `ngx.req.get_body_data` | ❌ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 写 `ngx.header` | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| `require "resty.*"` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

**记不住就抓三条红线**：
1. `set_by_lua_*` 与 `init_by_lua_*` **纯计算**，任何 IO 都会拖死 worker。
2. `header_filter` / `body_filter` / `log` **禁止** `cosocket` 与 `timer.at(0)` 之外的同步操作。
3. `ngx.say / ngx.exit / ngx.exec / ngx.redirect` **只在请求阶段（rewrite/access/content）可用**。

# 操作步骤：亲手验证阶段

## 1) 在挂点里打日志

```nginx
server {
    listen 8080;

    set_by_lua_block $who { return "rafeng" }

    rewrite_by_lua_block { ngx.log(ngx.WARN, "1-rewrite") }
    access_by_lua_block  { ngx.log(ngx.WARN, "2-access") }
    content_by_lua_block { ngx.log(ngx.WARN, "3-content"); ngx.say("hi ", ngx.var.who) }
    header_filter_by_lua_block { ngx.log(ngx.WARN, "4-header_filter") }
    body_filter_by_lua_block   { ngx.log(ngx.WARN, "5-body_filter") }
    log_by_lua_block           { ngx.log(ngx.WARN, "6-log") }
}
```

```bash
sudo openresty -s reload
curl -s http://localhost:8080/ > /dev/null
sudo grep -E '^[0-9]+.* (1-rewrite|2-access|3-content|4-header_filter|5-body_filter|6-log)' \
    /usr/local/openresty/nginx/logs/error.log | tail -20
```

看到数字顺序 1→6 就是阶段顺序的直接印证。

## 2) 用 `ngx.ctx` 跨挂点传数据

```lua
-- rewrite_by_lua_block
ngx.ctx.trace_id = ngx.var.request_id or ngx.now()

-- log_by_lua_block
ngx.log(ngx.INFO, "trace=", ngx.ctx.trace_id, " status=", ngx.status)
```

`ngx.ctx` 只在同一请求内跨挂点存活，请求结束就丢。要跨请求请走 `lua_shared_dict`。

# 避坑

- **在 `header_filter_by_lua_block` 里调 `ngx.timer`**：官方文档明确禁用，运行时抛 `API disabled in the context of header_filter_by_lua*`——这不是配置错，是阶段限制。
- **在 `access_by_lua_*` 里 `proxy_pass`**：`proxy_pass` 会接管 content 阶段，`access_by_lua_*` 只是**决策者**；正确姿势是 access 里判完 → 让 nginx 的 proxy 走 content。
- **`body_filter_by_lua_*` 里字符串拼接**：每 chunk 一次 concat，大响应会内存爆表；用 `table.concat` 或流式处理。
- **`log_by_lua_*` 里同步 HTTP 上报**：这里请求已经发完，同步 cosocket 会**拖住连接回收**；一定要异步 → `ngx.timer.at(0, function() ... end)`。
- **`init_by_lua_block` 里做远程调用**：master 阶段 worker 未起，`cosocket` 直接抛错；配置拉取放 `init_worker_by_lua_block` + `ngx.timer.every`。
- **`_by_lua_block` 内花括号解析**：nginx 用简单的 brace-matching 找块边界，字符串里的 `{` `}` 会被误算；有复杂逻辑就切 `_by_lua_file`。
- **一个 location 里出现两次同阶段挂点**：nginx 会抛 `directive is duplicate`；要串联多段逻辑，抽到一个 `.lua` 里按顺序调用。

# 总结

**阶段是骨架，挂点是接口**。OpenResty 的学习曲线一大半是"每个阶段能干什么、不能干什么"这张地图；把上表打印贴在工位上，剩下的都是熟练度。写完业务前先问三个问题：这段逻辑在哪个阶段？需要 IO 吗？能异步走 timer 吗？答案对上，代码位置就对了。下一步看 [080.包管理 opm 与 luarocks](./080.包管理opm与luarocks.md)，把 `lua-resty-*` 生态接进来。
