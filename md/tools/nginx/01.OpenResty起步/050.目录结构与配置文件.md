# 概述

OpenResty 的安装位置由 **prefix**（默认 `/usr/local/openresty/`）统一决定，与 apt 装的裸 Nginx（`/etc/nginx` + `/usr/sbin/nginx`）完全不同。搞混这两套路径是新手踩坑 Top 3；本文一次讲清楚：装在哪、配置文件从哪读、Lua 库放哪、日志在哪、`conf.d` 拆分怎么写。

# 标准目录树

以 Ubuntu APT 装的 **1.31.8.1** 为例，装完后的目录：

```
/usr/local/openresty/
├── bin/
│   ├── openresty                # ★ 主启动器（推荐入口，脚本转发到 nginx）
│   ├── opm                      # OpenResty 包管理器
│   ├── resty                    # 独立 Lua 解释器 CLI（脱离 nginx 跑脚本）
│   ├── restydoc                 # 本地查询模块文档
│   ├── nginx                    # 与 openresty 等价的 nginx 二进制
│   ├── luajit                   # OpenResty 版 LuaJIT 2.1 解释器
│   └── ngx_openresty            # 别名，历史遗留
├── nginx/
│   ├── conf/                    # ★ 配置目录（默认 prefix）
│   │   ├── nginx.conf           # ★ 主配置
│   │   ├── mime.types           # content-type 映射表
│   │   ├── fastcgi_params / uwsgi_params / scgi_params
│   │   ├── win-utf              # Windows 编码映射（Linux 下也用）
│   │   ├── koi-utf / koi-win
│   │   └── conf.d/              # 可选拆分目录（官方包默认不含，自己 include）
│   ├── html/
│   │   └── 50x.html             # 默认静态目录
│   ├── logs/                    # ★ 运行期日志
│   │   ├── access.log
│   │   ├── error.log
│   │   └── nginx.pid            # master PID
│   └── sbin/
│       └── nginx                # 真正的 nginx 二进制
├── lualib/                      # ★ Lua 库搜索根（默认 lua_package_path 覆盖）
│   ├── cjson.so / lzlib.so / ...
│   ├── bit/  jit/  ngx/  resty/ # 系统库
│   └── app/                     # 你的业务 Lua（约定，非官方）
├── luajit/
│   ├── bin/luajit
│   ├── include/luajit-2.1/
│   └── lib/
├── pod/                         # 各模块的 perldoc 手册，restydoc 用它
└── COPYING                      # BSD 2-clause
```

- **只有 `/usr/local/openresty/nginx/conf/` 会被 nginx 读**——不要往 `/etc/nginx/` 或 `/etc/openresty/` 扔配置，那是 apt 裸 nginx 或某些第三方包的路径。
- **`bin/openresty` vs `nginx/sbin/nginx`**：前者是 shell wrapper，加了 `daemon off` 与 signal 转发的便利；后者是真正的 nginx ELF。生产脚本推荐统一走 `openresty` 命令。
- **`lualib/app/`**：官方没定义业务代码放哪，社区惯例是 `lualib/app/` 或 `lualib/site/`，通过 `lua_package_path` 挂上。

# 主配置骨架（`nginx.conf`）

官方 APT 包安装后 `/usr/local/openresty/nginx/conf/nginx.conf` 的默认内容大致如下，本系列后续示例都基于它扩展：

```nginx
user  nginx;
worker_processes  auto;

error_log  logs/error.log  warn;
pid        logs/nginx.pid;

# 单个 worker 打开的最大 fd 上限
worker_rlimit_nofile 65535;

# 事件模型
events {
    worker_connections  10240;
    multi_accept on;
    use epoll;
}

http {
    ## 基础 ##
    include       mime.types;
    default_type  application/octet-stream;
    server_tokens off;               # 隐藏版本号

    ## 日志格式 ##
    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for" '
                      'rt=$request_time urt=$upstream_response_time';
    access_log  logs/access.log  main;

    ## 传输优化 ##
    sendfile        on;
    tcp_nopush      on;
    tcp_nodelay     on;
    keepalive_timeout  65;
    gzip  on;

    ## Lua 环境（OpenResty 特有） ##
    lua_package_path  "$prefix/lualib/?.lua;;";
    lua_package_cpath "$prefix/lualib/?.so;;";
    lua_code_cache    on;                    # 生产必须 on
    init_by_lua_block {
        require "resty.core"                 # 启用 FFI 版 API
        -- 全局共享表
        _ENV.APP = { version = "1.31.8.1" }
    }
    init_worker_by_lua_block {
        -- 每个 worker 启动时跑一次
        ngx.log(ngx.INFO, "worker ", ngx.worker.pid(), " booted")
    }

    ## 共享内存 ##
    lua_shared_dict locks    1m;
    lua_shared_dict api_cache 20m;

    ## 站点拆到 conf.d/，方便 git 管理 ##
    include conf.d/*.conf;
}

stream {
    # 四层代理入口，见 03 章 100 篇
    include stream.conf.d/*.conf;
}
```

要点：

- **`$prefix`** 是运行时变量，展开为 nginx 编译期 prefix（`/usr/local/openresty/nginx`）；`lua_package_path` 用它避免写死绝对路径。
- **`lua_code_cache on`** 生产必须开，`off` 会让每个请求重编 Lua，性能断崖；只在开发调试期短暂关闭。
- **`init_by_lua_block`** 在 master 加载配置时跑一次，之后 fork worker 会共享 Lua VM 状态；**禁止在里面做 IO / sleep**，会卡住整个 nginx 启动。
- **`init_worker_by_lua_block`** 才是每个 worker 独立跑一次的地方，`timer` / 心跳 / 订阅等要放这里。

# `conf.d/` 拆分惯例

**一个站点一个文件**，用文件名排序控制加载顺序：

```
conf.d/
├── 00-upstreams.conf          # upstream 定义
├── 10-default.conf            # catch-all（放最前作 404 兜底）
├── 20-api-gateway.conf        # 网关路由
└── 30-admin-console.conf      # 后台
```

`10-default.conf` 里的示例：

```nginx
server {
    listen 80 default_server;
    server_name _;
    location / {
        content_by_lua_block {
            ngx.status = 404
            ngx.say("no such host")
        }
    }
}
```

`include conf.d/*.conf;` 加载顺序在**同一次 reload 内**是稳定的（按字典序），跨 reload 由 shell glob 保证。

# 常用命令

```bash
# 语法检查（改配置后必跑）
openresty -t

# 指定 prefix 与配置文件（多实例场景）
openresty -p /opt/ors-a -c /opt/ors-a/conf/nginx.conf

# 只打印版本（不带编译选项）
openresty -v

# 打印版本 + 全部编译选项
openresty -V

# 前台启动（容器内 PID 1）
openresty -g 'daemon off;'

# 优雅停止 worker（reload）
openresty -s reload

# 快速关闭
openresty -s stop

# 平滑退出（等活跃连接处理完）
openresty -s quit

# 打开/关闭 debug log（需 --with-debug 编译）
openresty -s reopen
```

`-p` 决定 **相对路径解析的基准**——`nginx.conf` 里 `logs/error.log`、`conf.d/*.conf` 这些相对路径都基于 `-p`。多实例部署一定要显式带上 `-p`，否则两个实例会往同一个 `logs/` 里写。

# 验证

```bash
# 1) 找对主配置
openresty -t
# nginx: the configuration file /usr/local/openresty/nginx/conf/nginx.conf syntax is ok
# 路径如果不在 /usr/local/openresty/... 说明 prefix 有问题

# 2) 找对 lualib
resty -e 'print(package.path)'
# 应该能看到 /usr/local/openresty/lualib/?.lua

# 3) reload 后 worker 换代
openresty -s reload
ps -ef | grep 'nginx: worker' | grep -v grep   # worker PID 变了
```

# 避坑

- **`/etc/nginx/nginx.conf` 里改配置不生效**：你改的是 apt 裸 nginx 的 conf；openresty 只看自己的 prefix。
- **`include` 相对路径**：`include conf.d/*.conf;` 是**相对于 `-p` 指定的 prefix**（默认 `/usr/local/openresty/nginx/`）——不是相对于 `nginx.conf` 本身；跨 prefix 部署要写成绝对路径或提前 `-p`。
- **软链接会踩坑**：把 `conf` 目录软链到 `/opt/config/`，`$prefix` 变量展开时不会跟随；要么直接 bind mount，要么在 nginx.conf 里用绝对路径。
- **权限**：master 以 root 起（bind 80/443），worker 用 `user nginx;` 降权；`logs/` 与 `client_body_temp/` 必须对 `nginx` 用户可写，否则 500。
- **多实例共享 pid 文件**：`pid logs/nginx.pid;` 是相对路径，两个实例都会写到各自的 prefix 下；如果你把 `-p` 都指到同一个目录就会打架。
- **`worker_processes auto` 在容器里数宿主机核**：Cgroup CPU limit 生效前 `auto` 可能算错，K8s 里显式写 `worker_processes 2;` 更稳。
- **改完配置忘 reload**：`lua_code_cache on` 下 Lua 文件的修改也要 reload 才生效——**不是 reload 就能立即热更**；真要热更得走 `lua-resty-hotreload` 或共享字典里的版本号机制（详见 05 章）。

# 总结

`/usr/local/openresty/` 是唯一的 root，`bin/openresty` 是唯一的入口，`nginx/conf/nginx.conf` 是唯一的主配置——三件事记牢，剩下的都是把它拆得更清爽的工程问题。`conf.d` 按站点/按角色切分、`stream.conf.d` 按四层服务切分，`init_by_lua_block` 只做全局初始化、`init_worker_by_lua_block` 才做每 worker 的事。掌握这些就够撑到 [060.第一个 HelloWorld](./060.第一个HelloWorld.md)。
