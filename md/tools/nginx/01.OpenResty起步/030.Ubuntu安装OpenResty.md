# 概述

Ubuntu 是 OpenResty 官方发行包的一等公民：作者为 LTS 版本（jammy 22.04、noble 24.04，历史上还有 focal 20.04、bionic 18.04）维护 **APT 仓库**，一条 `apt install` 就能装到 **1.31.8.1**，附带 systemd 单元、`openresty` 启动器、`opm` 包管理器，生产环境首选。

本流程同样适用于 Debian bookworm/trixie（用官方 Debian 仓库）、CentOS Stream 9 / RHEL 9（用官方 RPM 仓库）；差异只在仓库配置那一段，其余一致。

要点速览：

| 项目 | 值 |
|------|---|
| APT 仓库 | `http://openresty.org/package/ubuntu` |
| GPG Keyring | `/usr/share/keyrings/openresty.gpg` |
| 包名 | `openresty`（含 nginx + luajit + 模块）；扩展包 `openresty-opm`、`openresty-resty`、`openresty-debug` |
| Prefix | `/usr/local/openresty/` |
| 二进制 | `/usr/local/openresty/bin/openresty`、`/usr/local/openresty/nginx/sbin/nginx` |
| 主配置 | `/usr/local/openresty/nginx/conf/nginx.conf` |
| systemd 单元 | `/lib/systemd/system/openresty.service` |
| 默认日志 | `/usr/local/openresty/nginx/logs/{access,error}.log` |

# 操作步骤

## 1) 准备依赖

```bash
sudo apt update
sudo apt install -y --no-install-recommends \
    wget curl gnupg lsb-release ca-certificates \
    sudo
```

## 2) 添加官方 APT 源（1.31.8.1）

```bash
# 导入 GPG key（现代做法，用 keyring 而非 trusted.gpg.d）
curl -fsSL https://openresty.org/package/pubkey.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/openresty.gpg

# 添加源：jammy/noble/focal 都走同一个仓库，$(lsb_release -sc) 会自动匹配
echo "deb [signed-by=/usr/share/keyrings/openresty.gpg] \
http://openresty.org/package/ubuntu $(lsb_release -sc) main" \
  | sudo tee /etc/apt/sources.list.d/openresty.list

sudo apt update
```

## 3) 安装

```bash
sudo apt install -y openresty
# 常见配套：
sudo apt install -y openresty-opm openresty-resty
```

`openresty-opm` 提供官方包管理器（详见 [080.包管理 opm 与 luarocks](./080.包管理opm与luarocks.md)），`openresty-resty` 提供 `resty` 命令行 Lua REPL。

## 4) 启动与开机自启

```bash
sudo systemctl enable --now openresty
sudo systemctl status openresty
```

单元文件长这样（`/lib/systemd/system/openresty.service`）：

```ini
[Unit]
Description=The OpenResty Application Platform
After=network.target

[Service]
Type=forking
PIDFile=/usr/local/openresty/nginx/logs/nginx.pid
ExecStartPre=/usr/local/openresty/bin/openresty -t
ExecStart=/usr/local/openresty/bin/openresty
ExecReload=/bin/kill -s HUP $MAINPID
ExecStop=/bin/kill -s QUIT $MAINPID
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

`Type=forking` + `PIDFile` 是 Nginx 传统 master-worker 模型的标准 systemd 集成方式；改配置后 `systemctl reload openresty` 走 `HUP` 信号，不断连。

## 5) 指定版本 / 降级 / 锁定

```bash
# 查看仓库里可用的版本
apt-cache madison openresty
# openresty | 1.31.8.1-1or~24.04 | http://openresty.org/package/ubuntu noble/main amd64 Packages
# openresty | 1.27.1.1-1or~24.04 | ...

# 安装指定版本
sudo apt install -y openresty=1.31.8.1-1or~24.04

# 防止被 apt upgrade 意外升级
sudo apt-mark hold openresty
```

## 6) 编译安装（可选：需要额外 C 模块时）

```bash
sudo apt install -y build-essential libpcre3-dev libssl-dev zlib1g-dev perl
wget https://openresty.org/download/openresty-1.31.8.1.tar.gz
tar xzf openresty-1.31.8.1.tar.gz && cd openresty-1.31.8.1

./configure --prefix=/usr/local/openresty-1.31.8.1 \
            --with-http_ssl_module \
            --with-http_v2_module \
            --with-http_realip_module \
            --with-pcre-jit \
            --with-stream \
            --with-stream_ssl_module \
            -I/usr/include/libxml2 \
            --add-module=/path/to/your/custom_module

make -j$(nproc)
sudo make install
```

`--with-stream` 打开四层 Lua（`ngx_stream_lua_module`），MySQL/Redis 前置代理必备；`--with-pcre-jit` 打开 PCRE JIT 让 `location ~` 匹配加速。

# 验证

```bash
openresty -v
# nginx version: openresty/1.31.8.1
# built by gcc 13.2.0 ...
# TLS-SNI supported, epoll enabled

openresty -V 2>&1 | tr ' ' '\n' | grep -E 'with-(http_ssl|stream|pcre-jit|http_v2)'
# 看到编译期指令清单，用来核对第三方模块是否已启用

sudo systemctl is-active openresty       # active
curl -sI http://localhost/ | head -1     # HTTP/1.1 200 OK

resty -e 'print(ngx and "in-nginx?" or "no-ngx, ok")'  # 独立 Lua REPL
```

# 避坑

- **默认 prefix 是 `/usr/local/openresty/` 不是 `/etc/nginx`**：和 apt 装的裸 Nginx 完全不同，别把配置扔到 `/etc/nginx/nginx.conf`——openresty 根本不读那里。
- **`openresty` 与 `nginx` 是两个命令**：apt 装的官方包只放 `openresty`；`nginx` 需要你自己 `ln -s /usr/local/openresty/nginx/sbin/nginx /usr/local/bin/nginx`。推荐永远用 `openresty`。
- **systemd 单元没有 `Restart=always`**：官方包默认进程挂掉不会自动重启，生产环境请 drop-in 覆盖：`systemctl edit openresty` 加 `[Service] Restart=always RestartSec=1s`。
- **`ulimit` 太低**：Ubuntu 默认 `nofile=1024`，跑高并发前用 drop-in `LimitNOFILE=65535` 或改 `/etc/security/limits.conf`；主配置里 `worker_rlimit_nofile` 也要同步放大。
- **`http{}` 里的 `lua_shared_dict` 记得声明**：`apt install openresty` 不带任何字典，业务代码用 `ngx.shared.foo` 前必须在 http 块声明，否则运行时 `nil`。
- **apt 装完后没有 `opm` 命令**：说明漏装 `openresty-opm`；`apt install openresty-opm` 补上。
- **HTTPS 仓库**：官方仓库是 **HTTP**，包体本身通过 GPG 签名，无需 `https`；不要为了合规把 URL 手改成 `https://`，会 502。
- **升级中断**：`apt install` 时若旧版进程还活着会失败，先 `systemctl stop openresty` 再升级，或用 `apt -o Dpkg::Options::="--force-confdef" -o Dpkg::Options::="--force-confold"` 保留旧配置。

# 总结

Ubuntu 是 OpenResty 最"顺"的发行平台，官方 APT + systemd 一体化，1.31.8.1 装完就跑。开发机走 APT，生产要加装自定义模块时再走源码；永远用 `openresty` 命令而不是软链的 `nginx`，也永远不要用 apt 的裸 nginx 包"混装"——两套 prefix 打架是踩坑重灾区。装完之后先照着 [050.目录结构与配置文件](./050.目录结构与配置文件.md) 熟悉 prefix，再进 [060.第一个 HelloWorld](./060.第一个HelloWorld.md)。
