# 概述

OpenResty 生态的 Lua 库安装有两个工具：**`opm`**（OpenResty 官方包管理器，作者亲自维护）与 **`luarocks`**（Lua 社区通用包管理器）。两者**不冲突，但选型有边界**：OpenResty 生态库（`lua-resty-*`）优先 `opm`，通用纯 Lua/C 库（如 `lpeg`、`luaposix`）走 `luarocks`。本文给出两者的定位、命令、镜像源、依赖清单与选型建议。

# 一图看懂定位

```
      你想要装什么库？
              │
      ┌───────┴────────┐
      │                │
lua-resty-*       其它 Lua 生态
（OpenResty 场景专用）
      │                │
   opm              luarocks
      │                │
默认装到              装到系统 luarocks 树，
/usr/local/openresty/  再手工把 lualib 加入
lualib/                 lua_package_cpath
```

- **`opm`**：GitHub 仓库为源，`<owner>/<repo>` 就是包名；`opm get ledgetech/lua-resty-http` 直接从 GitHub 拉 release tag。
- **`luarocks`**：LuaRocks 中央仓库 `<https://luarocks.org>` 的元数据 + tarball；支持版本约束、`--tree` 隔离。

# 安装与配置

## 1) `opm`：Ubuntu APT 已经带

```bash
# 30 章的 apt 装完后
sudo apt install -y openresty-opm

opm -V                     # 0.3.x
opm update                 # 拉仓库 index
opm get ledgetech/lua-resty-http   # 安装
opm list                          # 已安装包
```

`opm` 默认 prefix 是 `/usr/local/openresty/`（与 OpenResty 一致），装完 Lua 文件就在 `/usr/local/openresty/site/lualib/`；这个路径已在 `nginx.conf` 默认 `lua_package_path` 里，无需再配。

## 2) `opm`：源码安装（Windows/其他发行版）

```bash
curl -L https://github.com/openresty/opm/archive/refs/heads/master.tar.gz | tar xz
cd opm-master && perl Makefile.PL && make && sudo make install
```

## 3) `opm` 镜像源（墙内友好）

```bash
# 把仓库源切到 GitHub 直连（默认已是）或国内镜像
opm config registry https://opm.tr0.cn         # 社区镜像，可选
opm config github_token <YOUR_PAT>             # 私有仓库或限速时
```

## 4) `luarocks`：随 OpenResty 打包，但需另装

OpenResty 官方包**不带 luarocks**（因为 opm 覆盖了主流场景）。需要装纯 Lua/C 库时：

```bash
sudo apt install -y libluajit-5.1-dev luajit luarocks
echo "luajit" | sudo luarocks    # 或交互式选 lua 版本

# 让 luarocks 装到 OpenResty 能找到的路径
sudo luarocks config variables.prefix /usr/local/openresty/luajit
sudo luarocks install luaposix
sudo luarocks install lpeg
```

配置一次即可，之后 `luarocks install <pkg>` 默认落在 `/usr/local/openresty/luajit/lib/lua/5.1/` 与 `/share/lua/5.1/`，与 `lua_package_path` 里的 `$prefix/lualib/?.lua` 不冲突。

# 常用命令对照

| 目的 | opm | luarocks |
|-----|-----|----------|
| 搜索包 | `opm search <kw>`（走 index） | `luarocks search <kw>` |
| 安装 | `opm get <owner>/<repo>` | `luarocks install <pkg> [ver]` |
| 升级到最新 | `opm upgrade` | `luarocks install <pkg> --nodeps` |
| 列已装 | `opm list` | `luarocks list` |
| 卸载 | `opm remove <owner>/<repo>` | `luarocks remove <pkg>` |
| 装到自定义 prefix | `opm --prefix=/path ...` | `luarocks --tree=/path install ...` |
| 依赖清单 | `opm describe <owner>/<repo>` | `luarocks show <pkg>` |

# 常见选型：这些库从哪装

| 库 | 用途 | 推荐渠道 | 备注 |
|---|-----|---------|------|
| `ledgetech/lua-resty-http` | HTTP 客户端（比 `ngx.location.capture` 灵活） | **opm** | 官方维护 |
| `openresty/lua-resty-redis` | 非阻塞 Redis 客户端 | **opm** | 官方 |
| `openresty/lua-resty-mysql` | 非阻塞 MySQL 客户端 | **opm** | 官方 |
| `openresty/lua-resty-string` | 加解密封装（AES/RSA） | **opm** | 官方 |
| `openresty/lua-resty-jwt` | JWT | **opm** | 官方 |
| `api7/lua-resty-jit-protocol`（APISIX 系） | 限流/负载均衡工具集 | **opm** | api7 维护 |
| `cloudflare/lua-resty-cookie` | Cookie 解析 | **opm** | 官方 |
| `cjson` | JSON 编解码 | **不需要装**，OpenResty 内置 `cjson` 与 `cjson.safe` | 用 `require "cjson.safe"` 更稳 |
| `lpeg` | PEG 解析 | **luarocks** | 有 C 扩展 |
| `luaposix` | POSIX 调用（`getpid`、`syslog`） | **luarocks** | 与 cosocket 组合用 |
| `dkjson` | 纯 Lua JSON 备选 | **luarocks** | 无 C 依赖 |
| `busted` | Lua 单测框架 | **luarocks** | OpenResty 场景更推荐 `Test::Nginx`，见 04 章 |
| `luacheck` | 静态检查 | **luarocks** | CI 建议装 |

# 验证

## opm

```bash
opm get ledgetech/lua-resty-http
ls /usr/local/openresty/site/lualib/resty/http.lua    # 存在即成功

# 在 resty CLI 里试
resty -e 'local http = require "resty.http"; print(http.VERSION)'
```

## luarocks

```bash
sudo luarocks install lpeg
resty -e 'local re = require "re"; print(re.match(".*", "hi"))'
# hi  nil?  不 —— 应该 hi
```

## nginx 里能否 require

```lua
-- 在 init_by_lua_block 里
local ok, http = pcall(require, "resty.http")
if not ok then error("missing dep: " .. http) end
```

`init_by_lua_block` 是**最早的 require 时机**，能暴露 `lua_package_path` 配置问题。

# 避坑

- **`opm` 装完 nginx 找不到库**：90% 是没跑 `opm update`（本地 index 过期），或 `lua_package_path` 被自定义 `nginx.conf` 覆盖了。默认 `nginx.conf` 的 `lua_package_path` 应该包含 `$prefix/../site/lualib/?.lua`。
- **`opm` 与 `luarocks` 装同名包（如都装了 `lua-resty-http`）**：会覆盖，行为取决于 `lua_package_path` 匹配顺序；**一个包只走一个渠道**，写进团队约定。
- **`luarocks` 装 C 扩展失败**：缺 `libluajit-5.1-dev`；OpenResty 打包了 LuaJIT 头文件在 `/usr/local/openresty/luajit/include/luajit-2.1/`，`luarocks` 默认找不到。加 `luarocks --lua-version=5.1 --with-lua=/usr/local/openresty/luajit` 或提前 `luarocks config variables.LUA_INCDIR ...`。
- **版本锁定**：`opm` 目前不支持版本约束（永远拉最新 release tag），生产环境**装完就 `opm list > deps.lock` 冻结**，重建镜像时人工 diff。
- **私有仓库**：`opm get my-org/my-private-repo` 需要 `github_token`，公开走匿名 API 会限速；企业 CI 里一定要配 token。
- **Docker 里装 opm 会污染镜像层**：`opm get` 落 `/usr/local/openresty/site/`，写在 Dockerfile 里就 OK；容器里运行时再 `opm get` 会在下次重建时丢。
- **`opm` 与 `luarocks` 装到不同 tree**：`opm` 落 `site/`，`luarocks` 落 `luajit/`；两条路径都要在 `lua_package_path` 里覆盖到，否则其中一边 `require` 失败。

# 总结

选型的口诀：**OpenResty 生态（`lua-resty-*`）就 `opm`，通用 Lua（有 C 扩展或非 OpenResty 用途）就 `luarocks`**。两个渠道都装时，把 `lua_package_path` 与 `lua_package_cpath` 两条搜索路径配齐，`init_by_lua_block` 里 `require` 一遍做冒烟测试。到这里起步章的九篇正文就全部到位，转 [02 章运行时内幕](../02.Lua与OpenResty运行时内幕/001.运行时内幕概述.md) 打开 LuaJIT 的引擎盖。
