# 概述

`openresty/openresty` 是官方维护的 Docker 镜像，覆盖 Ubuntu / Debian / Alpine 三种基底、x86_64 / arm64 / armv7 / s390x 多种架构，每个 OpenResty 版本（含 **1.31.8.1**）都提供对应 tag。**它不是 `-alpine` 就够用**：Alpine 用 musl，某些 `lua-resty-*`（依赖 `libcap`、`openssl-legacy` 等）在 musl 上会行为差异；生产推荐 `jammy`/`noble` 基底。

镜像要点：

| 项目 | 值 |
|------|---|
| 主 tag 格式 | `openresty/openresty:<版本>-<基底>`，如 `1.31.8.1-jammy`、`1.31.8.1-noble`、`1.31.8.1-alpine`、`1.31.8.1-bookworm` |
| 隐式 latest | `openresty/openresty:latest` 跟随最新 stable，**生产不要用** |
| Prefix（容器内） | `/usr/local/openresty/` |
| 配置文件默认位置 | `/usr/local/openresty/nginx/conf/nginx.conf` |
| 暴露端口 | Dockerfile 里 `EXPOSE 80`，需要 `-p` 才映射 |
| CMD | `/usr/local/openresty/bin/openresty -g 'daemon off;'` — 前台运行，配合容器 PID 1 |
| Entry | 官方仓库 <https://github.com/openresty/docker-openresty> |

# 操作步骤

## 1) 拉取并跑起来

```bash
docker pull openresty/openresty:1.31.8.1-jammy

# 最小可跑：暴露 80 端口，容器名 ors
docker run -d --name ors -p 8080:80 openresty/openresty:1.31.8.1-jammy

# 检查
docker logs ors
curl -sI http://localhost:8080/ | head -1
```

## 2) 挂载自定义配置（推荐的开发姿势）

```
deploy/
├── docker-compose.yml
├── nginx.conf
├── conf.d/
│   └── default.conf
└── lua/
    └── hello.lua
```

```yaml
# deploy/docker-compose.yml
services:
  openresty:
    image: openresty/openresty:1.31.8.1-jammy
    container_name: ors
    restart: unless-stopped
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/usr/local/openresty/nginx/conf/nginx.conf:ro
      - ./conf.d:/etc/nginx/conf.d:ro
      - ./lua:/usr/local/openresty/lualib/app:ro
    environment:
      - TZ=Asia/Shanghai
    healthcheck:
      test: ["CMD", "openresty", "-t"]
      interval: 30s
      timeout: 5s
      retries: 3
```

```bash
docker compose up -d
docker compose logs -f openresty
```

## 3) 打进镜像（生产）

```dockerfile
# Dockerfile
FROM openresty/openresty:1.31.8.1-jammy

# 装 opm 依赖
RUN opm get ledgetech/lua-resty-http \
    && opm get skywind3000/resty-jit

# 拷贝配置与 Lua 源码
COPY nginx.conf /usr/local/openresty/nginx/conf/nginx.conf
COPY conf.d/    /etc/nginx/conf.d/
COPY lua/       /usr/local/openresty/lualib/app/

# 覆盖 CMD：调试期可以开 lua_code_cache off，生产永远 on
CMD ["openresty", "-g", "daemon off;"]
```

```bash
docker build -t my-ors:1.31.8.1 .
docker run -d --name ors -p 8080:80 my-ors:1.31.8.1
```

## 4) 进容器调试

```bash
docker exec -it ors bash
openresty -t                       # 语法检查
openresty -s reload                # 容器内 reload（不重启容器）
tail -F /usr/local/openresty/nginx/logs/error.log

# 用 resty CLI 跑单文件 Lua（脱离 nginx）
resty -e 'print(require("cjson").encode({a=1,b={2,3}}))'
```

## 5) Alpine 变体：小镜像但 musl 陷阱

```bash
docker pull openresty/openresty:1.31.8.1-alpine
```

Alpine 版镜像小约 30 MB（vs jammy 版 ~180 MB），但 musl libc 与 glibc 在 DNS 解析、线程栈、`getaddrinfo` 行为上有差异；用到 `lua-resty-dns`、`posix`、`brotli` 之类底层库时**先在 jammy 上验通再切 Alpine**。

## 6) K8s 里的姿势

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: openresty-gateway
spec:
  replicas: 3
  template:
    spec:
      containers:
        - name: ors
          image: registry.example.com/my-ors:1.31.8.1
          ports:
            - containerPort: 80
          readinessProbe:
            httpGet: { path: /healthz, port: 80 }
            periodSeconds: 5
          livenessProbe:
            exec:
              command: ["openresty", "-t"]
            periodSeconds: 30
          volumeMounts:
            - name: conf
              mountPath: /etc/nginx/conf.d
              readOnly: true
      volumes:
        - name: conf
          configMap:
            name: openresty-confd
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: openresty-confd
data:
  default.conf: |
    server {
      listen 80;
      location /healthz { return 200 'ok'; }
      location / { content_by_lua_block { ngx.say("hello from k8s") }; }
    }
```

改配置只滚动 ConfigMap + `rollout restart`；比 reload 更清晰，也天然利用 K8s 的探针。

# 验证

```bash
# 1) 版本
docker exec ors openresty -v
# nginx version: openresty/1.31.8.1

# 2) 配置语法
docker exec ors openresty -t

# 3) 请求路径打通
curl -s http://localhost:8080/ | head

# 4) 挂载文件真的生效（改本地后 reload）
echo "-- reloaded" >> deploy/conf.d/default.conf
docker exec ors openresty -s reload
curl -sI http://localhost:8080/

# 5) PID 1 是前台
docker top ors
# 期望看到 "openresty -g daemon off;"，不是 "nginx: master process"
```

# 避坑

- **忘 `-g 'daemon off;'`**：官方镜像默认 CMD 已经带，但**你重写 CMD 时容易丢**；一旦 daemon 化，容器 PID 1 就退出，Docker 判为容器终止。
- **挂载路径不对**：官方镜像 prefix 是 `/usr/local/openresty/nginx/conf/`，**不是** `/etc/nginx/`；把配置挂到 `/etc/nginx/` 是 nginx 官方镜像的做法，两者混用是大坑。
- **volume 权限**：宿主机 UID 与容器 `nobody`/`www-data` 不一致时 `logs/` 写不进去；生产要么改 `user:` 要么把 `logs` 挂 tmpfs。
- **reload 会杀容器**：容器里 `openresty -s reload` 只重启 worker，master 是 PID 1 不变；但**不要**用 `docker restart` 代替 reload——`docker restart` 有几百毫秒不可用窗口。
- **`opm get` 时机**：必须在 Dockerfile 里跑，运行时 `docker exec` 装的包在下次容器重建后消失。
- **Alpine + cosocket**：musl 的 `getaddrinfo` 与 Nginx `resolver` 语义不一致，某些 `lua-resty-*`（尤其 DNS 相关）在 Alpine 上会 hang；跨平台镜像测试不能只跑一个基底。
- **镜像 tag `latest` 不要用**：官方镜像的 `latest` 是滚动语义，K8s 会因 `imagePullPolicy` 判断出节点侧不可复现；永远 pin 到 `1.31.8.1-jammy` 具体版本。
- **健康检查用 `openresty -t`**：这个命令做**语法检查**，不打业务流量；真正的 readiness 建议起一个 `location /healthz { return 200 'ok'; }` 走 HTTP GET。
- **privileges**：容器默认能 bind 80 是因为跑在 root 下；非 root 场景要么 `setcap 'cap_net_bind_service=+ep'` 要么直接换高端口 + iptables 转发。

# 总结

Docker 部署 OpenResty 的正确姿势：**jammy 基底 + 版本 pin + 挂载或 COPY 配置 + 保留官方 CMD 的前台 flag**。开发用 `docker compose` + bind mount 快速迭代，生产把配置与依赖打进自定义镜像（`FROM openresty/openresty:1.31.8.1-jammy`），K8s 场景优先用 ConfigMap + 探针。装完之后进 [050.目录结构与配置文件](./050.目录结构与配置文件.md) 熟悉 prefix，或直接从 [060.第一个 HelloWorld](./060.第一个HelloWorld.md) 上手写 Lua。
