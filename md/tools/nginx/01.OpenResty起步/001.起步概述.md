# 概述

本章带你把 OpenResty 从"完全没装"推到"能跑第一个 Lua 请求处理"：先厘清 OpenResty 是什么、和 Nginx/Kong 是什么关系，然后在 **Windows / Ubuntu / Docker** 三条路径上装好 **1.31.8.1**，摸清目录与配置骨架，用 `content_by_lua_block` 写出第一个 hello world，把 Nginx 的 11 个处理阶段与 Lua 挂点串一遍，最后把包管理（`opm` 与 `luarocks`）选好。

读完本章你应该能回答：
- 什么场景应该选 OpenResty 而不是传统后端？
- 一个 OpenResty 安装里到底打包了哪些子项目？
- Lua 代码写在 `nginx.conf` 的哪一段？改完怎么生效？
- `rewrite`、`access`、`content`、`log` 阶段分别适合放什么逻辑？
- 装第三方 Lua 库到底走 `opm` 还是 `luarocks`？

# 环境要求

- **Ubuntu**：22.04 LTS（jammy）或 24.04 LTS（noble），x86_64 或 arm64；
- **Windows**：Windows 11 + WSL2（推荐），或 Docker Desktop 4.x；
- **Docker**：24.x 及以上，能拉 `openresty/openresty` 官方镜像；
- **版本口径**：本章所有示例围绕 **OpenResty 1.31.8.1**（对应 nginx core 1.31.8，LuaJIT 2.1 OpenResty fork），若使用 1.25/1.27 系列请先看 [02 章运行时内幕](../02.Lua与OpenResty运行时内幕/001.运行时内幕概述.md) 里对 LuaJIT 分支的说明；
- **前置知识**：会写任意一门脚本语言即可，Lua 语法在 [02 章 090.OpenResty 中 Lua 的约束与常见坑](../02.Lua与OpenResty运行时内幕/090.OpenResty中Lua的约束与常见坑.md) 与其中分篇补齐。
