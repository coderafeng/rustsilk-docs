# 概述

**Step 3**：让网关能"扛事"——**上游熔断 + 灰度分流 + 请求重试**。核心：**主动健康检查、失败率统计、shdict 存状态、按 header / cookie / 用户尾号选路**。

# 目标架构增量

```text
Client ─▶ gateway
              │
              ├─ access_by_lua（Step 2）
              │    └─ ★ 灰度标签注入：canary_tag / cohort
              ├─ rewrite_by_lua（Step 1）
              ├─ ★ 新增：健康实例过滤（Step 3）
              ├─ balancer_by_lua（Step 1 → 增强）
              │    ├─ 熔断：shdict 记录每个实例错误率
              │    ├─ 选路：按 canary_tag 分流到不同 upstream
              │    └─ retry：幂等方法 + 失败率兜底
              └─ log_by_lua：★ 上报错误率
```

# 一、上游健康与熔断

## 状态定义

```text
每个实例的状态：
  healthy  ─▶ 正常参与选路
  suspect  ─▶ 错误率高；降权
  unhealthy ─▶ 熔断；不选；后台探活
  recovering ─▶ 探活成功；逐步放量
```

## 状态存储

```lua
-- shdict: upstream_health
-- key = svc|host|port
-- value = 状态字符串
-- flags = 失败计数

local sh_health = ngx.shared.upstream_health

local function record_failure(svc, host, port)
    local key = svc .. "|" .. host .. "|" .. port
    local count, flags = sh_health:incr(key, 1, 0)
    -- 错误率窗口：每 60s 清零；shdict TTL 自动过期
    sh_health:set(key, count, 60)

    if count >= 20 then
        sh_health:set(key, "unhealthy", 300)         -- 熔断 5 分钟
        ngx.log(ngx.WARN, "circuit opened: ", key)
    elseif count >= 5 then
        sh_health:set(key, "suspect", 60)
    end
end

local function record_success(svc, host, port)
    local key = svc .. "|" .. host .. "|" .. port
    local v = sh_health:get(key)
    if v == "suspect" then
        -- 连续 3 次成功 → 转 healthy
        local c = tonumber(sh_health:get(key .. ":ok") or 0) + 1
        if c >= 3 then
            sh_health:delete(key)
            sh_health:delete(key .. ":ok")
        else
            sh_health:set(key .. ":ok", c, 60)
        end
    end
end

local function is_available(svc, host, port)
    local key = svc .. "|" .. host .. "|" .. port
    local v = sh_health:get(key)
    if v == "unhealthy" then return false end
    if v == "suspect" then return math.random(100) > 50 end   -- 降权
    return true
end
```

## 在 balancer 里过滤 + 兜底

```lua
-- lua/lb.lua（Step 3 增强）
function _M.pick(service, canary_tag)
    local nodes = _load_nodes(service, canary_tag)
    local available = {}
    for _, n in ipairs(nodes) do
        if is_available(service, n.host, n.port) then
            available[#available+1] = n
        end
    end
    if #available == 0 then
        -- 全熔断：退让到"最少坏"（避免整站挂）
        available = nodes
        ngx.log(ngx.ALERT, "all peers circuit-broken: ", service)
    end

    local node = pick_by_p2c(available)                -- 简单 P2C
    balancer.set_current_peer(node.host, node.port)
    ngx.ctx.selected_node = node
    balancer.set_more_tries(2)                          -- 允许重试 2 次
end
```

## 在 log 阶段上报

```lua
log_by_lua_block {
    local node = ngx.ctx.selected_node
    if node and ngx.status >= 500 then
        record_failure(ngx.ctx.service, node.host, node.port)
    elseif node then
        record_success(ngx.ctx.service, node.host, node.port)
    end
}
```

**要点**：`log_by_lua` 是唯一能拿到 `ngx.status` 且**不影响响应**的阶段（见 [01 章 070](../01.OpenResty起步/070.请求处理阶段总览.md)）。

# 二、灰度分流

## 标签来源

```lua
-- access_by_lua 里
local function compute_canary_tag()
    local hdr = ngx.req.get_headers(30)

    -- 优先级 1：显式 header（内部工具）
    if hdr["x-canary"] == "on" then return "canary" end

    -- 优先级 2：cookie（前端埋点）
    local cookie = hdr["cookie"] or ""
    if cookie:find("canary=1", 1, true) then return "canary" end

    -- 优先级 3：user_id 尾号（稳定分流）
    local uid = ngx.ctx.user_id
    if uid then
        local tail = tonumber(tostring(uid):sub(-2)) or 0
        local pct = tonumber(ngx.shared.routes:get("canary_pct") or 0)
        if tail < pct then return "canary" end
    end

    return "stable"
end
ngx.ctx.canary_tag = compute_canary_tag()
```

## 服务发现里区分 stable / canary

Consul 里的实例带 metadata：

```json
{ "Node": {"Address": "10.0.0.1"},
  "Service": {"Port": 8080, "Meta": {"track": "canary"}} }
```

`_load_nodes` 按 `canary_tag` 过滤：

```lua
local function _load_nodes(service, tag)
    local raw = ngx.shared.upstreams:get(service) or "[]"
    local all = cjson.decode(raw)
    local out = {}
    for _, n in ipairs(all) do
        local track = n.track or "stable"
        if track == tag or tag == "stable" then
            out[#out+1] = n
        end
    end
    -- 兜底：canary 无节点时退回 stable
    if #out == 0 and tag == "canary" then
        for _, n in ipairs(all) do
            if (n.track or "stable") == "stable" then out[#out+1] = n end
        end
    end
    return out
end
```

## 动态调整比例

```bash
# 灰度 20% → 50% → 100%
curl -X PUT http://consul.local:8500/v1/kv/gateway/canary_pct -d 50
# 网关 syncer 拉配置：sh:set("canary_pct", 50)
```

# 三、请求重试

**只在幂等 + 无副作用**的操作上重试。

```lua
-- balancer_by_lua_block
local tries = balancer.get_attempts()
if tries > 0 then
    -- 上一次失败；已换 peer；继续走
    return
end
```

nginx 层的 retry 由 `proxy_next_upstream` 控制：

```nginx
location / {
    proxy_pass http://internal_backend;
    proxy_next_upstream error timeout http_502 http_503 http_504;
    proxy_next_upstream_tries 3;
    proxy_next_upstream_timeout 10s;
}
```

**Lua 侧只负责选下一个节点**（`balancer_by_lua` 每次被 nginx 重试时都会重跑）。

## 非幂等方法的保护

```lua
access_by_lua_block {
    local method = ngx.req.get_method()
    if method ~= "GET" and method ~= "HEAD" and method ~= "OPTIONS" then
        -- 关闭自动 retry；只允许显式重试
        ngx.ctx.no_retry = true
    end
}
```

对应 nginx.conf：

```nginx
proxy_next_upstream error timeout http_502 http_503 http_504 no_reuse;
```

**权衡**：写请求不 retry → 网络抖动直接返错；写请求 retry → 可能重复扣款。让**业务代码用 idempotency-key**（`Idempotency-Key` header），网关侧透传即可。

# 完整 nginx.conf 增量

在 Step 2 的 conf 上加：

```nginx
http {
    # Step 1-2 已有
    lua_shared_dict upstream_health 8m;
    lua_shared_dict canary_config   1m;

    server {
        location / {
            access_by_lua_block {
                local auth = require "auth"
                local ok, err = auth.check()
                if not ok then return ngx.exit(401) end

                ngx.ctx.canary_tag = compute_canary_tag()  -- ★ 新

                local rl = require "ratelimit"
                local pass = rl.check()
                if not pass then return ngx.exit(429) end
            }
            rewrite_by_lua_block { ... }   -- Step 1 路由

            proxy_pass http://internal_backend;
            proxy_next_upstream error timeout http_502 http_503 http_504;
            proxy_next_upstream_tries 3;

            log_by_lua_block {
                -- ★ Step 3：上报错误率
                local node = ngx.ctx.selected_node
                if node then
                    if ngx.status >= 500 then
                        require("health").record_failure(
                            ngx.ctx.service, node.host, node.port)
                    else
                        require("health").record_success(
                            ngx.ctx.service, node.host, node.port)
                    end
                end
            }
        }

        upstream internal_backend {
            server 0.0.0.1:1;
            balancer_by_lua_block {
                require("lb").pick(ngx.ctx.service, ngx.ctx.canary_tag)
            }
            keepalive 512;
        }
    }
}
```

# 交付验证清单

- [ ] kill 一个上游实例，20 次失败后熔断 5 分钟；期间新请求不再走它；
- [ ] 后台探活（可选）；恢复后转 recovering → healthy；
- [ ] 全服务实例都熔断时，请求仍能通过（退让兜底）；
- [ ] 设 `canary_pct=50` → 一半流量命中 canary 标签；
- [ ] header `X-Canary: on` → 100% 走 canary；
- [ ] GET 请求上游 502 时自动 retry 到另一节点；POST 默认不 retry；
- [ ] wrk 混合场景 5 分钟：无 5xx 突增；circuit_open 指标稳定。

# 避坑

- **熔断阈值调太高**：一次网络抖动 → 大面积熔断；从 `5 次/分钟` 起步；
- **所有实例都熔断**：必须**退让**——否则全站 503；见 lb.lua；
- **canary 分流抖动**：user_id 尾号哈希**必须稳定**；用 `ngx.crc32_short(uid) % 100`；
- **retry 与限流冲突**：一次逻辑请求 = 多次实际请求；限流按**逻辑请求**计数，在 access 阶段完成；
- **`proxy_next_upstream` 需要 `proxy_next_upstream_tries`**：不设默认无限；生产给 3；
- **`log_by_lua` 里 cosocket**：允许，但**不能再改响应**——响应已发；只做上报。

# 总结

- Step 3 = Step 2 + 熔断 + 灰度 + 重试；
- 熔断：shdict 存状态；三档 healthy/suspect/unhealthy；
- 灰度：三优先级 header/cookie/user_id；shdict 控比例；
- 重试：nginx 原生 + balancer 每次换节点；非幂等关闭；
- 到这里网关具备生产级韧性。
