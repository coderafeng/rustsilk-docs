# 目标形态

一个能扛 **5 万 QPS**、支持：
- 动态路由（从服务发现拉）
- JWT 鉴权 + API Key 双通道
- 多维限流（tenant / user / api）
- 上游熔断（错误率 > 20% 打开）
- 灰度发布（按 header / cookie / user_id 尾号）
- 全链路 metrics / trace

的网关。

# 分三步走

```text
Step 1 路由与转发
   最小网关：服务发现 → 动态 upstream → 转发
   ↑ 完成后能替代 nginx + 手工 upstream

Step 2 鉴权与限流
   在 Step 1 前加 access 阶段
   ↑ 完成后能对外提供 API

Step 3 熔断与灰度
   在 Step 1 的 balancer 阶段做智能选路
   ↑ 完成后进入生产级
```

**每步都是可运行的独立版本**；不要一口气堆到 Step 3 才测。

# 技术栈

- OpenResty **1.31.8.1**
- `lua-resty-http` 外部调用
- `lua-resty-lock` 互斥
- `lua-resty-lrucache` L1 缓存
- `lua-resty-prometheus` 指标
- Redis（限流状态、会话）
- Consul / Nacos（服务发现）

# 版本口径与运行环境

示例代码假设：
- Ubuntu 22.04，OpenResty 装到 `/usr/local/openresty/`；
- 网关监听 `:8080`，metrics `:9090`；
- 服务发现地址 `consul.local:8500`；
- Redis `127.0.0.1:6379`。
