# 概述

OpenResty 用的是 **LuaJIT 2.1**（openresty/luajit2 分支），语言层面**兼容 Lua 5.1**、**部分兼容 5.2**、**少量兼容 5.3/5.4**。它不是标准 Lua，也不是最新的 5.4。搞清楚差异，才能：

- 别写只有 5.4 才有的语法（`<close>`、整数/浮点分离的 `//`）；
- 别指望标准 5.1 上没有的 API 却假设可用（比如 `string.pack`、`utf8.*`）；
- 跨 LuaJIT 与 standalone Lua 时明白哪些坑是"环境性"的、哪些是"版本性"的。

# 版本兼容矩阵

| 特性 | 5.1 | 5.3 | 5.4 | LuaJIT 2.1（OpenResty） |
|-----|-----|-----|-----|------------------------|
| `goto` / label | ❌ | ✅ | ✅ | ✅ |
| 整数/浮点分离 | ❌ | ✅ | ✅ | ❌（数字都是 double） |
| `//` 整除 | ❌ | ✅ | ✅ | ❌ |
| `<close>` 变量 | ❌ | ❌ | ✅ | ❌ |
| `_ENV` 词法作用域 | ❌ | ✅ | ✅ | ❌（仍是 `_G` / `setfenv`） |
| `bit` 位运算库 | 需外部 | 用 `&` 运算符 | 同 | ✅ 内建 `bit.*` |
| `string.pack/unpack` | ❌ | ✅ | ✅ | ❌（用 FFI 替代） |
| `utf8.*` | ❌ | ✅ | ✅ | ❌（外部库） |
| `table.unpack` | ❌（`unpack`） | ✅ | ✅ | ✅（两者都有） |
| `math.type/isinteger` | ❌ | ✅ | ✅ | ❌ |
| `os.time` 秒级 | ✅ | ✅ | ✅ | ✅（毫秒用 `ngx.now()`） |

**结论**：把 LuaJIT 当 **Lua 5.1 + `bit` + `goto` + `jit` + FFI**。写跨平台代码就锁死在 5.1 语法上最保险。

# LuaJIT 特有 API

```lua
-- 1) bit 库（32 位整数位运算）
local bit = require("bit")
bit.band(0xff00, 0x00f0)   -- 0x0000
bit.bor(1, 2)              -- 3
bit.lshift(1, 8)           -- 256
bit.tobit(0xffffffff)      -- -1（转成 int32）

-- 2) ffi 库（详见 040 篇）
local ffi = require("ffi")
ffi.cdef[[ typedef struct { int a; double b; } my_t; ]]
local p = ffi.new("my_t", 42, 3.14)

-- 3) jit 库（详见 010 篇）
local jit = require("jit")
jit.off(); jit.on(); jit.flush()
jit.opt.start(2, "hotcount=80")

-- 4) jit.util / jit.bcsave / vmprofile 等辅助模块
```

# 常见"以为是标准 Lua 但行为不同"

## 1) `tostring` 数字格式

```lua
-- LuaJIT 2.1 与 5.1 一致：一切数字是 double
print(1 + 1)     -- 2      -- 输出 "2"
print(4.0)       -- 4      -- 输出 "4"（不是 "4.0"）
print(1/3)       -- 0.33333333333333
print(math.maxinteger)  -- nil（不存在）
```

需要判整数：`math.floor(x) == x`；需要 int64：`ffi.cast("int64_t", x)`。

## 2) 整数溢出

```lua
print(2^53 + 1 == 2^53)   -- LuaJIT 下 true（double 精度丢），5.4 下 false
```

超过 2^53 的整数运算请走 FFI。

## 3) `#` 运算符

LuaJIT 里 `#t` 与 5.1 一致：遇到 hash 部分的第一段 nil 会短路；详见 [050.table 与 metatable 内幕](./050.table与metatable内幕.md)。

## 4) 字符串内部化

LuaJIT 会把短字符串 intern 到内部哈希表，等价的字面量共享同一份内存：

```lua
local a = "hello"; local b = "hello"
print(a == b)   -- true 且指针相等（比较极快）
```

好处：`==` 是指针比较；坏处见 [060.字符串内部化与 GC](./060.字符串内部化与GC.md)。

# 迁移与跨环境建议

- **团队规范里锁定语言版本**：luacheck 的 `.luacheckrc` 设 `std = "luajit"`，别混 `lua54`。
- **别依赖 `_ENV` / `<close>` / `//`**：在 LuaJIT 上直接编译失败。
- **需要 `utf8` 库**：装 `luarocks install luautf8` 或用 `resty.string`。
- **需要 `bit` 且跨到标准 Lua**：`luarocks install bit32`（API 略不同）。
- **`string.pack` 缺失**：用 FFI 或手写 `bit.lshift` 拼接。
- **JSON 一律走 `cjson.safe`**：与标准 Lua 的 `cjson` 行为一致但错误不抛异常。

# 验证

```bash
luajit -e 'print(_VERSION)'          -- Lua 5.1（LuaJIT 报 5.1 兼容层）
luajit -e 'print(jit.version)'       -- LuaJIT 2.1.xxxxx
luajit -e 'print(jit.os, jit.arch)'  -- Linux x64
luajit -e 'print(ffi and "ffi ok" or "no ffi")'  -- 需要 -e 里 require

# 在 openresty 里
resty -e 'print(_VERSION)'
resty -e 'local jit = require "jit"; print(jit.version)'
```

# 避坑

- **不要混用 `bit` 与 `bit32`**：`bit.lshift(1, 40)` 在 LuaJIT 里返回 0（32 位截断）；`bit32.lshift` 也是 32 位但语义略有不同。团队固定一个。
- **不要以为 `math.floor` 返回整数**：LuaJIT 里 `math.floor(3.7)` 返回 `3`（double），不是 int64；跨到 5.3+ 语义不同。
- **数字格式化**：`string.format("%d", 3.5)` 在 LuaJIT 里抛 `bad argument`；标准 5.4 也一样，但 5.3+ 会先截断；跨版本前先 `math.floor`。
- **`load` 二进制模式**：`string.dump` 生成的字节码**不跨 LuaJIT 版本、不跨架构**——生产灰度时不要 cache 编译产物。
- **`os.getenv` 返回值类型**：LuaJIT 与 5.4 一致是字符串或 nil；但 5.1 上可能返回空字符串——统一用 `os.getenv("X") or "default"`。
- **`pcall` vs `xpcall`**：LuaJIT 与 5.1 的 `xpcall` 只接 2 个参数（函数 + handler）；5.4 允许额外参数——跨版本时用闭包传参。
- **协程 API**：LuaJIT 与 5.1 一致（`coroutine.resume` 返回 `ok, ...`；无 `coroutine.isyieldable`）；用到 5.4 独有 API（如 `coroutine.close`）会 `nil`。

# 总结

LuaJIT 是**"Lua 5.1 超集 + 独有 API"**，不是"新版 Lua"。写 OpenResty 里的 Lua 代码，把自己限制在 5.1 语法 + LuaJIT 扩展（`bit` / `ffi` / `jit`）里最稳；跨环境部署（比如同一份 Lua 也要跑在 openresty 与 standalone 上）时，把 5.3+ 特性都当不可用。语言层清楚了，[030.NYI 与 JIT 失效](./030.NYI与JIT失效.md) 讲的就是"哪些操作会让 LuaJIT 编不出机器码"——那是这层兼容性之上的性能问题。
