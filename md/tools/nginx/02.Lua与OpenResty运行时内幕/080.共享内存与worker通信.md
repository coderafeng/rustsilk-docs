# 概述

Nginx 是多进程 worker 模型，`worker_processes N` 起 N 个进程；**进程之间内存隔离**，普通 Lua 变量、模块级 table、closure 里的状态都只在**当前 worker** 有效。要跨 worker 共享状态、限流计数、缓存路由表，OpenResty 提供 **`lua_shared_dict`**：一块 nginx 启动时 mmap 出来的共享内存 + 内置的 slab 分配器 + 红黑树 + LRU 队列 + 自旋锁。这一篇讲它的**结构、API、并发语义、性能边界与常见坑**。

# 内部结构

```
   Master 进程启动 → mmap(MAP_SHARED) → 一段 shm 内存
        │
        ├─── 所有 worker fork 后继承同一个映射 → 天然共享
        │
   ┌────────────────────────────────────────────────┐
   │  ngx_shared_zone                              │
   │  ├── name: "api_cache"                        │
   │  ├── size: 20 MB                              │
   │  ├── shm_ctx (slab allocator)                 │
   │  ├── rbtree (key → node)                      │
   │  ├── lru_queue (最近使用顺序)                  │
   │  └── mutex (shmtx: 跨进程自旋锁 + 阻塞锁)      │
   └────────────────────────────────────────────────┘

   节点结构 (ngx_http_lua_shm_node)：
   ┌────────┬──────────┬────────┬─────────┬────────┐
   │ key    │ key_len  │ value  │ data_len│ expires│
   │ (bytes)│ (u32)    │ (bytes)│ (u32)   │ (ms)   │
   └────────┴──────────┴────────┴─────────┴────────┘
```

- **slab allocator**：nginx 自带的共享内存分配器，按页（4KB）+ 分级小对象；比 malloc 快、碎片可控。
- **红黑树**：key 查询 O(log n)；key 是二进制安全（可含 `\0`），Lua 字符串直接对比。
- **LRU 队列**：空间不够时从队尾驱逐；`get` 会把节点提到队首。
- **锁**：默认粗粒度**整表读写锁**——所有操作互斥；高并发热点会成瓶颈。

# 声明与访问

## 1) 声明

`nginx.conf` 的 `http{}` 里：

```nginx
lua_shared_dict api_cache     20m;
lua_shared_dict locks         1m;
lua_shared_dict rate_limit   16m;
```

**必须声明才能用**；未声明的 dict 在 Lua 里是 `nil`。大小 1KB 起，越大越好（但受 shm 与内存限制）。

## 2) Lua 端拿到引用

```lua
local cache = ngx.shared.api_cache
local ok, err = cache:set("user:42", '{"name":"rafeng"}', 60)   -- TTL 60s
local val = cache:get("user:42")
```

**每次 `ngx.shared.xxx` 都会走 metatable 查找返回 dict 对象**——热路径请缓存引用：

```lua
local cache = ngx.shared.api_cache   -- 模块顶层 local
```

# 核心 API

| 方法 | 语义 | 备注 |
|-----|------|-----|
| `set(key, value, ttl?, flags?)` | 覆盖写 | value 支持 string/number/boolean，**不支持 table** |
| `safe_set(...)` | 空间不足时**不驱逐**直接失败 | 用于容量敏感的写 |
| `add(key, value, ttl?, flags?)` | 只在 key **不存在**时写 | 原子性检查+写 |
| `replace(key, value, ttl?, flags?)` | 只在 key **已存在**时写 | |
| `get(key)` → `value, flags` | 读 | 值被序列化，number 会保留类型；string 原样 |
| `incr(key, num, init?, ttl?)` | 原子 +N；`init` 是首次的起点（含 num） | 计数器/限流核心 |
| `delete(key)` | 删 | 无 TTL 回收，立即释放 slab |
| `flush_all()` | 清空 | 但**保留 slab 内存**（延迟回收） |
| `capacity()` / `free_space()` | 总容量 / 剩余字节 | 空间监控 |
| `get_keys(n)` | 返回前 n 个 key | 会拷贝，大 dict 慎用；有 `flush_expired` 补充 |
| `flush_expired(max_count?)` | 清除已过期项 | 定期跑，减少访问到过期项的机会 |
| `force_flush_expired()` | 无视 LRU 立即清 | 危险 |

`flags` 是可选 32-bit 整数，业务自己用作版本号/类型标签，`get` 一并返回。

# 并发语义

**关键**：`lua_shared_dict` 的**每个方法内部是加锁的**，跨 worker 是**原子的**。但**多个方法之间不原子**：

```lua
-- ❌：两个进程可能同时读到 old → 都判定 → 都 set
local v = cache:get("k")
if v == nil then
    cache:set("k", expensive())
end

-- ✅：add 是原子的 check-and-set
local ok = cache:add("k_lock", true, 5)   -- 5s 锁
if ok then
    local val = expensive()
    cache:set("k", val)
    cache:delete("k_lock")
end

-- ✅：incr 天然原子，做计数器/限流最合适
local cur, err, forcible = cache:incr("hits", 1, 0)
```

`incr` 的 `forcible` 返回值：`true` 表示这次写入触发了 LRU 驱逐（容量不够）。

# 分布式限流的最小实现

```lua
-- access_by_lua_file lualib/app/ratelimit.lua
local dict = ngx.shared.rate_limit
local key = "rl:" .. ngx.var.http_x_client_id
local limit = 100                        -- 每分钟 100 次
local current, err, forcible = dict:incr(key, 1, 0, 60)   -- TTL 60s
if not current then
    ngx.log(ngx.ERR, "shared dict incr failed: ", err)
    return ngx.exit(500)
end
if current > limit then
    ngx.status = 429
    ngx.header["X-RateLimit-Remaining"] = 0
    return ngx.exit(429)
end
ngx.header["X-RateLimit-Remaining"] = limit - current
```

**令牌桶 / 滑动窗口** 的实现细节留给 05 章；这里说明 shared dict 是"够用"的原子存储。

# 性能边界

- **粗粒度锁**：热点 key 高并发时 worker 会争抢；生产压测常见 20-40 万 ops/s（4 worker，简单 set/get）；热点场景瓶颈在锁不是 CPU。
- **序列化开销**：`value` 只支持原生类型；业务对象请 `cjson.encode` 后存 string。
- **key 长度**：建议 <250 字节；太长时红黑树比较成本上升。
- **驱逐代价**：LRU 队列头尾指针移动是 O(1)，但 slab 释放与再分配有碎片成本；`forcible=true` 频繁出现就该扩 size。
- **不适合大 value**：>64KB 的对象别塞 shared dict（分配慢、拷贝慢），改走 Redis 或磁盘。

**监控指标**：`free_space()`、`capacity()`、`incr` 的 `forcible`、`get_keys(0)` 的 key 数。生产上通过 `timer.every(5, ...)` 打到 Prometheus（见 03 章）。

# 避坑

- **未声明就 `ngx.shared.foo`**：得到 `nil`，之后 `foo:set(...)` 报 `attempt to index local 'foo' (a nil value)`。
- **想 set table**：`cache:set("u", {name="x"})` 直接抛 `unsupported type`。要存对象请 `cjson.encode` 或 `string.pack`。
- **把 shared dict 当消息队列**：`get_keys` 无序，`incr` 原子但只针对单 key；请走 `lua-resty-redis` 或 nginx 上游消息队列。
- **TTL 单位混淆**：`set(k, v, 1)` 是 1 **秒**（浮点也行，精度到 ms），不是 ms。
- **reload 期间丢数据**：`lua_shared_dict` 的内容跨 reload **保留**（因为 mmap 在 master 层）；**restart 才丢**。别把 shared dict 当持久存储。
- **`flush_all` 后 free_space 没涨**：slab 延迟回收，`get_keys` 会返回空但内存还占着；重启进程才真正释放。
- **超大 dict（>1G）**：受 `worker_rlimit_nofile` 与内核 shm 上限影响，Linux 上单块 shm 建议 <4G。
- **worker 里的模块级变量 ≠ shared dict**：`_ENV.CFG = {...}` 只在当前 worker 生效，reload 后新 worker 会重置；`shared dict` 才是跨 worker 唯一原生通道。
- **别在 hot loop 里 `ngx.shared.xxx` 每次都取**：`local dict = ngx.shared.xxx` 缓存到 local；查 `resty.core.shdict` 有 FFI 加速但仍不如 local。

# 验证

```lua
-- 冒烟：跨 worker 真的能看到吗
content_by_lua_block {
    local d = ngx.shared.api_cache
    local key = "test:" .. ngx.worker.pid()
    d:set(key, 1, 5)
    ngx.say("wrote ", key, " pid=", ngx.worker.pid())
    -- 另一个 worker 的 curl 也能读到
}

location = /dump {
    content_by_lua_block {
        local d = ngx.shared.api_cache
        local keys = d:get_keys(0)
        for _, k in ipairs(keys) do ngx.say(k) end
    }
}
```

反复 `curl /dump`，worker 之间轮转，看到的 keys 集合应稳定——不一致就是没走 shared dict（用了模块级变量）。

# 总结

`lua_shared_dict` 是 OpenResty **唯一原生的跨 worker 通信通道**：slab + 红黑树 + LRU + 一把大锁，够用且原子。掌握它的**语义边界**（`set/add/replace/incr` 的原子性差别、TTL 单位、value 类型限制）与**性能边界**（粗锁、大 key 慢、大 value 别放）之后，就能写出限流器、鉴权缓存、动态路由表这些典型流量层组件。更高级的多级缓存与缓存风暴治理在 05 章性能优化篇展开。
