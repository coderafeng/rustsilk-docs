# 概述

OpenResty 里的 Lua **不是 standalone Lua**：跑在 nginx worker 里、由 lua-nginx-module 提供 `ngx.*` 命名空间、受限于事件循环模型、禁止某些"能阻塞 worker"的 API。这一篇是"落地规范"——写团队 luacheck 规则、Code Review 检查清单、新人上手手册都从这里出发。

# 与 standalone Lua 的三大差异

## 1) 有 `ngx` 全局表，但没有 `print`

OpenResty 里的 Lua 环境仍然有 `print` / `tostring` / `string` / `table` 全套标准库，但 **`print` 输出到 stderr**（不是 stdout），实际生产请一律 `ngx.log(level, ...)`。standalone 场景下 `resty` CLI 才走 stdout。

## 2) **禁用/半禁用** API 清单

以下 API 在**请求协程上下文**里被 lua-nginx-module 拦下或行为受限：

| API | 状态 | 原因 |
|-----|------|-----|
| `os.execute` / `os.exit` | **禁用** | 会 fork/exec 阻塞 worker |
| `os.remove` / `os.rename` / `os.tmpname` | **半禁用**（`os.getenv` 可用） | 阻塞 IO |
| `io.open` / `io.read` / `io.write` / `popen` | **禁用**（`lua_io` 默认关） | 同步文件 IO 会拖死 worker |
| `os.time` / `os.clock` | 可用 | 但更推荐 `ngx.now` / `ngx.update_time` |
| `math.random` | 可用 | worker 各自 seed，跨 worker 序列独立 |
| `require` | 可用 | `lua_code_cache on` 下模块表**每 worker 一份** |
| `debug.*` | 可用 | 但 `debug.sethook` 会关掉 JIT |
| `coroutine.*` | 可用 | 但**只在** lua-nginx-module 内部 yield 语义正确 |
| `string.dump` | 可用 | 但字节码不跨 LuaJIT 版本 |
| `setfenv` / `getfenv` | 可用 | 5.1 语义 |
| `jit.*` | 可用 | LuaJIT 扩展 |
| `ffi.*` | 可用 | LuaJIT 扩展 |

**开 `lua_io` 编译指令可以解开 `io.*`**，但**生产不要**：一个同步读大文件就够让整个 worker 卡几百毫秒。需要文件 IO 请走 `ngx.timer.at` + 单独 worker 或干脆外部服务。

## 3) **每 worker 独立状态**

- 模块级变量（`local M = {}` 里的字段、`_ENV.XXX`）**只在当前 worker 生效**；
- `lua_shared_dict` 是唯一原生跨 worker 通道（见 [080 篇](./080.共享内存与worker通信.md)）；
- **不要指望 `require("mod")` 单例是全进程的**——它有 N 个副本。

# Lua 常见坑（OpenResty 场景视角）

## 1) 全局变量污染

```lua
-- ❌：忘了 local，写入 _G
function handler()
    tmp = "leak"       -- 变成 _G.tmp，跨请求脏读
end

-- ✅
function handler()
    local tmp = "safe"
end
```

**规约**：`.luacheckrc` 里 `allow_globals = false`；`strict` 模式要求显式声明。

**跨请求脏读**：worker 里的 `_G` 是**每 worker 一份**且**跨请求持久**——一个请求写了 `ngx.var.foo = _G.counter`，另一个请求会看到累加值，比内存泄漏还难查。

## 2) `nil` vs `false` vs 空字符串

```lua
local v = ngx.var.arg_q     -- 未提供时是 nil
if not v then ... end        -- ✅
if v == false then ... end   -- ❌（永远不会真）

-- 空字符串与 nil
local v = ngx.var.arg_empty   -- 用户 ?empty= 时 v == ""
if not v then ... end          -- ❌ "" 是 truthy
if v == nil or v == "" then ... end  -- ✅
-- 或：if not (v and v ~= "") then ... end
```

## 3) `#` 与 nil 空洞

见 [050.table 与 metatable 内幕](./050.table与metatable内幕.md)：`#t` 遇 nil 不确定；`for i=1,#t` 在中间有 nil 时行为未定义。

## 4) 整数除与浮点

```lua
-- LuaJIT：一切数字是 double
print(7 / 2)      -- 3.5
print(7 // 2)     -- 报错：LuaJIT 没有 //
-- 整除：math.floor(7 / 2) = 3
```

## 5) `pcall` 里跨 yield

```lua
-- ❌：pcall 里有 cosocket
local ok, res = pcall(function()
    local sock = ngx.socket.tcp()
    sock:connect("127.0.0.1", 6379)   -- yield → 越过 pcall 边界，5.1 报错
    return sock
end)
```

LuaJIT 2.1 已经允许跨 yield（有对应实现），但**语义微妙**——pcall 里的错误处理可能吞掉 yield；稳妥做法是把 yield 挪到 pcall 外面。

## 6) `require` 缓存与热更新

```lua
-- 第一次
local m = require "app.mod"       -- 从 disk load 并 cache 到 package.loaded

-- 想热更新
package.loaded["app.mod"] = nil
local m2 = require "app.mod"      -- 重新 load
-- ⚠️：已有闭包/upvalue 引用 m 的地方不会切到 m2；不推荐
```

**结论**：热重载 Lua 请用 `lua-resty-hotreload`（改 nginx.conf 触发 reload，worker 换代）或 `lua_code_cache off`（调试），不要手工清 `package.loaded`。

## 7) 字符串与数字比较

```lua
print("1" == 1)      -- false，不同型
print("1" + 0 == 1)  -- true，字符串可隐式转数字
print(ngx.var.arg_n + 0)   -- 若 arg_n 为 nil 会抛 "attempt to perform arithmetic on a nil value"
```

**规约**：`tonumber(x) or 0`；别依赖隐式转换。

## 8) 短字符串与长括号

```lua
-- 短字符串里不能有 \n
local s = "line1
line2"                    -- ❌：编译错误

-- ✅ 长括号
local s = [[line1
line2]]
```

**Lua 长字符串里可以嵌套 `[` `]`**（不能同名长括号）；SQL 里带 `[` 时用 `[==[ ... ]==]`。

## 9) `..` 与数字串拼接优先级

```lua
print("a" .. 1 .. "b")      -- "a1b"
print(1 .. 2)               -- ❌：parse error (1 被读成 1.0 后 ".." 冲突)
print((1) .. (2))           -- "12"
```

数字与 `..` 冲突是 Lua 老坑，写成 `(1)..(2)` 或先 `tostring`。

## 10) `os.time()` 精度

`os.time()` 秒级，跨秒抖动明显；毫秒用 `ngx.now()`；高精度计时用 `ngx.update_time_info()` + `ngx.now()` 或直接 `ffi.C.gettimeofday`。

## 11) `os.date("*t")` 里的时区

LuaJIT 里 `os.date` 依赖 C 库的 `localtime`，**跟 nginx worker 启动时的 TZ 走**——`TZ=Asia/Shanghai` 环境正确；Docker 里忘设 TZ 会拿到 UTC。安全做法：`ngx.today()` / `ngx.localtime()` / `ngx.http_time()`（走 resty.core.time，与 nginx 时区绑定一致）。

## 12) 表构造与浅拷贝

```lua
local a = {x=1, y={z=2}}
local b = a                       -- 引用
b.x = 99                          -- a.x 也变
b.y.z = 100                       -- a.y.z 也变（浅拷贝）

-- 手写深拷贝，或用 resty.deep_copy / planner.tableutils
```

# OpenResty 里独有的坑

## 13) 请求协程结束后 timer 抓引用

```lua
-- ❌：把 ngx.ctx 交给 timer
log_by_lua_block {
    local ctx = ngx.ctx                    -- 表引用
    ngx.timer.at(0, function()
        ngx.log(ngx.INFO, ctx.trace_id)     -- ctx 已被回收 → 可能读到 nil 或脏数据
    end)
}

-- ✅：只传纯值
log_by_lua_block {
    local trace_id = ngx.ctx.trace_id
    ngx.timer.at(0, function()
        ngx.log(ngx.INFO, trace_id)
    end)
}
```

## 14) `pcall(require, "xxx")` 与 resty.core 加载

`resty.core` 会重写 `require`；加载顺序错了会让某些模块**在 resty.core 生效前**拿到旧版 `ngx.*` 函数的引用（作为 upvalue 缓存）。安全顺序：

```nginx
init_by_lua_block {
    require "resty.core"       -- 第一件事
    -- 再 require 其他
}
```

## 15) `set_by_lua_*` 里的 `error`

`set_by_lua_block` 只能 return 字符串/数字，**不能 yield、不能 error**；error 会让整个 worker 崩，不是只让请求失败。要"取值失败就置空"就 return `""`。

## 16) `_` 前缀不是"私有"约定，Lua 里就是普通变量

团队规范里如果靠 `_internal` 判"不要动"，Lua 层不做保护；真要保护用 metatable `__newindex` 拦（但见 [050 篇](./050.table与metatable内幕.md) 说函数版 `__newindex` 慢）。

# 编码规范建议（团队可直接抄）

**luacheck 配置 `.luacheckrc`**：

```lua
std = "luajit"
globals = { "ngx", "ndk" }
allow_defined = false           -- 全局必须显式声明
max_line_length = 120
unused = true                   -- 报未使用变量
redefined = true                -- 报重定义
```

**必守的 5 条硬约束**：

1. **所有变量都 `local`**——除非刻意写 `_ENV`。
2. **热路径禁用 `..`、`tostring`、`string.format`**——用 `table.concat` / `resty.string`。
3. **`ngx.*` API 调用先看阶段限制**（[01/070](../01.OpenResty起步/070.请求处理阶段总览.md) 表）。
4. **`require` 全部在文件顶层**——别在函数里 `require`（除非懒加载）。
5. **禁止 `io.*` / `os.execute` / `os.exit`**——luacheck 里显式屏蔽。

**推荐做法**：

- 日志一律 `ngx.log`；级别 `DEBUG` 只在 `--with-debug` 环境开。
- JSON 走 `cjson.safe`；解析失败判 `nil, err`，不 `pcall(cjson.decode, ...)`。
- 模块文件顶 `local _M = {}` + 末尾 `return _M`，中间不写全局。
- Timer 里判 `premature`；`ngx.timer.at(0, ...)` 而不是同步做重活。

# 验证

**luacheck 冒烟**：

```bash
luacheck --config .luacheckrc lualib/
```

**OpenResty 侧运行时约束**：写一段最小 handler 试：

```nginx
location /check {
    content_by_lua_block {
        local ok, err = pcall(os.execute, "echo hi")
        ngx.say("os.execute=", ok, " ", err or "")   -- 期望 false, "API disabled"
    }
}
```

`error.log` 里能看到 `API disabled in the context of content_by_lua*`。

# 总结

OpenResty 里的 Lua = **LuaJIT 5.1 语法 + nginx 事件循环 + `ngx.*` API + worker 隔离**。三件事最要紧：**API 禁用清单**（`io.*` / `os.execute` / 阶段限制）、**worker 状态独立**（别把全局变量当共享状态）、**协程边界**（`pcall` 跨 yield、timer 里的引用捕获）。把这三条 + luacheck 硬约束落到 CI，团队代码质量就有下限。02 章十篇到此结束，转 03 章核心 API（`cosocket`、`shared dict` 的高级用法）与 05 章性能优化篇。
