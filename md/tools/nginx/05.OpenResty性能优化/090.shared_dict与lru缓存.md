# 概述

**缓存分层**是 OpenResty 性能优化的最大杠杆。shared_dict 提供跨 worker 的 L2；`lua-resty-lrucache` 提供每 worker 的 L1。本文讲怎么用这两层，以及如何避坑。

# 三层缓存模型

```text
请求 → [L1: worker 本地 lru] 命中 → 返回
        ↓ miss
      [L2: shared_dict]      命中 → 回 L1、返回
        ↓ miss
      [L3: 上游 Redis / DB]  命中 → 回 L2、L1、返回
        ↓ miss
      回源 + 反向填三层
```

**每一层的目的**：
- **L1** 消除跨进程锁（`shared_dict` 全局锁）；
- **L2** 让多 worker 复用同一份数据；
- **L3** 提供持久化和跨机器共享。

# L1：`lua-resty-lrucache`

```lua
-- 文件顶
local lrucache = require "resty.lrucache"
local cache, err = lrucache.new(200)      -- 最多 200 项
if not cache then error("failed: " .. (err or "unknown")) end

-- 每次请求
local v = cache:get("key")
if not v then
    v = compute_expensive("key")
    cache:set("key", v, 60)               -- 60s TTL
end
ngx.say(v)
```

**关键点**：
- **每 worker 独立**：`worker_processes 4` → 4 份 cache；一致性靠 TTL；
- **LRU** 淘汰：容量满时按最近使用顺序丢；
- **不占用 shared_dict 内存**；纯 Lua VM；
- 单 worker 命中率 = 数据热度决定；跨 worker 命中率不共享。

# L2：`shared_dict` 用法

```nginx
lua_shared_dict my_cache 64m;
```

```lua
local sh = ngx.shared.my_cache

local v, flags = sh:get(key)
if not v then
    v = fetch_from_upstream(key)
    if v then
        sh:set(key, v, 30)                -- 30s TTL
    end
end
```

**要点**：
- value 必须是 number / bool / string；复杂数据先 `cjson.encode`；
- 全局锁 = **写多必慢**：把写频率降下来（见 100 缓存风暴）；
- 容量估算：`峰值 QPS × TTL × value 平均字节` × 1.5（LRU 冗余）。

# L1 + L2 组合

```lua
local lrucache = require "resty.lrucache"
local l1, _ = lrucache.new(500)
local l2 = ngx.shared.my_cache

local function get(key)
    -- L1
    local v = l1:get(key)
    if v ~= nil then return v end
    -- L2
    v = l2:get(key)
    if v ~= nil then
        l1:set(key, v, 5)                 -- L1 TTL 短、避免陈旧
        return v
    end
    -- L3 / 回源
    v = fetch_origin(key)
    if v ~= nil then
        l1:set(key, v, 5)
        l2:set(key, v, 60)
    end
    return v
end
```

**TTL 分层**：`L1 < L2 < L3`。L1 5s、L2 60s、L3 无 TTL 或长期。**L1 短 TTL** 是防陈旧的关键。

# 命中率与观测

```lua
-- /metrics
local hits_l1, misses_l1 = 0, 0
local hits_l2, misses_l2 = 0, 0

-- 在 get(key) 里计数（模块级变量）
local sh = ngx.shared.metrics
sh:incr("cache_l1_hit", 1, 0)
sh:incr("cache_l1_miss", 1, 0)
```

Prometheus 抓取：

```text
cache_l1_hit  108234
cache_l1_miss 12233
cache_l2_hit  9870
cache_l2_miss 2363
```

**健康区间**：L1 hit 80%+；L2 hit 60%+（相对 L1 miss）；miss 打到 L3 的 <20%。

# 一个反例：把 lrucache 存到全局

```lua
-- 反例：污染 _G，跨 reload 残留
_L1_CACHE = lrucache.new(200)

-- 正例：文件顶 local + 只在 init_worker 起一次
local l1
init_worker_by_lua_block {
    l1 = lrucache.new(200)
}
```

**`lua_code_cache on` 时，文件顶 `local` 已经是"每 worker 一份"**——不需要挂全局。

# 避坑

- **L1 短 TTL**：跨 worker 一致性靠 L1 TTL 撑住；L1 长 TTL = 数据陈旧；
- **value 大小**：shared_dict 单 value 太大（>1MB）会撑爆 slab；用 hash 分桶或换 Redis；
- **cache stampede**：热门 key 过期瞬间成千上万请求回源；见 [100.缓存风暴治理](./100.缓存风暴治理.md)；
- **LRU 不是 LFU**：热点变化时 LRU 会淘汰刚建的数据；小 L1 + 大 L2 缓解；
- **别把 lru 当队列用**：它按访问频率淘汰，可能丢新写的项。

# 总结

- L1 = `lua-resty-lrucache`（每 worker，微秒）；
- L2 = `lua_shared_dict`（跨 worker，几十微秒 + 全局锁）；
- L3 = Redis / DB；
- TTL 分层：L1 < L2 < L3；
- 命中率必须打指标；L1 80%+ 才算合理。
