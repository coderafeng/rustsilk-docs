# 概述

前三篇（010 阻塞、020 字符串、030 table）都是"具体 API 层面"的优化。这篇把这些约束汇总成一份 **编码纪律**——新写的 Lua 代码过这份清单就基本没问题。

# 十条硬约束

## 1. 局部变量优先

```lua
-- 反例：全局
counter = counter + 1

-- 正例：local + upvalue
local counter = 0
local function inc() counter = counter + 1 end
```

**理由**：LuaJIT 对 local 变量访问是**寄存器**级；全局是 hash lookup（`_G` 表）。热路径能差 5-10x。

## 2. 函数顶部一次性 `local` 抽库

```lua
-- 反例：反复 require / 索引
function handle()
    local cjson = require "cjson"
    return cjson.encode({...})
end

-- 正例：文件顶部
local cjson = require "cjson"
local ngx.say = ngx.say                   -- 甚至 ngx.* 也能缓存

function handle()
    return cjson.encode({...})
end
```

## 3. 避免闭包在热路径

```lua
-- 反例：每请求新建闭包
function handle()
    local items = get_items()
    local sum = 0
    table.sort(items, function(a, b) return a.k < b.k end)   -- 每次新建 anonymous fn
end

-- 正例：upvalue 一次
local function by_k(a, b) return a.k < b.k end
function handle()
    local items = get_items()
    table.sort(items, by_k)
end
```

**代价**：闭包 = 一次 proto + 一次 upvalue 分配；高频创建 = GC 频繁。

## 4. 循环外算常量

```lua
-- 反例：
for i = 1, 1e6 do
    process(i * (2 * math.pi))
end

-- 正例：
local TWO_PI = 2 * math.pi
for i = 1, 1e6 do
    process(i * TWO_PI)
end
```

LuaJIT 会常量折叠算术表达式，但 `math.pi` 是全局读取，无法折叠。

## 5. 类型稳定的变量

```lua
-- 反例：v 有时是 number 有时是 nil
local v
if cond then v = tonumber(s) end
return v + 1                  -- 出错 / JIT 需 guard

-- 正例：
local v = tonumber(s) or 0
return v + 1
```

**JIT 对类型稳定的变量能省 guard**。一个变量"有时是 X 有时是 Y"会拖慢整段 trace。

## 6. 别混用整数和浮点

```lua
-- 反例
local i = 0
for k = 1, 100 do i = i + 0.5 end      -- 中途从 int 变 float，JIT 断

-- 正例
local x = 0.0
for k = 1, 100 do x = x + 0.5 end
```

LuaJIT 里 int / float 是两种表示；一个"变量"跨类型 = 每次都要 tag 检查。

## 7. `pcall` 少用，用返回值约定

```lua
-- 反例
local ok, err = pcall(risky)
if not ok then return nil, err end

-- 正例
local res, err = safe_risky()
if not res then return nil, err end
```

**理由**：`pcall` 本身有开销；LuaJIT 遇到 `pcall` 会结束当前 trace。库函数返回 `nil, err`，业务代码不 pcall。

## 8. 大 if-else 用 dispatch table

```lua
-- 反例
if op == "GET" then handle_get()
elseif op == "POST" then handle_post()
elseif op == "PUT" then handle_put()
-- ...
end

-- 正例
local DISPATCH = {
    GET  = handle_get,
    POST = handle_post,
    PUT  = handle_put,
}
local fn = DISPATCH[op]
if fn then fn() else return ngx.exit(405) end
```

12 个分支以上，dispatch table 快得多（hash 命中 vs 顺序比较）。

## 9. 别把 string 当数字算

```lua
-- 反例
local s = "1"
for i = 1, 1e6 do s = s .. i end       -- 灾难 O(n²)

-- 正例
local parts = {}
for i = 1, 1e6 do parts[i] = tostring(i) end
local s = table.concat(parts)
```

## 10. 缓存 `ngx.var`

```lua
-- 反例：同一变量读多次
ngx.log(ngx.INFO, ngx.var.uri, " ", ngx.var.uri, " ", ngx.var.uri)

-- 正例
local uri = ngx.var.uri
ngx.log(ngx.INFO, uri, " ", uri, " ", uri)
```

**`ngx.var.xxx` 每次都走 C 侧的 regex 缓存查询**（`ngx_http_lua_var_get`），100ns 一次；重复读浪费。

# luacheck 规则集

`.luacheckrc`：

```lua
std = "luajit"
globals = { "ngx", "ndk" }
max_line_length = 120
unused = false              -- 允许 _ = fn() 忽略返回值

-- 严格打开的检查
allow_defined = false       -- 禁止全局隐式定义
module = false
cache = true

-- 排除生成代码
exclude_files = { "vendor/**" }
```

**CI 里跑**：

```bash
luacheck lib/ t/ --no-color
```

十条硬约束里 #1（local 优先）、#7（pcall 少用）都能被 luacheck 提醒。

# 一条性能回归测试模板

```lua
-- 每次修改热路径 Lua，跑一次基准
local function bench(name, iters, fn)
    collectgarbage("collect")
    local t0 = ngx.now()
    for i = 1, iters do fn() end
    local dur = (ngx.now() - t0) * 1000
    print(string.format("%-20s %8.2fms (%.0f ns/op)", name, dur, dur * 1e6 / iters))
end

bench("dispatch table", 1e6, function()
    return DISPATCH["GET"]
end)
```

**门槛**：单次改动导致基准劣化 >10% 就回滚。

# 避坑

- **过度优化伤可读性**：#6 类型稳定、#8 dispatch table 只用在**热点函数**；普通代码怎么清晰怎么来。
- **优化前必测**：见 080 火焰图；猜的性能坑 80% 不是主因。
- **`local ngx.say = ngx.say`**：只在**每请求调几百次**以上才值得；否则反而伤可读性。

# 总结

- local 优先，库上提到文件顶；
- 热路径不建闭包、不 pcall、不混 int/float；
- 大 if-else → dispatch；
- 缓存 `ngx.var`；
- luacheck + 微基准守住下限。
