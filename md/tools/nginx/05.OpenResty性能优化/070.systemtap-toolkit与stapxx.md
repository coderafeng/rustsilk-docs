# 概述

**systemtap**（stap）是 Linux 上的动态插桩工具，能在**运行时**给 C 代码打探针，性能开销可控。OpenResty 官方基于它做了 **systemtap-toolkit** 和上层封装 **stapxx**，把"分析 nginx 进程在做什么"这件事标准化。

# 三者关系

```text
systemtap        ← Linux 内核级探针框架（要 root + debuginfo）
   ↓
systemtap-toolkit ← 章玉峰写的一堆 .stp 脚本，针对 nginx/OpenResty
   ↓
stapxx (sxx)     ← 参数化 / 组件化封装；用户只写表达式
```

**结论**：日常用 `stapxx`；stapxx 覆盖不到就手写 `.stp`；两者都需要 systemtap 环境。

# 安装

```bash
# Ubuntu / Debian
sudo apt install -y systemtap stapserver
sudo apt install -y openresty-dbgsym            # debug symbols

# 验证
stap -e 'probe begin { println("hello"); exit() }'
```

**必需**：内核 debuginfo + OpenResty 二进制的 debuginfo。生产发行版通常要单独装。

# 常用探针（systemtap-toolkit）

## 1. `ngx_http_lua_socket_tcp_send.stp`

**问题**：某段时间 cosocket send 到底在写什么？

```bash
sxx cosocket-send -p BIN=/usr/local/openresty/bin/openresty
# 输出：每 send 一次一行；字段：pid, tid, bytes, conn, addr
```

## 2. `find-lua-mps.stp`

**问题**：LuaJIT 分配了多少 memory per second？

```bash
sxx find-lua-mps -p BIN=/usr/local/openresty/bin/openresty \
                -p INTVL=5                   # 每 5 秒报告一次
# 输出：MPS = 21.34 MB/s
```

**用途**：QPS 稳定但内存涨 → 看 MPS；MPS 高 = Lua 分配过多（见 030）。

## 3. `lua-stap-perf.stp`

**问题**：热点 Lua 函数是哪几个？

```bash
sxx lua-stap-perf -p BIN=/usr/local/openresty/bin/openresty -- sleep 30
# 生成 perf.data → FlameGraph
```

**输出**：Lua 层的火焰图（详见 [080.wrk 与火焰图](./080.wrk与火焰图定位瓶颈.md)）。

## 4. `timer-profile.stp`

**问题**：哪个 timer 跑了多久？

```bash
sxx timer-profile -p BIN=/usr/local/openresty/bin/openresty -- sleep 60
```

**输出**：`timer cb 名称 + 平均耗时 + 调用次数`。timer 卡 worker 时必备。

## 5. `hotcall.stp`

**问题**：nginx 侧哪个 C 函数最热？

```bash
sxx hotcall -p BIN=/usr/local/openresty/bin/openresty -- sleep 30
```

**输出**：Top 20 函数 + 命中次数。

# stapxx 语法

`stapxx` = "systemtap + Lua 表达式"，让你**在命令行里写 probe handler**：

```bash
sxx --e='probe begin { printf("start\n") }
     probe process("/usr/local/openresty/bin/openresty").function("ngx_http_process_request").call {
         printf("req pid=%d uri=%s\n", pid, user_string($r->uri->data))
     }' \
--skip-handler-check
```

**难点**：熟悉 systemtap 语法 + C 结构体字段。大多数场景用官方 toolkit 里的现成脚本更快。

# 手写 `.stp` 示例：cosocket 慢连接

```c
-- file: slow-cosocket.stp
global latency = 0
global slow_count = 0

probe process("/usr/local/openresty/bin/openresty").function("ngx_http_lua_socket_tcp_read").return {
    if (elapsed > 1000000) {  # 100ms
        slow_count++
        printf("slow read: %d us, conn=%p\n", elapsed/1000, $s)
    }
}

probe timer.s(10) {
    printf("slow count: %d\n", slow_count)
    slow_count = 0
}
```

跑：

```bash
stap -g slow-cosocket.stp -x $(pgrep -f "nginx: worker" | head -1)
```

# 与其他观测手段的对比

| 手段 | 开销 | 侵入性 | 精度 | 适合 |
|------|------|--------|------|------|
| error.log | 中 | 需改代码 | 粗 | 常规运维 |
| Dashboard | 低 | 需配置 | 中 | 宏观状态 |
| stap / stapxx | **中**（10-30%） | **零** | 高 | 疑难杂症 |
| perf | 低 | 零 | 采样级 | CPU 火焰图 |
| bpftrace | 极低 | 零 | 高 | 内核 syscall |
| OpenTelemetry | 中 | 埋点 | 业务级 | 分布式追踪 |

**stap 的价值**：**生产环境零改动、零重启**，直接看到进程内部。

# 什么时候用

- 有 p99 毛刺但 perf 火焰图看不出问题 → **stap 探针看 Lua 层**；
- shared_dict 命中率莫名下降 → **stap 追 flush_expired 调用**；
- timer 拖 worker → **stap timer-profile**；
- cosocket 连接泄漏 → **stap 找 setkeepalive 未调路径**。

# 避坑

- **stap 上生产 = 谨慎**：一个 probe 可能拖慢进程 30%+；只短时开启；
- **无 debuginfo 会失败**：`WARNING: cannot find ...`；先装 `openresty-dbgsym`；
- **内核版本兼容**：systemtap 依赖内核 3.10+；CentOS 7 需 `kernel-devel`；
- **别 probe 热点函数**：`ngx_palloc` 一秒调 10 万次；探针自身开销爆炸。

# 总结

- systemtap-toolkit = 一堆针对 nginx 的 `.stp`；stapxx = 参数化上层；
- 常用五个脚本：`cosocket-send` / `find-lua-mps` / `lua-stap-perf` / `timer-profile` / `hotcall`；
- 生产零改动、动态插桩；开销中等，短时开启；
- 需要 debuginfo + root + 内核 3.10+。
