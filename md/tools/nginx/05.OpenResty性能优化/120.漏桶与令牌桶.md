# 概述

限流有两种主流算法：**漏桶**（Leaky Bucket）和**令牌桶**（Token Bucket）。前者强制匀速；后者允许突发。本文拆开两者的语义、Lua 实现和选型。

# 语义对比

```text
漏桶：请求进桶 → 桶匀速流出 → 桶满时新请求拒绝
       效果：绝对匀速；下游永远不被突发打爆

令牌桶：桶里存令牌；请求拿令牌才放行；桶按速率生产令牌
         效果：平均速率受控；短期突发可用光存量令牌
```

| 维度 | 漏桶 | 令牌桶 |
|------|------|--------|
| 输出速率 | 恒定 | 平均恒定、瞬时可变 |
| 突发容忍 | 完全不容忍 | 允许 ≤ capacity 的突发 |
| 反压下游 | 强 | 中 |
| 典型场景 | 严格速率的 API | 一般业务接口 |
| 实现难度 | 简单 | 简单 |

# Lua 实现

## 令牌桶

```lua
-- 状态存在 shared_dict；value 是 last_refill_ms，另外存 tokens
local sh = ngx.shared.buckets

local function check_rate(key, capacity, rate)
    local now_ms = ngx.now() * 1000
    local tokens, last_ms = sh:get(key)
    if not tokens then
        tokens, last_ms = capacity, now_ms
    else
        local delta = (now_ms - last_ms) / 1000 * rate
        tokens = math.min(capacity, tokens + delta)
    end

    if tokens >= 1 then
        tokens = tokens - 1
        sh:set(key, tokens, 5, last_ms)
        sh:set(key .. ":last", now_ms, 5)
        return true
    else
        sh:set(key, tokens, 5)
        return false
    end
end
```

**注意**：`tokens` 是 number；`last_ms` 通过 `flags` 存 shared_dict。上面代码简化：把两个字段合并成一个 table 或用两次 `set`；实际生产建议一次原子写。

## 漏桶

```lua
-- 简化：只存"上次允许时刻"；下次允许要 now - last >= 1/rate
local sh = ngx.shared.buckets

local function leaky_allow(key, rate)
    local now = ngx.now()
    local last = sh:get(key) or 0
    if now - last >= 1 / rate then
        sh:set(key, now, 5)
        return true
    else
        return false
    end
end
```

**这就是 nginx `limit_req` 的默认语义**（对应 leaky bucket，rate + burst 组合）。

# 与 `limit_req` / `limit_req_zone` 的对比

| 能力 | nginx 原生 | Lua 自建 |
|------|-----------|----------|
| 精度 | 毫秒 | 毫秒 |
| 维度 | 单变量（IP / header / uri） | 任意组合 |
| 动态配置 | 需 reload | shared_dict 秒生效 |
| 算法 | 漏桶（带 burst） | 任选 |
| 全局计数 | 每 worker 独立；跨机不同步 | 同左；也可 Redis 全局 |

**能用 nginx 原生命令搞定的**，别用 Lua：更快、更省。

**只有以下情形才上 Lua**：
- 动态阈值（从配置中心拉）；
- 多维组合 key（user + api + tenant）；
- 需要自定义响应体；
- 全局（跨机）限流；
- 令牌桶语义。

# 生产版：多维 + 动态阈值

```lua
-- access_by_lua_block
local sh = ngx.shared.ratelimit
local config_sh = ngx.shared.config

-- 从 config 拿规则；命中缓存 5s
local key_rule = "rule:" .. ngx.var.http_x_tenant .. ":" .. ngx.var.uri
local rule_json = sh:get(key_rule)
if not rule_json then
    rule_json = config_sh:get("rules")           -- 上游推送
    if rule_json then sh:set(key_rule, rule_json, 5) end
end
local rule = rule_json and cjson.decode(rule_json)

if rule and rule.rate then
    local ok = check_rate("rl:" .. key_rule, rule.capacity or rule.rate * 2, rule.rate)
    if not ok then
        ngx.status = 429
        ngx.header["Retry-After"] = "1"
        return ngx.exit(429)
    end
end
```

**特点**：
- key 多维：`tenant + uri`；
- 阈值来自配置中心；
- 命中缓存 5s，规则改动秒级生效；
- 429 + Retry-After 明确告知客户端。

# 全局 vs 本地限流

## 本地（每 worker 独立）

漏桶 / 令牌桶都存在 shared_dict；shared_dict **只在同一台机器的 worker 之间共享**。多机部署时每机各限各的：**总吞吐 = 单机限流 × 机器数**。

## 全局（跨机）

Redis + Lua：

```lua
-- INCR + EXPIRE 原子脚本
local script = [[
    local key = KEYS[1]
    local window = tonumber(ARGV[1])
    local limit = tonumber(ARGV[2])
    local cur = redis.call('INCR', key)
    if cur == 1 then redis.call('EXPIRE', key, window) end
    if cur > limit then return 0 end
    return 1
]]
local ok = redis:eval(script, 1, "rl:" .. key, 1, 1000)
```

**代价**：每次请求 +1 次 Redis 往返（~1ms）；Redis 挂了限流失效。**只用在真正需要全局配额**的场景。

# 避坑

- **`shared_dict` value 不能同时存 tokens 和 last**：用 flags（只能存 number）或序列化成 string；
- **精度**：`ngx.now()` 缓存！限流里要 `ngx.update_time()` 或用 `ngx.req.start_time()`；
- **令牌桶 refill 计算**：`(now - last) * rate` 是浮点；用 `math.floor` 防抖动；
- **burst 语义**：capacity 决定"最大瞬时突发"；配 rate 时 `capacity = rate × 允许突发秒数`；
- **Redis 全局限流的雪崩**：Redis 挂了所有请求全放过；做降级 fallback。

# 总结

- 漏桶 = 匀速；令牌桶 = 允许突发；
- 能用 `limit_req` 就别用 Lua；
- 动态、多维、全局才写 Lua；
- Redis 全局 + 本地双保险。
