# 概述

前面几节把限流讲透了。这一节回答**为什么 OpenResty 是"动态化"的杀手锏**——不是因为它快，而是因为它是**唯一能在请求路径上做完全动态决策**的通用网关。

# "动态"的三个层次

| 层次 | 含义 | 谁能做到 |
|------|------|---------|
| L1 配置动态 | 不改代码、`reload` 生效 | nginx / Envoy / HAProxy |
| L2 逻辑动态 | 改 Lua 代码，`reload` 或热更生效 | **OpenResty** / Envoy Wasm |
| L3 数据动态 | 每请求现拉规则现算，无需 reload | **OpenResty**（shared_dict + cosocket） |

**OpenResty 的独特性在 L2 + L3 都做得到**：Lua 代码本身是"数据"，shared_dict 让配置和代码状态都成了"可热改的数据"。

# 三个真实动态场景

## 场景一：秒级灰度发布

**传统**：改 nginx.conf 里 upstream → `reload` → 30 秒生效；reload 期间新旧 worker 并存。

**OpenResty**：

```lua
-- balancer_by_lua_block
local sh = ngx.shared.canary
local pct = sh:get("canary_pct") or 0            -- 0-100
local r = ngx.random(1, 100)
if r <= pct then
    ngx.balancer.set_current_peer(CANARY_HOST, CANARY_PORT)
else
    ngx.balancer.set_current_peer(STABLE_HOST, STABLE_PORT)
end
```

**改灰度比例**：`curl -X POST http://admin/canary -d 'pct=10'` → `sh:set("canary_pct", 10)`。**秒级生效、零 reload**。

## 场景二：按用户动态降级

大促期间，非会员用户返回简化页；会员不受影响：

```lua
-- rewrite_by_lua_block
local sh = ngx.shared.degrade
if sh:get("mode") == "peak" then
    local user_type = ngx.ctx.user_type or lookup_user_type()
    if user_type ~= "vip" then
        return ngx.exec("/simplified" .. ngx.var.uri)
    end
end
```

**开关切换**：管理员 `curl -d 'mode=peak'`；不用发版、不用改代码。

## 场景三：路由规则实时推送

```lua
-- 每 5 秒从服务发现拉路由表
init_worker_by_lua_block {
    ngx.timer.every(5, function(prem)
        if prem then return end
        local routes = fetch_routes_from_registry()     -- Nacos / etcd
        if routes then
            ngx.shared.routes:set("current", routes, 15)
        end
    end)
}

-- 每请求按路由表匹配
local routes = cjson.decode(ngx.shared.routes:get("current") or "{}")
```

**任何时刻**新加/删除路由都 <5s 生效；比 reload 快得多。

# 杀手级特性清单

## 1. `_by_lua_block` 里的**任何**行为都能被配置驱动

```lua
access_by_lua_block {
    local policy = load_policy_from_shdict()
    if policy.auth_type == "jwt" then check_jwt()
    elseif policy.auth_type == "oauth2" then check_oauth()
    elseif policy.auth_type == "custom" then check_custom()
    end
}
```

配置中心一发改，鉴权方式就换。

## 2. **代码本身**可以下发

```lua
-- 极端：把 Lua 代码字符串塞进 shdict，load() 后调用
local code_str = sh:get("handler_body")
local chunk = assert(load(code_str))
chunk()
```

**慎用**：这是 RCE 后门；只用于内部配置中心，加签名验证。**但确实做到了"完全动态"**。

## 3. 每请求现决策，无 reload

Envoy 的 Wasm filter 也能"配置动态"，但**逻辑改动还是要重编 Wasm 模块**（秒-分钟）；OpenResty 里 Lua 就是文本，改完 `reload` 或不改代码只改 shdict 都行。

# "动态"的代价

- **配置在 shared_dict 里 = 状态复杂**：一次 bug 让 shdict 数据污染 → 全站故障；必须有**校验 + 版本 + 回滚**；
- **代码热更 = 缺类型检查**：Lua 是动态类型，改代码没编译错误；测试必须严；
- **timer + shdict = 竞态**：见 03 章 040；CAS/锁不能省；
- **动态 regex / dispatch 爆炸**：`lua_regex_cache_max_entries` 上限；动态规则数量控好。

# 生产纪律

上"动态"之前，必须做到：

1. **配置版本化**：shdict 里带 `version` 字段；出问题能秒回滚；
2. **配置校验**：写入前 schema 校验；拒绝非法；
3. **配置变更审计**：谁在何时改了什么；
4. **限流兜底**：动态规则挂了时要有静态默认；
5. **代码路径覆盖测试**：所有 if-else 分支都有测试；
6. **灰度**：新配置先发 10%、50%、100%。

# 避坑

- **动态 ≠ 无脑动态**：能预编译的先固化（比如 regex）；
- **别把主逻辑塞 shdict**：只放阈值 / 开关 / 路由表；代码文件仍是主干；
- **reload 也别忘了**：动态改配置后 `nginx -s reload` 有时仍必要（比如 listen 端口）；
- **配置回滚要有幂等**：同一份配置发两次不炸。

# 总结

- OpenResty = L2 + L3 都能动态的通用网关；
- 三大杀手场景：灰度、按用户降级、路由实时推送；
- 代价：状态复杂、类型无保障、竞态；
- 生产纪律：版本、校验、审计、限流、测试、灰度。
