# 概述

**缓存风暴** = 大量请求同时 miss，把压力全部砸到后端。三种典型形态：**雪崩**（同时过期）、**击穿**（热点 key 过期）、**穿透**（不存在的 key 反复回源）。本文给每一类的**治理**方案。

# 三大问题分类

| 现象 | 成因 | 影响 |
|------|------|------|
| 雪崩 | 同一批 key 集中过期 | 后端瞬时 QPS 爆炸 |
| 击穿 | 单个热点 key 过期瞬间 | 该 key 上为并发回源 |
| 穿透 | 不存在的 key 反复查询 | 后端持续被无效流量攻击 |

# 治理一：TTL 打散（对雪崩）

```lua
-- 反例：所有 key 都 60s
sh:set(key, val, 60)

-- 正例：TTL ± 20% 抖动
local base = 60
local ttl = base + math.random(-12, 12)
sh:set(key, val, ttl)
```

**用 `ngx.random`**（见 [03 章 070](../03.OpenResty核心API/070.时间正则等常用API.md)），不用 `math.random`（协程不安全）。

**更彻底**：写入时按 key 哈希固定 TTL 偏移：

```lua
local off = ngx.crc32_short(key) % 30
sh:set(key, val, 60 + off)
```

# 治理二：互斥回源（对击穿）

## 手撸版

```lua
local sh = ngx.shared.locks

local function get_or_fetch(key)
    local v = sh:get(key)
    if v then return v end

    -- 抢锁：第一个 miss 的 worker 干活
    local got = sh:add("lk:" .. key, true, 5)      -- 5s 锁 TTL
    if not got then
        -- 别人正在拉；等一会儿再读
        for _ = 1, 20 do
            ngx.sleep(0.05)
            v = sh:get(key)
            if v then return v end
        end
        return nil, "timeout waiting for owner"
    end

    -- 只有 owner 到这里
    local ok, err = pcall(function()
        v = fetch_origin(key)
        if v then sh:set(key, v, 60) end
    end)
    sh:delete("lk:" .. key)                          -- 释放
    return v, err
end
```

## 用 `lua-resty-lock`（推荐）

```lua
local lock = require "resty.lock"
local locker = lock:new("locks", { timeout = 5 })

local v = sh:get(key)
if v then return v end

local elapsed, err = locker:lock("fetch:" .. key)
if elapsed then
    -- 拿到锁，回源
    v = fetch_origin(key)
    if v then sh:set(key, v, 60) end
    local ok = locker:unlock()
elseif err == "timeout" then
    -- 抢锁超时：直接读缓存或返回旧值
    v = sh:get(key)
end
return v
```

`lua-resty-lock` 内部也是 shared_dict + 轮询；封装了重试、超时、事件驱动。

# 治理三：负缓存 + 布隆（对穿透）

## 负缓存

对"确认不存在"的 key 也存进 shared_dict：

```lua
local v = sh:get(key)
if v == "__MISS__" then return nil end              -- 命中"不存在"标记
if v then return v end

v = fetch_origin(key)
if v then
    sh:set(key, v, 60)
else
    sh:set(key, "__MISS__", 30)                     -- 短 TTL 负缓存
end
```

**简单粗暴、90% 场景够用**。

## 布隆过滤器

数据总量大、"不存在" key 多（比如恶意攻击枚举用户 ID）时，用 `lua-resty-bloom-filter`：

```lua
local bloom = require "resty.bloom_filter"
local bf = bloom.new({
    dict_name = "bloom",
    hash_count = 8,
    capacity = 1e7,
    failure_rate = 0.01,
})

-- 启动时把有效 ID 灌进去
for _, id in ipairs(all_valid_ids) do bf:add(id) end

-- 请求时
if not bf:check(user_id) then
    return ngx.exit(404)                             -- 一定不存在；直接拒
end
-- 可能存在 → 走正常缓存 + 回源
```

**特性**：假阳性可控（1%），**假阴性无**——判定"不存在"绝对准确。

# 治理四：软过期（serve-stale）

对实时性不敏感的场景，`flags` 存"逻辑过期时间"：

```lua
-- 写入
local now = ngx.now()
sh:set(key, val, 300, now + 60)                   -- 物理 TTL 300、逻辑 TTL 60

-- 读取
local v, flags = sh:get(key)
if v then
    if flags and flags < now then
        -- 逻辑过期：仍返回旧值 + 异步刷新
        ngx.timer.at(0, function(prem)
            if prem then return end
            local fresh = fetch_origin(key)
            if fresh then
                sh:set(key, fresh, 300, ngx.now() + 60)
            end
        end)
    end
    return v
end
```

**效果**：用户永远拿到"能用的数据"，刷新走异步；击穿彻底消失。这是 **serve-stale-while-revalidate** 模式。

# 治理五：缓存预热

冷启动 / reload 时缓存全空，第一波流量必爆。做法：

```lua
-- init_worker_by_lua_block
local only_once = ngx.shared.warmup
if ngx.worker.pid() == ngx.shared.warmup:get("owner_pid") then
    local keys = hot_key_list()                    -- 从上游拉一份 top-N
    for _, k in ipairs(keys) do
        local v = fetch_origin(k)
        if v then sh:set(k, v, 60) end
        ngx.sleep(0)                                -- 让出 CPU
    end
end
```

**或**：CI/CD 里加一步 `warmup.sh`，用 wrk 打一遍流量再切流量。

# 组合示例：完整的多重防护

```lua
local function get_safely(key)
    -- 1. 主缓存 + 软过期
    local v, flags = sh:get(key)
    if v then
        if flags and flags < ngx.now() then
            _refresh_async(key)
        end
        return v
    end

    -- 2. 布隆挡穿透
    if not bf:check(key) then
        return nil, "definite miss"
    end

    -- 3. 抢锁防击穿
    local elapsed, err = locker:lock("f:" .. key)
    if err == "timeout" then return nil, "busy" end

    -- 4. double check
    v = sh:get(key)
    if v then locker:unlock(); return v end

    -- 5. 回源 + 写缓存（打散 TTL）
    v = fetch_origin(key)
    if v then
        sh:set(key, v, 300 + math.random(-30, 30), ngx.now() + 60)
    else
        sh:set(key, "__MISS__", 30)
    end
    locker:unlock()
    return v
end
```

**五层叠加**：软过期 + 布隆 + 锁 + double check + 打散 TTL。

# 避坑

- **锁 TTL 太短**：owner 拉取超时 → 锁自动释放 → 又一波并发进来；给足 5s+；
- **`unlock` 漏调**：pcall 保护；或 `lua-resty-lock` 的 `expire`；
- **布隆过滤器容量估小**：真实数据超上限，假阳性飙升；每次灌数据后监控；
- **serve-stale 的 refresh timer 无限堆**：同一 key 一秒内只起一次 timer（用 shared_dict `add` 去重）。

# 总结

- 雪崩 → TTL 打散；
- 击穿 → 互斥锁（`lua-resty-lock`）；
- 穿透 → 负缓存 / 布隆；
- 极致 → 软过期 serve-stale；
- 冷启 → 预热。
