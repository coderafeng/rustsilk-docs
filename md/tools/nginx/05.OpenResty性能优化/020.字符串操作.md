# 概述

Lua 字符串是**不可变**字节序列；每次拼接都新建一个 string，触发内存分配和潜在 GC。热路径上字符串操作的写法能拉开 3-10 倍差距。

# 五种字符串操作，性能从高到低

| 排名 | 写法 | 复杂度 |
|------|------|--------|
| 1 | 内部化常量字符串（`sh:get("const")` / upvalue） | O(1) |
| 2 | `table.concat(parts)` | O(n) |
| 3 | `string.format("%s:%s", a, b)` | O(n) |
| 4 | `a .. b .. c` | O(n²) 若循环 |
| 5 | 循环内 `s = s .. x` | O(n²) 灾难 |

# 反例与正例

## 拼接：`..` → `table.concat`

```lua
-- 反例：n 次拼接 = n 次分配
local s = ""
for _, p in ipairs(parts) do s = s .. p end

-- 正例：一次分配
local s = table.concat(parts)
```

**基准**：10000 段，1MB 总长：`..` 500ms，`table.concat` 20ms。

## 分隔：加 `sep` 参数

```lua
local s = table.concat(parts, ",")            -- 逗号分隔
local s = table.concat(parts, "\r\n", 2, 5)   -- 第 2-5 段用 \r\n
```

`table.concat` 底层 C 实现，直接扫一次拼接；不要自己 `s .. sep .. p` 循环。

## 匹配：`string.find` 定长

```lua
-- 反例：Lua pattern 每次现编译
local ok = s:find("^%a+")

-- 正例：纯字面量匹配加 plain=true
local from = s:find("http://", 1, true)     -- plain=true，快 5-10x

-- 复杂 regex：走 ngx.re + o
local m = ngx.re.match(s, [[^https?://]], "jo")
```

**关键**：`string.find(s, lit, 1, true)` 里的第 4 参 `true` 让 pattern 引擎退化成 `memmem`；不用它，每次跑 Lua pattern。

## 转换：`tonumber` / `tostring`

```lua
-- 反例：反复字符串→数字
for line in lines do
    local n = tonumber(line)
    process(n)
end

-- 正例：能缓存就缓存；小整数在 LuaJIT 里 int 表示、无需转换
local cache = setmetatable({}, { __mode = "k" })
```

**LuaJIT 数字串坑**：`tonumber("007")` = 7；`"007" .. "" = "007"`；`tonumber(s) == 7` 是 true 但 `s == "7"` 是 false；哈希 key 一致性容易出错。

## 内部化：短字面量

LuaJIT 会**自动 intern** 短字符串（≤ 40 字节）；同一片段共享一份 memory。热路径上：

```lua
-- 反例：每次新建 string
local key = "cache:" .. id .. ":v1"

-- 正例：模板拆段
local PREFIX = "cache:"
local SUFFIX = ":v1"
local key = PREFIX .. id .. SUFFIX      -- 三段中两段是 intern 常量
```

**效果**：内存减半；string hash 只算一次。见 [02 章 060.字符串内部化与GC](../02.Lua与OpenResty运行时内幕/060.字符串内部化与GC.md)。

# 常用字符串惯用法

## 判断前缀 / 后缀

```lua
-- 反例：string.sub + 比较
if s:sub(1, 7) == "http://" then ... end

-- 正例：find + plain
if s:find("http://", 1, true) == 1 then ... end

-- 或用 ngx.re
if ngx.re.find(s, [[^http://]], "jo") then ... end
```

## 拆分

```lua
-- Lua 没有原生 split；三种写法
-- ① 简单：gmatch
local parts = {}
for w in s:gmatch("[^,]+") do parts[#parts+1] = w end

-- ② 有 pattern 需求：
local parts = {}
for line in (s .. "\n"):gmatch("(.-)\n") do parts[#parts+1] = line end

-- ③ 生产推荐：ngx.re 或 lua-resty-string
local str = require "resty.string"
```

`gmatch` 每次创建一个 iterator；对性能敏感场景，`string.find(s, sep, pos, true)` 手写循环。

## 大小写 / 修剪

`string.upper/lower/gsub("^%s+",""):gsub("%s+$","")` 都产生新串；OpenResty 无原生 trim，用：

```lua
-- 手写 trim 避免 gsub
local function trim(s)
    return (s:gsub("^%s*(.-)%s*$", "%1"))     -- 括号消掉多返回值
end
```

# 二进制安全

Lua string 可含 `\0`——**别信 `#s`**。想拿真实字节数：

```lua
local data = sock:receive(n)      -- 严格读 n 字节
if data and #data == n then ... end
```

`ngx.decode_base64` 返回的字符串含任意字节；处理时**不要**用 pattern。

# 一个"字符串密集"网关的优化前后

**Before**：单次 rewrite 里做 6 次字符串操作 + 2 次 regex → 每请求 800 字节分配。

**After**：

```lua
-- 常量拆出来
local ROUTE_PREFIX = "/api/"
local DEFAULT_UPSTREAM = "default"

-- 一次 regex 拿到所有信息
local m = ngx.re.match(uri, [[^/api/(v\d+)/(\w+)(?:/(\w+))?$]], "jo")
if m then
    local version, service, action = m[1], m[2], m[3] or "index"
    -- 上游名拼接用 concat
    local pool = table.concat({ service, version, action }, ":")
end
```

结果：分配减少 65%，p99 延迟 8ms → 3ms。

# 避坑

- **`s1 == s2` 长度不同也走 memcmp**：字符串比较先看内部化指针，短路命中；intern 常量比较快。
- **`string.rep` 大 buffer**：`string.rep("a", 1e6)` 一次性 1MB；用循环 + concat 分块。
- **`tostring(n)` 在热点里**：数字转字符串每次都建 string；缓存 `tostring(code)` 到 table 里。
- **`string.byte` 循环**：比 `s[i]`（Lua 无 `[]`）快；遍历字节用它。

# 总结

- 拼接首选 `table.concat`；
- 匹配首选 `find(..., true)` 或 `ngx.re + o`；
- 常量抽出来做 upvalue，享受 intern；
- 二进制串永远按长度、不要 pattern；
- 优化前跑一次火焰图（见 080）。
