# 概述

线上出问题时"debug by print"太慢；OpenResty 有一套完整的调试手段：从**日志、REST debug、`ngx.log` 分级、`resty` 命令行 REPL、OpenResty Dashboard、SystemTap/eBPF 探针**逐层深入。本文一次盘点。

# 六层调试工具

```text
① error.log + 分级          最基础；一切从这里开始
② ngx.log 结构字段           加 trace_id、耗时；定位单请求
③ 命令行 resty               脱离 nginx 跑 Lua；单步调试
④ OpenResty Dashboard        可视化 timer / shdict / worker 状态
⑤ stapxx / systemtap         进程内动态探针；不改代码
⑥ ebpf / perf                内核级；火焰图与 syscall
```

# ① 日志分级

`error_log` 五级：`emerg` / `alert` / `err` / `warn` / `info`；`debug` 需要 `--with-debug` 编译（OpenResty 官方包一般带）。

**开发**：`error_log logs/error.log debug;` + `debug_arg all;`（`nginx.conf` 顶部）；日志爆量，但能看到 cosocket、shared_dict 每次操作。

**生产**：`warn` 或 `err`；Lua 里用 `ngx.log(ngx.WARN, ...)`。**永远别 INFO 起**——日志 IO 会成为瓶颈。

## 日志节流

```lua
local LAST_LOG = 0
function warn_throttled(msg)
    local now = ngx.now()
    if now - LAST_LOG < 1 then return end
    LAST_LOG = now
    ngx.log(ngx.WARN, msg)
end
```

**同类错误一秒一条**，避免打爆磁盘。

# ② 结构化字段

给每条日志加 `req_id` + `phase`：

```lua
local function slog(level, fmt, ...)
    local msg = string.format(fmt, ...)
    ngx.log(level, "[", ngx.var.request_id or "-", "] ",
                  "[", ngx.get_phase(), "] ", msg)
end

slog(ngx.INFO, "upstream=%s status=%d", upstream, status)
```

配合 `access_log` 里的 `$request_id` 就能全链路追踪。

# ③ `resty` 命令行

OpenResty 自带 `resty` = "LuaJIT + ngx API 子集"的 REPL：

```bash
$ resty
Welcome to the OpenResty resty CLI!
> = string.rep("ab", 3)
ababab
> = require "cjson".encode({a=1})
{"a":1}
> os.exit(0)
```

**能用的 ngx.\***：`ngx.re.*`、`ngx.encode_base64`、`ngx.now`、`ngx.log`。**不能**：`ngx.req`、`ngx.socket`（需要请求上下文）。

跑文件：

```bash
resty /tmp/test.lua
```

**调试纯 Lua 库**（不涉及 nginx 上下文）最快的入口。

## 单步调试

`resty` 支持 `-d` 起 Lua 调试器（MobDebug / zero_brain）：

```bash
resty -d /tmp/test.lua              # 监听 8172
# 用 ZeroBrain / VSCode Lua 插件连
```

**生产别开**——端口暴露、无鉴权。

# ④ OpenResty Dashboard

OpenResty 官方出的观测面板，走 nginx 状态页 + 一段 lua_app：

```nginx
http {
    lua_shared_dict prom_shm 10m;
    init_worker_by_lua_block {
        require("resty.prometheus").init()
    }
    location /metrics {
        content_by_lua_block { require("resty.prometheus").metric_text() }
    }
    location /dashboard/ {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

看：**worker CPU / connections / timer 数 / shared_dict 命中率**。

**指标**：`resty.prometheus` / `lua-resty-metrics` 都能出。

# ⑤ stapxx / systemtap

**动态探针、不改代码、不重启进程**——见 [070.systemtap-toolkit 与 stapxx](./070.systemtap-toolkit与stapxx.md) 详解。

典型用法：

```bash
# 抓 cosocket 每次 send 的字节数
sxx -e 'cosocket-send.stp' -p BIN=/usr/local/openresty/bin/openresty
```

# ⑥ ebpf / perf

**内核视角**：

```bash
perf top -p $(pgrep -f "nginx: worker")          # 实时热点
perf record -g -p <pid> -- sleep 30               # 采样
perf script | stackcollapse-perf.pl | flamegraph.pl > perf.svg
```

**bpftrace** 一行 syscall 计数：

```bash
bpftrace -e 'tracepoint:syscalls:sys_enter_* /pid == 1234/ { @[probe] = count(); }'
```

如果 worker 卡在 epoll_wait 之外的 syscall（比如 read file、DNS lookup）——**bpftrace 立刻抓出**。

# 一个"三分钟内定位"的排障套路

**症状**：p99 从 10ms 涨到 200ms。

```text
1. error.log 里有没有异常？ → 无
2. Dashboard 看 worker CPU：80% → Lua 忙
3. perf top：ngx_http_lua_socket_tcp 上热点 → cosocket
4. stapxx cosocket-send：每次 send 大小 → 1MB+
5. 查 nginx.conf：proxy_buffering off + 大响应 → 命中
```

**从"看日志"到"定位代码行"通常 3 步内**。

# 避坑

- **`error_log debug` 上生产 = 磁盘爆**：只在临时窗口开；用完关闭；
- **`resty` CLI 不带请求上下文**：测 `_by_lua` 里的代码路径要起真 nginx；
- **`stap` 需要 debug symbols**：OpenResty 官方包是 stripped；装 `openresty-external-openssl-debuginfo`；
- **`perf` 在非 root 下受限**：`/proc/sys/kernel/perf_event_paranoid` 调到 1。

# 总结

- 日志分级 + 结构化字段：最基础、必须做；
- `resty` CLI：Lua 库单测/调试；
- Dashboard：宏观状态；
- stapxx：不改代码的动态探针；
- perf/bpftrace：内核视角兜底。
