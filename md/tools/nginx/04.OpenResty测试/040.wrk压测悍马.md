# 概述

`wrk` 是一款用 C + Lua 编写的 HTTP 压测工具，在 OpenResty 社区里是**默认基准工具**——lua-nginx-module 的性能回归、shared_dict 优化、JIT 效果验证都用它。本文覆盖 `wrk`（吞吐模式）与 `wrk2`（固定速率模式）。

# 安装

```bash
git clone https://github.com/wg/wrk.git
cd wrk && make -j
sudo cp wrk /usr/local/bin/

# wrk2（固定速率 + latency 报告）
git clone https://github.com/giltene/wrk2.git
cd wrk2 && make -j && sudo cp wrk /usr/local/bin/wrk2
```

macOS：`brew install wrk`。Windows 走 WSL。

# wrk 三种模式

## 模式一：默认吞吐

```bash
wrk -t12 -c400 -d30s http://127.0.0.1:8080/api/hello
```

- `-t12` 12 个线程
- `-c400` 400 个长连接
- `-d30s` 跑 30 秒
- 报告：**RPS、传输量、平均/最大延迟、错误数**

## 模式二：固定速率（wrk2）

```bash
wrk2 -t4 -c128 -d60s -R10000 http://127.0.0.1:8080/api
```

`-R10000` = 每秒 10000 请求（**闭环变开环**）。**给延迟指标必须用 wrk2**：wrk 的 latency 会因为吞吐爆炸严重失真。

## 模式三：带 Lua 脚本

```bash
wrk -s POST.lua -t8 -c200 -d30s http://127.0.0.1:8080/api
```

`POST.lua`：

```lua
-- 初始化：每个 wrk 线程跑一次
wrk.method = "POST"
wrk.headers["Content-Type"] = "application/json"
wrk.headers["Authorization"] = "Bearer test-token"

-- 每个请求生成 body
local counter = 0
function wrk.request()
    counter = counter + 1
    wrk.body = string.format('{"id":%d,"name":"u%d"}', counter, counter)
    return wrk.format()
end

-- 响应处理（可选）
function wrk.response(status, headers, body)
    if status ~= 200 then
        io.stderr:write(string.format("bad resp: %d\n", status))
    end
end

-- 报告扩展（可选）
function wrk.done(last)
    io.write(string.format("total requests: %d\n", counter))
end
```

# 关键指标解读

wrk 输出示例：

```text
Running 30s test @ http://127.0.0.1:8080/api
  12 threads and 400 connections
  Thread Stats   Avg      Stdev     Max   +/- Stdev
    Latency    15.32ms    8.44ms 145.21ms   87.29%
    Req/Sec     2.18k   289.44     3.45k    65.50%
  781234 requests in 30.02s, 118.23MB read
Requests/sec:  26024.14
Transfer/sec:      3.94MB
```

- **`Req/Sec Avg × 12 threads` ≈ 26024**：整体吞吐；
- **Latency Avg 15ms Stdev 8ms Max 145ms**：波动大 → 有 GC 或后端抖动；
- **Requests 总数、字节数**：一致性核对；
- **`socket errors`** 单独列出来：connect / read / write / timeout 各自数量。

# wrk2 才有分位数

wrk 只给 avg/max/stdev；**看不到 p99/p99.9**。想拿延迟分布必须 wrk2：

```bash
wrk2 -t4 -c128 -d60s -R10000 --latency http://...
#   Latency Distribution
#      50%    5.23ms
#      75%    8.11ms
#      90%   12.44ms
#      99%   28.99ms
#      99.9%  75.11ms
#      99.999%  145.23ms
```

**基准报告至少给 p50/p90/p99**；avg 单值意义有限。

# 一个 OpenResty 基准脚本模板

```bash
#!/bin/bash
# bench.sh
HOST="127.0.0.1:8080"
PATH_="/api/hello"
RATE=${RATE:-50000}
DURATION=${DURATION:-60s}
THREADS=${THREADS:-8}
CONNS=${CONNS:-256}

for R in 10000 25000 50000 100000; do
  echo "===== @ ${R} req/s ====="
  wrk2 -t$THREADS -c$CONNS -d$DURATION -R$R --latency http://$HOST$PATH_
  sleep 5
done
```

**阶梯速率压测**：从低到高跑几档，观察延迟随速率的增长曲线，能定位"这台机器扛到多少 RPS 会崩"。

# wrk 常见坑

- **本机压本机**：wrk 自身可能吃满 CPU，被测服务被打不满；分两台机器；
- **端口耗尽**：`-c 10000` 单机容易 `cannot assign requested address`；调 `net.ipv4.ip_local_port_range`；
- **连接数 << 线程数**：`-t12 -c4` 意味着 8 个线程闲置；一般 `-c` 是 `-t` 的 4-8 倍；
- **keepalive 默认开**：`Connection: keep-alive` 是 wrk 默认；测冷启动要禁；
- **Lua 脚本里的 `math.random`**：wrk 内嵌 LuaJIT 5.1，种子相同 → 所有线程 body 相同。手动 `math.randomseed(wk.thread_id)`。

# wrk vs ab vs bombardier

| 工具 | 语言 | 分位数 | 开环 | Lua 定制 | 生态 |
|------|------|--------|------|----------|------|
| wrk | C+Lua | ❌ | ❌ | ✅ | OpenResty 社区标配 |
| wrk2 | C | ✅ | ✅ | ✅ | 延迟基准首选 |
| ab | C | 部分 | ❌ | ❌ | 古老，功能弱 |
| bombardier | Go | ✅ | ✅ | ❌ | 单二进制、CI 友好 |
| hey | Go | ✅ | ❌ | ❌ | 简单快速 |

**推荐组合**：功能测试 wrk、延迟基准 wrk2、CI 单文件 bombardier。

# 总结

- wrk 快、可 Lua 脚本；wrk2 才能出分位数；
- 阶梯速率跑（10k → 100k）看拐点；
- 压本机不准，两台机器；
- Lua 脚本里生成动态 body 是最常用能力；
- socket errors 一定要看，非零说明压测端自己先到极限。
