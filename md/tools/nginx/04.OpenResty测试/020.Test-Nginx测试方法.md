# 概述

`Test::Nginx` 用例的**核心是"section"**——每段以 `--- xxx` 开头的文本块，声明"配置什么、发什么、期望什么"。本文把常用 section 一张表列全，再给三类典型场景。

# 常用 section 速查

| Section | 语义 | 备注 |
|---------|------|------|
| `--- config` | server 级配置片段 | 至少 4 空格缩进；放 location |
| `--- http_config` | http 级配置片段 | 用于 `lua_shared_dict` / `init_by_lua` |
| `--- lua` | 全局 Lua 代码（顶部） | 供 `--- config` 里的 Lua 引用 |
| `--- request` | 请求内容 | `GET /t HTTP/1.1\r\nHost: x\r\n\r\n`；或简单一行 `GET /t` |
| `--- more_headers` | 额外请求头 | `X-Foo: bar` |
| `--- body` | 请求 body | 与 `--- request` 里的 raw 二选一 |
| `--- response_body` | 期望响应 body | 精确匹配 |
| `--- response_body_like` | 期望响应 body 匹配 regex | Perl regex |
| `--- response_headers` | 期望响应头 | `Content-Type: text/plain` |
| `--- error_code` | 期望 HTTP 状态码 | `400` |
| `--- error_log` | error.log 里应出现 | 子串匹配 |
| `--- no_error_log` | error.log 里**不应**出现 | 常用 `[error]` / `[alert]` |
| `--- ignore_response_body` | 不校验 body | 只测不崩溃 |
| `--- timeout` | 用例总超时秒 | 默认 3s |
| `--- user_files` | 临时文件 | `>>> a.txt\nhello\n<<<` |
| `--- sh_config` | stream 场景的 server 配置 | 四层用 |

# 三类典型场景

## 场景一：单元断言响应体

```text
=== TEST 1: hello
--- config
    location = /t {
        content_by_lua_block { ngx.say("hi") }
    }
--- request
GET /t
--- response_body
hi
```

## 场景二：断言错误日志

```text
=== TEST 2: bad json
--- config
    location = /t {
        content_by_lua_block {
            local cjson = require "cjson"
            local ok, err = pcall(cjson.decode, "{bad")
            if not ok then ngx.log(ngx.ERR, "decode failed: ", err) end
            ngx.say("ok")
        }
    }
--- request
GET /t
--- response_body
ok
--- error_log
decode failed
```

## 场景三：断言不出现错误

```text
--- no_error_log
[error]
[alert]
```

只要日志里出现 `[error]` 就 fail；用来确保**没有 Lua 异常**。

# 变量注入

在 `.t` 顶部用 `add_block_preprocessor` 或直接 `$ENV{...}`：

```perl
use Test::Nginx::Socket::Lua 'no_plan';
our $TEST_PORT = 19823;
add_block_preprocessor(sub {
    my ($block) = @_;
    my $config = $block->config // '';
    $config =~ s/%%PORT%%/$TEST_PORT/g;
    $block->set_value("config", $config);
});
```

用例里：

```text
--- config
    server {
        listen %%PORT%%;
        location /t { return 200 "ok"; }
    }
```

# shell 预处理

某些场景需要动态生成 config。`--- config` 前放 `--- config_mod_perl`：

```text
--- config_mod_perl
my $extra = $ENV{WITH_SSL} ? "ssl_certificate server.crt;" : "";
return $extra;
```

**少用**——大多数需求靠 `--- http_config` + 环境变量 `TEST_NGINX_XXX` 就够了。

# 跑起来 & 常见输出

```bash
# 单个文件
TEST_NGINX_BINARY=/usr/local/openresty/bin/openresty prove -v t/000-sanity.t

# 全目录 + 并行
TEST_NGINX_BINARY=/usr/local/openresty/bin/openresty prove -j -v t/
```

**并行** `-j` 会同时跑多个 `.t`；每个用例分配独立端口，互不干扰。快机器能把 5 分钟的用例集缩到 30 秒。

**保留中间产物**（重要！调试用）：

```bash
TEST_NGINX_RANDOMIZE=1 TEST_NGINX_LEAVE=1 prove -v t/000-sanity.t
# 产物在 test-nginx-tmp/ 下：nginx.conf、error.log、access.log
```

失败时先去看 `error.log`——**80% 的问题在这一步就定位了**。

# 与 CI 集成

**GitHub Actions** 最短配置：

```yaml
- name: Install OpenResty
  run: |
    wget -O - https://openresty.org/package/pubkey.gpg | sudo apt-key add -
    sudo apt-get install -y openresty
- name: Install Test::Nginx
  run: sudo cpanm --notest Test::Nginx
- name: Run tests
  run: TEST_NGINX_BINARY=/usr/bin/openresty prove -j t/
```

# 避坑

- **`--- response_body` 精确匹配末尾换行**：`ngx.say` 会自动加 `\n`；期望值末尾也要有；不然用 `response_body_like` + `qr/^hi\s*$/`。
- **`--- error_log` 是**子串**匹配**：`[error]` 会命中所有 error；写具体关键字。
- **用例之间共享 state**：同一个 `.t` 里多个 TEST 用同一个 nginx 实例；shared dict、init_worker 都只跑一次。想彻底隔离就拆到不同 `.t`。
- **`timeout` 单位**：`--- timeout 10` = 10 秒；不要写成毫秒。
- **`--- more_headers` 里的 header 大小写不敏感**：写 `X-Foo` 或对。

# 总结

- `.t` 文件 = 若干 `=== TEST` 段；每段 = 若干 `--- section` 块；
- 断言三件套：`response_body` / `error_code` / `error_log`；
- 顶部用 Perl 代码注入变量、预处理；
- `prove -j` 并行跑；失败看 `test-nginx-tmp/error.log`。
