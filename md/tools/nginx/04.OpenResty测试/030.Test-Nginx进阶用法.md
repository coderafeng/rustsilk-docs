# 概述

前一文给了基本 section；这篇讲**进阶技巧**——多阶段协作、复杂 mock、动态断言、跨用例 fixture、跳过条件。掌握这些，能覆盖 90% 的实际场景。

# 一、多阶段协作

一个 `.t` 里的多个 TEST 共用同一个 nginx 实例；`init_worker` 只跑一次，`lua_shared_dict` 里的数据跨用例累积。想显式跨用例传状态：

```text
=== TEST 1: warmup
--- http_config
    lua_shared_dict store 1m;
    init_worker_by_lua_block {
        ngx.shared.store:set("counter", 0)
    }
--- config
    location = /inc {
        content_by_lua_block {
            ngx.shared.store:incr("counter", 1, 0)
            ngx.say(ngx.shared.store:get("counter"))
        }
    }
--- request
GET /inc
--- response_body
1

=== TEST 2: still counting
--- request
GET /inc
--- response_body
2
```

**要点**：`TEST 2` 不用重写 `http_config` / `config`——Test::Nginx 会继承上一个 TEST。

# 二、动态断言

`--- response_body_eval` / `--- response_body_like` 支持 Perl 表达式：

```text
--- response_body_like
^v=\d+\.\d+$
```

**Lua 里带随机数**：`ngx.re.match` + eval：

```text
--- response_body_eval
$_ =~ s/\d+/X/g;   # 把数字换成 X 便于比对
return $_
```

或者反过来，测试里根据返回值动态改期望：

```perl
--- response_body_filter
my $body = shift;
$body =~ s/\r\n/\n/;
return $body;
```

# 三、Mock 上游

场景：网关转发到上游，测试里上游要能控制响应。**两条路**：

## 路 1：在 `.t` 里额外起一个 location 当上游

```text
--- config
    upstream backend {
        server 127.0.0.1:%%UPSTREAM_PORT%%;
    }
    location = /proxy {
        proxy_pass http://backend/mock;
    }
```

再用 `add_block_preprocessor` 生成 mock 服务的 `server` 块，或用 `--- http_config` + `init_worker` 起一个内部 timer 服务的 mock。

## 路 2：用 `lua-resty-mock` 直接桩

```lua
-- init_worker_by_lua_block
local mock = require "resty.mock"
mock.stub("redis", "get", function(key) return "MOCKED_" .. key end)
```

**不推荐**：会绕过真实的 cosocket 路径，测不到协议 bug。**优先真上游**。

# 四、跳过条件

按环境跳过：

```perl
use Test::Nginx::Socket::Lua;
plan(no_plan => skips => 1);
SKIP: {
    skip "OpenSSL 1.1.1 required", 1 unless $ENV{WITH_TLS};
    # 该 TEST 只在 WITH_TLS=1 时跑
}
```

或用 section：

```text
--- only_for_master_branch
--- skip_nginx_master: 3: 1.25.0
```

`skip_nginx_master: N: min_ver` = "nginx master 分支且低于 min_ver 时跳过 N 个断言"。

# 五、`log_level` 与断言粒度

`.t` 顶部：

```perl
log_level('debug');     # 会打印 nginx debug 日志（需要 --with-debug 编译）
worker_processes(1);    # 有些用例强依赖单 worker
use_http2();            # 强制走 HTTP/2
add_cleanup_handler(sub { ... });
```

**`worker_processes(1)`** 常用于共享字典状态断言——多 worker 会让 incr 计数不确定。

# 六、动态预处理：`add_block_preprocessor`

场景：所有 TEST 都要注入一段 `lua_shared_dict`。

```perl
add_block_preprocessor(sub {
    my $block = shift;
    $block->set_value("http_config",
        ($block->http_config // '') . "\n" .
        "lua_shared_dict store 1m;\n" .
        "lua_package_path '" . $ENV{PWD} . "/lib/?.lua;;';\n"
    );
});
```

**价值**：把重复的 `http_config` 抽出；用例只写业务部分。

# 七、`--- grep_error_log` / `--- grep_error_log_out`

想**只**关心某些日志、其他一律不管：

```text
--- grep_error_log eval
qr/my_module: \S+/
--- grep_error_log_out
my_module: hello
my_module: world
```

框架从 error.log 里 grep 出匹配行、按顺序对比。**测 timer 触发次数**很好用。

# 八、多阶段串联测试

一个请求要走 rewrite → access → content → log；`.t` 里给四段 Lua，然后断言最终响应：

```text
--- config
    location = /t {
        rewrite_by_lua_block { ngx.ctx.step = "rewrite" }
        access_by_lua_block  { ngx.ctx.step = ngx.ctx.step .. ",access" }
        content_by_lua_block {
            ngx.ctx.step = ngx.ctx.step .. ",content"
            ngx.say(ngx.ctx.step)
        }
        log_by_lua_block     {
            ngx.log(ngx.INFO, "step=", ngx.ctx.step)
        }
    }
--- request
GET /t
--- response_body
rewrite,access,content
--- error_log
step=rewrite,access,content
```

# 九、stream 层测试

用 `Test::Nginx::Lua::Stream`：

```text
use Test::Nginx::Lua::Stream 'no_plan';
run_tests();

__DATA__

=== TEST 1: echo
--- stream_config
    server {
        listen 19830;
        content_by_lua_block {
            local sock = ngx.req.socket()
            local line = sock:receiveLine()
            sock:send(line)
        }
    }
--- stream_request
hello\n
--- stream_response
hello
```

`stream_request` / `stream_response` 是 stream 模块专属 section。

# 避坑

- **多 worker 让 shared dict 测试 flaky**：显式 `worker_processes(1)`；
- **`error_log` 是子串不是 regex**：想匹配模式 → `grep_error_log eval` + Perl qr；
- **`--- response_body_like` 里的 `^` `$`** 默认不 anchor 多行；加 `(?m)`；
- **`SKIP` 计数** 要和 TEST 里断言数一致，否则 TAP 会报 plan 不匹配。

# 总结

- 跨用例继承：config 不用重复写；
- 动态断言：`response_body_like` / `_eval` / `_filter`；
- Mock 上游：优先起真 mock location；不要用 `lua-resty-mock` 桩掉 cosocket；
- `add_block_preprocessor` 抽公共 config；
- `worker_processes(1)` 保证状态断言；
- `grep_error_log` 精准断言日志序列；
- stream 测试用 `Test::Nginx::Lua::Stream`。
