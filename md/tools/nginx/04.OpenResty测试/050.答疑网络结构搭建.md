# 概述

"我在 CI 里怎么同时起 nginx + mock 上游 + Redis + 一个 HTTP echo 服务？"——测试环境的**网络结构搭建**是 OpenResty 项目里最容易被忽略、又最容易出事的一环。本文给出三种常见编排。

# 三种拓扑

```text
A. 单 nginx 自给自足（最简）
B. 双 nginx：网关 + 上游 mock（推荐）
C. 外部依赖：真 Redis/DB（集成测试）
```

## A. 单 nginx

`--- config` 里同时定义 upstream 和 mock：

```nginx
upstream backend {
    server 127.0.0.1:%%BACKEND_PORT%%;
    keepalive 64;
}

server {
    listen %%BACKEND_PORT%%;
    location = /mock/api {
        content_by_lua_block {
            ngx.say('{"code":0,"data":"from mock"}')
        }
    }
}

server {
    listen %%GATEWAY_PORT%%;
    location = /gateway/api {
        proxy_pass http://backend/mock/api;
    }
}
```

**优点**：起一个 nginx 全搞定；**缺点**：网关代码问题会连带 mock 挂；日志混杂。

## B. 双 nginx

两个独立 `Test::Nginx` 实例。做法：把 mock server 单独放一个 `.t`，用 `Test::Nginx::HTTP` 常驻。

```perl
# t/lib/MockUpstream.pm
package MockUpstream;
use Test::Nginx::HTTP;
sub start {
    my $class = shift;
    my $srv = Test::Nginx::HTTP->new(listen => 19900);
    # 后台起一个 echo 服务
    return $srv;
}
1;
```

主用例：

```perl
use MockUpstream;
my $mock = MockUpstream->start();
# 网关用例引用 127.0.0.1:19900 作为 backend
```

**优点**：故障隔离；日志分离。**缺点**：多一层 Perl 编排代码。

## C. 外部依赖

用 Docker Compose 起 Redis + MySQL，nginx 只做网关：

```yaml
# docker-compose.test.yml
services:
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
  gateway:
    image: openresty/openresty:1.31.8.1
    volumes:
      - ./conf:/etc/nginx/conf.d
      - ./lua:/usr/local/openresty/lualib/app
    ports: ["8080:8080"]
    depends_on: [redis]
```

用 Test::Nginx 只测网关逻辑；Redis 直连真容器。**这是集成测试**。

# 端口分配规范

**冲突是 OpenResty 测试最常见的坑**。约定：

```text
10000-10999  → Test::Nginx 自动分配（框架管）
15000-15999  → 网关主服务
16000-16999  → mock 上游
17000-17999  → Redis / DB
18000-18999  → 观测（Prometheus / Grafana）
```

在 Makefile 里统一：

```makefile
export GATEWAY_PORT ?= 15001
export MOCK_PORT    ?= 16001
export REDIS_PORT   ?= 17001
```

# 常见拓扑：网关 + 三个下游

```text
                    ┌─── auth-service (mock) :16001
   client ─▶ gateway ─┼─── biz-service (mock) :16002
                    └─── cache (Redis)     :17001
```

对应 nginx.conf 结构：

```nginx
upstream auth { server 127.0.0.1:16001; keepalive 32; }
upstream biz  { server 127.0.0.1:16002; keepalive 32; }

lua_shared_dict tokens 1m;

server {
    listen 15001;
    location = /api {
        access_by_lua_block {
            -- 1. 调 auth
            local http = require "resty.http"
            local res = http.request_uri("http://127.0.0.1:16001/check", {
                method = "POST", body = ngx.req.get_headers()["authorization"]
            })
            if res.status ~= 200 then return ngx.exit(401) end

            -- 2. 查 Redis
            local redis = require "resty.redis"
            local r = redis:new()
            r:connect("127.0.0.1", 17001)
            local cached = r:get("api:" .. ngx.var.request_uri)
            if cached then
                ngx.say(cached); return ngx.exit(200)
            end
        }
        proxy_pass http://biz;
    }
}
```

对应的 mock `.t`：

```text
=== TEST 1: auth returns 200/401 by token
--- config
    server {
        listen 16001;
        location = /check {
            content_by_lua_block {
                ngx.req.read_body()
                local tok = ngx.req.get_body_data()
                if tok == "Bearer valid" then
                    ngx.exit(200)
                else
                    return ngx.exit(401)
                end
            }
        }
    }
```

# 依赖服务的启停顺序

```bash
# 1. 起 Redis（外部）
docker run -d --name or-test-redis -p 17001:6379 redis:7-alpine

# 2. 起 mock 上游（Test::Nginx 会自管）
# 3. 跑 prove
TEST_NGINX_BINARY=/usr/local/openresty/bin/openresty prove -v t/

# 4. 收尾
docker rm -f or-test-redis
```

**Makefile 目标**：

```makefile
setup:
	docker run -d --name or-test-redis -p 17001:6379 redis:7-alpine
	docker exec or-test-redis redis-cli FLUSHALL

teardown:
	docker rm -f or-test-redis

test: setup
	TEST_NGINX_BINARY=/usr/local/openresty/bin/openresty prove -j t/
	$(MAKE) teardown
```

# CI 里的注意事项

- **GitHub Actions 提供 service container**：`services: redis:` 直接注入；
- **Test::Nginx 需要 `--privileged`**：某些 syscalls（比如 `reuseport`）在容器里受限；CI 用 `docker run --privileged`；
- **共享 runner 端口冲突**：始终 `TEST_NGINX_RANDOMIZE=1` 让框架随机分配端口；
- **日志留档**：失败时上传 `test-nginx-tmp/` 目录，方便事后 debug。

# 避坑

- **mock 上游 keepalive 未设**：网关每次请求新 TCP，测试环境比生产还慢——给 mock 加 `keepalive`。
- **Redis 数据未 flush**：跨用例污染，出现"上一用例写 key，下一用例读到"；`setup` 里 `FLUSHALL`。
- **网关测试端口 hardcode**：CI 与其他任务撞；永远从 `$ENV{GATEWAY_PORT}` 或 `TEST_NGINX_PORT` 拿。
- **`reuseport` 在 macOS 上不支持**：CI 用 Linux；本地开发禁用 `reuseport`。

# 总结

- 单 nginx：最快、适合纯 Lua 单元测试；
- 双 nginx：故障隔离、适合网关逻辑；
- Docker Compose：真依赖，集成测试；
- 端口规划 + Makefile 目标 + CI service container = 三件套。
