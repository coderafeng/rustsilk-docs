# 概述

**特权进程**（privileged agent）是 worker 之外多出来的一个进程，能碰阻塞操作、又不影响主 worker；**定时任务**（`ngx.timer.*`）是 OpenResty 里唯一的"后台线程"。两者组合起来撑起 OpenResty 的"非请求驱动"能力。

# privileged agent：一个"敢阻塞"的 worker

`privileged agent` 从 nginx 1.7.11 起存在；`init_by_lua_block` 里通过 `primes` 或 `privileged_agent_by_lua_block` 启用。它的角色：

- 和 worker 共享 Lua VM 配置；
- **允许** `os.execute`、`io.open`、`ngx.socket.tcp` 阻塞、`resty.lock` 长等待；
- 处理"重资源加载"、"定期上报"、"外部命令"这些**不能塞进主 worker** 的活儿。

## 配置

```nginx
http {
    # 启用 privileged agent
    privileged_agent_by_lua_block {
        ngx.log(ngx.INFO, "privileged agent starting")
    }

    # 或简写：只关心 init_worker
    init_worker_by_lua_block {
        if ngx.process_type() == "privileged" then
            -- privileged 侧逻辑
        else
            -- 普通 worker 侧逻辑
        end
    }
}
```

## 使用样例：定期从 K8s API 拉配置

```lua
-- privileged 侧
ngx.timer.every(15, function()
    local http = require "resty.http":new()
    http:set_timeout(10000)
    local res, err = http:request_uri("https://k8s/api/v1/configmaps/gateway", {
        method = "GET",
        headers = { ["Authorization"] = "Bearer " .. TOKEN },
    })
    if res and res.status == 200 then
        local sh = ngx.shared.config
        sh:set("cm_data", res.body, 60)
    end
end)
```

**worker 侧**通过 `ngx.shared.config:get("cm_data")` 读取——**跨进程无锁**（详见 [02 章 080.共享内存与 worker 通信](../02.Lua与OpenResty运行时内幕/080.共享内存与worker通信.md)）。

# `ngx.timer.*` 全 API

| 方法 | 语义 | 首次延迟 | 是否重复 |
|------|------|----------|----------|
| `ngx.timer.at(0, cb)` | 一次性 | delay 秒 | 否 |
| `ngx.timer.every(5, cb)` | 每 5s | delay 秒 | 是 |
| `ngx.timer.running_count()` | 当前正在跑的 timer 数 | — | — |
| `ngx.timer.pending_count()` | 已排程未跑的 timer 数 | — | — |

## 完整签名

```lua
local prem, err = ngx.timer.at(
    5,                              -- delay（秒，可用小数）
    function(prem)                  -- 回调
        if prem then return end     -- nginx 正在退出/shutdown，主动放弃
        -- 干活
    end,
    arg1, arg2, ...                 -- 附加参数会传给回调
)
```

**prem 参数**：`true` 表示"这次触发是在 worker shutdown 期间"。回调里第一件事就是 `if prem then return end`，避免在退出阶段做无用 IO。

# Timer 的三个约束

1. **单 worker 上限**：`lua_max_running_timers`（默认 4096）、`lua_max_pending_timers`（默认 1024）。超过会返回 `too many pending timers`。
2. **回调上下文**：timer 回调运行在一个新协程里，**没有请求上下文**——不能用 `ngx.req.*`、`ngx.say`、`ngx.exit`；只能用 `ngx.log`、cosocket、`ngx.shared`。
3. **worker 之间不共享调度**：每个 worker **独立**跑一份 timer。做"每 60 秒上报"时，如果 worker=4，实际是 4×/60s。要么走 `privileged_agent`，要么用 shared dict 抢锁。

## 只让一个 worker 跑：抢锁法

```lua
local LOCK_KEY = "cron:heartbeat"
local sh = ngx.shared.locks

ngx.timer.every(60, function(prem)
    if prem then return end
    -- 只有抢到锁的 worker 干活；TTL 60s，锁自动过期
    local ok = sh:add(LOCK_KEY, ngx.worker.pid(), 60)
    if not ok then return end
    -- 干活：上报指标 / 清缓存 / 拉配置
    do_real_work()
end)
```

**注意**：`sh:add` 的原子性是"key 不存在时才写入"——天然分布式锁；60s TTL 保证 worker 崩了下一次仍能抢。

# `timer` 里的 cosocket

```lua
ngx.timer.at(0, function(prem)
    if prem then return end
    local sock = ngx.socket.tcp()
    sock:settimeouts(2000, 2000, 2000)
    local ok = sock:connect("metrics.local", 9090)
    if ok then
        sock:send(payload)
        sock:setkeepalive()
    end
end)
```

timer 协程里 cosocket **完全可用**——这是 fire-and-forget 上报的标准做法。

# 一次性异步任务：`timer.at(0, ...)`

主请求已经响应，但你想**异步做点事**（写审计、发消息）：

```lua
content_by_lua_block {
    -- 主逻辑
    ngx.say("ok")
    ngx.eof()                       -- 提前把响应推给客户

    -- 异步落审计
    local audit = { user = user, action = "..." }
    local ok, err = ngx.timer.at(0, function(prem)
        if prem then return end
        local sock = ngx.socket.tcp()
        sock:connect("audit.local", 5140)
        sock:send(cjson.encode(audit) .. "\n")
        sock:setkeepalive()
    end)
    if not ok then ngx.log(ngx.WARN, "audit dispatch failed: ", err) end
}
```

**这是 OpenResty 里做异步的最佳模式**：主链路不等，回调里 cosocket 走池。

# `master_start_time` / `ngx.timer.pending_count` 观测

```lua
-- /metrics
ngx.say("openresty_timer_running ", ngx.timer.running_count())
ngx.say("openresty_timer_pending ", ngx.timer.pending_count())
```

`pending` 长期高企 = 有 timer 阻塞、或跑太快 worker 处理不过来。

# 避坑

- **不要在 timer 回调里 `error()`**：未捕获会让整个 timer 静默失败——`pcall` 包住业务代码。
- **timer 里 `ngx.say` = nil 输出**：无请求上下文；只能 `ngx.log`。
- **timer 泄漏**：`every` 会永远跑；worker reload 时旧 timer 会随旧 worker 消亡，**但不要 `every` 里再启 `every`**——会指数级增长。
- **prem 处理不彻底**：worker shutdown 时 timer 触发一次带 `prem=true` 的回调；如果里面对接了外部系统，会写垃圾数据。永远 `if prem then return end`。
- **锁 + timer 抢锁失败静默**：如上例，`sh:add` 返回 false 就直接 `return`——**别打 error**；否则日志爆量。

# 总结

- privileged agent：一个"敢阻塞、能碰外部系统"的额外进程；
- `ngx.timer.at/every`：请求上下文之外的所有异步/定时都靠它；
- 三约束：`prem` 判空、无请求上下文、每 worker 独立跑；
- 跨 worker 只跑一次：shared dict 抢锁；
- fire-and-forget：`ngx.timer.at(0, ...)`。
