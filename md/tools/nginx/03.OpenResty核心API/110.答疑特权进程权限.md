# 概述

关于 `privileged_agent_by_lua*`（特权进程）的常见答疑集中在这几类：**能不能改配置、能不能碰磁盘、能不能 cosocket、能不能跑外部命令**。本文一次性讲透它的权限边界。

# privileged agent 的由来

nginx 的 worker 进程处理 IO，任何**同步阻塞**都会拖垮整台机器上的所有请求。有些活儿又必须做：从 Nacos / etcd 拉配置、执行 `nginx -t` 检查、定期 `dig` 域名、写审计文件。这些活儿**能容忍慢、能容忍短暂阻塞**——就交给 `privileged agent`。

# 权限矩阵

| 能力 | worker | privileged agent | 备注 |
|------|--------|------------------|------|
| 处理请求 | ✅ | ❌ | agent 不监听端口 |
| `_by_lua*` 请求阶段 API | ✅ | ❌ | agent 里没有 request 上下文 |
| `ngx.timer.*` | ✅ | ✅ | agent 里独立跑一份 |
| cosocket（`ngx.socket.*`） | ✅（非阻塞） | ✅ | agent 里允许阻塞使用（仍走非阻塞实现，但阻塞不影响 worker） |
| `ngx.shared.DICT` | ✅ | ✅ | 共享同一份内存 |
| `ngx.log` | ✅ | ✅ | agent 独立 tag |
| `os.getenv` | ✅（受限） | ✅ | worker 里出于安全不建议 |
| `os.execute` | ❌（禁用） | ✅ | agent 存在的核心原因之一 |
| `io.open` / `io.write` | ❌（禁用） | ✅ | 同上 |
| `ngx.socket.udp` + DNS | ✅ | ✅ | — |
| 修改 nginx 主配置 | ❌ | ❌ | 只能 reload，不能改 nginx.conf |
| 影响 worker 内存 | 通过 shared dict | 通过 shared dict | 只能通过 shdict 传数据 |

**核心一句话**：privileged agent 是**能碰文件系统、能执行命令、能跑阻塞代码**的 worker 兄弟，但它**不处理请求**。

# 典型问题

## Q1：能不能让 privileged agent 处理请求？

**不能**。agent 没有 listen 端口、没有 request 上下文。要处理请求请放 worker；agent 只做**辅助**。

## Q2：能不能热重载 nginx？

```lua
-- privileged_agent_by_lua_block
ngx.timer.every(300, function(prem)
    if prem then return end
    local ok = os.execute("/usr/local/openresty/bin/openresty -s reload")
    ngx.log(ngx.INFO, "reload: ", ok)
end)
```

**能**——agent 里 `os.execute` 允许。**但要注意**：reload 时新旧 worker 会并存 5-10 秒，agent 也会重启一次；别每 30 秒 reload 一次，那是配置错误。

## Q3：能不能拉起外部进程常驻？

```lua
-- 拉一个后台脚本
os.execute("/opt/my-sidecar/start.sh &")   -- 加 & 后台；agent 不阻塞
```

**能**。但要考虑：nginx reload / stop 时 sidecar 是否会成为孤儿。加一个 `ngx.on_abort` 或用 `master_fifo` 通知。

## Q4：agent 崩了会怎样？

worker 崩了 → master 自动重 spawn；agent 崩了同样会重 spawn。**agent 崩溃不影响 worker 服务**。日志里出现：

```text
[alert] worker process #N SIGCHLD
[notice] signal 15 (SIGTERM) received from XXX to re-open logs
```

排查 agent 崩溃定位到 `privileged_agent_by_lua*` 里报错的那段。

## Q5：agent 里的 timer 和 worker 里的 timer 会不会重复？

**独立跑**。假设 `worker_processes 4`，`privileged_agent on`，`every(60, cb)` 会启动 4 + 1 = **5 份 timer**。做全局限频/心跳要**用 shared dict 抢锁**（见 [060.特权进程与定时任务](./060.特权进程与定时任务.md)）；或者只写在 `privileged_agent_by_lua*` 里，天然只有一份。

## Q6：agent 里能改 nginx.conf 吗？

**不能**。agent 是 Lua 进程，它没有 nginx 主配置的写入权限。要改配置：
1. 外部程序（Ansible / Kubernetes ConfigMap）改文件；
2. agent 里 `os.execute("openresty -s reload")`；
3. 或直接把配置塞进 shared dict，worker 里读。

## Q7：agent 挂了 worker 还能不能干活？

**能**。agent 完全独立；它挂了 master 会 respawn，期间 worker 无感知。**这是它存在的意义**——把 risky 代码放这儿。

## Q8：`privileged_agent_by_lua*` 和 `init_worker_by_lua*` 里判 `process_type` 有什么区别？

```lua
-- 写法 A：agent 单独一段
privileged_agent_by_lua_block {
    -- 只有 agent 跑
}

-- 写法 B：init_worker 里判
init_worker_by_lua_block {
    if ngx.process_type() == "privileged" then
        -- agent 跑这段
    else
        -- 普通 worker 跑这段
    end
}
```

**语义等价**。写法 A 更清晰；写法 B 适合两块逻辑共享大量代码。

# 何时**不要**用 privileged agent

- 只是"想让某个 timer 只跑一次" → 用 `shdict:add` 抢锁，agent 是大炮打蚊子；
- 只是想读文件 → 用 `lua-resty-...` 库预加载到 shared dict，agent 里定期刷；
- 只是想隔离一段 Lua → 起一个独立 OpenResty 实例更清晰。

# 避坑

- **agent 里 cosocket 仍非阻塞**：agent 是**允许**阻塞语义（不会拖累 worker），但 cosocket API 本身没变。
- **`os.execute` 会 fork 子进程**：agent 关闭时子进程会变孤儿；自己管生命周期。
- **别把 agent 当 cron 用**：它没有秒级/分钟级 cron 表达式；要精确到点自己算 delay。

# 总结

- privileged agent = 一个不处理请求、可跑阻塞代码的 worker 兄弟；
- 权限核心增量：`os.execute`、`io.*`、阻塞式 IO；
- 崩了不影响 worker；timer 独立跑一份；
- 不能改 nginx.conf，不能处理请求；
- 只用于"外部系统集成 / 定期重载 / 写文件"这几类活儿。
