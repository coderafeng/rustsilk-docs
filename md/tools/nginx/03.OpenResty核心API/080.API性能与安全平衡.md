# 概述

OpenResty 的 API 大多"看着无害"，实则有性能和安全代价：`read_body` 什么时候落盘？`setkeepalive` 用错池会耗尽？`get_uri_args` 不设上限被大请求打爆？本文把这些"平衡点"逐个列出，并给出**默认安全配置**。

# 性能与安全的三条主线

```text
资源占用 ── 请求体、header、args、cosocket 池、shared dict
CPU ────── 正则、JSON、LuaJIT 编译、加密
IO ──────── 上游连接、DNS、临时文件、日志
```

每处 API 都影响这三条中的一条或多条，选值就是**权衡**。

# 请求体：`read_body`

## 决策表

| 场景 | 建议 |
|------|------|
| 小 body（< 8KB）且要解析 | `client_body_buffer_size 16k;` + `ngx.req.read_body()`；全内存 |
| 大 body（文件上传） | `client_body_buffer_size 8k;` + `client_max_body_size 100m;`；自然落盘临时文件 |
| 只想透传，不读 body | **别调** `read_body`；`proxy_pass` 会流式转发 |
| 校验签名（HMAC） | 需要完整 body；`read_body(true)` 强制不落盘 |

**关键点**：`read_body(true)` 里参数是"discard body"，而不是"强制内存"。想强制内存要 `client_body_in_memory_only`（无此指令，得手动 `read_body` + 检查 `get_body_file`）；或调大 buffer 覆盖最大可能 body。

## `client_body_buffer_size` 与内存

- 默认：`8k`（32 位）/ `16k`（64 位）
- 每 worker 每请求一份 buffer → **worker 数 × 请求并发 × buffer** = 峰值内存
- 建议：小 body 场设 32k-64k；大 body 别调太大，让它落盘

# Header / Args：上限

```lua
-- 默认 30；建议 100-200
local args = ngx.req.get_uri_args(100)
local hdrs = ngx.req.get_headers(100)

-- 遇到大 header 会返回 truncated = true
local hdrs, truncated = ngx.req.get_headers(100)
if truncated then
    ngx.log(ngx.WARN, "headers truncated for uri=", ngx.var.uri)
end
```

**nginx 层的对应**：`large_client_header_buffers 4 16k;`——超过返回 `414 URI Too Long` / `400 Bad Request`。Lua 上限 ≥ nginx 上限才有意义。

# cosocket：池与超时

## 池

```lua
-- 反例：不设上限 → 一个后端被 4 worker × 每 worker 1000 连接打爆
local ok = sock:connect("backend", 8080)

-- 正例：显式池上限 + backlog
local ok = sock:connect("backend", 8080, {
    pool = "backend_main",
    pool_size = 128,     -- 单 worker 最多 128 空闲
    backlog = 256,       -- 池满时等待队列
})
```

## 超时：三段独立设

```lua
sock:settimeouts(
    1000,   -- connect：内网 500ms；跨区 2000ms
    3000,   -- read：取决于对端处理时间
    3000    -- write
)
```

**没有超时 = 依赖 nginx 全局默认（60s）**：一个后端挂了，worker 里的请求会挂 60 秒，把 `worker_connections` 全部耗尽。**永远显式设**。

# 正则：注入与回溯

## 编译缓存被"动态 regex"绕过

```lua
-- 危险：每次拼一个新 regex → 缓存爆炸 → CPU 100%
local pat = "^" .. user_input .. "$"
ngx.re.match(s, pat, "jo")     -- 千万不要用 o，且 pat 变 → 缓存 miss
```

**对策**：
1. 输入进 regex 前**转义**：`ngx.re.gsub(user_input, "[.*+?()\\[\\]{}|^$]", "\\\0", "jo")`；
2. 尽量把可变部分做成 **枚举 + 精确匹配**（`sh:get("blacklist:"..input)`），而不是 regex。

## 回溯炸弹

`.*(a+)+b` 这类 regex 会让 PCRE 指数级回溯。OpenResty 有：

```nginx
lua_useDefaultCC ...;
pcre_jit on;                       -- nginx 主配置
```

**关键**：`pcre_jit on` 让 PCRE 走 JIT，抗回溯好很多；同时**永远避免"能匹配空"的量词套"能匹配空"的量词**——`(a*)*b`、`(.*).*x`。

# 日志：等级与限速

```lua
-- 高频路径不要 INFO/DEBUG；生产默认 WARN 起
ngx.log(ngx.WARN, "...")

-- 想保留 DEBUG 但不打爆：限速
local logged_at = 0
function throttled_log(level, msg)
    local now = ngx.now()
    if now - logged_at < 1 then return end     -- 1s 最多一条
    logged_at = now
    ngx.log(level, msg)
end
```

对应 nginx 层：`error_log /var/log/nginx/error.log warn;` 定级；`access_log` 单独走 `log_by_lua`。

# shared dict：容量与 TTL

- **容量**：`lua_shared_dict limits 10m;`；太小 → `premature = true` 淘汰频繁；太大 → 内存吃紧。经验值：**峰值 QPS × TTL × 每 key 平均字节数 × 2**。
- **TTL**：永远给正数 TTL；`set(k, v, 0)` 只在"内存紧张时可淘汰"的缓存语义下用。

# 权限与安全

## 别把 Lua 代码写进 `if` 里的用户参数

```lua
-- 危险：load() 是动态求值，用户可控 = RCE
local chunk = load("return " .. user_input)   -- 永远不要这样

-- 想解析数字：tonumber()
local n = tonumber(user_input)
```

## `os.getenv` 泄漏

```lua
-- 反例：把环境变量当配置源，可能泄漏密钥到日志
ngx.log(ngx.INFO, "db_url=", os.getenv("DATABASE_URL"))
```

**对策**：配置从 `lua_shared_dict` 或 `init_by_lua` 加载；`os.getenv` 只在 init 阶段读，之后不接触。

## 敏感 header 剥离

网关透传前：

```lua
for _, h in ipairs({"authorization", "cookie", "x-api-key"}) do
    -- 只在必要时传给特定上游；默认剥离
    if not is_trusted_upstream then
        ngx.req.clear_header(h)
    end
end
```

# 一个"默认安全"配置样板

```nginx
http {
    client_max_body_size 10m;
    client_body_buffer_size 32k;
    large_client_header_buffers 4 16k;

    lua_socket_pool_size 64;
    lua_socket_log_errors off;                -- 生产关掉，防日志爆
    lua_regex_cache_max_entries 4096;
    lua_match_limit 400000;                   -- PCRE 匹配步数上限，防回溯炸弹
    pcre_jit on;

    lua_shared_dict limits 16m;
    lua_shared_dict config 4m;

    init_worker_by_lua_block {
        -- 全局初始化：加载库、启动 timer
    }
}
```

配合 Lua 层的三条纪律：

1. `get_uri_args(100)` / `get_headers(100)` 都带上限；
2. `sock:settimeouts` 三段全部显式；
3. `set(k, v, ttl)` 永远给正数 ttl。

# 避坑

- **`lua_socket_log_errors off` 会静默 cosocket 错误**：出错只在业务返回；调试期先 `on`。
- **`lua_match_limit` 太小**：正常 regex 报 `pcre_exec() exceeded match limit`；从 100k 起步、压测调整。
- **共享字典太小 → 频繁 forced eviction → 限流失效**：观察 `premature` 计数告警。
- **动态 regex 忘转义**：安全边界，见上。

# 总结

- body / header / args：都设上限，永远带 `truncated` 判空；
- cosocket：显式三段超时 + `pool_size` + `backlog`；
- 正则：常量 + `o` + 转义输入 + `pcre_jit on`；
- shared dict：容量按 QPS × TTL 估算，永远给 ttl；
- 日志：WARN 起 + 限速；
- 权限：禁 `load` 动态求值、剥离敏感 header。
