# 概述

[02 章 080.共享内存与 worker 通信](../02.Lua与OpenResty运行时内幕/080.共享内存与worker通信.md) 讲了 slab + LRU + 全局锁的**原理**。这篇补齐**日常写代码时会用到的完整 API**：CAS、批量、过期回调、事件通知、flush 与统计。

# API 全表

| 分类 | 方法 | 关键返回 |
|------|------|----------|
| 读写 | `get / set / add / replace / delete` | `premature?` |
| 数值 | `incr / decr` | `err` 或 `"not found"` |
| 批量 | `get_keys(n)` | keys 表 |
| CAS | `cas(key, old, new, ...) / lpush / rpush / lpop / rpop` | 视方法 |
| 空间 | `flush_all / flush_expired / flush_lock / free_space / capacity` | 数字 |
| 状态 | `num / size / capacity` | 计数 |
| 事件 | `set_incr_init_value` / 通过 `ffi` 监听 forced eviction | — |

**默认 TTL**：`set(k, v, 0)` 里的 `0` 表示"不过期，但被 LRU 强制挤出"；生产环境建议永远给一个正数 TTL。

# CAS：无锁更新

```lua
-- 场景：读一个 counter，如果值仍是 old_val 就替换为 new_val
local sh = ngx.shared.my_store
local val, flags = sh:get("config")
local ok, err = sh:cas("config", val, "new_config", flags)
-- ok = true  → 更新成功
-- ok = false → 值已被其他 worker 改了；重读再试
```

**注意**：`cas` 只保证"key 的 value 没变过"这一件事；它不会给你一段逻辑的原子性。想跨多字段原子改，把整个状态塞进一个 value 里（例如 JSON），或用 `lua-resty-lock` 加互斥。

# 批量：`get_keys`

```lua
-- 遍历前 N 个 key（不保证顺序、不保证不重复、可能中途插入或淘汰）
local keys = sh:get_keys(1000)
for _, k in ipairs(keys) do
    ngx.log(ngx.INFO, "key=", k, " val=", tostring(sh:get(k)))
end
```

**性能红线**：`get_keys` 会**在遍历期间拿全局锁**——字典越大越慢。生产环境不要用 `get_keys(n)` 里 `n` 特别大（例如 `-1`/`100000`）；否则 worker 会 stall 几百毫秒。想全量清理，用 `flush_all`。

# incr 的 forcible 语义

```lua
local val, err = sh:incr("hits", 1, 0, 1)   -- init=0, init_ttl=1s
-- 首次：val=1，key 已建、TTL=1
-- 之后：val++
-- 强制淘汰发生：val 变成新窗口，err = "not found"？—— 不会；incr 会重建 init
```

**关键点**：`incr` 第 3、4 参（`init`、`init_ttl`）**在 1.21.4.1+ 才稳定**；更早版本要 `add(k, 0, ttl)` 兜底。1.31.8.1 放心用完整签名。

# 过期回调：`flush_expired` + 定时任务

shared dict **不主动通知过期**。想要"key 过期时执行 X"，两条路：

## 路 1：定时扫过期

```lua
-- init_worker_by_lua_block
ngx.timer.every(30, function()
    local sh = ngx.shared.my_store
    local n = sh:flush_expired(1000)        -- 每次最多回收 1000 个
    if n > 0 then
        ngx.log(ngx.INFO, "flushed expired: ", n)
    end
end)
```

**代价**：30s 精度、每次 O(过期数量)。适合"过期后要做次生清理"的场景（比如回收 token、清理限流窗口）。

## 路 2：把 TTL 交给外部存储

Redis 有 keyspace notification；shared dict 没有。要做**准实时的过期事件**，把带 TTL 的数据挪到 Redis，让 Redis 触发通知。

# 事件通知：`forced` eviction

shared dict 被 LRU 强制淘汰时，`set` 返回 `premature = true`。想监听淘汰事件，只能在**写路径**做钩子：

```lua
local ok, err, premature = sh:set(k, v, ttl)
if premature then
    ngx.log(ngx.WARN, "shared dict forced eviction when writing key=", k)
end
```

想**主动观察**淘汰计数：`sh:capacity() - sh:free_space()` 给"当前占用"，但没有"淘汰次数"这一指标。要做指标监控，把 `premature = true` 记 counter，或者用 `stapxx` / `ebpf` 探针（详见 [05 章 070.systemtap-toolkit 与 stapxx](../05.OpenResty性能优化/070.systemtap-toolkit与stapxx.md)）。

# 队列 API：lpush / rpush / lpop / rpop

shared dict 支持每个 key 挂一个字符串队列，可当**极简跨 worker 队列**：

```lua
-- 生产者
sh:lpush("jobq", ngx.encode_base64(payload))

-- 消费者
local item = sh:rpop("jobq")
if item then
    local payload = ngx.decode_base64(item)
    -- 处理
end
```

**局限**：
- 每个 value 有 slab 上限（通常几 KB）；
- `rpop` 不是原子的"取一条并弹出"，多 worker 并发下可能拿到 nil；
- 队列长度大时性能急剧下滑；
- 需要严格消息保证 → 用 Redis Stream / Kafka。

# 内存与容量指标

```lua
local free   = sh:free_space()          -- 剩余 slab 字节
local n      = sh:num()                  -- 当前 key 数量（不含已过期未回收）
local cap    = sh.capacity               -- 字典总大小（字节）
```

放到 `/metrics` 里暴露：

```lua
location /metrics {
    content_by_lua_block {
        local sh = ngx.shared.my_store
        ngx.say("openresty_shdict_bytes_free ", sh:free_space())
        ngx.say("openresty_shdict_keys ", sh:num())
    }
}
```

# 避坑

- **`set(k, v, ttl)` 里 ttl 精度是 1ms**：<1ms 会向上取整；跨进程一致性靠 `ngx.now()` + 每次比较。
- **`add` vs `replace` vs `set`**：`add` 只在 key 不存在时写；`replace` 只在 key 存在时写；`set` 无条件写。做计数器 init 用 `add`，避免覆盖。
- **`incr` 的 key 必须是数字**：`set(k, "abc")` 后 `incr(k, 1)` 返回错误 `"value not numeric"`。
- **`get_keys` 大 N = stall**：见上，永远给一个 1000 以下的上界。
- **shared dict 不能存 nil**：`set(k, nil)` 报错；删除用 `delete(k)`。
- **flags 有 5 位保留**：`set(k, v, ttl, 0xFFFF)`——高 16 位可用；低 8 位被模块内部占用。

# 总结

- 基本读写：`get/set/add/replace/delete`；
- 数值：`incr(k, v, init, init_ttl)`；
- 并发更新：`cas`；
- 清理：`flush_expired`（定时）+ `flush_all`（重启）；
- 观测：`num / free_space / premature`；
- 队列：`lpush/rpop`，小流量凑合，大流量走 Redis。
