# restydoc：命令行手册

`restydoc` 是章玉峰（agentzh）做的**离线聚合**工具，把所有 `lua-nginx-module`、`stream-lua-nginx-module`、`drizzle-lua` 等模块的 POD 文档合成一份可 grep 的文本。

**安装**：

```bash
# 从源码
git clone https://github.com/leafo/restydoc
cd restydoc && luarocks make

# 或用 opm
opm get leafo/restydoc
```

**使用**：

```bash
restydoc ngx.shared.DICT               # 查共享字典 API
restydoc ngx.socket.tcp                # 查 cosocket
restydoc -s 'phase'                    # 全库搜索 "phase"
restydoc -p content_by_lua_block       # 定位到具体指令
```

**局限**：不是所有 `lua-resty-*` 库都被收录，第三方库仍需查各自 README。

# 官方测试用例的位置

每个 C 模块仓库下都有 `t/` 目录，`*.t` 是 Perl Test::Nginx 用例。**读它们的价值高于读任何博客**：

```bash
# 例：ngx_http_lua_module 的共享字典用例
git clone https://github.com/openresty/lua-nginx-module
less lua-nginx-module/t/109-shared.t          # 共享字典 incr / decr / flush_expired
less lua-nginx-module/t/164-socket.t          # cosocket 全套
less lua-nginx-module/t/023-request.t         # ngx.req.*
```

用例结构固定三段：

```text
=== TEST 1: 用例名
--- config
    location /test {
        content_by_lua_block { ... }
    }
--- request
GET /test
--- response_body
hello
```

想验证一个不确定的 API 行为，最快就是**从 `t/` 挑一个最接近的用例改一改**。

# 本地跑官方用例

```bash
# 1. 装 Perl 测试依赖
cpanm --notest Test::Nginx

# 2. clone 目标模块
git clone https://github.com/openresty/lua-resty-core
cd lua-resty-core

# 3. 用 Perl prove 跑测试
export TEST_NGINX_BINARY=/usr/local/openresty/nginx/sbin/nginx
prove -v -I /path/to/test-nginx/lib t/*.t
```

`TEST_NGINX_BINARY` 指向**已编译的 nginx 二进制**——通常是 OpenResty 装好的那个。不设它，Test::Nginx 会尝试自己编译 nginx，很慢。

# 一个可复用的最小测试骨架

新写一个 Lua 库时，直接抄这个：

```text
# t/smoke.t
use Test::Nginx::Socket::Lua 'no_plan';
run_tests();

__DATA__

=== TEST 1: lib loads
--- lua_code_top
local mylib = require "mylib"
--- config
    location = /t {
        content_by_lua_block {
            ngx.say(mylib.hello())
        }
    }
--- request
GET /t
--- response_body
hello from mylib
```

跑起来：

```bash
prove -v t/smoke.t
```

# 避坑

- **博客 / 教程里出现的 API 别盲信**——很多是 1.13/1.15 时代的用法，有些签名早已改；权威只有 `lua-nginx-module` 的 README 和 `t/` 用例。
- **`restydoc` 更新滞后**：新模块可能未收录；查不到就直接读 GitHub README。
- **跑测试前一定 `export TEST_NGINX_BINARY`**，否则会现场编译 nginx，浪费几分钟。
- **`lua_code_cache on` 会污染测试**：跑测试时通常 `lua_code_cache off` 让改动即时生效；跑基准测试要 `on`。

# 总结

- 权威文档 = 模块仓库 README；`t/` 目录 = 可执行示例；
- `restydoc` 适合命令行速查，不适合深入；
- 写新库照 Test::Nginx 骨架起步，比自造测试脚本省一半时间。
