# 概述

请求进来 → Lua 处理 → 响应出去，这条主干上，OpenResty 提供了一整套 `ngx.req.*` / `ngx.resp.*` / `ngx.var.*` / `ngx.ctx` / `ngx.socket.*` API。本文按请求生命周期串一遍，边写边给可运行代码。

# 读请求

```lua
-- 请求方法 / URI / 协议
local method = ngx.req.get_method()            -- "GET" / "POST" / ...
local uri    = ngx.var.request_uri             -- 带 query 的完整 URI
local path   = ngx.var.uri                     -- 只有路径
local args   = ngx.req.get_uri_args(100)       -- 查询参数表；上限 100 防放大

-- Header
local h = ngx.req.get_headers(100)             -- 键全小写；上限 100
local ua = h["user-agent"]
local auth = ngx.req.get_headers()["authorization"]

-- Body：先声明"我要读 body"
ngx.req.read_body()                            -- 不调这句，get_body_data() 返回 nil
local body = ngx.req.get_body_data()           -- 内存里的 body；若已缓冲到临时文件则返回 nil
if not body then
    local file = ngx.req.get_body_file()
    if file then
        local fh = io.open(file, "rb")         -- 这里 io.open 只用于读临时文件，允许
        body = fh:read("a")
        fh:close()
    end
end

-- POST form 参数
local form = ngx.req.get_post_args()           -- 隐含调用 read_body()
```

**上限必设**：`get_uri_args`/`get_headers`/`get_post_args` 默认 30 项，防大请求打爆 worker。生产设 100–200 足够；上限之外会静默丢弃，用 `ngx.req.get_headers(max)` 显式覆盖。

# 改请求

```lua
-- 常见于网关侧透传前的清洗
ngx.req.set_uri("/rewritten", false)           -- 第二参 false = 不触发 rewrite 循环
ngx.req.set_uri_args({ a = 1, b = {2,3} })     -- 覆盖 query
ngx.req.set_header("X-Real-IP", ngx.var.remote_addr)
ngx.req.clear_header("If-Modified-Since")

-- 内部子请求：并行拉多份资源
local sub1 = ngx.location.capture("/internal/userinfo", { method = ngx.HTTP_GET })
local sub2 = ngx.location.capture("/internal/config",   { method = ngx.HTTP_GET })
if sub1.status == 200 and sub2.status == 200 then
    ngx.say(sub1.body, sub2.body)
end
```

`ngx.location.capture` 走的是"内部子请求"——命中的是**同 server / 同 upstream** 的另一个 `location`；它天然并发（在 cosocket 层做非阻塞），一次可以并发几十上百个。

# 写响应

```lua
ngx.status = 201
ngx.header["Content-Type"] = "application/json"
ngx.header["X-Request-Id"] = ngx.var.request_id       -- nginx 1.11.0+；OpenResty 里也有

-- 三选一：
ngx.say("line 1")                                     -- 追加并带 \n
ngx.print("partial")                                  -- 追加不带 \n
ngx.resp.get_headers()                                -- 读当前已设置的响应头

-- 提前结束：
ngx.arg                                   -- 空
ngx.exit(200)                             -- 完成，走 body_filter/log
ngx.exit(ngx.HTTP_INTERNAL_SERVER_ERROR)  -- 500
ngx.eof()                                 -- 显式发送最后一块，之后仍可继续 log/timer
```

**`ngx.exit` vs `return ngx.exit`**：在 `_by_lua_block` 里，`ngx.exit` 会**立即中断当前阶段协程**；`return ngx.exit` 语义一样但更清晰。混用容易漏 return，导致 exit 之后又有代码跑到——建议一律 `return ngx.exit(...)`。

# 跨阶段共享状态：ngx.ctx

```lua
rewrite_by_lua_block {
    ngx.ctx.trace_id = ngx.var.request_id
    ngx.ctx.start_ts = ngx.now()
}

access_by_lua_block {
    -- 能拿到 rewrite 阶段存的字段
    assert(ngx.ctx.trace_id)
}

log_by_lua_block {
    local dur = ngx.now() - ngx.ctx.start_ts
    ngx.log(ngx.INFO, "trace=", ngx.ctx.trace_id, " dur=", dur)
}
```

`ngx.ctx` 是一个每请求 Lua table。**它的生命周期 = 一次请求**——子请求会拿到一份 shallow copy。

**性能**：`ngx.ctx` 走 C 到 Lua 的 table 拷贝，热路径大对象放这里不如放 `ngx.id` 索引的模块级 WeakTable（详见 [02 章 050.table 与 metatable 内幕](../02.Lua与OpenResty运行时内幕/050.table与metatable内幕.md)）。

# 上游 socket：cosocket 简版

```lua
local sock = ngx.socket.tcp()
sock:settimeouts(2000, 5000, 5000)                  -- connect / read / write 三段超时 ms
local ok, err = sock:connect("10.0.0.5", 6379, { pool = true, pool_size = 32 })
if not ok then return ngx.exit(ngx.HTTP_BAD_GATEWAY) end

sock:send("*2\r\n$3\r\nGET\r\n$3\r\nfoo\r\n")
local line = sock:receiveLine()
sock:setkeepalive(10000, 32)                        -- 归还连接池；空闲 10s、池 32
```

细节见 [050.cosocket 核心精髓](./050.cosocket核心精髓.md)。

# 完整示例：网关侧的清洗 + 转发 + 计时

```lua
-- access_by_lua_block
local start = ngx.now()
ngx.ctx.start = start

-- 1. 参数与头清洗
local args = ngx.req.get_uri_args(200)
if not args.token then return ngx.exit(ngx.HTTP_UNAUTHORIZED) end

ngx.req.set_header("X-Trace-Id", ngx.var.request_id)
ngx.req.clear_header("X-Internal-Only")

-- 2. 转发由 proxy_pass 完成；这里只做前置

-- log_by_lua_block
ngx.log(ngx.INFO,
    "uri=", ngx.var.uri,
    " status=", ngx.status,
    " dur_ms=", (ngx.now() - ngx.ctx.start) * 1000,
    " upstream_ms=", tonumber(ngx.var.upstream_response_time) or 0)
```

# 避坑

- **`read_body` 之前调 `get_body_data` = nil**：nginx 默认不缓冲 body，`_by_lua*` 里必须显式 `read_body`。
- **body 太大落临时文件**：超过 `client_body_buffer_size` 时，`get_body_data` 返回 nil、`get_body_file` 返回路径。想避免落盘：调大 `client_body_buffer_size`。
- **`get_headers` 键全小写**：`h["User-Agent"]` 拿不到；写 `h["user-agent"]`。
- **`ngx.say` 只在有请求的上下文有效**：`init_worker`/`timer` 里调它没有输出目标，会静默失败。
- **`ngx.ctx` 别放函数**：序列化到子请求时函数丢失；只放数据。
- **`ngx.location.capture` 里的 location 必须 `internal`**：不 `internal` 也能跑，但会被外部直接访问，形成漏洞。

# 总结

- 读：`get_uri_args` / `get_headers` / `read_body` / `get_body_data`；
- 改：`set_uri` / `set_uri_args` / `set_header` / `clear_header`；
- 写：`ngx.status` / `ngx.header` / `ngx.say` / `ngx.print` / `ngx.exit`；
- 跨阶段：`ngx.ctx`；
- 并发子请求：`ngx.location.capture`。
