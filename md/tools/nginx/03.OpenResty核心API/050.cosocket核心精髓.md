# 概述

`cosocket`（coroutine socket）是 OpenResty 最核心的能力：**非阻塞 + 协程挂起 + 连接池**三件套，让 Lua 代码写起来像同步，跑起来是全异步。本文拆开这三层，再给完整使用规范。

# 三层结构

```text
你的 Lua 代码        sock:send / sock:receive / sock:connect
     ↓
协程层              yield 当前 coroutine、等 epoll 唤醒
     ↓
nginx 事件循环      注册读/写事件、回调唤醒 coroutine
     ↓
OS socket           非阻塞 fd
```

**关键约束**：`cosocket` API 只能在**有请求上下文或 timer 上下文**里创建——`init`/`init_worker` 阶段没有 coroutine 宿主，不能用。

# API 骨架

```lua
local sock, err = ngx.socket.tcp()          -- 或 ngx.socket.udp()
if not sock then return nil, err end

-- 超时：三个独立值
sock:settimeouts(
    2000,     -- connect 超时（ms）
    5000,     -- receive 超时
    5000      -- send 超时
)

-- 连接
local ok, err = sock:connect("127.0.0.1", 6379, {
    pool = "redis_main",                     -- 池名（默认 host:port）
    pool_size = 64,                          -- 单 worker 池上限
    backlog = 128,                           -- 溢出时的等待队列
    keepalive = true,                        -- 是否启用 TCP keepalive
})
if not ok then return nil, err end

-- 发送
local bytes, err = sock:send("PING\r\n")

-- 接收：四种模式
local line = sock:receiveLine()                       -- 读到 \n
local chunk = sock:receive(5)                          -- 精确读 5 字节
local rest = sock:receive("*a")                        -- 读到 EOF（谨慎！）
local hdr = sock:receive("*l")                         -- 与 receiveLine 等价但保留 \r

-- 半关闭 / 关闭
sock:shutdown("both")
sock:close()

-- 归还池：核心 API
local ok, err = sock:setkeepalive(
    10000,     -- 空闲超时（ms），默认lua_socket_keepalive_timeout
    32         -- 池大小上限，默认lua_socket_pool_size
)
```

# 连接池的三个数字

| 配置项 | 出现位置 | 语义 |
|--------|----------|------|
| `lua_socket_pool_size 32;` | nginx.conf（http/stream 级） | 单 worker、单 pool 的**最大空闲连接数** |
| `sock:setkeepalive(timeout, size)` | Lua 代码 | 覆盖上一条；`size` 是运行时上限 |
| `backlog` | `connect` 选项 | 池满时新连接排队长度；超过 503 或 `busy` |

**推荐值**：`pool_size = 目标并发 / worker 数 × 1.5`。假设 4 worker 支撑 1000 并发到同一个上游：`pool_size ≈ 375`。

# 拿到池化连接的完整链路

```lua
local sock = ngx.socket.tcp()
-- ① 尝试复用池里的连接
local ok, err = sock:connect("backend", 8080, { pool_size = 32 })

-- ② 用...
sock:send(request)
local resp = sock:receive("*l")

-- ③ 关键：用完后 setkeepalive，而不是 close
sock:setkeepalive(60000, 32)
```

**如果不调 `setkeepalive`**：`sock` 会随协程 GC **被关闭**，下次请求重新 TCP 握手。做微基准时性能差 3–10 倍。

**如果出错（超时/协议错）**：连接状态未知，**不要** `setkeepalive`；调 `sock:close()` 丢弃它。

# 半关闭与 graceful close

```lua
-- 只想写不想读时
sock:shutdown("write")    -- 让对方读到 EOF，本端仍可 receive
```

**协议场景**：HTTP client 发完请求 → `shutdown("write")` → 读响应；避免 server 等你后续发送。

# UDP 特性

```lua
local sock = ngx.socket.udp()
sock:settimeouts(2000, 5000, 5000)
sock:connect("10.0.0.1", 53)                 -- UDP 也走"connect"语义
sock:send(dns_query)
local packet = sock:receive()                -- 一次一个数据报
```

**UDP 没有连接池的意义**：`setkeepalive` 对 UDP 是 no-op；每次用完 `close`。

# DNS 解析

`connect` 里的 host 会**同步解析**（阻塞 worker！）——除非：

```lua
-- 用 lua-resty-dns-client 异步解析
local resolver = require "resty.dns.resolver":new({ nameservers = { "8.8.8.8" } })
local answers, err = resolver:query("example.com", { qtype = resolver.Types.A })
-- 拿到 IP 后再 sock:connect(ip, port)
```

或直接给 IP，绕开 DNS。**这是很多生产事故的根因**：`connect("some-host.example.com", ...)` 首次调用可能卡住 worker 5 秒。

# TLS

```lua
local ok, err = sock:connect("api.example.com", 443, {
    ssl = true,
    ssl_verify = true,               -- 打开证书校验
    ssl_client_hello = custom_hello, -- 可选：自定义握手
})
```

`ssl_verify = false` 默认值；生产环境务必 `true`，或自己 `sock:ssl_handshake(true, "sni.example.com")`。

# 避坑

- **别在 `init_worker_by_lua` 里 cosocket**：没有请求上下文，会返回 `API disabled in the context of init_worker_by_lua*`。定时任务里可以——见 [060.特权进程与定时任务](./060.特权进程与定时任务.md)。
- **`receive("*a")` 除非明确知道对端会关连接**：否则读到超时才返回，浪费几秒。
- **`connect` 的 host 走同步 DNS**：见上，永远预解析或直接给 IP。
- **`setkeepalive` 之前必须读完/写完**：残留数据会让下一个协程读到脏包（协议错乱）。想清楚，出错时 `close()`。
- **`sock` 变量跨请求复用不了**：每次都要 `ngx.socket.tcp()` 新创建，池是内部的、透明复用。
- **connect 后异常**：`ok, err = sock:connect(...)` 拿到 err 时**别继续 send**。

# 总结

- 三层：Lua API → 协程 yield → nginx 事件；
- 生命周期：`tcp() → settimeouts → connect → send/receive → setkeepalive`；
- 池三数字：`pool_size` / `setkeepalive(timeout, size)` / `backlog`；
- 出错就 `close`，正常用完必须 `setkeepalive`；
- DNS 同步阻塞是隐藏炸弹，能预解析就预解析。
