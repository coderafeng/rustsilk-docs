# 概述

除开请求响应、cosocket、shared dict，日常写 Lua 代码时最高频的其实是**时间、字符串、正则、编码、随机**这些"琐碎 API"。OpenResty 给了一套 `ngx.*` 版本，避开 Lua 标准库和 LuaJIT 的坑。

# 时间

| API | 语义 | 备注 |
|-----|------|------|
| `ngx.now()` | 秒 + 毫秒（浮点） | **cached**：同一次请求返回同一值，除非 `ngx.update_time()` |
| `ngx.time()` | 整秒 Unix 时间戳 | 同上，缓存 |
| `ngx.update_time()` | 强制刷新缓存 | 打点、算耗时前调 |
| `ngx.today()` | `YYYY-MM-DD` | 缓存时间 |
| `ngx localtime()` / `ngx.unixtime()` | 分解字段 | — |
| `ngx.req.start_time()` | **请求进入 nginx 的时刻**（不受缓存影响） | 算耗时首选 |

## 算请求耗时的正确写法

```lua
log_by_lua_block {
    local dur_ms = (ngx.now() - ngx.req.start_time()) * 1000
    ngx.log(ngx.INFO, "dur=", dur_ms, "ms")
}
```

**不要**用 `ngx.now()` 减自己协程里的另一个 `ngx.now()`——两者可能相同。**用 `ngx.req.start_time()` 或 `ngx.update_time()`**。

# 字符串 / 编码

| API | 用途 |
|-----|------|
| `ngx.encode_base64(s)` / `ngx.decode_base64(s)` | Base64；比 Lua 纯实现快 |
| `ngx.encode_base32` / `decode_base32` | Base32（TOTP 常用） |
| `ngx.hmac_sha1(secret, s)` | HMAC-SHA1 |
| `ngx.md5(s)` / `ngx.md5_bin(s)` | MD5 |
| `ngx.sha1_bin(s)` | SHA1 二进制 |
| `ngx.crc32_short(s)` / `ngx.crc32_long(s)` | CRC32；短/长实现按输入长度自动切换 |
| `ngx.escape_uri(s)` / `ngx.unescape_uri(s)` | URL 编解码 |
| `ngx.quote_sql_str(s)` | MySQL 字符串字面量转义 |
| `ngx.is_safe_method(m)` | HTTP 方法是否可安全重放 |

## 加密扩展

SHA256 / SHA512 / AES 不在 `ngx.*` 里；用 `lua-resty-string` 或 `resty.openssl`：

```lua
local sha2 = require "resty.string"                -- 或 lua-resty-string
local md5_hex = sha2.to_hex(md5_bin)

local ossl = require "resty.openssl.digest"
local d, _ = ossl.new("sha256")
d:update(body)
local digest = d:final()
```

# 正则 `ngx.re`

`ngx.re` 底层是 **PCRE2 + 编译缓存**，比 Lua 原生 `string.find`（Lua Pattern，弱）强得多，也避免了 LuaJIT 里正则字符串重复编译。

## API 全表

| 方法 | 说明 | 返回 |
|------|------|------|
| `ngx.re.match(subject, regex, options, ctx, res_table)` | 匹配第一个 | captures 表 或 nil；err |
| `ngx.re.find(subject, regex, options, ctx, nth)` | 只返位置 | from, to, err；比 match 快 |
| `ngx.re.gmatch(subject, regex, options, ctx)` | 全匹配迭代器 | iterator |
| `ngx.re.sub(subject, regex, repl, options, ctx)` | 替换第一处 | newstr, num, err |
| `ngx.re.gsub(subject, regex, repl, options, ctx)` | 替换所有 | newstr, num, err |

## options 常用位

- `i` 忽略大小写；`s` 单行模式（. 匹配换行）；`m` 多行；
- `j` PCRE_INFO_JCHANGED（允许在命名捕获里重名）；
- `o` **只编译一次**（regex 必须是常量！动态拼接的 regex 千万别加 `o`，会导致缓存串）；
- `g` 全局匹配；`U` 非贪婪；
- 数字（如 `2`）：limit，最多匹配次数。

## 示例

```lua
-- 只关心位置：find 比 match 快
local from, to, err = ngx.re.find(uri, [[^/api/v(\d+)/]], "jo")
if from then
    local version = uri:sub(to - 0, to)   -- 抓最后一位；或第 3 参 nth 拿具体捕获
end

-- 命名捕获
local m = ngx.re.match(sed, [[^(?<key>\w+)=(?<val>.+)$]], "o")
if m then
    local key, val = m.key, m.val
end

-- gsub 一次替换所有 token
local new_body = (ngx.re.gsub(body, "{{\\s*(\\w+)\\s*}}", function(m)
    return vars[m[1]] or ""
end, "jo"))
```

## 正则缓存

- PCRE 编译结果**进程内缓存**（默认 `lua_regex_cache_max_entries 1024`，指令可调）；
- **超过 1024 条**：新的 regex 每次现场编译 → CPU 高。避免动态拼接 regex；用固定模式 + `o`。

# JSON

OpenResty 内置 `cjson`（lua-cjson）：

```lua
local cjson = require "cjson"
local cjson_safe = require "cjson.safe"     -- 出错返 nil, err 而不抛异常

local obj  = cjson.decode(body)
local json = cjson.encode(obj)

-- 空对象要 {}，别让 cjson 编成 []：
cjson.encode_empty_table_as_object(false)   -- 或 true（默认 true）
```

**性能注意**：`cjson.encode` 对超大表慢；热路径考虑 `lua-resty-json` 或手工拼接。

# 随机

**禁用** `math.random`（LuaJIT 里它非协程安全、种子共享）；用 `ngx.random`：

```lua
local r = ngx.random(1, 100)                -- 均匀分布
```

或 `lua-resty-string` 的 `resty.random`：

```lua
local bytes = require("resty.random").bytes(32, true)   -- 加密安全
```

# URL 解析

`ngx.req.get_uri_args` 只解 query。要完整解析 URL：

```lua
local parse = require "resty.url".parse
local p = parse("https://user:pass@example.com:8443/a/b?x=1#frag")
-- p = { scheme="https", userinfo="user:pass", host="example.com", port=8443,
--       path="/a/b", query={x="1"}, fragment="frag" }
```

# 避坑

- **`ngx.now()` 缓存陷阱**：见上，热路径打时间戳要 `ngx.update_time()`；`log_by_lua` 里通常够用。
- **`ngx.re` 里 `o` 只能配常量 regex**：动态 regex + `o` = 缓存串扰，是经典事故。
- **`cjson.decode` 空 body 抛异常**：`cjson.safe.decode` 返 `nil, "expected object"`。
- **`math.random` 多 worker 同种子**：跨 worker 生成同随机数；改 `ngx.random`。
- **`ngx.quote_sql_str` 只用于 MySQL**：不同 DB 转义规则不同；建议参数化。

# 总结

- 时间：`ngx.now()` 缓存 + `ngx.req.start_time()` 打点；
- 编解码：`ngx.*_base64/base32/md5/sha1/crc32/escape_uri/quote_sql_str`；
- 正则：`ngx.re.find/match/gmatch/sub/gsub`，永远带 `o`（常量 regex 场景）；
- JSON：`cjson` / `cjson.safe`；
- 随机：`ngx.random`；
- URL：`resty.url.parse`。
