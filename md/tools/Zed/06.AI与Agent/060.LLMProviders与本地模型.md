# 概述

**LLM Providers** 决定哪些模型为 [Zed Agent](./020.AgentPanel与ZedAgent.md) 及 Zed 自有的 AI 功能（Inline Assistant、Git 提交信息生成、线程摘要等）供能。本页梳理五条「模型访问路径」及本地模型方案。

> [!important] 谁受这里配置影响
> 模型访问路径**不**配置 External Agents 或 Terminal Threads——它们自带模型访问、认证与配置。本页只作用于 Zed Agent 与 Zed 自有 AI 功能。

> [!note] Edit Prediction 单独配
> [Edit Prediction](./050.InlineAssistant与EditPrediction.md) 有自己的 provider 设置（`edit_predictions`），不走本页的 LLM providers。

## 五条模型访问路径

| 路径 | 最适合 | 说明 |
|------|--------|------|
| **Zed-Hosted Models** | 想用由 Zed 计费的托管模型 | 登录 Zed 账号即用，无需管理各家 API key |
| **Use API Access** | 自带 provider API key / 额度 / 用量计费 | 直连 Anthropic、OpenAI 等，或 OpenAI/Anthropic 兼容端点 |
| **Use an Existing Subscription** | 已付费订阅 ChatGPT / Claude / Copilot 等 | 复用你已有的订阅 |
| **Use a Gateway** | 走 OpenRouter / Amazon Bedrock / Vercel AI Gateway 等 | 由网关统一路由到上游 provider |
| **Use a Local Model** | 本地或自托管运行模型 | Ollama、LM Studio、本地 OpenAI 兼容服务 |

> [!important] API key 存放位置
> 通过 Zed 保存的 provider key 存放在**系统 keychain**（Windows 凭据管理器 / macOS 钥匙串 / Linux secret service），**不写进** `settings.json`。因此别指望在设置文件里看到明文 key，也不要把 key 手动塞进 settings.json 提交到仓库。

## Zed-Hosted Models（最省事）

登录 Zed 账号后，即可使用由 Zed 路由、按 Zed 计费方式结算的托管模型。优点：

- 无需分别注册、管理 Anthropic / OpenAI / Google 等多套 API key。
- 所有托管模型**开箱支持工具调用**（tool calling），Agent Panel 的 agentic editing 直接可用。
- Edit Prediction 的 **Zeta** 也需要登录才能用。

在 Agent Panel 的模型选择器里，托管模型的 provider 显示为 `zed.dev`。

## Use API Access（自带 key）

若你已有某 provider 的 API 访问权、额度或用量计费账户，可直接接入。Anthropic 兼容、OpenAI 兼容的端点都在此路径下配置。配置入口：`agent: open settings`（Settings → AI）或 Settings Editor 里对应 provider 项。key 输入后存入系统 keychain。

## Use an Existing Subscription

已经为 ChatGPT、Claude、GitHub Copilot 等付费订阅的用户，可复用现有订阅，而不必单独购买 API 额度。具体按各订阅的接入方式在 Settings → AI 里登录授权。

## Use a Gateway（网关）

通过 OpenRouter、Amazon Bedrock、Vercel AI Gateway 等平台统一路由到多个上游 provider。适合想用一个入口/一份账单访问多家模型，或有企业合规路由需求的场景。

## Use a Local Model（本地/自托管）

在本地或自托管环境跑模型，数据不出本机，适合离线、隐私敏感或成本敏感场景。常见后端：

- **Ollama**：本地拉取并运行开源模型，默认 `http://localhost:11434`。
- **LM Studio**：本地图形化运行模型，暴露 OpenAI 兼容 API。
- **本地 OpenAI 兼容服务**：vLLM、llama.cpp server、LocalAI 等。

在 Settings → AI 里为对应 provider 填 `api_url` 与 `model` 即可。Edit Prediction 也能用本地模型（Ollama / OpenAI 兼容），配置见 [050.InlineAssistant与EditPrediction](./050.InlineAssistant与EditPrediction.md#本地与自托管模型)。

> [!tip] 本地模型与工具调用
> 本地小模型的工具调用能力参差不齐。若要用 Agent Panel 的 agentic editing（自动改文件、跑命令），优先选明确支持 function/tool calling 的模型；纯补全或 Inline Assistant 场景对工具调用要求低，本地模型更可行。

## 模型选择与切换

配好 provider 后，在 Agent Panel 消息编辑框点模型选择器或按 `Ctrl+Alt+/`（macOS `Cmd+Alt+/`）切换。注意：

- 同一模型可能由多个 provider 提供，认准选择器里模型左侧的 **provider logo**。
- 用 `agent.favorite_models` 收藏常用模型，`Alt+Tab`（macOS `Alt+L`）在收藏间循环。
- 可为特定功能指定模型，如 `agent.commit_message_model`（Git 提交信息生成）。

## 设置里的默认模型

```jsonc
{
  "agent": {
    "default_model": { "provider": "zed.dev", "model": "claude-sonnet-4-5" },
    "inline_assistant_model": { "provider": "zed.dev", "model": "gpt-5-mini" }
  }
}
```

- `default_model`：agent 线程默认模型，也是 Inline Assistant 未单独配置时的回退。
- `inline_assistant_model`：Inline Assistant 专用主模型。
- `inline_alternatives`：Inline Assistant 额外并行生成用的备选模型（见 [050](./050.InlineAssistant与EditPrediction.md#多模型)）。

## 完全关闭 AI

Settings Editor 搜 `Disable AI` 启用，或：

```jsonc
{ "disable_ai": true }
```

关闭后 Threads Sidebar、Agent Panel、Edit Prediction、Inline Assistant 全部禁用。隐私与数据保留细节见 [070.AI隐私与安全](./070.AI隐私与安全.md)。
