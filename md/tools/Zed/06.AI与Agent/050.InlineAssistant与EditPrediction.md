# 概述

本页覆盖 Zed 两个「就地生成代码」的 AI 功能。它们都在编辑器里内联出代码，但触发方式截然不同：

- **Inline Assistant（内联助手）**：**显式、prompt 驱动**。你写一句 prompt、选中要改的内容，AI 用响应替换它。
- **Edit Prediction（编辑预测）**：**自动、上下文推断**。Zed 根据你最近的改动、访问过的文件、光标位置自动建议编辑，无需 prompt。

# Inline Assistant

## 使用总览

用 `Ctrl+Enter`（macOS 同为 `Ctrl+Enter`，也可 `Ctrl+I`）在编辑器、channel notes、终端面板里打开 Inline Assistant。它把当前选区（或整行）发给语言模型，并用响应替换。

## 前置条件

首次使用需至少配置一个 [LLM provider](./060.LLMProviders与本地模型.md)：用 Zed 托管模型，或用 API access（Anthropic 等 provider 或 OpenRouter 等网关）。若已为 Agent Panel 配好 provider，Inline Assistant 直接可用。

> [!note] External Agents 不适用于 Inline Assistant
> External Agents 只在 agent 线程里运行，不能用于 Inline Assistant 生成。Inline Assistant 用 Zed 配置的 LLM providers（含托管模型、provider API key、网关、本地模型、支持的订阅）。

## 添加上下文

与 Agent Panel 一样：@-mention 文件、目录、历史线程、指令文件、符号；粘贴剪贴板里的图片。还能先在 Agent Panel 建线程，再用 `@thread` 在 Inline Assistant 里引用它——无需重述上下文即可打磨大线程里的某个具体改动。

## 并行生成

### 多光标

有多光标时，按 `Ctrl+Enter` 会把同一 prompt 发到每个光标位置，同时在所有位置生成改动。这与 [multibuffer](../04.代码编辑与导航/060.Multibuffers多缓冲.md) 里的 excerpt 配合极佳。

### 多模型

可把同一 prompt 一次发给多个模型。在设置文件里配置 `inline_alternatives`：

```jsonc
{
  "agent": {
    "default_model": { "provider": "zed.dev", "model": "claude-sonnet-4-5" },
    "inline_alternatives": [
      { "provider": "zed.dev", "model": "gpt-5-mini" },
      { "provider": "zed.dev", "model": "gemini-3-flash" }
    ]
  }
}
```

配置多模型后，Inline Assistant UI 会出现按钮让你在各模型输出间循环。这里的模型总是在主模型（`agent.inline_assistant_model`，未配则用 `agent.default_model`）**之外**额外使用。上例每次 assist 生成三份输出：Claude Sonnet 4.5、GPT-5-mini、Gemini 3 Flash。

## 预填 prompt

在 keymap 里加自定义键位以预填 prompt：

```jsonc
[
  {
    "context": "Editor && mode == full",
    "bindings": {
      "ctrl-shift-enter": ["assistant::InlineAssist", { "prompt": "Build a snake game" }]
    }
  }
]
```

# Edit Prediction

Edit Prediction 是 Zed 的 AI 代码补全方式：LLM 预测你想写的代码。你打字时，Zed 向 edit prediction provider 请求预测，返回单行或多行建议，按 `Tab` 接受。

默认 provider 是 **Zeta**（Zed 自研的开源模型），也可用 GitHub Copilot、Mercury Coder、Codestral 等其它 provider。

## 配置 Zeta

要用 Zeta 需先[登录](https://zed.dev/docs/authentication)。登录后打字即出现预测。验证方式：打开 Settings Editor（`Ctrl+,`）搜 `edit_predictions`，`provider` 应为 `Zed AI`；或在 settings.json：

```jsonc
{ "edit_predictions": { "provider": "zed" } }
```

状态栏的 **Z 图标**也表示 Zeta 已激活。

> [!note] 定价
> Zeta 预测包含在 Zed Pro、Pro 试用、Student、Business 计划里。Free 计划可用其它 provider（如 GitHub Copilot）或本地模型。

## 两种显示模式

1. `eager`（默认）：只要不与 language server 补全冲突，就内联显示预测。
2. `subtle`：仅在按住修饰键（默认 `Alt`）时内联显示。

```jsonc
"edit_predictions": { "mode": "eager" }  // 或 "subtle"
```

也可在状态栏菜单里切换。模式对任何预测 provider 都有效。

## 默认键位

- 所有平台：`Alt+Tab` 接受预测。Linux/Windows 上 `Alt+Tab` 常被系统用于切窗口，故这些平台还默认绑了 `Alt+L`。
- `eager` 模式下也可用 `Tab` 接受，除非补全菜单开着（此时 `Tab` 接受 LSP 补全）。想用 `Tab` 插入空白，先按 `Esc` 取消预测再按 `Tab`。
- `editor: accept next word edit prediction`（`Alt+K`，macOS `Ctrl+Cmd+→`）：接受到下一个词边界。
- `editor: accept next line edit prediction`（`Alt+J`，macOS `Ctrl+Cmd+↓`）：接受到下一行边界。

## 配置接受键位

### 始终用 Tab

让 `Tab` 总是接受预测（无论 LSP 补全菜单是否打开）：

```jsonc
[
  {
    "context": "Editor && edit_prediction",
    "bindings": { "tab": "editor::AcceptEditPrediction" }
  }
]
```

之后 `Tab` 仍可用于接受 LSP 补全。

### 始终用 Alt+Tab

停止用 `Tab`、改用 `Alt+Tab`，在 eager 上下文解绑默认 `tab`：

```jsonc
[
  {
    "context": "Editor && edit_prediction",
    "unbind": { "tab": "editor::AcceptEditPrediction" }
  }
]
```

### 同时重绑 Tab 与 Alt+Tab

```jsonc
[
  {
    "context": "Editor && edit_prediction",
    "unbind": {
      "alt-tab": "editor::AcceptEditPrediction",
      // Windows/Linux 还可加 "alt-l": "editor::AcceptEditPrediction",
      "tab": "editor::AcceptEditPrediction"
    },
    "bindings": { "ctrl-enter": "editor::AcceptEditPrediction" }
  }
]
```

> [!note] 旧 keymap 清理
> Zed v0.229.0 之前配置的键位可能有冗余项。`unbind` 出现前，阻止 `tab` 接受预测的唯一办法是把所有默认非预测 `tab` 绑定拷进 keymap——若还留着这些拷贝项，删掉它们改用单条 `unbind`。旧 `edit_prediction_conflict` 上下文已被 `edit_prediction && (showing_completions || in_leading_whitespace)` 取代，Zed 会自动迁移。

## 配置预测防抖（Debounce）

防抖控制你停止打字后 Zed 等多久才自动请求预测（毫秒），在所选 provider 设置下配置：

```jsonc
{
  "edit_predictions": {
    "provider": "open_ai_compatible_api",
    "open_ai_compatible_api": { "prediction_debounce": 500 }
  }
}
```

各 provider 默认防抖：GitHub Copilot 75ms、Codestral 150ms、Zed / Mercury / Ollama / OpenAI 兼容 API 均 0ms。设 `0` 禁用额外延迟。用 `editor: show edit prediction` 显式请求会绕过防抖。

## 禁用自动预测

可在多个层级关闭，或彻底关掉（也可考虑用 subtle 模式）：

```jsonc
// 所有 buffer 不自动显示
{ "show_edit_predictions": false }

// 仅特定语言
{ "languages": { "Python": { "show_edit_predictions": false } } }

// 仅特定目录/文件
{ "edit_predictions": { "disabled_globs": ["~/.config/zed/settings.json"] } }

// 彻底关闭（所有 provider）
{ "edit_predictions": { "provider": "none" } }
```

设 `show_edit_predictions: false` 后仍可用 `editor: show edit prediction` 或 `Alt+Tab`（macOS `Alt+\`）手动触发。

## 其它 Provider

### GitHub Copilot

```jsonc
{ "edit_predictions": { "provider": "copilot" } }
```

登录：点状态栏 Copilot 图标，弹窗显示 device code，复制后点 "Connect to GitHub" 打开验证页粘贴 code。企业版可设 `copilot.enterprise_uri`（如 `https://foo.ghe.com`），对 Copilot 预测与 Chat 均生效。Copilot 可提供多个候选，用 `editor: next edit prediction`（`Alt+]`）/ `previous`（`Alt+[`）循环。

### Mercury Coder / Codestral

Settings Editor 搜 "Edit Predictions" → **Configure Providers**，填对应 API key（Mercury 来自 Inception Labs 面板，Codestral 来自 Mistral 面板）。或直接设 `"provider": "mercury"` / `"provider": "codestral"`。

### 本地与自托管模型

可用 Ollama 或任何实现 OpenAI completion API 格式的服务器（Ollama、vLLM、llama.cpp server、LocalAI 等）。

**Ollama：**

```jsonc
{
  "edit_predictions": {
    "provider": "ollama",
    "ollama": {
      "api_url": "http://localhost:11434",
      "model": "qwen2.5-coder:7b-base",
      "prompt_format": "infer",
      "max_output_tokens": 512
    }
  }
}
```

**OpenAI 兼容服务器：**

```jsonc
{
  "edit_predictions": {
    "provider": "open_ai_compatible_api",
    "open_ai_compatible_api": {
      "api_url": "http://localhost:8080/v1/completions",
      "model": "deepseek-coder-6.7b-base",
      "prompt_format": "deepseek_coder",
      "max_output_tokens": 512
    }
  }
}
```

`prompt_format` 控制代码上下文如何格式化给模型，可选 `zeta`/`zeta2`/`zeta2_1`/`code_llama`/`star_coder`/`deepseek_coder`/`qwen`/`code_gemma`/`codestral`/`glm`/`sweep`，或 `infer`（默认，按模型名自动检测）。OpenAI 兼容服务器须实现 `/v1/completions` 端点。

> [!tip] 本地跑 Zeta
> 想用本地 Zeta，把 `model` 设为 `zeta2` 或 `zeta2.1`、`prompt_format` 设为 `infer` 即可自动匹配对应格式；模型名不符时显式设 `zeta2` / `zeta2_1`。

# Inline Assistant vs Edit Prediction

| 维度 | Inline Assistant | Edit Prediction |
|------|------------------|-----------------|
| 触发 | 你写 prompt、选中要改的内容 | 自动，无需 prompt |
| 上下文 | 你显式控制 | Zed 依最近改动、访问文件、光标推断 |
| 键位 | `Ctrl+Enter` | `Tab` / `Alt+Tab` |
| 适合 | 有明确意图的改写 | 顺手补全下一处编辑 |

一句话：Inline Assistant 显式、prompt 驱动；Edit Prediction 自动、上下文推断。
