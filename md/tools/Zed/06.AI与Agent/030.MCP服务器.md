# 概述

Zed 通过 **Model Context Protocol（MCP）** 与「上下文服务器（context servers）」交互。

> MCP 是一个开放协议，用标准接口把 LLM 应用连接到外部工具与数据源。

一句话理解：MCP 让 agent 除了 Zed 内置工具外，还能调用**外部世界**的能力——查文档、操作 GitHub、跑数据库、控制浏览器等。

## 支持的特性

Zed 目前支持 MCP 的 **Tools（工具）** 与 **Prompts（提示）** 特性，并处理 `notifications/tools/list_changed` 通知——server 在运行时增删改工具时，Zed 会自动重载工具列表，无需重启 server。（Discovery、Sampling、Elicitation 等特性欢迎社区贡献。）

## 三种 agent 路径下的 MCP 行为

| Agent 路径 | MCP 行为 |
|------------|----------|
| **Zed Agent** | 直接使用 Zed 配置的 MCP servers |
| **External Agents** | Zed 可经 ACP 转发配置的 MCP servers；agent 也可能读自己的原生 MCP 配置 |
| **Terminal Threads** | 原生 CLI/TUI 读自己的 MCP 配置 |

## 安装 MCP Server

### 方式一：作为扩展安装

许多 MCP server 以 Zed 扩展形式提供。查找途径：

1. [Zed 官网扩展页](https://zed.dev/extensions?filter=context-servers)
2. 应用内命令面板执行 `zed: extensions`
3. 应用内 **Settings → AI → MCP Servers**，点 `Add Server` → `Install from Extensions`

热门扩展形式 MCP server 包括：Context7、GitHub、Puppeteer、Gem、Brave Search、Prisma、Framelink Figma、Resend 等。

你也可以把自己的 MCP server 做成扩展（见官方 MCP Server Extensions 文档与 [07.扩展与语言支持](../07.扩展与语言支持/001.扩展概述.md)）。

### 方式二：自定义 server（本地/远程）

不做扩展也能连。在 **Settings → AI → MCP Servers**（也可 `agent: open settings` 后选 `MCP Servers`）点 `Add Server`，选 `Add Local Server` 或 `Add Remote Server`。配置会写入设置文件（`zed: open settings file` 打开），形如：

```jsonc
{
  "context_servers": {
    "local-mcp-server": {
      "command": "some-command",
      "args": ["arg-1", "arg-2"],
      "env": {}
    },
    "remote-mcp-server": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    },
    "remote-mcp-server-with-oauth": {
      "url": "https://mcp.example.com/mcp"
    }
  }
}
```

> [!note] 远程 server 的 OAuth
> 当远程 MCP server 没有配置 `"Authorization"` 头时，Zed 会用标准 MCP OAuth 流程提示你认证。

## 使用 MCP Server

### 配置检查

多数 MCP server 安装后还需配置。

- **扩展形式**：安装后 Zed 会弹窗说明需要什么。例如 GitHub MCP 扩展要求填 [Personal Access Token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
- **自定义 server**：查阅 provider 文档，确定需要什么 command、args、env。

检查是否正常：打开 **Settings → AI → MCP Servers**，看名字旁的指示点。绿色 + "Server is active" 表示运行正常；其它颜色与提示表示异常。

### 在 Agent Panel 里用

安装完成后回到 Agent Panel 开始提示即可。

- MCP 工具被调用的可靠性因模型而异。**在提示里点名某个 MCP server** 能帮模型选它的工具。
- 若想**确保**用某个 MCP server，可建一个[自定义 profile](./020.AgentPanel与ZedAgent.md)，关掉所有内置工具（或可能冲突的工具），只开该 server 的工具。

例如 Dagger 团队建议对其 Container Use MCP server 这样做：

```jsonc
"agent": {
  "profiles": {
    "container-use": {
      "name": "Container Use",
      "tools": {
        "fetch": true,
        "edit_file": false,
        "terminal": false
        // ...关掉其余内置工具
      },
      "enable_all_context_servers": false,
      "context_servers": {
        "container-use": {
          "tools": {
            "environment_create": true,
            "environment_run_cmd": true
            // ...只开该 server 需要的工具
          }
        }
      }
    }
  }
}
```

### 工具权限（Tool Permissions）

> [!note] 版本差异
> Zed v0.224.0 及以上，工具批准由 `agent.tool_permissions.default` 控制；更早版本由布尔量 `agent.always_allow_tool_actions`（默认 `false`）控制。

`agent.tool_permissions.default` 三种取值：

- `"confirm"`（默认）：运行任何工具动作（含 MCP 工具调用）前都提示批准。
- `"allow"`：自动批准，不提示。
- `"deny"`：阻止所有工具动作。

对特定 MCP 工具的精细控制：MCP 工具的 key 格式为 `mcp:<server>:<tool_name>`（如 `mcp:github:create_issue`）。对 MCP 工具而言，条目上的 `default` 键是主要机制（基于模式的规则对 MCP 工具匹配空字符串，多数模式匹配不上）。

### External Agents

Zed 里配置的 MCP servers 会经 **Agent Client Protocol（ACP）** 转发给 External Agents；它们也能访问自己原生配置文件里的 MCP servers。

### 错误处理

MCP server 处理工具调用出错时，agent 会直接收到错误消息、操作失败。常见错误：参数无效、服务端故障（数据库连接、限流）、不支持的操作或资源缺失。错误消息会显示在 agent 响应里，便于诊断。

## 小结：MCP 与内置工具、Skills 的关系

| 机制 | 作用 | 来源 |
|------|------|------|
| **内置工具** | 搜索代码库、编辑文件、跑终端命令 | Zed 自带 |
| **MCP server** | 连接外部工具与数据源 | 扩展或自定义配置 |
| **[Skills](./040.Skills与Instructions.md)** | 可复用的任务指令包 | `~/.agents/skills/` 等 |

三者都由 Agent Profiles 与 Tool Permissions 统一管控开关与批准策略。
