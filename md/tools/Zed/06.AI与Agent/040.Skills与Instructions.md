# 概述

Zed Agent 有两套「喂给 AI 的知识」机制，容易混淆，先一句话区分：

- **Skills（技能）**：**可复用、按需调用**的任务指令包。agent 看到一份技能目录，任务匹配时自动加载，你也可以用斜杠命令手动调用。
- **Instructions（指令）**：**常驻、始终生效**的上下文，用于每次相关交互都应遵循的持久指导（如仓库约定、语气偏好、项目约束）。

| 用途 | 最适合 | 例子 |
|------|--------|------|
| Instructions | 常驻指导 | 仓库约定、偏好语气、项目约束 |
| Skills | 可复用任务工作流 | 代码审查清单、发布流程、迁移助手 |

# Skills

Skill 是给 agent 特定任务知识的**可复用指令包**：测试驱动开发流程、文档处理、数据库集成，或你团队的内部编码规范。一个 skill 就是一个含 `SKILL.md`（元数据 + 指令）的文件夹。agent 看到所有已安装 skill 的目录，可按需加载；你也能在消息编辑框用斜杠命令直接调用。

## 添加 Skills

### 自己创建

- Zed 内置 `create-skill` 技能——用 `/create-skill` 调用，agent 会带你走完流程。
- 也可从 Agent Panel 打开 **Skills Manager**（`Ctrl+Alt+L`，macOS `Cmd+Alt+L`），或点 `...` 选 **Skills**。面板外用命令面板 `agent: open skill creator`，或在 **AI > Skills** 设置页点 **Create Skill**。创建器作为设置窗口的一页打开，填写 name、description、body，可选切换 `disable-model-invocation`。技能保存到设置窗口所选 scope：**User** 标签建全局技能，**Project** 标签建项目本地技能。
- 还能从已有 GitHub Markdown 文件导入：命令面板 `agent: create skill from url`。若剪贴板里有受支持的 GitHub `.md` URL，Zed 会自动预填并抓取。

### 从 skills.sh 注册表

[skills.sh](https://skills.sh) 是开源技能的社区注册表，有各种框架、工具、工作流的技能（如 `find-skills`、`frontend-design`、`pdf`）。安装方式：把技能文件夹拷进 `~/.agents/skills/`（全局）或项目的 `.agents/skills/`（项目本地）。

## 管理 Skills

打开 Settings Editor（`Ctrl+,`，macOS `Cmd+,`）进入 **AI > Skills**。**User** 标签显示全局技能，各 **Project** 标签显示该项目技能。每个技能可：

- **Copy Share Link**：复制内嵌该技能的 `zed://skill` 链接，发给别人。
- **Open**：在编辑器打开该技能的 `SKILL.md`。
- **Delete**：从磁盘删除技能文件夹。

### 分享 Skills

在 Skills 设置页点某技能行的**链接**图标，复制 `zed://skill?data=…` 链接。该链接自包含：内嵌完整 `SKILL.md` 内容（base64url 编码），接收者无需访问你的项目或注册表。对方打开链接时，Zed 会打开预填好的 "Create Skill" 页，可审阅 name/description/body、选 scope、点 **Save** 安装。**未显式保存前不写盘**，因此分享链接绝不会静默安装指令。

## 使用 Skills

默认 agent **自主**拾取技能：它在 system prompt 里看到每个已安装技能的目录（name + description），任务匹配某技能描述时调用 `skill` 工具。

- agent 调用你创建/安装的技能时，Zed 会像其它工具一样提示你允许或拒绝。Zed 内置技能不提示。可在 Tool Permissions 里为技能设默认值，避免对信任的技能反复提示。

### 手动调用

- **斜杠命令**：在消息编辑框输入 `/`，按名选技能。
- **@-mention**：输入 `@skill`，从补全菜单选技能。

两者都会把技能指令作为上下文注入。加载的技能在线程里显示为一个 crease 按钮，点击可打开技能文件。

### 阻止自主调用

在技能 frontmatter 加 `disable-model-invocation: true`，agent 就不会自主拾取它——但它仍作为斜杠命令存在，由你掌控何时运行。适合部署、发布这类不想让 agent 自动触发的工作流。

```yaml
---
name: deploy
description: Deploy the current branch to production.
disable-model-invocation: true
---
```

## Skill 格式

### 文件夹结构

```text
my-skill/
├── SKILL.md          # 必需：元数据与指令
├── scripts/          # 可选：agent 可运行的脚本
├── references/       # 可选：附加文档
└── assets/           # 可选：模板与静态文件
```

约定文件夹名与 `SKILL.md` 里的 `name` 字段一致。

### SKILL.md 格式

以 YAML frontmatter 开头，后接 Markdown 指令：

```markdown
---
name: my-skill
description: What this skill does and when to use it.
---

## Instructions

Step-by-step instructions for the agent...
```

frontmatter 字段：

| 字段 | 必需 | 说明 |
|------|------|------|
| `name` | 是 | 仅小写字母、数字、连字符，最长 64 字符，应与文件夹名一致 |
| `description` | 是 | 技能做什么、何时用，最长 1024 字符（超长仍加载但告警） |
| `disable-model-invocation` | 否 | 设 `true` 从 agent 目录隐藏（仅斜杠命令/@-mention 可调用） |

> [!tip] 写好 description
> description 要帮 agent 识别技能何时相关，包含具体任务类型与触发短语。「Use when handling PDFs, extracting text, or filling forms」比「Helps with PDFs」好得多。

`name` 校验规则：仅小写字母/数字/连字符，不以连字符开头结尾，不含连续连字符（`--`），1~64 字符。非法 name 的技能加载失败并在 UI 报错。

### 打包资源与渐进式披露

`SKILL.md` body 保持在 **500 行以内**，把详细材料移到 reference 文件并从 body 链接。agent 用 `read_file`、`list_directory` 工具**按需**加载这些文件。技能采用[渐进式披露（progressive disclosure）](https://agentskills.io/specification#progressive-disclosure)：agent 激活技能前只看到 name 与 description，激活后才加载完整 body。因此把最重要的指令放 body 顶部，脚本放 `scripts/`。

## Skills 存放位置

| Scope | 路径 | 生效范围 |
|-------|------|----------|
| 全局 | `~/.agents/skills/` | 每个项目 |
| 项目本地 | `<worktree>/.agents/skills/` | 仅当前项目 |

每个技能是 skills 根的直接子项，**不支持**嵌套子文件夹。

> [!warning] 项目本地技能与信任
> 项目本地技能只从**受信任的 worktree** 加载。刚克隆或不受信任项目里的技能，在你授予信任前会被排除出目录与斜杠命令——防止恶意项目在你审阅前把指令注入 agent 的 system prompt。

- **覆盖行为**：全局与项目本地技能同名时，项目本地优先，便于项目定制/替换全局技能。
- **编辑保护**：即便在受信任项目里，agent 也**不能**未经你显式授权编辑 `SKILL.md` 或其打包资源，防止被攻陷的对话篡改治理未来对话的技能。

## Skills 的限制

- **仅扁平布局**：技能须是 skills 根的直接子项，`~/.agents/skills/group/my-skill/` 这类嵌套不被发现。
- **50KB 目录预算**：所有技能 name + description 总大小上限 50KB，超出的技能被丢弃并告警，故 description 要精简。
- **无远程注册表**：运行时不从远程发现/加载技能，不支持自定义搜索路径（可一次性从 GitHub URL 导入）。需要指向别处就用 symlink。
- **实时重载**：增删改 `SKILL.md` 立即生效，无需重启会话；但改 name 或 description 会使当前会话的模型 prompt 缓存失效。

> [!note] agent 路径边界
> Zed Skills 作用于 **Zed Agent**。External Agents 与 Terminal Threads 可能有自己的原生技能/提示/指令系统，需在对应 agent 或 CLI 里配置。

# Instructions

Instructions 是 Zed Agent 的**常驻上下文**，用于每次相关交互都应生效的持久指导。想要「按名调用的可复用任务指令」请改用 Skills。Zed 支持 [`AGENTS.md`](https://agents.md/) 作为个人与项目级 agent 指导的主指令文件。

## 个人 Instructions

对你用 Zed Agent 打开的每个项目生效。创建/编辑：

```text
~/.config/zed/AGENTS.md
```

Windows 下等价文件在 `%APPDATA%\Zed\AGENTS.md`。

## 项目 Instructions

对当前项目生效。Zed 使用下表中**第一个匹配**的文件：

- `.rules`
- `.cursorrules`
- `.windsurfrules`
- `.clinerules`
- `.github/copilot-instructions.md`
- `AGENT.md`
- `AGENTS.md`
- `CLAUDE.md`
- `GEMINI.md`

冲突时，项目 Instructions **覆盖**个人 `AGENTS.md`。

> [!tip] 兼容其它工具
> 这份列表意味着 Zed 能直接复用你为 Cursor、Windsurf、Cline、Copilot、Claude、Gemini 准备的指令文件。团队里已存在的 `CLAUDE.md` 或 `.github/copilot-instructions.md` 会被 Zed Agent 作为兼容项目指令加载。

## Instructions 文件支持矩阵

| 文件 | Zed Agent | External Agents | Terminal Threads |
|------|-----------|-----------------|------------------|
| `~/.config/zed/AGENTS.md` | 作为个人指令加载 | 一般不用 | 除非 CLI 自己读 |
| 项目 `AGENTS.md` | 作为项目指令加载 | 取决于 agent | 取决于 CLI |
| `CLAUDE.md` | 作为兼容项目指令加载 | Claude 原生读 | Claude Code CLI 原生读 |
| `.github/copilot-instructions.md` | 作为兼容项目指令加载 | 取决于 agent | 取决于 CLI |

External Agents 与 Terminal Threads 可能直接读自己的原生指令文件，别假设 Zed 的指令加载器控制它们。

## 从 Rules 迁移

Rules 已被 Skills 与 Instructions 取代：

- 可复用、按需的 Rules → **Skills**
- 默认、常驻的 Rules → 个人 **`AGENTS.md`**
- 项目 `.rules` 文件仍作为兼容项目指令文件被支持

> [!note] Rules Library 已移除
> Zed v1.4.0 之前用 Rules Library 配置（例如 Git 提交指令），现已移除，改用 `AGENTS.md` 与相应设置字段。
