# 概述

Zed 是「**AI 原生**」编辑器：AI 不是外挂插件，而是与编辑器深度集成的一等能力。它既能让 agent 读写、搜索、运行你项目里的代码，也能在你打字时预测下一处编辑。本章系统梳理 Zed 的 AI 体系。

> [!important] 专业名词保留英文
> 本章涉及大量官方术语，如 `agent`、`mcp`、`skills`、`instructions`、`edit prediction`、`inline assistant`、`llm provider`、`zeta`、`acp`，均保留英文原文，方便与命令面板、设置项、官方文档一一对应。

## 三类 AI 能力

Zed 的 AI 能力大致分三层，覆盖从「随手补全」到「自主改代码」的完整光谱：

| 能力 | 交互方式 | 典型场景 | 文档 |
|------|----------|----------|------|
| **Edit Prediction** | 自动、无需提示 | 打字时预测下一处编辑，`Tab` 接受 | [050](./050.InlineAssistant与EditPrediction.md) |
| **Inline Assistant** | 显式提示、选中改写 | 选中代码 `Ctrl+Enter` 让 AI 改写 | [050](./050.InlineAssistant与EditPrediction.md) |
| **Agent Panel / Zed Agent** | 对话式、可调用工具 | 让 agent 自主搜索、编辑、运行、跨文件重构 | [020](./020.AgentPanel与ZedAgent.md) |

## 三种 Agent 路径

Zed 区分三类「agent」，理解这点能避免很多配置困惑：

1. **Zed Agent（第一方）**：Zed 自带的 agent，使用 Zed 配置的模型、内置工具、Skills、Instructions、MCP servers。是本章重点。
2. **External Agents（外部）**：通过 **ACP（Agent Client Protocol）** 接入 Zed 的第三方 agent（如 Claude、Codex、Gemini CLI 等）。它们通常自带认证、模型、工具与 MCP 配置。
3. **Terminal Threads（终端线程）**：在 Agent Panel 里直接跑 CLI/TUI 形式的 agent，它们读自己的原生配置。

> [!note] 谁配置模型？
> 只有 **Zed Agent** 和 Zed 自有的 AI 功能（Inline Assistant、Edit Prediction、Git 提交信息生成、线程摘要）使用 Zed 配置的 [LLM Providers](./060.LLMProviders与本地模型.md)。External Agents 与 Terminal Threads **自带**模型访问、认证与配置，Zed 的 provider 设置管不到它们。

## 核心理念

- **键盘优先**：Agent Panel（`Ctrl+Shift+A` 或 `agent: new thread`）、Inline Assistant（`Ctrl+Enter`）、Edit Prediction（`Tab`）都有顺手键位。
- **你掌控上下文**：agent 能自动搜索代码库，但用 `@` 显式提供文件/符号/URL 上下文能显著提升质量、降低延迟。
- **可审阅、可回滚**：agent 每次编辑都有 **Restore Checkpoint**，改动通过 **Review Changes** 的 multibuffer 逐个 hunk 接受/拒绝。
- **权限可控**：工具调用默认 `confirm`（逐个批准），可通过 Agent Profiles 与 Tool Permissions 精细控制。
- **隐私默认友好**：Zed 默认不保留你的 prompt 与代码上下文，仅在显式反馈或选择加入训练时才收集。
