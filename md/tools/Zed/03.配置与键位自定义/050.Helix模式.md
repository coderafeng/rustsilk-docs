# 概述

Zed 的 **Helix 模式**是一套模拟 [Helix 编辑器](https://helix-editor.com/) 键位与模态编辑的层。它**构建在 Zed 的 Vim 模式之上**，因此大量核心能力是共享的——启用 `helix_mode` 会**同时启用** `vim_mode`。

> [!warning] 仍在完善中（Work in progress）
> Helix 模式尚未实现全部 Helix 键位。当前进度与缺失功能可在官方讨论 ["Are we Helix yet?"](https://github.com/zed-industries/zed/discussions/33580) 查看。

## Helix 与 Vim 的核心理念差异

- **Vim：action → motion**（先动作后范围），如 `d w` = 删除一个词。
- **Helix：selection-first（先选择后动作）**，先选中范围，再对其执行动作，选择结果始终可见，更直观。

由于建立在 Vim 模式上，Vim 模式里的 motion、text object、命令行、多光标等大多同样可用，参见 [040.Vim模式](./040.Vim模式.md)。

## 启用

```jsonc
{ "helix_mode": true }
```

或通过命令面板切换。启用后 `vim_mode` 自动生效。默认起始模式可用 `vim.default_mode` 设为 `"helix_normal"`。

## 核心差异要点

- 任何能用 `m i` / `m a` 的 text object 也能配合 `]` 和 `[` 使用，例如 `] (` 选中光标后的下一对括号。
- 部分 text object 键遵循 Helix 而非 Vim 的含义：
  - `m i m` / `m a m`：选中最近的任意种类包围对（括号、引号、反引号或竖线）
  - `t`：类型 / class text object
  - `c`：注释 text object
  - `x`：(X)HTML 元素 text object
- 与 Helix 一致，最近包围对（`m i m`、`m a m`、`m d m`、`m r m`）通过语言的语法树匹配，因此字符串字面量或注释里的分隔符不会被当成配对。没有语言信息的 buffer 中不匹配任何对。

## 上下文

Helix 模式在键位 context 中新增 `helix_mode`：当前模式为 Helix 模式（`helix_normal` 或 `helix_select`）时置位，包括操作符挂起、`vim_mode` 报告为 `operator` 或 `waiting` 期间。可据此编写仅在 Helix 模式生效的绑定。
