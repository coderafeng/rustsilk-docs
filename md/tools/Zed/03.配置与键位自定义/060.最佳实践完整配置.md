# 概述

本篇给出一套**可以直接复制投产**的 Zed 配置，覆盖 **Rust、Java、C/C++、Python、前端（TypeScript / JavaScript / Vue / HTML / CSS）** 六条开发线，格式风格对齐 **IntelliJ 全家桶**（IDEA / WebStorm / PyCharm / CLion / RustRover）的默认习惯。

先说清楚一个关键认知：**「按什么风格格式化」不由 Zed 单独决定，而是两层配置合力**：

1. **`settings.json`（编辑器层）**：决定缩进宽度、格式化接线（用哪个 formatter / language server）、键位方案、外观手感。
2. **语言工具链配置文件（项目层）**：`rustfmt.toml`、`.clang-format`、`.prettierrc`、`pyproject.toml` 等——formatter 真正读的是这些文件。它们随仓库提交，**同一套文件在 IntelliJ IDE、VS Code、CI 里也生效**，这才是团队统一风格的正道。

下面两层都给你完整版，复制后基本只需改 0-2 处路径。

## 风格基准（对齐 IntelliJ 全家桶）

| 语言 | 对应 IDE | Zed 中的 formatter | 缩进 | 行宽 | 风格文件 |
|------|----------|--------------------|------|------|----------|
| Rust | RustRover | rust-analyzer（内部调 `rustfmt`） | 4 空格 | 100 | `rustfmt.toml`（默认即 RustRover 风格，也是官方风格指南） |
| Java | IntelliJ IDEA | Eclipse JDTLS | 4 空格 | 120 | JDTLS 内置 profile（默认≈IDEA） |
| C / C++ | CLion | clangd（clang-format 规则） | 4 空格 | 100 | `.clang-format` |
| Python | PyCharm | Ruff（LSP 模式） | 4 空格 | 120 | `pyproject.toml` / `ruff.toml` |
| 前端 | WebStorm | Prettier + vtsls / Volar | 2 空格 | 120 | `.prettierrc` |

IntelliJ 系共性习惯在 Zed 里的落点：`base_keymap: "JetBrains"`（快捷键对齐）、`JetBrains Mono` 字体、保存时自动格式化 + 自动整理 import（对应 IDEA 的 Actions on Save）、当前行高亮、光标为竖线、无 minimap、双引号为主。

## 全局 settings.json（整份复制）

Windows 放 `~\AppData\Roaming\Zed\settings.json`，macOS / Linux 放 `~/.config/zed/settings.json`（用 `Ctrl+Alt+,` 直接打开）。**带 `⚠` 注释的行是唯一可能需要改的地方**。

```jsonc
{
  // ───────── 键位：对齐 IntelliJ 全家桶 ─────────
  "base_keymap": "JetBrains",   // 键位基底。可选值："JetBrains" | "VSCode" | "SublimeText" | "Atom" | "Emacs" | "Cursor" | "TextMate" | "None"；本值提供 Shift+F6 重命名、Ctrl+Alt+L 格式化等
  "vim_mode": false,            // 模态编辑总开关；想用 Vim/Helix 见下文「与 Vim 模式的搭配」
  "telemetry": {                // 遥测：崩溃诊断与使用指标上报，两者独立开关
    "diagnostics": false,       // 不上传 panic/崩溃信息（IDEA 首次启动也会问）
    "metrics": false            // 不上传功能使用统计
  },

  // ───────── 外观与字体（IDEA 默认观感） ─────────
  "theme": {                    // 也可直接填单个主题名字符串；对象形式按系统明暗自动切换（≈ IDEA 的 Theme Preferred Mode）
    "mode": "system",           // 可选值："system"（跟随系统）| "light" | "dark"
    "light": "One Light",       // 系统浅色时用这套
    "dark": "One Dark"          // 系统深色时用这套
  },
  "buffer_font_family": "JetBrains Mono", // 编辑区字体 ⚠ 需安装该字体，否则改回 "Zed Plex Mono"
  "buffer_font_size": 14,       // 编辑区字号（像素），IDEA 默认 13，Zed 渲染略小取 14 接近
  "ui_font_size": 14,           // 面板/菜单等项目 UI 字号（像素）
  "cursor_shape": "bar",        // 可选值："bar" | "block" | "underline" | "hollow"；本值竖线光标（Zed 默认 block，IDEA 系都是 bar）
  "current_line_highlight": "line", // 可选值："none" | "gutter" | "line" | "all"；本值高亮光标所在整行（IDEA 默认）
  "minimap": {                  // 小地图配置
    "show": "never"             // 可选值："auto"（滚动条可见时）| "always" | "never"；IntelliJ 系没有 minimap，关掉腾出右侧空间
  },

  // ───────── 编辑行为：IDEA 手感 ─────────
  "autosave": "on_focus_change", // 可选值："off" | "on_focus_change" | "on_window_change" | { "milliseconds": N }；本值≈ IDEA「永远帮你保存」
  "tab_size": 4,                 // 一级缩进宽度：后端语言默认 4 空格，前端在 languages 里覆盖为 2
  "hard_tabs": false,            // 用空格而非 Tab 字符缩进，跨工具 diff 不被污染
  "preferred_line_length": 120,  // 期望行宽：软换行/rewrap 的目标宽度（真正的折行上限由各语言 formatter 决定）
  "show_wrap_guides": true,      // 显示行宽标尺线（≈ IDEA 的 Visual guides）
  "wrap_guides": [100, 120],     // 标尺位置：100（rustfmt 行宽）与 120（IDEA 系右边界）
  "inlay_hints": {               // 内联提示（参数名/类型灰字，≈ IDEA 的 InlayHints）
    "enabled": true
  },
  "format_on_save": "on",        // 可选值："on" | "off" | { "external": { command, arguments } } | { "code_action": "..." }；本值≈ IDEA 的 Reformat on save

  // ───────── Git 与终端 ─────────
  "git": {
    "inline_blame": {            // 行尾灰字显示「谁在哪次提交改了这行」（≈ IDEA 的 Annotate/ blame）
      "enabled": true
    }
  },
  "terminal": {
    "font_family": "JetBrains Mono" // 集成终端用与编辑区同款字体，观感统一
  },

  // ───────── 语言级设置（覆盖全局同名项，注意不合并） ─────────
  // formatter 可选值："language_server" | { "language_server": { "name": "..." } } | { "external": { command, arguments } } | { "code_action": "..." }，也可写成数组串联多步
  "languages": {
    // Rust：formatter 交给 rust-analyzer（内部即 rustfmt），4 空格/100 列与 RustRover 默认一致
    "Rust": { "tab_size": 4, "formatter": "language_server", "format_on_save": "on" },

    // C：clangd 提供格式化，具体规则读项目里的 .clang-format
    "C": { "tab_size": 4, "formatter": "language_server", "format_on_save": "on" },
    // C++：同上，与 C 共用一套 .clang-format
    "C++": { "tab_size": 4, "formatter": "language_server", "format_on_save": "on" },

    // Java：Eclipse JDTLS 提供格式化，格式化策略见下方 lsp.jdtls 段
    "Java": { "tab_size": 4, "formatter": "language_server", "format_on_save": "on" },

    // Python：Ruff（LSP 模式）负责格式化，风格细节读 pyproject.toml 的 [tool.ruff]
    "Python": {
      "tab_size": 4,                                          // PyCharm 默认 4 空格
      "formatter": { "language_server": { "name": "ruff" } },  // 显式指定由 ruff server 格式化
      "code_actions_on_format": { "source.organizeImports.ruff": true }, // 格式化前先整理 import ≈ PyCharm 的 Optimize imports on save
      "format_on_save": "on"
    },

    // 前端语言组：WebStorm 习惯的 2 空格 + Prettier（风格细节读项目里的 .prettierrc）
    "JavaScript": { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // JS 基础语言
    "TypeScript": { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // TS（补全由 vtsls 提供，格式化归 Prettier）
    "TSX":        { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // React TSX
    "Vue":        { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // Vue 单文件组件（需装 Vue 扩展，Volar 管补全）
    "HTML":       { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // HTML 模板
    "CSS":        { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // CSS
    "SCSS":       { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // SCSS
    "JSON":       { "tab_size": 2, "prettier": { "allowed": true }, "format_on_save": "on" }, // JSON（package.json / tsconfig 等）

    // Markdown 例外：Prettier 会重排正文段落，文档类项目建议关掉保存时格式化
    "Markdown": { "format_on_save": "off" }
  },

  // ───────── LSP 微调（内容原样透传给对应 language server） ─────────
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {   // 启动时发送的初始化选项，键名与 VS Code 的 rust-analyzer.* 配置同名
        // 社区主流：保存时跑 cargo check（rust-analyzer 出厂默认，留空即不改）；Clippy 交给 CI/提交前跑
        // "check": { "command": "clippy" }, // RustRover 风味：保存即出 clippy 警告，大项目会变慢
      }
    },
    "jdtls": {
      "settings": {                 // Zed Java 扩展的入口：java_home 等扩展级选项放这层
        // ⚠ 若 JAVA_HOME / PATH 里没有 JDK 21+（JDTLS 自身运行需要），填一个 JDK 路径：
        // "java_home": "C:/Program Files/Java/jdk-21",
        "initialization_options": { // 再往下是 JDTLS 的 LSP initialize 参数，结构照搬 VS Code 的 java.* 配置
          "settings": {
            "java": {
              "format": { "enabled": true },                       // 开启 JDTLS 格式化能力（format_on_save 依赖它）
              "saveActions": { "organizeImports": true },          // 保存时自动优化 import ≈ IDEA 的 Optimize imports on the fly
              "completion": { "importOrder": ["java", "javax", "org", "com", ""] }, // import 排序规则（"" 表示其余包排最后）
              "configuration": { "updateBuildConfiguration": "interactive" } // 可选值："interactive"（变更前询问）| "automatic"（自动重导入）| "disabled"
            }
          }
        }
      }
    }
  }
}
```

> [!note] 这些键的出处
> `formatter` / `code_actions_on_format` / `prettier.allowed` / `lsp.*.settings` 均为官方写法，分别见 [Rust](https://zed.dev/docs/languages/rust)、[C++](https://zed.dev/docs/languages/cpp)、[Python](https://zed.dev/docs/languages/python)、[Java](https://zed.dev/docs/languages/java)、[TypeScript](https://zed.dev/docs/languages/typescript) 各文档页；本站对应机制讲解在 [020.语言支持配置](../07.扩展与语言支持/020.语言支持配置.md)。

## 项目层配套文件（决定格式规则本体）

以下文件放进**每个项目仓库根目录**并提交，团队共享。它们同样会被 IntelliJ IDE、CI 工具读取，保证「离开 Zed 风格也不变」。

### Rust：`rustfmt.toml`（可选）

rustfmt 的默认参数就是 RustRover 采用的格式化风格——而且两者同根：**rustfmt 由 Rust 官方团队维护（rust-lang/rustfmt），其默认配置就是官方 Rust 风格指南（Rust Style Team 制定）的落地**，所以「对齐 RustRover」与「社区主流」在格式化上是同一件事。**不放此文件也没问题**；显式钉住基线可防成员各自改配置漂移：

```toml
edition = "2021"  # 可选值："2015" | "2018" | "2021" | "2024"；按项目实际 edition 设，rustfmt 采用对应版本的官方规则
max_width = 100   # 单行宽度上限（rustfmt 官方默认值，也是 RustRover 默认）
tab_spaces = 4    # 一级缩进 4 空格
```

### C / C++：`.clang-format`（CLion 风格）

clangd 格式化读的就是这个文件。下面这份把 LLVM 基底改成 CLion 默认观感——4 空格缩进、**函数/类/命名空间左花括号换行**（`if`/`for` 等控制语句仍跟行）、指针星号贴类型：

```yaml
---
BasedOnStyle: LLVM              # 可选值：LLVM | Google | Chromium | Mozilla | WebKit | Microsoft | GNU | Stroustrup；本值以 LLVM 为基底再逐项覆盖成 CLion 观感
IndentWidth: 4                  # 一级缩进 4 空格（CLion 默认，LLVM 基底是 2）
ContinuationIndentWidth: 8       # 折行续行缩进 8 空格（≈ IDEA 的 continuation indent）
ColumnLimit: 100                # 行宽上限（数字，0 = 不限），超出才折行
PointerAlignment: Left          # 可选值：Left（int* p）| Right（int *p）| Middle（int * p）；CLion 习惯用 Left
DerivePointerAlignment: false   # 禁用「按历史代码自动猜星号位置」，保证全员统一
BreakBeforeBraces: Custom       # 可选值：Attach | Linux | BSD | Google | Chromium | Mozilla | WebKit | Allman | Custom；本值 Custom，细节见下方 BraceWrapping
BraceWrapping:
  AfterFunction: true           # 函数左花括号换行（CLion 默认风格）
  AfterClass: true              # class 左花括号换行
  AfterStruct: true             # struct 左花括号换行
  AfterUnion: true              # union 左花括号换行
  AfterNamespace: true          # namespace 左花括号换行
  AfterEnum: true               # enum 左花括号换行
  BeforeCatch: true             # } 与 catch 分行
  BeforeElse: true              # } 与 else 分行
  AfterControlStatement: Never  # 可选值：Ignore（跟随基底）| Never | Always；本值 if/for/while 左花括号仍跟行（K&R，CLion 习惯）
```

完整选项见 [Clang-Format Style Options](https://clang.llvm.org/docs/ClangFormatStyleOptions.html)。C 项目建议再加一行 `---\nLanguage: C\n` 分段，避免 C/C++ 共用一套规则时的边界差异。

### Python：`pyproject.toml`（Ruff 段）

对齐 PyCharm 默认（4 空格、双引号）并按 IDEA 习惯放宽行宽：

```toml
[tool.ruff]
line-length = 120                 # 行宽上限，对齐 IDEA 系右边界（Black 基底默认 88）

[tool.ruff.format]
quote-style = "double"            # 可选值："double" | "single" | "preserve"；PyCharm 默认也是双引号
indent-style = "space"            # 可选值："space" | "tab"；空格缩进，不用 Tab 字符

[tool.ruff.lint]
ignore = ["E501"]                 # 行长交给 formatter 统一处理，不让 linter 重复报 E501
```

独立 `ruff.toml` 同理（去掉 `tool.ruff` 前缀）。分析器（basedpyright / pyright）如需严格模式，另放 `pyrightconfig.json`。

### 前端：`.prettierrc`

WebStorm 系习惯 + IDEA 的 120 右边界；`endOfLine: "auto"` 是 Windows 下免踩 CRLF 坑的关键：

```jsonc
{
  "printWidth": 120,             // 单行宽度上限，取 IDEA 系右边界（Prettier 默认 80）
  "tabWidth": 2,                 // 一级缩进 2 空格（WebStorm 习惯）
  "semi": true,                  // 语句末尾保留分号（WebStorm 默认）
  "singleQuote": false,          // 字符串用双引号（两系默认一致）
  "quoteProps": "as-needed",     // 可选值："as-needed" | "consistent" | "preserve"；本值：对象键仅在必要时加引号
  "trailingComma": "es5",        // 可选值："none" | "es5" | "all"；本值：多行对象/数组尾逗号，diff 更干净
  "bracketSpacing": true,        // 对象字面量花括号内侧加空格：{ a: 1 }
  "arrowParens": "always",       // 可选值："always" | "avoid"；本值：单参数箭头函数也保留括号 (x) => x
  "endOfLine": "auto"            // 可选值："auto" | "lf" | "crlf" | "cr"；本值沿用文件自身换行符，Windows 下避免整文件 CRLF 翻转
}
```

ESLint 项目可让 Zed 在格式化前先跑自动修复，在 `settings.json` 的对应语言里追加：

```jsonc
"TypeScript": {
  "code_actions_on_format": { "source.fixAll.eslint": true }, // 格式化前先执行 ESLint 自动修复
  "prettier": { "allowed": true }                              // 修复完成后仍由 Prettier 定排版
}
```

### Java：默认即 IDEA 风格，需要像素级一致时挂 profile

JDTLS 内置格式化风格（4 空格、K&R 花括号）与 IDEA 默认高度接近，一般项目无需定制。要求严格一致时：在 IDEA 里 **Export Settings**（勾选 Code Style）得到 XML，转成 Eclipse formatter profile，再通过 `java.format.settings.url` 指给 JDTLS（路径相对项目根，写法参考 [JDTLS 配置说明](https://github.com/eclipse-jdtls/eclipse.jdt.ls/wiki)）：

```jsonc
"java": {
  "format": {
    "enabled": true,                                       // 开启格式化
    "settings": { "url": ".settings/formatter.xml" }        // 指向项目内的 Eclipse formatter profile
  }
}
```

### 通用兜底：`.editorconfig`

上面各文件管「格式规则」，`.editorconfig` 管「缩进与换行符」这类基础约定，Zed 与 IntelliJ 全家桶都原生读取，多编辑器团队协作时值得放一份：

```ini
root = true                  ; 停止向上继续查找其它 .editorconfig

[*]                          ; 所有文件的通用约定
charset = utf-8              ; 统一 UTF-8，防中文注释乱码
indent_style = space         ; 可选值：space | tab；本值空格缩进（= Zed 的 hard_tabs: false）
indent_size = 4              ; 后端语言默认 4 空格（与 settings.json 全局 tab_size 一致）
insert_final_newline = true  ; 文件末尾保留一个换行（IDEA 默认行为）
max_line_length = 120        ; 行宽上限提示（部分工具会据此报警/折行）

[{*.ts,*.tsx,*.js,*.jsx,*.vue,*.css,*.scss,*.html,*.json,*.yml,*.yaml}]
indent_size = 2              ; 前端文件族覆盖为 2 空格（与 languages 段一致）
```

## 与 Vim 模式的搭配

`base_keymap: "JetBrains"` 和 `vim_mode` 服务于两类人群，**二选一为主**：

- **IDEA 肌肉记忆派**：保持上面模板原样即可，`Ctrl+D` 复制行、`Shift+F6` 重命名、`Ctrl+Alt+L` 格式化等 JetBrains 键位直接可用。
- **Vim 派**：把 `vim_mode` 设为 `true`（`base_keymap` 可保留 JetBrains 管窗口/面板键，编辑键归 Vim）。本文的格式化接线（`format_on_save`、`formatter`、`prettier.allowed`）**与模态编辑完全正交**，不用改。Vim 模式细节见 [040.Vim模式](./040.Vim模式.md)。

> [!tip] 混合团队的推荐分层
> 键位、字体、minimap 这类**个人手感**放全局 `settings.json`；`languages` 里的 tab_size / formatter 接线和风格文件放项目 `.zed/settings.json` + 仓库配置文件。这样新人 clone 仓库打开 Zed 就是标准风格，不用问「我该配什么」。

## 投产验收清单

逐条验证一次，全过即配置生效：

| # | 操作 | 预期 |
|---|------|------|
| 1 | 新建 `hello.rs`，写一行超长 `fn main`，保存 | rustfmt 重排，4 空格缩进、100 列折行 |
| 2 | 打开 `.py`，文件顶部乱序 import，保存 | Ruff 整理 import 并按 4 空格/双引号格式化 |
| 3 | 打开 `.cpp`（项目里有 `.clang-format`），保存 | 函数左花括号换行、4 空格缩进 |
| 4 | 打开 `.ts` / `.vue`，保存 | Prettier 生效：2 空格、120 行宽、双引号 |
| 5 | 打开 `.java`，加一个未 import 的类引用后保存 | JDTLS 自动 organize imports |
| 6 | 按 `Shift+F6` | 弹出重命名（JetBrains 键位生效）；`Ctrl+Alt+L` 手动格式化 |
| 7 | 编辑 `.md` 保存 | 正文**不**被重排（Markdown 已排除） |

## 常见调整

| 需求 | 改法 |
|------|------|
| 没有 JetBrains Mono 字体 | 装 [JetBrains Mono](https://www.jetbrains.com/mono/)，或把两处 `buffer_font_family`/`terminal.font_family` 改成 `"Zed Plex Mono"` / `"Cascadia Code"` |
| 前端想单引号 | `.prettierrc` 里 `"singleQuote": true`（WebStorm 用户常这么调） |
| Python 想用 Black 而非 Ruff | `formatter` 改为 `{ "external": { "command": "black", "arguments": ["--stdin-filename", "{buffer_path}", "-"] } }`，保留 Ruff 整理 import |
| 大型 Rust 项目保存卡顿 | 默认配置（`cargo check` on save）已最轻；若开了注释里的 clippy 行可关掉它，再把 `checkOnSave` 设 `false`，改用 Tasks 跑 `cargo check` |
| 想要 RustRover 式「保存即出 Clippy」 | 取消 `lsp.rust-analyzer.initialization_options` 里 `"check": { "command": "clippy" }` 那行的注释即可（Clippy 本身是官方工具链组件，`rustup component add clippy`） |
| JDK 版本混乱（Java） | 显式设置 `lsp.jdtls.settings.java_home` 指向 JDK 21+（跑 JDTLS 用），项目本身 JDK 由 Maven/Gradle 决定 |
| 想保留 Zed 默认键位 | 删掉 `base_keymap` 一行即可 |
