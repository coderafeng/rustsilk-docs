# 概述

Zed 通过 **Debug Adapter Protocol（DAP）** 提供跨语言调试能力。DAP 是一套标准协议，规定了调试器、编辑器、IDE 之间如何通信。Zed 实现协议的**客户端**，各语言的 **debug adapter** 实现服务端——因此 Zed 无需为每种语言单独写调试逻辑，就能统一支持断点、单步、变量检查等功能。

## 支持的语言

调试某语言需要对应的 debug adapter。部分由 Zed 内置，部分由语言扩展提供：

| 语言 | 来源 |
|------|------|
| C / C++ | 内置 |
| Go | 内置 |
| JavaScript / TypeScript | 内置 |
| PHP | 内置 |
| Python | 内置 |
| Rust | 内置 |
| Java | 扩展提供 |
| Ruby | 扩展提供 |
| Swift | 扩展提供 |

> [!note] 语言未列出？
> 若你的语言不在表中，可通过编写 debugger 扩展来贡献 debug adapter。详见官方 debugger extensions 文档与 [07.扩展与语言支持](../07.扩展与语言支持/001.扩展概述.md)。

## 快速开始

多数语言最快的方式是执行 `debugger: start`（`F4`，macOS 同为 `F4`）。它会打开**新进程模态框（new process modal）**，列出当前项目预配置的调试任务。这些任务由测试、入口点（如 `main` 函数）等来源自动创建。也可点击调试面板右上角的「加号」按钮打开同一模态框。

对于不提供预配置任务的语言（如 C、C++ 及部分扩展语言），需在项目根的 `.zed/debug.json` 里定义配置。该文件是一个配置对象数组：

```jsonc
[
  {
    "adapter": "CodeLLDB",
    "label": "First configuration"
    // ...
  },
  {
    "adapter": "Debugpy",
    "label": "Second configuration"
    // ...
  }
]
```

配置好后它们会出现在新进程模态框列表里。

> [!tip] 兼容 VS Code
> 若 `.zed/debug.json` 里没有配置，Zed 会**加载 `.vscode/launch.json`** 并显示在新进程模态框中。从 VS Code 迁移时可直接复用。

### 全局调试配置

跨多个项目复用同一批 launch 配置时，可存到用户级配置。命令面板执行 `zed: open debug tasks` 打开全局 `debug.json`，它位于：

- **macOS**：`~/Library/Application Support/Zed/debug.json`
- **Linux / BSD**：`$XDG_CONFIG_HOME/zed/debug.json`（回退 `~/.config/zed/debug.json`）
- **Windows**：`%APPDATA%\Zed\debug.json`

其中定义的场景会合并进每个工作区，自动出现在 "New Debug Session" 对话框里。

## Launch（启动）与 Attach（附加）

Zed 调试器有两种方式：

- **Launch**：启动程序的新实例。因为 Zed 与 adapter 掌控整个程序生命周期，通常能更好地获取调试信息。跑单元测试或调试构建版本适合用 launch。
- **Attach**：附加到已运行的进程。适合无法重启程序的场景，例如 bug 只在生产环境复现。

## 配置字段

Zed 要求所有调试任务都有 `adapter` 和 `label` 两个字段。此外 `build` 字段用于在调试器启动前跑准备步骤，`tcp_connection` 字段用于连接已有进程。其余字段由各 debug adapter 定义，且都能包含[任务变量](./020.Tasks任务.md#变量variables)。多数 adapter 支持 `request`、`program`、`cwd`：

```jsonc
[
  {
    "label": "Example Start debugger config",  // 用于在面板与模态框里识别会话
    "adapter": "Example adapter name",         // Zed 使用的 debug adapter
    "request": "launch",                       // launch 启动 / attach 附加
    "program": "path_to_program",              // 要调试的程序，支持 ~ 和 . 路径解析
    "cwd": "$ZED_WORKTREE_ROOT"                // 默认项目工作目录
  }
]
```

`request: attach` 时若未指定 `process_id`，会显示进程选择器（目前仅 node 支持）。

### Build 任务

`build` 字段可内嵌一个 Zed 任务，在调试器启动前运行，用于准备环境或编译：

```jsonc
[
  {
    "label": "Build Binary",
    "adapter": "CodeLLDB",
    "program": "path_to_program",
    "request": "launch",
    "build": { "command": "make", "args": ["build", "-j8"] }
  }
]
```

也可通过未替换的 label 引用已有任务：`"build": "my build task"`（或 `"my build task for $ZED_FILE"`）。

### 自动场景创建

给定一个 Zed 任务，Zed 能自动为你创建调试场景（也支撑 gutter 里的场景创建）。目前支持 Rust、Go、Python、JavaScript、TypeScript。

## 断点（Breakpoints）

在编辑器 gutter（行号左侧区域）**点击**即可设断点。右键断点图标可调整：

- **Add a log**：日志断点，命中时输出日志消息而不暂停。
- **Conditional**：条件断点，仅当条件满足时暂停（条件语法因 adapter 而异）。
- **Hit count**：命中次数断点，命中指定次数后才暂停。
- **Disable**：禁用断点，保留在 gutter 显示但不生效。

部分 adapter（如 CodeLLDB、JavaScript）会**验证**断点是否可命中，不可命中的断点在 UI 里更醒目地提示。

调试会话 UI 的 "Breakpoints" 项列出项目所有已启用断点，并可在此管理**异常断点（exception breakpoints）**——当指定类型异常发生时暂停，支持的异常类型取决于 adapter。

## 分屏协作

多分屏调试时，Zed 在一个窗格显示当前调试行，其它窗格保留你的布局。若同一文件在多个窗格打开，调试器会选择该文件已是活动标签的窗格，不会切换非活动窗格的标签。一旦选定，本次会话后续断点继续用该窗格；若你拖动含调试行的标签到别的分屏，调试器会跟随。

## 设置

调试器设置集中在 `settings.json` 的 `debugger` 键下：

| 设置 | 说明 | 默认 |
|------|------|------|
| `dock` | 调试面板位置：`left` / `right` / `bottom` | `bottom` |
| `stepping_granularity` | 单步粒度：`statement` / `line` / `instruction` | `line` |
| `save_breakpoints` | 断点是否跨 Zed 会话保留 | `true` |
| `button` | 状态栏是否显示调试按钮 | `true` |
| `timeout` | 连接 TCP debug adapter 的超时（毫秒） | `2000` |
| `log_dap_communications` | 是否记录 adapter 与 Zed 间通信（DAP 开发用） | `false` |
| `format_dap_log_messages` | 是否格式化 DAP 日志消息 | `false` |

单步粒度三种取值：

- `statement`：运行到当前语句结束（语句含义由 adapter 决定，可能等同于一行；如 `for(int i=0;i<10;i++)` 可视为 3 个语句）。
- `line`：运行到当前源行执行完（默认）。
- `instruction`：执行一条机器指令（如一条 x86 指令）。

```jsonc
{
  "debugger": {
    "dock": "bottom",
    "stepping_granularity": "line",
    "save_breakpoints": true
  }
}
```

### 内联变量值（Inline Values）

调试时可在代码里用 inlay hint 显示变量值，由 `inlay_hints.show_value_hints` 控制（默认 `true`），也能从编辑器工具栏的 Editor Controls 菜单切换：

```jsonc
{ "inlay_hints": { "show_value_hints": false } }
```

### 自定义 Debug Adapter

用 `dap.$ADAPTER.binary` 和 `dap.$ADAPTER.args` 覆盖 Zed 启动某 adapter 的方式。`binary` 应指向 **debug adapter**（如 `lldb-dap`）而非调试器本身（如 `lldb`）：

```jsonc
{
  "dap": {
    "CodeLLDB": {
      "binary": "/Users/name/bin/lldb-dap",
      "args": ["--wait-for-debugger"]
    }
  }
}
```

## 主题

调试器支持以下主题项：

- `debugger.accent`：断点及相关符号的强调色。
- `editor.debugger_active_line.background`：当前调试行背景色。

## 故障排查

调试遇到问题时，可用这些动作收集信息（也便于提 GitHub issue）：

- `dev: copy debug adapter arguments`：复制描述 Zed 如何初始化会话的 JSON（会话启动失败时尤其有用）。
- `dev: open debug adapter logs`：查看最近调试会话中 Zed 与 adapter 的全部通信轨迹。

> [!warning] adapter 路径别指错
> `dap.$ADAPTER.binary` 要指向 debug adapter（如 `lldb-dap`），不是底层调试器（如 `lldb`）。指错会导致会话无法启动。
