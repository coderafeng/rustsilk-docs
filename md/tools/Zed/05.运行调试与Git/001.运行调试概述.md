# 概述

编辑器不只是写代码的地方，还要能**跑起来、调得动、管得住版本**。本章覆盖 Zed 的四大「运行时能力」：集成终端（Terminal）、任务系统（Tasks）、调试器（Debugger）、交互式执行（REPL），以及贯穿日常开发的 Git 集成。

## 设计理念

Zed 把这些能力都做成「**键盘优先、命令驱动**」：几乎每个功能都对应一个命令面板里的动作（action），并且大多没有默认快捷键——鼓励你按自己习惯在 `keymap.json` 里绑定。这与前两章讲的命令面板、键位体系一脉相承。

> [!note] 终端、Tasks、Debugger 的关系
> - **Terminal** 是底座：Tasks 和很多命令最终都在集成终端里执行并输出。
> - **Tasks** 是「可复用、可绑键、能读编辑器状态」的命令封装，适合 `build`、`test`、`run` 这类高频操作。
> - **Debugger** 走的是标准 DAP 协议，与各语言的 debug adapter 通信，提供断点、单步、变量检查。
> - **REPL** 则面向数据/脚本类交互式执行，基于 Jupyter kernel。

## 与 VS Code / IDEA 的对应关系

| 能力 | VS Code | IntelliJ IDEA | Zed |
|------|---------|---------------|-----|
| 集成终端 | 内置 Terminal | Terminal 工具窗 | Terminal Panel / Center Terminal |
| 任务 | `tasks.json` | Run Configurations | `tasks.json`（格式相近） |
| 调试 | `launch.json` | Run/Debug Configurations | `.zed/debug.json`（也读 `.vscode/launch.json`） |
| 交互式执行 | Jupyter 扩展 | Scratch / Jupyter | 内置 REPL |
| 版本控制 | Source Control 面板 | Git 工具窗 | Git Panel + Project Diff |

> [!tip] 迁移提示
> 如果你从 VS Code 过来，Zed 会**自动加载 `.vscode/tasks.json` 和 `.vscode/launch.json`**（在缺少 `.zed/` 对应文件时），大量已有配置可直接复用。详见 [040.从VSCode与IDEA迁移](../01.起步与安装/040.从VSCode与IDEA迁移.md)。
