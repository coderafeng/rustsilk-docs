# 概述

**Tasks（任务）** 是 Zed 对「在集成终端里跑命令」的可复用封装。与直接敲命令不同，任务能读取编辑器状态（当前文件路径、选中文本、符号名等），可绑定快捷键、可自动触发、可跨项目复用，非常适合 `build`、`test`、`run`、`lint` 这类高频操作。

## 两个核心动作

- `task: spawn`：打开任务模态框，列出当前上下文可用的所有任务，选择后执行。
- `task: rerun`：重跑最近一次执行的任务。

默认情况下，重跑会复用同一个终端（`use_new_terminal: false`），并等待上一个任务结束再启动（`allow_concurrent_runs: false`）。若希望重跑时**取消**上一个任务，保持 `use_new_terminal: false` 并设 `allow_concurrent_runs: true`。

## tasks.json 完整格式

```jsonc
[
  {
    "label": "Example task",              // 任务名，显示在模态框里
    "command": "for i in {1..5}; do echo \"Hello $i/5\"; sleep 1; done",
    //"args": [],                          // 命令参数（数组）
    "env": { "foo": "bar" },               // 追加到终端环境的变量覆盖
    //"cwd": "/path/to/working/directory", // 工作目录，默认项目根
    "use_new_terminal": false,             // 是否用新终端标签
    "allow_concurrent_runs": false,        // 是否允许同任务并发运行
    "reveal": "always",                    // always / no_focus / never：启动后如何显示面板
    "hide": "never",                       // never / always / on_success：结束后如何隐藏
    "shell": "system",                     // system / {program} / {with_arguments}
    "show_summary": true,                  // 输出里是否显示任务行
    "show_command": true,                  // 输出里是否显示命令行
    "save": "none",                        // all / current / none：运行前保存哪些 buffer
    "tags": []                             // 内联可运行指示器的标签
  }
]
```

`reveal` 与 `hide` 的组合能精细控制终端 UI 的打扰程度，例如后台跑测试用 `"reveal": "no_focus"` + `"hide": "on_success"`。

## 任务的四种定义位置

| 位置 | 作用范围 | 打开方式 |
|------|----------|----------|
| 全局 `~/.config/zed/tasks.json` | 所有项目 | 动作 `zed: open tasks` |
| 项目 `.zed/tasks.json` | 仅含该 worktree 的项目 | 动作 `zed: open project tasks` |
| Oneshot（临时） | 项目内、不跨会话持久化 | 在 `task: spawn` 模态框直接输入命令 |
| 语言扩展提供 | 由扩展注入（如 Rust 的 `cargo` 任务） | 自动出现在模态框 |

> [!note] Windows 下的全局路径
> 全局 `tasks.json` 在 Windows 位于 `%APPDATA%\Zed\tasks.json`。不必记路径，直接用命令面板 `zed: open tasks` 打开即可。

## 变量（Variables）

任务像 shell 一样支持 `$VAR_NAME` 语法。Zed 额外注入了一批反映编辑器状态的变量：

| 变量 | 含义 | 示例 |
|------|------|------|
| `ZED_FILE` | 当前文件绝对路径 | `/path/to/project/src/main.rs` |
| `ZED_FILENAME` | 当前文件名 | `main.rs` |
| `ZED_DIRNAME` | 当前文件所在目录（去文件名） | `/path/to/project/src` |
| `ZED_RELATIVE_FILE` | 相对 `ZED_WORKTREE_ROOT` 的文件路径 | `src/main.rs` |
| `ZED_RELATIVE_DIR` | 相对根的目录 | `src` |
| `ZED_STEM` | 文件名去扩展名 | `main` |
| `ZED_ROW` / `ZED_COLUMN` | 当前行 / 列 | — |
| `ZED_SYMBOL` | 当前选中符号（面包屑最后一个） | `mod tests > fn test_x` |
| `ZED_SELECTED_TEXT` | 当前选中文本 | — |
| `ZED_LANGUAGE` | 当前 buffer 语言 | `Rust` / `Python` |
| `ZED_WORKTREE_ROOT` | 当前 worktree 根绝对路径 | `/path/to/project` |
| `ZED_MAIN_GIT_WORKTREE` | 主 git worktree 的工作目录 | 普通检出等于 `ZED_WORKTREE_ROOT` |
| `ZED_CUSTOM_RUST_PACKAGE` | （Rust 专用）源文件所属父包名 | — |

用法示例：

```jsonc
{ "label": "echo current file's path", "command": "echo $ZED_FILE" }
```

也支持带默认值的详细语法：`${ZED_FILE:default_value}`。这些变量同样能用在 `cwd`、`args`、`label` 字段里。

### 变量引用与转义

路径含空格时务必正确转义。不要写 `stat $ZED_FILE`，而应：

```jsonc
{ "label": "stat current file", "command": "stat", "args": ["$ZED_FILE"] }
```

或显式加引号：`"command": "stat \"$ZED_FILE\""`。

### 基于变量的任务过滤

含「当前不存在的变量」的任务会被自动过滤掉。例如：

```jsonc
{ "label": "selected text", "command": "echo \"$ZED_SELECTED_TEXT\"" }
```

只有**存在文本选区**时才会出现在模态框里。想让它始终显示，给变量设默认值：`${ZED_SELECTED_TEXT:no text selected}`。

## Oneshot 任务

`task: spawn` 模态框支持直接跑任意 bash 式命令：在输入框敲命令，按 `opt-enter`（即 `Alt+Enter`）执行。这类临时命令在本次会话内被记住，`task: rerun` 也能重跑它们。

- 在模态框里按 `Tab` 可把选中任务的命令放进输入框编辑，改造成 oneshot。
- **Ephemeral（瞬时）任务**：spawn 时加 `cmd` 修饰键，这类任务不增加使用计数、不会被 `task: rerun` 重跑、也不会在模态框里排名靠前，适合「不想打断连续 rerun 流」的一次性命令。

## 重跑的上下文控制

默认任务只解析一次变量，之后 rerun 都用这份「已解析」的快照。设 `"reevaluate_context": true` 可让每次运行前重新解析：

```jsonc
{
  "context": "Workspace",
  "bindings": {
    "alt-t": ["task::Rerun", { "reevaluate_context": true }]
  }
}
```

## 为任务绑定快捷键

给 `task::Spawn` 传参数即可绑定指定任务：

```jsonc
{
  "context": "Workspace",
  "bindings": {
    "alt-g": ["task::Spawn", { "task_name": "echo current file's path" }]
  }
}
```

还能用 `reveal_target` 控制任务在哪里显示，例如把 TUI 程序开在中心区：

```jsonc
// tasks.json
{ "label": "start lazygit", "command": "lazygit -p $ZED_WORKTREE_ROOT" }
```

```jsonc
// keymap.json
{
  "context": "Workspace",
  "bindings": {
    "alt-g": ["task::Spawn", { "task_name": "start lazygit", "reveal_target": "center" }]
  }
}
```

## Hooks（自动触发）

在任务模板里加 `hooks` 字段，可让任务在特定 Zed 事件发生时自动运行。目前支持：

- `create_worktree`：Zed 创建新的 linked git worktree 后运行。此时 `ZED_WORKTREE_ROOT` 指向新 worktree，`ZED_MAIN_GIT_WORKTREE` 指向原仓库工作目录，非常适合复制 `.env` 等未跟踪文件或跑初始化命令。

```jsonc
[
  {
    "label": "copy .env into new worktree",
    "command": "cp",
    "args": ["$ZED_MAIN_GIT_WORKTREE/.env", "$ZED_WORKTREE_ROOT/.env"],
    "hooks": ["create_worktree"],
    "reveal": "no_focus",
    "hide": "on_success"
  }
]
```

带 `hooks` 的任务同时仍可手动从模态框运行。

## 自定义 Git 命令（Git Graph）

Git Graph 的提交右键菜单支持跑自定义 Git 命令任务。在**全局** `tasks.json` 里给任务加 `git-command` 标签（暂不支持 worktree 本地任务）。这类任务可用以下 Git 专用变量：

| 变量 | 含义 |
|------|------|
| `ZED_GIT_SHA` | 选中提交的完整 SHA |
| `ZED_GIT_SHA_SHORT` | 短 SHA |
| `ZED_GIT_REPOSITORY_NAME` | 选中仓库名 |
| `ZED_GIT_REPOSITORY_PATH` | 仓库工作目录绝对路径 |
| `ZED_GIT_REF` | 点击的 ref 名（分支/远程 ref/标签），仅从 ref 标签打开菜单时提供 |

```jsonc
[
  {
    "label": "Branches containing commit: $ZED_GIT_SHA_SHORT",
    "command": "git",
    "args": ["branch", "-a", "--contains", "$ZED_GIT_SHA"],
    "tags": ["git-command"]
  }
]
```

## VS Code 任务格式兼容

从 `.vscode/tasks.json` 导入时可省略 `label`，Zed 会按类型自动生成：npm 任务 → `npm: <script>`，gulp → `gulp: <task>`，shell → 直接用 `command` 字符串，无类型 → `Untitled Task`。显式写 `label` 可覆盖。

## 绑定 runnable 标签

代码里（如测试函数旁）的**内联可运行指示器**默认动作可被 `tasks.json` 覆盖，优先级：工作区 `tasks.json` > 全局 `tasks.json` > 语言提供的标签绑定。给任务加 `tags`（如 `"rust-test"`、`"bash-script"`）即可接管对应指示器。

绑定到 runnable 的任务还能通过 Code Actions 快速运行：`editor: toggle code actions`（`Ctrl+.`，macOS `Cmd+.`），任务会排在下拉第一项。

## 运行 Bash 脚本

打开 `.sh` / `.bash` 文件时，Zed 自动识别为可运行，出现在任务选择器里（标签 `bash-script`）。要传参或定制环境，在 `.zed/tasks.json` 里加配置即可。

## Shell 初始化

Zed 运行任务时会在**登录 shell（login shell）** 中启动命令，因此会先 source `.bash_profile`、`.zshrc` 等初始化文件，任务能拿到你 shell 里配置的环境变量、别名与 PATH。若任务找不到某个在终端里能用的命令，检查 shell 配置文件。可用 `terminal.shell` 设置覆盖任务使用的 shell。
