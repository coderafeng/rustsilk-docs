# 概述

本页面向想**开发并发布 Zed 扩展**的读者。Zed 扩展是包含 `extension.toml` 清单的 Git 仓库，可提供语言、主题、调试器、snippets 与 MCP servers。过程性代码用 Rust 编写并编译为 WebAssembly。

> [!note] 多数扩展无需 Rust
> 只有 **language server、context server（MCP）、debugger** 三类扩展需要自定义 Rust 代码。纯主题、图标主题、snippets 扩展只需声明式文件即可工作。

## 前置准备

开发扩展前，先[通过 rustup 安装 Rust](https://www.rust-lang.org/tools/install)。

- Zed 用 `wasm32-wasip2` Rust target 编译扩展。若 Rust 经 rustup 安装，Zed 会自动装该 target；若经 Homebrew / Nix 等安装，需自行让 `wasm32-wasip2` 可用（如加进 Nix rust-overlay 或 fenix toolchain 的 `targets`）。
- 提供 grammar 的扩展还需 [wasi-sdk](https://github.com/WebAssembly/wasi-sdk) 来编译 Tree-sitter parser。Zed 会自动下载，也可设 `WASI_SDK_PATH` 环境变量指向已有安装（含 `bin/clang` 的根目录）。

## 目录结构

一个提供全部能力的扩展示例结构：

```text
my-extension/
  extension.toml          # 必需：扩展清单
  Cargo.toml              # 有 Rust 代码时需要
  src/
    lib.rs                # Rust 扩展入口
  languages/
    my-language/
      config.toml         # 语言配置
      highlights.scm      # Tree-sitter 高亮查询
  themes/
    my-theme.json         # 主题
  snippets/
    snippets.json         # 全局 snippets
    rust.json             # Rust 专属 snippets
```

### extension.toml

清单必须包含扩展的基本信息：

```toml
id = "my-extension"
name = "My extension"
version = "0.0.1"
schema_version = 1
authors = ["Your Name <you@example.com>"]
description = "Example extension"
repository = "https://github.com/your-name/my-zed-extension"
```

## Rust 与 WebAssembly

包含自定义代码的扩展需要一个 `Cargo.toml`：

```toml
[package]
name = "my-extension"
version = "0.0.1"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
zed_extension_api = "0.1.0"
```

用 crates.io 上最新的 [`zed_extension_api`](https://crates.io/crates/zed_extension_api)，并确认它与你打算支持的 Zed 版本[兼容](https://github.com/zed-industries/zed/blob/main/crates/extension_api#compatible-zed-versions)。

在 `src/lib.rs` 里定义扩展结构体、实现 `Extension` trait、并用 `register_extension!` 宏注册：

```rust
use zed_extension_api as zed;

struct MyExtension {
    // ... state
}

impl zed::Extension for MyExtension {
    // ...
}

zed::register_extension!(MyExtension);
```

> [!warning] WASM 环境的差异
> 扩展被编译成 WebAssembly，某些 Rust 特性不按预期工作。例如 `cfg` 指令无效，`std::env::var` 也拿不到预期结果。请改用 [`zed_extension_api::current_platform`](https://docs.rs/zed_extension_api/latest/zed_extension_api/fn.current_platform.html) 获取当前环境信息，并熟悉 [`Worktree` 结构及其方法](https://docs.rs/zed_extension_api/latest/zed_extension_api/struct.Worktree.html) 来读取环境变量、在用户 `PATH` 里查找二进制。

## 本地开发与调试

开发时无需发布即可在 Zed 里使用——作为 **dev extension** 安装：

1. 在扩展页点 `Install Dev Extension` 按钮，或执行 `zed: install dev extension` 动作。
2. 选择包含扩展的目录。

若已安装该扩展的发布版，安装 dev extension 前会先卸载发布版；成功后扩展页标注上游扩展 "Overridden by dev extension"。

### 调试 Rust 扩展

扩展的 `stdout` / `stderr` 会直接转发给 Zed 进程。要看到扩展的 `println!` / `dbg!` 输出：

- 从终端以 `zed --foreground` 启动 Zed，输出更详细的 INFO 级日志。
- 命令面板执行 `zed: open log` 查看 Zed.log。

## 扩展能力分类

Zed 依据扩展提供的功能，自动把它归类到扩展页的分类里；提供多种功能的扩展可能出现在多个分类。可提供的能力：

| 能力 | 开发文档 |
|------|----------|
| Languages | Developing Language Extensions |
| Debuggers | Developing Debugger Extensions |
| Themes | Developing Themes |
| Icon Themes | Developing Icon Themes |
| Snippets | Developing Snippets |
| MCP Servers | Developing MCP Servers |

### 语言扩展要点

语言扩展通常提供 `languages/<name>/config.toml`（语言配置：文件扩展名、注释符、括号配对等）与 `highlights.scm`（Tree-sitter 高亮查询）。若要捆绑 language server，则需 Rust 代码在 `Extension` trait 里实现下载/启动逻辑。语言**配置**（非开发）见 [020.语言支持配置](./020.语言支持配置.md)。

### MCP server 扩展要点

把 MCP server 打包成扩展，让它能从 Extension Gallery 一键安装。MCP 的**使用**见 [030.MCP服务器](../06.AI与Agent/030.MCP服务器.md)。

### Debugger 扩展要点

为某语言提供 debug adapter（DAP 服务端）。这让 Zed 能调试内置列表之外的语言——第 05 章 [030.Debugger调试器](../05.运行调试与Git/030.Debugger调试器.md) 里 Java/Ruby/Swift 的调试正是由扩展提供。

## 发布扩展

考虑发布时，需满足 Zed 的**发布前置条件**（对扩展提供的功能有要求），并遵循发布流程：

1. **Publishing Prerequisites**：确认扩展满足功能与质量要求。
2. **License Requirements**：满足许可证要求。
3. **Publishing Guide**：按指南提交到 Zed 扩展仓库（通常是给 `zed-industries/extensions` 提 PR）。
4. **Updating an Extension**：发布后更新与维护。

> [!note] 发布是走 Git 仓库 PR
> Zed 扩展生态的去中心化程度较高：扩展本体是你自己的 Git 仓库，发布到官方画廊一般通过向 Zed 的扩展索引仓库提交 PR 完成。具体以官方 Publishing 文档为准。

## 相关 FAQ

- **支持哪些 Zed 版本？** 由 `zed_extension_api` 版本与 `schema_version` 决定，注意兼容性矩阵。
- **扩展能访问网络/文件系统吗？** 受 WASM 沙箱与 `Worktree` API 约束，不能像原生程序那样随意访问。
