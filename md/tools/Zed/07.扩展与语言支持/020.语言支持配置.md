# 概述

Zed 的语言支持建立在两项技术之上：

1. **Tree-sitter**：负责语法高亮，以及基于结构的特性（如大纲面板）。
2. **Language Server Protocol（LSP）**：提供语义特性——代码补全、诊断、跳转定义、重构。

理解这个分工很关键：高亮、折叠、大纲靠 Tree-sitter（静态解析语法树）；补全、报错、跳转、重命名靠 LSP（语言服务器实时分析）。本页覆盖语言专属设置、文件关联、language server 配置、格式化、lint 与语法高亮。

## 语言专属设置

Zed 允许为单个语言覆盖全局设置，定义在 `settings.json` 的 `languages` 键下：

```jsonc
"languages": {
  "Python": {
    "tab_size": 4,
    "formatter": "language_server",
    "format_on_save": "on"
  },
  "JavaScript": {
    "tab_size": 2,
    "formatter": {
      "external": {
        "command": "prettier",
        "arguments": ["--stdin-filepath", "{buffer_path}"]
      }
    }
  }
}
```

常用的每语言设置项：

| 设置 | 作用 |
|------|------|
| `tab_size` | 每级缩进的空格数 |
| `hard_tabs` | 用 Tab 而非空格缩进 |
| `formatter` | 代码格式化工具 |
| `format_on_save` | 保存时是否自动格式化 |
| `enable_language_server` | 开关 language server 支持 |
| `preferred_line_length` | 推荐的最大行宽 |
| `soft_wrap` | 长行如何换行 |
| `show_completions_on_input` | 打字时是否显示补全 |
| `show_completion_documentation` | 补全菜单是否显示文档 |
| `colorize_brackets` | 是否用 Tree-sitter 括号查询着色（彩虹括号） |

> [!note] 顶层设置是默认值，不合并
> 每个语言设置也能写在 `settings.json` 顶层（`languages` 映射之外），作为所有语言的默认值。但语言专属值会**完全替换**顶层值，两者**从不合并**。

## 文件关联

Zed 按扩展名自动识别文件类型，也可用 `file_types` 自定义：

```jsonc
"file_types": {
  "C++": ["c"],
  "TOML": ["MyLockFile"],
  "Dockerfile": ["Dockerfile*"]
}
```

上例含义：把 `.c` 当 C++ 而非 C；把名为 `MyLockFile` 的文件识别为 TOML；对任何以 `Dockerfile` 开头的文件套用 Dockerfile 语法。支持 glob 模式做更灵活的匹配。

## Language Server

language server 实现 LSP，标准化了编辑器与语言工具间的通信，让 Zed 无需为每种语言单独实现就能支持高级特性。它们提供：代码补全、错误检查与诊断、代码导航（跳转定义、查找引用）、代码动作（重命名、提取方法）、悬停信息、工作区符号搜索。

### 自动管理

Zed 简化了 language server 管理：

1. **自动下载**：打开匹配文件类型的文件时，Zed 自动下载对应 language server（对已知文件类型也可能提示安装扩展）。
2. **存储位置**：macOS 在 `~/Library/Application Support/Zed/languages`；Linux 在 `$XDG_DATA_HOME/zed/languages` 等。
3. **自动更新**：Zed 保持 language server 最新。

### 选择与排序 language server

有些语言提供多个 language server 选项（你可能装了多个捆绑同一语言 server 的扩展）。用 `language_servers` 设置指定优先级与开关：

```jsonc
"languages": {
  "PHP": {
    "language_servers": ["intelephense", "!phpactor", "!phptools", "!phpantom", "..."]
  }
}
```

规则：

- 直接列名（如 `intelephense`）→ 设为主 server，保持其位置。
- `!` 前缀（如 `!phpactor`）→ **完全排除**该 server。
- `"..."` → 通配符，展开为「其余已注册但未显式列出的」server，填在该位置。

> [!warning] 覆盖会替换默认列表
> 当你覆盖 `language_servers` 时，你的列表**完全替换**默认列表。这意味着默认禁用的 server（如 Ruby 的 `kanayago`）会被 `"..."` 重新启用，除非你再次显式 `"!kanayago"`。想完全掌控启用哪些 server，就**省略** `"..."`——只有你列名的 server 会被使用。

以 Ruby 默认配置为例（`solargraph` 为主，其余带 `!` 禁用，末尾 `"..."`）：

| 你的配置 | 结果 |
|----------|------|
| `["..."]` | 全部启用（含默认禁用的 `kanayago`） |
| `["ruby-lsp", "..."]` | `ruby-lsp` 优先，其余全启用 |
| `["ruby-lsp", "!solargraph", "!kanayago", "..."]` | `ruby-lsp` + 其余（排除 `solargraph`、`kanayago`） |
| `["ruby-lsp", "solargraph"]` | 仅这两个 |

某些 server 对某些语言**默认禁用**（如 TypeScript 的 `typescript-language-server`、Python 的 `ty`），扩展也可标记其 server 为 opt-in。这类 server 永远不被 `"..."` 包含，只有你显式列名才启动。

### Toolchains（工具链）

有些 language server 需要配置当前「toolchain」——某语言编译器/解释器特定版本的安装，可能含项目全套依赖。Python 的虚拟环境就是 Zed 视为 toolchain 的例子。并非所有语言都支持 toolchain 发现与选择；支持的语言可通过 toolchain picker（`toolchain: select`）指定。

> [!tip] Python 的 toolchain 与 REPL kernel 分开
> Zed 对 Python 的 **toolchain**（供 LSP/诊断用）与 **REPL kernel** 是分别选择的。若诊断与 REPL 表现不一致，用 `toolchain: select` 对齐。REPL 见 [040.REPL](../05.运行调试与Git/040.REPL.md)。

### 配置 language server

许多 language server 接受自定义配置，写在 `settings.json` 的 `lsp` 段：

```jsonc
"lsp": {
  "rust-analyzer": {
    "initialization_options": {
      "check": { "command": "clippy" }   // 保存时用 clippy 额外 lint
    }
  }
}
```

> [!important] 用嵌套对象，别用点号字符串
> 配置 LSP 选项时要用**嵌套对象**而非 VS Code 式的点号分隔字符串。例如 TypeScript：
> ```jsonc
> "lsp": {
>   "typescript-language-server": {
>     "initialization_options": {
>       // ✗ 不支持："preferences.strictNullChecks": true
>       "preferences": {           // ✓ 正确：嵌套
>         "strictNullChecks": true,
>         "target": "ES2020"
>       }
>     }
>   }
> }
> ```

两种主要配置途径：

- **initializationOptions**：language server 启动时发送一次，改动需重启 server 才生效（rust-analyzer、clangd 只用这种）。
- **Configuration Request（`settings`）**：server 可多次查询，多数 server 只用这种。

```jsonc
"lsp": {
  "tailwindcss-language-server": {
    "settings": { "tailwindCSS": { "emmetCompletions": true } }
  }
}
```

指定 language server 二进制的启动方式：

```jsonc
"lsp": {
  "rust-analyzer": {
    "binary": {
      "ignore_system_version": false,  // 从网络获取还是本地查找
      "path": "/path/to/langserver/bin",
      "arguments": ["--option", "value"],
      "env": { "FOO": "BAR" }
    }
  }
}
```

### 开关 language server

全局或按语言开关：

```jsonc
"languages": {
  "Markdown": { "enable_language_server": false }  // 大型文档项目提升性能
}
```

可配在全局 `~/.config/zed/settings.json` 或项目 `.zed/settings.json`。

## 格式化与 Lint

### 配置 formatter

Zed 支持内置与外部 formatter，可全局或按语言配置：

```jsonc
"languages": {
  "JavaScript": {
    "formatter": {
      "external": { "command": "prettier", "arguments": ["--stdin-filepath", "{buffer_path}"] }
    },
    "format_on_save": "on"
  },
  "Rust": {
    "formatter": "language_server",
    "format_on_save": "on"
  }
}
```

关闭某语言格式化：`"format_on_save": "off"`。`formatter` 也可设为 `"language_server"` 或外部命令，这正是第 04 章 [010.编辑代码与多光标](../04.代码编辑与导航/010.编辑代码与多光标.md) 里提到的 `format_on_save` 取值。

> [!tip] 拿来即用
> 覆盖 Rust / Java / C/C++ / Python / 前端的完整 formatter 接线模板（IntelliJ 风格），见 [060.最佳实践完整配置](../03.配置与键位自定义/060.最佳实践完整配置.md)。

### 配置 linter

Lint 通常由 language server 处理。许多 server 允许配置 lint 规则：

```jsonc
"lsp": {
  "eslint": {
    "settings": { "codeActionOnSave": { "rules": ["import/order"] } }  // 保存时整理 import
  }
}
```

保存时自动跑 linter 修复：

```jsonc
"languages": {
  "JavaScript": {
    "formatter": { "code_action": "source.fixAll.eslint" }
  }
}
```

### 格式化 + Lint 一起用

用数组把多个 formatter 串起来（先 ESLint 修复，再 Prettier 格式化）：

```jsonc
"languages": {
  "JavaScript": {
    "formatter": [
      { "code_action": "source.fixAll.eslint" },
      { "external": { "command": "prettier", "arguments": ["--stdin-filepath", "{buffer_path}"] } }
    ],
    "format_on_save": "on"
  }
}
```

### 格式化选区

`editor: format selections`（无默认键位）只格式化选中文本，行为取决于 formatter：language server 发 LSP range formatting 请求（最精确，需 server 支持）；Prettier 用内置 range formatting，落在选区外的编辑被丢弃；外部命令 formatter **不支持** range formatting 会被跳过；code action formatter 作用于整个 buffer，不单独启用该动作。

### 排错

格式化/lint 出问题时：① `zed: open log` 看错误；② 确认外部工具已装且在 PATH；③ 核对 Zed 设置与语言专属配置文件（`.eslintrc`、`.prettierrc`）。

## 语法高亮与主题

### 自定义语法高亮

Zed 用 Tree-sitter grammar 做高亮，可用 `theme_overrides` 覆盖默认高亮。下例让注释斜体、改字符串颜色：

```jsonc
"theme_overrides": {
  "One Dark": {
    "syntax": {
      "comment": { "font_style": "italic" },
      "string": { "color": "#00AA00" }
    }
  }
}
```

### 语义令牌（Semantic Tokens）

语义令牌用 language server 的类型与作用域信息提供更丰富的高亮：

```jsonc
"semantic_tokens": "combined"
```

- `"off"`：仅 Tree-sitter 高亮（默认）
- `"combined"`：LSP 语义令牌叠加在 Tree-sitter 上
- `"full"`：LSP 语义令牌完全取代 Tree-sitter

可通过 `global_lsp_settings.semantic_token_rules` 自定义令牌颜色与样式。主题选择与切换见 [020.主题与外观](../03.配置与键位自定义/020.主题与外观.md)。

## LSP 特性使用速查

| 特性 | 命令 | 快捷键 |
|------|------|--------|
| Inlay hints | 设置 `inlay_hints`（enabled / show_type_hints / show_parameter_hints / show_other_hints） | — |
| Code actions | `editor: toggle code actions` | `Ctrl+.`（macOS `Cmd+.`） |
| 跳转定义 | `editor: go to definition` | `F12` |
| 跳转类型定义 | `editor: go to type definition` | `Ctrl+F12`（macOS `Cmd+F12`） |
| 查找所有引用 | `editor: find all references` | `Shift+F12` |
| 重命名符号 | `editor: rename` | `F2` |
| 悬停信息 | `editor: hover` | — |
| 工作区符号搜索 | `project symbols: toggle` | — |
| 手动触发补全 | `editor: show completions` | `Tab` / `Enter` 接受 |
| 查看全部诊断 | `diagnostics: deploy` | `Ctrl+Shift+M` |

- **Inlay hints**：悬停看 tooltip，双击插入到代码（若 server 提供编辑，如 rust-analyzer 类型提示）；`editor: accept inlay hint` 插入选区内第一个可编辑 hint。
- **跨文件重命名**：重命名跨多文件的符号时，Zed 在 multibuffer 里打开预览，审阅全部改动后**保存该 multibuffer 即确认**；不想改就撤销或不保存关闭。这些特性都依赖各语言 server 的能力。

> 补全、诊断、查找导航、multibuffer 的**操作层面**已在 [04.代码编辑与导航](../04.代码编辑与导航/001.编辑与导航概述.md) 详述；本页侧重它们背后的**语言/LSP 配置**。
