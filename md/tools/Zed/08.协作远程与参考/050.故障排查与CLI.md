# 概述

本页两部分：遇到问题时如何**收集信息、看日志、排错**；以及 `zed` **命令行工具**的完整用法。第 01 章 [020.安装与更新](../01.起步与安装/020.安装与更新.md) 只讲了 CLI 的安装，这里给出全量参数。

# 故障排查

## 第一步：收集基本信息

很多异常（渲染、启动、语言支持）先确认版本与运行环境。打开命令面板（`Ctrl+Shift+P` / macOS `Cmd+Shift+P`）执行：

| 动作 | 作用 |
|------|------|
| `zed: about` | 查看 Zed 版本与渠道（stable / preview / nightly / dev） |
| `zed: copy system specs into clipboard` | 把系统信息复制到剪贴板（提 issue 必备） |
| `zed: copy installed extensions into clipboard` | 复制已安装扩展清单 |

## 第二步：看日志

- `zed: open log` —— 在 Zed 内打开日志（近 1000 行）。
- `zed: reveal log in file manager` —— 在文件管理器里定位日志文件。

日志文件位置：

| 平台 | 路径 |
|------|------|
| macOS | `~/Library/Logs/Zed/Zed.log` |
| Windows | `C:\Users\YOU\AppData\Local\Zed\logs\Zed.log` |
| Linux | `~/.local/share/zed/logs/Zed.log` |

> [!tip] 更详细的启动日志
> 从终端以 `zed --foreground` 启动 Zed，INFO 级日志会直接打到终端，便于观察扩展输出（`println!` / `dbg!` 会转发给 Zed 进程）。

## 常见问题模式

### 启动 / 工作区异常

Zed 用 SQLite 数据库存最近项目与工作区状态。若 Zed **启动即崩溃或工作区损坏**，可移走 db 文件测试（重启会重建）：

| 平台 | db 位置 |
|------|---------|
| macOS | `~/Library/Application Support/Zed/db` |
| Linux | `~/.local/share/zed/db` |
| Windows | `%LOCALAPPDATA%\Zed\db` |

文件名按渠道区分：`0-stable` / `0-preview` / `0-nightly` / `0-dev`。移走（而非删除）后重启，若恢复正常说明 db 损坏。

### language server 异常

补全/诊断失效时先执行 `editor: restart language server`；仍不行则看 `zed: open log` 里的 LSP 报错，或临时关掉该语言的 server 定位问题（`"enable_language_server": false`）。language server 配置详见 [020.语言支持配置](../07.扩展与语言支持/020.语言支持配置.md)。

### 扩展 / 格式化异常

扩展装不上、主题不生效：`zed: open log` 看下载报错；确认扩展与 Zed 版本兼容；必要时到扩展页卸载重装。格式化出问题的排查顺序见 [020.语言支持配置](../07.扩展与语言支持/020.语言支持配置.md) 的排错一节。

### Agent 报 "Max tokens reached"

对话超出模型上下文时的处理：新开会话线程、换更大上下文的模型、把大请求拆小、清理工具输出（工具调用历史会很快吃掉 token）。详见 [020.AgentPanel与ZedAgent](../06.AI与Agent/020.AgentPanel与ZedAgent.md)。

### 性能剖析（macOS）

怀疑卡顿时可用 Apple Instruments 的 **Time Profiler** 附加到 Zed 进程采样热点。

# zed CLI 完整参考

## 基本形态

```text
zed [OPTIONS] [PATHS]...
```

## 打开文件与目录

| 用法 | 效果 |
|------|------|
| `zed .` | 打开当前目录为项目 |
| `zed file.rs` | 打开单文件 |
| `zed a.rs b.rs c.rs` | 一次打开多个文件 |
| `zed file.rs:42:10` | 打开并定位到第 42 行第 10 列 |
| `zed - file.rs < input.txt` | 用 `-` 从 stdin 读内容（打开为未命名 buffer） |

也接受 URL：`zed://`（含 `zed://ssh/host/path` 远程链接）、`file://`、`ssh://`。

## 常用选项

| 选项 | 作用 |
|------|------|
| `-w`, `--wait` | 阻塞直到文件在 Zed 中关闭——配合 `git commit` / `EDITOR="zed --wait"` 当外部编辑器 |
| `-n`, `--new` | 强制新实例打开 |
| `-a`, `--add` | 把路径加入已运行实例 |
| `-r`, `--reuse` | 复用最近窗口打开 |
| `-e`, `--existing` | 复用已运行实例（不新建窗口） |
| `--diff OLD NEW` | 以 diff 视图打开两个文件 |
| `--foreground` | 前台运行并输出详细日志 |
| `--user-data-dir DIR` | 指定独立用户数据目录（做干净环境测试） |
| `-v`, `--version` | 打印版本 |
| `--completions SHELL` | 生成 bash/zsh/fish 等 shell 补全脚本 |
| `--uninstall` | 卸载 Zed |
| `--zed PATH` | 指定要调用的 zed 可执行文件（多版本共存时用） |

> [!note] 默认打开行为可配置
> `cli_default_open_behavior` 设置决定不带参数时 CLI 的复用/新建策略。

## 渠道参数（macOS）

macOS 上装了多个渠道时可用 `--stable` / `--preview` / `--nightly` 选择由哪个渠道打开。

## 作为外部编辑器

```bash
export EDITOR="zed --wait"
export GIT_EDITOR="zed --wait"
```

git rebase / commit message / crontab 等都会调用 `$EDITOR`；`--wait` 让命令等你关闭文件后再继续。

## 退出码

- `0`：成功。
- `1`：失败（路径不存在、连不上实例等）。

> [!warning] 远程会话里不能用
> [远程开发](./020.远程开发SSH.md)时，`zed` CLI 只在你**本地**机器上有效；远程 Terminal 里没有 `zed` 命令可用。
