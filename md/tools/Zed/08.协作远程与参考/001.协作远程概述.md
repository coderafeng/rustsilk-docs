# 概述

第 08 章覆盖 Zed 的**协作、远程开发能力**与**排错参考**。前面几章解决"一个人在本地怎么用 Zed"，本章解决两类更进阶的场景：

1. **多人/多机**：与他人实时结对编程，或让本地 UI 连接远程服务器/容器里的代码。
2. **兜底参考**：出问题时怎么排错，如何用命令行 `zed` 驱动编辑器，以及 Zed 底层 UI 框架 gpui 的架构。

> [!note] 为什么 Zed 没有"翻译成本地语言"的选项
> 正如本笔记开篇背景所述，Zed 官方**暂无本地化 / 国际化（i18n）计划**，界面长期为英文，且默认键位偏 Vim 风格（复制不是 `Ctrl+C`）。因此本章涉及的 Collaboration Panel、Remote Projects、Channels 等面板**同样全为英文**，笔记里会保留其英文原名并附中文解释。

## 能力全景

```text
                 ┌─────────────────────────┐
   实时协作 ───▶ │  本地 Zed（UI / 渲染）    │ ◀─── Channels / Contacts
                 │  gpui · Tree-sitter      │
                 └───────────┬─────────────┘
                             │ SSH / Dev Container
                 ┌───────────▼─────────────┐
   远程开发 ───▶ │  远程 server            │
                 │  language server · tasks │
                 │  terminal · 源码         │
                 └─────────────────────────┘
```

- **实时协作（Collaboration / Channels）**：多个 Zed 实例通过 Zed 的服务连接，可同时编辑同一份代码、语音通话、共享屏幕。需要登录。
- **远程开发（Remote Development）**：UI 跑在你本地机器（保持响应），language server、tasks、terminal、源码都在远程服务器。二者通过 SSH 通信。
- **Dev Containers**：远程开发的特例——"远程"是本机的 Docker/Podman 容器，用 `.devcontainer/devcontainer.json` 描述环境。

> [!tip] 三者关系
> Collaboration 解决"和谁一起写"，Remote Development / Dev Containers 解决"代码跑在哪台机器/容器上"。它们可以叠加：你可以在远程项目里再邀请他人协作。
