# 概述

Dev Containers 通过在容器配置里定义项目的依赖、工具与设置，提供**一致、可复现**的开发环境。若你的仓库包含 `.devcontainer/devcontainer.json`，Zed 就能把项目在开发容器内打开。

可以把 Dev Containers 理解为[远程开发](./020.远程开发SSH.md)的特例："远程"其实是本机上的一个 Docker/Podman 容器，UI 仍在本地，tasks / terminal / language server 都跑在容器里。

## 前置要求

- **Docker 或 Podman** 已安装且在 `PATH` 里。用 Podman 时须在 settings.json 里把 `use_podman` 设为 `true`。
- 项目里存在 `.devcontainer/devcontainer.json`。

> [!note] BuildKit
> 默认情况下，当 `docker buildx` 插件可用时，Zed 用 **BuildKit** 构建 dev container 镜像。若你的 Docker 兼容引擎没有集成 BuildKit（例如通过 Docker-API 桥接的 Apple Container），在 settings.json 里设 `"dev_container_use_buildkit": false` 改用经典 Docker builder。

## 在 Zed 里使用

### 自动提示

打开含 `.devcontainer/devcontainer.json` 的项目时，Zed 会弹窗询问是否在 dev container 内打开。选 **Open in Container** 会：

1. 构建 dev container 镜像（如需要）。
2. 启动容器。
3. 以连接容器环境的方式重新打开项目。

### 手动打开

若关掉了提示、或想之后重新在容器里打开：

- 命令面板执行 **Project: Open Remote**，选择在 dev container 里打开；或
- 用 Remote Projects 模态框（`Ctrl+Alt+Shift+O` / macOS `Ctrl+Cmd+Shift+O`）选 **Connect Dev Container**。

## 修改容器配置

> [!warning] 改配置不会自动重建
> 修改 `.devcontainer/devcontainer.json` 后，Zed **当前不会**自动重建或重载容器。改完需：
> 1. 手动停止/杀掉现有容器（如 `docker kill <container>`）。
> 2. 重新在容器里打开项目。

## 在容器里工作

连接后，Zed 的 tasks、terminal、language server 都在容器环境里运行。文件按 dev container 规范从你的工作区链接进容器。

## 注入扩展

在 `.devcontainer/devcontainer.json` 的 `customizations` 字段里指定 Zed 扩展：

```json
{
  "customizations": {
    "zed": {
      "extensions": ["vue", "ruby"]
    },
    "vscode": { },
    "codespaces": { }
  }
}
```

> [!note] 扩展作用于整个会话
> 扩展是为 Zed 会话加载的，因此这些扩展也会存在于你本地的 Zed 实例上。

## 已知限制

> [!important] 该特性仍在开发中
> - **配置变更**：更新 `devcontainer.json` 不触发自动重建/重载，容器必须手动重启。

## Dev Container vs SSH 远程开发

| 维度 | Dev Container | SSH 远程开发 |
|------|---------------|--------------|
| 代码/环境位置 | 本机容器 | 远程服务器 |
| 环境定义 | `.devcontainer/devcontainer.json` | 服务器现状 + `ssh_connections` |
| 连接方式 | Docker/Podman | SSH |
| 适用场景 | 统一团队环境、隔离依赖 | 编辑远程机器上的既有代码 |

两者共享同一套"本地 UI + 远程执行"的模型，settings 分工与 [020.远程开发SSH](./020.远程开发SSH.md#三处设置的分工) 一致。
