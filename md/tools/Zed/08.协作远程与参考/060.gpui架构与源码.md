# 概述

Zed 快的口碑一半来自它的底层 UI 框架 **gpui**——一个 Rust 编写的**混合即时/保持模式、GPU 加速**的 UI 框架。本页不教你用 gpui 开发应用，而是从"读者/排错"视角解释：为什么 Zed 是这个交互形态、界面卡顿与渲染有什么关系、以及想读源码时的仓库地图。

> [!note] 为什么使用教程要讲架构
> Zed 无 i18n、键位偏 Vim，很多"和别的编辑器不一样"的体验（全屏 GPU 渲染、无插件主线程阻塞、多窗口即 workspace）都根植于 gpui 的设计。理解一层架构，能帮你解释排错时看到的很多现象（比如渲染问题往往与 Metal/DirectX/OpenGL 后端有关）。

## gpui 三层抽象

gpui 官方 README 把框架能力分成三个"档位（registers）"：

| 档位 | 核心概念 | 说明 |
|------|----------|------|
| 状态管理 | **Entity** | 应用状态放在 Entity 里，由 gpui 拥有，通过类似 `Rc` 的智能指针访问；跨模块通信靠 context（`App`/`Context`） |
| 高层声明式 UI | **View** | 实现了 `Render` trait 的 Entity 即可渲染；每帧从根 view 调用 render，构建一棵 **element 树**，用 tailwind 风格 API 布局与样式 |
| 低层命令式 UI | **Element** | UI 的最小积木，完全控制自身与子元素的渲染方式——编辑器视口、虚拟滚动长列表都是自定义 element |

```text
Application（gpui_platform::application()）
 └── Window
      └── 根 View（Entity + Render trait）
           └── render() 每帧构建 Element 树
                └── 布局（tailwind 风格）→ GPU 光栅化
```

此外 gpui 还提供：**Actions**（把按键转成逻辑操作，正是第 03/08 章 keymap 里绑定的那些动作名）、**异步 executor**（与平台事件循环集成）、**平台服务**（打开 URL、退出应用等）。

## 平台后端

gpui 的渲染与文本走各平台原生高性能 API：

| 平台 | 渲染 | 窗口/文本 |
|------|------|-----------|
| macOS | Metal | Cocoa；字形光栅化可用 font-kit |
| Linux / FreeBSD | OpenGL 路径 | Wayland 和/或 X11 |
| Windows | DirectX 路径 | Win32 + DirectWrite |

> [!tip] 排错关联
> 界面花屏/字体异常时，`zed: copy system specs into clipboard` 里的 GPU 信息就是排查起点；Windows 上远程桌面环境禁用硬件加速导致的黑屏也是这类后端问题。

## 为什么 Zed "快"

- **GPU 合成整屏**：UI、文本、代码全部走同一渲染管线，没有 DOM/WebView 分层。
- **Rust + 无插件主线程**：扩展编译为 WebAssembly 在沙箱跑，慢扩展拖不垮编辑器主循环。
- **Tree-sitter 增量解析**：按键级增量高亮，大文件滚动不掉帧。
- **异步优先**：language server、AI 请求都在 gpui 的 executor 上并发，UI 永不等待网络。

## 源码仓库地图

仓库：<https://github.com/zed-industries/zed>（Rust 为主，单仓多 crate）。想读源码建议按下表顺序：

| crate / 目录 | 内容 | 对应本笔记章节 |
|--------------|------|----------------|
| `crates/gpui` | UI 框架本体（App/Entity/View/Element、action、keymap 解析） | 03 章、08 章本页 |
| `crates/assets` 与主题 JSON | 内置主题、图标 | 03 章主题 |
| `crates/editor` | 编辑器核心（buffer 视图、多光标、inline assistant 渲染） | 04 章 |
| `crates/project` + `crates/languages` | 项目模型、LSP/Tree-sitter 集成 | 07 章 |
| `crates/terminal` + `crates/task` | 集成终端与 tasks | 05 章 |
| `crates/debugger` | DAP 客户端 | 05 章调试器 |
| `crates/agent` + `crates/acp`（相关） | Agent Panel、MCP、ACP | 06 章 |
| `crates/collab` | 协作服务端（Channels、实时同步 CRDT） | 08 章协作 |
| `crates/remote_server` | 远程开发 headless server | 08 章远程 |
| `crates/extensions` + extension API | 扩展加载、WASM 运行时 | 07 章扩展开发 |
| `docs/` | 官方文档源（即 zed.dev/docs 的内容） | 全部 |

> [!note] 编辑器数据模型小知识
> buffer 的并发编辑用 **CRDT**（冲突自由 replicated data types）建模——这是协作功能（多人同时敲同一文件不丢字）与"撤销历史跟随每个人"的底层原因。源码在 `crates/language` 的 `operation.rs` 一带。

## 用 gpui 写自己的应用

gpui 已发布到 crates.io（pre-1.0，版本间常有 breaking change）。最小骨架：

```rust
use gpui::*;

fn main() {
    gpui_platform::application().run(|cx: &mut App| {
        // 在这里 open_window 并注册根 view
    });
}
```

官方态度是目前"最好的学习方式就是读 Zed 源码或在 Zed Discord 提问"，文档仍在建设中。做桌面小工具可行，生产应用需接受 pre-1.0 的变动成本。
