# 概述

Remote Development（远程开发）让你**编辑远程服务器上的代码，同时在本地运行 Zed UI**。UI 保持流畅，因为它跑在你的机器上；而 language server、tasks、terminal 都跑在远程服务器。

> [!note] 版本要求
> 远程开发需要 **Zed v0.159 或更高版本**。早期版本曾通过 Zed 服务器中转流量，自 v0.157 起该模式已移除，现在必须走 SSH 直连。

## 架构

```text
本地机器（Zed UI）              远程服务器（Zed headless server）
┌──────────────────┐  SSH   ┌────────────────────────┐
│ · UI / 渲染(gpui) │◀──────▶│ · 源码                  │
│ · 调用 LLM        │        │ · language server       │
│ · Tree-sitter 高亮 │        │ · tasks / terminal      │
│ · 未保存改动/最近项 │        │ · ~/.zed_server         │
└──────────────────┘        └────────────────────────┘
```

本地负责：UI、与大模型通信、用 Tree-sitter 解析高亮、存未保存改动与最近项目。远程负责：源码、language server、tasks、terminal。AI 功能（Agent Panel、Inline Assistant）在远程会话里照常可用。

## 连接步骤

1. 安装 [Zed](https://zed.dev/releases)（≥ v0.159）。
2. 按 `Ctrl+Alt+Shift+O`（macOS `Ctrl+Cmd+Shift+O`）打开 **Remote Projects** 对话框。
3. 点 **Connect New Server**，输入你平时 SSH 登录该服务器的命令。
4. 本地 Zed 用 PATH 上的 `ssh` 二进制连接远程；成功后 Zed 会在远程下载并启动 server。
5. server 起来后，选择要在远程打开的路径。

> [!warning] 不要打开超大目录
> Zed 目前对打开超大目录（如 `/` 或 `~`，可能 >10 万文件）处理不佳。建议只打开具体项目或大 mono-repo 的子目录。

### 命令行直连

简单场景（无需额外 SSH 参数）可直接：

```bash
zed ssh://[<user>@]<host>[:<port>]/<path>
```

也接受 scp 风格：`zed ssh://[<user>@]<host>:~/project` 或 `zed ssh://[<user>@]<host>:/absolute/path`。想做成可点击的链接：`zed://ssh/[<user>@]<host>[:<port>]/<path>`。

## 支持的平台

远程机器需能运行 Zed server：

- macOS Catalina 或更新（Intel / Apple Silicon）
- Linux（x86_64 或 arm64，暂不支持 32 位）
- Windows（x86_64 或 arm64）

## 配置

远程服务器列表存在 settings.json（`Ctrl+,` / macOS `Cmd+,`）。推荐用 Remote Projects 对话框编辑（它会先验证连接能否建立再写入）：

```json
{
  "ssh_connections": [
    {
      "host": "192.168.1.10",
      "projects": [{ "paths": ["~/code/zed/zed"] }]
    }
  ]
}
```

Zed 会 shell out 到 PATH 上的 `ssh`，因此会**继承 `~/.ssh/config`** 里对该 host 的配置。需要覆盖时可加：

```json
{
  "ssh_connections": [
    {
      "host": "192.168.1.10",
      "projects": [{ "paths": ["~/code/zed/zed"] }],
      "args": ["-i", "~/.ssh/work_id_file"],  // 传给 ssh master 进程的参数
      "port": 22,                              // 默认 22
      "username": "me"                         // 默认取本地用户名
    }
  ]
}
```

两个 Zed 专属选项：

```json
{
  "ssh_connections": [
    {
      "host": "192.168.1.10",
      "upload_binary_over_ssh": true,  // 远程无外网时：先下载到本地再经 SSH 上传
      "nickname": "lil-linux"          // UI 里区分多台主机
    }
  ]
}
```

> [!important] 密码不写入 settings.json
> 命令行可临时传密码 `zed ssh://user:password@host/~`，但 settings 文件**不支持**存密码。反复连同一台主机应配置**基于密钥**的认证。

## Windows 与 WSL

- **Windows SSH 远程**：支持，会按需弹出凭据对话框（askpass）。认证失败时确认 ssh-agent 在运行、`ssh.exe` 在 PATH。
- **WSL**：原生支持在 WSL 内打开文件夹。
  - `projects: open folder in wsl`：把本地文件夹在某个 WSL 发行版里打开（会列出发行版供选）。
  - `projects: open wsl`：打开已在 WSL 里的文件夹，发行版会加入 Remote Projects 窗口。

## 端口转发

想在本地访问远程端口（如本地浏览器打开远程 web 服务），配置 `port_forwards`（底层用 ssh 的 `-L`）：

```json
{
  "ssh_connections": [
    {
      "host": "192.168.1.10",
      "port_forwards": [{ "local_port": 8080, "remote_port": 80 }]
    }
  ]
}
```

本地 `localhost:8080` 的请求会被转发到远程的 80 端口。默认绑定 localhost，同网其他机器访问不到；要放开可设 `local_host: "0.0.0.0"`。远程侧默认也绑 localhost，需要时设 `remote_host`。

## 三处设置的分工

远程项目涉及三处 settings：

| 位置 | 用途 |
|------|------|
| 本地 Zed settings | 影响 **UI**：字号等（macOS `~/.zed/settings.json`；Linux `~/.config/zed/settings.json`） |
| 远程 server settings | 影响 **server**：language server 路径、代理等（远程机同路径） |
| 项目 settings | 影响**项目**：缩进、用哪个 formatter / language server（`.zed/settings.json` 或 `.editorconfig`） |

本地与远程 Zed 都读项目 settings，但**互不知晓对方的主 settings 文件**。本地安装的扩展会**传播到远程 server**，因此 language server 等能正常工作。

## 代理配置

远程 server **不使用**你本地的代理配置（网络策略可能不同）。若远程需要代理上网，须在**远程机器本身**配置。多数情况下远程已配好代理环境变量，Zed 下载 language server、连 LLM 时会自动用。也可在远程 shell 配置（如 `~/.bashrc`）里设：

```bash
export http_proxy="http://proxy.example.com:8080"
export https_proxy="http://proxy.example.com:8080"
export no_proxy="localhost,127.0.0.1"
```

或在远程机的 `~/.config/zed/settings.json`（Linux）/ `~/.zed/settings.json`（macOS）里设 `"proxy": "http://proxy.example.com:8080"`。

## 初始化远程 server

提供 SSH 选项后，Zed 会 shell out 到本地 `ssh` 建立 **ControlMaster** 连接；SSH 需要的交互（验证 host key、输密钥密码）都会显示在 UI 里。连接建立后，Zed 检查远程 `~/.zed_server` 里是否有版本匹配的 server 二进制，没有或不匹配就下载（默认从 `https://zed.dev`；设 `upload_binary_over_ssh:true` 则经本地上传）。

想自己维护 server 二进制，可从 [GitHub Releases](https://github.com/zed-industries/zed/releases) 下预构建版，或自行构建：

```bash
cargo build --release --package remote_server
llvm-objcopy --strip-debug target/release/remote_server
```

## 支持的 SSH 选项

Zed 透传常用 SSH 选项：`-p`（端口）、`-l`（用户）、`-L`/`-R`（转发）、`-i`（密钥）、`-o`（选项）、`-J`（跳板）、`-w`（隧道）、`-F`（配置文件）等。**禁用** `-t`/`-T`（强制分配/不分配 tty），因为 Zed 需要自己的 pty 控制。

> [!warning] 限制
> 不能从**远程 Terminal** 里用 `zed` 命令去打开文件——`zed` CLI 属于本地机器。
