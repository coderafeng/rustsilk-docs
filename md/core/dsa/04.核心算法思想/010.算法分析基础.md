# 概述

算法分析用**渐近记号**描述运行时间/空间随输入规模增长的趋势，抛开机器与实现常数；用**递归式**刻画分治类算法的代价，再用**主定理**这类工具把递归式解成闭式复杂度。这是全书所有「时间复杂度：O(…)」声明背后的公共语言。

**本篇收录**：渐近记号、递归式、主定理

- 所属章节：[000.核心算法思想概述](./000.核心算法思想概述.md)

- 常见增长阶排序（n→∞ 时）：`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)`。
- 应用场景：一切复杂度声明的基础语言——[02.基础算法](../02.基础算法/000.基础算法概述.md) 各排序的 O(n log n)/O(n²) 对比、[030.堆与优先队列](../03.树结构/030.堆与优先队列.md) 建堆 O(n) 的级数推导、[060.动态规划基础](./060.动态规划基础.md) 的「状态数 × 转移代价」分析，都建立在本篇记号与递归式之上；面试与论文中的「这个算法快在哪」最终都化为对增长阶的比较。

2. n ≈ 10⁴：O(n²)（10⁸ 次操作）开始可感，O(n log n)（≈10⁵）仍轻松；
3. n ≈ 10⁶：O(n log n) 约 2×10⁷ 仍在毫秒~秒级，O(n²) 已达 10¹²——现代机器要跑约半小时以上；

5. 结论一句话：**选算法本质是选增长阶，增长阶决定你能处理的规模上限**。

# 详解

## 渐近记号：O、Ω、Θ、o

设 `T(n)` 为某操作代价，`f(n)` 为参照函数（n 足够大时非负）：

| 记号 | 定义（存在正常数 c、n₀） | 直觉 |
|------|--------------------------|------|
| `T(n) = O(f(n))` | n ≥ n₀ 时 `T(n) ≤ c·f(n)` | 增长**不快于** f（上界，可为松界） |
| `T(n) = Ω(f(n))` | n ≥ n₀ 时 `T(n) ≥ c·f(n)` | 增长**不早于** f（下界） |
| `T(n) = Θ(f(n))` | 同时 O 且 Ω | 与 f **同阶**（紧确界） |
| `T(n) = o(f(n))` | 对任意 c>0 最终 `T(n) < c·f(n)` | **严格慢于** f |

- 日常说「插入排序最好 Ω(n)、最坏 O(n²)」是上下界语言；说「归并排序 Θ(n log n)」意味着上界下界都成立、这就是它的真实阶。
- **最好/平均/最坏**是另一维度（对输入分布的量化），与 O/Ω/Θ 正交：最坏情况最好也不过是 `O(n²)` 这类嵌套表述。
- 忽略常数与低阶项的正当性：分析的是趋势。`3n² + 500n + 10⁶ = O(n²)`，但 n < 10⁵ 时那个「低阶/常数」恰恰是主角——渐近分析天然偏袒大规模场景。

## 递归式：分治代价的方程

分治算法的运行时间天生是递归的：把规模 n 的问题拆成 a 个规模 n/b 的子问题，外加合并代价 `f(n)`：

```text
T(n) = a·T(n/b) + f(n),  T(1) = Θ(1)
```

三种经典解法：

1. **代入法（猜+归纳证明）**：先猜 `T(n) = O(n log n)`，再数学归纳验证——万能但需要直觉；
2. **递归树法**：逐层展开画树，每层代价相加。归并排序 `T(n)=2T(n/2)+Θ(n)`：树高 log n、每层合计 Θ(n) → Θ(n log n)；堆建表（见 [030.堆与优先队列](../03.树结构/030.堆与优先队列.md)）按层下沉求和 `Σ 2^l(h-l)` 收敛到 O(n) 同理；
3. **主定理**：直接查表，见下节。

其他常见形态：`T(n) = T(n-1) + Θ(n)`（递归版选择排序）展开成等差数列求和 = Θ(n²)；`T(n) = 2T(n-1) + O(1)`（朴素斐波那契）= Θ(2ⁿ)，这正是 [060.动态规划基础](./060.动态规划基础.md) 要用记忆化/递推消灭的重叠子问题来源。

## 主定理：查表解 T(n)=aT(n/b)+n^d

比较「子问题工作量增长 `n^(log_b a)`」与「合并工作量 `n^d`」：

| 情形 | 条件 | 解 | 例子 |
|------|------|----|------|
| 1 | `log_b a > d` | `Θ(n^(log_b a))`（子问题主导） | Karatsuba 大数乘：a=3,b=2,d=1 → `Θ(n^log₂3≈1.585)`（见 [070.Karatsuba乘法](../07.数值计算/070.Karatsuba乘法.md)） |
| 2 | `log_b a = d` | `Θ(n^d · log n)`（两者同阶，逐层叠加） | 归并排序：a=2,b=2,d=1 → `Θ(n log n)`；二分查找：a=1,b=2,d=0 → `Θ(log n)` |
| 3 | `log_b a < d` | `Θ(n^d)`（合并主导） | 若合并退化为 O(n²) 的「假分治」：a=2,b=2,d=2 → `Θ(n²)` |

适用前提：`f(n)` 是多项式 `n^d`（或满足正则条件）；`a ≥ 1, b > 1`。形式不匹配（如 `T(n)=T(n/2)+n·log n`）就回到递归树/代入法。

## 常见陷阱

- **O 不是等号**：`O(n²)` 的算法也可能实际是 Θ(n)、Θ(n log n)——只给上界不保证紧；汇报复杂度尽量用 Θ 或注明最好/最坏。
- 把「最坏情况」与「大 O」混为一谈：最坏情况是给输入的限定，大 O 是函数阶的限定，两者独立（存在「平均情况的 O(n) 界」这类说法）。
- 主定理情形 2/3 边界误判：`f(n) = n log n` 这类「多项式因子 lg 之差」不满足情形 3 的多项式分离条件，需要扩展主定理或手工证明。
- 忽略隐藏参数：哈希表「O(1) 查找」隐藏了「字符串相等比较 O(len)」；图算法 O(V+E) 里遍历邻接表的两倍计数——声明复杂度前想清楚哪些操作被当成 O(1) 了。
- 用渐近结论指导小数据：n ≤ 64 时插入排序常数极小反而比归并快，这正是 [110.TimSort](../02.基础算法/110.TimSort与自然归并.md) 混合策略的理论依据。

# 总结

- O/Ω/Θ 是描述增长趋势的上界/下界/紧界语言，与「最好/平均/最坏」两个维度正交，别混用；
- 递归式 T(n)=aT(n/b)+f(n) 是分治算法的代价方程：代入法靠猜证、递归树靠展开求和、主定理靠查表比阶；
- 复杂度分析决定规模上限而非当前速度——选增长阶，同时记住小数据上常数称王。
