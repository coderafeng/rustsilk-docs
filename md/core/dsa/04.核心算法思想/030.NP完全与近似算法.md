# 概述

P 是多项式时间可解的问题集；NP 是「答案可在多项式时间**验证**」的问题集。**NP 完全（NPC）**是 NP 中最难的一撮：任何一个 NP 问题都能多项式归约到它——找到一个 NPC 的多项式算法就等于证明 P=NP（普遍相信不存在）。实践中判断「这题能不能暴力/精确解」的第一件事，就是识别它是不是 NP 难，然后转向**近似、随机化、启发式或参数化**四条退路。

- 时间复杂度视角：NPC 问题已知最快精确算法是指数级（如 O(2ⁿ poly)），且指数下界有强指数时间假设（SETH）背书；小规模（n ≤ 40 上下）仍可精确搜（回溯/分支界定/DP 压缩），见 [090.回溯算法](./090.回溯算法.md)、[100.分支界定法](./100.分支界定法.md)。
- 空间复杂度：判定问题本身 PSPACE 以内；工程上瓶颈通常在时间而非空间。
- 应用场景：判断「需求能不能按时精确做完」的元能力——排班/物流（TSP、车辆路径）、芯片布局（图着色）、资源分配（背包、集合覆盖）、软件工程（测试最小化=覆盖）、密码学（大整数分解的困难性反而**利用**了「找不到多项式算法」，见 [09.密码学算法](../09.密码学算法/000.密码学算法概述.md)）。产品/算法岗面试中「这个问题是不是 NP 难、你打算怎么近似」是高阶考点。

# 详解

## 概念地图与判定路线

| 类别 | 定义 | 代表问题 |
|------|------|---------|
| P | 多项式时间**可解** | 排序、最短路、二分图匹配、2-SAT |
| NP | 多项式时间可**验证** | 3-SAT、哈密顿回路、子集和 |
| NP 难（NP-hard） | 至少和 NP 中最难的一样难（不必属于 NP） | 停机问题类、优化版 TSP、大整数分解（未知是否 NP 完全） |
| NP 完全（NPC） | NP ∩ NP 难 | 3-SAT、独立集、顶点覆盖、图着色、哈密顿路径 |

实战判定三步：① 先搜「是不是有已知多项式算法」——如二分图匹配有匈牙利算法、2-SAT 线性可解、区间调度贪心最优；② 疑似 NP 难则找归约源（Garey & Johnson 的 21 个经典 NPC 是弹药库：3-SAT ⇌ 独立集 ⇌ 顶点覆盖 ⇌ 团 ⇌ 着色，子集和 ⇌ 划分 ⇌ 背包判定版）；③ 确认 NP 难后放弃精确解执念，选下节四条退路之一。

## 近似算法与近似比

**近似比 ρ**：近似解代价与最优解代价之比（最小化 ≥1，最大化 ≤1，写作 1+ε 或 1-ε），多项式时间内可证。

| 问题 | 近似策略 | 保证 |
|------|---------|------|
| 顶点覆盖 | 极大匹配端点法/贪心 | **2-近似**，且 UG 猜想下难优于 2 |
| 集合覆盖 | 每步选覆盖新元素最多的集合 | **H(d)≈ln n 近似**，且此量级最优（除非 P=NP） |
| 度量 TSP | MST 双倍边走欧拉回路 + 三角短路 | **3/2 近似**（Christofides 1976，多年未破） |
| MAX-SAT/割 | 随机赋值 + 条件期望去随机化 | 期望 7/8、1/2 近似 |
| 背包 | 按价值密度贪心 + 小物品 DP | **FPTAS**：1+ε 近似，时间 poly(n,1/ε) |

两个概念分水岭：**APX**（存在常数因子近似，如顶点覆盖）与 **PTAS/FPTAS**（任意 1+ε，如 Makespan 调度、背包）；而如集合覆盖的 ln n 界与 TSP 的「无近似下界（除非 P=NP，一般度量版才有常数界）」说明近似难度也分层。

启发式（模拟退火、遗传、局部搜索、LKH 之类）不提供可证近似比，只提供「实践中足够好」，与 [040.随机化算法](./040.随机化算法.md)、[110.A星与启发式搜索](./110.A星与启发式搜索.md) 相接。

## 其余两条退路：随机化与参数化

- **随机化**：期望意义上的快（随机化快排）或近似（哈希、采样估计），本篇目录另立 040。
- **参数化（FPT）**：指数只压在「小参数」上，如顶点覆盖 `O(1.2738^k + kn)`、支配集核化——k 小（10~20）时亿级 n 也能精确解。 kernelization + bounded search tree 是两大套路。
- 工程组合拳最常见形态：**精确算法处理子问题（DP/ILP 求解器）+ 启发式处理全局（局部搜索/元启发式）**，如 Google OR-Tools 的调度产品。

## 示例：2-近似顶点覆盖（贪心/匹配法）

::: code-group

```java [Java]
// 任取一条边，两端点都入选并删除关联边；选中边构成极大匹配 M，cover = 2|M| ≤ 2·OPT
public static Set<Integer> approxVertexCover(List<int[]> edges) {
    Set<Integer> cover = new TreeSet<>();
    boolean[] used = new boolean[edges.size()];
    for (int i = 0; i < edges.size(); i++) {
        if (used[i]) continue;
        int u = edges.get(i)[0], v = edges.get(i)[1];
        cover.add(u);
        cover.add(v);
        for (int j = i + 1; j < edges.size(); j++) {
            int[] f = edges.get(j);
            if (f[0] == u || f[0] == v || f[1] == u || f[1] == v) used[j] = true;
        }
    }
    return cover;
}
```

```python [Python]
def approx_vertex_cover(n: int, edges: list[tuple[int, int]]) -> set[int]:
    """任取一条边双端点入覆盖，删其关联边；选中的边构成极大匹配 M。
    下界：OPT ≥ |M|（匹配边需要互异端点）；上界：|cover| = 2|M| ≤ 2·OPT。"""
    cover, used = set(), [False] * len(edges)
    for i, (u, v) in enumerate(edges):
        if used[i]:
            continue
        cover.add(u); cover.add(v)
        for j, (x, y) in enumerate(edges):
            if not used[j] and (u in (x, y) or v in (x, y)):
                used[j] = True
    return cover
```

:::

> [!tip] 证明两行字：选中的边互不相交（极大匹配 M），每条匹配边至少要一个独立端点盖住 ⇒ `OPT ≥ |M|`；本解每个端点盖 ≥1 条匹配边且恰取双端点 ⇒ `|cover| = 2|M| ≤ 2·OPT`。Rust/TypeScript 版按此两行逻辑直译即可。

## 常见陷阱

- **别对一般图 TSP 用「最近邻」**：最近邻无常数近似比（可构造任意坏），度量 TSP 才有 Christofides——「近似比」三个字只在多项式可证的意义下成立。
- 优化版与判定版混淆：证 NP 难用判定版（「存在 ≤k 的覆盖吗」），近似比谈优化版（最小覆盖大小）；背包「伪多项式 O(nW) DP」不等于多项式算法——W 以二进制计，是 NP 难与 FPTAS 并存的活例。
- 归约方向做反：证问题 B 难，要把**已知难问题 A 归约到 B**（A ≤ₚ B），不是相反——方向反了证明的是 B 更容易。
- 近似解「经验好」≠「有保证」：报告近似结果时应区分可证界的近似算法与玄学启发式。
- P vs NP 未解决 ≠ 你的问题可能不难：几乎所有自然 NP 难问题都被相信不在 P 内，工程决策按「不存在多项式精确算法」执行即可。

# 总结

- 识别 NP 难是算法工作的止损点：Cook-Levin 给原点，两两归约织成网，遇到「集合选择/排序调度/图匹配」类组合优化先查网内传染路径；
- 四条退路各司其职：近似（可证 ρ 界）、随机化（期望/概率保证）、启发式（实践好但无界）、参数化（指数压进小参数）；
- 2-近似顶点覆盖与 Christofides 的 3/2 提醒我们：**放弃精确不等于放弃质量**——可证的「足够好」正是工程师对 NP 难的正确姿态。
