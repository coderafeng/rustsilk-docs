# 概述

分支界定（Branch and Bound，分支界限）在状态空间树上做**带界限剪枝的系统搜索**：每个活节点算一个目标值界（下界 LB 用于最小化 / 上界 UB 用于最大化），**界劣于已知解的节点整枝剪掉**；与回溯的最大差别是搜索顺序——回溯固定 DFS 一路走黑，分支界定可用 **BFS / 优先队列（最佳优先）**，让「最有希望的节点」先出队、从而更早收紧全局界、剪掉更多分支。

- 时间复杂度：最坏仍指数（它不改变问题难度），但实际剪枝率取决于**界限函数的质量**与搜索顺序；好界 + 最佳优先常把可解规模从 n≈20 推到 n≈60+（以 TSP 为例）。
- 空间复杂度：优先队列保存前沿节点，**最佳优先可能 O(2^h)**——这是用空间换剪枝效率，与回溯 O(h) 形成对照。
- 应用场景：整数规划/线性规划求解器（SCIP、Gurobi、CPLEX 的核心就是分支界定 + 切割平面）、TSP 精确解（Hungarian 界/Held-Karp 界做 LB）、0-1 背包精确解（Dantzig 分数界）、调度（作业车间 JSP）、蛋白质折叠与电路布局；它是 NP 难问题「小规模要精确最优」时的工业答案（大规模则退回 [030.NP完全与近似算法](./030.NP完全与近似算法.md) 的启发式）。

物品 `(v,w)= A(10,10)、B(9,8)、C(2,3)、D(15,12)`，容量 W=17，按性价比降序 `D(1.25) > B(1.125) > A(1.0) > C(0.67)`，逐层「选/不选」分支：

1. 根节点界 = 分数背包解（允许切碎）：装 D 用 12 容量，剩 5 切 B 的 5/8 → **UB = 15 + 9×5/8 ≈ 20.6**；
2. 展开根得两子节点：「选 D」UB 仍是 20.6；「不选 D」从 B 起分数装：9 + 10×9/10 = **18**——入优先队列按界降序，「选 D」先出队（最大化问题先探最乐观节点）；
3. 「选 D」层继续分支：D+B/D+A 超重不可行；D+C 整数可行，价值 **17** → incumbent 更新；
4. 此后队列里凡 `UB ≤ 17` 的节点整枝丢弃；「不选 D」分支界 18 > 17 保留继续搜，其下所有完整解（B+C=11、A+C=12…）都赶不上 17，展开殆尽；
5. 队列清空 ⇒ **最优 = D+C = 17，自带证明**——回溯要搜完全树才敢宣称找齐，BB 靠界把「不可能更优」的子树成片锯掉，且结束时最优性无需额外验证。

# 详解

## 四步骨架

1. **定搜索结构**：解表示成决策序列（背包=每件选/不选），自然形成二叉树；
2. **界函数**：对当前部分解求乐观估计——最大化问题用「松弛（分数/忽略约束）后的值」做 UB 候选，最小化问题用「剩余必付的下界」做 LB；
3. **剪枝**：节点界不优于全局 incumbent（已知最优整数解）→ 丢弃；
4. **选扩展策略**：FIFO（BFS）/ LIFO（DFS，≈回溯）/ **优先级队列按界排序（最佳优先，LC 规则）**——策略决定 incumbent 多快收紧。

## 范例：0-1 背包的最佳优先 BB

分数背包界（Dantzig 贪心）是教科书级 LB/UB 来源：对剩余容量按性价比「切半件」装，得到整数解的乐观上限。

::: code-group

```java [Java]
record Node(int idx, int weight, int value, double bound) {}

int bbKnapsack(int[] v, int[] w, int W) {
    int n = v.length;
    Integer[] ord = new Integer[n];
    for (int i = 0; i < n; i++) ord[i] = i;
    java.util.Arrays.sort(ord, (a, b) ->
            Double.compare((double) v[b] / w[b], (double) v[a] / w[a]));  // 性价比降序

    var pq = new java.util.PriorityQueue<Node>(
            java.util.Comparator.comparingDouble(Node::bound).reversed());
    int best = 0;
    pq.add(new Node(-1, 0, 0, bound(ord, v, w, W, -1, 0, 0)));
    while (!pq.isEmpty()) {
        Node cur = pq.poll();
        if (cur.bound() <= best) continue;               // 剪枝：乐观界不敌已知解
        for (int k = cur.idx() + 1; k < n; k++) {        // 逐个尝试加入物品 k
            if (cur.weight() + w[ord[k]] <= W) {
                int nv = cur.value() + v[ord[k]];
                best = Math.max(best, nv);               // 整数可行解更新 incumbent
                double b = bound(ord, v, w, W, k, cur.weight() + w[ord[k]], nv);
                if (b > best) pq.add(new Node(k, cur.weight() + w[ord[k]], nv, b));
            }
        }
    }
    return best;
}

// 分数松弛界：从第 lo 件之后按性价比装满剩余容量（可切碎）
double bound(Integer[] ord, int[] v, int[] w, int W, int lo, int wt, int val) {
    double b = val; int cap = W - wt;
    for (int i = lo + 1; i < ord.length && cap > 0; i++) {
        int j = ord[i];
        if (w[j] <= cap) { b += v[j]; cap -= w[j]; }
        else b += (double) v[j] / w[j] * cap;            // 切半件
    }
    return b;
}
```

```python [Python]
import heapq

def bb_knapsack(vals, wts, W):
    n = len(vals)
    items = sorted(range(n), key=lambda i: vals[i] / wts[i], reverse=True)

    def bound(i, wt, val):                     # 分数松弛上界
        b, cap = val, W - wt
        while i < n and cap > 0:
            v, w = vals[items[i]], wts[items[i]]
            if w <= cap: b, cap = b + v, cap - w
            else: b += v / w * cap
            i += 1
        return b

    best, pq = 0, []
    heapq.heappush(pq, (-bound(0, 0, 0), 0, 0, 0))       # 负号：最大界先出队
    while pq:
        nb, i, wt, val = heapq.heappop(pq)
        if -nb <= best: continue               # 界不优于已知整数解，剪
        if i == n: best = max(best, val); continue
        j = items[i]
        if wt + wts[j] <= W:                   # 分支 1：选
            heapq.heappush(pq, (-bound(i + 1, wt + wts[j], val + vals[j]),
                                i + 1, wt + wts[j], val + vals[j]))
        heapq.heappush(pq, (-bound(i + 1, wt, val), i + 1, wt, val))  # 分支 2：不选
    return best
```

> [!tip] Rust/TypeScript 版按同一骨架直译：`BinaryHeap`/`MaxHeap` 存 `(bound, idx, weight, value)`，界函数用分数背包；核心三行——**弹队看界、选/不选两分支、入队前比 incumbent**。

## 与回溯/DP/贪心的谱系定位

| 方法 | 顺序 | 剪枝依据 | 给最优证明 | 典型空间 |
|------|------|---------|-----------|---------|
| 回溯 | DFS | 可行性/对称性 | 要搜完全树 | O(h) |
| 分支界定 | BFS/最佳优先 | **界限比较** | ✅ 队列空即证明 | O(前沿)，可能指数 |
| DP | 拓扑序 | 无（全算） | ✅ | O(状态数) |
| 贪心 | 单路径 | 不回头 | 仅当可证安全 | O(1) |

同一背包问题四法对照：贪心（性价比）快但可能错；DP `O(nW)` 对但 W 大即爆；回溯能出解但慢；BB 靠分数界常常剪得最狠——**界限函数 = 问题定制的「DP/松弛」，搜索 = 通用引擎**。

## 经典界函数速查

- TSP：LB = 当前路径长 + 未访问点「各取最小出边和入边的一半」下界（Littlewood 规则）；或 MST 剩余界。
- 作业车间调度：LB = 已排 makespan 与「剩余工件在关键机器上的总工时」取 max。
- 整数线性规划：松弛掉整数约束解 LP，LP 值即 LB/UB——单纯形每节点只需增量重解，这是商用求解器分支定界的引擎。

## 常见陷阱

- **界函数不合法**（对最小化问题给了偏大的 LB）→ 错剪最优分支，答案悄悄变错；合法性检验：「任何经由本节点的完整解的目标值都不优于本节点界」必须在每个节点成立。
- 严格不等号方向：最大化剪枝条件 `bound <= best` 剪、`>` 留；写成 `>=` 会留下等界节点做无用功（不是错，是慢），反过来 `>` 留成 `<` 剪会漏解。
- 最佳优先的内存炸弹：前沿节点可指数增长；n 大时换 DFS 迭代加深式 BB（空间换不回）或「深度优先 + 启发式排序子节点」的 hybrid。
- incumbent 初始太弱：先用贪心/取整解给一个较好初值，开局剪枝率天差地别——**先跑贪心再开搜**是标配。
- 对称分支未破：物品/城市顺序全排列里同解多次出现，加「决策序约束」（同价值层强制按编号）压对称性。

# 总结

- 分支界定 = 系统枚举 + 界限剪枝：界函数给「经此节点能好到哪儿」的乐观估计，劣者整枝丢弃，队列清空时最优性自带证明；
- 与回溯分家的两点：搜索顺序（最佳优先用优先队列尽早收紧 incumbent）与剪枝依据（比界而不是比可行）；空间可能指数是其阿喀琉斯之踵；
- 工程形态就是 ILP/CP 求解器与 TSP 精确解的核心循环——界 = 松弛问题（分数背包/LP/MST），拿到一个好界等于拿到一台剪枝发动机。
