# 概述

动态规划（DP）把问题拆成**重叠子问题**并记录每个子问题的解，「空间换重复计算」；适用前提是**最优子结构**（大问题的最优解由小问题最优解拼成）+ **无后效性**（当前状态一旦确定，之后怎么走与怎么走来的路无关）。相比分治（子问题独立，见 [050.分治算法](./050.分治算法.md)），DP 的核心动作是**定义状态**——状态选对，方程自然来。

- 时间复杂度：`状态数 × 每状态转移代价`——这是 DP 分析万能公式；空间可做滚动数组/路径压缩优化。
- 应用场景：
  - **经典决策**：最短编辑距离（拼写纠正、DNA 比对 Smith-Waterman 全局/局部比对）、资源/背包类组合优化（预算分配、装载）、正则与解析（CYK 语法分析）、文本排版（LaTeX/TeX 断行算法）；
  - **工业系统**：Viterbi 解码（语音识别/输入法）、序列比对（生物信息 BLAST）、动态路由与库存补货、游戏 AI 行为树之外的策略表、视频编码（x264 码率分配）；
  - **刷题版图**：LeetCode「动态规划」标签 400+，是笔试面试区分度最高的专题。

- 所属章节：[000.核心算法思想概述](./000.核心算法思想概述.md)

1. **纯递归**：画 fib(5) 的调用树——fib(3) 被算 2 次、fib(2) 被算 3 次，树形状如指数爆炸（`T(n)=T(n-1)+T(n-2)` ≈ Θ(1.618ⁿ)），重叠子问题肉眼可见；
2. **记忆化（自顶向下）**：给调用树装缓存——第一次算 fib(2) 后写下结果，第二次到来直接命中返回；每个状态只算一次，复杂度 = 状态数 n × 转移 O(1) = O(n)；
3. **递推（自底向上）**：扔掉递归栈，从 `f[0], f[1]` 开始按依赖顺序逐步填表到 `f[n]`——同样是 O(n)，但没有递归开销、可提前终止、能做滚动数组把空间从 O(n) 压到 O(1)；
4. 动画里三个画面共用同一张「状态转移图」：递归是**倒着走**这张图（带重复），记忆化是**带备忘录地走**，递推是**按拓扑序走**——三者是同一 DAG 的三种遍历方式。

# 详解

## DP 四步推导法（状态定义 → 转移 → 边界 → 顺序）

以**打家劫舍**（LeetCode 198：不能偷相邻房屋，求最大金额）走一遍完整推导：

1. **状态定义**：`f[i]` = 「只考虑前 i 间房」能偷到的最大金额。——定义时务必说清「前 i 个」这个**子问题边界**；
2. **转移方程**：第 i 间只有偷/不偷两种：`f[i] = max(f[i-1], f[i-2] + money[i])`；
3. **边界**：`f[0] = 0`（没房可偷），`f[1] = money[0]`；
4. **计算顺序**：i 从小到大（转移只依赖前两项，天然无后效性）。

**为什么满足最优子结构**：`f[i]` 最优时，它内部引用的 `f[i-1]`、`f[i-2]` 也必须最优——若存在更大的 `f'[i-2]`，替换后能得到更大的 `f[i]`，矛盾（切割粘贴论证）。

## 三种实现骨架对比

::: code-group

```java [Java]
// ① 记忆化递归：递归 + HashMap/数组缓存
long[] memo;
long rob(int[] money, int i) {
    if (i < 0) return 0;
    if (memo[i] != -1) return memo[i];
    return memo[i] = Math.max(rob(money, i - 1), rob(money, i - 2) + money[i]);
}

// ② 递推填表：显式 DP 数组
long[] f = new long[n + 1];
f[1] = money[0];
for (int i = 2; i <= n; i++) {
    f[i] = Math.max(f[i - 1], f[i - 2] + money[i - 1]);
}

// ③ 滚动变量：依赖窗口只有 2 → O(1) 空间
long prev2 = 0, prev1 = 0;
for (int x : money) {
    long cur = Math.max(prev1, prev2 + x);
    prev2 = prev1;
    prev1 = cur;
}
```

```rust [Rust]
// 递推填表版
pub fn rob(money: &[i64]) -> i64 {
    let (mut prev2, mut prev1) = (0i64, 0i64);   // 滚动变量即最优空间写法
    for &x in money {
        let cur = prev1.max(prev2 + x);
        prev2 = prev1;
        prev1 = cur;
    }
    prev1
}
```

```typescript [TypeScript]
function rob(money: number[]): number {
  let prev2 = 0, prev1 = 0;
  for (const x of money) {
    const cur = Math.max(prev1, prev2 + x);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
```

```python [Python]
def rob(money: list[int]) -> int:
    prev2 = prev1 = 0
    for x in money:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1
```

## 状态设计的三板斧

- **维度选择**：一维线性（斐波/抢劫/股票买卖系列）、二维网格（路径计数、LCS、编辑距离）、**集合/子集**（状态压缩 DP：`f[mask]`，旅行商 O(2ⁿn²)）、**区间**（`f[l][r]`，见 [070.经典DP模型](./070.经典DP模型.md) 区间 DP）、**树上**（树形 DP，在 [03.树结构](../03.树结构/000.树结构概述.md) 的 DFS 后序上套 DP）。
- **设计心法**：转移要回答「最后一步从哪来」（倒推终局分类）；「以 i 结尾」与「前 i 个的最优」是两套常用定义——最长类问题几乎都用「以 i 结尾」（否则无法接后续，见 LIS）。
- **还原方案**：要输出具体方案就存 `parent` 指针或从终态倒着按转移方程回溯——DP 默认只给最优值，构造最优解要额外记账。

## 常见陷阱

- **无后效性不成立硬做**：如「偷环状房屋」i=1 与 i=n 相互制约，直接递推破坏无后效——正确做法是拆成「不偷 1」「不偷 n」两次线性 DP。
- 状态定义含糊导致转移漏情况：先写下「f[i] 到底表示什么子问题」的中文句子再动笔，检查它是否**覆盖所有后续会引用的信息**（只存最大值却需要「至少用了一枚硬币」这类额外条件时，要拆多维状态）。
- 边界与初始值：求 min 类 DP 未达状态要初始化 `+∞`，求 max 用 `-∞` 或不可达标记；`f[0]` 的「空子问题」取值（0 还是 -∞）决定整张表的正确性。
- 填表顺序 ≠ 下标顺序：依赖 `f[i+w]`（如完全背包内层正序）或区间 DP 需按**长度从小到大**——画状态依赖图按拓扑序走（图解节结论：递推 = 状态 DAG 的拓扑序遍历）。
- 递归版忘初始化 memo（如默认 0 与合法答案 0 冲突）导致全表「假装已算」；用哨兵值 `-1`/`None` 区分「未算」。

# 总结

- DP = 最优子结构 + 重叠子问题 + 无后效性，复杂度口诀「状态数 × 转移代价」；
- 记忆化与递推是同一张状态 DAG 的两种遍历：自顶向下好写、自底向上省栈且方便滚动数组与方案回溯；
- 难点从来不是代码而是**状态定义**——用一句中文说清 `f[...]` 是什么、检查信息是否完备、倒推最后一步，四步法练熟后经典模型只是换皮（下一篇 [070.经典DP模型](./070.经典DP模型.md) 展开背包/LCS/LIS/区间四大套路）。
