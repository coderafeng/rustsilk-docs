# 概述

线性搜索（Linear / Sequential Search）从首元素起**逐个比对**直到命中或遍历结束，是不依赖任何前提（无需有序、无需额外空间）的兜底查找。

- 时间复杂度：最好 O(1)、平均/最坏 **O(n)**；n 个等概率元素平均比较 (n+1)/2
- 空间复杂度：O(1)
- 应用场景：无序数据、小型集合、链表/哈希桶内/迭代器等无法随机访问的结构、`find`/`any` 的底层。

# 详解

## 优化：哨兵法减少边界判断

把 target 放到数组末尾作哨兵，可省去循环里 `i < n` 的判断，命中后判断是否为哨兵位即可——经典 C 优化。

::: code-group
```java [Java]
int linearSearch(int[] a, int target) {
    for (int i = 0; i < a.length; i++) if (a[i] == target) return i;
    return -1;
}
```
```rust [Rust]
fn linear_search(a: &[i32], target: i32) -> Option<usize> {
    a.iter().position(|&x| x == target)   // 标准库即线性查找
}
```
```typescript [TypeScript]
function linearSearch(a: number[], target: number): number {
    for (let i = 0; i < a.length; i++) if (a[i] === target) return i;
    return -1;
}
// 实际多用 a.indexOf(target) 或 a.find(x => ...)
```
```python [Python]
def linear_search(a, target):
    for i, x in enumerate(a):
        if x == target:
            return i
    return -1
# 实际多用 a.index(target)（未找到抛 ValueError）
```
:::

## 常见陷阱

- **别对大数据无序线性扫**：能排序就转二分 O(log n)，能建索引就转哈希 O(1)。
- **返回 -1 与下标 0 冲突**：用 `Optional`/哨兵/异常区分"未找到"，别把 0 当假值。

# 总结

- 线性搜索：无前提、O(1) 空间、O(n) 时间的兜底查找；
- 适合小数据与不可随机访问的结构（链表、桶内）；
- 一旦数据量大且可预处理，应升级为二分（有序）或哈希（按键）。
