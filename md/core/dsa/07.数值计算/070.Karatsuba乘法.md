# 概述

两个 \(n\) 位十进制数相乘，人人从小背的是「逐位相乘再相加」的 \(O(n^2)\) 竖式。1960 年，Anatoly Karatsuba 在莫斯科大学听苏联数值数学奠基人 Kolmogorov 的研讨课时，证明了「3 次乘法就够了」——第一个打破「乘法必须 \(n^2\)」直觉的算法，直接开创了分治乘法家族。核心恒等式只有一行：把数按高位/低位切开，\(xy = z_2 B^2 + z_1 B + z_0\)，其中 \(z_0 = x_0y_0\)、\(z_2 = x_1y_1\)、而交叉项 \(z_1 = x_0y_1 + x_1y_0\) 不必做两次乘法，用 \((x_0+x_1)(y_0+y_1) - z_0 - z_2\) **一次乘法白捡**。

- 所属章节：[000.数值计算概述](./000.数值计算概述.md)
- 时间复杂度：\(T(n) = 3T(n/2) + O(n) = O(n^{\log_2 3}) \approx O(n^{1.585})\)；空间复杂度：递归栈 + 临时和 \(O(n)\)
- 应用场景：大整数库的地板档——GMP、Python `int`、Java `BigInteger` 在「几百到几千位」区间用 Karatsuba/Toom-Cook，再大才切 FFT/NTT 路线；密码学 RSA/ECC 的模乘内核（[09.密码学算法/020.RSA非对称加密](../09.密码学算法/020.RSA非对称加密.md) 里 2048 位模幂的底子就是大数乘）；计算器与 CAS 的精确算术
- 前置：分治与主定理见 [04.核心算法思想/050.分治算法](../04.核心算法思想/050.分治算法.md)；「用更少的乘法换更多加减」的矩阵同族见 [020.矩阵运算算法](./020.矩阵运算算法.md)；更快的大数乘法见 [060.快速傅里叶变换FFT](./060.快速傅里叶变换FFT.md)

4. **白捡中间项** \(z_1 = 6164 - 2652 - 672 = 2840\)——省掉了 \(34\times56\) 与 \(12\times78\) 两次独立乘法。

1. \(n\) 位数的乘法树：每层节点数 \(\times 3\)、问题规模 \(\div 2\)，深度 \(\log_2 n\)。

# 详解

## 恒等式与复杂度

设 \(x = x_1 B + x_0\)、\(y = y_1 B + y_0\)（\(B = 10^{\lceil n/2 \rceil}\)，即按一半位数切开）：

\[
xy = \underbrace{x_1y_1}_{z_2} B^2 + \big(x_1y_0 + x_0y_1\big) B + \underbrace{x_0y_0}_{z_0}
\]

交叉项的「三项技巧」：

\[
z_1 = x_1y_0 + x_0y_1 = (x_0 + x_1)(y_0 + y_1) - z_0 - z_2
\]

于是 \(n\) 位乘法 = 3 个 \(n/2\) 位乘法 + 若干 \(O(n)\) 加减/移位。递推 \(T(n) = 3T(n/2) + O(n)\)，主定理情形 1（\(\log_2 3 > 1\)）给 \(T(n) = O(n^{\log_2 3})\)。

家族续命：Toom-Cook 3-way 用 5 次 \(n/3\) 乘法得 \(O(n^{1.465})\)；FFT/NTT 路线（[060.快速傅里叶变换FFT](./060.快速傅里叶变换FFT.md)）逼近 \(O(n\log n)\)（2019 年 Harvey–van der Hoeven 给出理论达到 \(O(n\log n)\) 的算法）。但**小乘法永远是 Karatsuba 的天下**——库实现普遍按位数分段：小学竖式 → Karatsuba → Toom-Cook → FFT，每段切换点都实测校准过。

```java [Java]
/** 教学版：限非负、结果不超 long（约 9 位以内输入）；生产请用 BigInteger.multiply 的内部递归 */
public static long karatsuba(long x, long y) {
    if (x < 0 || y < 0) throw new IllegalArgumentException("需非负输入");
    if (x < 100 && y < 100) return x * y;                 // 递归出口（阈值可调）
    int n = Math.max(digits(x), digits(y));
    int half = (n + 1) / 2;
    long base = pow10(half);
    long x1 = x / base, x0 = x % base;
    long y1 = y / base, y0 = y % base;
    long z0 = karatsuba(x0, y0);
    long z2 = karatsuba(x1, y1);
    long z1 = karatsuba(x0 + x1, y0 + y1) - z0 - z2;      // 三项技巧
    return z2 * pow10(2 * half) + z1 * pow10(half) + z0;
}

static int digits(long x) {
    int d = 1;
    while ((x /= 10) > 0) d++;
    return d;
}

static long pow10(int k) {
    long p = 1;
    while (k-- > 0) p *= 10;
    return p;
}
// karatsuba(1234, 5678) → 7006652
```

```rust [Rust]
/// 教学版：限非负 u64 且结果不溢出（输入约 ≤ 9 位）
pub fn karatsuba(x: u64, y: u64) -> u64 {
    if x < 100 && y < 100 {
        return x * y;
    }
    let n = digits(x).max(digits(y));
    let half = (n + 1) / 2;
    let base = pow10(half);
    let (x1, x0) = (x / base, x % base);
    let (y1, y0) = (y / base, y % base);
    let z0 = karatsuba(x0, y0);
    let z2 = karatsuba(x1, y1);
    let z1 = karatsuba(x0 + x1, y0 + y1) - z0 - z2;
    z2 * pow10(2 * half) + z1 * pow10(half) + z0
}

fn digits(mut x: u64) -> u32 {
    let mut d = 1;
    x /= 10;
    while x > 0 {
        d += 1;
        x /= 10;
    }
    d
}

fn pow10(k: u32) -> u64 {
    (0..k).fold(1u64, |acc, _| acc * 10)
}
```

## 工程实现的真实形态

教学版用十进制拆位，真实大数库把数存成**机器字数组**（base \(2^{32}\) 或 \(2^{64}\)），此时：

1. 「切一半」= 数组对半分，\(O(1)\)；「\(B^2\) 移位」= 下标偏移，\(O(1)\)。
2. 进位合并只在最外层做一次（逐字加法带进位链），中间量全部原地处理。
3. 递归出口取「一次 cache line 能装的字数」附近（常见 32～256 字），实测校准而非理论推导。
4. 负数通过「符号外提 + 无符号核心」处理；减法产生的中间借位在字级用补码吸收。

Python `int` 在 CPython 里就是这套：30 位一「digit」的数组，超过阈值走 Karatsuba（`x_mul` → `k_mul`），这就是它算 \(2^{100000}\) 级别乘法远快于朴素竖式的根本原因。

## 常见陷阱

1. **递归出口阈值**：出口设太小（如个位数）递归开销反超收益；固定版要求 `x < 100 && y < 100`（双小），若写成 `x < 100 || y < 100`（任一为小）会把「小数 × 大数」也拉进拆分解体，实测更慢。真实库一律双小阈值。
2. **定宽整数溢出**：Java `long`/Rust `u64` 版只能当教具，结果超过 \(2^{63}-1\) 直接绕回负数；任意精度请用 `BigInteger`/`num-bigint`/原生 `int`，或把本算法实现到字数组上。
3. **z₁ 的减法顺序**：`(x0+x1)(y0+y1) - z0 - z2` 数学上恒非负，但实现时若先算 `z0 + z2` 可能提前溢出（定宽整数的中间量峰值比最终结果更大）——按「先减后加」顺序或升宽度。
4. **字符串拆位是性能黑洞**：Python 版 `len(str(x))` 每层重复转字符串，\(O(n^2)\) 起手就毁了复杂度；练习时传位数或缓存。
5. **不要用 Karatsuba 做模乘**：RSA 场景是模 \(N\) 乘法（[06.字符串与数论/070.快速幂与模运算](../06.字符串与数论/070.快速幂与模运算.md)），Karatsuba 的组装项 \(z_2B^2\) 在模意义下并不省—— Montgomery 约化才是标配路线（[09.密码学算法/020.RSA非对称加密](../09.密码学算法/020.RSA非对称加密.md)）。
6. **常数时间防线**：密码学实现里乘法的分支/内存访问模式若随操作数位数变化，可能构成侧信道；大数乘在敏感路径上需 padding 到固定规模。

# 总结

Karatsuba 的历史意义大于它的工程排名：它证明了「\(n^2\) 不是乘法的命」，教会整个领域用**代数换元**换**分支因子**——交叉项合并技巧后来原样出现在 [020.矩阵运算算法](./020.矩阵运算算法.md) 的 Strassen（8 块变 7 块）里。工程上它守在大数乘法的第一档（竖式 → Karatsuba → Toom-Cook → FFT/NTT），是「简单算法在中小规模仍是赢家」的最佳教材。与 FFT 相比，Karatsuba 全程整数、无舍入误差、实现三十行——在 \(10^2 \sim 10^4\) 位区间，它仍是答案本身。
