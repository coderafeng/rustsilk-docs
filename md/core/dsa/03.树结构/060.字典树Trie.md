# 概述

字典树（Trie，读音同 "try"，前缀树）把字符串集合按**公共前缀合并成树**：根到某标记节点的路径拼出一个词，边即字符。查询代价只与**词长 L** 有关、与集合大小 n 无关——在「海量词 + 短查询」的前缀匹配场景里，这是哈希表做不到的（哈希只能整串等值查询，不支持前缀）。

- 时间复杂度：插入/查找 O(L)；以某前缀开头的计数/枚举 O(L + 命中子树规模)
- 空间复杂度：O(Σ|word| × 字符集)，最坏每个字符一个节点；压缩 Trie（Radix Tree）把单子链合并成边上的字符串片段，可大幅瘦身
- 应用场景：
  - **输入补全/搜索联想**：搜索引擎下拉词、IDE 代码补全（前缀命中后沿子树 DFS 按热度出词）；
  - **敏感词过滤**：内容审核扫描文本逐字符走树，命中 `isEnd` 即拦截；多模式扩展即 AC 自动机（Trie + fail 指针，见 [06.字符串与数论](../06.字符串与数论/000.字符串与数论概述.md) 的字符串匹配篇）；
  - **网络路由**：IP 转发表的最长前缀匹配（LPM）用二叉/多叉 Trie 实现；
  - **拼写纠错与前缀统计**：编辑距离 ≤1 联想（DFS + 通配一层）、`startsWith` 类 API；
  - 变种：01 Trie（LeetCode 1265 二进制位前缀→最大异或对，把数值按 bit 建树）、持久化 Trie、Radix Tree（Redis 早期、Linux 页缓存、CMDB 键空间都用它）。

**动画：插入 `cat / car / do / dog` 后查询 `car` 与前缀 `ca`**
<!-- dsa.assets/trie/trie-insert-search.gif -->

1. **插入 `cat`**：从根沿 c→a→t 建三个节点，`t` 节点置 `isEnd = true`（标记「到此为止是一个完整词」）；
2. **插入 `car`**：c、a 两节点已存在直接复用，只为 `r` 新建分支并打 `isEnd`——**公共前缀只存一份**，这就是 Trie 的空间法则；
3. **查询 `car`**：沿 c→a→r 走，路径存在但要看终点 `isEnd`——若只查 `ca` 且 `ca` 未打标记，答案是「不是词，但是前缀」；
4. **前缀统计**：定位到 `a` 节点后，其子树里所有 `isEnd` 计数（可预先在节点上存 `pass` 经过计数）就是「以 ca 开头的词数」，无需重新扫描词表。

# 详解

## 标准实现：insert / search / startsWith

节点 = 「孩子表 + 是否词尾」。孩子表用小写 26 字母数组最省；字符集大/杂时用哈希表存边。

::: code-group

```java [Java]
public class Trie {
    private static class Node {
        Node[] next = new Node[26];
        boolean isEnd;
    }
    private final Node root = new Node();

    public void insert(String word) {
        Node cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
        }
        cur.isEnd = true;
    }

    private Node walk(String prefix) {
        Node cur = root;
        for (char c : prefix.toCharArray()) {
            cur = cur.next[c - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }

    public boolean search(String word) {
        Node n = walk(word);
        return n != null && n.isEnd;               // 路径存在 ≠ 是词
    }

    public boolean startsWith(String prefix) {
        return walk(prefix) != null;               // 路径存在即为前缀
    }
}
```

```rust [Rust]
use std::collections::HashMap;

#[derive(Default)]
pub struct TrieNode {
    children: HashMap<char, TrieNode>,
    is_end: bool,
}

pub struct Trie {
    root: TrieNode,
}

impl Default for Trie {
    fn default() -> Self { Self::new() }
}

impl Trie {
    pub fn new() -> Self { Self { root: TrieNode::default() } }

    pub fn insert(&mut self, word: &str) {
        let mut cur = &mut self.root;
        for c in word.chars() {
            cur = cur.children.entry(c).or_default();
        }
        cur.is_end = true;
    }

    fn walk<'a>(&'a self, prefix: &str) -> Option<&'a TrieNode> {
        let mut cur = &self.root;
        for c in prefix.chars() {
            cur = cur.children.get(&c)?;
        }
        Some(cur)
    }

    pub fn search(&self, word: &str) -> bool {
        self.walk(word).is_some_and(|n| n.is_end)  // 路径存在 ≠ 是词
    }

    pub fn starts_with(&self, prefix: &str) -> bool {
        self.walk(prefix).is_some()
    }
}
```

```typescript [TypeScript]
class TrieNode {
  children = new Map<string, TrieNode>();
  isEnd = false;
}

class Trie {
  private root = new TrieNode();

  insert(word: string): void {
    let cur = this.root;
    for (const c of word) {
      if (!cur.children.has(c)) cur.children.set(c, new TrieNode());
      cur = cur.children.get(c)!;
    }
    cur.isEnd = true;
  }

  private walk(prefix: string): TrieNode | null {
    let cur: TrieNode | null = this.root;
    for (const c of prefix) {
      cur = cur.children.get(c) ?? null;
      if (!cur) return null;
    }
    return cur;
  }

  search(word: string): boolean {
    const n = this.walk(word);
    return !!n && n.isEnd;                         // 路径存在 ≠ 是词
  }

  startsWith(prefix: string): boolean {
    return this.walk(prefix) !== null;
  }
}
```

```python [Python]
class Trie:
    def __init__(self):
        self.root = {"is_end": False}          # 节点 = 嵌套 dict

    def insert(self, word: str) -> None:
        cur = self.root
        for c in word:
            cur = cur.setdefault(c, {"is_end": False})
        cur["is_end"] = True

    def _walk(self, prefix: str):
        cur = self.root
        for c in prefix:
            cur = cur.get(c)
            if cur is None:
                return None
        return cur

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node["is_end"]   # 路径存在 ≠ 是词

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None
```

## 进阶一：节点记 `count`，前缀统计 O(L)

在孩子表之外给每节点加 `pass`（插入时途经 +1）：查询前缀 `p` 的「开头词数」只需走完 `p` 读 `pass`，把 O(子树) 降为 O(L)——搜索联想框里「找到约 N 条」就靠它。删除单词时沿路径 `pass` 回减并剪掉零计数分支。

## 进阶二：01 Trie——把整数当二进制串

LeetCode 421「数组中两个数的最大异或值」：把所有数按 31 个 bit 从高到低插入二叉 Trie，查询 `x` 时贪心走**与 x 当前 bit 相反**的分支——Trie 不止装字符串，凡是「按位/按符号序列前缀匹配 + 贪心」都能套。

## 常见陷阱

- **`search` 与 `startsWith` 的差别只在终点 `isEnd`**：只用「能否走通」判存在，`car` 会被误判为词而它只是 `cards` 的前缀；插入时忘打 `isEnd` 是第一大 bug。
- **删除不能只清 `isEnd`**：词表要萎缩时还需回收无 `isEnd`、无兄弟的尾巴节点，否则空间只增不减。
- **字符数组 vs 哈希孩子表**：26 字母 `Node[26]` 定位 O(1) 但每节点 26 个指针开销大；Unicode/混合字符集必须换 `Map`，或做字符→小整数映射。
- 敏感词过滤扫描文本时，**匹配失败要能回到正确分支**——纯 Trie 只能从每个位置重新起扫 O(n·L)；生产方案是 AC 自动机（Trie + KMP 式 fail 指针 + 出边压缩），一次扫描完成多模式匹配。
- 递归 DFS 出词在深层 Trie（长 URL/中文逐字）可能爆栈，改显式栈或迭代。

# 总结

- Trie 用「公共前缀共享路径」把查询代价从集合规模 n 里解耦，只剩词长 L，是前缀匹配问题的唯一体面结构；
- 一个 `isEnd` 标记划清「是词」与「是前缀」，一个 `pass` 计数换来电商级前缀统计，01 Trie 证明它同样装得下整数；
- 规模上去后交给压缩 Radix Tree 省节点、交给 AC 自动机加 fail 边做一遍扫描——Trie 是这一整个「前缀家族」的根。
