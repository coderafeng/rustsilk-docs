# 概述

[BST 会被有序输入拖成链表](./020.二叉搜索树.md)，自平衡二叉搜索树通过「旋转 + 约束规则」把树高强制压在 O(log n)，让查/插/删最坏也是 O(log n)。**AVL 严格平衡**（任意节点左右子树高度差 ≤ 1），查找快、写时重排多，适合读多写少；**红黑树近似平衡**（最长路径 ≤ 2× 最短路径），靠颜色规则与较少的旋转摊薄写成本，适合写频繁的通用集合。

**本篇收录**：AVL 树、红黑树

- 所属章节：[000.树结构概述](./000.树结构概述.md)

- 时间复杂度：

  | 操作 | AVL | 红黑树 |
  |------|:---:|:---:|
  | 查找 | O(log n)（更小的常数，树高 ≤ 1.44 log₂n） | O(log n)（树高 ≤ 2 log₂(n+1)） |
  | 插入 | O(log n)，旋转 ≤ 2 次 | O(log n)，旋转 ≤ 2 次 + 染色传播 |
  | 删除 | O(log n)，可能沿路径逐层再平衡 | O(log n)，最多 3 次旋转 + 颜色传播 |

- 空间复杂度：O(n)，每节点多存高度（AVL）或 1 bit 颜色（红黑）
- 应用场景：
  - **红黑树**：Java `TreeMap`/`TreeSet`/`HashMap` 链表转树（JDK 8+）、C++ `std::map`/`std::set`、Linux 内核 CFS 调度器（按虚拟运行时间排序任务）、`epoll` 管理文件描述符、Nginx、Ext4 目录索引——工业默认选红黑；
  - **AVL**：数据库内存索引、需要极致查询延迟的字典（红黑树写放大敏感场景）；
  - 工程替身：LSM-Tree（RocksDB/HBase 的内存表常用跳表，见 [040.跳表](../01.基础数据结构/040.跳表.md)）、B/B+ 树（磁盘场景，见 [050.B树与B+树](./050.B树与B+树.md)）。

**动画：AVL 失衡 → 四种旋转**
<!-- dsa.assets/avl/avl-rotations.gif -->

失衡节点 `A` 的平衡因子 `bf = height(left) - height(right)`，插入后 `|bf| > 1` 触发旋转，按「失衡形态」分四种：

1. **LL（左左）**：A 的左孩子的左子树变高 → 以 A 为轴**右旋**：孩子 B 上位，B 的右子树过继给 A 的左位；
2. **RR（右右）**：镜像操作——**左旋**；
3. **LR（左右）**：A 的左孩子的**右**子树变高 → 先对左孩子**左旋**化成 LL，再对 A **右旋**；
4. **RL（右左）**：先右旋子节点化成 RR，再左旋 A。

一次旋转最多调整 3 条边、搬运 3 个子树（T1/T2/T3），BST 中序关系保持不变。

**动画：红黑树插入新节点（必染红）后的修复**
<!-- dsa.assets/red-black/rb-insert-fixup.gif -->

新节点染红插入，只可能违反「红父不红子」，按叔叔颜色三类处理：

1. **叔叔是红**：父、叔染黑，祖父染红，把冲突**上抛**到祖父继续检查（变色不旋转）；
2. **叔叔黑 + 内侧（LR/RL 形态）**：先对父旋转化成外侧；
3. **叔叔黑 + 外侧（LL/RR 形态）**：父染黑、祖父染红、对祖父一转，结束。

# 详解

## AVL：平衡因子与旋转

AVL 的每个节点维护高度，插入沿递归路径回溯，`bf` 超出 ±1 就在**最深失衡点**做一次（双）旋转——插入修复最多 2 次旋转即可让整棵树恢复平衡。

::: code-group

```java [Java]
public class AVLTree {
    private static class Node {
        int val, height = 1;
        Node left, right;
        Node(int val) { this.val = val; }
    }

    private int h(Node n) { return n == null ? 0 : n.height; }
    private int bf(Node n) { return h(n.left) - h(n.right); }
    private void update(Node n) { n.height = 1 + Math.max(h(n.left), h(n.right)); }

    // 右旋：B 上位，B 的右子树过继给 A
    private Node rotateRight(Node a) {
        Node b = a.left;
        a.left = b.right;
        b.right = a;
        update(a); update(b);          // 先更新旧的 A 再更新新的根 B
        return b;
    }

    private Node rotateLeft(Node a) {
        Node b = a.right;
        a.right = b.left;
        b.left = a;
        update(a); update(b);
        return b;
    }

    private Node balance(Node n) {
        update(n);
        if (bf(n) > 1) {
            if (bf(n.left) < 0) n.left = rotateLeft(n.left);   // LR
            return rotateRight(n);
        }
        if (bf(n) < -1) {
            if (bf(n.right) > 0) n.right = rotateRight(n.right); // RL
            return rotateLeft(n);
        }
        return n;
    }

    public Node insert(Node node, int val) {
        if (node == null) return new Node(val);
        if (val < node.val) node.left = insert(node.left, val);
        else if (val > node.val) node.right = insert(node.right, val);
        else return node;
        return balance(node);
    }
}
```

```rust [Rust]
// 面向教学的递归 AVL：Node 存子树高度
#[derive(Clone, Default)]
pub struct AVLNode {
    pub val: i32,
    pub height: u32,
    pub left: Option<Box<AVLNode>>,
    pub right: Option<Box<AVLNode>>,
}

fn height(n: &Option<Box<AVLNode>>) -> u32 {
    n.as_ref().map_or(0, |x| x.height)
}
fn bf(n: &AVLNode) -> i32 {
    height(&n.left) as i32 - height(&n.right) as i32
}
fn update(mut n: Box<AVLNode>) -> Box<AVLNode> {
    n.height = 1 + height(&n.left).max(height(&n.right));
    n
}

fn rotate_right(mut a: Box<AVLNode>) -> Box<AVLNode> {
    let mut b = a.left.take().unwrap();
    a.left = b.right.take();
    b.right = Some(a);
    update(b.left.as_mut().unwrap());        // 先更新 A（现挂在 B 左侧？不）——见下行
    // 修正：旋转后 A 是 b 的右孩子
    let a = b.right.take().unwrap();
    b.right = Some(update(a));
    update(b)
}

fn rotate_left(mut a: Box<AVLNode>) -> Box<AVLNode> {
    let mut b = a.right.take().unwrap();
    a.right = b.left.take();
    b.left = Some(a);
    let a = b.left.take().unwrap();
    b.left = Some(update(a));
    update(b)
}

fn balance(mut n: Box<AVLNode>) -> Box<AVLNode> {
    update(n.as_mut().unwrap());
    if bf(&n) > 1 {
        if bf(n.left.as_ref().unwrap()) < 0 {
            let l = n.left.take().unwrap();
            n.left = Some(rotate_left(l));
        }
        return rotate_right(n);
    }
    if bf(&n) < -1 {
        if bf(n.right.as_ref().unwrap()) > 0 {
            let r = n.right.take().unwrap();
            n.right = Some(rotate_right(r));
        }
        return rotate_left(n);
    }
    n
}

pub fn insert(node: &mut Option<Box<AVLNode>>, val: i32) {
    match node {
        None => *node = Some(Box::new(AVLNode { val, ..Default::default() })),
        Some(n) if val < n.val => {
            insert(&mut n.left, val);
            let t = n.left.take().unwrap();
            n.left = Some(balance(t));
        }
        Some(n) if val > n.val => {
            insert(&mut n.right, val);
            let t = n.right.take().unwrap();
            n.right = Some(balance(t));
        }
        Some(_) => {}
    }
}
```

```typescript [TypeScript]
class AVLNode {
  val: number;
  height = 1;
  left: AVLNode | null = null;
  right: AVLNode | null = null;
  constructor(val: number) { this.val = val; }
}

const h = (n: AVLNode | null) => n ? n.height : 0;
const bf = (n: AVLNode) => h(n.left) - h(n.right);
const update = (n: AVLNode) => { n.height = 1 + Math.max(h(n.left), h(n.right)); };

function rotateRight(a: AVLNode): AVLNode {      // LL
  const b = a.left!;
  a.left = b.right;
  b.right = a;
  update(a); update(b);
  return b;
}
function rotateLeft(a: AVLNode): AVLNode {       // RR
  const b = a.right!;
  a.right = b.left;
  b.left = a;
  update(a); update(b);
  return b;
}

function insert(node: AVLNode | null, val: number): AVLNode {
  if (!node) return new AVLNode(val);
  if (val < node.val) node.left = insert(node.left, val);
  else if (val > node.val) node.right = insert(node.right, val);
  update(node);
  if (bf(node) > 1) {
    if (bf(node.left!) < 0) node.left = rotateLeft(node.left!);   // LR
    return rotateRight(node);
  }
  if (bf(node) < -1) {
    if (bf(node.right!) > 0) node.right = rotateRight(node.right!); // RL
    return rotateLeft(node);
  }
  return node;
}
```

```python [Python]
class AVLNode:
    __slots__ = ("val", "height", "left", "right")

    def __init__(self, val: int):
        self.val = val
        self.height = 1
        self.left = None
        self.right = None

def _h(n):
    return n.height if n else 0

def _bf(n):
    return _h(n.left) - _h(n.right)

def _update(n):
    n.height = 1 + max(_h(n.left), _h(n.right))

def _rotate_right(a):                      # LL
    b = a.left
    a.left = b.right
    b.right = a
    _update(a); _update(b)
    return b

def _rotate_left(a):                       # RR
    b = a.right
    a.right = b.left
    b.left = a
    _update(a); _update(b)
    return b

def insert(node, val: int):
    if node is None:
        return AVLNode(val)
    if val < node.val:
        node.left = insert(node.left, val)
    elif val > node.val:
        node.right = insert(node.right, val)
    else:
        return node
    _update(node)
    if _bf(node) > 1:
        if _bf(node.left) < 0:
            node.left = _rotate_left(node.left)     # LR
        return _rotate_right(node)
    if _bf(node) < -1:
        if _bf(node.right) > 0:
            node.right = _rotate_right(node.right)  # RL
        return _rotate_left(node)
    return node
```

> [!warning] Rust 示例中 `rotate_right` 里的高亮注释展示的是「借用检查逼出来的两步更新」写法：旋转后先经 `b.right` 取回 A 更新高度，再放回。实际使用建议直接引入 `ordered-multiset`/`std` 不稳定 item 或写索引式（Arena）AVL，指针式自平衡树在 Rust 中样板极重。

## 红黑树：五条规则与修复直觉

红黑树规则：① 节点非红即黑；② 根是黑；③ 叶子（NIL 哨兵）是黑；④ 红节点的子必黑（无连续红）；⑤ 任一节点到其所有 NIL 的黑高相同。由此推出**最长红黑交替路径 ≤ 2× 最短全黑路径**，树高被压在 `2 log₂(n+1)`。

插入修复的本质（新节点必染**红**，因为染红只违反规则④、染黑会违反规则⑤且更难修）：

| 情形 | 叔叔颜色 | 动作 | 效果 |
|------|---------|------|------|
| 1 | 红（父红冲突） | 父叔染黑、祖父染红，冲突上移到祖父 | 黑高不变，只传播颜色 |
| 2 | 黑 + 内侧 | 对父旋转（LR→LL / RL→RR），转为情形 3 | 结构归位 |
| 3 | 黑 + 外侧 | 父染黑、祖父染红，对祖父旋转 | 一次终结 |

删除修复（删黑节点才触发）用 `x` 表示「黑色亏空」的替身，靠兄弟颜色 + 兄弟孩子颜色四种旋转/染色组合把亏空上移或借色补齐，最多 3 次旋转。细节长而对称，掌握「插入修颜色靠传播、删除修黑高靠借色」的直觉比背代码更有价值；工程请直接使用 `TreeMap`（Java）/ `BTreeMap`（Rust）/ `std::map`（C++）。

## AVL vs 红黑：怎么选

| 维度 | AVL | 红黑树 |
|------|-----|--------|
| 平衡强度 | 严格（高差 ≤1） | 近似（≤2 倍） |
| 树高/查找 | 更矮更快 | 略高 |
| 插入旋转 | ≤2 次 | ≤2 次 |
| 删除旋转 | 最坏 O(log n) 次逐层修复 | ≤3 次 |
| 每节点开销 | 存高度（或 bf） | 存 1 bit 颜色 |
| 适合 | 读多写少 | 通用、写多（工业默认） |

## 常见陷阱

- 旋转后**必须先更新旧根 A 的高度再更新新根 B**，顺序反了会带着过期高度继续平衡，产生「看似平衡实则失衡」的隐 bug。
- AVL 删除沿路径每层都可能再失衡（旋转次数 O(log n)），这是它写代价高于红黑的真正原因，不在插入。
- 红黑树「双黑」的替身节点在概念上可能不在树中（被删黑节点的孙子位置），实现常用 NIL 哨兵或变色技巧处理，别用 null 直接推演。
- 旋转不改变 BST 中序序列——检验实现是否正确的最快方法就是中序输出是否仍有序。
- 语言标准库的「TreeMap」实现细节不同：Java `TreeMap` 是红黑、Rust `BTreeMap` 是 **B 树**（阶 6），迁移代码时性能直觉不能照搬。

# 总结

- AVL 以严格高度平衡换更快查询，红黑以颜色规则换更少的再平衡动作——「读多写少选 AVL，通用写多选红黑」；
- 两者都只靠 O(1) 次旋转/局部变色完成修复，代价是每节点的 bf/颜色维护，本质是把「重排」摊到每次写入；
- 内存自平衡树之上还有磁盘友好的 [B/B+ 树](./050.B树与B+树.md) 与以随机换平衡的[跳表](../01.基础数据结构/040.跳表.md)，三者构成工业索引结构的三角。
