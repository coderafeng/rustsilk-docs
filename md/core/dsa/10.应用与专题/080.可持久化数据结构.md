# 概述

普通数组改一个位置就覆盖旧值，旧版本荡然无存。**可持久化数据结构（Persistent Data Structure）** 反其道：每次修改**不破坏旧版本**，而是产出一个新版本，且新旧版本**共享绝大部分节点**——只把「从根到被改点」这条路径上的节点复制一份，其余子树原样引用。于是「查询任意历史版本」「版本回滚」「撤销/重做」「函数式状态」都以 \(O(\log n)\) 的代价自然达成。它是**函数式编程的落地基石**（Clojure/Haskell 的持久化集合），也是竞赛与系统中「区间第 k 小」「版本化配置」「快照隔离」的核心武器。代表结构：**可持久化线段树（Chairman Tree / 持久化段树）** 与 **完全持久化平衡 BST（Okasaki 红黑树）**。

- 所属章节：[000.应用与专题概述](./000.应用与专题概述.md)
- 时间复杂度：单点更新/查询 \(O(\log n)\)（只复制一条根到叶路径）；前缀/区间查询 \(O(\log n)\)
- 空间复杂度：每次更新 \(O(\log n)\) 新节点（路径复制 + 共享），\(m\) 次修改共 \(O(n + m\log n)\)
- 应用场景：区间第 k 小/区间历史版本查询、数据库快照与 MVCC、编辑器撤销栈、函数式 Map/Set、版本化配置、交易前状态回溯
- 关联：建立在 [03.树结构](../03.树结构/000.树结构概述.md) 的线段树/平衡树之上；哈希数组映射 trie（HAMT）呼应 [01.基础数据结构/090.哈希表应用](../01.基础数据结构/090.哈希表应用.md)

# 详解

## 核心机制：结构共享（path copying）

关键不变式：**任何节点一旦创建就不再修改**（immutability）。更新时不是原地改，而是**新建一条从根到目标叶的指针链**，沿途每个新节点复制旧节点的字段、只把指向「被更新子树」的那根子指针换成新版本，另一根子指针**照旧指向老节点**。因为老节点永不改动，多个版本安全共享。

- 线段树深度 \(\lceil\log_2 n\rceil\) → 一次单点更新新建 \(O(\log n)\) 节点。
- 区间更新若要持久化则更贵（懒标记也要复制），一般用**可持久化平衡树 + split/merge（treap）** 处理区间版本。

## 可持久化线段树：静态区间第 k 小

最著名的应用：给序列 \(a_1..a_n\)，回答多次「区间 \([l,r]\) 第 k 小」。做法是把线段树建成**前缀值域树**：第 \(i\) 个版本 \(T_i\) 是在 \(T_{i-1}\) 基础上，把「值 \(a_i\)」在值域上 +1（可持久化插入）。于是「区间 \([l,r]\) 里落在值域 \([L,mid]\) 的元素个数」= \(T_r\) 与 \(T_{l-1}\) 两棵树对应节点计数之差。查询第 k 小时**同时下钻 \(T_r, T_{l-1}\) 两棵树**，用差值判断第 k 小落在值域左半还是右半，\(O(\log V)\) 定位。

```java [Java]
// 静态区间第 k 小：主席树。值域 [1, MAXV]，node 记录左右子 + count
static final int MAXN = 100005, MAXV = 100000;
static int[] lc = new int[MAXN * 20], rc = new int[MAXN * 20], cnt = new int[MAXN * 20];
static int[] root = new int[MAXN];
static int tot = 0;
static int update(int prev, int l, int r, int pos) {   // 在 prev 版本上把 pos 计数 +1
    int cur = ++tot;
    lc[cur] = lc[prev]; rc[cur] = rc[prev]; cnt[cur] = cnt[prev] + 1;  // 复制旧节点
    if (l != r) {
        int mid = (l + r) >> 1;
        if (pos <= mid) lc[cur] = update(lc[prev], l, mid, pos);       // 只更新一侧，另一侧共享
        else rc[cur] = update(rc[prev], mid + 1, r, pos);
    }
    return cur;
}
static int queryKth(int u, int v, int l, int r, int k) { // u=root[l-1], v=root[r]
    if (l == r) return l;
    int mid = (l + r) >> 1;
    int leftCount = cnt[lc[v]] - cnt[lc[u]];             // 区间落在左值域的个数
    if (k <= leftCount) return queryKth(lc[u], lc[v], l, mid, k);
    else return queryKth(rc[u], rc[v], mid + 1, r, k - leftCount);
}
```

```rust [Rust]
// 同一棵主席树，用 Vec 存池；u=root[l-1], v=root[r]
#[derive(Default, Clone)]
struct Node { lc: usize, rc: usize, cnt: i32 }
struct PresidentTree { pool: Vec<Node> }
impl PresidentTree {
    fn update(&mut self, prev: usize, l: i32, r: i32, pos: i32) -> usize {
        let base = self.pool[prev].clone();
        let cur = self.pool.len();
        self.pool.push(Node { lc: base.lc, rc: base.rc, cnt: base.cnt + 1 }); // 复制
        if l != r {
            let mid = (l + r) / 2;
            if pos <= mid {
                let nlc = self.update(base.lc, l, mid, pos);
                self.pool[cur].lc = nlc;                                    // 左新右共享
            } else {
                let nrc = self.update(base.rc, mid + 1, r, pos);
                self.pool[cur].rc = nrc;
            }
        }
        cur
    }
}
```

```typescript [TypeScript]
// 池化数组；下标即节点 id，0 为空节点哨兵
const lc: number[] = [0], rc: number[] = [0], cnt: number[] = [0];
function update(prev: number, l: number, r: number, pos: number): number {
  const cur = lc.length;                                   // 新节点
  lc.push(lc[prev]); rc.push(rc[prev]); cnt.push(cnt[prev] + 1);  // 复制旧节点
  if (l !== r) {
    const mid = (l + r) >> 1;
    if (pos <= mid) lc[cur] = update(lc[prev], l, mid, pos);   // 只换一侧指针
    else rc[cur] = update(rc[prev], mid + 1, r, pos);
  }
  return cur;
}
```

```python [Python]
# 字典池版；root[i] 为第 i 个前缀版本
lc, rc, cnt = {0: 0}, {0: 0}, {0: 0}
tot = 0

def update(prev, l, r, pos):
    global tot
    tot += 1
    cur = tot
    lc[cur], rc[cur], cnt[cur] = lc[prev], rc[prev], cnt[prev] + 1   # 复制
    if l != r:
        mid = (l + r) >> 1
        if pos <= mid:
            lc[cur] = update(lc[prev], l, mid, pos)                 # 左更新右共享
        else:
            rc[cur] = update(rc[prev], mid + 1, r, pos)
    return cur

def query_kth(u, v, l, r, k):
    if l == r:
        return l
    mid = (l + r) >> 1
    left = cnt[lc[v]] - cnt[lc[u]]
    return query_kth(lc[u], lc[v], l, mid, k) if k <= left \
        else query_kth(rc[u], rc[v], mid + 1, r, k - left)
```

## 全持久化 vs 部分持久化

- **部分持久化（partial）**：只查询**最新版本**或**任意历史版本但仅只读**——路径复制即可（本篇线段树即属此类）。
- **全持久化（fully）**：允许从任意旧版本分叉出多条修改链——仍靠结构共享，只是版本形成一棵「版本树」而非「版本链」；Okasaki/Avi-Wigderson 的持久化红黑树、Schmidt 的持久化跳表达成此能力。
- **临时/半持久化**：为高频修改提供 \(O(1)\) 快照 + 撤销（delta 记录），牺牲随机历史访问换更低常数。

## 更广的持久化家族

- **HAMT（哈希数组映射 trie）**：Clojure/Scala 持久化 Map/Set 的底——32 叉位分层 trie + 位图压缩，插入 \(O(\log_{32} n)\) 且结构共享。
- **持久化平衡树/BST**：Okasaki 纯函数红黑树（插入可能「破坏」局部黑高，靠 `balance` 复修），完全无 mutation。
- **持久化并查集**：用「可持久化数组（段树）维护 fa/rank」实现带版本回滚的并查集（离线可 undo，配合 DSU-on-tree）。
- **持久化队列/栈**：纯函数双端队列（RealtimeDeque）、Conchon-Pachigi 持久化队列（均摊 \(O(1)\)）。
- **Copy-on-write 系统应用**：Git blob、文件快照（ZFS/btrfs）、MVCC 数据库（Postgres 元组、InnoDB undo）、React 不可变 state、Redux store——都是「不改旧的、造新的、共享不变部分」这一思想在不同层次的化身。

## 常见陷阱

::: danger 陷阱清单
1. **误改了「不可变」节点**：一旦某个共享节点被就地修改，所有引用它的旧版本一起被污染，历史全乱——持久化的生命线是**严格 immutability**，语言层面用 const/不可变类型兜底。
2. **节点池没开够**：主席树节点数 \(\approx n\log V\)，数组开小了越界（Java/Rust 直接 panic/UB）；先估 \(N\cdot\lceil\log_2 V\rceil + Q\) 再开池。
3. **递归更新爆栈**：\(n\) 极大时 \(\log n\) 虽浅，但若写成非路径复制的暴力递归或值域过大（\(V=10^9\) 未离散化）会 TLE/MLE——值域先**离散化**到 \([1,n]\)。
4. **忘存 root 数组**：可持久化的全部意义在「每个版本一个根」；漏存根 = 丢版本 = 退化成普通段树还多花空间。
5. **共享内存的回收错觉**：GC 语言里旧版本只要还被引用就不能回收；大量短命版本会造成内存膨胀——需要引用计数/GC 调优或定期压缩（版本快照归档）。
6. **把它当免费的 undo**：全持久化随机访问旧版本是 \(O(\log n)\)，不是 \(O(1)\)；若只需「撤销上一步」，用栈存 delta 更省更快，别上重型持久化结构。
:::

# 总结

- 可持久化 = 「不改旧的、复制一条路径、共享其余」：靠 immutability + 结构共享，让每次修改只花 \(O(\log n)\) 就产出一个能独立查询的完整新版本。
- 可持久化线段树（主席树）是招牌：前缀值域版本 + 两版本节点计数差，静态区间第 k 小 \(O(\log V)\) 求解；全持久化平衡树/HAMT 把能力扩到任意版本分叉与函数式 Map/Set。
- 它是「不可变 + 共享」范式的结构化表达，Git blob、ZFS 快照、MVCC、React state 都是同一哲学在不同层次的翻版——理解它就理解了「快照隔离」的算法内核。
- 底座是 [03.树结构](../03.树结构/000.树结构概述.md) 的线段树与平衡 BST；离散化技巧见 [02.基础算法](../02.基础算法/000.基础算法概述.md)；与 [090.并发数据结构](./090.并发数据结构.md) 殊途同归——**不可变数据天然无竞态**，持久化结构常直接作为并发读的安全快照，无需加锁。
