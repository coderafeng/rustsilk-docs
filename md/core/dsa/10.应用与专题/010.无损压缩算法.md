# 概述

无损压缩的契约是「一个比特都不能差」：解压后必须逐字节还原。整个家族靠两件事吃饭——**消灭统计冗余**（常见符号用短码：哈夫曼、算术编码）与**消灭结构冗余**（重复出现的内容用「指针」代替：LZ77 的「距离+长度」、LZ78/LZW 的「字典号」）；**游程编码**则是两件事的最小特例：「连续相同」本身就是最直白的重复。ZIP 把 LZ77 + 哈夫曼串成 DEFLATE，GIF/PNG 上游挂着 RLE 与滤波，`zstd` 至今统治着备份与网络传输的性价比区——三种原语的不同排列组合，就是半个压缩工业史。

**本篇收录**：**哈夫曼编码**、**LZ77/LZ78（含 LZW）**、**游程编码（RLE）**

- 所属章节：[000.应用与专题概述](./000.应用与专题概述.md)
- 时间复杂度：哈夫曼建树 \(O(n \log n)\)（堆）；LZ77 朴素滑窗匹配 \(O(n \cdot w)\)（后缀结构可至 \(O(n \log n)\)）；LZW 线性 \(O(n)\)；RLE 线性 \(O(n)\)
- 空间复杂度：哈夫曼码表 \(O(n)\)（需随流传输或用静态表）；LZ77 窗口（DEFLATE 为 32KB）；LZW 字典（至多 \(2^{bits}\) 项）
- 应用场景：ZIP/GZIP/PNG（DEFLATE）、JPEG/GIF（RLE 环节）、数据库页压缩（Snappy/LZ4）、对象存储与备份（zstd）、协议负载（HTTP Content-Encoding）
- 信息论底线：Shannon 熵 \(H = -\sum p_i \log_2 p_i\) 是无损压缩的极限——哈夫曼平均码长落在 \([H, H+1)\)；有损压缩请移步 [020.有损压缩原理](./020.有损压缩原理.md)

2. 反复合并两个最小：先两两并 1+1 → 节点 2，层层上推，最终根为 14。
3. 左 0 右 1 赋码：a 得 2-bit 码、t/s/o 得 3-bit、其余 4-bit。
4. 平均码长 \(= (3\times2 + 3\times3 + 6\times4)/14 \approx 3.36\) bit/符号 → 全文 \(14 \times 3.36 \approx 47\) bit；对比定长 4-bit 码需 56 bit、ASCII 需 112 bit——**熵越低（分布越偏）省得越多**。

**动画 2：RLE 与 LZW 各压一句**

1. RLE：`WWWWWWWWWWWWBWWWWWWWWWWWWBBB`（28 字符）→ `12W1B12W3B`（10 字符）；但 `abcabc` 压成 `1a1b1c1a1b1c`（12 字符）反而膨胀——**RLE 只吃重复，不吃周期**。
2. LZW（`TOBEORNOTTOBEORTOBEORNOT`，标准演示串）：单字符先入典（T=84、O=79、B=66、E=69、R=82、N=78），随后逐格输出 `84 79 66 69 78 79 84 79 66`（TOBEORNOT），同时字典长出 TO=256、BE=257、OR=258、NO=259、OT=260、TTO…；第二遍 `TOBEORNOT` 几乎整段命中字典号，末尾 `TOBEORNOT` 再复用——8 位输入流最终输出约 16 个码字，压缩比 \(\approx 24/16 = 1.5\)，且**边压边建典，解压端可同步重建**。

# 详解

## 哈夫曼：贪心最优前缀码

自底向上反复合并频次最小的两棵树（贪心选择性质可用交换论证证明最优），得到带权路径最短的前缀码树——任一码字都不是另一码字的前缀，故解码无需分隔符。与 [04.核心算法思想/080.贪心算法](../04.核心算法思想/080.贪心算法.md) 里的范例同源，本篇给出**完整可跑的编解码**（解码端凭同一棵树走位还原）：

```java [Java]
// 编码：建树 → 走位生成码表
public static Map<Character, String> huffmanCodes(String text) {
    Map<Character, Integer> freq = new HashMap<>();
    for (char c : text.toCharArray()) freq.merge(c, 1, Integer::sum);
    PriorityQueue<Node> pq = new PriorityQueue<>(Comparator.comparingInt(n -> n.w));
    freq.forEach((c, w) -> pq.add(new Node(c, w, null, null)));
    if (pq.size() == 1) pq.add(new Node('\0', 0, null, null));      // 单符号边界
    while (pq.size() > 1) {
        Node a = pq.poll(), b = pq.poll();
        pq.add(new Node('\0', a.w + b.w, a, b));
    }
    Map<Character, String> codes = new HashMap<>();
    walk(pq.peek(), "", codes);
    return codes;
}
static void walk(Node n, String path, Map<Character, String> codes) {
    if (n.left == null && n.right == null) { if (n.c != '\0') codes.put(n.c, path.isEmpty() ? "0" : path); return; }
    walk(n.left, path + "0", codes);
    walk(n.right, path + "1", codes);
}
record Node(char c, int w, Node left, Node right) {}
// "data compression" → a:"01" t:"101" s:"000" o:"001" …（同频次下形态可交换，长度谱不变）
```

```rust [Rust]
use std::collections::{BinaryHeap, HashMap};
use std::cmp::Reverse;

#[derive(Debug)]
struct Node { w: u32, c: Option<char>, l: Option<Box<Node>>, r: Option<Box<Node>> }

pub fn huffman_codes(text: &str) -> HashMap<char, String> {
    let mut freq: HashMap<char, u32> = HashMap::new();
    for c in text.chars() { *freq.entry(c).or_insert(0) += 1; }
    let mut pq: BinaryHeap<Reverse<(u32, usize)>> = BinaryHeap::new();
    let mut nodes: Vec<Node> = freq.into_iter()
        .map(|(c, w)| { pq.push(Reverse((w, nodes.len())));
                        Node { w, c: Some(c), l: None, r: None } })
        .collect();
    while pq.len() > 1 {
        let Reverse((w1, i1)) = pq.pop().unwrap();
        let Reverse((w2, i2)) = pq.pop().unwrap();
        let (l, r) = (nodes[i1].clone_box(), nodes[i2].clone_box());
        nodes.push(Node { w: w1 + w2, c: None, l: Some(l), r: Some(r) });
        pq.push(Reverse((w1 + w2, nodes.len() - 1)));
    }
    let mut codes = HashMap::new();
    if let Some(root) = nodes.last() { walk(root, String::new(), &mut codes); }
    codes
}
// clone_box 为 Node 的深拷贝辅助；walk 同 Java 版递归赋码
```

```typescript [TypeScript]
function huffmanCodes(text: string): Map<string, string> {
  const freq = new Map<string, number>();
  for (const c of text) freq.set(c, (freq.get(c) ?? 0) + 1);
  type Node = { w: number; c?: string; l?: Node; r?: Node };
  const pq: Node[] = [...freq].map(([c, w]) => ({ w, c }));
  const push = (n: Node) => { pq.push(n); pq.sort((x, y) => x.w - y.w); };  // 教学小堆
  while (pq.length > 1) {
    const a = pq.shift()!, b = pq.shift()!;
    push({ w: a.w + b.w, l: a, r: b });
  }
  const codes = new Map<string, string>();
  const walk = (n: Node, path: string) => {
    if (!n.l && !n.r) { if (n.c) codes.set(n.c, path || "0"); return; }
    walk(n.l!, path + "0"); walk(n.r!, path + "1");
  };
  walk(pq[0], "");
  return codes;
}
```

```python [Python]
import heapq
from collections import Counter

def huffman_codes(text):
    if not text:
        return {}
    heap = [[w, (c, "")] for c, w in Counter(text).items()]
    heapq.heapify(heap)
    while len(heap) > 1:                                  # 反复合并最小两棵
        w1, t1 = heapq.heappop(heap)
        w2, t2 = heapq.heappop(heap)
        heapq.heappush(heap, [w1 + w2, (None, (t1, t2))])
    codes = {}
    def walk(node, path):
        c, kids = node
        if c is not None:
            codes[c] = path or "0"
            return
        walk(kids[0], path + "0"); walk(kids[1], path + "1")
    walk(heap[0][1], "")
    return codes
```

## LZ77：滑窗 + 回溯引用

LZ77 不建字典，而是盯着**最近 32KB 的滑动窗口**：当前位置能匹配窗口里的最长串，就输出三元组 \((距离, 长度, 下一字符)\)；匹配不到就直出字面量。「距离+长度」本质是**把重复复制变成一条指针**——DEFLATE 在此基础上把三元组与字面量统一送进哈夫曼（外加「距离也分桶变长编码」的 length/distance code）。LZ4/Snappy/zstd 全是同族提速/提比变体（zstd 再加有限状态熵编码 FSE）。

```java [Java]
public static List<int[]> lz77(String s, int window, int maxLen) {
    List<int[]> out = new ArrayList<>();
    int i = 0;
    while (i < s.length()) {
        int bestLen = 0, bestDist = 0;
        int start = Math.max(0, i - window);
        for (int j = start; j < i; j++) {                 // 窗口内逐起点试匹配
            int len = 0;
            while (len < maxLen && i + len < s.length()
                    && s.charAt(j + len) == s.charAt(i + len)) len++;  // j+len 可越 i（重叠复制）
            if (len > bestLen) { bestLen = len; bestDist = i - j; }
        }
        if (bestLen >= 3) {                               // 短于 3 不值得编码
            out.add(new int[]{bestDist, bestLen, i + bestLen < s.length() ? s.charAt(i + bestLen) : 0});
            i += bestLen + 1;
        } else {
            out.add(new int[]{0, 0, s.charAt(i)});        // 字面量
            i += 1;
        }
    }
    return out;
}
// "abababcd"（win=4）→ (0,0,'a') (0,0,'b') (2,4,'d') —— 长度 4 的匹配靠重叠自复制实现
```

```rust [Rust]
pub fn lz77(s: &[u8], window: usize, max_len: usize) -> Vec<(usize, usize, u8)> {
    let mut out = Vec::new();
    let mut i = 0;
    while i < s.len() {
        let mut best = (0usize, 0usize);                   // (len, dist)
        let start = i.saturating_sub(window);
        for j in start..i {
            let mut len = 0;
            while len < max_len && i + len < s.len()
                && s[j + len] == s[i + len] { len += 1; }  // 允许重叠：j+len 可越过 i
            if len > best.0 { best = (len, i - j); }
        }
        if best.0 >= 3 {
            let next = *s.get(i + best.0).unwrap_or(&0);
            out.push((best.1, best.0, next));
            i += best.0 + 1;
        } else {
            out.push((0, 0, s[i]));
            i += 1;
        }
    }
    out
}
```

def lz77(data: bytes, window=32768, max_len=258):
    out, i = [], 0
    while i < len(data):
        best_len, best_dist = 0, 0
        for j in range(max(0, i - window), i):            # 窗口内找最长匹配
            length = 0
            while (length < max_len and i + length < len(data)
                   and data[j + length] == data[i + length]):
                length += 1                               # 重叠自复制允许 j+length > i

            i += best_len + 1
        else:
            out.append((0, 0, data[i])); i += 1
    return out

## LZ78 / LZW：自适应字典流

LZ78 把「已见前缀」实时登记进字典，每个 token 输出「字典号 + 新字符」；**LZW** 是它的工程变体（token 只剩字典号，字典在压缩端与解压端**各自同步重建**，无需传输）。GIF、旧版 UNIX `compress`、PDF 流都用过它。要点：码宽随字典增长逐级加位（8→9→12 bit），字典满后按策略清典复位（GIF 的最小代码尺寸规则）。

```java [Java]
public static List<Integer> lzw(String s) {
    Map<String, Integer> dict = new HashMap<>();
    for (int c = 0; c < 256; c++) dict.put("" + (char) c, c);   // 单字符打底
    int next = 256;
    List<Integer> codes = new ArrayList<>();
    String w = "";
    for (char c : s.toCharArray()) {
        if (dict.containsKey(w + c)) { w += c; }                // 字典里有：继续吃
        else { codes.add(dict.get(w)); dict.put(w + c, next++); w = "" + c; }  // 登记新词
    }
    if (!w.isEmpty()) codes.add(dict.get(w));
    return codes;
}
```

```rust [Rust]
pub fn lzw(data: &[u8]) -> Vec<u32> {
    let mut dict: std::collections::HashMap<Vec<u8>, u32> = std::collections::HashMap::new();
    for i in 0..256u32 { dict.insert(vec![i as u8], i); }
    let mut next = 256u32;
    let mut codes = Vec::new();
    let mut w: Vec<u8> = Vec::new();
    for &c in data {
        let mut wc = w.clone(); wc.push(c);
        if dict.contains_key(&wc) { w = wc; }
        else {
            codes.push(dict[&w]);
            dict.insert(wc, next); next += 1;                   // 新词入典
            w = vec![c];
        }
    }
    if !w.is_empty() { codes.push(dict[&w]); }
    codes
}
```

}

## RLE：最古老的「重复折叠」

把「连续相同」替换为 `(值, 计数)`。真实部署都是**混合方案**：BMP/TIFF 变体、PackPNG 的 `Paeth + RLE`、JPEG 熵编码层的 `(runLength, size) + value`、以及一切「计数也变长编码」的祖先。它常作为**二级压缩**：先由预测/变换把数据推成大片零，再让 RLE 大杀四方——PNG 滤波器与 DCT 置零系数都是这个套路。

```python [Python]
def rle(data: bytes) -> bytes:
    '''(计数, 值) 对；计数 >255 切段——单测：rle(b"aaab") == b"\x03a\x01b"'''
    out = bytearray()
    i = 0
    while i < len(data):
        j = i
        while j < len(data) and data[j] == data[i] and j - i < 255:
            j += 1
        out.append(j - i); out.append(data[i])
        i = j
    return bytes(out)
```

## 常见陷阱

::: danger 陷阱清单
1. **压缩可能变大**：随机数据/已压缩数据再压必膨胀（DEFLATE 加约 0.03% 头 + 块开销）——所有存储引擎都要带「压不动就存原文」的逃生阀（zstd `--format=no-dictionary` 之外还有 Parquet/Snappy 的 fallback 标志）。
2. **哈夫曼码表忘随流传输**：非自适应静态码表必须前置（DEFLATE 的 dynamic block header 花几十到几百字节存树）；或改用「按块重建」的自适应方案——解码端没有树就是天书。
3. **单符号文本除零**：全是同一字符时堆里只有一棵树——上面代码特意补哨兵并赋码 `"0"`；LZW 满典同理需复位策略。
4. **LZW 专利地雷**：Unisys 对 GIF LZW 的专利维权曾让整个行业转向 PNG——选格式时顺手查一遍专利史不丢人。
5. **解压缩炸弹**：0.1MB 的 zip 解出 4.5TB（嵌套 deflate「42.zip」）——凡接受外部压缩流必须限解压配额与压缩比。
6. **忽略字符集与边界**：对 UTF-8 字节流做哈夫曼/LZW 完全合法，但若按「字符」建典则必须保证解码端同码页；跨多字节边界输出的分块压缩还可能破坏编码完整性（LZ4 的块模式因此附带校验和）。
:::

# 总结

- 三条原语、一个灵魂：**哈夫曼吃统计冗余、LZ 家族吃结构冗余、RLE 吃最直白的连续重复**；DEFLATE = LZ77 + 哈夫曼，zstd = 更聪明的匹配器 + FSE——现代格式只是排列组合与工程打磨。
- LZ77 的「重叠自复制」与 LZW 的「双端同步建典」是两处最精巧的设计：前者让一条指针复制出指数级长度，后者让字典本身免传输。
- 熵是天花板：数据先「变整齐」（预测、变换、移动）再压缩，比换更强的熵编码收益更大——bzip2 的 BWT 正是「先重排、再 RLE/哈夫曼」的教科书。
- 有损世界另有一套取舍（感知模型 + 变换量化），见 [020.有损压缩原理](./020.有损压缩原理.md)；哈夫曼的贪心证明在 [04.核心算法思想/080.贪心算法](../04.核心算法思想/080.贪心算法.md)，优先队列建树在 [03.树结构](../03.树结构/000.树结构概述.md)。
