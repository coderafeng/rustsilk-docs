# 概述

字符串（String）是由字符组成的有限序列，是**数组的特化**——元素类型为字符。它的工程重要性在于：几乎所有输入/输出、协议、文本处理都以它为载体，而其内部表示（编码、是否可变、内存布局）直接决定拼接、查找、比较等操作的性能。

- 时间复杂度（以长度为 n 的字符串为例）：

  | 操作 | 复杂度 | 说明 |
  |------|:------:|------|
  | 按下标取字符 | O(1)（定长编码）/ O(n)（变长编码如 UTF-8） | 变长编码需从头累加字节 |
  | 取长度 | O(1) | 现代实现都缓存长度（如 SDS） |
  | 拼接 | O(n + m) | 不可变字符串每次生成新对象 |
  | 子串查找 | O(n·m) 朴素 | KMP 等可优化（见 [06.字符串与数论](../06.字符串与数论/000.字符串与数论概述.md)） |
  | 比较 | O(n) | 逐字符 |

- 空间复杂度：O(n)，变长编码（UTF-8）按实际字节存储更省，定长（UTF-32）按字符数固定但浪费。
- 应用场景：文本与序列化、协议字段、URL/文件名、模式匹配与前缀检索（配合 [03.树结构/060.字典树Trie](../03.树结构/060.字典树Trie.md)）；底层表示如 Redis 的 **SDS**、Java 的**不可变 String**。

1. 初始 `s = "hello"`，指向堆中一块只读字符数组；
2. 执行 `s = s + " world"`，**不修改原数组**，而是新建一块 `"hello world"` 的数组；
3. 旧数组失去引用，等待回收；
4. 循环拼接 k 次 → 每轮复制前缀，总拷贝量 1+2+…+k = O(k²)；
5. 改用缓冲区（`StringBuilder`/`join`）后，各片段先入可变缓冲，最后一次性生成，回到 O(n)。

# 详解

## 编码与随机访问

ASCII/UTF-16/UTF-32 是定宽编码，`s[i]` 可 O(1) 直达；**UTF-8 是变宽编码**（1–4 字节/码点），按「码点下标」访问需从头扫描字节，退化为 O(n)。Python 3 的 `str` 采用「紧凑可变形 Unicode」按最大码点选 1/2/4 字节保证 O(1) 索引；Rust 的 `String` 出于安全**禁止**按下标取字符，只能迭代 `char`。

## 不可变性与缓冲区

不可变字符串可安全共享、可缓存 hash、可作为 map 键，代价是拼接昂贵。批量拼接务必用可变缓冲：

::: code-group
```java [Java]
String s = "hello";
s = s + " world";                 // 不可变：生成新对象，循环拼接 O(n²)
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.append("ab"); // 可变缓冲，批量拼接用这个
String t = sb.toString();
```
```rust [Rust]
// String 可变且堆分配，&str 是不可变视图；push_str 均摊 O(1)
let mut s = String::from("hello");
s.push_str(" world");
println!("{s}, len={}", s.len()); // 注意 len 是字节数，非字符数
for ch in "你好".chars() { print!("{ch} "); } // 按码点迭代，不能按索引取
```
```typescript [TypeScript]
// 批量拼接优先 join，避免 += 产生的中间串
const parts: string[] = [];
for (let i = 0; i < 1000; i++) parts.push("ab");
console.log(parts.join("").length);
```
```python [Python]
# str 不可变；批量拼接用 ''.join 而非 += （后者 O(n²)）
parts = []
for _ in range(1000):
    parts.append("ab")
s = "".join(parts)
print(len(s), s[:5])
```
:::

## 常见陷阱

- **长度歧义**：字节数 ≠ 字符数 ≠ 码点数（尤其中文/emoji），截断字符串按字节切会切碎多字节字符。
- **循环内 `+=` 拼接**：不可变语言下是 O(n²) 热点。
- **子串引用原内存**：Java 早期 `substring` 共享底层数组会造成"一个字符拖住整块大字符串"的内存泄漏。

# 总结

- 字符串是字符的线性表，**性能由编码（定宽/变宽）与可变性**共同决定；
- 定宽编码随机访问 O(1)、变长更省空间但索引变慢；
- 批量拼接一律走可变缓冲（`StringBuilder`/`push_str`/`join`），不要在循环里对不可变串 `+=`。
