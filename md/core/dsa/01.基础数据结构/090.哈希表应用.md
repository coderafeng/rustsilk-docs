# 概述

哈希表（Hash Table / Map / Set）用哈希函数把**键**直接映射到**值所在的桶**，实现平均 O(1) 的增删查——是"按键找值"这一最高频需求的默认答案。本篇聚焦它的应用形态：`HashMap`、`HashSet` 与经典综合题 **LRU 缓存**。

- 时间复杂度：

  | 操作 | 平均 | 最坏 |
  |------|:----:|:----:|
  | 查找 / 插入 / 删除 | O(1) | O(n)（全部冲突或树化前） |
  | 遍历 | O(n) | 与桶数同阶 |
  | 有序遍历 | 不支持 | 需换 [跳表](./040.跳表.md)/平衡树 |

- 空间复杂度：O(n)，且为压低 α 常预留冗余桶（省时间费空间）。
- 应用场景：计数/去重、索引与字典、缓存、 JOIN、记忆化、任何"按 key 存取"的地方。

1. 哈希表负责 key → 链表节点的 O(1) 定位；
2. 双向链表按"最近使用"排序：**头部最新、尾部最旧**；
3. 命中某 key：把它的链表节点**移到头部**；
4. 新 key 且容量满：**删除尾部节点**并同步从哈希表删其 key。

# 详解

## 选型：HashMap vs 有序结构

哈希表快但**无序**；需要范围查询/有序遍历就要换跳表或红黑树（O(log n)）。这是 Java `HashMap` 与 `TreeMap`、Redis 字典与 ZSet 的根本分野。

## 手写 LRU（面试必考）

LRU（Least Recently Used）用"哈希表 + 双向链表"同时满足 **O(1) 查找** 与 **O(1) 淘汰最久未用**：

::: code-group
```java [Java]
// 偷懒版：LinkedHashMap 开 accessOrder=true，覆写 removeEldestEntry 即 LRU
class LRUCache extends java.util.LinkedHashMap<Integer, Integer> {
    private final int cap;
    LRUCache(int cap) { super(cap, 0.75f, true); this.cap = cap; }
    @Override protected boolean removeEldestEntry(java.util.Map.Entry<Integer,Integer> e) {
        return size() > cap;
    }
}
```
```rust [Rust]
// 标准库无 LRU；手写用 HashMap<i32, Node> + Vec/双向链表维护使用序
// 生态里 lru crate 提供 get/put，命中即移到 MRU 端
use std::collections::HashMap;
struct Lru { map: HashMap<i32, i32>, order: Vec<i32>, cap: usize }
// get: 命中则把 key 移到 order 末尾；put: 超容量移除 order 头部
```
```python [Python]
from collections import OrderedDict
class LRUCache:
    def __init__(self, cap): self.cap, self.d = cap, OrderedDict()
    def get(self, k):
        if k not in self.d: return -1
        self.d.move_to_end(k)          # 命中移到最近使用端
        return self.d[k]
    def put(self, k, v):
        if k in self.d: self.d.move_to_end(k)
        self.d[k] = v
        if len(self.d) > self.cap: self.d.popitem(last=False)  # 淘汰最旧
```
```typescript [TypeScript]
// Map 保持插入序：用 delete+set 模拟“移到最近”，尾部即最久未用
class LRUCache {
    private m = new Map<number, number>();
    constructor(private cap: number) {}
    get(k: number) { const v = this.m.get(k); if (v === undefined) return -1;
        this.m.delete(k); this.m.set(k, v); return v; }
    put(k: number, v: number) { if (this.m.has(k)) this.m.delete(k);
        this.m.set(k, v); if (this.m.size > this.cap)
            this.m.delete(this.m.keys().next().value!); }
}
```

## 使用要点

- **key 必须稳定可哈希**：Java 里可变对象作键，`hashCode` 变了会"存进去取不出"——用 `record`/`final` 字段或不可变类型。
- **预分配容量**：已知规模时给初始容量（Java `new HashMap<>(n*4/3+1)`）避免反复 rehash。
- **并发场景**：普通 HashMap 多线程扩容会丢数据/死循环，用 `ConcurrentHashMap`（分段/CAS）或加锁。

# 总结

- 哈希表是"按键存取"的 O(1) 默认结构，代价是**无序**与**桶冗余空间**；
- 需要有序退避到跳表/平衡树，需要"淘汰最旧"用 **HashMap + 双向链表**（LRU）；
- 生产使用盯三件事：**键不可变、预分配容量、并发换并发安全实现**。
