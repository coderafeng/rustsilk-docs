# 概述

跳表（Skip List）在**有序链表**之上叠加多层稀疏索引：高层"跳跃"跨越大段、低层精确逼近，查找时从最高层向右、走不动就下沉，从而在链表上实现 O(log n) 的有序查找。它是「用空间换时间」的典型，且实现远比红黑树简单、天然利于并发。

- 时间复杂度（n 个元素、期望层高 log n）：

  | 操作 | 期望 | 最坏 |
  |------|:----:|:----:|
  | 查找 | O(log n) | O(n)（概率极低） |
  | 插入/删除 | O(log n) | O(n) |
  | 顺序遍历 | O(n) | O(n) |

- 空间复杂度：O(n)（每节点期望 2 个指针，层高按几何分布收敛）。
- 应用场景：**Redis 有序集合 ZSet**（`跳表 + 字典`双结构）、LevelDB/RocksDB 的 memtable、ConcurrentSkipListMap 提供的并发有序映射。

1. 从**最高层最左**的 head 出发；
2. 若当前节点「本层后继 ≤ 目标」则**向右**移动；
3. 否则**下沉一层**继续比较；
4. 重复「右移 / 下沉」直到第 0 层命中或越过目标；
5. 路径呈阶梯状，总步数 = 各层右移次数 + 下沉次数 = O(log n) 期望。

**动画二：插入节点时的随机提升** <!-- dsa.assets/skip-list/skip-list-insert.gif -->

1. 先按查找流程定位各层的插入前驱；
2. 抛硬币决定新节点层高（每层以概率 p=0.5 再升一层）；
3. 逐层把新节点缝进前驱之后，更新被跨越节点的指针。

# 详解

## 为什么 Redis 用跳表而非平衡树

1. **范围查询天然**：ZSet 的核心操作是 `ZRANGEBYSCORE`，跳表第 0 层就是有序链表，定位起点后顺次后移即可，红黑树需中序回溯；
2. **实现简单**：插入/删除只改局部指针，无旋转，代码量与出错率远低于 AVL/红黑树（见 [03.树结构/040.AVL树与红黑树](../03.树结构/040.AVL树与红黑树.md)）；
3. **易于并发**：局部改动使其在 lock-free 场景（如 JDK `ConcurrentSkipListMap`）比平衡树更好做。

## 层高与复杂度的直觉

每个节点以概率 p 晋升一层，则高度期望为 log_{1/p} n；查找每层平均只需走常数步，总期望 O(log n)。p 常取 0.5（等价于二叉堆般的二分）。

## 各语言中的跳表

::: code-group
```java [Java]
// JDK 内置并发跳表：ConcurrentSkipListMap（有序 + O(log n) + 线程安全）
var map = new java.util.concurrent.ConcurrentSkipListMap<Integer, String>();
map.put(10, "a");
map.put(5, "b");
map.put(17, "c");
System.out.println(map.firstKey());        // 5
System.out.println(map.subMap(5, 17));     // 范围查询 O(log n + k)
```
```rust [Rust]
// 标准库无跳表；有序映射用 BTreeMap（红黑/ B 树系），需要跳表可用第三方 crate
use std::collections::BTreeMap;
let mut m = BTreeMap::new();
m.insert(10, "a"); m.insert(5, "b"); m.insert(17, "c");
println!("{:?}", m.keys().next());         // Some(5)
println!("{:?}", m.range(5..17).count());  // 范围统计
```
```typescript [TypeScript]
// 需自行实现；这里给出核心的“随机层高”，查找/插入按多层链表缝合即可
function randomLevel(p = 0.5, maxLevel = 16): number {
    let level = 1;
    while (Math.random() < p && level < maxLevel) level++;
    return level;
}
```
```python [Python]
# 教学实现要点：查找“能右则右、不能右则下沉”
import random

def random_level(p=0.5, max_level=16):
    level = 1
    while random.random() < p and level < max_level:
        level += 1
    return level
```
:::

## 常见陷阱

- **退化风险**：极端 unlucky 的随机数序列会拉高某节点层数，工程上设 `maxLevel` 上限兜底。
- **内存膨胀**：p 越小层高越大、指针开销越高，Redis 取 p=0.25 在层数与内存间折中。

# 总结

- 跳表 = **有序链表 + 多层随机索引**，用 O(n) 额外指针换 O(log n) 查找/插入；
- 相比平衡树**实现简单、范围查询友好、易并发**，故被 Redis ZSet 与 JDK 并发容器采用；
- 关键设计是**晋升概率 p** 与**层高上限**，二者共同决定期望复杂度与内存占用。
