# 概述

数组（Array）是用**一段连续内存**存放**同类型**元素的线性表。逻辑上线性排列，物理上首尾紧邻，因而可通过「基地址 + 下标 × 元素字节数」直接算出任一元素的地址——这是它随机访问 O(1) 的根本原因，也是它插入/删除需要整体搬移的代价来源。

- 时间复杂度：

  | 操作 | 平均 | 最坏 | 说明 |
  |------|:----:|:----:|------|
  | 按下标访问 | O(1) | O(1) | 地址直接计算，无需遍历 |
  | 按值查找 | O(n) | O(n) | 有序时可折半至 O(log n) |
  | 尾部插入 | O(1) 均摊 | O(n) | 动态数组扩容时才退化 |
  | 中间插入/删除 | O(n) | O(n) | 需搬移后续全部元素 |

- 空间复杂度：O(n)，额外开销极小（仅一个长度/容量字段），且**缓存友好**（顺序内存利于 CPU 预取）。
- 应用场景：几乎所有语言的数组/字符串底层；Java `ArrayList`、Rust `Vec`、JS `Array`、Python `list` 均为动态数组；也是哈希表桶数组、二叉堆、线段树、矩阵与图像像素、各类缓冲区（buffer）的底座。

# 详解

## 静态数组与动态数组

- **静态数组**：长度在创建时固定（如 Java `int[]`、C 数组），不能增删容量，胜在零额外开销。
- **动态数组**：封装了「容量不足即翻倍扩容 + 迁移」的数组（Java `ArrayList`、Rust `Vec`、Python `list`、JS `Array`），对外表现为长度可增长，代价是偶发的 O(n) 重分配。**翻倍**而非 +1 扩容，是把 n 次尾插的总代价压到 O(n)、单次均摊 O(1) 的关键。

## 随机访问为什么是 O(1)

连续内存 + 定长元素，使地址计算只是「乘加」两条指令，与下标无关；对比链表必须从头节点逐指针走 O(n)。这也是数组遍历比链表遍历快一个数量级的原因——顺序访问命中 CPU 缓存行。

## 插入与删除的真实代价

中间位置插入/删除要搬移其后所有元素。LeetCode 高频技巧「**逆向双指针**」（如原地移除元素、合并两个有序数组从尾部开始）正是为了把 O(n) 搬移降到不可避免的最少次数。频繁头部增删应改用 [030.链表](./030.链表.md) 或双端队列。

## 基本操作与手写动态数组

::: code-group
```java [Java]
// 定长数组 + 手写动态扩容
int[] data = new int[4];
int size = 0;

void add(int v) {
    if (size == data.length) {                 // 容量不足
        data = Arrays.copyOf(data, data.length * 2); // 翻倍并迁移，均摊 O(1)
    }
    data[size++] = v;
}

int get(int i) {
    if (i < 0 || i >= size) throw new IndexOutOfBoundsException();
    return data[i];                            // 随机访问 O(1)
}
```
```rust [Rust]
// Vec<T> 即动态数组：push 在容量不足时自动翻倍增长
fn main() {
    let mut v: Vec<i32> = Vec::new();   // capacity = 0
    v.push(1);
    v.push(2);
    println!("len={} cap={}", v.len(), v.capacity()); // 扩容后 capacity 为 4
    println!("随机访问 v[0] = {}", v[0]);             // O(1)
    v.insert(0, 9);                                    // 头部插入：整体后移 O(n)
}
```
```typescript [TypeScript]
// JS 数组是动态数组，下标访问 O(1)，push 均摊 O(1)
const arr: number[] = [10, 20, 30];
arr.push(40);          // 尾部，快
console.log(arr[2], arr.length); // 30 4
arr.unshift(5);        // 头部，需要重排索引，慢（O(n)）
```
```python [Python]
# list 底层是动态数组：append 均摊 O(1)，insert(0, x) 为 O(n)
arr = [10, 20, 30]
arr.append(40)         # 尾部，快
print(arr[2], len(arr))
arr.insert(0, 5)       # 头部，整体后移，慢
del arr[2]             # 中间删除，整体前移，慢
```
:::

## 常见陷阱

- **下标越界**：Java/C 不做边界检查会破坏内存或抛异常，循环边界 `i < n` 与 `i <= n` 是重灾区。
- **多维数组的存储序**：C/Java/Python 行优先、Fortran/MATLAB 列优先；按内存顺序遍历（行优先就按行扫）能显著减少缓存失效，矩阵运算尤甚。
- **误当哈希表**：按「值」查找数组是 O(n)，键值映射应走 [070/080/090 哈希表](./080.冲突解决策略.md)。
- **频繁头删**：动态数组头部 O(n)，改用 `VecDeque`/`ArrayDeque`/`collections.deque`。

# 总结

- 数组的核心红利是**连续内存 → O(1) 随机访问 + 缓存友好**，核心短板是**中间插删 O(n) + 定长/偶发扩容**；
- 「随机访问多、增删少」选数组，「增删频繁、不随机访问」选链表，「按键查找」选哈希表；
- 动态数组靠**翻倍扩容**把尾插均摊压到 O(1)，是 `ArrayList`/`Vec`/`list` 的通用底层策略。
