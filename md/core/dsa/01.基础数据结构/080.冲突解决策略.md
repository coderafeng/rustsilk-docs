# 概述

哈希冲突不可避免（鸽巢原理：值域小于键域）。冲突解决策略决定哈希表的性能曲线与内存形态，核心就一句：**把"撞格"的键安置到哪里、怎么再找回来**。

- 关键指标：**装填因子 α = 元素数 / 桶数**，α 越大冲突越多，需扩容（rehash）压低。
- 三大流派：链地址法、开放地址法、再哈希法，各有空间局部性与删除语义上的取舍。

**本篇收录**：链地址法（Separate Chaining）、开放地址法（线性/二次探测、双重哈希）、再哈希法

# 详解

## 链地址法 vs 开放地址法

| 维度 | 链地址法 | 开放地址法 |
|------|----------|------------|
| 删除 | 直接摘节点 | 需墓碑标记，否则破坏探测链 |
| 内存 | 指针额外开销、分散 | 无指针、连续数组、缓存友好 |
| α 上限 | 可 > 1 | 必须 < 1（越满越慢） |
| 代表 | Java HashMap、Python dict | Go map（带优化）、许多 C 实现 |

## 双重哈希与再哈希

- **双重哈希**：`H(k, i) = (h1(k) + i·h2(k)) % m`，用第二个哈希动态决定步长，几乎消除聚集；
- **再哈希法**：撞格时换用另一个哈希函数重算，而非在表内线性/二次探测，减少同义堆叠。

## Java HashMap 的演进（链化）

::: code-group
```java [Java]
// HashMap 冲突处理：桶=数组，每格挂链表；链长≥8 且表长≥64 → 转红黑树
Map<String, Integer> map = new HashMap<>();
map.put("a", 1);
// 内部：int idx = (n - 1) & hash;  (n 为 2 的幂，用与代替模)
// hash 扰动：(h = key.hashCode()) ^ (h >>> 16)
```
```rust [Rust]
// std HashMap = SwissTable（开放地址 + SIMD 元数据组），冲突走组内探测
use std::collections::HashMap;
let mut m = HashMap::new();
m.insert("a", 1);
m.remove("a"); // 内部用 "tombstone" 语义处理删除
```
```python [Python]
# dict = 开放地址 + 二次探测变体，稀疏表 + 紧凑条目，3/4 装填即扩容
d = {"a": 1}
d["b"] = 2   # 冲突时按 perturb 算法跳探
```
```typescript [TypeScript]
// Map 由引擎实现（多为哈希 + 插入序链表）；自实现开放地址时注意删除用墓碑
class OpenAddress<K, V> {
    private keys: (K | typeof DEAD)[] = [];
    static DEAD = Symbol("dead");
    // put/get 线性或二次探测；remove 置 DEAD 而非清空，避免断链
}
```
:::

## 常见陷阱

- **开放地址删除直接置空**：会让本应继续探测的键"失联"，必须用墓碑或 backward-shift。
- **α 过高不扩容**：链变长/探测暴增，退化到 O(n)——扩容阈值（Java 0.75）不可忽略。
- **可对抗输入的哈希**：若哈希函数固定，攻击者构造大量同桶键发起 **HashDoS**，需随机盐（Rust/Python 默认已抗）。

# 总结

- 冲突解决两条主线：**链地址法**（桶外挂链/树，删除简单、α 可 >1）与**开放地址法**（表内探测，缓存友好、需墓碑、α<1）；
- 探测越分散越快：线性→聚集、双重哈希→近似无聚集；
- 工程默认多为链地址（HashMap/dict 各有混合优化），并靠**控制装填因子 + 扩容**维持 O(1)。
