# 概述

决策树用「一问一答」的轴对齐分裂把特征空间切成块，每块内给一个多数类/均值：它天然可解释、免特征缩放、能吃类别特征，但也容易一路分裂到叶子纯而又纯——过拟合。集成学习给树配上两条矫正路线：**Bagging**（自助采样训练多棵树再投票，平均掉方差）与 **Boosting**（串行地让新树修正前作的错误，逐步压掉偏差）。随机森林是前者的旗帜，GBDT/XGBoost 是后者的王者——Kagula 表格赛与工业风控的半壁江山都在这两面旗下。

**本篇收录**：**ID3/CART（决策树构建与剪枝）**、**随机森林（Bagging）**、**GBDT/XGBoost（Boosting）**

- 所属章节：[000.机器学习算法概述](./000.机器学习算法概述.md)
- 时间复杂度：建树（预排序）\(O(dn \log n)\)、逐特征扫描 \(O(dn)\)；随机森林 \(t\) 棵树 \(O(t \cdot dn \log n)\) 天然可并行；GBDT \(M\) 轮 \(M\) 棵树串行，不可并行整链（层内可并行）
- 空间复杂度：单树 \(O(\text{节点数})\)；森林/GBDT 线性乘棵树数
- 应用场景：可解释规则导出（风控「硬规则」从树路径提取）、推荐粗排、欺诈检测、缺失值友好建模（树系不挑 NaN）；XGBoost/LightGBM/CatBoost 长期统治表格数据；集成中的「多数表决」也是分布式系统 quorum 思路的近亲
- 前置：贪心选择性质见 [04.核心算法思想/080.贪心算法](../04.核心算法思想/080.贪心算法.md)；信息熵与条件熵（下文速推）

**动画：Bagging 与 Boosting 的分工** <!-- dsa.assets/tree/bagging-vs-boosting.gif -->

1. Bagging：同一堆数据自助采样出 5 份，5 棵树各自独立疯长（高方差、低偏差），投票后误差带（阴影）收窄——**平均降方差**。
2. Boosting：第 1 棵树拟合残差 \([-2, 0, 2]\)（初始为均值），第 2 棵树拟合第 1 棵的残差……每棵都是弱手，叠加后偏差逐级下沉——**串行降偏差**。
3. 对照卡片：Bagging 并行、可加树数；Boosting 串行、树数即轮数、对学习率敏感。

# 详解

## 决策树：贪心分裂 + 不纯度度量

**ID3** 用信息增益 \(Gain = H(D) - \sum_v \frac{|D_v|}{|D|} H(D_v)\)，熵 \(H = -\sum p \log_2 p\)；增益偏向取值多的特征，**C4.5** 改增益率修正。**CART** 用 Gini 不纯度（分类）或方差（回归），产出二叉树。分裂搜索的本质是：对每个特征排序（或预排序）后滑窗统计左右两边的类计数，取加权不纯度最小的切点——一次线性扫描一个特征，总 \(O(dn)\)（已排序）或 \(O(dn \log n)\)。

**剪枝**是树的第二半条命：预剪枝（max_depth/min_samples_leaf）早停；后剪枝（CCP/代价复杂度剪枝）先建树、再按 \(R_\alpha(T) = R(T) + \alpha |T|\) 自底向上砍掉「性价比最低」的子树——与验证集上扫 \(\alpha\) 路径配合，是 sklearn `DecisionTreeClassifier(ccp_alpha=…)` 的机制。

## 随机森林：Bagging + 特征随机

对 \(n\) 个样本有放回抽样 \(t\) 次、每次长一棵**不剪枝**的深树；分裂时只看随机 \(m \approx \sqrt{d}\) 个候选特征。两重随机把树间相关性压低——Bagging 的方差缩减 \(\sigma^2 \frac{1+(t-1)\rho}{t}\) 里，**关键是 \(\rho\)（树间相关）而非 \(t\)**，特征随机正是为砍 \(\rho\) 而加。附带福利：袋外样本（OOB，约 37% 未被抽中）天然当验证集，变量重要性 = 该特征打乱后袋外误差上涨幅度。

## GBDT/XGBoost：残差上的贪心下降

前向分框：\(F_M(x) = \sum_{m=1}^M \eta h_m(x)\)，每轮新树 \(h_m\) 拟合当前损失的负梯度（平方损失即「残差」——故称 Gradient **Boosting**）。XGBoost 的二阶展开给每轮叶子最优值与增益的闭式：

\[
Gain_{leaf} = \frac{1}{2}\Big[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\Big] - \gamma
\]

\(\lambda\) 收缩、\(\gamma\) 为分裂门槛、列采样继承随机森林思想——工程三件套让深树不再失控；再配直方图分箱、近似分位数、缺省方向学习与并行按层生长，才有「表格数据之王」的实测速度。

```java [Java]
/** 返回 {特征序号, 切点阈值}；labels 取 0/1；values[j][i] 为样本 i 的特征 j */
public static double[] bestSplit(double[][] values, int[] labels) {
    int d = values.length, n = labels.length;
    double bestGain = -1;
    double[] best = {-1, 0};
    double parent = gini(labels, 0, n);
    for (int j = 0; j < d; j++) {
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        final int fj = j;
        java.util.Arrays.sort(idx, (a, b) -> Double.compare(values[fj][a], values[fj][b]));
        int leftPos = 0;
        for (int k = 0; k < n - 1; k++) {                      // 滑窗统计左半类计数
            if (labels[idx[k]] == 1) leftPos++;
            if (values[fj][idx[k]] == values[fj][idx[k + 1]]) continue;
            int leftN = k + 1, rightN = n - leftN;
            double gl = giniCount(leftPos, leftN);
            int rightPos = countPos(labels, idx, k + 1, n);
            double gr = giniCount(rightPos, rightN);
            double weighted = leftN / (double) n * gl + rightN / (double) n * gr;
            double gain = parent - weighted;
            if (gain > bestGain) {
                bestGain = gain;
                best = new double[]{j, values[fj][idx[k]]};
            }
        }
    }
    return best;
}

static int countPos(int[] labels, Integer[] idx, int from, int to) {
    int c = 0;
    for (int k = from; k < to; k++) if (labels[idx[k]] == 1) c++;
    return c;
}

/** Gini = 1 - p² - (1-p)²，p 为切片内正类占比 */
static double giniCount(int pos, int total) {
    if (total == 0) return 0;
    double p = (double) pos / total;
    return 1 - p * p - (1 - p) * (1 - p);
}

static double gini(int[] labels, int from, int to) {
    int pos = 0;
    for (int i = from; i < to; i++) pos += labels[i];
    return giniCount(pos, to - from);
}
```

```rust [Rust]
/// 返回 (特征序号, 阈值)；labels 用 bool 表示两类
pub fn best_split(values: &[Vec<f64>], labels: &[bool]) -> Option<(usize, f64)> {
    let n = labels.len();
    if n < 2 {
        return None;
    }
    let pos_total = labels.iter().filter(|&&l| l).count();
    let gini_count = |pos: usize, total: usize| -> f64 {
        if total == 0 {
            return 0.0;
        }
        let p = pos as f64 / total as f64;
        1.0 - p * p - (1.0 - p) * (1.0 - p)
    };
    let parent = gini_count(pos_total, n);
    let mut best = None;
    let mut best_gain = f64::MIN;
    for (j, col) in values.iter().enumerate() {
        let mut order: Vec<usize> = (0..n).collect();
        order.sort_by(|&a, &b| col[a].partial_cmp(&col[b]).unwrap());
        let mut left_pos = 0;
        for k in 0..n - 1 {
            if labels[order[k]] {
                left_pos += 1;
            }
            if col[order[k]] == col[order[k + 1]] {
                continue;
            }
            let left_n = k + 1;
            let right_n = n - left_n;
            let right_pos = pos_total - left_pos;
            let weighted = (left_n as f64 / n as f64) * gini_count(left_pos, left_n)
                + (right_n as f64 / n as f64) * gini_count(right_pos, right_n);
            let gain = parent - weighted;
            if gain > best_gain {
                best_gain = gain;
                best = Some((j, col[order[k]]));
            }
        }
    }
    best
}
```

```typescript [TypeScript]
function giniCount(pos: number, total: number): number {
  if (total === 0) return 0;
  const p = pos / total;
  return 1 - p * p - (1 - p) * (1 - p);
}

/** 返回 {feature, threshold}；labels 为 0/1 数组 */
function bestSplit(values: number[][], labels: number[]):
    { feature: number; threshold: number } | null {
  const n = labels.length;
  if (n < 2) return null;
  const posTotal = labels.reduce((s, l) => s + l, 0);
  const parent = giniCount(posTotal, n);
  let best: { feature: number; threshold: number } | null = null;
  let bestGain = -Infinity;
  for (let j = 0; j < values.length; j++) {
    const order = [...Array(n).keys()].sort((a, b) => values[j][a] - values[j][b]);
    let leftPos = 0;
    for (let k = 0; k < n - 1; k++) {
      if (labels[order[k]] === 1) leftPos++;
      if (values[j][order[k]] === values[j][order[k + 1]]) continue;
      const leftN = k + 1, rightN = n - leftN;
      const weighted =
        (leftN / n) * giniCount(leftPos, leftN) +
        (rightN / n) * giniCount(posTotal - leftPos, rightN);
      if (parent - weighted > bestGain) {
        bestGain = parent - weighted;
        best = { feature: j, threshold: values[j][order[k]] };
      }
    }
  }
  return best;
}
```

```python [Python]
def gini_count(pos, total):
    if total == 0:
        return 0.0
    p = pos / total
    return 1 - p * p - (1 - p) * (1 - p)


def best_split(values, labels):
    """values: 特征列的列表 values[j][i]；labels: 0/1；返回 (特征序号, 阈值)"""
    n = len(labels)
    if n < 2:
        return None
    pos_total = sum(labels)
    parent = gini_count(pos_total, n)
    best, best_gain = None, -math.inf
    for j, col in enumerate(values):
        order = sorted(range(n), key=lambda i: col[i])
        left_pos = 0
        for k in range(n - 1):

            if parent - weighted > best_gain:

                best = (j, col[order[k]])
    return best
```

有了这一层「最优贪心切点」，递归调用即得完整 CART；森林 = 并行重复 + 特征子采样；GBDT = 每轮把「标签」换成「负梯度」再建树——**三个模型共享同一棵树的零件**。

## 常见陷阱

1. **树的不稳定性 ≠ 森林的稳**：单棵树对训练集扰动极敏感（换一个切点全盘皆变，这正是它适合 Bagging 的原因）；但「深树 + 不剪枝」在袋内高方差下靠平均收敛，袋外误差才可信——看 OOB，别看袋内。
2. **变量重要性有偏**：高基数类别特征（ID 列）会虚胖地霸榜重要性——先按基数分桶看、或用 Permutation/SHAP 复核；`importances_` 直方图不能直接当「因果解释」。
3. **GBDT 学不动离群点**：平方损失下异常值主导残差，前期树全部力气去追离群；换 Huber/分位数损失或先清洗。
4. **`max_depth` 一把梭**：树深 20 与 6 的 GBDT 完全不是一回事——Boosting 要「弱学习器」（深度 3~8），强树 + 多轮 = 过拟合 + 慢；轮数与学习率此消彼长，早停定轮数。
5. **类别编码暴露顺序假象**：把「城市」编码成 0~999 整数直接喂树，Gini 滑窗会切出「编码 > 500」这种伪规则；用目标编码/OneHot/CatBoost 的原生类别处理。
6. **等值样本切不开**：特征全同、标签相反时分裂退化（本实现的 `continue` 分支），树会一直分裂失败直至样本数下限——数据质量问题，别指望算法兜底。
7. **森林的 OOB ≠ 万能验证**：同一棵树被用于袋内训练与 OOB 评估的「共享样本」使 OOB 对**树数**基本无偏、但对**超参搜索**仍有乐观偏差；最终调参仍需独立验证集。

# 总结

一条树是「贪心地把空间切纯」，两条随机（样本 + 特征）把它炼成稳的森林，一轮轮负梯度把它磨成准的 GBDT——XGBoost 再把每步的贪心算到二阶闭式并工程化。ID3→CART 的历史线说明**分裂准则可以换（熵/Gini/方差/自定义损失增益），骨架不变**；Bagging/Boosting 的对偶则揭示偏差与方差可以分别用「平均」与「修正」来驯服。树系的免缩放、NaN 友好、规则可导出，让它在神经网络时代依然守着表格数据与可解释场景的半壁江山；而「串行弱学习器」思想与 [060.期望最大化EM算法](./060.期望最大化EM算法.md) 的「交替优化」、[07.数值计算/030.数值优化方法](../07.数值计算/030.数值优化方法.md) 的梯度法同属「迭代逼近」大家族。
