# 概述

密码学哈希把任意长度的消息压成固定长度的摘要，要求三条铁律：**原像抗性**（给定摘要 \(h\) 找不到 \(m\) 使 \(H(m)=h\)）、**第二原像抗性**（给定 \(m\) 找不到同摘要的 \(m'\)）、**抗碰撞**（找不到任何一对 \(m \ne m'\) 使 \(H(m)=H(m')\)）。它与哈希表里的散列函数分属两个世界——后者求快、允许冲突、结构公开无妨；前者求「像随机函数」，任何可预测性都是攻击面（对比见 [01.基础数据结构/070.哈希函数设计](../01.基础数据结构/070.哈希函数设计.md)）。SHA-256 是今天的默认值，MD5/SHA-1 已死于碰撞攻击仍在遗产系统里苟活；HMAC 则回答了一个微妙问题：**密钥怎么安全地「掺」进哈希**。

- 所属章节：[000.密码学算法概述](./000.密码学算法概述.md)
- 时间复杂度：SHA-256 约 \(O(n)\)（每 64 字节块 64 轮混合，约 1～2 cycle/byte）；摘要长度固定，验证成本与消息大小无关（签名验证只哈希一次）
- 空间复杂度：内部状态即压缩函数的链值（SHA-256 为 256-bit），流式哈希 \(O(1)\) 额外空间
- 应用场景：数字签名的预处理层（见 [070.数字签名](./070.数字签名.md)）、口令存储（Argon2/bcrypt，专用慢哈希）、完整性校验（包签名/checksum 公示）、HMAC 消息认证、Merkle 树与区块链、PoW
- 家族速览：MD5（128-bit，碰撞 2⁶·³ 秒级可造，弃用）→ SHA-1（160-bit，SHAttered 2017 实际碰撞，弃用）→ SHA-2（256/512，现役）→ SHA-3（Keccak 海绵结构，与 SHA-2 异构备份）

**动画 1：SHA-256 的流水线（Merkle-Damgård）**

1. **填充**：消息尾部加 `1` + 若干个 `0` + 64-bit 原始长度，凑成 512-bit 的整数倍——「abc」(24 bit) 填成 1 块：`61 62 63 80 00…00 18`（末尾 0x18=24）。
2. **链接**：初值 IV = 前 8 个素数平方根的小数部分前 32 位（`0x6a09e667…`，「 nothing-up-my-sleeve」常数），逐块过压缩函数：\(c_i = \mathrm{压缩}(c_{i-1}, m_i)\)。
3. **搅拌**：每块 64 轮，消息调度 \(W_t = \sigma_1(W_{t-2}) + W_{t-7} + \sigma_0(W_{t-15}) + W_{t-16}\) 把每个输入比特扩散进全部状态；轮函数里多数表决（Ch，右移 28/34/39）与奇偶校验（Maj，右移 2/14/18）提供非线性。
4. **输出**：链值相加截断即 256-bit 摘要。改 1 个比特 → 摘要约一半比特翻转（雪崩）。

**动画 2：HMAC 的双层三明治（\(ipad=0x36, opad=0x5c\)）**

1. 密钥 \(k\) 短于块长 64B 则补零至 64 字节。
2. 内层：\(H((k \oplus ipad) \,\|\, m)\)——ipad 翻转密钥每组 4 个低位比特。
3. 外层：\(H((k \oplus opad) \,\|\, 内层摘要))\)——opad 翻转每组 2～5 位。
4. 手验比特：`0x36 ^ 0x5c = 0x6a`（0011 0110 ^ 0101 1100 = 0110 1010）——两组掩码恰相差 0x6a，密钥的每一比特都被两处独立掺入，长度扩展攻击无从下手。

## 标准测试向量（自查实现正确性的锚点）

| 输入 | SHA-256 摘要（十六进制） |
|------|--------------------------|
| `""` | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| `"abc"` | `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` |

对照：`MD5("hello") = 5d41402abc4b2a76b9719d911017c592`、`SHA1("abc") = a9993e364706816aba3e25717850c26c9cd0d89d`——后两者仅用于历史数据校验，新系统一律 SHA-2/SHA-3。

## 摘要与 HMAC：四语言标准姿势

```java [Java]
// 摘要：MessageDigest（JDK 自带 SHA-256）
public static byte[] sha256(byte[] msg) throws NoSuchAlgorithmException {
    return MessageDigest.getInstance("SHA-256").digest(msg);
}
// HMAC：javax.crypto.Mac，密钥独立于消息
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(new SecretKeySpec(key, "HmacSHA256"));
byte[] tag = mac.doFinal(message);        // 32B 认证标签，验证前先等长恒定时间比较
```

```rust [Rust]
// RustCrypto：sha2 + hmac
pub fn sha256(msg: &[u8]) -> [u8; 32] {
    Sha256::digest(msg).into()
}
let tag = Hmac::<Sha256>::new_from_slice(key)
    .expect("valid key length")
    .chain_update(message)
    .finalize()
    .into_bytes();                        // GenericArray<u8, U32>
// 恒定时间比较：tag.ct_eq(&received_tag).into()
```

```typescript [TypeScript]
// Node crypto
import crypto from "node:crypto";
const digest = crypto.createHash("sha256").update(message).digest();      // Buffer(32)
const tag = crypto.createHmac("sha256", key).update(message).digest();
// 验证：crypto.timingSafeEqual(tag, receivedTag) —— 绝不用 === / Buffer.equals
```

```python [Python]
import hashlib, hmac

def sha256(msg: bytes) -> bytes:
    return hashlib.sha256(msg).digest()

tag = hmac.new(key, message, hashlib.sha256).digest()
# 验证：hmac.compare_digest(tag, received)（恒定时间）
```

想理解 HMAC 内部，手写一次「双掩码」即可——它的定义就这一行：

\[
\mathrm{HMAC}(k, m) = H\big((k \oplus opad)\,\|\,H((k \oplus ipad)\,\|\,m)\big)
\]

```python [Python]
def hmac_manual(key: bytes, msg: bytes, block=64) -> bytes:
    if len(key) > block:                       # 超长密钥先哈希
        key = hashlib.sha256(key).digest()
    key = key.ljust(block, b"\x00")            # 补零到块长
    ipad = bytes(b ^ 0x36 for b in key)
    opad = bytes(b ^ 0x5c for b in key)
    inner = hashlib.sha256(ipad + msg).digest()
    return hashlib.sha256(opad + inner).digest()
```

## 长度扩展攻击：MD 结构的阿喀琉斯之踵

Merkle-Damgård 的链式结构意味着：知道 \(H(m)\) 与 \(\lvert m\rvert\)，**无需密钥**即可算出 \(H(m \,\|\, \text{padding} \,\|\, m')\)——把摘要当「已算到一半的状态」继续压缩。危险场景：服务端用 `H(secret || msg)` 当 MAC（朴素拼接 MAC），攻击者截取一条合法 `(msg, tag)` 后，以 `tag` 为初始链值、按填充规则补齐长度域，直接续压出扩展消息 `msg||pad||msg'` 的合法标签——整个过程不需要知道 `secret`。

防御三选一：**用 HMAC**（密钥被 ipad/opad 两次掺入，外部无法构造合法初值）、**用 SHA-3/Blake3**（海绵结构天然免疫）、或至少改成 `H(msg || secret)`（柚子式后置密钥，但仍不如 HMAC 干净）。

## 口令哈希：别拿快哈希当苦力

SHA-256 每秒可算数十亿次，GPU 字典攻击如虎添翼——**口令存储必须用「慢哈希」**：bcrypt（Cost 因子调工作量）、scrypt（内存硬）、**Argon2id**（内存+时间双硬，PHC 竞赛冠军，默认之选）。要点：每人随机盐（防彩虹表）、工作参数随硬件水涨船高、验证走恒定时间。KDF 场景（把口令展开成 AES 密钥）则用 HKDF（高熵输入）或 Argon2（低熵输入）。

## 常见陷阱

::: danger 陷阱清单
1. **MD5/SHA-1 签名证书**：2008 年鲁宾逊用 MD5 碰撞伪造 CA 证书、FLAME 恶意软件借此签名——凡「碰撞可造」的哈希进签名链，整条信任链归零。
2. **`H(secret || msg)` 朴素 MAC**：长度扩展攻击直接续推；MAC 一律 HMAC，加密认证一律 AEAD（[010.对称加密算法](./010.对称加密算法.md) 的 GCM tag）。
3. **比较标签不用恒定时间**：`==`/`equals` 短路比较把验证耗时泄露成「猜对前缀越长」的信号，网络侧可逐字节爆破——用 `MessageDigest.isEqual`（Java 已是恒定实现）、`crypto.timingSafeEqual`、`hmac.compare_digest`。
4. **SHA256(密码) 存库**：快哈希 + 无盐 = 拖库后 GPU 秒破百万条；口令必须 bcrypt/scrypt/Argon2。
5. **拿摘要当唯一键忽略碰撞概率**：SHA-1 截断到 80-bit 在 2⁴⁰ 量级即生日碰撞；用截断摘要做指纹时按生日界 \(2^{b/2}\) 评估冲突预算。
6. **自创哈希结构**：把 MD5 换轮数、把 SHA 改常数的「自制加强版」历史上全军覆没——密码学算法的安全性来自公开评审，不来自混搭。
:::

# 总结

- 密码学哈希 = 确定性、抗原像、抗碰撞的「数字指纹」；SHA-256 以 Merkle-Damgård 链 + 64 轮混淆提供 128-bit 安全强度（生日界），SHA-3/Blake3 用海绵结构补上长度扩展免疫。
- HMAC 用 ipad/opad 双掩码把密钥「焊死」在哈希的两端，是「密钥 + 哈希」构造认证标签的唯一正统姿势；验证永远恒定时间。
- 哈希的三种职场分工要分清：**指纹**（快哈希，完整性/去重）、**MAC**（HMAC，认证）、**口令/KDF**（慢哈希 Argon2，对抗算力）——用错场景比算法过时更常见。
