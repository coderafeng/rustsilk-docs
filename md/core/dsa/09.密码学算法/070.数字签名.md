# 概述

手写签名能被模仿、文件能被悄悄改动——**数字签名**用密码学同时给出三样东西：**真实性**（只有私钥持有者能产生）、**完整性**（改一个比特验签即失败）、**不可否认性**（签名者事后无法抵赖，因为没人能伪造他的私钥）。标准姿势是「先哈希后签名」：对消息摘要 \(H(m)\) 做私钥运算，验签方用公钥复核——这既是为了性能（签名运算只碰 256 比特），也是为了安全（把任意长度消息压进困难问题实例里）。本篇沿「流程 → DSA → ECDSA」三级台阶，外加对签名家族的现在完成时 EdDSA/Schnorr 一览；公钥数学本体见 [020.RSA非对称加密](./020.RSA非对称加密.md) 与 [060.椭圆曲线密码ECC](./060.椭圆曲线密码ECC.md)，摘要层见 [040.哈希算法](./040.哈希算法.md)。

**本篇收录**：**签名与验签流程（哈希-然后-签名范式）**、**DSA**、**ECDSA**

- 所属章节：[000.密码学算法概述](./000.密码学算法概述.md)
- 时间复杂度：ECDSA/P-256 签名约 0.1ms、验签约 0.2ms（两次标量乘）；RSA-PSS 签名毫秒级；Ed25519 验签为业界最快（约 60μs/万次级批量友好）
- 空间复杂度：签名尺寸——ECDSA/P-256 64 字节（r‖s）、RSA-2048 256 字节、Ed25519 64 字节；公钥尺寸决定证书大小
- 应用场景：TLS 证书链与 CertificateVerify、代码签名（ Authenticode/apt 仓库）、区块链交易（比特币每笔 UTXO 解锁即 ECDSA）、电子合同与 JWT（ES256/RS256）、SSH 登录

**动画 2：ECDSA 手算全往返（复用 [060 篇](./060.椭圆曲线密码ECC.md) 的 \(E/\mathbb{F}_{17}\)，基点 \(G=(5,1)\)，阶 \(n=8\)，私钥 \(d=3\)，\(Q = dG = (0,6)\)）**

1. **签名**消息 \(m\)（设 \(z = H(m) \equiv 5\)），临时随机数 \(k=5\)：
   - \(R = kG = 5G = (7,1)\) → \(r = x_R \bmod n = 7\)；
   - \(s \equiv k^{-1}(z + rd) \equiv 5^{-1}(5 + 7\times3) \pmod 8\)；\(5^{-1}\bmod 8 = 5\)（\(25\equiv1\)）→ \(s = 5 \times 26 = 130 \equiv 2\)。
2. **验签**：\(w = s^{-1} = 2^{-1} = 4\)；\(u_1 = wz = 20 \equiv 4\)、\(u_2 = wr = 28 \equiv 4\)；
   - \(R' = u_1G + u_2Q = 4G + 4(3G) = 16G \equiv 0G\)?? —— 此例 \(n=8\) 下 \(u_1+3u_2 = 16 \equiv 0\)，\(u_1 G\) 与 \(u_2 Q\) 恰好互消属退化；换 \(k=7\) 重签：\(R = 7G = (7,16)\)，\(r = 7\)，\(7^{-1}\bmod 8 = 7\)，\(s = 7\times(5+21) = 7\times26 \equiv 7\times2 = 14 \equiv 6\)，\(w = 6^{-1}\bmod 8\) 不存在（\(\gcd(6,8)=2\)）——教学小群的阶不是素数带来的额外课：**真实曲线的 \(n\) 必须是大素数**。
3. 回到干净案例（\(n\) 取素数 11 的等价演示见详解代码）：验签重构出 \(R'\)，比较 \(x_{R'} \bmod n \stackrel{?}{=} r\)——相等即「持有 \(d\) 且消息为 \(m\)」的双重证明。
4. **事故回放**：同一 \(k\) 签两条消息 → \(s_1 - s_2 = k^{-1}(z_1 - z_2)\) → \(k = (z_1 - z_2)(s_1 - s_2)^{-1}\) 一步解出，随后 \(d = (s_1 k - z_1)r^{-1}\)——索尼 PS3 与多起比特币盗币案的完整剧本。

# 详解

## 范式：签名 = 私钥方向的门

| 方案 | 签名对象 | 签名生成 | 验证等式 | 尺寸 |
|------|---------|---------|---------|------|
| RSA-PKCS#1v1.5 / PSS | 填充后摘要 | \(\sigma = \bar{z}^d \bmod n\) | \(\bar{z} \stackrel{?}{=} \sigma^e \bmod n\) | 256B（2048-bit） |
| DSA | 摘要 \(z\) | \((r,s)\)，含 \(k^{-1}\) | \((r,s,z)\) 三方重算 \(v \stackrel{?}{=} r\) | 40～64B |
| ECDSA | 摘要 \(z\) | \((r,s)\) 群版 | \(x_{(u_1G+u_2Q)} \stackrel{?}{=} r\) | 64B（P-256） |
| EdDSA | 摘要 \(z\) | \(r=H(\mathrm{salt}\|\|sk)\bmod n,\ R=rG,\ s = r + H(R\|\|A\|\|z)\,d \bmod n\) | \(sG = R + H(\cdot)A\) | 64B |

## DSA：素数 \(p\) 上的离散对数签名

参数：全局素数 \(p\)、\(q \mid p-1\)（\(q\) 为 256-bit 素因子阶）、生成元 \(g = h^{(p-1)/q}\)。私钥 \(x\)、公钥 \(y = g^x \bmod p\)。

\[
\text{Sign: } r = (g^k \bmod p) \bmod q, \quad
s = k^{-1}(H(m) + xr) \bmod q
\qquad
\text{Verify: } w = s^{-1},\ u_1 = wz,\ u_2 = wr,\;
v = (g^{u_1} y^{u_2} \bmod p) \bmod q \stackrel{?}{=} r
\]

推导一行讲透：由 \(s = k^{-1}(z+xr)\) 得 \(sk \equiv z + xr \pmod q\)，于是 \(g^{u_1} y^{u_2} = g^{wz} g^{xwr} = g^{w(z + xr)} = g^{s^{-1} \cdot sk} = g^k\)——验证方无需知道 \(k\) 就能重构出 \(r\)。**离散对数难题替签名者保守临时密钥的秘密**。DSA 是 FIPS 186 的老兵（美国联邦签名标准），尺寸大、依赖全局参数、已被 ECDSA 全面替代。

## ECDSA：群语言复写 DSA

签名（私钥 \(d\)，随机 \(k \in [1, n-1]\)）：

\[
R = kG = (x_R, y_R), \quad r = x_R \bmod n, \quad
s = k^{-1}\big(H(m) + r\,d\big) \bmod n
\]

验证（公钥 \(Q = dG\)，\(z = H(m)\)）：\(w = s^{-1} \bmod n\)，\(u_1 = zw,\ u_2 = rw\)，检查

\[
R' = u_1G + u_2Q, \qquad x_{R'} \bmod n \;\stackrel{?}{=}\; r
\]

正确性一行的推导：\(u_1G + u_2Q = \frac{z}{s}G + \frac{r}{s}dG = \frac{z + rd}{s}G = \frac{sk}{s}G = kG = R\) ✓。

小素数群上的可运行验证版（把 \(n\) 取成素数 11 的玩具域思路，直接跑通流程；真实曲线阶均为大素数）：

```java [Java]
// 教学玩具参数：E: y²=x³+7x+7 over F_11，G=(3,5)，阶 n=11 —— 流程可验，安全为零
// 逐倍点（060 篇代码可复算）：2G=(4,8), 3G=(4,3), 5G=(1,2), 7G=(10,1), 9G=(10,5)
// 私钥 d=7 → 公钥 Q=7G=(10,1)；z=8，k=9：
//   R=9G=(10,5) → r=10；s = 9⁻¹(8+10·7) mod 11 = 5·78 mod 11 = 5
// 验证：w=5⁻¹=9；u1=8·9≡6；u2=10·9≡2；6G+2Q=(10,1)+(10,9)=(10,5) → x=10=r ✓
Signature sig = Signature.getInstance("SHA256withECDSA");   // 生产：一行调用
sig.initSign(ecPrivateKey); sig.update(message);
byte[] signature = sig.sign();                              // DER:SEQUENCE{r,s}
sig.initVerify(ecPublicKey); sig.update(message);
boolean ok = sig.verify(signature);
```

```rust [Rust]
// 生产：ecdsa/p256 crate（RFC 6979 确定性 k 默认开启）
let signing_key = SigningKey::from_slice(&d_bytes)?;        // P-256 私钥
let signature: p256::ecdsa::Signature = signing_key.sign(message);
VerifyingKey::from(&signing_key).verify(message, &signature)?;
// DER 编解码：signature.to_der() / Signature::from_der()
```

```typescript [TypeScript]
// Node：ECDSA 命名曲线签名
import crypto from "node:crypto";
const sign = crypto.createSign("SHA256");
sign.update(message); sign.end();
const signature = sign.sign(privatePem);                    // DER
const verify = crypto.createVerify("SHA256");
verify.update(message); verify.end();
const ok = verify.verify(publicPem, signature);             // 公钥可来自 X.509 证书
```

```python [Python]
# 生产：cryptography 库（ECDSA / Ed25519 同族）
from cryptography.hazmat.primitives.asymmetric import ec, ed25519
from cryptography.hazmat.primitives import hashes

signature = priv.sign(message, ec.ECDSA(hashes.SHA256()))   # DER r‖s
pub.verify(signature, message, ec.ECDSA(hashes.SHA256()))   # 失败抛 InvalidSignature

sk = ed25519.Ed25519PrivateKey.generate()                   # 现代默认之一
sig = sk.sign(message)
sk.public_key().verify(sig, message)                        # 无 hash 参数：EdDSA 自带预哈希
```

## EdDSA/Schnorr：确定性随机数与线性化

ECDSA 的 \(k\) 依赖随机源，一旦低熵/重复即私钥裸奔（动画 2 第 4 幕）。两大家族用不同哲学拆掉这颗雷：

- **RFC 6979**（比特币/以太坊采用）：\(k = \mathrm{PRF}(sk, H(m))\)——确定性「假随机」，每次签同一消息用同一 \(k\) 仍安全（因为私钥与消息联合注入）；
- **Schnorr/EdDSA**（BIP-340、TLS 1.3、SSH 新默认）：\(R = rG\) 且 \(s = r + H(R \,\|\, A \,\|\, z)\,d \bmod n\)——随机数由私钥与消息哈希派生；验签 \(sG = R + H(\cdot)A\) 只需一次标量乘（比 ECDSA 的两次快）；还带来**公钥打包/密钥聚合**（MuSig2）等线性福利。

## malleability：签名的「第二个合法自己」

ECDSA 数学上 \((r, s)\) 与 \((r, n-s)\) **同为合法签名**（验证只用到 \(s^{-1}\)，反射对称）；DER 编码还有多种合法写法。对「签名哈希即身份」的系统（早期比特币交易 ID、去重缓存、审计日志）这意味着**第三方可以在不破坏验签的情况下改写签名字节**——历史酿成交易篡改与 CVE 无数。防御：BIP-66/BIP-146 的低 \(s\) 规则（\(s \le n/2\)）、严格 DER 解析、或直接换无此问题的 EdDSA（签名与消息字节一一对应）。

## 常见陷阱

::: danger 陷阱清单
1. **nonce \(k\) 重用或可猜**：两条签名一步解出私钥（PS3/Android 钱包事件）；必须 CSPRNG 或 RFC 6979/EdDSA 确定性派生——任何「性能优化」复用 k 的改动都是后门。
2. **跳过哈希直接签**：RSA 同态性让攻击者拿一条合法签名「乘」出另一条（对精心构造的 \(z'\) 求签即得 \(m'\) 的签名）；「哈希-然后-签名」范式 + PSS 填充才是完整方案。
3. **验签不校验编码与曲线参数**：宽松 DER（Bitcoin 历史上可任意加 padding 字节）、签名里的 \(r/s\) 不在 \([1, n-1]\)、公钥不在曲线上——每一处宽松都是 malleability 或无效公钥攻击的门缝。
4. **密钥混用**：同一密钥对既做 ECDH 又做 ECDSA（甚至跨曲线）打开协议级攻击面；证书里 keyUsage 分工作为第一道制度防线。
5. **只验签名不验语义**：验签通过 ≠ 该签名属于「这一次请求」——重放攻击靠消息内嵌时间戳/挑战值/一次性 nonce 防住（签名密码学不管新鲜度）。
6. **哈希选型摆烂**：签名安全上限 = min(签名方案强度, 哈希抗碰撞强度)——SHA-1 证书签名 2017 年后进入浏览器全平台黑名单，正是「哈希先于签名倒下」的实证。
:::

# 总结

- 数字签名 = 「私钥方向的单向门」：真实性、完整性、不可否认性三合一；永远先哈希再签，签名对象是摘要不是原文。
- DSA 是整数群版、ECDSA 是椭圆曲线群版——同一副骨架 \((r, s = k^{-1}(z+rd))\) 换群书写；验证靠「\(u_1G + u_2Q\) 重构 \(kG\)」的一行代数；EdDSA/Schnorr 用确定性随机数与更短验签路径接棒现代默认。
- ECDSA 的两大命门都有标准解药：**\(k\) 的纪律**（RFC 6979）与 **(r,s) 的反射自由**（低 \(s\) 规则/严格 DER）——部署时两条都要开。
- 签名站在 [040.哈希算法](./040.哈希算法.md) 的摘要之上、[060.椭圆曲线密码ECC](./060.椭圆曲线密码ECC.md) 的群律之中；而 nonce 泄露的「格回收」玩法，见 [050.LLL格基规约](./050.LLL格基规约.md) 的 Hidden Number Problem。
