# 概述

对称加密是「一把钥匙开一把锁」：加密与解密共用同一密钥，因此快到可以处理整盘数据、视频流与 TLS 记录层负载。它的现代形态是一部「三层演化史」：**流密码**（RC4→ChaCha20，密钥流与明文逐字节异或）、**分组密码**（DES→AES，固定 16 字节一块地轮换、代换）、**工作模式**（ECB→CBC→CTR→GCM，决定同一把密钥如何安全地用在多块数据上——ECB 会暴露图案，CTR 把分组密码变成流密码，GCM 顺手把完整性也包办）。密码学安全从来不是单个算法的事，而是「算法 + 模式 + 随机数 + 密钥管理」链条的短板效应。

- 所属章节：[000.密码学算法概述](./000.密码学算法概述.md)
- 时间复杂度：AES-NI 硬件加速下可达 \(O(n)\) 且每字节常数极低（现代 CPU 约 0.1～0.5 cycle/byte）；ChaCha20 无硬件加速时亦仅约 3～6 cycle/byte，软件实现友好
- 空间复杂度：\(O(1)\) 额外状态（分组链式模式需保存上一密文块）
- 应用场景：TLS 记录层（AES-GCM/ChaCha20-Poly1305）、磁盘与文件系统加密（XTS）、数据库字段加密、文件容器（ZIP 的 AES）
- 与非对称的分工：公钥密码慢三个数量级，只用来传对称密钥/签名（见 [020.RSA非对称加密](./020.RSA非对称加密.md)、[030.密钥交换算法](./030.密钥交换算法.md)）

3. **ShiftRows**：第 \(i\) 行循环左移 \(i\) 格——把列间的数据横向打散。
4. **MixColumns**：每列乘固定 MDS 矩阵（\(\{02\}\cdot 54 \oplus \{03\}\cdot 12 \oplus \dots\) 的有限域乘法）——纵向扩散。
5. 10 轮循环（末轮无 MixColumns）；一位明文的 1 bit 变化，两轮后至少影响 3 个字节、5 后整个状态面目全非——**雪崩效应**。

**动画 2：ECB 的失败与 CTR 的补救（图像版）**

1. 把 Tux 图片按 16 字节分组、同一密钥 ECB 加密。

3. 换 CTR：每块加密「nonce+计数器」得密钥流，再与明文异或。
4. 同一明文两次加密密文完全不同；只要 nonce 不重用，CTR 安全且可并行。

# 详解

## 流密码：ChaCha20 的「ARX + 置换」

ChaCha20（Bernstein，2008）的构件只有加法、异或、循环移位（ARX 三件套）：256-bit 密钥 + 96-bit nonce + 32-bit 计数器展开 512-bit 状态，经 20 轮列/对角混合后输出 64 字节密钥流，与明文异或即密文。它没有查表（免疫缓存侧信道）、软件速度稳定，是移动端 TLS 的常客（ChaCha20-Poly1305 套件）。

教学上先把「完美保密」的原型——**一次性密码本**讲清楚：密钥流与明文等长、真随机、绝不重用，密文即信息论安全。现实缺的是「真随机长密钥」，于是用短密钥 + 密码学 PRNG（ChaCha20 正是一名优秀的 PRNG）扩张密钥流。XOR 流密码骨架四语言如下（真实部署请直接使用成熟库的 ChaCha20，勿手搓密钥流）：

```java [Java]
// 教学用：密钥流 = SHA-256(key || counter) 逐块级联；生产用 ChaCha20
public static byte[] xorStream(byte[] key, byte[] data, boolean decrypt) {
    int n = data.length;
    byte[] out = new byte[n];
    long counter = 0;
    try {
        MessageDigest md = MessageDigest.getInstance("SHA-256");
        for (int off = 0; off < n; off += 32, counter++) {
            md.reset();
            md.update(key);
            md.update(longToBytes(counter));
            byte[] ks = md.digest();                     // 32B 密钥流块
            for (int t = 0; t < 32 && off + t < n; t++)
                out[off + t] = (byte) (data[off + t] ^ ks[t]);
        }
    } catch (NoSuchAlgorithmException e) { throw new AssertionError(); }
    return out;                                          // encrypt/decrypt 同构
}
```

```rust [Rust]
/// 教学用 XOR 流密码：keystream_i = sha256(key || LE_i64(i)) 级联截断
pub fn xor_stream(key: &[u8], data: &[u8]) -> Vec<u8> {
    let mut out = Vec::with_capacity(data.len());
    for (i, chunk) in data.chunks(32).enumerate() {
        let mut h = Sha256::new();
        h.update(key);
        h.update((i as i64).to_le_bytes());
        let ks = h.finalize();
        for (j, &b) in chunk.iter().enumerate() {
            out.push(b ^ ks[j]);
        }
    }
    out
}
// 注意：nonce/计数器一旦重用，两次密文异或直接泄露明文差——流密码的命门在「密钥流绝不重用」
```

```typescript [TypeScript]
// Node 环境示意：webcrypto.digest 作密钥流发生器（教学用）
async function xorStream(key: Uint8Array, data: Uint8Array): Promise<Uint8Array> {
  const out = new Uint8Array(data.length);
  let off = 0;
  const ctr = new Uint8Array(8);
  while (off < data.length) {
    const buf = new ArrayBuffer(8);
    new DataView(buf).setBigUint64(0, BigInt(off / 32));
    ctr.set(new Uint8Array(buf));
    const ks = new Uint8Array(await crypto.subtle.digest("SHA-256",
      Uint8Array.from([...key, ...ctr])));
    for (let j = 0; j < 32 && off + j < data.length; j++)
      out[off + j] = data[off + j] ^ ks[j];
    off += 32;
  }
  return out;
}
```

```python [Python]
import hashlib

def xor_stream(key: bytes, data: bytes) -> bytes:
    """教学用：keystream = sha256(key||i) 级联；加解密同函数"""
    out = bytearray()
    for i, chunk in enumerate([data[j:j+32] for j in range(0, len(data), 32)]):
        ks = hashlib.sha256(key + i.to_bytes(8, "little")).digest()
        out += bytes(b ^ k for b, k in zip(chunk, ks))
    return bytes(out)
```

## AES：替换-置换网络的工业标准

AES（Rijndael，FIPS-197）是**代换-置换网络（SPN）**：分组固定 128-bit，密钥 128/192/256 对应 10/12/14 轮。每轮四步——SubBytes（S-Box 非线性代换）、ShiftRows（行移位）、MixColumns（列混合，\(\mathrm{GF}(2^8)\) 上的矩阵乘法）、AddRoundKey（轮密钥异或）。轮密钥由**密钥扩展**从主密钥派生。

两个工程事实值得背下：其一，AES 的有限域乘法可用「xtime + 查表」实现到常数时间，防侧信道；其二，**解密结构几乎复用加密**（InvSubBytes/InvMixColumns + 逆序轮密钥），硬件只需一套数据通路。

```java [Java]
// 正确姿势：调用 JCE，AES/GCM/NoPadding（128-bit tag）
public static byte[] aesGcmEncrypt(byte[] key, byte[] plaintext) throws Exception {
    byte[] iv = new byte[12];                            // GCM 推荐 96-bit nonce
    new SecureRandom().nextBytes(iv);
    Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
    c.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "AES"),
           new GCMParameterSpec(128, iv));
    byte[] ct = c.doFinal(plaintext);                    // 密文已含认证 tag
    byte[] out = new byte[12 + ct.length];
    System.arraycopy(iv, 0, out, 0, 12);                 // 前置 nonce
    System.arraycopy(ct, 0, out, 12, ct.length);
    return out;
}
// 解密：取前 12 字节为 iv，其余 doFinal；tag 校验失败抛 AEADBadTagException
```

```rust [Rust]
// 正确姿势：aes-gcm crate（RustCrypto）
pub fn aes_gcm_encrypt(key: &[u8; 16], plaintext: &[u8]) -> Vec<u8> {
    let cipher = Aes256Gcm::new_from_slice(key).expect("key len");
    let nonce = Nonce::generate(&mut OsRng);             // 96-bit
    let ct = cipher.encrypt(nonce, plaintext).expect("encryption failure");
    [nonce.as_slice(), ct.as_slice()].concat()
}
// 密文 = nonce ‖ ct ‖ tag；解密端 tag 不过 → 直接报错，绝不返回半成品明文
```

```typescript [TypeScript]
// WebCrypto：AES-GCM，crypto.subtle 提供经过审计的实现
async function aesGcmEncrypt(key: CryptoKey, data: ArrayBuffer) {
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const ct = await crypto.subtle.encrypt({ name: "AES-GCM", iv }, key, data);
  const out = new Uint8Array(iv.length + ct.byteLength);
  out.set(iv); out.set(new Uint8Array(ct), iv.length);
  return out;                                            // iv ‖ ciphertext‖tag
}
```

```python [Python]
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

def aes_gcm_encrypt(key: bytes, plaintext: bytes) -> bytes:
    iv = os.urandom(12)                                  # 96-bit nonce
    ct = AESGCM(key).encrypt(iv, plaintext, None)        # 含 128-bit tag
    return iv + ct
# 解密：AESGCM(key).decrypt(iv, ct, None)；tag 失败抛 InvalidTag
```

## 工作模式：同一把密钥的四种用法

| 模式 | 思路 | 并行加密 | 完整性 | 致命伤 |
|------|------|---------|--------|---------|
| ECB | 每块独立加密 | ✅ | ❌ | 相同明文块→相同密文块（Tux 图） |
| CBC | 先与上一密文块异或再加密 | ❌（解密可并行） | ❌ | padding oracle 攻击 |
| CTR | 加密「nonce+计数」当密钥流 | ✅ | ❌ | nonce 重用即「两次一密」 |
| GCM | CTR + GHASH 认证标签 | ✅ | ✅（AEAD） | nonce 重用泄露密钥流与认证密钥 |

现代协议的默认答案是 **AEAD**（GCM/ChaCha20-Poly1305）：加密与完整性一体，密文被篡改会在解密端报错——先认证再放行明文，从根上消灭 padding oracle 这类「先解密后校验」的旁路。CBC 时代「加密然后 MAC」的错误顺序（BREACH/POODLE 诸多教训）正是 AEAD 存在的原因。

## 常见陷阱

::: danger 陷阱清单
1. **手写 ECB 或固定 IV 的 CBC**：图像 Tux 实验不是猎奇，是每周都在真实系统里重演的事故——凡「加密后仍能看出结构」先查 ECB 与恒定 IV。
2. **nonce/IV 重用**：流密码与 CTR/GCM 的 nonce 一旦重复，两次密文异或直接消掉密钥流；GCM 的 nonce 重用更会泄露 GHASH 认证密钥，连完整性一起崩。
3. **`Math.random()` 生成密钥**：密码学密钥/IV 必须来自 CSPRNG（Java `SecureRandom`、Node `crypto.randomBytes`、Python `secrets`）——PRNG 种子可猜即密钥可猜。
4. **密钥当字符串存**：派生自口令请用 PBKDF2/scrypt/Argon2（加盐 + 高迭代拉爆离线爆破，见 [040.哈希算法](./040.哈希算法.md)），而不是「把密码直接 SHA-256 当 key」。
5. **只加密不认证**：密文可被恶意改写而解密端浑然不觉（CBC 的 bit-flipping）——没带 tag 的加密在对抗环境里等于没加密。
6. **填充 oracle**：CBC 解密若把「padding 对不对」的差异（错误码/响应时间）暴露给攻击者，可在无密钥下逐步解密——用 AEAD 或先验证 MAC 再解密。
:::

# 总结

- 对称加密三层认知：**算法**（ChaCha20/AES）、**模式**（ECB/CBC/CTR/GCM）、**工程链条**（CSPRNG、nonce 纪律、AEAD 一体化）——任何一层失守，整体即失守。
- AES 用 SPN 的「代换混淆 + 置换扩散」十数轮碾出雪崩；ChaCha20 用纯 ARX 在无硬件平台上打出稳定高速——两者都是「公开评审多年、被反复锤过」的默认选择。
- 落地口诀：**能 AEAD 不用裸分组，能调库不自实现，nonce 一用即弃，口令派生走 Argon2**。
- 对称密钥如何安全递到对方手里，是下一篇的问题：[020.RSA非对称加密](./020.RSA非对称加密.md) 与 [030.密钥交换算法](./030.密钥交换算法.md)。
