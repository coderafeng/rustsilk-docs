# 数据安全与个人信息保护

只要产品会收集用户数据（哪怕只有一个手机号注册），你就已经是《个人信息保护法》（PIPL）、《数据安全法》、《网络安全法》三部法律的规制对象。**这是互联网创业罚款上限最高的一部法：PIPL 顶格可罚上年营业额5%。**

## 个保法、数安法核心要求

- **PIPL 主线**：处理个人信息 = **告知 → 取得同意 → 在告知范围内使用**；处理**敏感个人信息**（生物识别、医疗健康、金融账户、行踪轨迹、**不满十四周岁未成年人信息**）须取得**单独同意**并做个人信息保护影响评估；
- **用户权利清单**（必须提供便捷行使渠道）：查阅、复制、更正、删除、撤回同意、注销账号、要求解释说明——**"注销入口藏三层"被App通报的最常见原因**；
- **委托处理与共享**：把数据交给云厂商/第三方分析（受托处理）要签**委托处理协议**；向第三方**提供**个人信息须再次取得单独同意；**共同处理**须约定各自责任；
- **DSA 主线**：数据分类分级、建立安全管理制度、识别并保护"重要数据"（未定核心数据即一般从严）；发生安全事件**立即处置并报告**；
- **网安法主线**：按**网络安全等级保护**定级备案（一般系统二级，重要系统三级）并测评——To G/To B 投标常把等保二级/三级作为资质门槛，**做政企客户的第一年就该办**；
- **数据出境**（用到海外服务器/海外SaaS/跨境集团传输时看）：按2024年《促进和规范数据跨境流动规定》——自当年1月1日起累计向境外提供**100万人以上一般个人信息或1万人以上敏感个人信息**的须申报安全评估；低于上述门槛的走标准合同/认证或豁免（如履行跨境合同所必需、跨境人力资源管理所必需、非大规模且不满10万人一般信息可豁免）；**先用尽豁免情形，再考虑标准合同备案**。

## 隐私政策与用户协议要点

一份能被监管"过检"的隐私政策：

- **逐项列明**：收集哪些字段（到字段级）、目的、方式、保存期限、共享对象——**一揽子打包式授权（"为改善服务我们可能收集您的全部信息"）直接通报**；
- **SDK 双清单**：收集个人信息清单 + 与第三方共享清单（含SDK名称、采集字段、用途），App里可查阅——应用商店上架审核已强制要求；
- **权限调用时机**：相机/位置/通讯录**用到时再弹窗**，"启动即索取全部权限"是典型违规；
- 14岁以下未成年人产品：单独制定**儿童个人信息处理规则**并取得监护人同意；
- **重大变更要重新同意**（新增收集字段、变更用途、共享对象变化）；
- 用户协议侧：账号封禁与虚拟财产条款、免责条款要**加粗提示**（格式条款提示义务，见本篇合同章）。

## 数据收集的最小必要原则

落到工程与运营动作上的五条纪律：

1. **能不收的就不收**：注册只留手机号就只留手机号——多收的每一个字段都是负债不是资产；
2. **收了的存最短期限**：明确保存期限，到期**删除或匿名化**（这是法定义务，不是可选项）；
3. **内部权限最小化**：客服/运营/分析师按角色分级授权，查询敏感字段**留操作日志**——员工批量导出客户信息，出事时公司连带担责；
4. **测试环境脱敏**：生产数据直接拷贝到测试库是高频违规动作（含泄露风险）；
5. **爬虫红线**：只抓公开、非个人信息、不规避技术措施的数据；**抓取公民个人信息可能直接构成侵犯公民个人信息罪**，"数据是公开的"不是挡箭牌；购买数据必须核验来源授权链。
