# 从0到1的最小可行产品

MVP不是"缩水版产品"，是**"验证最关键假设的最小实验"**——你的目标不是做出一个东西，而是**用最短时间、最低成本，拿到"这事值不值得继续"的可靠答案**。

## MVP 的核心思想

- **假设先行**：先把创业想法拆成三层假设——**价值假设**（有人要、肯付钱）、**增长假设**（能复制地获取更多同样的客户）、**可用性假设**（他们真能用起来）——**每个MVP只测当下一步最致命的那一个**；
- **最致命的先测**：最可能让你全盘皆输的假设优先（通常是"愿不愿意付钱"而不是"功能够不够优雅"）；
- **实验四要素**：假设 → 动作 → 指标 → **通过线**——写不出通过线的实验是"做东西玩"："落地页访客→留资转化率 ≥ 8% 即算价值假设初步成立，两周为期"——达不到就改或撤；
- 完整产品思维的代价：闭门开发半年 = 用最贵的方式（你的时间）买到一个"没人要"的结论——**MVP是把"六个月找死"压缩成"三周试错"**。

## 低成本试错的方式

按"投入从轻到重"的光谱，取能回答当前问题的最轻一档：

| 形态 | 做法 | 适合验证 |
|---|---|---|
| **对话/预登记** | 目标客户访谈 + 意向登记表 | 痛点与替代方案 |
| **落地页 + 小额投放** | 一页讲清价值主张，留邮箱/付定金，广告费几百元试转化 | 需求强度与获客成本 |
| **人肉MVP（Concierge）** | 手工服务前5—10个客户，后台是Excel和腿 | 服务流程与真实价值 |
| **绿野仙踪MVP** | 前台像产品，后台人工伪装自动化 | 交互与付费意愿 |
| **No-code/低代码** | 表单+小程序+自动化工具拼出可用版本 | 可用性与留存 |
| **单功能Demo** | 只做核心那一个功能 | 技术可行性 |

- 给技术型创始人的特别警告：**你会写代码，所以你会忍不住用写代码解决问题**——Demo不是验证，**有人付钱/反复使用才是**；把开发预算设上限（如"人工可以替代两周的一切功能"），把省下的时间全部投给"找10个真用户"；
- 时间盒纪律：单轮MVP **2—4周、预算封顶**（几百到几千元），到期强制出复盘结论——超时通常是"舍不得杀死假设"的症状。

## 验证指标与反馈闭环

每个阶段只看离钱和离留存最近的指标：

- **信号强度阶梯**（下强上弱，别用弱信号说服自己）：预付定金/签约 > 真实使用并次周回访仍活跃 > 付费试用 > 留资/进群 > 点赞关注 > "挺好的""一定要出"；
- **定性反馈定量用**：每轮访谈5—10个目标用户，记录**原话**（不是你的转译）——高频出现的不满和惊喜词，就是产品文案与功能优先级的原料（获客内容选题也来自这里，见《冷启动与获客》）；
- **反馈闭环的固定节拍**：上线 → 48小时内回访前10个用户 → 周复盘会（数据+原话）→ **三选一决议**：
  - **继续（Persevere）**：通过线达成 → 加码测下一层假设（增长）；
  - **转向（Pivot）**：需求真、方案错 → 保留学到的，换切入形态再开一轮；
  - **停止（Kill）**：需求伪或自己算不过账 → 归档复盘进想法池——**杀死自己的项目是MVP期最光荣的产出，一万元的止损省下的是一年的青春**；
- 样本小时看"方向"不看"规模"：10个陌生目标用户里6个付定金是有意义的路绿灯，**不要因为在群里拉了200个好友来稀释样本**。
