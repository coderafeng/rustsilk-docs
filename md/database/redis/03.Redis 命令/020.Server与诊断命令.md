# 概述

Server / Connection 分组命令用于**观测服务器状态、动态调参、诊断性能问题、管理客户端连接**。它们是排障时的"仪表盘"，也是最容易被误用的危险区。

- 归属与可用性：Redis 开源核心能力（各子命令版本以官方为准）
- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/management/>

# 命令速查

**Connection（连接与会话）**

| 命令 | 作用 |
|------|------|
| `PING` / `ECHO msg` | 连通性探测 / 回显 |
| `AUTH user password` / `AUTH password` | 认证（6.0+ 支持用户名） |
| `SELECT n` | 切换 db（**集群仅 db0**） |
| `HELLO [proto]` | RESP 协议握手（RESP3 用 `HELLO 3`，6.0+） |
| `RESET` | 重置连接状态（退出 MULTI / 订阅态） |
| `CLIENT LIST/ID/GETNAME/SETNAME/KILL/UNBLOCK/NO-EVICT/REPLY/TRACKING` | 连接管理族 |

**Server（状态与诊断）**

| 命令 | 作用 |
|------|------|
| `INFO [section]` | 全量/分段状态（memory、persistence、replication、stats、clients、keyspace、cpu…） |
| `DBSIZE` | 当前 db 键数量（不阻塞，近似 O(1)） |
| `CONFIG GET/SET/REWRITE/RESETSTAT` | 读参、热改、回写文件、重置统计 |
| `SLOWLOG GET/LEN/RESET` | 慢查询日志（只记执行耗时，不含排队/网络） |
| `LATENCY DOCTOR/HISTOGRAM/LATEST/GRAPH` | 延迟事件诊断 |
| `MEMORY USAGE/DOCTOR/PURGE/STATS` | 单键内存、诊断建议、碎片整理、统计 |
| `DEBUG SLEEP/SET-ACTIVE-EXPIRE/OBJECT/JMAP` | 调试用（生产慎用，`DEBUG` 可致宕机） |
| `SHUTDOWN [NOSAVE|SAVE]` | 停机（默认按配置持久化后退出） |
| `TIME` | 服务器当前时间 |
| `BGSAVE` / `BGREWRITEAOF` | 触发快照 / AOF 重写（详见持久化篇） |

# 实操要点

**看什么：`INFO` 的高频字段**

```bash
redis-cli INFO memory      # used_memory_human、mem_fragmentation_ratio、maxmemory_policy
redis-cli INFO stats        # instantaneous_ops_per_sec、keyspace_hits/misses、total_connections_received
redis-cli INFO clients      # connected_clients、blocked_clients
redis-cli INFO replication  # role、master_link_status、connected_slaves
redis-cli INFO keyspace     # 各 db 键数与过期分布
```

**慢查询定位**

```bash
CONFIG SET slowlog-log-slower-than 10000   # 超过 10ms(单位微秒)记一条
CONFIG SET slowlog-max-len 128
SLOWLOG GET 10        # 最近 10 条：返回(序号, 时间戳, 耗时μs, 命令...)
SLOWLOG RESET
```

**动态调参 + 落盘（改配置不重启）**

```bash
CONFIG SET maxmemory 2gb          # 运行时生效
CONFIG GET maxmemory-policy
CONFIG REWRITE                    # 把当前运行值写回 redis.conf（需可写）
```

**连接排查**

```bash
CLIENT LIST                       # 看每条连接的 addr、age、idle、cmd、omem(输出缓冲)
CLIENT KILL ID <cid>              # 按 ID 断开异常连接
CLIENT INFO                       # 当前连接自身信息
```

# 避坑

- **`MONITOR` 生产禁用**：它把每条命令实时广播给 monitor 客户端，高 QPS 下严重拖慢服务端甚至打满带宽，只能用于秒级临时诊断（呼应 [070.大key与热key](../08.工程化/070.大key与热key.md)）。
- **`DEBUG` 是双刃剑**：`DEBUG SEGFAULT`、`DEBUG RELOAD` 等可直接让实例宕机或长时间不可用，生产环境应通过 ACL 或 `rename-command` 禁用 `DEBUG`。
- **`SLOWLOG` 不含排队与网络耗时**：它只记命令**执行**耗时——"客户端觉得慢但慢日志没记录"往往是网络/排队/大回复，不是执行慢。且 `SLOWLOG GET n` 会取出并（视配置）消费，读用 `RESET` 前谨慎。
- **`CONFIG GET *` / `KEYS` 类全量操作别在高峰期跑**：`CONFIG GET *` 返回巨大且 `KEYS` 阻塞，大实例上会放大抖动。
- **`CONFIG SET` 不落盘**：热改只在内存生效，重启丢失——确认后要 `CONFIG REWRITE` 或同步改 redis.conf（否则"改了又弹回"）。
- **`SHUTDOWN` 默认会持久化**：不带参数时按 `save` 配置尝试落盘，RDB/AOF 大时停机很慢；确认数据可弃用 `SHUTDOWN NOSAVE`，强求落盘用 `SHUTDOWN SAVE`。
- **`INFO` 是快照不是趋势**：单帧 `INFO` 看不出问题演化，要周期性采集入库做曲线（`instantaneous_ops_per_sec`、`evicted_keys`、`rejected_connections` 的变化率比绝对值更有诊断价值）。

# 总结

Server 命令分两类用法：**观测**（`INFO`/`SLOWLOG`/`LATENCY`/`MEMORY`/`CLIENT LIST` 构成排障四件套）与**操作**（`CONFIG`、`BGSAVE`、`SHUTDOWN`、`DEBUG`）。观测看趋势不看单帧，操作里凡是能阻塞全表的（`MONITOR`/`DEBUG`/`CONFIG GET *`）都要当危险命令对待。把它们和 [09.原理与源码](../09.原理与源码/000.原理与源码概述.md) 的机制对应起来，才知道每个指标背后是什么在消耗资源。
