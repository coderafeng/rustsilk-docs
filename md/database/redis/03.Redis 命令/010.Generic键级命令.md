# 概述

Generic 命令作用于**键（key）本身**，与 value 的具体类型无关：删除、判存、设过期、改名、查类型/编码、遍历键空间等。

- 归属与可用性：Redis 开源核心能力（各命令引入版本见速查表标注）
- 官方文档：<https://redis.io/docs/latest/develop/commands/keyspace/>

> [!tip] 与 [080.了解基础命令](../01.Redis%20起步/080.了解基础命令.md) 的分工
> 起步章从"会用"角度介绍最常用的几条；本篇是**完整参考 + 参数细节 + 避坑**，日常查表以本篇为准。

# 命令速查

| 命令 | 作用 | 关键参数 / 版本 |
|------|------|----------------|
| `DEL key [key...]` | 删除键，返回删除数量 | 大 key 会阻塞主线程 |
| `UNLINK key [key...]` | **异步删除**（后台 lazyfree 回收） | 4.0+；删大 key 首选 |
| `EXISTS key [key...]` | 判断存在，返回存在的数量 | — |
| `TYPE key` | 返回 value 的数据类型 | — |
| `TTL` / `PTTL key` | 剩余过期秒 / 毫秒 | -2=键不存在，-1=无过期 |
| `EXPIRE key seconds [NX\|XX\|GT\|LT]` | 设相对过期 | 7.0+ 支持条件修饰符 |
| `PEXPIRE` / `EXPIREAT` / `PEXPIREAT` | 毫秒 / 绝对时间过期 | `EXPIREAT` 传 UNIX 时间戳 |
| `EXPIRETIME` / `PEXPIRETIME` | 读到期绝对时间戳 | 7.0+ |
| `PERSIST key` | 移除过期时间 | — |
| `RENAME` / `RENAMENX` | 改名 / 不存在才改名 | 覆盖同名目标键 |
| `COPY src dst [DB n] [REPLACE]` | 复制键 | 6.2+ |
| `SCAN cursor [MATCH pat] [COUNT n] [TYPE t]` | **游标遍历键空间** | 生产遍历唯一推荐 |
| `RANDOMKEY` | 随机取一个键 | O(1) |
| `OBJECT ENCODING\|IDLETIME\|FREQ\|REFCOUNT\|HELP key` | 查内部编码/空闲/频次/引用 | `FREQ` 需 LFU 策略 |
| `TOUCH key [key...]` | 批量"访问"以更新 LRU，不取值 | O(1) 语义 |
| `DUMP` / `RESTORE` | 序列化 / 反序列化单键（跨实例搬迁） | `RESTORE` 带 TTL、`REPLACE` |
| `MOVE key db` | 把键移到同实例另一 db | 集群无多 db |

# 高频用法

**过期条件的四种修饰符（7.0+ `EXPIRE`/`EXPIREAT`）**

```text
EXPIRE k 100 NX   # 仅当当前【无】过期时间才设
EXPIRE k 100 XX   # 仅当【已有】过期时间才改
EXPIRE k 100 GT   # 仅当新时间【更晚】才设（延长）
EXPIRE k 100 LT   # 仅当新时间【更早】才设（缩短）
```

**SCAN 游标遍历（分批不阻塞）**

```bash
redis-cli --scan --pattern 'user:*'          # 封装好的扫描
# 手动：cursor 从 0 开始，回传新 cursor，直到再次返回 0 表示完成
redis-cli SCAN 0 MATCH user:* COUNT 1000
```

**大键的"查—删"安全姿势**

```text
MEMORY USAGE bigkey          # 先看真实字节
TYPE bigkey                  # 确认类型
# 集合类可先分批裁剪（HSCAN+HDEL / ZREMRANGEBYRANK），整体删除一律用 UNLINK
UNLINK bigkey
```

# 避坑

- **`KEYS` 禁用**：O(N) 全表扫描且阻塞单线程，生产环境用 `SCAN`（呼应 [070.大key与热key](../08.工程化/070.大key与热key.md)）。
- **`SCAN` 返回的 cursor 要传回、且结果会重复/可能空**：它是"至少遍历一次"弱一致保证，客户端要对结果**去重**；`COUNT` 是每次扫描的提示量不是返回条数。
- **`TTL` 的 -1 与 -2 含义别混**：-2=键不存在，-1=键存在但无过期时间。判断"有没有 TTL"要用 -1。
- **`DEL` 大键 = 自造阻塞**：删含百万成员的集合是 O(N) 主线程操作，一律 `UNLINK`（需 `lazyfree-lazy-user-del` 或直接用 `UNLINK`）。
- **`RENAME`/`COPY` 会覆盖目标键**：`COPY src dst` 若 dst 已存在会报错，除非加 `REPLACE`；`RENAME` 则**静默覆盖** dst——改名前确认目标不存在。
- **`EXPIRE` 非精确闹钟**：过期靠惰性 + 定期删除（见 [09.原理与源码](../09.原理与源码/000.原理与源码概述.md)），到期后 key 不一定立刻消失，只是"读到即过期"；别依赖过期做精确定时任务。
- **`DUMP`/`RESTORE` 跨大版本有兼容风险**：序列化格式随版本变化，跨异构版本搬迁先在小样本验证。
- **`OBJECT FREQ`/`IDLETIME` 依赖淘汰策略**：`FREQ` 仅在 LFU 策略下有值；`IDLETIME` 在 noeviction 下可能不更新——诊断前先确认 `maxmemory-policy`（呼应 [050.Redis配置](../01.Redis%20起步/050.Redis配置.md)）。

# 总结

Generic 命令围绕"**键的生命周期 + 键空间遍历**"两件事：生命周期用 `EXPIRE` 家族（记得 7.0+ 的 NX/XX/GT/LT 条件）、删除一律 `UNLINK` 优先；遍历一律 `SCAN` 游标、客户端去重。自省类 `OBJECT`/`MEMORY`/`TYPE` 是排障利器，但多数依赖淘汰策略配置才能拿到有意义的数据。
