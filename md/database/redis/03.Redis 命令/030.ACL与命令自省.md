# 概述

本篇覆盖两组"元"命令：**ACL（访问控制）** 管理"谁能连、能跑哪些命令、能碰哪些 key"；**COMMAND（命令表自省）** 查询命令自身的元数据（文档、 arity、key 位置、分类）。

- 归属与可用性：ACL 为 Redis **6.0+**（取代旧 `requirepass`/`masterauth` 单一密码模型）；`COMMAND` 族全版本，`COMMAND DOCS` 为 7.0+
- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/management/acl/>、<https://redis.io/docs/latest/develop/commands/reserved-commands/>

# ACL

**用户与规则模型**

- 6.0+ 引入多用户 ACL，每个用户由一组**规则**累积定义；`default` 用户是所有未认证连接的落点。
- `ACL SETUSER <user> [rule...]`：一条命令可叠加多条规则，规则按序生效。

| 规则 | 含义 |
|------|------|
| `on` / `off` | 启用 / 禁用该用户 |
| `>password` / `<password` | 添加 / 移除一个密码 |
| `#<sha1>` | 用 SHA256 存密码（不落明文） |
| `reset` / `resetchannels` | 清空全部权限 / 只清频道权限 |
| `~pattern` | 允许访问匹配该 glob 的 key（`~*` 全放行） |
| `&channel` | Pub/Sub 频道权限（`&*` 全放行） |
| `+command` / `-command` | 允许 / 禁止某命令 |
| `+@category` / `-@all` | 按命令分类批量放行/禁止（如 `+@read`、`-@dangerous`） |
| `allcommands` / `allkeys` / `alldbs` | 全开便捷词 |

**命令族**

| 命令 | 作用 |
|------|------|
| `ACL SETUSER` / `ACL DELUSER` / `ACL LIST` / `ACL GETUSER` | 增删查用户与规则 |
| `ACL WHOAMI` | 当前连接身份 |
| `ACL CAT [category]` | 列出分类 / 某分类下的命令 |
| `ACL LOG [count|RESET]` | 权限拒绝事件日志（排障关键） |
| `ACL GENPASS [bits]` | 生成随机强密码 |
| `ACL SAVE` / `ACL LOAD` | 把内存规则写回 / 从 `aclfile` 重载 |

**实操示例：给应用建一个只能读写 `app:` 前缀、禁危险命令的用户**

```bash
redis-cli ACL SETUSER appuser on '>S3cr3t!pw' '~app:*' '+@read' '+@write' '-@dangerous' 'resetchannels' '&<none>'
redis-cli ACL GETUSER appuser
redis-cli -u redis://appuser:S3cr3t!pw@127.0.0.1:6379   # 用该用户连接
redis-cli ACL LOG 5                                      # 被拒时看这里
```

# COMMAND（命令自省）

| 命令 | 作用 |
|------|------|
| `COMMAND` | 返回全部命令的元数据数组（巨大，勿轻易全量拉） |
| `COMMAND COUNT` | 命令总数 |
| `COMMAND INFO cmd [cmd...]` | 指定命令的 arity/标志/首末 key 步长等 |
| `COMMAND DOCS [cmd...]` | **人读文档**：摘要、复杂度、参数、历史、分类（7.0+） |
| `COMMAND GETKEYS arg...` | 给定一条完整命令，解析出它会操作哪些 key |
| `COMMAND GETKEYSANDFLAGS` | 同时返回 key 及其读写标志（7.0+） |
| `COMMAND LIST [FILTERBY ...]` | 按模块/acl 分类/命名空间过滤列出命令名 |

**用途**：写通用代理/审计工具时，用 `COMMAND GETKEYS` 精确知道某命令动了哪些 key（做 key 级路由、审计、限流），比正则猜参数可靠得多；学习新命令时用 `COMMAND DOCS SET` 直接看官方结构化文档。

# 避坑

- **`requirepass` 在新模型里只是 `default` 用户的一条规则**：只设 `requirepass` 等于给 `default` 加密码但仍拥有全权限——要最小权限必须**新建受限用户**并禁用/收紧 `default`。
- **别把 `default` 用户留在 `on` + `allcommands` + 无密码**：一旦实例暴露，等于开门。生产要么 `ACL SETUSER default off`，要么给它强密码并限权。
- **`-@dangerous` 不是万能**：`@dangerous` 分类覆盖 `KEYS`/`FLUSHALL`/`CONFIG`/`DEBUG` 等，但**不同版本分类内容会变**，别假设一次配好永久够用；`ACL CAT dangerous` 随时复核。
- **ACL 规则顺序敏感、`SETUSER` 是增量修改**：在已有用户上再 `ACL SETUSER u ...` 是**叠加**不是覆盖；想干净重来要先 `ACL SETUSER u reset` 或直接删建。
- **改完不落盘重启即失效**：`ACL SETUSER` 只改内存，实例重启回到 `aclfile`/配置——务必 `ACL SAVE`（前提配了 `aclfile`），否则"权限又回来了"。
- **key 模式漏配导致莫名 NOPERM**：用户 `~app:*` 却访问 `session:1001` 会被拒，排障第一步看 `ACL LOG`——它会明确记是谁、哪条命令、哪个 key 触发了哪种拒绝。
- **`COMMAND`（全量）返回巨大**：调试用 `COMMAND INFO`/`COMMAND DOCS <cmd>` 定向查，别在客户端直接跑裸 `COMMAND` 拉全表。
- **集群/副本下 ACL 要同步**：ACL 配置不会自动传到副本以外的独立实例；多实例部署要让每个实例加载同一份 `aclfile`，避免故障转移后权限漂移。

# 总结

ACL 把"一个密码走天下"升级为"**用户 × 命令 × key × 频道**"的最小权限模型，配三件套必做：收紧 `default`、按业务建受限用户、`ACL SAVE` 落盘 + 用 `ACL LOG` 排障。`COMMAND` 族则是"让 Redis 自己解释自己"——`COMMAND DOCS` 给人看、`COMMAND GETKEYS(ANDFLAGS)` 给工具用，是写代理与审计的基础。两者共同点：**都是关于 Redis 自身、而非关于你的数据的元能力**。
