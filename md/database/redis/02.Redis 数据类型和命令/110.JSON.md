# 概述

Redis 原生存储符合 ECMA-404 标准的结构化 JSON 文档，支持 JSONPath 语法进行细粒度访问和原子更新部分文档，无需序列化/反序列化。

- 归属与可用性：原 RedisJSON 模块，**自 Redis 8.0 起并入开源版**（8.0 前需 Redis Stack）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/json/>

与"String 存 JSON 字符串"的本质区别：文档以**解析后的树结构**存储，读写字段走路径（`$.user.address.city`），更新是服务端原子的，不搬运整个文档。

# 命令速查

| 命令 | 说明 |
|------|------|
| `JSON.SET key $ '<json>'` | 在根路径写入文档（路径非 `$`/`.` 时要求父节点存在） |
| `JSON.GET key [$.path ...] [INDENT n NEWLINE s SPACE c]` | 读整档或指定路径（可多路径、可序列化选项） |
| `JSON.MGET key... $` | 多键取同一路径 |
| `JSON.DEL` / `JSON.FORGET` | 删除路径（两者等价，FORGET 是更名别名） |
| `JSON.NUMINCRBY` / `JSON.NUMMULTBY` | 数值路径原子增减/倍增 |
| `JSON.TOGGLE key $.active` | 布尔取反（原子开关） |
| `JSON.STRAPPEND` / `JSON.STRLEN` | 字符串路径追加/长度 |
| `JSON.ARRAPPEND` / `JSON.ARRINSERT` / `JSON.ARRPOP` / `JSON.ARRTRIM` / `JSON.ARRLEN` / `JSON.ARRINDEX` | 数组路径全套操作 |
| `JSON.OBJKEYS` / `JSON.OBJLEN` | 对象键/字段数 |
| `JSON.CLEAR key $` | 容器清空、数值归零、布尔置 false |
| `JSON.TYPE` / `JSON.DEBUG MEMORY` | 路径类型 / 内存观测 |
| `JSON.MERGE key $ '<partial>'` | 按 RFC 7386 深合并补丁 |
| `JSON.RESP` | 以 RESP 结构返回 |

JSONPath 要点：`$` 根、`$.a.b`、`$.arr[*]`、`$.arr[0:3]` 切片、`$..name` 递归搜索、`[?(@.age > 18)]` 过滤表达式。

# 典型场景

1. **层级对象缓存**：用户档案（内嵌地址/偏好数组）一次 `JSON.SET`，详情页只 `JSON.GET $.profile.avatar`。
2. **原子局部更新**：`JSON.NUMINCRBY $.stats.views 1`、`JSON.TOGGLE $.vip`——告别"GET→改→SET"竞态。
3. **配置中心**：`JSON.MERGE` 下发补丁只覆盖变化的键，不整档替换防误删。
4. **文档型轻数据库**：配合 Query Engine（`FT.CREATE ... ON JSON`）做二级索引 + 复杂查询（见 [Vector Set](./130.Vector%20Set%20向量集合.md) 与官方 search 文档）。

# 避坑

- **8.0 以下环境没有 JSON.\* 命令**：部署前先 `COMMAND DOCS JSON.SET`；老 Stack 版本路径根写法可能是 `.` 而非 `$`（v1/v2 方言差异，2.4+ 默认 JSONPath-v2）。
- **JSON.GET 不带路径 = 整文档序列化**，大文档（MB 级）照样打满带宽——结构化也救不了懒惰的全量读。
- 与 Hash 的选型：扁平少嵌套 → Hash（字段级 TTL、HINCRBY 生态成熟）；层级/数组 → JSON。混用时注意二者**不能互相转换**，迁移要写双写。
- 数值精度为 IEEE 754 double，超大整数（>2^53）会失真——订单号等用字符串存。
- 索引不在 JSON 类型里：需要按字段查询要建 `FT.CREATE`（Query Engine），别拿 `JSON.GET $..x` 全文档扫描当检索。

# 总结

- RedisJSON = "可寻址的文档"：树结构 + JSONPath + 服务端原子局部更新；
- 8.0 起开源版开箱可用，之前版本需 Stack/自行加载模块；
- 与 Hash 互补而非替代：扁平属性选 Hash，嵌套文档选 JSON，复杂检索再加 FT 索引。
