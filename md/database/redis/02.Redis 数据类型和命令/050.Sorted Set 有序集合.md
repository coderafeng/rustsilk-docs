# 概述

Sorted Set 为每个元素关联一个分数（score）并按分数自动排序，支持范围查询和排名操作。

- 归属与可用性：Redis 开源核心类型（1.0+）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/sorted-sets/>

小规模用 **listpack**（`zset-max-listpack-entries` / `zset-max-listpack-value` 默认均 128/64）；超出后转 **跳表 + 哈希表双结构**：跳表维护有序性供范围查询，哈希表维护 member→score 保证 `ZSCORE` O(1)。score 为 double，member 唯一——重复写入即更新分数。

# 命令速查

| 命令 | 说明 | 复杂度 |
|------|------|--------|
| `ZADD key [NX\|XX] [GT\|LT] [CH] [INCR] score m [score m...]` | 写入（GT/LT 6.2+：仅更大/更小时更新） | O(log N) |
| `ZINCRBY key delta m` | 分数原子增减 | O(log N) |
| `ZSCORE` / `ZMSCORE`（6.2+） | 取分数 | O(1) / O(N) |
| `ZRANK` / `ZREVRANK key m [WITHSCORE]` | 升/降排名（WITHSCORE 7.2+） | O(log N) |
| `ZRANGE key start stop [WITHSCORES] [REV] [BYSCORE\|BYLEX] [LIMIT]` | 6.2+ 统一范围查询入口，旧 `ZRANGEBYSCORE`/`ZRANGEBYLEX` 仍可用 | O(log N+M) |
| `ZCOUNT` / `ZCARD` / `ZLEXCOUNT` | 分数区间计数 / 基数 / 字典序区间计数 | O(log N) |
| `ZPOPMIN` / `ZPOPMAX key [count]` / `ZMPOP`（7.0） | 弹出最小/最大 | O(log N*count) |
| `BZPOPMIN` / `BZPOPMAX` | 阻塞弹出（5.0+） | O(log N) |
| `ZREMRANGEBYSCORE` / `BYRANK` / `BYLEX` | 按区间删除 | O(log N+M) |
| `ZUNION` / `ZINTER` / `ZDIFF`（+`*STORE`，`WEIGHTS`/`AGGREGATE`） | 多集合并/交/差（7.0/6.2） | O(1..N*K) |
| `ZRANGESTORE dst src min max` | 范围结果落键（6.2+） | O(log N+M) |
| `ZSCAN key cursor [MATCH p]` | 增量遍历 | O(1)/次 |

# 典型场景

1. **排行榜**：`ZADD rank:game score uid`；`ZREVRANGE rank:game 0 9 WITHSCORES` 取 TOP10，`ZREVRANK rank:game uid` 查我的名次。
2. **延迟队列**：score = 执行时间戳；`ZRANGEBYSCORE delay 0 now LIMIT 0 50` 取到点后必须 **先 ZREM 成功再执行**（或用 Lua/ZPOPMIN 保证唯一消费者），多 Worker 才不会重复执行。
3. **滑动窗口限流**：`ZREMRANGEBYSCORE rl:{uid} 0 now-window` → `ZCARD` 判断 → `ZADD now nonce`（member 带随机后缀防去重坍缩）→ `EXPIRE window`。
4. **同分按字典序检索**（自动补全）：全部 score 置 0，`ZRANGEBYLEX words [w \x00`。
5. **带权多路合并**：`ZUNIONSTORE hot 2 tag:a tag:b WEIGHTS 3 1` 融合热榜。

# 避坑

- **member 唯一 = "追加"会互相覆盖**：限流/打点场景 member 必须拼时间戳或随机数，否则同秒请求只算一次。
- **score 是 double**：整数精确安全区间 ±2^53，更大数值改字典序方案或字符串拆分。
- **`ZRANGE 0 -1` 全量拉巨型 ZSet**：百万成员一步打满带宽——分页 LIMIT 或 `ZSCAN`。参见 [070.大key与热key](../08.工程化/070.大key与热key.md)。
- **`ZADD GT/LT` 与 `ZPOPMIN` 前先看版本**：低版本没有会直接报语法错，部署前用 `COMMAND INFO` 确认。
- 多键命令（ZUNIONSTORE/ZRANGESTORE/LMOVE）Cluster 下同槽约束。
- 延迟队列只进不出会无限膨胀：删除已执行任务 + 设 `EXPIRE` 兜底；"取任务"别用 GET 判断再 ZREM 两步，非原子会被抢。

# 总结

- Sorted Set = Set + 跳表：**排序、排名、范围、优先级**四类需求都归它；
- 6.2+ 起用统一 `ZRANGE`（BYSCORE/BYLEX/REV/LIMIT）即可覆盖旧命令；
- 高并发消费（延迟队列、抢票）的核心是"弹出/删除的原子性"，优先 ZPOPMIN/ZMPOP/Lua，而不是应用层加锁。
