# 概述

String 是二进制安全的字节序列，可存储文本、二进制数据、整数或浮点数，单个 value 最大 512MB。

- 归属与可用性：Redis 开源核心类型（1.0+）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/strings/>

底层以 **SDS（Simple Dynamic String）** 存储：O(1) 取长度、杜绝缓冲区溢出、预留空间减少重分配。按内容分三种编码：纯整数用 `int`，短字符串（≤44 字节）用 `embstr`（一次分配、读写一体），其余用 `raw`。可用 `OBJECT ENCODING key` 查看。

# 命令速查

| 命令 | 说明 | 复杂度 |
|------|------|--------|
| `SET key value [EX s \| PX ms \| EXAT ts \| PXAT ts] [NX \| XX] [KEEPTTL] [GET]` | 写入，可原子携带过期与条件（`GET` 7.0+；8.4 起支持 CAS 比较并设置） | O(1) |
| `GET key` | 读取 | O(1) |
| `GETEX key [EX/PX/...]` | 读取并刷新过期（6.2+） | O(1) |
| `GETDEL key` | 取出并删除，原子"读一次"（6.2+） | O(1) |
| `MSET k1 v1 ...` / `MGET k1 ...` | 批量读写，整批原子 | O(N) |
| `MSETEX numkeys k1 v1 ... [NX \| XX] [EX/PX/EXAT/PXAT/KEEPTTL]` | 多键写入 + **共享过期**，单命令原子（8.4+） | O(N) |
| `SETNX key value` / `SETEX key s value` | 旧式写法，等价 `SET ... NX` / `SET ... EX` | O(1) |
| `INCR` / `INCRBY n` / `INCRBYFLOAT f` / `DECR` / `DECRBY n` | 原子增减（整数 64 位，超界报错） | O(1) |
| `INCREX key [BYINT/BYFLOAT n] [LBOUND/UBOUND] [SATURATE] [EX/PX/...] [ENX]` | 增减 + 上下界 + 过期一体的**窗口限流原语**（8.8+） | O(1) |
| `DELEX key [IFEQ v \| IFNE v \| IFDEQ digest \| IFDNE digest]` | 按值/摘要**条件删除**，免“先 GET 再 DEL”的竞态（8.4+） | O(1)* |
| `DIGEST key` | 返回值的密码学摘要，配合 `DELEX IFDEQ` 做乐观并发控制（8.4+） | O(N) |
| `APPEND key value` / `STRLEN key` | 追加 / 取长度 | O(1)* |
| `SETRANGE` / `GETRANGE` | 按偏移写 / 读子串 | O(len) |
| `TYPE` / `TTL` / `EXPIRE` / `PERSIST` | 键级通用操作 | O(1) |

*APPEND 均摊 O(1)；DELEX 的 IFEQ/IFNE 为 O(1)，IFDEQ/IFDNE 为 O(N)。

# 典型场景

1. **缓存对象**：`SET art:1024 '<json>' EX 300`——缓存必须带 TTL，避免脏数据永驻。
2. **计数器**：`INCR page:view:1024`；限流场景 8.8+ 可直接用原子窗口限流命令 `INCREX key BYINT 1 UBOUND 100 EX 60`（超界配合 `SATURATE` 饱和或报错拒绝），不再需要 Lua 拼装；8.4+ 批量写入 + 统一 TTL 用 `MSETEX`（见 [Redis 8.8 版本特性](../10.Redis%20版本特性/080.Redis8.8.md)）。
3. **分布式锁**：`SET lock:order NX PX 30000`，value 存"随机令牌"，解锁用 Lua 比较令牌后删除——详见 [020.事务与分布式锁](../08.工程化/020.事务与分布式锁.md)。
4. **一次性令牌/验证码**：`GETDEL` 原子取出，天然防重放。
5. **局部更新**（不落整对象）：`INCRBYFLOAT balance 10.5`。
6. **安全的“检查再删”**：缓存锁/会话销毁时 `DIGEST` + `DELEX key IFDEQ <digest>`，单命令完成“确认内容未变才删除”，避免读后写间隙被其他客户端更新的竞态（8.4+）。

# 操作示例

## 班级档案缓存：写入-读取-失效闭环

```bash
# 查库后回填缓存，300 秒过期（样本数据见 01 章 090.样本数据）
redis-cli SET "cache:class:C1:profile" '{"class_id":"C1","name":"初三(1)班"}' EX 300
redis-cli GET "cache:class:C1:profile"
# 班主任变更后直接作废缓存，下次请求重建
redis-cli DEL "cache:class:C1:profile"
```

先更新数据库、再删缓存（Cache Aside），不要双写改缓存，避免旧值残留。

## 登录验证码：GETDEL 一次性核销

```bash
# 家长手机号 13800000001（S001 张伟）登录查学情，验证码 5 分钟有效
redis-cli SET "otp:13800000001" "482913" EX 300
# 核销时原子取出并删除：第二个请求拿到 nil，无法重放
redis-cli GETDEL "otp:13800000001"
```

## 成绩导入接口限流：INCREX（8.8+）

```bash
# 教师端每分钟最多提交 100 次导入请求，首次自增时设置 TTL——旧版 INCR + EXPIRE + 比较三步合一
redis-cli INCREX "rl:score:import:teacher:吴刚" BYINT 1 UBOUND 100 EX 60
# 饱和模式：超界不报错、钉在 100，适合只要“封顶计数”的仪表盘
redis-cli INCREX "rl:score:import:teacher:吴刚" BYINT 1 UBOUND 100 SATURATE
```

## 安全的锁释放：DIGEST + DELEX（8.4+）

```bash
# C1 成绩批量导入前抢锁：SET NX PX 带随机 token
redis-cli SET "lock:score:import:C1" "a7f3c1e2-8b45-4d1a-9c77-2f6b8d0e1a34" NX PX 60000
digest=$(redis-cli DIGEST "lock:score:import:C1")   # 读出内容时登记摘要
redis-cli DELEX "lock:score:import:C1" IFDEQ "$digest"   # 内容没变才删；返回 0 = 已被他人接管
```

等价于传统“GET 比对 + Lua DEL”两步拼装，服务端单命令完成，没有读后写间隙。

## 期中报表多键同生共死：MSETEX（8.4+）

```bash
# E2 数学分析页的多个统计键一次写入、共享过期，7 天后整体自动下线
redis-cli MSETEX 3 "exam:E2:SUB2:avg" "93.4" "exam:E2:SUB2:pass_rate" "0.8" "class:C1:score_sum:E2" "2282" EX 604800
redis-cli MGET "exam:E2:SUB2:avg" "exam:E2:SUB2:pass_rate"   # "93.4" / "0.8"
```

# 避坑

- **MSET/MGET 在 Cluster 下**跨槽键会报 CROSSSLOT，用 hash tag（如 `{user:1000}:name`）把关联键约束到同槽，但注意热点槽倾斜。
- **SETNX + EXPIRE 两条命令非原子**：中间宕机留下"永不失效的死锁"——必须用单条 `SET ... NX EX`。
- **大 value（MB 级）**：拖慢网络与主从复制、过期删除时阻塞——拆字段转 Hash 或压缩存储，删除用 `UNLINK`。参见 [070.大key与热key](../08.工程化/070.大key与热key.md)。
- **INCR 到 2^63-1 报错** `ERR increment would produce NaN`；负数用 DECRBY。
- 对非 String 键执行 `GET` 返回 `WRONGTYPE`——先 `TYPE` 判断或保证键空间隔离。
- `GETRANGE`/`SETRANGE` 越界读返回空、越界写自动补零扩展，注意恶意撑大键。

# 总结

- String 是最基础也最高频的类型：缓存、计数、锁、令牌四大件离不开它；
- 写操作优先用带选项的单条 `SET`（NX/XX/EX/KEEPTTL），拒绝多命令拼装；
- 原子性是 Redis 的价值所在——凡"判断再修改"，先查有没有单命令方案（SET NX、GETDEL、INCREX、CAS）。
