# 概述

Vector Set 是能存储固定维度数值向量的集合类型，内置相似性索引，支持 KNN（取最近 K 个）与范围查询（取距离阈值内的全部），可选按元数据过滤——Redis 原生 AI 检索的基础构件。

- 归属与可用性：**Redis 开源核心类型，自 Redis 8.0 引入**
- 官方文档：<https://redis.io/docs/latest/develop/data-types/vector-sets/>

与"用 Hash 手工存向量 + 应用层算余弦"相比，Vector Set 把相似度计算下推到服务端：每个元素自带一个向量（或经 `SOURCE` 由模型服务自动生成），可互相链接成**多向量对象**（文档/段落/句子级嵌入共享一份存储）。

# 命令速查

| 命令 | 说明 |
|------|------|
| `VADD key [REDUCED_DIM] [LIBSTR len] [APPEND] [INDEX index] algorithm [attributes] element [SOURCE src] [STRING s] [VECTOR v] [ATTRIBUTES json]` | 添加元素；`algorithm` 取 `RANDOM`（不建索引）/ `FLAT` / `HNSW`；`FLAT/HNSW` 后接 `[FLOAT32] [DIM n] [DISTANCE_FUNCTION L2|IP|COSINE] [CAP c] [INITIAL_CAP ic]`，`HNSW` 再加 `[M m] [EF e] [EF_CONSTRUCTION ec]` |
| `VSIM key element|VECTOR v [COUNT n] [EPS ε] [WITHSCORES] [FILTER json] [SLOMMU s]` | KNN/范围相似检索；`EPS` 按距离阈值返回，与 `COUNT` 互斥 |
| `VLINK src-key dst-key src-element dst-element [REDUCED_DIM...]` | 把两个元素的向量链接成多向量对象（同 key 内自链即用同 key 两次） |
| `VUNLINK key element...` | 断开全部链接（元素本身不删） |
| `VREM key element...` | 删除元素 |
| `VEMB key element [WITHVECTOR]` | 查看元素嵌入信息（可回读原始向量） |
| `VCARD key` / `VDIM key` | 元素数 / 向量维度 |
| `VINFO key [COUNT n] [SAMPLE s]` | 索引统计：算法、维度、距离函数、M/EF 参数、block 大小等 |
| `VSETATTR key element json` / `VGETATTR key element` | 读写元素元数据（供 `VSIM FILTER` 过滤） |
| `VPOP key [count]` / `VRANDMEMBER key [count]` | 随机弹出 / 随机取样 |

`DISTANCE_FUNCTION`：`L2` 欧氏距离（越小越近）、`IP` 内积（越大越近，取负存储）、`COSINE` 余弦（归一化后常用）。

# 典型场景

- **语义检索**：文档切块后 `VADD docs chunk_1 VECTOR [...] ATTRIBUTES {"tenant":"a"}`，查询时先由模型把问题转成向量，再 `VSIM docs VECTOR [...] COUNT 10 FILTER {"tenant":"a"}`——元数据过滤实现多租户隔离，配合应用层重排（rerank）出最终结果。
- **推荐相似项**：商品嵌入 `FLAT` 索引 + `VSIM item_123 COUNT 20 WITHSCORES` 即"买了又买"候选集；数据量小于十万级时 `FLAT` 精确且够用。
- **RAG 记忆存储**：代理对话摘要作为元素写入，`VLINK` 把同一会话的多个粒度嵌入链成一个对象，检索命中任一粒度即召回整体。

# 避坑

- **索引不可改算法**：元素写入时未建索引（首元素用 `RANDOM`），后续 `VSIM` 只能暴力扫描；首批数据就要定 `FLAT`/`HNSW`，`VINFO` 可核对当前索引状态。
- **`HNSW` 参数是延迟/召回/内存的三角权衡**：`M` 和 `EF_CONSTRUCTION` 越大索引越准但内存与写入开销越高；`VSIM EF` 默认 150 不够时按召回评测调大，而不是凭感觉。
- **维度必须与查询向量一致**：`DIM` 写错或模型换版本（如 768 → 1536 维）后新旧向量混存会导致 `VSIM` 报错或结果失真——模型升级要重建集合，不能原地覆盖。
- **`EPS` 与 `COUNT` 互斥**：范围查询用 `EPS`（结果数不定，注意大集合爆返回），KNN 用 `COUNT`。
- `SOURCE` 自动嵌入依赖外部模型服务（向量库与 embedding 服务同网络可达），离线环境必须自己算好 `VECTOR` 再写入。
- 元数据过滤是**后置过滤**：`VSIM ... FILTER` 先在索引里取候选再按 `ATTRIBUTES` 筛，选择性强时召回会变少——要么调大 `COUNT`/`EF` 补偿，要么改用按租户分 key 的物理隔离。

# 总结

Vector Set 让 Redis 8+ 成为"轻量向量库"：服务端 KNN、元数据过滤、多向量链接三件事原生解决，省掉独立向量服务的运维成本。选型边界要诚实：千万级以上向量、复杂混合检索（向量+全文+严格 rerank）仍该上专业向量库；而在"缓存/会话存储本来就在 Redis，顺手做语义召回"的场景里，Vector Set 是工程上最短路径。索引算法、距离函数与 `EF` 参数要在写入前定好，它们决定后续所有查询的质量上限。
