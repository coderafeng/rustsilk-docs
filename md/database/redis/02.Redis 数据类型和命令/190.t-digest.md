# 概述

t-digest 是分位数估计结构：用"质心（centroid）压缩"的草图（sketch）流式接收观测值，直接回答 P50/P99/任意分位与 CDF（某值的百分位），无需保存原始数据。

- 归属与可用性：原 RedisBloom 模块能力，**自 Redis 6.2 起并入开源版**
- 官方文档：<https://redis.io/docs/latest/develop/data-types/probabilistic/t-digest/>

它专为"延迟分布"这类问题设计：**P99 不能靠平均值推断**，而"存全量样本再排序"内存不可承受。t-digest 把观测值聚成质心并在两端保留更高精度，头部/尾部误差极小——正好是分位数最被关注的区域。

# 命令速查

| 命令 | 说明 |
|------|------|
| `TDIGEST.CREATE key [COMPRESSION c]` | 创建；`COMPRESSION` 默认 100，越大越准越费内存（内存约 `50 × c` 字节量级） |
| `TDIGEST.ADD key value [value ...]` | 添加观测值（浮点） |
| `TDIGEST.MERGE destkey numkeys source [source ...] [COMPRESSION c] [OVERRIDE]` | 合并多草图（`OVERRIDE`：目标已存在时覆盖而非报错） |
| `TDIGEST.MIN key` / `TDIGEST.MAX key` | 最小/最大观测值 |
| `TDIGEST.QUANTILE key q [q ...]` | 分位数：`q` 为 0~100 的百分数，如 `50 95 99` |
| `TDIGEST.CDF key v [v ...]` | 反向查询：值 `v` 处于第几百分位（≤ v 的数据占比） |
| `TDIGEST.TRIMMED_MEAN key low_cut_percent high_cut_percent` | 去掉两端尾部后的均值 |
| `TDIGEST.RANK key v...` / `TDIGEST.REVRANK` | 值的升/降序排名（估计） |
| `TDIGEST.BYRANK` / `TDIGEST.BYREVRANK` | 按排名取近似值 |
| `TDIGEST.RESET key` / `TDIGEST.INFO key` | 清空复用 / 元数据（compression、capacity、观察数、质心数等） |

# 典型场景

- **接口延迟 SLI**：每个请求 `TDIGEST.ADD latency:api 23.5`，大盘直接 `TDIGEST.QUANTILE latency:api 50 95 99`；比"平均值 + 最大值"诚实得多，也能稳定回答"P99 是否超 200ms"。
- **窗口合并**：按分钟建 sketch，小时/日报表 `TDIGEST.MERGE` 合并原始分钟草图——分位数**不可跨窗口直接平均**，合并草图是唯一数学上站得住的做法。
- **异常值审计**：`TDIGEST.CDF latency:api 1000` 看"1 秒以上占比"，或 `TRIMMED_MEAN 5 95` 去极值均值做成本分析。

# 避坑

- **必须先 `TDIGEST.CREATE` 再 `ADD`**：与多数结构"写即建"不同，未创建直接 `ADD` 会报错——初始化要走在前面（模块默认参数亦可通过 `TDIGEST.CREATE` 显式指定）。
- **分位数只认 `QUANTILE`，别拿 CDF 凑**：`CDF` 回答"这个值排第几百分位"，`QUANTILE` 回答"第 N 百分位是多少"，方向相反，监控面板里两者混用是最常见的读图错误。
- **`COMPRESSION` 不是越大越好**：精度与内存、写入开销同涨；对 P99 误差容忍 ±1% 时默认 100 已够，金融级精度再上探。
- **空 sketch 的查询返回是陷阱**：未写入任何观测值时，`QUANTILE`/`CDF`/`MIN`/`MAX` 会返回 `nan`/`-inf`/nil 而非报错——聚合与看板渲染前先判 `TDIGEST.INFO` 的 `observation_count`。
- **`MERGE` 后目标不可回退成员**：合并是有损压缩，保留原始分钟草图再按需合并，别把合并结果当唯一真相。

# 总结

t-digest 解决的是分布类指标的根本矛盾：**要分位数，但不要存全量**。把它当成"延迟/成本/规模三类指标的官方容器"即可：写入端一行 `ADD`，看板端 `QUANTILE`，窗口端 `MERGE`。三条纪律保住可信度——先建后用、分位与 CDF 分清方向、保留原始窗口草图再做合并汇总。与 Top-K/CMS 的分工也清楚：它们管"谁最频繁"，t-digest 管"数值长什么样"。
