# 概述

List 是按插入顺序排列的字符串序列，底层为快速链表（quicklist），支持两端压入/弹出。

- 归属与可用性：Redis 开源核心类型（1.0+）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/lists/>

quicklist = 双向链表串起若干 **listpack 节点**：兼顾链表的两端 O(1) 插删与数组的紧凑内存。节点大小由 `list-max-listpack-size` 控制，`list-compress-depth` 可对中间节点 LZF 压缩（两端保持解压以快读写）。

# 命令速查

| 命令 | 说明 | 复杂度 |
|------|------|--------|
| `LPUSH` / `RPUSH key v [v...]` | 左/右插入（`LPUSHX`/`RPUSHX` 仅键存在时插） | O(N) |
| `LPOP` / `RPOP key [count]` | 左/右弹出（带 count 6.2+） | O(count) |
| `LRANGE key start stop` | 区间读取，负索引表示倒数 | O(S+N) |
| `LINDEX key i` | 按位置取（自动从较近端遍历） | O(N) |
| `LSET key i v` | 覆盖指定位置（两端 O(1)） | O(N) |
| `LINSERT key BEFORE\|AFTER pivot v` | 在参照值前/后插入 | O(N) |
| `LREM key count value` | 按值删除（count>0 从头、<0 从尾、0 全部） | O(N) |
| `LTRIM key start stop` | 原地裁剪到区间 | O(N) |
| `LLEN key` | 长度 | O(1) |
| `LMOVE src dst L\|R L\|R` | 原子两列表迁移（7.0；`BLMOVE` 6.2 阻塞版） | O(1) |
| `BLPOP` / `BRPOP keys... timeout` | 阻塞弹出，多键按序轮询 | O(1) |
| `LPOS key element [RANK n] [COUNT n]` | 查值的下标（6.0.6+） | O(N) |

# 典型场景

1. **固定长度时间线**：`LPUSH timeline:uid msg` + `LTRIM timeline:uid 0 99`，天然保留最新 100 条。
2. **生产者-消费者队列**：`RPUSH jobs task` 生产、`BRPOP jobs 0` 消费，阻塞式免轮询。
3. **可靠队列**：`LMOVE jobs processing RIGHT LEFT`（7.0 前用 `BRPOPLPUSH`）把任务原子挪到处理中列表，完成后再从 processing `LREM`，宕机可回捞。
4. **栈**：LPUSH/LPOP 同端进出即 LIFO。
5. **简单最新榜单**：`LRANGE key 0 9` 取首页；需要分数排序时改用 [Sorted Set](./050.Sorted%20Set%20有序集合.md)。

# 避坑

- **不要用 List 随机访问中间元素**：`LINDEX`/`LSET` 中间位置是 O(N)，大列表里高频访问中部请换 Hash/ZSet。
- **无界增长**：只 `RPUSH` 不 `LTRIM`/不消费，内存迟早打满——生产队列必须有消费端与水位告警（`LLEN` 监控）。参见 [070.大key与热key](../08.工程化/070.大key与热key.md)。
- **`BLPOP key 0` 永久阻塞**：客户端默认 socket 超时可能直接断连；阻塞命令会占用连接，控制连接池里的阻塞连接数量，别让大量 `BLPOP` 挂满 maxclients。
- **LMOVE 跨槽**：Cluster 下 src/dst 必须同槽（hash tag），否则 CROSSSLOT。
- `LREM` 大列表按值删除 O(N)，高频按值删改考虑 Hash 建模。
- List **不能给元素单独设 TTL**，过期只能整键——需要逐元素过期用 Stream 或 ZSet 打分。

# 总结

- List 适合"顺序 + 两端操作"：时间线、简单队列、栈，一页 `LRANGE` 搞定分页；
- 阻塞弹出（BLPOP/BLMOVE）是 Redis 做轻量任务队列的核心机制，但可靠性要求高时应选 Stream；
- 任何 O(N) 命令（LREM/LSET 中部/超长 LRANGE）都要先评估列表长度上限。
