# 概述

List 是按插入顺序排列的字符串序列，底层为快速链表（quicklist），支持两端压入/弹出。

- 归属与可用性：Redis 开源核心类型（1.0+）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/lists/>

quicklist = 双向链表串起若干 **listpack 节点**：兼顾链表的两端 O(1) 插删与数组的紧凑内存。节点大小由 `list-max-listpack-size` 控制，`list-compress-depth` 可对中间节点 LZF 压缩（两端保持解压以快读写）。**7.0 起提供多键弹出 `LMPOP`/`BLMPOP`**，**8.10 起新增批量原子迁移 `LMOVEM`/`BLMOVEM`**（一次搬 N 个元素），List 队列的批量吞吐能力补齐。

# 命令速查

| 命令 | 说明 | 复杂度 |
|------|------|--------|
| `LPUSH` / `RPUSH key v [v...]` | 左/右插入（`LPUSHX`/`RPUSHX` 仅键存在时插） | O(N) |
| `LPOP` / `RPOP key [count]` | 左/右弹出（带 count 6.2+） | O(count) |
| `LRANGE key start stop` | 区间读取，负索引表示倒数 | O(S+N) |
| `LINDEX key i` | 按位置取（自动从较近端遍历） | O(N) |
| `LSET key i v` | 覆盖指定位置（两端 O(1)） | O(N) |
| `LINSERT key BEFORE\|AFTER pivot v` | 在参照值前/后插入 | O(N) |
| `LREM key count value` | 按值删除（count>0 从头、<0 从尾、0 全部） | O(N) |
| `LTRIM key start stop` | 原地裁剪到区间 | O(N) |
| `LLEN key` | 长度 | O(1) |
| `LMOVE src dst L\|R L\|R` | 原子两列表迁移（7.0；`BLMOVE` 6.2 阻塞版） | O(1) |
| `LMOVEM src dst <L\|R> <L\|R> [COUNT n \| EXACTLY n] [OBO \| BULK]` | **批量**原子迁移并返回元素（8.10+）；`OBO`=不足 n 也搬、`BULK`=凑够才搬 | O(N) |
| `BLMOVEM src dst <L\|R> <L\|R> timeout [COUNT n \| EXACTLY n] [OBO \| BULK]` | `LMOVEM` 的阻塞版（8.10+） | O(N) |
| `BLPOP` / `BRPOP keys... timeout` | 阻塞弹出，多键按序轮询 | O(1) |
| `LMPOP` / `BLMPOP numkeys keys... LEFT\|RIGHT [COUNT n]` | 多键优先级弹出（7.0+） | O(N) |
| `LPOS key element [RANK n] [COUNT n]` | 查值的下标（6.0.6+） | O(N) |

# 典型场景

1. **固定长度时间线**：`LPUSH timeline:uid msg` + `LTRIM timeline:uid 0 99`，天然保留最新 100 条。
2. **生产者-消费者队列**：`RPUSH jobs task` 生产、`BRPOP jobs 0` 消费，阻塞式免轮询。
3. **可靠队列**：`LMOVE jobs processing RIGHT LEFT`（7.0 前用 `BRPOPLPUSH`）把任务原子挪到处理中列表，完成后再从 processing `LREM`，宕机可回捞；批量领取用 `LMOVEM jobs processing RIGHT LEFT COUNT 10 OBO`，一次取一批、少 N-1 次往返（8.10+）。
4. **批量搬运/合并**：把临时队列整体并入主队列 `LMOVEM tmp main RIGHT LEFT OBO`——源列表搬空后键自动删除，不留空键。
5. **栈**：LPUSH/LPOP 同端进出即 LIFO。
6. **简单最新榜单**：`LRANGE key 0 9` 取首页；需要分数排序时改用 [Sorted Set](./050.Sorted%20Set%20有序集合.md)。

# 操作示例

## 点名册：两端读写与分页

```bash
# 样本数据：C1 点名顺序（学号从前往后）
redis-cli RPUSH "class:C1:roll_call" S001 S002 S003 S004 S005
redis-cli LLEN "class:C1:roll_call"                 # (integer) 5
redis-cli LRANGE "class:C1:roll_call" 0 2           # 前三位：S001 S002 S003
redis-cli LINDEX "class:C1:roll_call" -1            # 最后一位：S005
```

## 成绩批改队列（阻塞式）

```bash
# 教师提交待批改任务
redis-cli RPUSH "queue:grading:SUB2" "S001:SUB2:E2" "S004:SUB2:E2"
# 助教消费：最多阻塞 30 秒，超时返回空后继续轮询下一轮
redis-cli BLPOP "queue:grading:SUB2" 30
```

## 可靠队列：doing 列表兜底

```bash
# 领任务时原子搬到处理中列表
redis-cli LMOVE "queue:grading:SUB2" "doing:grading:SUB2" RIGHT LEFT
# 批改完成后从 doing 移除（“签收”）
redis-cli LREM "doing:grading:SUB2" 1 "S001:SUB2:E2"
# 消费者宕机：任务仍在 doing，巡检脚本可归还未完成项
redis-cli LRANGE "doing:grading:SUB2" 0 -1
```

## 批量领取：LMOVEM（8.10+）

```bash
# 一次最多搬 5 份试卷，不足 5 也搬（OBO），网络往返降到 1/5
redis-cli LMOVEM "queue:grading:SUB2" "doing:grading:SUB2" RIGHT LEFT COUNT 5 OBO
# 严格整批：凑够 5 份才动（BULK），适合流水线批量录分
redis-cli LMOVEM "queue:grading:SUB2" "batch:grading:SUB2" RIGHT LEFT EXACTLY 5 BULK
```

## 固定长度成绩历史

```bash
# 样本数据：S001 数学历史，最近一次放最前（E3=106、E2=108、E1=100）
redis-cli LPUSH "student:S001:SUB2:history" 110
redis-cli LTRIM "student:S001:SUB2:history" 0 9     # 只保留最近 10 次考试
redis-cli LRANGE "student:S001:SUB2:history" 0 -1   # 110 106 108 100
```

# 避坑

- **不要用 List 随机访问中间元素**：`LINDEX`/`LSET` 中间位置是 O(N)，大列表里高频访问中部请换 Hash/ZSet。
- **无界增长**：只 `RPUSH` 不 `LTRIM`/不消费，内存迟早打满——生产队列必须有消费端与水位告警（`LLEN` 监控）。参见 [070.大key与热key](../08.工程化/070.大key与热key.md)。
- **`BLPOP key 0` 永久阻塞**：客户端默认 socket 超时可能直接断连；阻塞命令会占用连接，控制连接池里的阻塞连接数量，别让大量 `BLPOP` 挂满 maxclients。
- **LMOVE 跨槽**：Cluster 下 src/dst 必须同槽（hash tag），否则 CROSSSLOT；`LMOVEM`/`BLMOVEM` 同理。
- **`LMOVEM` 搬空即删键**：源列表元素全部迁走后键被删除，监听该键是否存在（如 `keyspace` 通知）的逻辑要注意语义；`BULK` 模式下凑不够 `EXACTLY n` 不会搬运，与 `OBO` 的行为差异要先测。
- `LREM` 大列表按值删除 O(N)，高频按值删改考虑 Hash 建模。
- List **不能给元素单独设 TTL**，过期只能整键——需要逐元素过期用 Stream 或 ZSet 打分。

# 总结

- List 适合"顺序 + 两端操作"：时间线、简单队列、栈，一页 `LRANGE` 搞定分页；
- 阻塞弹出（BLPOP/BLMOVE/BLMOVEM）是 Redis 做轻量任务队列的核心机制，但可靠性要求高时应选 Stream；
- 任何 O(N) 命令（LREM/LSET 中部/超长 LRANGE）都要先评估列表长度上限。
