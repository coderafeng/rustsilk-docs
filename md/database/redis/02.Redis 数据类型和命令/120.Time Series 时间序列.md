# 概述

Time Series 是以时间戳为键的数值序列，专为监控指标、传感器数据、金融行情等时序场景设计，支持高精度时间戳、标签索引、降采样聚合与多种保留策略。

- 归属与可用性：原 RedisTimeSeries 模块，**自 Redis 8.0 起并入开源版**（8.0 前需 Redis Stack）
- 官方文档：<https://redis.io/docs/latest/develop/data-types/timeseries/>

每条时间序列是"一个 key + 若干 `(时间戳, 数值)` 样本"，可附加**标签（labels）**用于跨序列的维度查询（类似 Prometheus 的 label）。底层样本以 **Gorilla 压缩**存入固定大小 block（默认 256 样本），内存占用远小于裸存储。8.x 持续加码查询面：**8.8 起单条命令可叠加多个聚合器**，**8.10 起新增按时间戳分组跨序列的 `TS.NRANGE`、阻塞式读取 `TS.READ`、标签元数据自省 `TS.QUERYLABELS`**（见 [Redis 8.10](../10.Redis%20版本特性/090.Redis8.10.md)）。

# 命令速查

| 命令 | 说明 |
|------|------|
| `TS.CREATE key [RETENTION ms] [LABELS k v ...] [CHUNK_SIZE n] [DUPLICATE_POLICY policy]` | 创建序列；`RETENTION` 为样本保留时长（0 为永久，默认 0） |
| `TS.MCREATE key... [SAME_LABELS ...]` | 批量创建 |
| `TS.ADD key ts value [RETENTION ...] [DUPLICATE_POLICY policy]` | 追加样本（`ts` 用 `*` 取服务端当前时间；键不存在时自动创建） |
| `TS.MADD key ts value [key ts value ...]` | 多序列批量写入 |
| `TS.INCRBY` / `TS.DECRBY key delta [TIMESTAMP ts]` | 原子增减（计数器场景） |
| `TS.RANGE` / `TS.REVRANGE key from to [FILTER_BY_VALUE min max] [FILTER_BY_TS ts...] [COUNT n] [ALIGN a AGGREGATION ag1 [ag2...] bucketDur [BUCKETTIMESTAMP <start\|-\|end\|+\|mid\|~>] [EMPTY]]` | 单序列读，可聚合降采样；多聚合器叠加（8.8+） |
| `TS.MRANGE` / `TS.MREVRANGE from to FILTER labelSelector... [GROUPBY label REDUCE func] [EXCLUDEEMPTY]` | 按标签跨多序列查询，`GROUPBY` 可再聚合；`EXCLUDEEMPTY` 剔除无样本序列（8.10+） |
| `TS.NRANGE` / `TS.NREVRANGE numkeys key... from to [AGGREGATION ag1 [ag2...] bucketDur ...]` | 指定多序列范围查询，结果**按时间戳分组**对齐（8.10+） |
| `TS.READ key ts [BLOCK ms min count] [MAX COUNT n]` | 读 ts 起最多 n 个样本；`BLOCK` 等到足量样本为止（8.10+） |
| `TS.GET` / `TS.MGET FILTER ... [SELECTED_LABELS ...]` | 取各序列最后一样本 |
| `TS.ALTER` / `TS.DEL` / `TS.DELETERANGE` | 改属性 / 删样本 |
| `TS.QUERYINDEX labelSelector...` | 按标签过滤查序列 key |
| `TS.QUERYLABELS <LABELS \| VALUES label> [FILTER ...]` | 枚举标签名/标签值，做前端维表下拉（8.10+） |
| `TS.INFO key` | 元数据（保留策略、chunk、压缩量、最大最小时间戳等） |

标签选择器语法：`label=value`、`label!=value`、`label=(v1,v2)`（或）、`label=`（匹配不存在该标签的序列）。

# 典型场景

- **主机/服务指标存储**：`label=cpu` 的延迟样本，写入 `TS.ADD`，告警侧 `TS.MRANGE ... FILTER env=prod,service=api GROUPBY host REDUCE max` 一次拉齐多机曲线。
- **降采样报表**：原始秒级数据 90 天（`RETENTION 7776000000`），`AGGREGATION avg 3600000` 出小时级曲线给大盘；8.0+ 支持**多层保留/降采样**（多分辨率组合），冷热数据自动分层。
- **业务计数器**：`TS.INCRBY` 带 `TIMESTAMP *` 记录下单量，`TS.MGET FILTER region=*` 取各区域最新值。
- **多机曲线对齐画图**：`TS.NRANGE 3 cpu:host1 cpu:host2 cpu:host3 - + AGGREGATION avg 60000` 一条命令拿到同一时间栅格下的对齐序列，不用再在应用层按时间戳 join（8.10+）；大盘轮询也可改 `TS.READ key last_ts BLOCK 30000 1` 长轮询新样本，减空转。
- **一次查询多种统计**：8.8+ 多聚合器——`AGGREGATION avg max min 60000` 单命令同时出均值包络与尖峰，告警回测少 N 倍往返。

# 操作示例

## 成绩序列：建序列、写入、读曲线

```bash
# 样本：S001 数学成绩，标签带学生/科目/班级/学期
redis-cli TS.CREATE "ts:S001:SUB2" LABELS student S001 subject SUB2 class C1 term 2024S1
redis-cli TS.ADD "ts:S001:SUB2" 1727481600000 100    # E1 第一次月考
redis-cli TS.MADD "ts:S001:SUB2" 1731024000000 108 "ts:S002:SUB2" 1731024000000 96    # E2 批量写入
# 全量采样点（按考试时间升序）
redis-cli TS.RANGE "ts:S001:SUB2" - +
```

## 多学生曲线对齐与跨序列聚合

```bash
# 8.10+：两名学生按同一时间栅格分组返回，前端直接画双曲线
redis-cli TS.NRANGE 2 "ts:S001:SUB2" "ts:S002:SUB2" - + ALIGN 0 AGGREGATION avg 86400000
# 8.8+ 多聚合器：同时拿均值与峰值
redis-cli TS.NRANGE 2 "ts:S001:SUB2" "ts:S003:SUB2" - + AGGREGATION avg max 86400000
# 按标签匹配 C1 全体，每次考试取全班最高分
redis-cli TS.MRANGE - + FILTER class=C1 subject=SUB2 GROUPBY exam REDUCE max
```

## 长轮询新成绩（8.10+）

```bash
# 从上次读到的时间戳继续；最多等 30s，至少积 1 个新样本就返回，单次上限 10
redis-cli TS.READ "ts:S001:SUB2" 1731024000000 BLOCK 30000 1 MAX COUNT 10
```

## 前端筛选下拉（8.10+）

```bash
redis-cli TS.QUERYLABELS LABELS FILTER class=C1          # 列出 C1 序列的全部标签名
redis-cli TS.QUERYLABELS VALUES student FILTER class=C1  # 列出 student 标签的可选值
redis-cli TS.QUERYINDEX class=C1 subject=SUB2           # 命中的序列 key 列表
```

# 避坑

- **乱序写入被 `DUPLICATE_POLICY` 拒绝**：默认 `BLOCK` 直接报错。允许乱序要显式设 `LAST`/`MAX`/`MIN`/`SUM`；`REPLICA` 策略专用于高可用多活写放大去重。
- **`RETENTION` 是相对服务端当前时间的滑动窗口**，不是绝对过期；`TS.RANGE` 查询超出保留窗口的区间返回空而非报错，别把"没数据"当"数据为零"。
- **`TS.MRANGE` 不带 `FILTER` 全量匹配**是典型大查询，序列多时一次拉爆内存；先 `TS.QUERYINDEX`/`TS.QUERYLABELS` 估算基数。
- **`TS.READ` 的 `BLOCK` 同样占连接**：与 BLPOP 一个道理，阻塞读并发要限流，客户端超时需大于 BLOCK 时长。
- **chunk 大小与写查询模式相关**：高频小写用默认 256 即可；`CHUNK_SIZE` 过小会增加元数据开销，过大浪费内存。
- 8.0 前该能力只在 Redis Stack 镜像中有，`redis:` 普通镜像没有 `TS.*` 命令——部署前先 `TS.ADD` 探测。

# 总结

Time Series 把"监控类追加写 + 时间窗口聚合读"做成了原生类型：Gorilla 压缩省内存、标签索引免自建元数据、多层保留策略自动冷热分层。选型判据：如果数据是"只追加、按时间查、带维度标签的数值流"，它就是比 Hash/String 手工拼 key 更正确的选择；乱序策略（`DUPLICATE_POLICY`）和 `FILTER` 查询基数是上线前必须压测的两个点。
