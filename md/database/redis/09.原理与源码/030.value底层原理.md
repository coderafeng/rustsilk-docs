# 概述

如果说 [020.key 底层原理](./020.key底层原理.md) 讲"怎么找到值"，本篇讲"**值长什么样**"。Redis 里所有 value 都包在同一个外壳 `redisObject`（robj）里，靠 `encoding` 字段决定用哪种内存布局，并随数据规模在"紧凑线性结构"和"通用哈希/树结构"之间自动切换。

# robj：值对象的统一外壳

键空间字典里存的不是裸数据，而是指向 `redisObject` 的指针：

```c
typedef struct redisObject {
    unsigned type:4;        // 逻辑类型：OBJ_STRING/OBJ_HASH/...
    unsigned encoding:4;    // 物理编码：OBJ_ENCODING_LISTPACK/...
    unsigned lru:24;        // LRU/LFU 时钟(复用字段)，也用于 maxmemory 淘汰
    int refcount;           // 引用计数，共享对象靠它
    void *ptr;              // 指向真正的底层结构(SDS/listpack/dict/...)
} robj;
```

| 字段 | 谁来填 | 作用 |
|------|--------|------|
| `type` | 命令层 | 决定"这是 String 还是 Hash"，`WRONGTYPE` 就是它不匹配 |
| `encoding` | 底层 | 决定"内存里到底怎么排布"，`OBJECT ENCODING` 读的就是它 |
| `lru` | 内存管理 | 24 位复用：LRU 模式存最后访问时间，LFU 模式高 16 位存对数概率计数器、低 8 位存衰减时间（呼应 [000.概述](./000.原理与源码概述.md#内存管理)） |
| `refcount` | 对象共享 | 小整数等共享对象只有一份，计数归零才回收 |
| `ptr` | 数据本体 | 指向 SDS / listpack / dict / skiplist / quicklist 等 |

# type 与 encoding 的关系

- **`type` 是逻辑视图**：面向命令语义（`HSET` 要求 type=hash）。
- **`encoding` 是物理视图**：同一 type 有多种 encoding，按规模/内容自动选，追求"小对象省内存、大对象保性能"。
- **切换通常单向不可逆**：listpack→hashtable、intset→hashtable 后，即使删回小规模也不会自动降级，除非重建键。压测要按**线上峰值规模**建模。

# SDS：所有字符串的底座

无论 key、String value、还是 listpack 里的字段，字符串一律用 **SDS（`sdshdr8/16/32/64`）**：

```text
[ len | alloc | flags | buf[] ... ]
  实际长度  已分配容量  头部类型   字节数组(末尾隐式 \0)
```

- **O(1) 取长度**（存了 `len`）、**二进制安全**（按 `len` 而非 `\0` 截断，可存图片字节）、**预分配**减少重分配。
- `flags` 决定用 8/16/32/64 位存 `len/alloc`，短串用窄头省内存。

# listpack 取代 ziplist（7.0）

旧版 Hash/ZSet/List 小对象用 **ziplist（压缩列表）**，它每个节点存"前一节点长度"用于反向遍历，存在**连锁更新**最坏情况（一次插入引发连续 realloc）。7.0 起用 **listpack** 取代：节点不再依赖相邻长度字段，彻底消除连锁更新，编码更简单。

# intset / quicklist / skiplist 要点

- **intset**：Set 全是整数且数量小时，用有序整数数组 + 升级机制（16→32→64 位），极省内存；一旦非整数或超阈值转 hashtable。
- **quicklist**：List 的底座，本质是"双向链表，每个节点是一个 listpack"，兼顾链表增删与数组缓存局部性；`list-compress-depth` 压缩中间节点、首尾保持解压以便快速 push/pop。
- **skiplist + dict（ZSet）**：跳表按 score 有序支撑范围查询 O(logN)，dict 提供按 member O(1) 查 score，两结构共享同一批元素。选跳表而非红黑树：实现简单、区间查询友好、单线程无需考虑平衡锁。

# embstr / raw / int 与共享对象

- String ≤44 字节且非整数 → `embstr`：robj 与 SDS **一次 malloc** 连续分配，省一次分配、缓存友好；>44 → `raw`：robj 与 SDS 分开分配。
- 可表示为长整数的值 → `int`：robj 直接存整数、不分配 SDS。
- **共享整数对象**：`OBJ_SHARED_INTEGERS`（默认 0–9999）预先造好，`refcount` 复用，海量小整数 value 只占一份内存。

# 查看与调试

| 命令 | 看什么 |
|------|--------|
| `OBJECT ENCODING key` | 当前 `encoding`（如 `listpack`/`hashtable`/`embstr`） |
| `OBJECT IDLETIME key` | 空闲秒数（LRU 近似依据） |
| `OBJECT FREQ key` | 访问频率（LFU 模式） |
| `OBJECT REFCOUNT key` | 引用计数（判断是否命中共享对象） |
| `MEMORY USAGE key` | 该键估算内存占用 |
| `DEBUG OBJECT key` | 底层 dump（生产慎用） |

# 避坑

- **编码转换不可逆**：删空元素不会把 hashtable 变回 listpack，压测按峰值规模估内存（呼应 [020.key 底层原理](./020.key底层原理.md)）。
- **`embstr` 只到 44 字节**：临界附近短串频繁在 `embstr`/`raw` 间用不同分配策略，批量写入留意编码分布。
- **大 key 的编码往往已是"重结构"**：一个转成 hashtable/skiplist 的大 key，其 `MEMORY USAGE`、序列化、迁移成本都高——按 [08.工程化/070.大key与热key](../08.工程化/070.大key与热key.md) 分桶。
- **`lru` 是复用字段**：LFU 策略下它不是纯时间戳，别拿 `OBJECT IDLETIME` 的直觉去解释 `maxmemory-policy=allkeys-lfu` 的行为。
- **模块类型编码自成一套**：别用核心类型的 listpack/skiplist 直觉去估 JSON/TS/Vector 的内存，用各模块自己的 `MEMORY`/信息命令。

# 总结

value 层的三句话：**① 一切皆 robj**——`type` 管语义、`encoding` 管布局、`lru`/`refcount`/`ptr` 各司其职；**② 按规模切编码**——小对象用 listpack/intset/embstr 省内存，越阈值转 hashtable/skiplist/raw 保性能，且转换不可逆；**③ 字符串统一 SDS**，listpack 已取代有连锁更新隐患的 ziplist。02 章每类型的动画与草图，都是这套通用机制在具体类型上的投影。
