# 概述

> 官方文档：<https://redis.io/docs/latest/develop/whats-new/8-10/>

Redis 8.10 在 8.8 的基础上继续迭代，核心看点：**紧凑 Hash（compact hashes）新编码 + `HIMPORT` 批量导入**、基于 MP-AOF 的节点侧 **`BACKUP` 命令**、列表多元素移动（`LMOVEM`/`BLMOVEM`）、集合基数命令（`SUNIONCARD`/`SDIFFCARD`）、大规模 **JSONPath 扩展**，以及多条 Time Series 新命令。

# 支持的操作系统

与 8.8 相同：Ubuntu 22.04/24.04/26.04、Rocky Linux 8.10/9.7/10.1、AlmaLinux 8.10/9.7/10.1、Debian 12.13/13.4、Alpine 3.23、macOS 14.8.4/15.7.4/26.3（Intel 与 ARM）。

# 安全修复

- 修复用户可通过在 Redis 错误回复中注入 `\r\n` 序列操纵连接读取数据的问题。

# 新特性

## 紧凑 Hash（Compact hashes）

新的 hash 编码：对**共享同一 schema 的 key 只存储一份字段名**，显著降低内存占用。配套新命令 `HIMPORT` 提供紧凑 hash 的高吞吐批量导入。

## BACKUP 命令

新命令 `BACKUP` 基于多部分 AOF（MP-AOF）提供**节点侧备份与恢复**实现。

## 列表多元素移动

新命令 `LMOVEM` 与 `BLMOVEM`：单条命令在列表间**移动多个元素**。

## 集合基数命令

- `SUNIONCARD`：返回多个集合**并集的基数**；
- `SDIFFCARD`：返回集合**差的基数**；

均无需物化实际结果集合。

## Streams 回复上限

`XREAD` 与 `XREADGROUP` 新增 `MAXCOUNT` 与 `MAXSIZE` 参数，限制回复的**累计条目数与累计体积**。

## SCRIPT_RUNNER 命令标志

新增 `SCRIPT_RUNNER` 标志，标识执行脚本或功能的命令。

## SLOWLOG GET 增强

回复新增参数：被记录命令的**参数总数**。

## FT.ALIASLIST

新命令返回某个 Search 索引的**全部别名**。

## 更多词干化语言

Redis Search 新增**马来语（Malay）**与**他加禄语（Tagalog）**词干化支持。

## FT.AGGREGATE COLLECT reducer

`COLLECT` reducer 区分远程与本地 reducer 调用。

## 更严格的查询超时控制

`FT.SEARCH`、`FT.AGGREGATE`、`FT.HYBRID` 更严格地强制执行查询 `TIMEOUT`。`search-on-timeout` 策略提供三种选项：

- `FAIL`：拒绝超时查询（`search-workers > 0` 时为抢占式强制执行）；
- `RETURN`（默认）：返回尽力而为的部分结果，后处理阶段不强制；
- `RETURN_STRICT`（新增）：返回部分结果且在后处理管线中持续执行超时限制，需 `search-workers > 0`；

主线程执行的查询受 `search-max-foreground-timeout-limit` 封顶（默认 60000 ms）。

## JSONPath 扩展

JSON 大幅扩展 JSONPath 表达能力：

- 顶层**投影表达式**；`==`/`!=` 可比较任意字面量（含数组/对象）；过滤器取反 `!`；
- `size`/`sizeof`、`empty`、`in`/`nin` 操作符；数值四则与一元运算符；对象 `~` 操作符；
- 函数：`length()`、`abs()`/`ceiling()`/`floor()`、`match()`/`search()`、`concat()`、`first()`/`last()`/`index()`/`append()`、`min()`/`max()`/`avg()`/`sum()`/`stddev()`、`keys()`、`count()`、`value()`、`subsetof()`/`anyof()`/`noneof()`。

## Time Series 新命令

- `TS.NRANGE` / `TS.NREVRANGE`：跨多条时序查询范围并按**时间戳分组**结果；
- `TS.READ`：可选的**阻塞式读取**；
- `TS.QUERYLABELS`：返回标签及标签值列表；
- `TS.MRANGE` / `TS.MREVRANGE` 新增 `EXCLUDEEMPTY` 参数：排除无样本的序列。

# 缺陷修复（摘选）

## 核心

- `SORT`、`GEORADIUS`、`XREAD` 等命令的 **ACL 权限绕过**修复；BCAST 客户端侧缓存失效中的 ACL key 名泄漏；
- I/O 线程对副本客户端的空转；重写负载下的全量同步问题；`VRANDMEMBER` 在 `LLONG_MIN` count 时崩溃；
- `MEMORY USAGE` 高报内存；`BITFIELD` 偏移解析有符号溢出；`SET` 未强制 `NX`/`XX` 与 `IF*` 互斥；
- 原子槽迁移任务在 `RM_ResetDataset`/`RM_RdbLoad` 期间未停止等。

## Redis Search

- 索引被删除后 `FT.CURSOR READ` 崩溃；集群 + RESP3 下 `FT.SEARCH LIMIT` 返回过多结果；
- 无 AVX 的 x86 上 FP32/L2 距离计算 SIGSEGV；`FT.HYBRID` 现支持 `EXPLAINSCORE`（暴露 RRF/LINEAR 融合方法）。

## JSON / 时序 / 概率结构

- JSON：递归下降路径求值错误、以 true/false/null 开头的字面量被误解析；
- 时序：`TS.INFO` 内存计算不准、聚合修复、拓扑变更后问题、`TS.INCRBY TIMESTAMP *` 复制时间戳漂移；
- 概率结构：`CF.LOADCHUNK` 部分复制问题。

# 性能与资源利用改进

## 核心

- `lpSeek()` 仅在必要时校验条目；新 hash 上的宽 `HSET`/`HMSET` 单次批量 listpack 追加；
- 每 cron tick 避免重复计算分配器碎片率；内联命令解析削减多余 SDS 分配；
- **rax 内存优化**（定长 key 树的叶子内联），提升 `XREADGROUP` 性能；`RESTORE REPLACE` 新 key 性能改进。

## Redis Search

- 写操作不再被"向量范围查询结果收集期间持有的读锁"阻塞；
- HNSW 索引每节点锁压缩为 1 字节，降低索引内存。

## JSON

- JSON 内存对象占用进一步优化。

# Modules API

- `RedisModuleEvent_ClusterTopologyChange`：集群拓扑变更事件；
- `REDISMODULE_SUBEVENT_FORK_CHILD_*`：允许多线程模块在 `fork()` 前静默后台工作；
- `REDISMODULE_SUBEVENT_CLUSTER_SLOT_MIGRATION_MIGRATE_MODULE_PROPAGATE_END`：在 ASM 复制流后注入命令；
- `RedisModule_AddPostNotificationJobForKey`：将延迟工作绑定到特定 key。

# 配置参数（紧凑 Hash）

- `hash-rdb-load-min-template-entries` / `hash-rdb-load-max-template-entries`：RDB 加载时转换为模板的字段数上下限；
- `hash-rdb-load-template-disassembly-threshold`：模板保留所需的最少 key 数。

# 指标

- `INFO STATS`：`hash_templates`（模板数）、`hash_template_keys`（模板承载的 key 数）；
- `INFO MEMORY`：`used_memory_hash_templates`；`MEMORY STATS`：`hash.templates`；
- `MEMORY USAGE <key>`：报告 key 自身内存 + 其分摊的模板成本。

# CLI 工具

- `--latency` / `--latency-history` 新增 `--latency-percentiles <p1,p2,...>` 自定义百分位报告；
- `--cluster reshard` 与 `rebalance` 改用**服务端原子槽迁移**移动 slot。

# 总结

- **内存治理**是 8.10 的主线：compact hashes 模板化编码、HNSW 单字节锁、rax 叶子内联都在压低单位数据成本；
- **运维能力**：`BACKUP`（MP-AOF 节点侧备份）、`redis-cli` 原子槽迁移重分片；
- **命令语义补齐**：`SUNIONCARD`/`SDIFFCARD` 免物化求基数、`LMOVEM` 批量移动、Streams 回复上限；
- JSONPath 扩展使 Redis 作为文档数据库的查询表达力接近专业引擎；
- 升级注意：`FT.SEARCH` 系超时策略更严格，依赖旧宽松行为的查询需回归测试。
