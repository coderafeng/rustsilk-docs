# 概述

> 官方文档：<https://redis.io/docs/latest/develop/whats-new/7-2/>

Redis 7.2 引入了地理空间多边形搜索、更便捷的 JSON 数据操作等新能力，同时在性能优化、客户端增强与行为一致性方面做了大量改进。需要注意的是，本版本包含若干**破坏性变更**，且 Redis Stack 不再包含 Graph 能力。

# 新特性

## 多边形搜索地理空间查询（Polygon search）

Redis Search 支持使用**多边形（polygon）**对地理空间数据进行查询，开发者可以高效地过滤与检索落在复杂地理边界内的数据。

## 更便捷的 JSON 数据操作

JSON 新增两条命令：

- `JSON.MERGE`：将给定的 JSON 值**合并**到匹配路径，支持更灵活的局部更新；
- `JSON.MSET`：按 key-path-value 三元组**同时设置或更新**多个 JSON 值，提升结构化数据处理效率。

# 改进

## 既有数据结构

各数据类型均有显著性能提升，常用于游戏排行榜的有序集合（sorted set）性能提升幅度达 **30% ~ 100%**。

此外：

- Stream 消费者跟踪（consumer tracking）增强，可更好地观测消费者活动；
- 阻塞类 stream 命令在目标 key 已不存在时返回**专属错误**。

## Redis Search 改进

- `SORT BY` 操作得到优化；
- RESP3 下新增 `FORMAT` 响应，提升效率与可读性。

## 脚本执行增强

- 客户端侧缓存跟踪（client-side tracking）现在可监控脚本执行期间**实际读取的 key**，追踪更精确；
- 被阻塞的命令在执行前会**重新校验权限**，确保安全策略变更即时生效；
- ACL 失败信息与错误码标准化，错误处理更清晰。

## 客户端与复制增强

- 基于 TLS 的复制支持 **SNI（Server Name Indication）**，提升安全部署的兼容性；
- `HELLO` 命令仅在**执行成功**时才修改客户端状态，行为更可预测。

# 变更

## 破坏性变更

Redis 7.2 引入多项向后不兼容变更：

- Lua 脚本不再支持 `print()` 函数；
- 只读脚本中 `PFCOUNT`、`PUBLISH` 被禁止；脚本执行期间时间采样不再冻结；
- 错误响应的大小写发生变化；
- `ZPOPMIN`/`ZPOPMAX` 对 `count 0` 的行为调整；`XCLAIM`/`XAUTOCLAIM` 行为调整；
- ACL 变更影响命令分类与 key 访问权限；
- 命令信息（COMMAND 内省）新增**按子命令统计**；
- 加载（loading）期间允许执行部分 `CONFIG` 命令；命令统计仅在命令实际执行时记录。

## 过期 key 从副本索引中删除

过期 key 现在会从 Redis Search 的副本索引中删除，查询已不存在的数据时返回**空数组**而非 `nil`。

## 其他变更

Redis Stack 7.2 不再包含 Graph 能力（RedisGraph 已宣布 EOL）。

# 组件版本

Redis 7.2 由以下组件构建：

| 组件 | 版本 |
|------|------|
| Redis | 7.2 |
| Search | 2.8 |
| JSON | 2.6 |
| Time series | 1.10 |
| Bloom | 2.6 |

# 总结

- 7.2 的功能亮点是**多边形地理查询**与 `JSON.MERGE`/`JSON.MSET`；
- 有序集合性能提升 30%~100%，是该版本最"实惠"的部分；
- 升级时重点关注破坏性变更：Lua `print()` 移除、错误信息大小写、`ZPOPMIN/ZPOPMAX` count 0 行为、ACL 分类调整；
- RedisGraph 自此退出历史舞台。
