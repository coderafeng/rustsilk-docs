# 概述

> 官方文档：<https://redis.io/docs/latest/develop/whats-new/8-8/>

Redis 8.8 在 8.6 的基础上继续演进，亮点包括：**全新的 Array 数据结构**、Hash **字段级键空间通知**、原子限流命令 `INCREX`、流命令 `XNACK`、时序多聚合器、`FT.HYBRID`/`FT.PROFILE` 增强，以及 Search/Query 层面（Rust 迭代器、向量热路径去虚化、AArch64 原子指令）的大批性能优化，并修复了多个 RCE 级安全漏洞。

# 支持的操作系统

Redis 8.8 通过测试的平台：

- Ubuntu 22.04 / 24.04 / 26.04
- Rocky Linux 8.10 / 9.7 / 10.1
- AlmaLinux 8.10 / 9.7 / 10.1
- Debian 12.13 / 13.4
- Alpine 3.23
- macOS 14.8.4 / 15.7.4 / 26.3（Intel 与 ARM）

# 安全修复

相对 8.8-M03 修复的重要 CVE：

- **CVE-2026-23479**：unblock client 流程中的 Use-After-Free，可能导致 RCE；
- **CVE-2026-25243**：`RESTORE` 中的无效内存访问，可能导致 RCE；
- **CVE-2026-23631**：Lua Use-After-Free，可能导致 RCE；
- **CVE-2026-25588**：`RESTORE` 无效内存访问（Time Series）；
- **CVE-2026-25589**：`RESTORE` 无效内存访问（Probabilistic）。

# 新特性

## Array 数据结构

Redis 8.8 引入全新的 **Array** 数据类型，为有序、可索引的集合提供专用结构。

## Hash 字段级通知

新增 hash 字段的 **subkey 通知**，键空间通知可精确到单个 hash 字段级别。

## INCREX 限流器

新命令 `INCREX` 是一个**窗口计数器限流器**：将 `INCR`、`INCRBY`、`INCRBYFLOAT`、边界（bounds）与过期（expiration）合并为**单个原子操作**，无需多命令事务即可实现常见限流模式。

## XNACK 流命令

新命令 `XNACK` 允许 stream 消费者**显式释放**待处理消息，对消费组 PEL（Pending Entries List）的控制更精细。

## 有序集合 COUNT 聚合器

`ZUNION`、`ZINTER`、`ZUNIONSTORE`、`ZINTERSTORE` 支持新的 `COUNT` 聚合器，用于合并有序集合。

## JSON.SET FPHA 参数

`JSON.SET` 接受新参数 `FPHA`，为同构浮点数组指定浮点类型（如 float16/bfloat16/double）。

## 时序多聚合器

`TS.RANGE`、`TS.REVRANGE`、`TS.MRANGE`、`TS.MREVRANGE` 支持在**单条命令中使用多个聚合器**。

## FT.HYBRID 每分片候选数

`FT.HYBRID` 的 `KNN` 子句接受新参数以**请求更少的每分片候选**，降低集群模式下的开销。

## FT.PROFILE HYBRID

`FT.PROFILE` 新增对 `FT.HYBRID` 查询的 profiling 支持。

## 组内排序 reducer

`FT.AGGREGATE` 新增 `COLLECT` reducer：在 `GROUPBY` 之后展开分组文档并在组内排序，构建更复杂的聚合管线。

# 缺陷修复（摘选）

## 核心

- `SUBSCRIBE`/`PSUBSCRIBE`/`SSUBSCRIBE` OOM 时崩溃；`VADD` 大 `REDUCE` 值崩溃/缓冲区溢出；`VSET` 巨型分配崩溃；
- 加载含重复消费者 PEL 条目的 streams 时双重释放；损坏 Streams RDB 数据处理问题；
- `cluster-announce-ip` 拒绝主机名的回归修复；`SENTINEL SET` 配置注入问题；
- `MULTI` 队列内存统计错误、listpack backlength 编码 off-by-one 等。

## Search 与 Query

- `FT.PROFILE HYBRID` 返回空回复；并发混合查询负载下 `FT.HYBRID` 竞态；
- 拓扑校验失败时 `FT.SEARCH` 崩溃；混合 `FT.SEARCH`/`FT.AGGREGATE` 负载下 coordinator 死锁；
- `FT.DROPINDEX` 与在途混合查询并发时内存泄漏；`MAXIDLE` 后游标未清理导致资源耗尽；
- `FT.CREATE` 现在在创建时即拒绝非法选项组合的 schema 定义。

## JSON / 时序 / 概率结构

- JSON：尾部多余字符被忽略、递归路径数组命令变更顺序错误、多个 JSONPath 求值问题；
- 时序：断连/TLS 失败时潜在崩溃、全 NaN 数据下 `count`/`countNaN`/`countAll` 返回 NaN、多分片命令期间集群拓扑变更未处理；
- 概率结构：RDB 加载内存泄漏。

# 性能与资源利用改进

## 核心

- HyperLogLog：4 个独立累加器最后合并；
- `MGET`/`MSET` 与 hashtable 编码 hash 的 `HGETALL` 批量预取；
- 向 jemalloc 传递 size hint 加速释放；编译期 jemalloc 调优降低分配器与统计开销。

## Search 与 Query

- 向量索引热路径（HNSW 与暴力检索）**去虚化**，降低单查询延迟；
- AArch64 启用 inline LSE 原子指令，提升 ARM64 原子吞吐；
- 大量 key 同时过期时的过期处理开销降低；
- x86_64 release 构建启用 **LTO**；
- 迭代器移植为 **Rust**，减少 FFI 开销；
- 向量字段不再更新 `numRecords`，去除写入开销；VecSim SVS 线程池并入 worker 池。

# 配置参数

- 慢日志截断：`slowlog-entry-max-argc`（单条慢日志保留的最大参数个数）、`slowlog-entry-max-string-len`（参数最大长度）；
- 默认最大工作线程数更新，`MAX_WORKER_THREADS` 改为字符串型配置。

# 指标与 CLI

- `FT.PROFILE` 新增队列时间（queue time）统计；
- `redis-cli` 修复畸形旧版 help 条目导致的内存泄漏。

# 总结

- **数据结构层面**：Array 类型与 hash 字段级通知扩展了建模与可观测粒度；
- **工程模式层面**：`INCREX` 一条命令实现原子窗口限流，`XNACK` 补全消费组语义，都是"事务瘦身"的典型设计；
- **性能层面**：Rust 迭代器、向量热路径去虚化、AArch64 LSE 原子、LTO 使 8.8 的 Search/Query 提升明显；
- **安全层面**：修复 5 个 RCE 级 CVE（含 `RESTORE` 与 Lua UAF），生产环境强烈建议升级。
