# 概述

> 官方文档：<https://redis.io/docs/latest/develop/whats-new/8-0/>

Redis 8.0 是一个里程碑版本：

- **Vector set（向量集合）数据结构进入 beta**，面向语义搜索、推荐系统等 AI 场景；
- 带来 Redis 历史上最大幅度的性能提升——**30+ 项优化**，命令执行最快提升 87%，复制最快提升 18%；
- **Redis Community Edition 更名为 Redis Open Source**，将原 Redis Stack 的全部模块能力内置到统一发行版中——没有模块、没有碎片化，只有 Redis。

# 新特性

## Vector set（向量集合）[beta]

全新的 `Vector set` 数据结构，支持高维向量相似度搜索，适合语义搜索与推荐系统等 AI 用例。它与既有基于 Redis Search 的向量搜索能力互为补充。

> 注意：Vector set 目前为 beta 状态，API 与行为可能在后续版本变更。

## 新增 Hash 命令

在 7.4 引入 Hash 字段级过期的基础上，Redis 8 新增三条 Hash 命令，简化常见的缓存与会话管理模式：

| 命令 | 说明 |
|------|------|
| `HGETEX` | 获取 Hash 字段，并可选地设置过期时间 |
| `HSETEX` | 设置 Hash 字段，并可选地设置过期时间 |
| `HGETDEL` | 获取并删除 Hash 字段 |

# 改进

## Redis Search 改进

Redis Search 可将 Redis 作为文档数据库、向量数据库、二级索引与搜索引擎使用。支持为 hash 与 JSON 文档定义索引，并使用丰富的查询语言完成：

- **向量搜索**：基于 `JSON` 或 hash 中存储的向量嵌入做语义相似度检索；
- **精确匹配**：过滤器、tag 与范围查询；
- **全文搜索**：支持词干化、同义词与模糊匹配。

应用场景覆盖从 AI 的 RAG（检索增强生成）系统到功能完整的搜索引擎。

## 访问控制（ACL）改进

ACL 已更新以覆盖 Redis 8 新增的数据结构：`@read`、`@write` 等既分类别现在包含 `JSON`、`time series`、`VECTOR` 与 `probabilistic` 数据结构的命令，可以对每种数据结构的操作实施更精细的权限控制。

## 性能改进

Redis 8 贡献了 Redis 历史上最大的性能飞跃，30+ 项优化包括：

- 命令延迟最高降低 **87%**；
- 副本节点内存节省 **35%**；
- 通过水平与垂直扩展，查询处理能力最高提升 **16 倍**。

单节点与集群部署均可受益。

# 变更

## 破坏性变更

### ACL 行为

模块命令现被纳入标准类别（如 `+@read`、`+@write`）。例如：拥有 `+@all -@write` 权限的用户**将不能再执行 `JSON.SET`**（此前可以）。若需保持访问权限，必须显式放行新的命令类别。

### Redis Search

以下变更影响行为与校验规则：

- `LIMIT` 参数强制校验（limit 为 0 时 offset 必须为 0）；
- `FT.CURSOR READ` 与 `FT.ALIASADD` 的解析规则收紧；
- `APPLY` 表达式中的幂运算优先级需要**括号**；
- 非法输入现在**报错**而非返回空结果；
- `AVG`、`COUNT`、`SUM`、`STDDEV`、`QUANTILE` 等 reducer 的默认值重新审视；
- 打分默认算法由 `TF-IDF` 改为 **`BM25`**；
- 改进对过期记录、内存约束与畸形字段的处理。

## 其他变更：One Redis

历史上 Redis 通过多个模块扩展搜索、向量相似度、时序分析与概率建模能力，但模块的版本兼容与安装管理带来了负担；Redis Stack 虽打包了模块，却也造成了生态碎片化。

Redis 8 将 **Redis Stack 与 Redis Community Edition 合并为单一统一发行版 —— Redis Open Source**：原先的模块功能全部内置，无需单独管理模块，所有部署获得一致的功能集。

# 组件版本

Redis 8.0 只交付 Redis 本身 —— 没有独立模块，没有碎片化（一体化发行版）。

# 总结

- **Vector set（beta）** 与内置 Search/JSON/时序/概率数据结构使 Redis 8 成为 AI 时代的基础设施底座；
- 性能提升幅度空前：87% 延迟改善、35% 副本内存节省、16x 查询吞吐；
- 升级两大注意点：**ACL 类别覆盖模块命令**、**Redis Search 校验与默认打分变化（BM25）**；
- "One Redis" 统一发行版（Redis Open Source）终结了 Stack/CE 分裂，是发布模式层面的最重要变化。
