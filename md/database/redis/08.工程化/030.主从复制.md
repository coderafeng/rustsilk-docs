# 概述

异步复制的全量/部分重同步流程、replicaof 配置、复制过期与一致性注意点。

- 归属与可用性：Redis 开源核心能力（`PSYNC2` 多副本链 4.0+）
- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/management/replication/>

一句话定位：**复制是 Redis 高可用的地基——它同时解决"数据冗余"和"读扩展"两件事，但它是异步的，所以默认不保证副本与主完全一致，也不自动故障转移（那是哨兵的活）。**

# 原理

**角色与数据流**

- 主节点（primary/master）处理写入，把写命令异步推给副本（replica/slave）；副本可选择性对外提供只读。
- 一个主可挂多个副本，副本又能被其他副本级联复制（`PSYNC2` 支持**复制图**，减轻主带宽压力）。
- 副本对客户端表现：默认数据与主一致，但**写入要回到主**（副本 `READONLY`）。

**全量同步 vs 部分重同步**

- 首次连接、或偏移量无法续接时走**全量同步（full resync）**：主 `BGSAVE` 生成 RDB 发给副本加载，期间缓冲新写命令一并发送。开销大。
- 断线重连且条件满足时走**部分重同步（partial resync）**：主维护环形复制缓冲区 `repl-backlog-size`，副本上报自己的 `repl-offset` 与 `replid`，主只补发缺口之后的命令。开销小，是短暂断网的期望路径。
- `repl-diskless-sync`：全量同步时不落盘、直接 socket 传 RDB，适合磁盘慢而网络快的环境。

**复制与过期（易被忽略）**

- 主节点 key 过期/被淘汰后，**把 `DEL` 当作写命令传给副本**；副本自身不主动过期（3.2 起），以保证主从数据一致（否则各自按本地时钟过期会分叉）。

# 配置与实操

**搭建主从（从节点视角）**

```bash
# redis.conf（副本）——二选一：配置文件写死，或运行时命令
replicaof <master-ip> <master-port>
masterauth <master-password>        # 主开了 requirepass 时必填
replica-read-only yes               # 副本只读（默认）

# 运行时动态挂主
redis-cli -p 6380 REPLICAOF 127.0.0.1 6379
redis-cli -p 6380 REPLICAOF NO ONE   # 脱离复制、变独立主
```

**关键调优参数（主节点）**

```bash
repl-backlog-size 1mb               # 部分重同步缓冲区；调大以容忍更长断网
repl-diskless-sync yes              # 无盘全量同步
repl-diskless-load on-empty-db      # 副本空库时用无盘接收
min-replicas-to-write 1             # 至少 1 个健康副本才接受写（弱一致护栏）
min-replicas-max-lag 10             # 副本滞后超 10 秒不计入"健康"
```

**观测**

```bash
redis-cli INFO replication
# 关注：role、master_link_status(up/down)、master_last_io_seconds_ago、
#       connected_slaves、slave_repl_offset（各副本偏移，判断滞后）
```

# 避坑

- **异步复制 = 可能丢数据**：主写完立即返回客户端，若尚未传给副本就宕机，新写入丢失。`WAIT numreplicas timeout` 可"等待 N 个副本确认"，但它是**尽力而为、不是持久性保证**，且宕机后仍可能不一致。
- **`min-replicas-to-write` 是软保护不是强一致**：它能挡住"完全没副本时的写入"，但网络分区下的语义复杂，别把它当成 Raft 那样的多数派。
- **副本 `READONLY` 但别拿它扛强读**：复制有延迟，副本可能读到旧值；"读己之写"一致性需业务保证（如刚写完读回主）。
- **全量同步风暴**：大实例反复断连触发多次 `BGSAVE` + 全量传输，压垮主 CPU/磁盘/带宽——排查方向是**增大 `repl-backlog-size`** 让重连走部分同步。
- **防火墙/安全组**：除数据端口外，哨兵还需 26379、集群还需 `端口+10000` 的总线端口，跨网段部署漏开端口是"复制起不来"的高频原因（呼应 [030.Ubuntu 安装](../01.Redis%20起步/030.Ubuntu系统安装Redis.md)）。
- **别让副本承担全部读**：缓存层大量读打到单一副本会把它压垮，读扩展要配合哨兵的 `+down-after-milliseconds`、代理或客户端负载均衡（见 [040.Sentinel](./040.Sentinel哨兵.md)）。
- **主从密码不一致导致 `master_link_status:down`**：主 `requirepass` 而从没配 `masterauth`，日志会明确报 `MASTER AUTHENTICATION FAILED`——排查复制先看这行。

# 总结

复制用一份 `replid + repl-offset + backlog` 把"全量"和"增量"统一进 `PSYNC2`：能续接就部分同步，续接不了才全量。它的价值是**冗余 + 读扩展**，它的边界是**异步 → 非强一致 → 不自动故障转移**。想要"主挂了自动选新主"，在复制之上加 [040.Sentinel 哨兵](./040.Sentinel哨兵.md)；想要"写也水平扩展"，上 [050.Cluster 集群](./050.Cluster集群.md)。生产三件套必调：`repl-backlog-size` 撑住断网、`masterauth` 对齐密码、监控 `master_last_io_seconds_ago` 看滞后。
