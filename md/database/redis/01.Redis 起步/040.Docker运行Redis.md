# 概述

官方 Docker 镜像 `redis` 是跨平台跑 Redis 的最短路径：镜像默认 `CMD ["redis-server"]`，数据目录约定为 `/data`，版本通过 tag 精确锁定（如 `redis:8.10`、`redis:8.10-alpine`）。

- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/install/install-stack/docker/>
- 镜像族：**`redis:<version>`**（开源核心，8.0 起已含 JSON/TimeSeries 等并入模块）、**`redis/redis-stack-server:<version>`**（额外带 Search 等 Stack 模块）、变体后缀 `-alpine`（更小体积）

# 操作步骤

1. 启动一个**带持久化**的实例（卷挂载到镜像约定的 `/data`，并打开 AOF）：

   ```bash
   docker run -d --name redis \
     -p 6379:6379 \
     -v redis-data:/data \
     redis:8.10 redis-server --appendonly yes --maxmemory 512mb --maxmemory-policy allkeys-lru
   ```

2. 使用**自定义配置文件**时，把 conf 挂进去并显式传给 `redis-server`（注意命令形态）：

   ```bash
   docker run -d --name redis \
     -v redis-data:/data \
     -v ./redis.conf:/usr/local/etc/redis/redis.conf \
     redis:8.10 redis-server /usr/local/etc/redis/redis.conf
   ```

   挂载的 conf 中要有 `dir /data`，否则持久化文件落在容器临时路径。

3. Compose 形态（健康检查 + 命名卷）：

   ```yaml
   services:
     redis:
       image: redis:8.10
       command: ["redis-server", "--appendonly", "yes"]
       ports: ["6379:6379"]
       volumes: [redis-data:/data]
       healthcheck:
         test: ["CMD", "redis-cli", "ping"]
         interval: 10s
   volumes:
     redis-data:
   ```

# 验证

```bash
docker exec -it redis redis-cli ping                 # PONG
docker exec -it redis redis-cli info persistence | grep aof_enabled   # aof_enabled:1
docker inspect redis --format '{{json .Mounts}}'     # 确认 /data 落在命名卷而非匿名层
```

# 避坑

- **不挂 `/data` 就没有持久化**：默认 `docker run redis` 不带卷，RDB/AOF 写在容器可写层，`docker rm` 即全部丢——卷是最便宜的保险。
- **命令参数覆盖 CMD 的形态**：`docker run redis:8.10 --appendonly yes` 会把 `--appendonly` 当成容器要执行的命令而报错；必须写全 `redis-server --appendonly yes`。
- **`--memory` 与 `maxmemory` 要成对设计**：只设 Docker 内存限制而不设 `maxmemory`，Redis 不知道上限，内核 OOM-Killer 直接杀进程；`maxmemory` 应留出 RDB fork COW 与缓冲的余量（通常 ≤ 容器限制的 3/4）。
- **protected-mode 在容器里基本无效**：容器内无 loopback 之外的"非安全绑定"判定，容器网络默认互通——暴露 `-p 6379:6379` 到宿主机时务必配 `requirepass`/ACL 或仅绑 `127.0.0.1:6379:6379`。
- **tag 用 `latest` 等于赌版本**：镜像重建即换 major；生产锁定 `redis:8.10` 这类精确 tag，升级走显式变更（与 [010.下载Redis安装包](./010.下载Redis安装包.md) 的 stable 策略一致）。
- **Windows/WSL 下 bind mount 性能差**：宿主机目录挂载（`-v ./data:/data`）的持久化写入在 Docker Desktop 上可能慢一个数量级，命名卷优先。

# 总结

Docker 路线的三条铁律：**数据进命名卷（`/data`）、配置进显式 conf、内存限制成对配**。镜像选择上 `redis:8.10` 已覆盖绝大部分场景（8.0 起原 Stack 模块已并入开源版），只有 Search 等仍属 Stack 的能力才需要 `redis-stack-server`。开发用 `docker run` 一把梭，联调与准生产直接上 Compose——健康检查与重启策略在 compose 文件里写清楚，比事后排查"容器起了但连不上"省力得多。
