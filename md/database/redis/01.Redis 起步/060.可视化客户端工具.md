# 概述

客户端工具分两层：**redis-cli**（官方命令行，随 `redis-tools` 安装，是排查与运维的第一工具）与 **RedisInsight**（官方图形化：浏览器/桌面/Docker 三种形态）。第三方桌面管理器（Another Redis Desktop Manager、Redis Desktop Manager 等）作为补充选项。

- 官方客户端总览：<https://redis.io/docs/latest/develop/clients/>
- RedisInsight：<https://redis.io/docs/latest/operate/redisinsight/>
- 命令语法查询：`redis-cli COMMAND DOCS vsim` 这类内置查询，或 <https://redis.io/commands/>

# 工具对比

| 工具 | 形态 | 强项 | 注意 |
|------|------|------|------|
| `redis-cli` | 终端 | 全命令覆盖、`--cluster` 管理、`--latency`/`--bigkeys`/`--memkeys` 诊断、`-r`/`-i` 压测回放 | 学习曲线在参数而非 GUI |
| RedisInsight | Web/桌面/Docker | 官方出品免费；Browser 按模式浏览键、Analyzer 键内存分析、慢查询/监控仪表盘、CLI 内置 | 生产大键扫描要谨慎发起 |
| Another Redis Desktop Manager | 桌面 | 开源免费、中文友好、轻量 | 社区维护，新类型（Vector Set 等）支持滞后 |
| Redis Desktop Manager | 桌面 | 老牌、稳定 | 商业授权；免费版功能受限 |

# redis-cli 高频用法

```bash
redis-cli -h 127.0.0.1 -p 6379 --user <acl_user> -a <password> --no-auth-warning   # 连接（-a 会进 history，优先用 REDISCLI_AUTH 环境变量或交互 AUTH）
redis-cli -n 2 keys 'user:*'            # 切 db 2 查键（生产用 scan 替代，见 080 篇）
redis-cli --cluster check 127.0.0.1:6379   # 集群拓扑健康检查
redis-cli --bigkeys                     # 抽样扫描大键（全键类型按 size 分桶统计）
redis-cli --latency-history -i 5        # 每 5 秒采样一次延迟
redis-cli -i 0.01 -r 1000 incr counter  # 以 10ms 间隔重复 1000 次（简易压测）
redis-cli --scan --pattern 'tmp:*' | wc -l   # 安全遍历统计键数
redis-cli monitor                       # 实时命令流（调试神器，性能杀手，慎用）
```

RedisInsight 的 Docker 形态（无需本机安装）：

```bash
docker run -d --name redisinsight -p 5540:5540 redis/redisinsight:latest
# 浏览器打开 http://localhost:5540，添加 Redis 连接（Host 用宿主机可达地址，容器内填 host.docker.internal）
```

# 典型场景

- **本地起 RedisInsight 连 Docker 里的 Redis**：两者同网络时 Host 填服务名；跨宿主用 `host.docker.internal`，避免误填 `127.0.0.1` 连到工具自己的容器。
- **生产事故初筛三板斧**：`redis-cli info memory` 看内存/逐出计数、`--bigkeys` 找大键、`SLOWLOG GET 10` 看慢命令——全部无需安装任何 GUI。
- **键巡检**：RedisInsight Analyzer 选中样本键做内存分解（`MEMORY USAGE`/`DEBUG OBJECT` 级别），比手工估算准确。

# 避坑

- **`MONITOR` 不是审计工具**：它会复制所有命令流量到当前连接，高 QPS 下直接拖垮实例且输出无完整性保证；生产审计走 ACLLOG / slowlog / 客户端日志。
- **`KEYS` 在 GUI 里同样是 O(N)**：RedisInsight 的 pattern 浏览后台也是 `SCAN` 分页，但手工执行 `KEYS *` 的习惯别带进终端（原因见 [080.了解基础命令](./080.了解基础命令.md)）。
- **密码进 shell history**：`-a` 方式会被记录；用 `REDISCLI_AUTH` 环境变量或 `--user`（ACL）替代。
- **第三方 GUI 的新类型滞后**：Vector Set、字段 TTL 等新命令在旧版工具里可能"看得见键、读不了内容"，选型先确认其支持的 Redis 版本。
- 生产实例**不要开公网 + 无密码给 GUI 直连**：工具装在运维网段，经堡垒机/隧道访问。

# 总结

起步阶段把 redis-cli 当主力：连接、`INFO`、`--bigkeys`、`SLOWLOG GET`、`--scan` 五个动作覆盖 80% 的日常排查；RedisInsight 负责"看结构、分析内存、演示讲解"这类可视化需求；第三方 GUI 按团队习惯补充，但要接受版本支持滞后。工具可以换，纪律不变——生产环境远离 `KEYS *` 与 `MONITOR`，密码不进 history。
