# 概述

Redis 高频术语速查表：按"概念 → 释义 → 相关命令/配置"组织，读其他篇章遇到生词回这里查。

- 官方文档入口：<https://redis.io/docs/latest/>

# 键空间与数据

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| Key space（键空间） | 一个 db 内全部键的集合；默认 16 个 db（0~15），Cluster 模式只有 db 0 | `SELECT`、`databases` |
| Key（键） | 字符串形式的标识符，全局唯一（同 db 内）；最大 512MB 但建议短小 | `SCAN`、`EXISTS` |
| TTL（Time To Live） | 键的存活时间；过期由服务端删除（惰性 + 定期双策略） | `EXPIRE`/`TTL`/`PERSIST` |
| 过期删除 | 惰性删除（访问时检查）+ 定期删除（采样清理）的组合，两者都不是“到点即删” | 与 `maxmemory` 淘汰联动；见 [050.Redis配置](./050.Redis配置.md) |
| Value（值） | 键关联的数据结构实例：String/Hash/List/Set/ZSet/Stream/Vector Set 等 | 见 [02 章数据类型](../02.Redis%20数据类型和命令/000.数据类型概述.md) |
| Type（类型） | 每个键有且仅有一个数据类型，写错类型报 `WRONGTYPE` | `TYPE` |

# 内存与淘汰

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| Eviction（淘汰/逐出） | `maxmemory` 达到后按策略删除键腾空间 | `maxmemory-policy`、`INFO stats` 的 `evicted_keys` |
| LRU / LFU | 淘汰依据：最近最少使用 / 最不经常使用（LFU 为近似计数） | `maxmemory-policy allkeys-lfu`、`maxmemory-sample-ratio` |
| Fragmentation（碎片率） | 分配内存与可用内存之比，过高说明 jemalloc 碎片多 | `mem_fragmentation_ratio`、活动碎片整理 `activedefrag` |
| OOM | 超出 `maxmemory` 且无可淘汰键时，写命令报 `OOM command not allowed` | `maxmemory`、淘汰策略 |

# 编码与内部结构

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| Encoding（内部编码） | 同一类型可按规模切换底层结构以省内存：`intset`/`listpack`/`hashtable`/`quicklist`/`skiplist`/`sds` | `OBJECT ENCODING`、`*-max-listpack-*` 参数 |
| listpack | 7.0 起取代 ziplist 的紧凑线性结构，无连锁更新问题 | `hash-max-listpack-entries` 等 |
| Geohash | 把经纬度编码成 52 位整数的方法，GEO 命令将其存入 ZSet 的 score | `GEOADD` |
| SDS | Simple Dynamic String，Redis 的字符串结构：O(1) 长度、二进制安全、预分配 | 见 [010.String](../02.Redis%20数据类型和命令/010.String%20字符串.md) |

# 持久化

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| RDB | 某时刻全量数据集的二进制快照；fork 子进程生成，恢复快、可能丢最后一次快照后的数据 | `save`、`BGSAVE`、`LASTSAVE` |
| AOF | 写命令追加日志；`appendfsync` 决定刷盘强度，丢数据窗口随之变化 | `appendonly`、`CONFIG SET appendonly yes`、`BGREWRITEAOF` |
| 混合持久化 | AOF 重写时基座用 RDB 格式、增量用 AOF 命令；6.2 起默认开启 | `aof-use-rdb-preamble` |
| COW | Copy-On-Write：fork 后父子共享页，写时复制——fork 瞬间内存翻倍风险的来源 | `INFO memory` 的 `mem_dirty`/rdb 相关指标 |

# 复制与高可用

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| Replication（复制） | 主从数据同步；异步复制，从库可能滞后 | `REPLICAOF`、`INFO replication` |
| Replication offset / backlog | 复制进度偏移与主库环形复制缓冲；断线续传（PSYNC2）依赖它 | `repl-backlog-size` |
| Full resync / Partial resync | 全量重同步（重传 RDB）/ 部分重同步（只补差额） | `repl-diskless-sync` |
| Sentinel（哨兵） | 监控主从拓扑、主故障时自动故障转移的独立进程体系 | `sentinel monitor`、见 [040.Sentinel](../08.工程化/040.Sentinel哨兵.md) |
| Quorum | 哨兵判定"主观下线 → 客观下线"所需同意票数 | `sentinel monitor mymaster 127.0.0.1 6379 2` 中的 `2` |
| Failover | 故障转移：哨兵选新主并重配从库/客户端 | `+tilt` 相关保护期参数 |
| Split-brain | 脑裂：旧主未被隔离前仍接收写，选主后这部分写丢失 | `min-replicas-to-write`/`min-replicas-max-lag` |

# 集群

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| Hash slot（槽） | 16384 个桶，键按 `CRC16(key) mod 16384` 路由到节点 | `CLUSTER KEYSLOT` |
| Hash tag（哈希标签） | key 中 `{...}` 部分参与槽计算，把多键钉到同槽以做跨键操作 | `SET user:{1001}:name` |
| CROSSSLOT | 多键命令的键不在同槽时报错 | 见 [010.String 避坑](../02.Redis%20数据类型和命令/010.String%20字符串.md) |
| MOVED / ASK | 槽迁移/转发的重定向响应；客户端需按指向重试 | `CLUSTER SLOTS`/`SHARDS` |
| Gossip | 节点间心跳协议（`cluster-announce-*`、PFAIL/FAIL 判定） | `cluster-node-timeout` |

# 客户端与协议

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| RESP | REdis Serialization Protocol（协议规范），RESP3 支持类型更丰富、服务端推送 | `HELLO 3`、`proto` |
| Pub/Sub | 发布订阅：即发即弃、订阅者离线即丢（与 Stream 的持久消费相对） | `PUBLISH`/`SUBSCRIBE`，见 [04 章](../04.发布订阅/000.发布订阅概述.md) |
| Keyspace notification | 键事件发布到 `__keyspace@N__` / `__keyevent@N__` 频道（N 为 db 编号） | `notify-keyspace-events` |
| Pipeline（管道） | 客户端批量发送不等逐个回复，省 RTT；非原子 | 各客户端 `pipeline()` |
| Transaction（MULTI/EXEC） | 命令入队后一次性顺序执行（无回滚，非 ACID 事务） | `MULTI`/`EXEC`/`WATCH`，见 [020.事务与分布式锁](../08.工程化/020.事务与分布式锁.md) |
| Lua / Functions | 服务端原子脚本执行；Functions 是 7.0 起的可注册、可复用替代 | `EVAL`/`FUNCTION`，见 [06 章](../06.可编程性/000.可编程性概述.md) |
| Slowlog | 超过阈值的命令记录（只计执行时间，不含排队） | `slowlog-log-slower-than`、`SLOWLOG GET` |
| Blocking client | `BLPOP` 等阻塞命令占用的连接，池化环境要单独管理 | `client-output-buffer-limit` |

# 安全

| 术语 | 释义 | 相关命令/配置 |
|------|------|--------------|
| ACL | 6.0 起的授权体系：用户 + 密码 + 命令开关 + 键模式 | `ACL SETUSER`、`aclfile`、`AUTH` |
| `default` 用户 | 未创建用户时的兜底账号，`requirepass` 即其密码 | `ACL LIST` |
| Protected mode | 无 bind 无密码时拒绝远程连接的保险丝 | `protected-mode` |
| Tenant | Redis Cloud/Software 的多租户实例概念（开源版无） | 见 [03 章命令概述](../03.Redis%20命令/000.命令概述.md) |

# 总结

术语按层次记：**数据层**（键空间/TTL/编码/淘汰）→ **持久层**（RDB/AOF/混合）→ **可用性层**（复制/哨兵/集群/槽）→ **交互层**（RESP/管道/发布订阅/ACL）。它们在 02/08/09 章各自展开为专题；本表作为索引，各条目均给出对应文档跳转。起步阶段先把"键空间、TTL、淘汰、RDB/AOF、主从、哨兵、槽"这七个词吃透，后续学习不会再被名词卡住。
