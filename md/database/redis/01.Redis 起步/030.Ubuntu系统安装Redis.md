# 概述

Ubuntu/Debian 生产安装的标准姿势是**官方 APT 仓库 `packages.redis.io`**，而不是发行版自带的 `redis-server` 包（后者版本常年滞后）。安装得到两个软件包：`redis-server`（服务端）与 `redis-tools`（`redis-cli`、bench 等客户端工具），由 systemd 托管。

- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/install/install-stack/apt/>
- 要点：GPG 密钥环配置、`deb [signed-by=...]` 源行、systemd 服务与配置文件路径

# 操作步骤

1. 安装依赖并导入官方 GPG 密钥（密钥环方式，避免污染全局 trusted.gpg）：

   ```bash
   sudo apt-get install -y lsb-release curl gpg
   curl -fsSL https://packages.redis.io/gpg | sudo gpg --dearmor -o /usr/share/keyrings/redis-archive-keyring.gpg
   sudo chmod 644 /usr/share/keyrings/redis-archive-keyring.gpg
   ```

2. 写入源并安装：

   ```bash
   echo "deb [signed-by=/usr/share/keyrings/redis-archive-keyring.gpg] https://packages.redis.io/deb $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/redis.list
   sudo apt-get update
   sudo apt-get install -y redis
   ```

3. systemd 日常管理：

   ```bash
   sudo systemctl enable --now redis-server
   sudo systemctl status redis-server
   sudo journalctl -u redis-server -f
   ```

关键路径（官方仓库包约定）：配置 `/etc/redis/redis.conf`（sentinel 配置同目录）、数据目录 `/var/lib/redis`、日志走 journald、运行用户 `redis`。

# 验证

```bash
redis-server --version && redis-cli --version
redis-cli ping                         # PONG
sudo systemctl is-enabled redis-server  # enabled
redis-cli info server | grep redis_version   # 与 packages.redis.io 上目标版本一致
```

# 避坑

- **别混用两个来源**：`apt install redis-server`（Ubuntu 官方源）与 `redis`（packages.redis.io）文件布局冲突，先卸载干净再切源；同一台机器只认一个 Provider。
- **`bind 127.0.0.1 -::1` + `protected-mode yes`**：远程连不上不是装坏了——要么改 `bind` 并置于防火墙/安全组之后，要么走 SSH/隧道；直接关 `protected-mode` 等于公网裸奔（详见 [050.Redis配置](./050.Redis配置.md)）。
- **systemd 与手动 `redis-server` 双进程打架**：`systemctl start` 后再手工前台起服务会端口冲突；排查先 `ss -lntp | grep 6379` 看监听者是谁。
- **AOF/RDB 权限**：官方包的 `/var/lib/redis` 属主是 `redis` 用户，自建目录或改 `dir` 参数后记得同步属主，否则启动日志报 Unrecoverable error。
- 发行版自带包**没有 8.x**：需要 Vector Set / JSON 等新能力时，`apt-cache policy redis-server` 看候选版本，确认走的是 packages.redis.io。

# 总结

Linux 生产部署 Redis 的最短正确路径：官方 APT 仓库 + systemd 托管，版本跟得上官方补丁节奏（呼应 [010.下载Redis安装包](./010.下载Redis安装包.md) 的维护策略）。装完的验收不是 `ping` 通就算数——`redis_version`、`is-enabled`、journald 无错误，三项齐了才算"可以上业务"。远程访问永远从 `bind`/`protected-mode`/防火墙三层设计入手，而不是关安全开关。
