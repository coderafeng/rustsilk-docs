# 概述

连接实例后最先要掌握的**键级通用命令**：不区分数据类型，管理键本身（存在性、过期、重命名、遍历）与连接（PING/AUTH/SELECT）。

- 官方文档：<https://redis.io/docs/latest/develop/commands/>（Generic / Connection 两组）
- 类型专属命令（如 `HSET`、`ZADD`）不在本篇，见 [02.Redis 数据类型和命令](../02.Redis%20数据类型和命令/000.数据类型概述.md) 各篇"命令速查"

# 命令速查

**连接与服务器（Connection/Server）**

| 命令 | 说明 |
|------|------|
| `PING` | 连通性探测，返回 `PONG`；带消息参数则原样回显 |
| `AUTH user password` / `AUTH password` | 认证；配合 ACL 或 `requirepass` |
| `SELECT n` | 切换 db（0~15）；**Cluster 模式不支持** |
| `HELLO 3` | 切换 RESP3 协议并返回服务端元信息 |
| `ECHO msg` | 回显（排查客户端序列化问题） |
| `INFO [section]` | 服务器状态（`memory`/`replication`/`keyspace` 等分段） |
| `DBSIZE` | 当前 db 键数量 |
| `TIME` / `COMMAND DOCS cmd` | 服务端时间 / 内置命令文档 |

**键管理（Generic）**

| 命令 | 说明 | 复杂度 |
|------|------|--------|
| `EXISTS key [key...]` | 存在计数 | O(N) |
| `DEL key [key...]` | 同步删除 | O(N) |
| `UNLINK key [key...]` | **异步删除**（内存回收交给后台 lazyfree，4.0+） | 返回立即，回收异步 |
| `TYPE key` | 返回数据类型（`none` 表示不存在） | O(1) |
| `EXPIRE key s [NX\|XX\|GT\|LT]` | 秒级过期；选项 7.0+：仅无过期时设（NX）/已过期间隔更严（GT/LT） | O(1) |
| `PEXPIRE` / `EXPIREAT` / `PEXPIREAT` | 毫秒级 / 绝对时间点版本 | O(1) |
| `TTL` / `PTTL` | 剩余秒/毫秒：`-1` 无过期，`-2` 键不存在 | O(1) |
| `PERSIST key` | 移除过期时间 | O(1) |
| `EXPIRETIME` / `PEXPIRETIME` | 读出绝对过期时间戳（7.0+） | O(1) |
| `RENAME` / `RENAMENX` | 改名（同 db 原子；Cluster 跨槽受限） | O(1) |
| `SCAN cursor [MATCH pattern] [COUNT n] [TYPE t]` | 增量遍历键空间；返回新游标，`0` 结束 | 每次 O(COUNT) |
| `RANDOMKEY` / `TOUCH key...` | 随机取键 / 访问标记（LRU 意义下的"摸一下"） | O(1) |
| `DUMP` / `RESTORE` | 键的序列化快照导出/导入（跨实例迁移小键） | O(N) |
| `COPY source dest [DB n] [REPLACE]` | 复制键（6.2+，同 db/跨 db 均可，Cluster 不支持跨节点） | O(N) |
| `OBJECT ENCODING/IDLETIME/REFCOUNT/FREQ key` | 内部编码 / 空闲时长 / 引用计数 / LFU 频率 | O(1) |
| `MEMORY USAGE key [SAMPLES n]` | 单键内存估算（含键名与元数据开销；`SAMPLES` 控制子元素抽样数） | O(N) |

# 操作步骤（一轮上手练习）

```bash
redis-cli ping
redis-cli set demo:1 "hello"
redis-cli type demo:1              # string
redis-cli expire demo:1 60
redis-cli ttl demo:1               # 5x
redis-cli expire demo:1 30 NX      # 已有过期 → 返回 0，不覆盖
redis-cli pttl demo:1
redis-cli scan 0 match 'demo:*' count 100
redis-cli persist demo:1 && redis-cli ttl demo:1   # -1
redis-cli rename demo:1 demo:2
redis-cli unlink demo:2
```

# 验证

- `SCAN` 练习：`redis-cli --scan --pattern 'demo:*'` 底层即游标循环，输出应与手工 `SCAN` 一致；
- 过期语义：`EXPIRE key -1` 直接删除键（返回 1），`EXPIRE` 对不存在的键返回 0——用这两条判断你是否真理解返回码；
- `UNLINK` 观察：删除大键后 `INFO stats` 的 `lazyfree_pending_objects` 短暂非零即异步生效。

# 避坑

- **`KEYS pattern` 禁用生产**：O(N) 全表扫描且阻塞单线程，千万键时一次 `KEYS *` 冻结实例数秒；遍历一律 `SCAN`（注意：`SCAN` 返回的键**可能重复**、且只保证"遍历期间一直存在的键必被返回"）。
- **`SCAN MATCH` 先取批后过滤**：pattern 在 COUNT 取回后才筛，稀疏命中时仍遍历全库——键多时加 `TYPE` 收窄、或用命名规范直接定位前缀，而不是依赖 `MATCH '*x*'` 式的全库正则幻想。
- **过期时间不是精确闹钟**：惰性 + 定期双策略意味着过期键可能"已死未埋"，`TTL` 为负/键还在的瞬时状态都正常；依赖"过期即触发"做业务（如订单超时）要么用 keyspace notification 兜底、要么用延迟队列，通知本身**不保证送达**（断线即丢，7.1 起才有 Shard 版）。
- **`DEL` 大键阻塞**：删 500 万元素的 ZSet，主线程同步释放可达数百毫秒——一律 `UNLINK`，或先分批裁剪元素（`LTRIM`/`ZREMRANGEBYRANK`）再删。
- **`SELECT` 与多 db 依赖**：db 0~15 共享一个实例的内存与淘汰，隔离性弱且 Cluster 下消失；按 db 分环境/分业务是迁移地雷，改用 key 前缀或分实例。
- **`EXPIRE` 的 GT/LT 比较的是剩余时间**：与"绝对时间点"直觉不同，重复续期场景用 `KEEPTTL`（`SET` 选项）或 `GT` 才稳。

# 总结

通用命令的三组心智：**连通与观测**（PING/INFO/DBSIZE）、**键的生命周期**（EXISTS/DEL vs UNLINK/EXPIRE 族/TTL 语义）、**遍历与迁移**（SCAN 取代 KEYS、DUMP/RESTORE/COPY）。其中最容易翻车的是把 `KEYS` 和 `DEL` 带上生产、以及把 TTL 当成精确闹钟。类型命令各自归 02 章，事务/发布订阅/集群命令的入口见 [03.Redis 命令](../03.Redis%20命令/000.命令概述.md) 与对应章节。
