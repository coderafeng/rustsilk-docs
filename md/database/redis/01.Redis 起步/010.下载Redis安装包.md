# 概述

从官方渠道获取 Redis：源码包在 [redis.io/downloads](https://redis.io/downloads/) 与 [GitHub Releases](https://github.com/redis/redis/releases) 发布，Docker 镜像、APT/YUM 仓库包与托管服务是另外的分发形态。

- 官方下载页：<https://redis.io/downloads/>
- 源码仓库：<https://github.com/redis/redis>（`unstable` 分支为开发树）

**版本节奏**（官方发布周期约定）：

- 版本号 `major.minor.patch`；**每年计划一个 major**，major 后约 6 个月出一个 minor，patch 按需发布（修复积累够了就发）。
- 历史上采用"偶数 minor 稳定、奇数 minor 不稳定"的惯例（如 2.9.x 是 3.0 的开发版）；Redis 8.x 时代实际执行的是 **major.minor 即稳定分支、unstable 分支承担新功能开发**，选型时看分支而不是看奇偶。
- 维护策略：**最新 stable 全量维护**；其前一个 minor 与上一个 major 只接受关键修复（以 patch 形式）。截至 2026-09，活跃分支为 8.10（最新 stable）、8.8、8.6、8.4、8.2，最新补丁均为 `.7/.2/.10` 量级——同一天五个分支齐发补丁，就是"多分支并行维护"的直接证据。

**源码包 vs 二进制包**：官方 releases 只提供 `redis-x.y.z.tar.gz` **源码包**（内含 `deps/hiredis`、`deps/lua` 等依赖，编译产物即服务端与 `redis-cli`）；开箱即用的二进制来自 Docker Hub `redis`/`redis/redis-stack-server` 镜像、`packages.redis.io` APT/YUM 仓库，以及 Redis Cloud/Software 托管服务。

# 操作步骤

1. 进入 <https://redis.io/downloads/>，选择 **Stable**（下载页同时列出 Unstable 供尝鲜）。
2. 校验来源：确认跳转到 `download.redis.io/releases/` 下对应 `redis-<version>.tar.gz` 的文件，或 GitHub `redis/redis` 仓库的对应 tag。
3. 源码编译（Linux/macOS）：

   ```bash
   tar xzf redis-8.10.2.tar.gz && cd redis-8.10.2
   make -j$(nproc)          # 依赖 gcc/make；全部测试可选 make all
   sudo make install PREFIX=/usr/local/redis
   ```

4. 只需要“今天就能用”：跳过本页，直接走 [Docker 运行 Redis](./040.Docker运行Redis.md) 或 [Ubuntu APT 安装](./030.Ubuntu系统安装Redis.md)。

# 验证

```bash
redis-server --version    # 确认二进制版本与下载一致
sha256sum redis-8.10.2.tar.gz   # 与官方渠道公布值比对（安全习惯）
```

# 避坑

- **Unstable/rc 上生产**：候选版本（RC）的语义是"收集反馈"，持久化格式与复制协议都可能变动；生产只认 stable。
- **旧版 tar 包无人回填**：Redis 的补丁只发最新 stable 与前两个维护分支，历史分支（如 7.x 末期）的"最新版"可能落后多个修复——升级分支而不是回退版本号。
- **Windows 没有官方原生包**：不要在第三方站点找 `redis.windows.zip`，正确姿势见 [Windows 系统安装 Redis](./020.Windows系统安装Redis.md)。
- 国内网络下载 `download.redis.io` 慢时，可改用 GitHub Releases 或镜像站，但务必校验压缩包完整性。

# 总结

下载渠道的本质是"你要源码还是成品"：学习与编译部署用官方 tar 包，生产运行优先 Docker 镜像或 `packages.redis.io` 仓库包（补丁跟进快、依赖干净）。记住两条纪律——生产只用 stable，以及"最新 stable 全量维护、前两个分支仅关键修复"的维护策略，它决定你多久必须升一次 patch。
