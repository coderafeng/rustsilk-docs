# 概述

Redis **没有官方原生 Windows 版**（自 Redis 3.x 起不再随 Windows 平台发布二进制）。官方支持路径是 Docker Desktop（Linux 容器）或 Redis Stack 安装文档给出的方式；本机原生体验可走 WSL2；要"Windows 服务"形态则选兼容发行版（Memurai 等）。

- 官方文档：<https://redis.io/docs/latest/operate/oss_and_stack/install/install-stack/windows/>
- 三条路线：**Docker Desktop**（推荐，版本最新最全）、**WSL2 内按 Ubuntu 流程装**（<https://redis.io/docs/latest/operate/oss_and_stack/install/install-redis/install-redis-on-windows/>）、**Memurai** 等第三方兼容发行版（<https://www.memurai.com/>）

取舍一览：

| 路线 | 版本新鲜度 | 与生产一致性 | 运维形态 | 适用 |
|------|-----------|-------------|---------|------|
| Docker Desktop | 跟随官方镜像 | 高（Linux 内核） | 容器 | 开发/试验首选 |
| WSL2 | 走 APT/源码，同 Ubuntu | 高 | systemd 服务 | 需要本机文件/调试集成 |
| Memurai 等 | 滞后于官方 major | 中（兼容层） | Windows 服务 | 必须原生服务形态的场景 |

# 操作步骤

**路线 A：Docker Desktop（推荐）**

```powershell
docker run --name redis -d -p 6379:6379 redis:8.10
docker exec -it redis redis-cli ping
```

**路线 B：WSL2**

```bash
# 在 WSL2 的 Ubuntu 内，按 030.Ubuntu系统安装Redis.md 的 APT 流程执行
sudo service redis-server start
redis-cli -h $(hostname) ping    # Windows 侧也可经 localhost 转发访问（WSL2 默认 localhost 互通）
```

**路线 C：Memurai**

安装 Developer 版 → 作为 Windows 服务自启 → 用 `redis-cli` 连 `localhost:6379`；注意其版本与功能集是"兼容 Redis"，以 Memurai 文档的版本对照表为准。

# 验证

```powershell
redis-cli ping                                  # 期望 PONG（Docker 端口映射或 WSL 转发就绪后）
redis-cli info server | Select-String redis_version
docker ps --filter name=redis                   # 容器路线确认 Restart 策略与端口
```

# 避坑

- **不要把第三方"Windows Redis"当官方**：GitHub 上 `redis-windows` 之类的打包仓库本质是 MSYS/Cygwin 移植，版本滞后且非生产推荐——与 [010.下载Redis安装包](./010.下载Redis安装包.md) 呼应，官方 tar 包不含 Windows 构建目标。
- **Docker Desktop 许可边界**：大型企业商用需订阅计划；纯学习可用 WSL2 + APT 零成本替代。
- **WSL2 网络模式**：NAT 模式下 Windows 访问 `localhost` 通常直通，但**局域网其他机器访问 WSL 内的 Redis 需要端口转发或 `networkingMode=mirrored`**；团队联调前先 `wslconfig` 确认。
- **文件跨系统 I/O 是性能陷阱**：WSL2 里把 Redis 数据目录放在 `/mnt/d/...`（9P 协议）会让持久化与快照显著变慢，数据留在 WSL 原生文件系统内。
- 兼容发行版（Memurai 等）的**新命令/新类型往往缺位**：用到 Vector Set、字段级 TTL 等 8.x 能力前先 `COMMAND DOCS` 确认存在。

# 总结

Windows 上"装 Redis"其实是选运行形态：追求与生产一致就 Docker 或 WSL2（两者都是真 Linux Redis），追求服务化体验才考虑兼容发行版，并接受版本滞后。无论哪条路线，最终验收都是同一件事：`redis-cli ping` 得到 PONG，且 `redis_version` 与你的目标版本一致——版本以官方 Docker 镜像与 APT 仓库为最可靠来源。
