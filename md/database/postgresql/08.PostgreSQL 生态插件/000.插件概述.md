# 概述

PostgreSQL 的"外挂系统"叫 **扩展（Extension）**：一套打包好的 SQL 对象（类型、函数、操作符、索引访问方法）+ 可选的本地代码（`.so`）与后台进程，通过 `CREATE EXTENSION 名称;` 一条命令装进数据库。官方随发行版携带 **contrib** 套件（ltree、pg_trgm、btree_gin/gist、pg_stat_statements、postgres_fdw 等），社区仓库 **PGXN** 与各项目 Release 页则分发第三方扩展（pgvector、TimescaleDB、Citus、PostGIS……）。

本章覆盖 24 个在生产中最常遇到的生态插件。每个插件单独一篇，统一结构：**概述（含官方/GitHub 链接）→ 安装 → 使用示例 → 避坑 → 总结**。

# 扩展机制速记

```sql
-- 服务器上有哪些扩展可装、版本几何
SELECT name, default_version, installed_version
FROM pg_available_extensions
ORDER BY name;

-- 当前库已装的扩展
SELECT extname, extversion FROM pg_extension;

CREATE EXTENSION IF NOT EXISTS pg_stat_statements;   -- 安装
ALTER EXTENSION pg_trgm UPDATE;                      -- 升级到包内新版本
DROP EXTENSION ltree;                                -- 卸载（其对象一并删除）
```

三类扩展的"安装姿势"差异（各篇均有细说）：

| 类型              | 例子                                  | 要点                                         |
|-------------------|---------------------------------------|----------------------------------------------|
| 纯 SQL 对象       | pg_partman、pgmq                      | 装包 → `CREATE EXTENSION` 即用，无需重启     |
| 需预加载后台进程  | pg_cron、timescaledb、pg_stat_monitor | 必须配 `shared_preload_libraries` 并**重启** |
| 带自定义类型/索引 | pgvector、PostGIS、ltree              | 装进每个使用的库；大版本升级后需重装匹配版本 |

# 学习建议

1. **先掌握官方 contrib 五件套**（pg_stat_statements、pg_trgm、ltree、btree_gin/gist、postgres_fdw）——零安装风险、面试必考、解决问题立竿见影；
2. **按业务再引入重型扩展**：时序→TimescaleDB/pg_partman，向量→pgvector 起步，监控→PoWA；
3. 上生产前必读各篇"避坑"节：预加载/重启要求、版本配套矩阵、权限与膨胀，是插件运维事故的主要来源；
4. 更多扩展可查 PGXN（pgxn.org）与官方 Extensions 维基页（postgresql.org/download/extensions/）。
