# 概述

> 官方仓库：**[percona/pg_stat_monitor](https://github.com/percona/pg_stat_monitor)**
> 
> 文档：https://docs.percona.com/pg-stat-monitor/

**pg_stat_monitor** 是 Percona 出品的 PostgreSQL 查询性能监控工具，在单一视图中提供全面的查询性能洞察：查询来源（数据库/用户/应用名/客户端 IP）、执行与规划统计、查询详情与元数据，显著提升可观测性。

它是基于 **[pg_stat_statements](./090.pg_stat_statements.md#概述)** 思路开发的高级替代品，核心差异是**时间桶（bucket）**：统计不再是一锅"自上次 reset 以来的累计值"，而是按固定窗口（默认 60 秒）切片滚动存储，天然自带"过去 N 分钟每条 SQL 的耗时分布"——无需外部快照任务即可回答"14:03 那波抖动是谁造成的"。

其它增强点：

- **查询指纹**：每条规范化 SQL 附带 `md5` 指纹与直方图（`histogram`/`bucket_time`），支持耗时分布分析；
- **更多维度**：按 `application_name`、`client_ip`、`username`、`dbid` 聚合，微服务共用实例时分得清来源；
- **历史保留**：`pg_stat_monitor.max_buckets` 控制保留桶数，旧桶自动淘汰；
- 与 pg_stat_statements **共存**（后者仍是许多工具的数据源），采集开销相近。

# 安装

需要预加载（它建立在 pg_stat_statements 的钩子之上，两者一起加载），配置后重启：

```ini
# postgresql.conf
shared_preload_libraries = 'pg_stat_statements,pg_stat_monitor'

# GUC 前缀为 pg_stat_monitor.（如 track / interval / max_buckets，
# 具体名称以 SELECT * FROM pg_stat_monitor_settings 实查为准）
```

```sql
CREATE EXTENSION pg_stat_statements;   -- 先
CREATE EXTENSION pg_stat_monitor;      -- 后（部分发行版顺序敏感）
```

RPM/DEB 由 Percona 源提供（`pg_stat_monitor_18`），Docker 可用 `percona/pg_stat_monitor` 系镜像；云托管（Percona Operator for PostgreSQL 等）内置支持。

# 使用示例

## 当前桶的 Top SQL

```sql
-- 本桶内按平均耗时排序（含来源维度）
SELECT bucket_start_time,
       dbname, username, application_name,
       calls,
       round(mean_time::numeric, 2) AS mean_us,
       round((max_time)::numeric, 0) AS max_us,
       left(query, 60) AS query
FROM pg_stat_monitor
ORDER BY mean_time DESC
LIMIT 10;
```

## 跨桶看历史

```sql
-- 过去 10 分钟每条语句各时间桶的调用与耗时（抖动定位）
SELECT bucket_start_time, md5, calls, mean_time, rows
FROM pg_stat_monitor
WHERE bucket_start_time >= now() - interval '10 minutes'
ORDER BY bucket_start_time DESC, mean_time DESC;

-- 单条语句的耗时直方图：P95 长什么样
SELECT histogram FROM pg_stat_monitor WHERE md5 = 'xxxx' LIMIT 1;
```

## 运维接口

```sql
-- 查看全部 GUC 及当前值
SELECT * FROM pg_stat_monitor_settings;

-- 清空全部统计（类似 pg_stat_statements_reset）
SELECT pg_stat_monitor_reset();
```

配合 **PoWA** 或 Grafana（Postgres datasource 直查本视图）即可出图，Percona 自家 PMM 对它有原生采集器。

# 关键列速查

| 列                                                          | 含义                     |
|-------------------------------------------------------------|--------------------------|
| `bucket_id / bucket_start_time`                             | 所属时间桶               |
| `userid / dbid / uname / applicationname / client_ip`       | 谁、从哪发起             |
| `query / md5 / fingerprint`                                 | 规范化 SQL 与查询指纹    |
| `calls / rows / errors`                                     | 次数、行数、失败数       |
| `min_time / max_time / mean_time / stddev_time / calls_cnt` | 执行时间分布（微秒）     |
| `cmd_type / commands`                                       | SELECT/INSERT 等语句类别 |
| `blocks / wal / read / temp_read`                           | 缓冲、WAL、IO 指标       |
| `histogram`                                                 | 桶内耗时直方图 JSON      |

# 避坑

- **桶宽与桶数决定内存**：`interval × max_buckets` 就是可回看窗口，想查"昨天下午"不合适——长期趋势仍要外置快照或走 PoWA。
- **与 pg_stat_statements 双开有重复内存成本**：两者共享一部分内核统计，但仍各有哈希表，`max` 类参数按实例 SQL 模板量评估。
- 重启/崩溃桶历史丢失（共享内存），容器环境尤其要注意"重启即断片"。
- 视图里时间为**微秒**，与 pg_stat_statements 的毫秒口径不同，做统一看板时先归一。
- 大版本升级需安装对应版本的扩展包（Percona 源按 PG 大版本发布）。

# 总结

pg_stat_monitor 把 pg_stat_statements 的"累计账本"升级为"时间桶账本"：**自带分钟级历史、来源维度与耗时直方图**，单扩展即可完成轻量版查询画像。选型分界线：只要"能回看最近几十分钟"——它足够且比 PoWA 更轻；要多实例集中、等待事件、Web 工作台——上 **[PoWA](./095.powa.md)**（两者也可并用：powa 管展示与留存，pg_stat_monitor 管细粒度分布）。
