# 概述

用 Rust 编写的 AI 检索扩展，在召回率相同时，查询速度比 **pgvector** 快 3.8 到 5.3 倍，并且支持元数据过滤和混合检索（向量+全文）。 它有自己的类型系统（如 pgcontext.vector）和索引方法（pgcontext_hnsw）。

# 与 pgvector 关系

如果业务已经使用了 **pgvector**，可以通过 **pgcontext_pgvector** 扩展做桥接，可以在现有列上，建立并使用 pgcontext 的 HNSW 索引，从而在不迁移数据、不更改列类型的前提下，获得 pgcontext 的查询性能优势。

它们之间是松耦合的，可以独立存在，也可以组合使用。

- pgcontext 与 pgvector 相互独立：两者可以以任意顺序安装。它们各自拥有独立的 SQL 类型，例如 pgvector 拥有 public.vector，而 pgcontext 拥有 pgcontext.vector，类型 OID 是分开的。
- pgcontext_pgvector 是桥梁：这个桥接扩展依赖于 pgcontext 和 pgvector 两者。它本身不合并两套类型系统，也不复制数据，只增加经过认证的类型转换和操作符类，让 pgcontext 的索引能够覆盖 pgvector 拥有的列。

如果追求极致的查询性能，可以直接使用 pgcontext，它提供了完整的向量检索能力。已有 pgvector 项目，如果你想保留现有数据和查询语句不变，同时获得性能提升，可以安装 pgcontext + pgcontext_pgvector 组合。桥接扩展让你能够平滑地引入 pgcontext 的索引，而无需重写任何应用代码。
