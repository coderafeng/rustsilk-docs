# 概述

> 官方仓库：**[evokoa/pgcontext](https://github.com/evokoa/pgcontext)**（Apache-2.0，支持 PostgreSQL 17/18）

**pgcontext** 是用 Rust（pgrx）编写的 AI 检索扩展，把 Postgres 变成一台完整的 AI 搜索引擎：稠密向量检索、**带元数据过滤的 ANN**、**混合检索（向量 + 全文，RRF 融合）**全部在库内完成。官方基准（GloVe-100-angular，118 万向量）显示：在召回率相同时，查询速度比 **pgvector** 快 3.8~5.3 倍；同样 2.5ms 延迟下 recall@10 可达 0.91（pgvector 约 0.75）。

它有自己的类型系统（如 `pgcontext.vector`）和索引方法（`pgcontext_hnsw`），设计上有两个鲜明主张：

- **数据不搬家**：普通 Postgres 表就是唯一事实源，向量、元数据、MVCC、RLS/ACL、备份复制全走原生体系；HNSW 图只是**可重建的派生索引**，永不与应用数据脱节；
- **近似结果必须精确复核**：ANN 候选回表后按实时行重新精确打分，保证"快答案也是正确答案"。

# 与 pgvector 关系

如果业务已经使用了 **pgvector**，可以通过 **pgcontext_pgvector** 扩展做桥接，可以在现有列上建立并使用 pgcontext 的 HNSW 索引，从而在不迁移数据、不更改列类型的前提下，获得 pgcontext 的查询性能优势。

它们之间是松耦合的，可以独立存在，也可以组合使用。

- pgcontext 与 pgvector 相互独立：两者可以以任意顺序安装。它们各自拥有独立的 SQL 类型，例如 pgvector 拥有 `public.vector`，而 pgcontext 拥有 `pgcontext.vector`，类型 OID 是分开的。
- pgcontext_pgvector 是桥梁：这个桥接扩展依赖于 pgcontext 和 pgvector 两者。它本身不合并两套类型系统，也不复制数据，只增加经过认证的类型转换和操作符类，让 pgcontext 的索引能够覆盖 pgvector 拥有的列。

如果追求极致的查询性能，可以直接使用 pgcontext，它提供了完整的向量检索能力。已有 pgvector 项目，如果你想保留现有数据和查询语句不变，同时获得性能提升，可以安装 pgcontext + pgcontext_pgvector 组合。桥接扩展让你能够平滑地引入 pgcontext 的索引，而无需重写任何应用代码。

# 安装

最快的方式是预构建 Docker 镜像（多架构，Linux/macOS/Windows 均可）：

```bash
docker pull ghcr.io/evokoa/pgcontext:pg17-v0.3.0
docker run -d --rm \
  --name pgcontext \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=pgcontext \
  -p 5432:5432 \
  ghcr.io/evokoa/pgcontext:pg17-v0.3.0
```

其它渠道：Homebrew（`brew install Evokoa/tap/pgcontext`，面向 brew 的 postgresql@17）、PGXN（`pgxn install pgContext`）、源码（需要 Rust 1.96+、cargo-pgrx 0.19.1、PG 17/18 开发头文件）：

```bash
make install PG_CONFIG=/path/to/postgresql-17/bin/pg_config
```

在数据库中启用（与 pgvector 一样即装即用，无需 shared_preload_libraries）：

```sql
CREATE EXTENSION pgcontext;
```

# 快速上手：集合 + 注册 + 检索

pgcontext 的 API 风格接近 Qdrant：先把普通表注册为**集合（collection）**，声明向量字段与可过滤字段，然后调用检索函数：

```sql
CREATE TABLE docs (
    id        text PRIMARY KEY,
    embedding pgcontext.vector(3) NOT NULL,
    category  text NOT NULL,
    metadata  jsonb NOT NULL
);

INSERT INTO docs VALUES
('postgres', '[1,0,0]', 'database', '{"language":"sql"}'),
('rust',     '[0.8,0.2,0]', 'systems', '{"language":"rust"}'),
('vectors',  '[0.7,0.1,0.2]', 'database', '{"language":"sql"}');

-- 1) 把表注册为集合
SELECT * FROM pgcontext.create_collection('docs', 'public.docs');
-- 2) 声明向量字段（3 维、余弦距离）与可过滤字段
SELECT pgcontext.register_vector('docs', 'embedding', 'embedding', 3, 'cosine');
SELECT pgcontext.register_filter_column('docs', 'category', 'category');
-- 3) 把现存行索引进加速结构
SELECT pgcontext.upsert_points('docs', ARRAY['postgres', 'rust', 'vectors']);

-- 带过滤的向量检索：只返回 category=database 的最近邻
SELECT source_key, score
FROM pgcontext.search(
    'docs', '[1,0,0]'::pgcontext.vector,
    '{"must":[{"key":"category","match":"database"}]}'::jsonb,
    3
);
```

过滤语法支持 `must` / `should` / `must_not`、等值、范围（`range: {gte, lt}`）、`is_null`，字段可以是注册列，也可以是 **JSONB 路径**（如 `"key": "metadata.topic"`）——无需为此新建任何专用索引。

# HNSW 索引与 SQL 直查

除了集合 API，也可以像 pgvector 一样用纯 SQL + 专属索引：

```sql
CREATE INDEX docs_embedding_hnsw
ON docs USING pgcontext_hnsw (embedding pgcontext.vector_hnsw_cosine_ops);

SELECT id, embedding OPERATOR(pgcontext.<=>) '[1,0,0]'::pgcontext.vector AS distance
FROM docs
ORDER BY embedding OPERATOR(pgcontext.<=>) '[1,0,0]'::pgcontext.vector
LIMIT 3;
```

支持 L2、内积、余弦、L1 四种度量；IVFFlat（`pgcontext_ivfflat`）目前为实验特性。

# 混合检索

pgcontext 把"稠密向量 + Postgres 全文检索（tsvector/GIN）"用 **RRF（倒数排名融合）**合并成一路结果，权重可调——这通常是应用层 glue 代码的活，现在一条 SQL 完成（`pgcontext` 的组合检索接口，支持 dense/sparse/fuzzy 多路分支）。配套能力还包括 scroll（游标翻页）、count、facets（分面聚合）、grouping（按字段分组取最近邻）。

# 避坑

- **表是事实源、索引是派生物**：大批量导入后记得 `upsert_points` 刷新，否则集合检索看不到新行；HNSW 索引损坏直接 REINDEX，不要当数据库修。
- **过滤字段必须先注册**（`register_filter_column`）：未注册的列出现在 filter 里会报错，这是防注入的设计而非疏漏。
- 项目还很年轻（0.3.x）：仅支持 PG 17/18，百万级以上规模的 IVFFlat/HNSW 认证仍在路线图内，生产采用前用自有数据跑召回基准。
- 与 pgvector **不共享类型**：`public.vector` 与 `pgcontext.vector` 是两个类型，混用需安装 pgcontext_pgvector 桥接。

# 总结

pgcontext 瞄准的是"要独立向量库的性能、又不想离开 Postgres"的空档：过滤感知 ANN、精确复核、库内混合检索三件套都是 pgvector 目前不提供的形态。存量 pgvector 用户可用桥接索引平滑升级；新项目若以检索质量与延迟为第一优先级，pgcontext 值得进入选型清单（与 **[pgvector](025.pgvector.md)** / **[pgvectorscale](030.pgvectorscale.md)** 同场竞技）。
