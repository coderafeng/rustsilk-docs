# 概述

> 官方仓库：**[timescale/pg_textsearch](https://github.com/timescale/pg_textsearch)**（Timescale 出品，PostgreSQL 17/18）

**pg_textsearch** 为 Postgres 带来**现代 BM25 相关性排序**的全文搜索：自建 BM25 索引（Postings 格式，磁盘原生），用 `ORDER BY content <@> '查询词'` 一个操作符完成"按相关度排序取 Top-K"，通过 Block-Max WAND 算法让 top-k 查询只扫必要的倒排链。相比内置 tsvector + `ts_rank`（只是粗糙的 TF 变体打分），它的排名质量对齐 Elasticsearch 级别的 BM25，且支持表达式索引、部分索引、分区索引等 PostgreSQL 索引的全部习惯用法。

核心特性：

- 简单语法：`ORDER BY content <@> 'search terms'`
- BM25 排名可配置 `k1` 和 `b`
- 复用 PostgreSQL 文本搜索配置（分词/词干化语言站）
- 表达式索引、部分索引和分区索引
- 使用 Block-Max WAND 实现快速 top-k 查询
- 大表并行索引构建

# 安装

```bash
# 源码（依赖 cargo/Rust 工具链与 PG 开发头文件）
git clone https://github.com/timescale/pg_textsearch
cd pg_textsearch && make && sudo make install
# 或从 Releases 下载 Linux amd64/arm64 预编译包
```

必须预加载后台组件，配置后**重启**服务器：

```ini
# postgresql.conf
shared_preload_libraries = 'pg_textsearch'
```

每个库启用扩展：

```sql
CREATE EXTENSION pg_textsearch;
```

# 快速上手

```sql
CREATE TABLE documents (
    id bigserial PRIMARY KEY,
    content text,
    category_id integer
);
INSERT INTO documents (content, category_id) VALUES
('PostgreSQL is a powerful database system', 1),
('BM25 is an effective ranking function', 1),
('Full text search with custom scoring', 2);

-- BM25 索引：指定文本搜索配置（必填）
CREATE INDEX docs_idx ON documents
USING bm25 (content) WITH (text_config = 'english');

-- 按相关度取 Top-5（<@> 返回负 BM25 分数，升序即最相关在前）
SELECT * FROM documents
ORDER BY content <@> 'database system'
LIMIT 5;
```

索引可从列自动探测；需要显式指定时（部分索引、表达式索引）用 `to_bm25query()`：

```sql
SELECT * FROM documents
ORDER BY content <@> to_bm25query('database system', 'docs_idx')
LIMIT 5;
```

确认走索引（小表优化器可能宁选顺序扫描 + 独立打分）：

```sql
EXPLAIN SELECT * FROM documents ORDER BY content <@> 'database system' LIMIT 5;
-- 测试期可 SET enable_seqscan = off;
```

# 索引选项

| 选项          | 默认 | 说明                                                         |
|---------------|------|--------------------------------------------------------------|
| `text_config` | 必填 | 使用的 PostgreSQL 文本搜索配置（english/simple/pg_jieba 等） |
| `k1`          | 1.2  | 词频饱和度（0.1~10.0），越大越看重重复出现                   |
| `b`           | 0.75 | 文档长度归一化（0.0~1.0），0 为不惩罚长文                    |

```sql
CREATE INDEX ON documents USING bm25 (content)
WITH (text_config = 'english', k1 = 1.5, b = 0.8);
```

# 表达式 / 部分 / 多语言索引

```sql
-- JSONB 字段：只对 description 建 BM25
CREATE INDEX events_expr_idx ON events
USING bm25 ((data->>'description')) WITH (text_config = 'english');

-- 多列合并索引（表达式必须是 IMMUTABLE）
CREATE INDEX ON articles
USING bm25 ((coalesce(title, '') || ' ' || coalesce(body, '')))
WITH (text_config = 'english');

-- 部分索引：只索引某分类（查询必须显式 to_bm25query 指定索引名）
CREATE INDEX documents_cat1_idx ON documents USING bm25 (content)
WITH (text_config = 'english') WHERE category_id = 1;

-- 多语言表：每种语言一个部分索引
CREATE INDEX docs_en_idx ON documents USING bm25 (content)
WITH (text_config = 'english') WHERE lang = 'en';
CREATE INDEX docs_de_idx ON documents USING bm25 (content)
WITH (text_config = 'german')  WHERE lang = 'de';
```

# 布尔过滤与混合检索

BM25 索引同时支持用 `@@`（tsquery 语法）做布尔过滤：

```sql
SET default_text_search_config = 'english';  -- 必须与索引配置一致

SELECT * FROM documents
WHERE content @@ to_tsquery('english', 'postgres & (search | database) & !mysql');
```

支持 `&`、`|`、`!`、短语 `<->`、前缀 `:*`、权重限制等 tsquery 特性。

**BM25 排序与布尔过滤是两种扫描模式**，不能在一次索引扫描中同时完成——"过滤 + 排序"的常规做法是先走普通过滤，再用 `<@>` 做独立打分：

```sql
CREATE INDEX ON documents (category_id);

SELECT * FROM documents
WHERE category_id = 1                  -- 走 B-tree 预过滤
ORDER BY content <@> 'search terms'    -- BM25 独立打分
LIMIT 10;
```

# 与中文生态配合

`text_config` 接受任何文本搜索配置，因此可与 **[pg_jieba](./055.pg_jieba.md)** 组合出"中文分词 + BM25 排序"：

```sql
CREATE EXTENSION pg_jieba;
CREATE INDEX docs_zh_idx ON documents
USING bm25 (content) WITH (text_config = 'jiebacfg');
```

# 避坑

- **忘了 shared_preload_libraries**：不重启则 `CREATE EXTENSION` 或索引扫描会报错。
- **`<@>` 的方向感**：它返回**负** BM25 分，`ORDER BY ... ASC`（默认）就是相关度从高到低；想取正分数需取反。
- **`@@` 与 `<@>` 混在一个查询**不会都走 BM25 索引（两种扫描模式），预期它做"过滤 + 打分"两段式。
- 布尔过滤要求 `default_text_search_config` 与索引配置一致；**准备语句切到通用计划后再改这个 GUC**，旧缓存计划会被拒绝执行以避免错误结果，需 `DEALLOCATE` 重新准备。
- 部分索引/表达式索引**必须** `to_bm25query('查询', '索引名')` 显式指定，隐式探测会跳过它们。

# 总结

pg_textsearch 补上了 Postgres 全文搜索最后缺失的一块——**像样的相关性排序**。它与内置 tsvector/GIN 的关系不是替换而是分层：分词、tsquery 布尔语义完全复用现有体系，只把"打分与 Top-K"换成真 BM25 引擎。中文场景配 pg_jieba/ICU 分词，关键词检索即可对齐专业搜索引擎体验；需要"语义 + 关键词"时再叠加 **[pgvector](025.pgvector.md#概述)** 做混合检索（RRF 融合）。
