# 概述

> 官方文档：**[pg_stat_statements — 跟踪所有 SQL 语句的统计信息](https://www.postgresql.org/docs/18/pgstatstatements.html)**
> 
> 中文版镜像：**[pg_stat_statements — 跟踪所有 SQL 语句的统计信息](https://pgsql.cc/docs/18/pgstatstatements.html)**

- **pg_stat_statements**：核心性能分析工具，跟踪所有 SQL 语句的执行计划、调用次数、总耗时等统计信息，是定位慢查询和系统瓶颈的起点。
- **PoWA**：是一款 PostgreSQL 工作负载分析器，收集性能统计数据并提供实时图表，配合 pg_stat_statements 提供图形化界面（见 **[powa](./095.powa.md)**）。

它的工作机制是**语句规范化（jumble）**：把 `WHERE id = 5` 与 `WHERE id = 42` 折叠成同一条"查询模板"（`queryid` 相同），按模板累计调用次数、总/平均耗时、读写行数、缓冲区命中、WAL 量等指标。因此它能回答 DBA 最核心的两个问题——"**哪类语句吃掉了最多资源？**"（`ORDER BY total_exec_time DESC`）和"**哪类语句单次最慢？**"（`ORDER BY mean_exec_time DESC`），而不是一句句翻日志。

# 安装

必须预加载（统计核实在服务器进程内），配置后重启：

```ini
# postgresql.conf
shared_preload_libraries = 'pg_stat_statements'
pg_stat_statements.max = 10000        # 最多跟踪多少条规范化语句（默认 5000）
pg_stat_statements.track = all        # top(默认)/all/none —— 是否连嵌套语句一起记
```

然后在使用统计的那个库里创建扩展（通常放 `postgres` 库即可，统计覆盖整个实例）：

```sql
CREATE EXTENSION pg_stat_statements;
```

云托管（RDS/Cloud SQL/PolarDB 等）一般已默认开启，改参数组 + 重启即可。

# 使用示例：找瓶颈 SQL

Top-10 总耗时（最该优先优化）：

```sql
SELECT round(total_exec_time::numeric, 2) AS total_ms,
       calls,
       rows,
       round((100.0 * total_exec_time / sum(total_exec_time) OVER ())::numeric, 1) AS pct,
       left(query, 80) AS query
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 10;
```

单次最慢（latency 刺客）与资源画像：

```sql
SELECT mean_exec_time, calls, stddev_exec_time,
       shared_blks_hit, shared_blks_read,       -- 缓冲区命中/读盘
       temp_blks_read,                          -- 落盘（排序/哈希溢出信号）
       query
FROM pg_stat_statements
ORDER BY mean_exec_time DESC
LIMIT 10;
```

配合 `EXPLAIN` 闭环调优：从视图里拿到模板 query 与 `queryid`，再对着真实参数 `EXPLAIN (ANALYZE, BUFFERS)`（见 **[EXPLAIN](../05.PostgreSQL%20数据库管理/045.EXPLAIN.md)**）。

# 视图与关键列

| 列                                            | 含义                                          |
|-----------------------------------------------|-----------------------------------------------|
| `userid / dbid / queryid`                     | 语句身份三元组（同一模板不同用户/库分开统计） |
| `query`                                       | 规范化后的语句文本（常量被替换为 `?`）        |
| `calls`                                       | 执行次数                                      |
| `total_exec_time / mean / min / max / stddev` | 执行时间统计（ms）                            |
| `plans`                                       | 生成执行计划的次数（配合 `mean_plan_time`）   |
| `rows`                                        | 返回/影响行数                                 |
| `shared_blks_hit/read/dirty/temp_blks_*`      | 缓冲区与临时块——IO 瓶颈判据                   |
| `wal_records / wal_bytes`                     | WAL 生成量（写瓶颈判据）                      |
| `jit_*`                                       | JIT 编译开销细分                              |

辅助对象：`pg_stat_statements_info`（含 `dealloc` 计数——统计槽被挤掉的次数，过大说明 `max` 不够）、函数 `pg_stat_statements_reset([dbid[, userid[, queryid]]])` 支持全量或**按语句**清零。

# 运维姿势

```sql
-- 周期性快照到自建表，做趋势分析（或交给 PoWA/pg_wait_sampling）
CREATE TABLE pss_snapshots AS SELECT now() ts, * FROM pg_stat_statements WITH NO DATA;
INSERT INTO pss_snapshots SELECT now(), * FROM pg_stat_statements;   -- 定时任务里跑

-- 采样：开销敏感场景可降低采集比例（track_rate GUC，需 track = all）
SET pg_stat_statements.track_rate = 0.1;   -- 采 10% 语句
```

- `track_utility = on` 才会统计 `CREATE INDEX`/`VACUUM` 等工具语句（默认开）；
- `track_timing` 关掉可省计时开销，但时间列将不再有值；
- 监控采集账号只需要视图的 SELECT 权限，别授予 reset 函数。

# 避坑

- **`query` 是被规范化的**：两个字面量不同的语句在同一行里，"这条 SQL 怎么长这样"时以 `queryid` 定位、`pg_get_querydef` 不可用时回应用层找原始语句。
- **max 溢出即静默淘汰**：达到 `pg_stat_statements.max` 后冷门语句被丢弃（`dealloc` 上涨），热点画像依然准，但"每周跑一次的那条慢 SQL"可能被挤掉——调大 max（每槽几 KB，1 万槽约几十 MB）。
- **reset 的代价**：全库清零会丢掉所有历史画像，多团队共享实例时优先按 `queryid` 局部 reset。
- 统计口径是**实例级共享内存**：库重启/崩溃即清零（PG17+ 支持部分统计持久化，仍非全部），要趋势必须外置快照。
- 视图里的执行时间不含连接/解析前的排队时间，定位"整体慢"时与 `pg_stat_activity`、等待事件分析（见 **[powa](./095.powa.md)**）互补使用。

# 总结

pg_stat_statements 是性能工作的第一站：**语句模板 × 资源画像**。固定用法 = 预加载开启 → 按 `total_exec_time`/`mean_exec_time` 双排序拉 Top-N → EXPLAIN 精查 → 修复后按 queryid reset 验证。要长期留存、多实例集中看、可视化火焰图，在它之上叠 **[PoWA](./095.powa.md)** 或 **[pg_stat_monitor](./100.pg_stat_monitor.md)**。
