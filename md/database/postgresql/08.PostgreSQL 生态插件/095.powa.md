# 概述

> 官方仓库：**[powa-team/powa-archivist](https://github.com/powa-team/powa-archivist)**
> 
> 架构文档：https://powa.readthedocs.io/en/latest/architecture.html
> 
> 快速上手：https://powa.readthedocs.io/en/latest/quickstart.html

PoWA 是一个依赖于多个组件的工具。它的主要目的是收集来自多个数据源的指标，将它们存储在中央存储库中，并提供一个用户界面来呈现这些数据，以便于排查问题。

主要组成有：

- **powa-archivist** 是 PostgreSQL 的扩展，用于收集统计信息，它有两个用途：
  - 以节省空间的方式存储各种指标，并提供任何其他相关功能（例如用户留存率等）。
  - 提供一致的指标视图，隐藏不同版本 PostgreSQL 或任何其他数据源之间的任何不兼容性。
- **powa-collector** 是一个守护进程，用于从专用存储库服务器上的远程 PostgreSQL 实例（可选）收集性能指标。
- **powa-web** 是 powa 收集的指标的 web 图形用户界面。

主要数据源是 **[pg_stat_statements](./090.pg_stat_statements.md#概述)**，它是 PostgreSQL 提供的一个扩展，必须启用。其他所有数据源都是可选的，可以根据需要动态添加或移除：`pg_stat_activity`（会话/等待事件）、`pg_stat_wal_receiver`、系统级（CPU/IO，经 powa-collector 抓取）、逻辑存储指标（表/索引膨胀）等。

一句话定位：**pg_stat_statements 只有"此刻的累计值"，PoWA 把它变成"带时间轴的历史 + 等待事件分析 + 多实例集中看板"**。

# 安装

## 被监控实例（每个要观测的 PostgreSQL）

powa-archivist 随发行版打包（Debian：`postgresql-18-powa`；RHEL 有对应 rpm），并需要预加载：

```ini
# postgresql.conf
shared_preload_libraries = 'pg_stat_statements,powa'
pg_stat_statements.track = all
```

```sql
CREATE EXTENSION pg_stat_statements;
CREATE EXTENSION powa;   -- 新版本扩展名即 powa（旧文档称 powa_archivist）
```

装完重启后，扩展开始按 `powa.retention`（默认 7 天）把指标写进本地 `powa` schema。

## 集中存储 + Web UI（推荐 Docker Compose）

多实例场景把历史汇聚到专用仓库库，并用 powa-web 出图：

```yaml
# docker-compose.yml（要点示意）
services:
  powa-db:    # 中央仓库 Postgres，安装 powa 扩展
    image: postgres:18
  powa-collector:  # 可选：抓取 OS 级指标与远程实例
    image: powa/powa-collector:latest
  powa-web:        # Web UI
    image: powa/powa-web:latest
    ports: ["8888:8080"]
    environment:
      POWA_REPOSITORY: "postgresql://powa:***@powa-db/powa"
```

浏览器打开 `http://localhost:8888`，添加被监控实例的连接串即可。单机只想快点看图，可以不装 collector——powa-web 直接连被监控实例自带的 `powa` schema 历史。

# 使用示例

## 界面怎么看

- **Overview**：TPS、平均延迟、回滚率、会话数随时间的曲线，红点即异常时段；
- **Top (query history)**：按时间窗选"最耗资源的语句"——这是 pg_stat_statements 做不到的（它没有历史）；
- **Activity**：实时 `pg_stat_activity` 采样 + **等待事件**堆叠图（Lock/LWLock/IO/Client 等），定位"慢在锁还是慢在 IO"；
- **Details 页**：单条 queryid 的耗时分布、计划变化、块命中趋势，并可**直接打开 EXPLAIN 面板**对比不同时间的执行计划。

## SQL 侧常用查询

```sql
-- 保留期与仓库体积
SHOW powa.retention;
SELECT pg_size_pretty(pg_total_relation_size('powa.snapshots'));

-- 最近 1 小时最耗时语句的历史快照（直查仓库表，表名随版本略有差异，\dt powa.* 实查）
SELECT bucket, queryid, calls, total_exec_time
FROM powa.stat_statements_history
WHERE bucket >= now() - interval '1 hour'
ORDER BY total_exec_time DESC LIMIT 10;
```

## 日常排障动线

1. Overview 曲线发现异常时段 → 2. Top 圈定该时段的头部 queryid → 3. Details 看该语句的历史计划是否突变 → 4. Activity 确认是否锁等待 → 5. 处置（kill/加索引/回滚变更）。

# 避坑

- **仓库本身也会膨胀**：`powa.retention` 到期前历史只增不减，多实例高频采样时监控库 IO 不可忽略；集中式部署请给 powa-db 独立磁盘。
- **powa 扩展必须与 pg_stat_statements 同时预加载**，且注册顺序在后者之后（依赖其共享内存）。
- 被监控实例重启会清空 pg_stat_statements 累计值，PoWA 靠差分恢复历史曲线——但**重启瞬间的明细统计确实会丢**，重要操作前后手工 `powa.collect()`。
- 远程模式（powa-collector）里时钟不同步会造成曲线错位，所有节点接同一 NTP 源。
- Web UI 认证默认薄弱（单用户/反代后面），公网暴露必须挂 OAuth/反向代理鉴权。

# 总结

PoWA 是 pg_stat_statements 的"时间维度 + 图形界面"补齐者：单机装 powa 扩展就有历史与 Dashboard，多实例用 collector + 中央仓库做统一观测面。同类选择还有 **[pg_stat_monitor](./100.pg_stat_monitor.md)**（时间桶 + 查询指纹聚合，偏轻量嵌入式分析）与商业方案（Percona Monitoring and Management、Datadog 等）——需要等待事件分析与查询级历史联动时，PoWA 是开源里最完整的。
