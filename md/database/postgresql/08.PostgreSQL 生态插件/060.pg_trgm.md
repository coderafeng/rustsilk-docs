# 概述

> 官方文档：**[pg_trgm — 通过三元组相似度匹配文本](https://www.postgresql.org/docs/18/pgtrgm.html)**
> 
> 中文版镜像：**[pg_trgm — 通过三元组相似度匹配文本](https://pgsql.cc/docs/18/pgtrgm.html)**

**pg_trgm** 是 PostgreSQL 官方 contrib 扩展，提供基于**三元组（trigram）**匹配来确定字母数字文本相似性的函数和运算符，以及支持快速搜索相似字符串的索引操作符类。

原理一句话：把字符串切成"连续 3 字符"的集合（前后补两个空格做边界），`foo` → `"  f"、" fo"、"oo "`，两个字符串的相似度 = **三元组交集大小 / 并集大小**。由此获得三种内置 tsvector 给不了的能力：

- **模糊匹配**：`similarity('Postgres', 'PostgreSQL')` 抗拼写错误、大小写变形、词序打乱；
- **子串加速**：`WHERE name LIKE '%ware%'` 这类中缀查询以前只能全表扫，pg_trgm 的 GIN/GiST 索引能直接加速；
- **相似度排序**：`ORDER BY title <-> 'harry potter'` 找"最接近的 N 条"，用于搜索纠错、去重、匹配建议。

它是内置扩展中做"不精确文本搜索"的第一选择；需要中文/日韩语分词级别的搜索请转 **[pg_jieba](./055.pg_jieba.md)** / **[PGroonga](./065.pgroonga.md)**。

# 安装

随 contrib 分发，装库后启用即可（无需重启）：

```sql
CREATE EXTENSION pg_trgm;

-- 验证
SELECT show_trgm('PostgreSQL');
-- {p,po,ost,stg,tgr,gre,req,esq,sql, l,"e ",q ,ql,...}（两端空格补齐的三元组集合）
```

# 相似度函数与运算符

| 函数/操作符                                         | 说明                                                            |
|-----------------------------------------------------|-----------------------------------------------------------------|
| `similarity(a, b)`                                  | 整句相似度（0~1），忽略词边界                                   |
| `word_similarity(a, b)`                             | a 中**任一连续词段**与 b 的最佳匹配度——"短查询串配长文本"更合理 |
| `a % b`                                             | `similarity` 超过阈值即真（默认 0.3）                           |
| `a <-> b`                                           | 相似度距离 `1 - similarity`，可配合 `<->` 索引做 Top-N 排序     |
| `a <<-> b` / `a <..> b`                             | 词相似度最小/最大距离（KNN 排序用）                             |
| `set_limit(x)` / GUC `pg_trgm.similarity_threshold` | 设置/查看 `%` 的相似度门槛                                      |
| `pg_trgm.word_similarity_threshold`                 | `word_similarity` 系操作符的门槛                                |

```sql
SELECT similarity('color', 'colour');               -- ≈ 0.38，拼写变体的相似度打分
SELECT word_similarity('database', 'PostgreSQL is a great database system');

-- 拼写容错搜索（Sakila 的 film 表）
SET pg_trgm.similarity_threshold = 0.2;
SELECT title FROM film
WHERE title % 'hary pottsr'           -- 打错的 "Harry Potter"
ORDER BY title <-> 'hary pottsr'
LIMIT 5;
```

# 索引：三种操作符类

pg_trgm 提供 GiST 与 GIN 两套操作符类，各有适用姿势：

```sql
-- 整句相似度检索（%、<->）：gin_trgm_ops / gist_trgm_ops
CREATE INDEX idx_film_title_trgm ON film USING gin (title gin_trgm_ops);
CREATE INDEX idx_film_title_trgm2 ON film USING gist (title gist_trgm_ops);
```

词段级操作符（`word_similarity` 及其 KNN 排序距离）需要专门的 GiST/GIN 操作符类，名称随大版本有差异，建索引前用 `\dDO pg_trgm` 列出当前实例可用的操作符类，或直查官方文档的 Indexes 一节。

GIN vs GiST：GIN 查询更快但构建慢、占空间大，静态大数据集首选；GiST 构建快、更新友好，写多读少选它。

**中缀 LIKE 加速**是 gin_trgm_ops 最常见的隐藏用法：

```sql
-- 以前：全表扫；现在：索引扫描（'war' 的三元组直接定位候选）
SELECT title FROM film WHERE title ILIKE '%war%';
```

> 阈值权衡：`%` 的默认阈值 0.3 对短字符串几乎永不命中（"abc" vs "abd" 相似度 0.2），短文本场景把 `pg_trgm.similarity_threshold` 调到 0.1 左右再试。

# 实战：模糊匹配 + 高亮 + 去重

**搜索建议/纠错**——用户输入不完整时找最接近的标签：

```sql
SELECT tag, similarity(tag, 'data base') AS s
FROM (SELECT DISTINCT unnest(tags) AS tag FROM film) t
WHERE tag % 'data base'
ORDER BY s DESC LIMIT 10;
```

**入库去重**——新地名与已有记录相似度超阈值则拒绝：

```sql
SELECT EXISTS (
    SELECT 1 FROM cities WHERE name % 'Mannchester'   -- 输入错误也能命中 Manchester
);
```

# 避坑

- **只对字母数字有效**：三元组是字符级的，中文每字都是一个"块"，相似度模型基本失效——中文模糊搜索不要指望 pg_trgm。
- **短串高误报**：两三个字符的输入能匹配一切；`%` 查询前应校验查询串长度（如 ≥ 4 字符才启用模糊通道）。
- **`word_similarity` 索引不自动生效**：默认建的 gin_trgm_ops 索引只服务整句相似度；跨词段查询走不了索引，需按文档用 `strict_word_similarity` 或带操作符类标注的表达式索引。
- 相似度阈值是**会话级 GUC**，连接池环境注意污染：应用侧每条模糊查询显式 `SET LOCAL`。
- 与全文搜索分工：tsvector 回答"哪些词出现"（词法），pg_trgm 回答"字符串长得像不像"（字形），混合搜索常两者并联。

# 总结

pg_trgm 用三元组把"像不像"变成可索引的数值问题：`%` 做容错过滤、`<->` 做相似排序、`gin_trgm_ops` 顺手加速 `%infix%` 模糊匹配——全部是官方 contrib、零外部依赖。它是拼写纠错、模糊搜索、脏数据去重三件事的默认答案；排名质量要求更高时用 `word_similarity`，多语言全文检索交给 PGroonga。
