# 概述

> 官网：**[postgis.net](https://postgis.net/)**
> 
> 仓库：**[postgis/postgis](https://github.com/postgis/postgis/)**

**PostGIS** 是 PostgreSQL 的地理空间扩展，也是开源 GIS 事实标准——为 Postgres **增加对存储、索引和查询地理空间数据的支持**：新类型（`geometry`、`geography`、`raster`、`topology`、`pointcloud`）、上千个空间函数（`ST_*`）、以及为空间数据特制的 GiST/BRIN 空间索引。

它能回答的问题是普通 SQL 回答不了的：

- "距离这家店 3 公里以内、营业中的门店有哪些？"（半径搜索）
- "这个地址落在哪个行政区划多边形内？"（点在面内）
- "这两条规划路线是否相交？重叠多少米？"（几何关系与叠加分析）
- "过去一小时的出租车轨迹里，哪些路段车速低于 10km/h？"（线性参考）

两种核心类型的选型一句话：**`geometry` 按平面坐标算（快，适合小范围/投影坐标系），`geography` 按椭球面算（真距离，适合全球尺度）**。PostGIS 之外还有空间聚合（ST_Union）、地理编码（需配合外部地理编码服务/扩展）、栅格分析等全家桶能力，桌面端 QGIS、服务端 GeoServer 等生态都原生支持。

# 安装

```bash
# Debian/Ubuntu（官方源）
apt install postgresql-18-postgis-3
# RHEL/CentOS（PGDG + EPEL）
dnf install postgresql18-postgis35
# Docker（PostGIS 官方镜像）
docker run -d --name postgis -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgis/postgis:18-3.5
```

在目标库启用（模板库 `template1` 也建议装上，方便新库继承）：

```sql
CREATE EXTENSION postgis;

-- 验证：数据库坐标系版本与常用空间类型注册
SELECT PostGIS_Version();
SELECT * FROM geometry_columns;
```

# 数据模型：写第一条空间数据

空间参考系统标识 **SRID** 是绕不开的概念：`4326` = WGS84 经纬度（GPS 坐标系），`3857` = Web 墨卡托（Web 地图瓦片），米制计算推荐选**投影坐标系**（UTM 分区等）。

```sql
CREATE TABLE places (
    id   serial PRIMARY KEY,
    name text,
    geom geometry(Point, 4326)          -- 点，WGS84
);

-- 从 WKT / GeoJSON 写入
INSERT INTO places (name, geom) VALUES
('西湖',  ST_GeomFromText('POINT(120.15 30.25)', 4326)),
('灵隐寺', ST_SetSRID(ST_MakePoint(120.12, 30.24), 4326));

INSERT INTO places (name, geom)
VALUES ('雷峰塔', ST_GeomFromGeoJSON('{"type":"Point","coordinates":[120.14,30.23]}'));

-- 读出 GeoJSON（前端直接喂给地图库）
SELECT json_agg(ST_AsGeoJSON(t)::json) FROM places t WHERE name LIKE '%塔%';
```

面、线、多点等类型同理：`geometry(Polygon, 4326)`、`geometry(LineString, 4326)`，用 WKT 造数：`ST_GeomFromText('POLYGON((0 0,1 0,1 1,0 1,0 0))', 4326)`。

# 空间索引

给几何列建 **GiST** 索引（边界框 R-Tree，最常用的空间索引）：

```sql
CREATE INDEX idx_places_geom ON places USING gist (geom);

-- 半径查询走索引：先 bbox 粗筛，再精确距离过滤
SELECT name FROM places
WHERE ST_DWithin(geom::geography,
                 ST_SetSRID(ST_MakePoint(120.15, 30.25), 4326)::geography,
                 5000)                      -- 5 公里，单位：米
LIMIT 10;
```

要点：

- `ST_DWithin` 是**可走索引**的半径查询标准写法；`ST_Distance(...) < x` 不会走空间索引；
- 超大规模点数据可用 **BRIN**（按几何边界盒的相关性）替代 GiST，索引小几个数量级；
- 索引列与查询表达式的**类型/维度/SRID 必须一致**（`geography` 查询对应 `gist_geography_ops`），否则静默不走索引。

# 常用空间分析速查

| 类别 | 函数                                                           | 用途                                 |
|------|----------------------------------------------------------------|--------------------------------------|
| 关系 | `ST_Intersects` / `ST_Contains` / `ST_DWithin` / `ST_Touches`  | 相交/包含/邻近判断（可走索引）       |
| 测量 | `ST_Distance` / `ST_Area` / `ST_Length` / `ST_Perimeter`       | 距离、面积、长度（geography 出真值） |
| 叠加 | `ST_Union` / `ST_Intersection` / `ST_Difference` / `ST_Buffer` | 几何合并、裁剪、缓冲                 |
| 编辑 | `ST_Centroid` / `ST_Simplify` / `ST_Transform`                 | 质心、抽稀、坐标系转换               |
| 读出 | `ST_AsGeoJSON` / `ST_AsText` / `ST_AsMVT`（矢量瓦片）          | 前端渲染管线                         |

```sql
-- 示例：某区划内的门店数量（点在面内）
SELECT c.name, count(p.id) AS shops
FROM cities c
JOIN places p ON ST_Contains(c.the_geom, p.geom)
GROUP BY c.name;

-- 聚合地图的几何合并
SELECT ST_AsGeoJSON(ST_Union(geom)) FROM places;
```

# 避坑

- **经纬度顺序**：PostGIS 一律 `经度 纬度`（x y），与地图 API 常见的 `[lat, lng]` 相反，前后端对接十有八九栽在这里。
- **别用度数做米制计算**：4326 下 `ST_Distance` 返回"度"，`ST_Buffer` 变形严重——算面积/距离请 `ST_Transform` 到投影坐标系（或直接用 `geography`）。
- **geography 索引限制**：GiST geography 只支持半球的查询优化差异，超大半径（>180°）查询会退化；国内业务一般 geometry + 投影更划算。
- WKT/GeoJSON 造数记得显式给 SRID，`-1` 的几何几乎参与不了任何有意义计算。
- 大版本配套：PostGIS 升级与 PG 大版本强绑定（扩展 .so 不可跨版本混用），迁移走 pg_dump 常规路径。

# 总结

PostGIS 让"带坐标的业务"不需要再养一个独立空间数据库：点线面、栅格、拓扑全在 Postgres 内，SQL 一把梭，前端 GeoJSON 直渲染，桌面 QGIS 直连编辑。小规模用 geometry + GiST 起步，全球/真距离需求换 geography，重分析场景（叠加、网络）再评估 pgRouting 等配套扩展。
