# 概述

> 官方仓库：**[jaiminpan/pg_jieba](https://github.com/jaiminpan/pg_jieba)**

**pg_jieba** 是嵌入 [jieba](https://github.com/fukuchiyu/cppjieba) 分词器的 PostgreSQL 全文搜索扩展，解决 Postgres 内置全文检索**不支持中文**的问题。

PostgreSQL 原生 tsvector 体系按空格/标点切词，对英文等字母语言工作良好，但中文句子没有空格——`'我来到北京清华大学'` 在 simple 配置下是一个整体 token，检索必然失败。pg_jieba 把工业级中文分词器 cppjieba 接入文本搜索配置链，提供：

- **多种分词模式**：默认提供文本搜索配置 `jiebacfg`（精确模式），并支持 HMM 新词发现、全模式等配置变体（以 `\dF` 实查为准）；
- **用户自定义词典**：领域专有名词（品牌、人名）可热更新；
- **零侵入**：分词结果就是普通 tsvector，`to_tsquery`/`plainto_tsquery`/GIN 索引/排序检索的全部既有玩法照旧，还可以作为 **[pg_textsearch](./050.pg_textsearch.md)** 等 BM25 方案的中文分词前端。

> 版本提示：PG 17/18 的头部改动曾导致官方版本编译失败（[issue #66](https://github.com/jaiminpan/pg_jieba/issues/66)，18 同理），使用前先确认仓库最新提交/分支是否已支持你的服务器大版本，必要时选用社区维护的 fork。

# 安装

依赖 cppjieba（以 git submodule 形式随仓库携带），源码编译：

```bash
git clone --recursive https://github.com/jaiminpan/pg_jieba
cd pg_jieba
mkdir build && cd build
cmake -DPostgreSQL_EXECUTABLE=$(which pg_config) ..   # 确保 pg_config 在 PATH
make && sudo make install
```

conda 环境用户可直接装 conda-forge 包（含服务端二进制）。随后在目标库启用：

```sql
CREATE EXTENSION pg_jieba;

-- 确认配置已就位
SELECT cfgname FROM pg_ts_config WHERE cfgname LIKE 'jieba%';
--  jiebacfg
--  …（不同版本可能附带 HMM/全模式配置，以实际输出为准）
```

# 使用示例：中文全文搜索

建表、生成 tsvector、建 GIN 索引、查询——与英文全文搜索的唯一区别是显式指定 jieba 配置：

```sql
CREATE TABLE articles (
    id   serial PRIMARY KEY,
    title text,
    body  text
);
INSERT INTO articles (title, body) VALUES
('数据库选型', '我来到北京清华大学，讨论 PostgreSQL 与 MySQL 的选型'),
('向量检索',   'pgvector 让 PostgreSQL 支持相似性搜索');

-- 看看分词效果
SELECT to_tsvector('jiebacfg', '我来到北京清华大学');
-- '北京':2 '来':1 '清华':3 '大学':4 ...（示意：jieba 识别出 北京/清华/大学）

-- 表达式索引（指定配置名的 to_tsvector 是 IMMUTABLE，可入索引）
CREATE INDEX idx_articles_body ON articles
USING gin (to_tsvector('jiebacfg', body));

-- 检索：同时包含 PostgreSQL 和 选型
SELECT * FROM articles
WHERE to_tsvector('jiebacfg', body)
      @@ to_tsquery('jiebacfg', 'PostgreSQL & 选型');

-- 自然语言查询串交给 SQL 构造器
SELECT * FROM articles
WHERE to_tsvector('jiebacfg', body)
      @@ plainto_tsquery('jiebacfg', '支持相似性搜索');

-- 相关度排序
SELECT id, ts_rank(vec, query) AS rank
FROM articles, plainto_tsquery('jiebacfg', '向量 检索') query,
     to_tsvector('jiebacfg', coalesce(title,'') || ' ' || body) vec
WHERE vec @@ query
ORDER BY rank DESC;
```

配置选择：默认用 **jiebacfg**（精确模式，索引体积小、召回准）；未登录词较多的语料可启用 HMM 模式配置提升切出新词能力；全模式切得过碎，一般只用于探索词表。

# 自定义词典

对于分词器切错的领域词（如"华科"应为一个词），维护用户词典表并重新加载：

```sql
-- pg_jieba 提供用户词典表（词/词频/词性三列，表名与加载函数随版本不同，\d 与 \df 实查）
INSERT INTO jieba_user_dict (name, freq, tag)
VALUES ('PostgreSQL', 100, 'n'), ('云原生', 50, 'n');

-- 触发重载（如 SELECT load_user_dict();，或重启会话生效）
```

此后 `to_tsvector('jiebacfg', '云原生数据库')` 会把"云原生"作为整体 token。

# 避坑

- **索引与查询必须用同一配置**：建索引 `jiebacfg`、查询 `jieba_hmm`，token 空间对不上，查询静默 0 命中且不报错。
- **不要依赖隐式配置**：`to_tsvector(body)` 走 `default_text_search_config`，会话一改就全乱——所有 SQL 显式写 `'jiebacfg'`。
- 新装扩展后**已有数据不会自动重切**：改词典/换配置后要重建索引（`REINDEX`）。
- 与 pg_textsearch/pg_tokenizer 的选型：pg_jieba 只解决"切词"，排序仍是内置 `ts_rank`（非 BM25）；对排名有要求时把它当分词层、检索层交给 **[pg_textsearch](./050.pg_textsearch.md)**。
- C++ 扩展的 ABI 风险：PostgreSQL 大版本升级后必须重新编译安装。

# 总结

pg_jieba 是 Postgres 中文全文搜索的"标配分词器"：一行 `CREATE EXTENSION` 让 tsvector 体系读懂中文。轻量站内搜索用它 + GIN 就够；要专业排名，用它的分词结果对接 pg_textsearch（BM25）；要彻底的多语言 + 高亮 + 聚合体验，再考虑 **[PGroonga](./065.pgroonga.md)** 这种自带完整搜索引擎的方案。
