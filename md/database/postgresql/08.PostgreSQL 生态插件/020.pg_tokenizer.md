# 概述

> 官方仓库：**[supervc-stack/pg_tokenizer.rs](https://github.com/supervc-stack/pg_tokenizer.rs)**（TensorChord / VectorChord 生态）

**pg_tokenizer** 是一个用 Rust 编写的 PostgreSQL 扩展，为**全文搜索提供分词器（tokenizer）**。它本身不建索引，而是负责把原始文本切分成词元（token）并映射为 token id 数组——设计与 **[VectorChord-bm25](https://github.com/tensorchord/VectorChord-bm25)**（原生 BM25 排序索引）配合使用，为 Postgres 提供 BM25 相关性排序能力。

它解决的痛点是：Postgres 内置全文搜索（tsvector）的分词与词干化体系**对中文、日文等语言支持弱**，且没有 BM25 排序。pg_tokenizer 提供：

- **现代分词流水线**：character filter（小写化、Unicode 规范化）→ pre-tokenizer（Unicode UAX#29 切分等）→ token filter（停用词、词干化），概念上对齐 Elasticsearch 的分析器；
- **多语言**：内置 unicode 切分，可接入 jieba、Lindera、ICU 等分词模型；
- **预训练/自定义模型**：可加载 HuggingFace 词表（如 `bert_base_uncased`、`llmlingua2`），也能基于自有语料训练自定义词表；
- **与 VectorChord-bm25 的桥接**：产出的 token 嵌入（`INT[]`）可直接 cast 为 `bm25vector` 建 BM25 索引。

# 安装

最省事的方式是使用预配置的 vchord-suite Docker 镜像（内置 pg_tokenizer + VectorChord-bm25 + VectorChord）：

```bash
docker run \
  --name vchord-suite \
  -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 \
  -d tensorchord/vchord-suite:pg18-latest
```

连接后启用扩展：

```sql
CREATE EXTENSION pg_tokenizer;
```

源码安装需要 Rust 工具链与 Postgres 开发头文件，`make && make install` 后同样 `CREATE EXTENSION`。

# 创建分词器

分词器（tokenizer）= **text analyzer（切词规则）+ model（token id 词表）**，配置使用 TOML 风格文本：

```sql
-- 最简单：直接使用预训练模型
SELECT create_tokenizer('tokenizer1', $$
model = "llmlingua2"
$$);

-- 验证效果：tokenize() 返回 (token数组, token id数组)
SELECT tokenize(
  'PostgreSQL is a powerful, open-source object-relational database system.',
  'tokenizer1'
);
```

自定义切词流水线（先定义 analyzer，再挂到 tokenizer 上）：

```sql
SELECT create_text_analyzer('text_analyzer1', $$
pre_tokenizer = "unicode_segmentation"   -- 按 Unicode UAX#29 切分
[[character_filters]]
to_lowercase = {}                        -- 统一小写
[[character_filters]]
unicode_normalization = "nfkd"           -- Unicode 规范化
[[token_filters]]
skip_non_alphanumeric = {}               -- 丢弃纯符号词
[[token_filters]]
stopwords = "nltk_english"               -- 英文停用词
[[token_filters]]
stemmer = "english_porter2"              -- Porter2 词干化
$$);

SELECT create_tokenizer('tokenizer2', $$
text_analyzer = "text_analyzer1"
model = "model1"
$$);
```

# 与 VectorChord-bm25 组合：BM25 全文搜索

典型落地是把 `tokenize()` 的结果物化到 `INT[]` 列，再交给 VectorChord-bm25 建索引：

```sql
CREATE TABLE documents (
    id        SERIAL PRIMARY KEY,
    passage   TEXT,
    embedding INT[]            -- 存放 token id 序列
);

-- 一键创建"入库即分词"的触发器 + 模型 + 分词器
SELECT create_custom_model_tokenizer_and_trigger(
    tokenizer_name     => 'tokenizer1',
    model_name         => 'model1',
    text_analyzer_name => 'text_analyzer1',
    table_name         => 'documents',
    source_column      => 'passage',
    target_column      => 'embedding'
);

-- 之后正常 INSERT，embedding 列自动填充
INSERT INTO documents (passage) VALUES
('PostgreSQL is a powerful, open-source object-relational database system.'),
('BM25 is a ranking function used by search engines to estimate relevance.');
```

随后在 `embedding` 列上创建 VectorChord-bm25 的 `bm25` 索引，用其提供的操作符按 BM25 分数排序检索（详见 VectorChord-bm25 文档）。

# 避坑

- **pg_tokenizer 只管"切词"，不管"检索"**：单独安装它得不到任何搜索能力，必须配合 VectorChord-bm25（或自行消费 `tokenize()` 输出）。
- **模型词表 ≠ 索引期与查询期可混用**：换了 model 之后必须重刷全表的 `embedding` 列，否则新旧 token id 空间对不上，检索结果静默错误。
- **触发器方案有写放大**：每行插入都要跑一遍分词，大文本高频写入场景考虑异步批量 `UPDATE ... SET embedding = tokenize(...)`。
- 项目仍在快速演进（Rust/pgrx 实现），扩展版本与 VectorChord-bm25 版本要按官方 support matrix 配对使用。

# 总结

pg_tokenizer 把"现代搜索引擎的分析器流水线"带进了 Postgres：切词规则可编程、词表可训练、产出直接喂给 VectorChord-bm25 做 BM25 排序。它与 **[pg_textsearch](./050.pg_textsearch.md)**（自带 BM25 索引）、**[pg_jieba](./055.pg_jieba.md)**（只解决中文切词）形成互补三角——要完整 BM25 排名选前两者，要自定义分词模型与稀疏向量治理选 pg_tokenizer。
