# 概述

> 官方文档：**[btree_gist — 在 GiST 索引里支持 B-tree 操作符类](https://www.postgresql.org/docs/18/btree-gist.html)**
> 
> 中文版镜像：**[btree_gist — 在 GiST 索引里支持 B-tree 操作符类](https://pgsql.cc/docs/18/btree-gist.html)**

**btree_gist** 把普通 B-tree 类型（数值、时间、字符串、网络地址、UUID、范围……）装进 **GiST 索引**：对多数查询来说，B-tree 与 GiST 的检索性能相当，真正的大杀器是——**让"标量列 + 区间列"能出现在同一条排他约束（EXCLUDE）里**。

没有 btree_gist 时，`EXCLUDE USING gist` 只支持几何/range/ltree 等原生 GiST 类型；想表达"同一房间、时间段不得重叠"这类约束就无从下手。装完后：

```sql
CREATE TABLE reservation (room int, during tsrange);

-- 同房间、时间重叠的记录直接拒收——约束级防超订
ALTER TABLE reservation
ADD EXCLUDE USING gist (room WITH =, during WITH &&);

INSERT INTO reservation VALUES (11, '[2026-01-01 14:00, 2026-01-01 15:00)');
INSERT INTO reservation VALUES (11, '[2026-01-01 14:30, 2026-01-01 15:30)');
-- ERROR: conflicting key value violates exclusion constraint
```

这是会议室/酒店/排班系统数据完整性的标准解法：把并发防重从应用层"查了再插"（竞态）下沉到数据库一行 DDL。

# 安装

contrib 自带，无需重启：

```sql
CREATE EXTENSION btree_gist;
```

# 使用示例

## 排他约束的进阶形态

按周期排班（周几 + 时间段不重叠）：

```sql
CREATE TABLE chap08_meeting (
    room_id   integer,
    day_of_week varchar(9) CHECK (day_of_week IN ('Mon','Tue','Wed','Thu','Fri','Sat','Sun')),
    time_range tsrange,
    EXCLUDE USING gist (room_id WITH =, day_of_week WITH =, time_range WITH &&)
);
```

多类型混搭（文本前缀 + IP 段重叠检测）：

```sql
CREATE TABLE ip_alloc (
    vpc_id text,
    addr   cidr,
    EXCLUDE USING gist (vpc_id WITH =, addr WITH &&)   -- 同一 VPC 内网段不得重叠
);
```

## 标量列的 GiST 组合索引

对"标量等值 + 范围/几何"混合过滤，btree_gist 提供与 **[btree_gin](./080.btree_gin.md)** 对称的 GiST 操作符类（`int4_ops`、`timestamptz_ops`、`inet_ops`、`text_ops`、各 range 类型的 `_ops` 等）：

```sql
CREATE TABLE events (user_id int, ts timestamptz, latency_ms int);

CREATE INDEX events_gist_idx ON events
USING gist (user_id int4_ops, ts timestamptz_ops, latency_ms int4_ops);

-- 多个标量条件共用一个 GiST 索引（等值 + 范围）
SELECT * FROM events
WHERE user_id = 42
  AND ts BETWEEN now() - interval '1 hour' AND now()
  AND latency_ms < 100;
```

## 覆盖类型清单（节选）

`int2/int4/int8`、`numeric`、`real/float`、`oid`、`timestamp(tz)/date/time(interval)`、`interval`、`money`、`char/varchar/text/bytea`、`inet/cidr/macaddr`、`uuid`、`enum/domain`、各类 **range**（`int4range/tsrange/daterange…`）与 `bool`。

# 选型速查

| 需求                        | 选择                                                               |
|-----------------------------|--------------------------------------------------------------------|
| 标量+区间排他约束（防重叠） | **btree_gist**（唯一解）                                           |
| 标量+数组/JSONB 组合索引    | **[btree_gin](./080.btree_gin.md)**                                |
| 纯标量列多条件查询          | 普通 B-tree 复合索引                                               |
| 相似文本/中缀匹配           | pg_trgm 的 GiST/GIN 操作符类（见 **[pg_trgm](./060.pg_trgm.md)**） |

# 避坑

- **GiST 不保证唯一**：`CREATE UNIQUE INDEX ... USING gist` 不支持，纯唯一性仍归 B-tree；排他约束是 GiST 的地盘。
- **字符串列排他约束的坑**：`text WITH =` 要求列有确定 collation 语义，跨库迁移/改 collation 后约束行为要重新验证。
- **range 列参与 && 的索引键大小**：区间重叠频繁更新时 GiST 页分裂明显，高频改期的排班表考虑只约束热窗口（部分索引 + 触发器兜底）。
- 索引膨胀监控常规项：GiST 删除不即时回收，定期 `REINDEX (CONCURRENTLY)`（见 **[日常维护](../05.PostgreSQL%20数据库管理/065.日常维护.md)**）。

# 总结

btree_gist 的两个身份：**排他约束的入场券**（"A 等值 + B 重叠即冲突"这条业务规则的最短表达）与**标量列进 GiST 的适配器**。凡是"时段/区间/空间不得重复占用"的需求——预订、排班、网段分配、版本号区间——都应先看它能否一行 DDL 解决，而不是应用层的 select-for-update 竞态补丁。
