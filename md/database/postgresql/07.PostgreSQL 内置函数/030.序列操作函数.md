# 概述

本篇覆盖官方 9.16 节**序列操作函数**。序列（`sequence`）是独立的计数器对象，常给主键自增用（`serial`/`identity` 列底层就是序列）。四个函数围绕"取下一个值 / 读当前值 / 设值"。

关键心智模型：

- **`nextval` 有副作用且不可回滚**：即便事务回滚，序列也已经前进了——所以序列**必然可能跳号**，别拿它当连续编号。
- **`currval` 是"本会话最近一次 `nextval` 的值"**，不是全局当前值；本会话没调用过 `nextval` 就查 `currval` 会报错。
- **`lastval` 是本会话内任意序列的最近 `nextval`/`setval`**，排查"刚插的那行 id"时方便，但并发/多序列场景不安全，生产最好显式传序列名。

> 序列的创建与 `ALTER SEQUENCE` 见 **[序列生成器](../03.PostgreSQL%20数据库和表/100.序列生成器.md)**。

# currval

`currval(regclass) → any integer`

返回指定序列在**当前会话**中最近一次 `nextval` 得到的值；未调用过则报错。

```sql
SELECT nextval('order_id_seq');   -- 例如 42
SELECT currval('order_id_seq');   -- 42（本会话仍是 42，别的会话不受影响）
```

> 坑：`currval` 与别的会话无关——多个连接各自维护"当前值"；它也不会推进序列。

# lastval

`lastval() → any integer`

返回**当前会话**内最近一次 `nextval`/`setval` 的值（不指定是哪个序列）。

```sql
SELECT lastval();   -- 本会话上一个序列操作的值
```

> 慎用：若本会话从未碰过任何序列会报错；表上触发器可能悄悄推进了别的序列，导致 `lastval` 不是你想要的那个——务必优先用带名字的 `currval`。

# nextval

`nextval(regclass) → any integer`

**推进序列并返回新值**。原子操作，多会话并发不重复。

```sql
INSERT INTO orders (id, amt) VALUES (nextval('order_id_seq'), 100);
SELECT nextval('order_id_seq');   -- 直接取下一个
```

> 要点：`nextval` **不受事务回滚影响**，值一旦发出就消耗掉，故 id 会跳号；`identity`/`serial` 列默认值就是隐式调用它。序列无 `cache` 时每次访问磁盘，高并发可设 `CACHE n` 换性能（代价是实例崩溃会丢未用的缓存值）。

# setval

`setval(regclass, value) → any integer`；`setval(regclass, value, log boolean)`

**显式设置序列当前值**。第 3 个参数 `log` 为 `false` 时不做 WAL 记录（主库崩溃后从库可能不同步）。

```sql
SELECT setval('order_id_seq', 1000);       -- 下一个 nextval 返回 1001
SELECT setval('order_id_seq', 1000, false);-- 下一个 nextval 返回 1000
```

> 典型用途：批量 `INSERT` 里手工写了 id 后，用 `setval('seq', (SELECT max(id) FROM t))` 把序列追到最大值，否则后续 `nextval` 会撞上已有行报唯一键冲突。
