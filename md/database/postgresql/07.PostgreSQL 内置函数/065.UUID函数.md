# 概述

本篇覆盖官方 9.14 节 **UUID 函数**。`uuid` 类型存 128 位 RFC 9562 UUID。PostgreSQL 内置的生成函数走随机（v4）与时间有序（v7）两条路线，另外提供从 UUID 反解版本/时间戳的提取函数。

选型的两条主线：

- **`gen_random_uuid()` / `uuidv4()` 随机 v4**：无需任何输入、纯随机，作主键即插即用；缺点是**无序**，做 B-tree 主键插入是随机页写，索引膨胀、缓存命中差。
- **`uuidv7()` 时间有序 v7（PG18 新增）**：高 48 位是毫秒时间戳，天然**近似递增**，作为主键对索引友好（局部性接近 bigserial），又保留全局唯一，是新项目主键的推荐选择。

> `uuid-ossp` 扩展另提供 v1/v3/v5 等标准算法（见 **[生态插件概览](../08.PostgreSQL%20生态插件/000.生态插件概览.md)**）。UUID 作为主键的索引代价，见 **[索引类型](../06.PostgreSQL%20索引/005.索引类型.md)**。

# gen_random_uuid

`gen_random_uuid() → uuid`

生成**版本 4（随机）UUID**。PG13 起内置，无需扩展，使用系统加密级随机源。

```sql
SELECT gen_random_uuid();   -- 5b30857f-0bfa-48b5-ac0b-5c64e28078d1
```

> 可直接作列默认值：`id uuid PRIMARY KEY DEFAULT gen_random_uuid()`。每次调用都产生新随机值，不可复现。

# uuidv4

`uuidv4() → uuid`

同样生成**版本 4（随机）UUID**，是 PG18 提供的、语义更明确的 v4 命名（与 `gen_random_uuid()` 等价）。

```sql
SELECT uuidv4();   -- b42410ee-132f-42ee-9e4f-09a6485c95b8
```

> 二者择一即可；`uuidv4`/`uuidv7` 命名成套，可读性更好。

# uuidv7

`uuidv7([ shift interval ]) → uuid`

生成**版本 7（时间有序）UUID**：48 位毫秒时间戳 + 子毫秒 + 随机位。可选 `shift` 参数把时间戳平移给定间隔（不接受无穷间隔，平移后须落在 1970 至约公元 10889 年范围内）。

```sql
SELECT uuidv7();                       -- 019535d9-3df7-79fb-b466-fa907fa17f9e
SELECT uuidv7(interval '-1 hour');    -- 时间戳回拨 1 小时
```

> 推荐作主键：插入近似递增，索引局部性好；同一毫秒内仍靠随机位保证唯一，但**不保证严格单调**，别当有序流水号解析。

# uuid_extract_timestamp

`uuid_extract_timestamp(uuid) → timestamp with time zone`

从**版本 1 或 7** 的 UUID 中反解时间戳；其他版本返回 NULL。提取值不保证精确等于生成时刻（取决于生成实现）。

```sql
SELECT uuid_extract_timestamp('019535d9-3df7-79fb-b466-fa907fa17f9e'::uuid);
-- 2025-02-23 21:46:24.503-05
```

# uuid_extract_version

`uuid_extract_version(uuid) → smallint`

提取 UUID 的**版本号**（RFC 9562 变体）；其他变体返回 NULL。

```sql
SELECT uuid_extract_version('41db1265-8bc1-4ab3-992f-885799a4af1d'::uuid);   -- 4
SELECT uuid_extract_version(uuidv7());                                        -- 7
```
