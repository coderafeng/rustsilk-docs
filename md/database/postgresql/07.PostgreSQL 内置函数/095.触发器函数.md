# 概述

本篇覆盖官方 9.28 节**触发器函数**。触发器函数是一种特殊函数：声明为返回 `trigger`、无参数、用 C 或过程语言（PL/pgSQL）编写，由 `CREATE TRIGGER` 在表事件上调用。PostgreSQL 内置了几个开箱即用的触发器函数，多数业务触发器则手写。

理解触发器函数的关键上下文：

- **返回类型是 `trigger`**：BEFORE 触发器返回 `NEW`（可修改行）/`NULL`（跳过本次操作）；AFTER/INSTEAD OF 返回值被忽略。
- **能访问 `NEW`/`OLD` 记录**与一组 **触发器变量**：`TG_OP`（INSERT/UPDATE/DELETE）、`TG_WHEN`、`TG_LEVEL`、`TG_NAME`、`TG_TABLE_NAME`、`TG_ARGV` 等。
- **不能直接建普通索引/被普通 SQL 调用**：它只作为触发器动作存在。

> 手写 PL/pgSQL 触发器（审计、自动维护 `updated_at`）见 **[05.PostgreSQL 数据库管理](../05.PostgreSQL%20数据库管理/000.命令概述.md)** 的触发器章节；`tsvector_update_trigger` 服务的全文检索见 **[文本检索函数](./075.文本检索函数.md)**。

# suppress_redundant_updates_trigger

`suppress_redundant_updates_trigger() → trigger`

定义为 **BEFORE UPDATE** 行级触发器时，若新值与旧值**完全相同**，返回 NULL 跳过这次空更新——避免无意义的写放大、WAL 与触发器级联。

```sql
CREATE TRIGGER trg_noop_update
  BEFORE UPDATE ON my_table
  FOR EACH ROW
  EXECUTE FUNCTION suppress_redundant_updates_trigger();
```

> 适用高频"整行覆盖式 UPDATE"（ORM 常把未变字段也提交）的场景。注意它会让 `UPDATE ... WHERE` 的受影响行数在"值未变"时为 0，业务侧别误判。

# tsvector_update_trigger

`tsvector_update_trigger(tsvector_col, config_oid, doc_col [, ...]) → trigger`

**BEFORE INSERT OR UPDATE** 行级触发器：自动把指定文本列**加权合并成一个 `tsvector` 列**，省去手工维护。参数依次是目标 tsvector 列名、搜索配置的 OID（如 `pg_catalog.english`）、参与索引的源文本列。

```sql
ALTER TABLE doc ADD COLUMN textsearchable_index_col tsvector;
CREATE TRIGGER tsvectorupdate BEFORE INSERT OR UPDATE
  ON doc FOR EACH ROW EXECUTE FUNCTION
  tsvector_update_trigger(textsearchable_index_col, 'pg_catalog.english', title, body);
```

> 源列可分别设权重（`setweight` 内部处理）；比在应用层每次算 `to_tsvector` 更省心，配合 GIN 索引即可做站内检索。

# trigger_data

`trigger_data() → json`

返回一个 **JSON 对象**，包含当前触发器的上下文信息（`table_name`、`text_argv`、`nargs`、`when`、`level`、`trigger_name`、`event`、`args`、`name`），便于在通用触发器函数里动态判断"是哪个触发器、什么操作"。

```sql
-- 在 PL 触发器里可查当前触发事件（等价的变量在 PL/pgSQL 里是 TG_OP 等）
SELECT trigger_data();
```

> 主要给 C/扩展级触发器函数用；PL/pgSQL 里通常直接读 `TG_OP`/`TG_NAME` 等变量，比调 `trigger_data()` 更直接。
