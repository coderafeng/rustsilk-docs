# 概述

本篇覆盖官方 9.21 节**窗口函数**。窗口函数在"不折叠行"的前提下，让每一行能访问同组其他行——`GROUP BY` 会合并行，窗口函数保留所有行并附带计算列。

语法骨架：

```sql
函数(...) OVER ([PARTITION BY 分组列] [ORDER BY 排序列] [帧窗口 ROWS/RANGE ...])
```

三条最容易踩的线：

- **`rank` vs `dense_rank` vs `row_number`**：并列时 `rank` 跳号（1,1,3）、`dense_rank` 不跳（1,1,2）、`row_number` 强制唯一（1,2,3，看排序稳定性）。
- **默认帧陷阱**：带 `ORDER BY` 又没写帧时，默认帧是 `RANGE UNBOUNDED PRECEDING..CURRENT ROW`，而 `CURRENT ROW` 会把**所有排序并列的行**都算进当前，导致 `sum() OVER (ORDER BY x)` 结果反直觉。要精确控制就显式写 `ROWS BETWEEN ...`。
- **不能直接用在 WHERE**：过滤窗口结果要套一层子查询/CTE。

> 聚合函数也能当窗口函数用（`sum() OVER ()` 等），聚合本体见 **[聚合函数](./060.聚合函数.md)**。

# cume_dist

`cume_dist() → double precision`

累计分布：值 **≤ 当前行** 的行数 / 分区总行数，落在 (0,1]，最后一行恒为 1。

```sql
SELECT name, cume_dist() OVER (ORDER BY score) FROM students;
```

# dense_rank

`dense_rank() → bigint`

排名，并列同名且**不跳号**（1,1,2,3）。

```sql
SELECT name, dense_rank() OVER (ORDER BY score DESC) AS rk FROM students;
```

# first_value

`first_value(anyelement) OVER (...) → anyelement`

返回**帧内第一个值**。默认帧下常等于分区排序后的首行。

```sql
SELECT name, first_value(score) OVER (PARTITION BY class ORDER BY score) FROM students;
```

> 坑：想要"分区内最大值对应的那一行首列"，`first_value` 受帧影响，配合显式 `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` 才稳定；单纯取最值用 `min/max OVER`。

# lag

`lag(value [, offset [, default]] ) OVER (ORDER BY ...) → 同 value`

取**当前行之前**第 offset 行的值（默认前 1 行）；越界返回 default（默认 NULL）。做同比/环比首选。

```sql
SELECT day, revenue,
       lag(revenue, 1) OVER (ORDER BY day) AS prev_day,
       revenue - lag(revenue, 1) OVER (ORDER BY day) AS diff
FROM daily_sales;
```

> `lag`=往前看，`lead`=往后看；"上一行"若排序有并列，结果依赖排序稳定性，必要时加唯一次级排序键。

# last_value

`last_value(anyelement) OVER (...) → anyelement`

返回**帧内最后一个值**。默认帧的 `CURRENT ROW` 让它往往不是你以为的"分区末行"。

```sql
SELECT name, last_value(score) OVER (
  ORDER BY score
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
) FROM students;   -- 显式帧才是全分区最后一个
```

# lead

`lead(value [, offset [, default]] ) OVER (ORDER BY ...) → 同 value`

取**当前行之后**第 offset 行的值。`lag` 的反向。

```sql
SELECT day, revenue, lead(revenue) OVER (ORDER BY day) AS next_day FROM daily_sales;
```

# nth_value

`nth_value(anyelement, n int) OVER (...) → anyelement`

返回**帧内第 n 个值**（n 从 1 起）；n 越界返回 NULL。n=1 即 `first_value`。

```sql
SELECT name, nth_value(score, 2) OVER (ORDER BY score ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
FROM students;   -- 分数第 2 低的值
```

# ntile

`ntile(n int) OVER (ORDER BY ...) → integer`

把分区按序**均分成 n 桶**，返回桶号（1..n），尽量均匀。分位数/分层抽样用。

```sql
SELECT name, ntile(4) OVER (ORDER BY score) AS quartile FROM students;  -- 分四档
```

> 桶大小无法整除时，前面的桶会多 1 行；`ntile(1)` 全部返回 1。

# percent_rank

`percent_rank() → double precision`

相对排名：`(rank - 1) / (总行数 - 1)`，落在 [0,1]，第一名恒为 0。

```sql
SELECT name, percent_rank() OVER (ORDER BY score) FROM students;
```

> 与 `cume_dist` 区别：`percent_rank` 基于 `rank`（含并列，首值 0），`cume_dist` 是累计占比（末值 1）。

# rank

`rank() → bigint`

排名，并列同名且**跳号**（1,1,3）。

```sql
SELECT name, rank() OVER (PARTITION BY class ORDER BY score DESC) AS rk FROM students;
```

> "每类取前 3 名"经典写法：外层 `WHERE rk <= 3`，内层算 `rank() OVER (PARTITION BY class ORDER BY score DESC)`。

# row_number

`row_number() → bigint`

给分区内每行**从 1 连续编号**，无视并列、绝对唯一。去重取每组一行最常用。

```sql
SELECT * FROM (
  SELECT *, row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC) rn
  FROM orders
) t WHERE rn = 1;   -- 每个用户最新一单
```

> 与 `rank` 区别：`row_number` 对并列行也会给出不同序号（依赖排序稳定性）；要"确定性去重"必须在 `ORDER BY` 里补唯一列。
