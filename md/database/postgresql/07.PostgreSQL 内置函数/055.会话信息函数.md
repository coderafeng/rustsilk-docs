# 概述

本篇覆盖官方 9.25 节**会话信息函数**：读取当前连接/会话的身份、库、schema、后端进程、网络地址、锁等待等运行期信息。多为无参或极简参数，常在诊断、审计、动态 SQL 里出现。

- **`current_user` vs `session_user`**：前者是可能被 `SET ROLE` 切换的"当前有效角色"，后者是登录时的原始会话用户；权限判断通常看 `current_user`。
- **`user` 是 `current_user` 的同义词**（SQL 标准遗留）。
- **`pg_` 前缀系列**读的是服务端进程/实例状态，做排障（谁堵谁、后端 PID、启动时间）时最有用。

> 更多系统目录/管理函数见 **[系统信息函数](./085.系统信息函数.md)** 与 **[系统管理函数](./090.系统管理函数.md)**。

# current_catalog

`current_catalog → name`

当前**数据库名**（SQL 标准写法，等价 `current_database()`）。

```sql
SELECT current_catalog;   -- sakila
```

# current_database

`current_database() → name`

返回**当前连接的数据库名**。

```sql
SELECT current_database();
```

# current_query

`pg_current_query() → text`

返回**当前正在执行的 SQL 语句文本**（常用于审计/触发器日志）。

```sql
-- 在审计触发器里记录触发动作来源语句
SELECT current_query();
```

> 提示：占位标题 `current_query` 对应的服务端函数为 `pg_current_query()`；旧版本或非支持环境可能不可用。

# current_role

`current_role → name`

当前**有效角色**名（受 `SET ROLE` 影响），是 `current_user` 的别名。

```sql
SET ROLE analyst;
SELECT current_role;   -- analyst
```

# current_schema

`current_schema() → name`

返回**搜索路径中第一个可见 schema**（新建对象默认落这里）。

```sql
SELECT current_schema();
```

# current_schemas

`current_schemas(boolean) → name[]`

返回**搜索路径列表**；参数 `true` 时展开隐式系统 schema（如 `pg_catalog`、`pg_temp`）。

```sql
SELECT current_schemas(false);           -- {public}
SELECT current_schemas(true);            -- {"pg_catalog",public,...}
```

# current_user

`current_user → name`

当前**有效用户/角色**名（权限判定用这个）。

```sql
SELECT current_user;
```

# inet_client_addr

`inet_client_addr() → inet`

**客户端**的 IP 地址（本地/Unix 套接字连接可能返回 NULL）。

```sql
SELECT inet_client_addr();
```

# inet_client_port

`inet_client_port() → integer`

**客户端**使用的 TCP 端口。

```sql
SELECT inet_client_port();
```

# inet_server_addr

`inet_server_addr() → inet`

**服务器**本端监听到的 IP 地址。

```sql
SELECT inet_server_addr();
```

# inet_server_port

`inet_server_port() → integer`

**服务器**监听的端口（默认 5432）。

```sql
SELECT inet_server_port();
```

> 四个 `inet_*` 组合起来可还原"谁从哪个端口连到哪个端口的哪个端口"，排查连接来源很有用。

# pg_backend_pid

`pg_backend_pid() → integer`

当前会话对应的**服务端后台进程 PID**，用于 kill、日志关联、gdb Attach。

```sql
SELECT pg_backend_pid();
```

# pg_blocking_pids

`pg_blocking_pids(integer) → integer[]`

返回**阻塞指定 PID 持锁**的所有后端 PID 数组，锁等待排障第一步。

```sql
SELECT pid, pg_blocking_pids(pid) AS blocked_by
FROM pg_stat_activity WHERE wait_event_type = 'Lock';
```

> 参数是被阻塞的后端 PID（通常填自己的 `pg_backend_pid()` 或 `pg_stat_activity.pid`）。

# pg_conf_load_time

`pg_conf_load_time() → timestamptz`

`postgresql.conf` 最近一次**加载时间**，判断改配置后是否 reload 生效。

```sql
SELECT pg_conf_load_time();
```

# pg_current_logfile

`pg_current_logfile([column text]) → text`

返回**当前日志文件路径**；传列名参数可配合日志收集。

```sql
SELECT pg_current_logfile();
```

# pg_is_other_temp_schema

`pg_is_other_temp_schema(oid) → boolean`

指定 OID 是否为**其他会话的临时 schema**（不能访问别人的临时表）。

```sql
SELECT pg_is_other_temp_schema(2200);
```

# pg_jit_available

`pg_jit_available() → boolean`

当前实例是否**可用 JIT**（编译了 LLVM 且 `jit` 开启）。

```sql
SELECT pg_jit_available();
```

# pg_listening_channels

`pg_listening_channels() → setof text`

返回当前会话通过 `LISTEN` **正在监听的通知通道名**（集合返回）。

```sql
LISTEN orders_changed;
SELECT pg_listening_channels();   -- orders_changed
```

# pg_my_temp_schema

`pg_my_temp_schema() → oid`

当前会话**临时 schema 的 OID**，没有则返回 0。

```sql
SELECT pg_my_temp_schema();
```

# pg_notification_queue_usage

`pg_notification_queue_usage() → double precision`

ASYNC 通知队列的**占用比例**（0~1），接近 1 需及时消费 `NOTIFY`。

```sql
SELECT pg_notification_queue_usage();
```

# pg_postmaster_start_time

`pg_postmaster_start_time() → timestamptz`

**数据库实例（postmaster）启动时间**，用于判断是否刚重启。

```sql
SELECT pg_postmaster_start_time();
```

# pg_trigger_depth

`pg_trigger_depth() → integer`

当前**触发器嵌套调用深度**，顶层为 0。常在触发器里用它防止递归自触发。

```sql
-- 触发器里：只有非触发器嵌套内才执行，避免无限递归
WHEN (pg_trigger_depth() = 0)
```

# session_user

`session_user → name`

**登录时的原始会话用户**，不受 `SET ROLE` 影响。

```sql
SELECT session_user;
```

# user

`user → name`

`current_user` 的**同义写法**（不带括号）。

```sql
SELECT user;   -- 等价 SELECT current_user
```

# version

`version() → text`

返回**服务端版本全字符串**（含发行、编译器、平台信息）。

```sql
SELECT version();
-- PostgreSQL 18.x ...
```

> 只看版本号数字用 `SHOW server_version;` 或 `pg_catalog.pg_version`；`version()` 适合打印诊断。
