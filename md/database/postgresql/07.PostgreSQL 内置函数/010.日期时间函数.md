# 概述

本篇覆盖官方 9.9 节**日期/时间函数**。PostgreSQL 的时间类型有 `date`、`time`、`timestamp`（无时区）、`timestamptz`（带时区）、`interval`，函数大多围绕它们转换。

先建立三个关键心智模型：

- **`now()` 家族返回的是"事务/语句起点"，不是墙钟**：`now()`、`current_timestamp`、`transaction_timestamp()` 在同一事务内**恒定不变**；要每行都取实时用 `clock_timestamp()`。这直接影响批量插入时 `created_at` 是否一致。
- **`timestamp` vs `timestamptz`**：存时刻优先用 `timestamptz`，它按会话时区自动换算，跨时区不出错；`timestamp` 只是"字面日期时间"，无时区语义。
- **`extract` / `date_part` 同义**，`date_trunc` 是"归零到某单位"（按月/天聚合统计的标配）。

# age

`age(timestamp | timestamptz [, timestamp2]) → interval`

返回与 `now()`（或给定的第二参数）之间的**间隔**，并把结果按"年月"与"24 小时日"做 justify 处理。

```sql
SELECT age('1994-12-27', '2020-01-01');   -- -25 years -4 days
SELECT age('1957-06-13'::timestamptz);    -- 距今多久（含 years/months/days）
```

> 提示：算"年龄/工龄"用它，比 `date_part('year', ...) - ...` 更准（考虑了月日）。单参数版以当前 `now()` 为基准。

# clock_timestamp

`clock_timestamp() → timestamp with time zone`

返回**真实的当前时间**，即使在同一条语句/同一个事务内每次调用都在变。

```sql
SELECT clock_timestamp(), pg_sleep(1), clock_timestamp();  -- 两个时间相差约 1 秒
```

> 对比：`now()` 在一次事务内不变。做耗时统计、逐行时间戳用 `clock_timestamp()`。

# current_date

`current_date → date`

返回当前**日期**（受会话时区影响的"今天"）。是 SQL 标准的关键字（不带括号）。

```sql
SELECT current_date;   -- 2026-09-24
```

# current_time

`current_time → time with time zone`

返回当前**时间（含时区）**。

```sql
SELECT current_time;   -- 14:03:22.123456+08
```

# current_timestamp

`current_timestamp → timestamp with time zone`

当前事务开始时的时间戳，等价于 `now()`。事务内**不变**。

```sql
SELECT current_timestamp;   -- 2026-09-24 14:03:22.123456+08
```

> 用于列默认值（`created_at timestamptz DEFAULT current_timestamp`）时，同事务多行会得到相同时间戳——通常正是想要的"批次时间"。

# date_bin

`date_bin(stride interval, source timestamp, origin timestamp) → timestamp`

把时间**向下取整到 stride 的整数倍**（相对 origin）。做时间序列降采样（5 分钟、1 小时窗口）比 `date_trunc` 灵活——stride 可任意。

```sql
SELECT date_bin('15 minutes', timestamp '2020-02-11 15:44:0', timestamp '2001-01-01');
-- 2020-02-11 15:30:00
```

> PG 14+ 提供。origin 用来对齐相位（例如按周一为起点分周）。

# date_part

`date_part(field text, source timestamp|interval) → double precision`

提取时间/间隔的**某一部分**（year、month、hour、epoch…），与 `extract` 等价，但可作用于更多类型（含 `time`）。

```sql
SELECT date_part('day', timestamp '2001-02-16 20:38:40');   -- 16
```

> 坑：`date_part` 返回 `double precision`，而 `extract` 新版本返回 `numeric`，做整数比较/运算时注意类型。

# date_trunc

`date_trunc(field text, source timestamp|interval) → timestamp|interval`

把时间**截断到指定单位**（比它小的单位归零）。按天/月/小时聚合的标配。

```sql
SELECT date_trunc('hour', timestamp '2001-02-16 20:38:40');   -- 2001-02-16 20:00:00
```

> 实战：`GROUP BY date_trunc('day', created_at)` 做每日统计。想给索引建表达式，可参照 **[表达式索引](../06.PostgreSQL%20索引/035.表达式索引.md)**。

# extract

`extract(field FROM source) → numeric`

SQL 标准写法，从时间/间隔中抽取字段（`year`、`month`、`dow`、`epoch`、`isoyear`…）。

```sql
SELECT extract(year from timestamp '2001-02-16 20:38:40');   -- 2001
```

> PG 14+ `extract` 返回 `numeric`（整数部分精确无浮点误差），比 `date_part` 更适合精确计算。

# isfinite

`isfinite(timestamp|date|interval) → boolean`

判断时间/间隔是否为**有限值**（`infinity`、`-infinity`、溢出算不算有限返回 false）。

```sql
SELECT isfinite(date 'infinity');   -- false
```

# justify_days

`justify_days(interval) → interval`

把间隔中超过 30 天的部分**折算成月**。

```sql
SELECT justify_days(interval '50 days');   -- 1 mons 20 days
```

# justify_hours

`justify_hours(interval) → interval`

把间隔中超过 24 小时的部分**折算成天**。

```sql
SELECT justify_hours(interval '30 hours');   -- 1 day 06:00:00
```

> 组合：`justify_interval` = 同时做 days + hours 的规整。

# justify_interval

`justify_interval(interval) → interval`

综合规整间隔：把小时折成天、天折成月，并按有符号方式规范化。

```sql
SELECT justify_interval(interval '1 mon -1 hour');   -- 29 days 23:00:00
```

# localtime

`localtime → time`

当前**日期时间的时间部分**（受时区影响的本地时间），SQL 关键字（不带括号）。

```sql
SELECT localtime;   -- 14:03:22.123456
```

# localtimestamp

`localtimestamp → timestamp`

当前**不带时区的时间戳**（本地时间字面值）。

```sql
SELECT localtimestamp;   -- 2026-09-24 14:03:22.123456
```

# make_date

`make_date(year int, month int, day int) → date`

由年月日**组装**一个 date。`extract` 的逆向。

```sql
SELECT make_date(2013, 7, 15);   -- 2013-07-15
```

# make_interval

`make_interval([years int, months int, weeks int, days int, hours int, mins int, secs double precision]) → interval`

由各分量组装 interval，参数**具名可选**。

```sql
SELECT make_interval(days => 10);            -- 10 days
SELECT make_interval(hours => 1, mins => 30); -- 01:30:00
```

# make_time

`make_time(hour int, min int, sec double precision) → time`

由时分秒组装 time。

```sql
SELECT make_time(1, 30, 20);   -- 01:30:20
```

# make_timestamp

`make_timestamp(year,month,day,hour,min,sec) → timestamp`

组装**无时区**时间戳。

```sql
SELECT make_timestamp(2013, 7, 15, 8, 15, 23.5);   -- 2013-07-15 08:15:23.5
```

# make_timestamptz

`make_timestamptz(year,month,day,hour,min,sec [, timezone text]) → timestamptz`

组装**带时区**时间戳，可显式指定时区（默认会话时区）。

```sql
SELECT make_timestamptz(2013, 7, 15, 8, 15, 23.5, 'America/Los_Angeles');
```

# now

`now() → timestamp with time zone`

当前**事务开始时间**，事务内恒定。等价 `current_timestamp`。

```sql
SELECT now();   -- 2026-09-24 14:03:22+08
```

> 为什么一次查询里多行 `now()` 相同？因为它代表事务快照时刻，保证同语句结果一致。要真实时钟用 `clock_timestamp()`。

# pg_sleep

`pg_sleep(seconds double precision) → void`

让当前会话**暂停指定秒数**（可含小数）。

```sql
SELECT pg_sleep(1.5);   -- 睡 1.5 秒
```

> 坑：会**一直占用连接和事务**，生产环境慎用（尤其连接池里）。测试锁等待/超时才有用。PG18 提供 `pg_sleep_for`/`pg_sleep_until` 更直观。

# pg_sleep_for

`pg_sleep_for(duration interval) → void`

按 **interval** 暂停（比裸秒数更易读）。PG 18 新增。

```sql
SELECT pg_sleep_for(interval '2 seconds');
```

# pg_sleep_until

`pg_sleep_until(timestamp with time zone) → void`

睡到**指定的绝对时刻**（若已过则立即返回）。PG 18 新增。

```sql
SELECT pg_sleep_until(now() + interval '1 minute');
```

# statement_timestamp

`statement_timestamp() → timestamp with time zone`

当前**语句开始执行**的时间。同一语句内不变，语句之间会变。

```sql
SELECT statement_timestamp();
```

> 精度介于 `now()`（事务级）与 `clock_timestamp()`（实时）之间，适合记录"语句发起时刻"。

# timeofday

`timeofday() → text`

返回**当前事务时间**的完整可读字符串（类似 `Tue Sep 24 ...`）。

```sql
SELECT timeofday();   -- Mon Sep 24 14:03:22.123456 2026 PDT
```

> 历史遗留：它其实调用的是 `now()`，事务内不变。真正实时请用 `clock_timestamp()::text`。

# to_date

`to_date(text, format text) → date`

按格式模板把字符串解析为 **date**。

```sql
SELECT to_date('05 Dec 2000', 'DD Mon YYYY');   -- 2000-12-05
```

> 坑：格式符要与文本严格对应；解析出的 date 不含时区。模板细节见官方 Table 9.8。

# to_timestamp

`to_timestamp(text, format) → timestamptz`
`to_timestamp(double precision) → timestamptz`

字符串按模板解析为时间戳；或把 **Unix epoch 秒数**转 timestamptz。

```sql
SELECT to_timestamp('2020-03-04 15:12:13', 'YYYY-MM-DD HH24:MI:SS');
SELECT to_timestamp(0);   -- 1970-01-01 00:00:00+00
```

> 双向：字符串→时间用 `to_timestamp`/`to_date`，时间→字符串用 `to_char`（见 **[字符串函数](./000.字符串函数.md)**）。

# transaction_timestamp

`transaction_timestamp() → timestamp with time zone`

当前**事务开始时间**，与 `now()`、`current_timestamp` 完全等价。

```sql
SELECT transaction_timestamp();
```

> 三个"时间戳"对比：`transaction_timestamp`/`now`（事务起点）< `statement_timestamp`（语句起点）< `clock_timestamp`（实时）。按需选精度。
