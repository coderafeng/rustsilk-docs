# 概述

装 PostgreSQL 前得先把包拿到手，并且**确认拿到的是官方、未被篡改的那份**——源码是要编译成二进制、跑在生产上的，中间任何一环被动过手脚都会被信任下去。本篇是 [03.Ubuntu系统安装PostgreSQL](./03.Ubuntu系统安装PostgreSQL.md) 的前置：只解决**获取**与**校验**两件事，编译安装交给 03。

获取渠道按用途分三条：

- **官方 FTP 源码包**（本文主线）：`https://www.postgresql.org/ftp/source/`，源码编译走这条；
- **镜像站**：内容、路径与官方 FTP 完全一致，国内下载更快；
- **Git 仓库**：带**签名 tag**，是唯一能做 GPG 强校验的渠道。

Windows 用户拿的是**二进制安装器**（图形化一键装），不走源码这条线，见 [02.Windows系统安装PostgreSQL](./02.Windows系统安装PostgreSQL.md)。

要点速览：

| 项目 | 值 |
|------|---|
| 版本口径 | PostgreSQL **18.7**（与 03 篇一致） |
| 源码包 | `postgresql-18.7.tar.bz2`（约 23 MB，首选 bzip2；另有 `.tar.gz`） |
| 官方地址 | `https://ftp.postgresql.org/pub/source/v18.7/postgresql-18.7.tar.bz2` |
| 目录结构 | `.../source/v<版本>/postgresql-<版本>.tar.<ext>` |
| 完整性文件 | 同目录附带 `.sha256` 与 `.md5` |
| 强校验 | Git 签名 tag `REL_18_7` + GPG |
| 文档包（可选） | `postgresql-18.7-docs.tar.gz` |

# 版本与文件命名

PostgreSQL 的版本号是 `大版本.小版本`（如 `18.7` = 第 18 大版本的第 7 个更新版）。源码包命名与所在目录一一对应：

- 包文件：`postgresql-18.7.tar.bz2`
- 所在目录：`v18.7`（注意目录名带 `v` 前缀、文件名不带）

同一目录里的成套文件：

| 文件 | 用途 |
|------|------|
| `postgresql-18.7.tar.bz2` | 源码包（bzip2，体积最小，首选） |
| `postgresql-18.7.tar.gz` | 源码包（gzip，二选一，内容相同） |
| `postgresql-18.7.tar.bz2.sha256` / `.md5` | 对应的校验值 |
| `postgresql-18.7-docs.tar.gz` | 离线文档，不含源码，一般不必下 |

> [!note]
> `.tar.bz2` 与 `.tar.gz` 是同一份源码的两种压缩，选哪个都行，只是 `tar` 解压参数不同（下文用 `.bz2`）。校验值要和**实际下载的那个文件**对上，别拿 `.gz.sha256` 去验 `.bz2`。

# 下载

```bash
# 官方 FTP
wget https://ftp.postgresql.org/pub/source/v18.7/postgresql-18.7.tar.bz2

# 顺手把校验文件一起拉下来
wget https://ftp.postgresql.org/pub/source/v18.7/postgresql-18.7.tar.bz2.sha256
```

国内觉得官方源慢，可换镜像站，路径与官方一致，把域名替换即可（如 `https://mirrors.tuna.tsinghua.edu.cn/postgresql/source/v18.7/`）。镜像只解决**速度**，不改变**校验要求**——下完仍要和官方公布的哈希比对。

想核对官方哈希的权威出处，看该版本的发布说明页（如 `https://www.postgresql.org/support/versioning/` 对应的 release notes），上面列有本次发布的 SHA256 校验值。

# 校验完整性

## SHA256（日常够用）

```bash
# 方式一：用随包下载的 .sha256 直接验
sha256sum -c postgresql-18.7.tar.bz2.sha256
# postgresql-18.7.tar.bz2: OK

# 方式二：手动算出哈希，与发布页/官方 FTP 公布的值逐字符比对
sha256sum postgresql-18.7.tar.bz2
```

`sha256sum -c` 输出 `OK` 即说明文件与哈希自洽。

> [!warning]
> 如果 `.tar.bz2` 和它的 `.sha256` 是**从同一个 HTTP(S) 端点一起下载**的，那么这份校验只防得住「传输损坏」，防不住「源头被整体替换」（攻击者可以连哈希一起改）。真正的信任锚点是官方发布页公布的哈希，或下面的签名 Git tag。

## GPG 签名（生产环境推荐）

源码包目录里**没有**逐包的 `.asc` 签名文件，官方的强信任链挂在 **Git 仓库的签名 tag** 上。流程：

```bash
# 1. 导入 PostgreSQL Global Development Group 的签名公钥
#    （密钥清单见 https://www.postgresql.org/media/keys/）
gpg --keyserver keyserver.ubuntu.com --recv-keys <PGDG 签名密钥 ID>

# 2. 克隆仓库并校验目标 tag 的签名
git clone https://github.com/postgres/postgres.git
cd postgres
git verify-tag REL_18_7        # 输出应包含 "Good signature" 且指向已信任的 PGDG 密钥

# 3. 检出已验证的 tag 作为源码
git checkout REL_18_7
```

`git verify-tag` 报 `Good signature` 且签名密钥是你导入并信任的 PGDG 密钥，才说明这份源码确实由官方发布。相比 FTP 包，这条路能给出**可验证的来源**，适合对供应链有要求的场景。

# 解压

校验通过后解出源码，交给 03 篇的编译流程：

```bash
tar xjf postgresql-18.7.tar.bz2      # .bz2 用 -j；若是 .gz 用 tar xzf
cd postgresql-18.7
```

到这里 `postgresql-18.7/` 源码树就位，接下来的 `./configure --prefix=...` 与 `make install` 见 [03.Ubuntu系统安装PostgreSQL](./03.Ubuntu系统安装PostgreSQL.md)。

# 避坑

- **只验速度不验来源**：从镜像下完不比对官方哈希，等于把信任全押在镜像运营方。镜像提速、官方哈希兜底，两者都要。
- **`.sha256` 与包同源下载**：同端点取回的哈希只防损坏不防篡改，生产环境以发布页哈希或签名 Git tag 为准。
- **拿错文件的校验值**：`.tar.gz.sha256` 校验不了 `.tar.bz2`；跨压缩格式、跨版本混用哈希必然失败。
- **误下 beta/rc**：FTP 目录里 `v19beta1`、`v19rc2` 这类是预发布版，别当稳定版拉进生产；只认 `18.7` 这样的正式小版本。
- **目录名与文件名混淆**：目录带 `v` 前缀（`v18.7`）、文件名不带（`postgresql-18.7.tar.bz2`），手敲 URL 时最容易在这两处出错。
- **GPG 密钥未信任就下结论**：`git verify-tag` 出现 `Good signature` 但带 `using untrusted key`，仍需先确认该密钥确属 PGDG（比对官网指纹），否则「好签名」也可能签在伪造密钥上。

# 总结

获取 PostgreSQL 源码包就两步：**从官方 FTP 或镜像取 `postgresql-<版本>.tar.bz2`**，再**用 SHA256 比对官方值确认没坏、用签名 Git tag 确认来源可信**。日常开发 SHA256 足够，生产环境补一道 GPG。包验完解压，编译安装的全部细节在 [03.Ubuntu系统安装PostgreSQL](./03.Ubuntu系统安装PostgreSQL.md)。
