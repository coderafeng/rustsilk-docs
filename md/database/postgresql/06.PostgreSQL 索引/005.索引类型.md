# 概述

PostgreSQL 提供了多种索引类型：**B-tree、Hash、GiST、SP-GiST、GIN、BRIN**，以及扩展提供的 **bloom** 等。每种类型使用不同的算法，**各自擅长不同类型的可索引条件**。

默认情况下，`CREATE INDEX` 创建的是 **B-tree** 索引——它覆盖最常见的场景。其他类型需要显式写 `USING 索引类型` 关键字：

```sql
CREATE INDEX idx_payment_pamt ON payment USING HASH (amount);
```

先记住一句选型口诀：

> **等值和范围找 B-tree，纯等值可试 Hash，多维/近似/排序找 GiST，非平衡树找 SP-GiST，"一个值里有多个成分"找 GIN，超大有序表找 BRIN。**

# B-tree（B 树）

**最通用、默认**的索引类型。能处理任何**可排序数据**上的**等值查询和范围查询**。只要索引列参与下列任一操作符的比较，查询规划器就会考虑使用 B-tree 索引：

```text
<   <=   =   >=   >
```

等价于这些操作符组合的构造——如 `BETWEEN`、`IN`——同样可以走 B-tree；索引列上的 `IS NULL` / `IS NOT NULL` 也能用 B-tree 检索。

**模式匹配**：当模式是**常量且锚定字符串开头**时，`LIKE` 与正则 `~` 也能走 B-tree，例如 `col LIKE 'foo%'` 或 `col ~ '^foo'`；但 `col LIKE '%bar'` 不行。如果数据库不是 C locale，还需要专门的**操作符类**（如 `text_pattern_ops`，见 **[操作符类和操作符族](./050.操作符类和操作符族.md)**）。`ILIKE` / `~*` 只有当模式以不受大小写影响的字符（非字母）开头时才可用。

B-tree 还能**按有序方式返回数据**（避免额外排序），详见 **[索引和 ORDER BY](./020.索引和%20ORDER%20BY.md)**。

> **PostgreSQL 18 改进**：B-tree 支持 **skip scan（跳跃扫描）**，多列 B-tree 索引在"缺少前导列等值约束"的场景下也有机会被使用，详见 **[多列索引](./015.多列索引.md)**。

# Hash（哈希）

哈希索引存储索引列值派生出的 **32 位哈希码**，因此**只能处理简单等值比较**：

```text
=
```

理论上纯等值场景下哈希索引比 B-tree 略小略快，但实践中差距不大，且不支持范围、排序、多列前缀匹配，**一般没有特别理由不必使用**（PostgreSQL 10 之后才写 WAL、才崩溃安全，老库升级时注意）。

```sql
CREATE INDEX idx_payment_amount_hash ON payment USING HASH (amount);
```

# GiST

**GiST**（Generalized Search Tree，通用搜索树）**不是一种具体的索引**，而是一个**基础设施**——很多不同的索引策略都可以在它之上实现。因此 GiST 索引能配合哪些操作符，**取决于所用的操作符类**。

标准发行版内置的 GiST 操作符类覆盖多种**二维几何数据类型**，支持如下操作符：

```text
<<   &<   &>   >>   <<|   &<|   |&>   |>>   @>   <@   ~=   &&
```

GiST 的另一大能力是优化**最近邻搜索**（排序操作符）：

```sql
-- 找离目标点最近的 10 个位置
SELECT * FROM places ORDER BY location <-> point '(101,456)' LIMIT 10;
```

日常后端开发中最常接触 GiST 的场合：**PostGIS 空间索引**、**JSONB 的 jsonb_ops**、**范围类型**、**ltree**、以及全文检索的 `tsvector`（GIN 也可）。GiST 是**lossy（有损）且非精确计数**的，命中后常需回表 recheck，但**更新快**，适合写多读多的场景。

# SP-GiST

**SP-GiST**（Space-Partitioned GiST）与 GiST 类似，也是一套支持多种搜索的基础设施。它的特色是允许实现**非平衡**的磁盘数据结构，如**四叉树（quadtree）、k-d 树、基数树（radix/trie）**。

标准发行版为二维点提供了 SP-GiST 操作符类，支持：

```text
<<   >>   ~=   <@   <<|   |>>
```

和 GiST 一样支持最近邻搜索。适用直觉：**数据分布高度不均匀**时（如 IP 前缀、文本前缀、偏态坐标点），SP-GiST 的非平衡划分比 B-tree/GiST 的均衡划分更省空间、更快。标准发行版内置的操作符类包括：二维点的 `quad_point_ops`（四叉树，默认）与 `kd_point_ops`（k-d 树）、文本前缀的 `text_ops`、网络地址的 `inet_ops`、范围的 `range_ops` 等；contrib 中还有 pg_trgm 的 `gist_trgm_ops` 等可选类。

```sql
-- 二维点用 k-d 树策略建索引（不写类名时默认取四叉树类 quad_point_ops）
CREATE INDEX idx_place_kd ON place USING SPGIST (location kd_point_ops);
```

# GIN

**GIN**（Generalized Inverted Index，通用倒排索引）适合**一个数据值包含多个成分**的场景，例如**数组、JSONB、全文检索 tsvector**。倒排索引为**每个成分值**单独建立条目，因此能高效回答"哪些行包含某个成分"。

和 GiST 一样，GIN 能配合的操作符取决于操作符类。标准发行版为**数组**提供的 GIN 操作符类支持：

```text
<@   @>   =   &&
```

Sakila 的 `film.special_features` 就是数组列：

```sql
-- 找出包含 "Trailers" 特性的电影
SELECT title FROM film WHERE special_features @> ARRAY['Trailers'];

CREATE INDEX idx_film_features ON film USING GIN (special_features);
```

GIN 的特点要与 GiST 对照记：

|               | GIN                              | GiST                       |
|---------------|----------------------------------|----------------------------|
| 查找速度      | **更快**（精确倒排）             | 相对慢（有损，需 recheck） |
| 更新/插入开销 | **大得多**（要维护每个键的倒排） | 小                         |
| 排序输出      | 不支持                           | 支持最近邻排序             |

> 若 GIN 写入跟不上，可调整 `fastupdate` 参数用**待处理列表**批量化更新（参见内置函数章节的 GIN 相关配置）。

# BRIN

**BRIN**（Block Range INdex，块范围索引）存储的是表中**连续物理块范围**内值的**摘要**（对有线性排序规则的类型，摘要即每段的**最小值和最大值**）。因此它只适用于**取值与物理存储顺序高度相关**的列——最典型的就是**按时间追加的日志/流水表**。

BRIN 支持的操作符：

```text
<   <=   =   >=   >
```

优势是**极致的小体积**：对 10 TB 的按天追加表，在时间列上建 BRIN 可能只有几十 MB，却能把月度查询裁剪到少量块范围上。默认每个范围 128 页（约 1 MB），可用 `pages_per_range` 存储参数调细：

```sql
-- 假设 payment.payment_date 大致随时间顺序入库
CREATE INDEX idx_payment_pdate_brin ON payment
    USING BRIN (payment_date) WITH (pages_per_range = 32);
```

> 代价：如果表的物理顺序与列值**无关**（大量随机更新/乱序写入），BRIN 的 min/max 摘要覆盖全值域，**几乎没有过滤能力**。可用 `autosummarize = on` 让后续新块也被自动摘要。

# 索引类型速查

| 类型        | 擅长条件                     | 典型场景                                  | 写开销 |
|-------------|------------------------------|-------------------------------------------|--------|
| **B-tree**  | 等值、范围、排序、前缀 LIKE  | 绝大多数普通列索引（默认）                | 中     |
| **Hash**    | 仅等值                       | 纯等值且想省一点空间                      | 中     |
| **GiST**    | 多维、近似、包含、最近邻排序 | 几何/PostGIS、范围、JSONB(含存在性)、全文 | 低~中  |
| **SP-GiST** | 非平衡空间划分、前缀         | IP 前缀、偏态文本/几何                    | 低~中  |
| **GIN**     | 多值成分的包含判断           | 数组、JSONB、全文检索                     | 高     |
| **BRIN**    | 范围（依赖物理相关性）       | 时序大表、只追加日志                      | 极低   |

# 总结

B-tree 是默认答案，Hash 只答等值，GiST/SP-GiST/GIN/BRIN 分别解决"多维与排序检索""非平衡数据""多值成分""超大有序表"四类问题。选对类型比调参数重要得多；而无论选哪种类型，具体的创建、并发重建与日常管理操作，请看 **[索引的基本操作](./010.索引的基本操作.md)**。
