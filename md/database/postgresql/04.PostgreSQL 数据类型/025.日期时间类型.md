# 概述

PostgreSQL 支持完整的一组 SQL 日期和时间类型。这些数据类型上可用的操作函数见 **[日期时间函数](../07.PostgreSQL%20内置函数/010.日期时间函数.md#概述)**。

PostgreSQL 日期时间体系可以分成 5 类：

| 类型 | 常用写法 | 含义 | 推荐场景 |
| --- | --- | --- | --- |
| date | date | 只有日期 | 生日、账单日、业务日期 |
| time | time / time without time zone | 一天中的时间 | 营业时间、每日时刻 |
| timestamp | timestamp / timestamp without time zone | 日期 + 时间，无时区 | 本地墙上时间 |
| timestamp with time zone | timestamptz | 日期 + 时间，绝对时刻 | 跨时区事件、创建时间、日志 |
| interval | interval | 时间间隔、时长 | 有效期、差值、周期 |

核心结论：

- **`timestamp` 默认等价于 `timestamp without time zone`。**
- **`timestamptz`** 是 PostgreSQL 对 `timestamp with time zone` 的简写扩展。
- 记录“某个**绝对时刻**”用 **`timestamptz`**。
- 记录“**本地墙上时间**”用 **`timestamp`**。
- **不要优先使用 `time with time zone`**，它通常没有实际意义。

# 类型速查表

| 名字 | 存储   | 描述 | 最小值 | 最大值 | 解析度 |
| --- |--------| --- | --- | --- | --- |
| timestamp [ (p) ] [ without time zone ] | 8字节  | 日期 + 时间，无时区 | 4713 BC | 294276 AD | 1微秒 |
| timestamp [ (p) ] with time zone | 8字节  | 日期 + 时间，有时区 | 4713 BC | 294276 AD | 1微秒 |
| date | 4字节  | 日期 | 4713 BC | 5874897 AD | 1日 |
| time [ (p) ] [ without time zone ] | 8字节  | 一天中的时间 | 00:00:00 | 24:00:00 | 1微秒 |
| time [ (p) ] with time zone | 12字节 | 一天中的时间，带时区 | 00:00:00+1559 | 24:00:00-1559 | 1微秒 |
| interval [ fields ] [ (p) ] | 16字节 | 时间间隔 | -178000000年 | 178000000年 | 1微秒 |

精度 p：

- 用于 time、timestamp、interval。
- 表示秒字段保留多少位小数。
- 范围：0 ~ 6。
- 不指定时，按输入字面量精度处理，最多 6 位。
- 如果同时指定 fields 和 p，fields 必须包含 SECOND。

示例：

```sql
SELECT timestamp(3) '2024-01-01 12:00:00.123456';
-- 2024-01-01 12:00:00.123

SELECT interval(2) '1 day 02:03:04.567';
-- 1 day 02:03:04.57
```

# 类型选择建议

| 需求 | 推荐类型 |
| --- | --- |
| 只记录日期 | date |
| 只记录一天中的时间 | time |
| 记录本地时间，不关心时区 | timestamp |
| 记录事件发生的绝对时刻 | timestamptz |
| 记录两个时间的间隔 | interval |
| 不建议 | time with time zone |

为什么不推荐 time with time zone？

- 时区偏移可能随夏令时变化。
- 只给一个“时间”，不给“日期”，无法确定某天到底用标准时间还是夏令时。
- 大多数场景下，date + time + timestamp + timestamptz 已经足够。

# 历法背景：了解即可

PostgreSQL 对所有日期都使用外推格里高利历，即使该历法在历史上尚未实际使用。

也就是说：

- PostgreSQL 不会根据国家、地区、历史时期切换儒略历/格里高利历。
- 1582 年、1752 年等历法改革不会影响 PostgreSQL 的日期计算。
- 中国农历、历史地方历法不是 PostgreSQL 日期类型的职责。

格里高利历闰年规则：

- 能被 4 整除：闰年。
- 能被 100 整除：不是闰年。
- 能被 400 整除：仍是闰年。

例如：

- 1700、1800、1900、2100、2200 不是闰年。
- 1600、2000、2400 是闰年。

# 日期/时间输入

## 概述

输入语法：

```sql
type [ (p) ] 'value'
```

示例：

```sql
date '2024-01-01'
timestamp(3) '2024-01-01 12:00:00.123'
timestamptz '2024-01-01 12:00:00+08'
interval '1 day 02:03:04'
```

要点：

- 日期/时间字面量必须用单引号。
- PostgreSQL 解析器非常灵活，支持 ISO 8601、SQL 兼容格式、传统 POSTGRES 格式。
- 有歧义时，DateStyle 决定解释方式：
  - MDY：月-日-年
  - DMY：日-月-年
  - YMD：年-月-日
- 推荐始终使用 ISO 格式：
  - 日期：YYYY-MM-DD
  - 时间：HH:MM:SS
  - 时间戳：YYYY-MM-DD HH:MM:SS

查看当前设置：

```sql
SHOW DateStyle;
```

设置示例：

```sql
SET DateStyle = 'ISO, MDY';
SET DateStyle = 'ISO, YMD';
```

## date（日期）

推荐格式：

```sql
DATE '1999-01-08'
DATE '19990108'
```

常见输入示例：

| 示例 | 描述 |
| --- | --- |
| 1999-01-08 | ISO 8601； 任何模式下的1月8日 （推荐格式） |
| January 8, 1999 | 在任何datestyle输入模式下都无歧义 |
| 1/8/1999 | MDY模式中的1月8日；DMY模式中的8月1日 |
| 1/18/1999 | MDY模式中的1月18日；在其他模式中被拒绝 |
| 01/02/03 | MDY模式中的2003年1月2日； DMY模式中的2003年2月1日； YMD模式中的2001年2月3日 |
| 1999-Jan-08 | 任何模式下的1月8日 |
| Jan-08-1999 | 任何模式下的1月8日 |
| 08-Jan-1999 | 任何模式下的1月8日 |
| 99-Jan-08 | YMD模式中的1月8日，否则报错 |
| 08-Jan-99 | 1月8日，但在YMD模式中会报错 |
| Jan-08-99 | 1月8日，但在YMD模式中会报错 |
| 19990108 | ISO 8601； 任何模式中的1999年1月8日 |
| 990108 | ISO 8601； 任何模式中的1999年1月8日 |
| 1999.008 | 年和一年中的第几天 |
| J2451187 | 儒略日 |
| January 8, 99 BC | 公元前99年 |

实践建议：

- 写入数据库时优先用 YYYY-MM-DD。
- 不要让应用依赖 DateStyle 解释 1/2/2024 这类格式。

## time（时间）

类型：

```sql
time [ (p) ] without time zone
time [ (p) ] with time zone
```

单独写 time 等价于 time without time zone。

规则：

- time without time zone 输入中如果带了时区，会被静默忽略。
- 如果给 time without time zone 指定日期，通常也会被忽略。
- 例外：使用涉及夏令时规则的时区名时，例如 America/New_York，必须提供日期来确定标准时间还是夏令时。
- time with time zone 会记录时区偏移，并按存储时原样输出，不会根据当前活动时区调整。

时间输入示例：

| 示例 | 说明                                 |
| --- |--------------------------------------|
| 04:05:06.789 | ISO 8601                             |
| 04:05:06 | ISO 8601                             |
| 04:05 | ISO 8601                             |
| 040506 | ISO 8601                             |
| 040506 | ISO 8601                             |
| 04:05 AM | 等价于 04:05            |
| 04:05 PM | 等价于 16:05，小时必须 <= 12  |
| 04:05:06.789-8 | ISO 8601，时区以 UTC 偏移表示        |
| 04:05:06-08:00 | ISO 8601，时区以 UTC 偏移表示        |
| 04:05-08:00 | ISO 8601，时区以 UTC 偏移表示        |
| 040506-08 | ISO 8601，时区以 UTC 偏移表示        |
| 040506+0730 | ISO 8601，时区的 UTC 偏移不是整小时  |
| 040506+07:30:00 | UTC 偏移精确到秒（ISO 8601中不允许） |
| 04:05:06 PST | 时区缩写                       |
| 2003-04-12 04:05:06 America/New_York | 完整时区名                       |

时区输入示例：

| 示例 | 说明                               |
| --- |------------------------------------|
| PST | 缩写（太平洋标准时间）             |
| America/New_York | 完整时区名                         |
| PST8PDT | POSIX风格的时区声明                |
| -8:00:00 | PST的UTC偏移                       |
| -8:00 | PST的UTC偏移量（ISO 8601扩展格式） |
| -800 | PST的UTC偏移量（ISO 8601基本格式） |
| -8 | PST的UTC偏移量（ISO 8601基本格式） |
| zulu | UTC的军方缩写                      |
| z | zulu的缩写形式（也在ISO 8601中）   |

## timestamp（时间戳）

timestamp 的有效输入通常是：

```text
日期 + 时间 + 可选时区 + 可选 AD/BC
```

示例：

```sql
TIMESTAMP '1999-01-08 04:05:06'
TIMESTAMP '1999-01-08 04:05:06 -8:00'
TIMESTAMP 'January 8 04:05:06 1999 PST'
```

SQL 标准认为：

```sql
TIMESTAMP '2004-10-19 10:23:54'
```

是 timestamp without time zone。

而：

```sql
TIMESTAMP '2004-10-19 10:23:54+02'
```

是 timestamp with time zone。

但 PostgreSQL 在确定字符串字面量类型之前不会检查内容，因此会把两者都当作 timestamp without time zone。

所以：

```sql
-- 会被当作 timestamp without time zone，+02 被忽略
SELECT TIMESTAMP '2004-10-19 10:23:54+02';

-- 显式指定为 timestamptz，才会按 +02 转 UTC
SELECT TIMESTAMP WITH TIME ZONE '2004-10-19 10:23:54+02';
```

timestamp without time zone：

- 任何时区指示都会被静默忽略。
- 结果直接取自输入字符串中的日期/时间字段。
- 不会因为时区而调整。

timestamp with time zone：

- 如果输入包含显式时区，按该时区偏移转换为 UTC。
- 如果输入没有时区，假定它位于系统 TimeZone 参数指定的时区。
- 内部统一以 UTC 存储。
- 原始声明或假定的时区不会被保留。

输出时：

- timestamptz 总会从 UTC 转换到当前 TimeZone，显示为本地时间。
- 想查看其他时区，可以改 TimeZone 或使用 AT TIME ZONE。

示例：

```sql
SET TimeZone = 'Asia/Shanghai';

SELECT TIMESTAMPTZ '2024-01-01 12:00:00+08';
-- 显示为上海时间

SELECT TIMESTAMPTZ '2024-01-01 12:00:00+08' AT TIME ZONE 'America/New_York';
-- 返回纽约当地时间，类型为 timestamp without time zone
```

在 timestamp 和 timestamptz 之间转换时，通常假定 timestamp 是本地时间。要指定不同时区，用 AT TIME ZONE。

## 特殊值

特殊日期/时间输入如下：

| 输入串 | 合法类型 | 说明                                    |
| --- | --- |-----------------------------------------|
| epoch | date, timestamp | 1970-01-01 00:00:00+00（Unix系统时间0） |
| infinity | date, timestamp, interval | 晚于所有其他时间戳                      |
| -infinity | date, timestamp, interval | 早于所有其他时间戳                      |
| now | date, time, timestamp | 当前事务的开始时间                      |
| today | date, timestamp | 今天午夜（00:00）                       |
| tomorrow | date, timestamp | 明天午夜（00:00）                       |
| yesterday | date, timestamp | 昨天午夜（00:00）                       |
| allballs | time | 00:00:00.00 UTC                         |

SQL 函数：

- CURRENT_DATE
- CURRENT_TIME
- CURRENT_TIMESTAMP
- LOCALTIME
- LOCALTIMESTAMP

注意：

- 这些是 SQL 函数，不会在日期/时间输入字符串中被识别。
- 'now'、'today'、'tomorrow'、'yesterday' 在交互式 SQL 中方便，但在预备语句、视图、函数定义中可能被提前转换成固定时间。
- 推荐在视图、函数、默认值中使用 SQL 函数，例如：
  ```sql
  CURRENT_DATE + 1
  ```
  而不是：
  
  ```sql
  'tomorrow'::date
  ```

# 日期/时间输出

DateStyle 支持四种输出风格：

| 风格     | 说明                     | 示例 |
|----------|--------------------------| --- |
| ISO      | ISO 8601，SQL 标准，默认 | 1997-12-17 07:37:16-08 |
| SQL      | 传统风格                 | 12/17/1997 07:37:16.00 PST |
| Postgres | 原始风格                 | Wed Dec 17 07:37:16 1997 PST |
| German   | 地区风格                 | 17.12.1997 07:37:16.00 PST |

注意：

- ISO 8601 规定日期和时间之间用大写 T 分隔。
- PostgreSQL 输入接受 T，输出默认用空格。
- SQL 和 POSTGRES 风格受 DMY / MDY 影响。
- ISO 风格中，时区显示为相对 UTC 的有符号数字偏移，东为正。
- 其他风格中，可能显示时区缩写。
- 灵活格式化用 to_char()。

示例：

```sql
SET DateStyle = 'ISO, YMD';
SELECT now();

SET DateStyle = 'SQL, DMY';
SELECT now();
```

# 时区

## 内部存储原则

- 所有带时区的日期和时间都以 UTC 存储。
- 显示给客户端前，转换为 TimeZone 参数指定的本地时间。
- 只包含日期或时间的类型，通常假定使用本地时区。

## 三种时区指定方式

PostgreSQL 允许使用三种不同形式来指定时区：

| 方式 | 示例 | 特点 |
| --- | --- | --- |
| 完整时区名 | America/New_York | 包含夏令时规则，推荐 |
| 时区缩写 | PST | 只表示固定 UTC 偏移 |
| POSIX 风格 | PST8PDT | 兼容用，必要时使用 |

区别示例：

- 2014-06-04 12:00 America/New_York：纽约当地时间中午，当天是 EDT，UTC-4。
- 2014-06-04 12:00 EDT：东部夏令时中午，UTC-4。
- 2014-06-04 12:00 EST：东部标准时中午，UTC-5，即使当天名义上实行夏令时。

重要：

- 完整时区名可能对应两个 UTC 偏移，因为有夏令时。
- 缩写只对应一个固定偏移。
- 时区名称和缩写不区分大小写。
- TimeZone 和 log_timezone 不能设置为时区缩写，但缩写可用于日期/时间输入和 AT TIME ZONE。

POSIX 风格符号与 ISO 8601 相反：

- ISO 8601：2014-06-04 12:00+04
- POSIX：UTC-4

设置时区：

```sql
SET TIME ZONE 'Asia/Shanghai';
SET TIMEZONE TO 'UTC';
```

客户端环境变量：

```text
PGTZ
```

# interval（间隔输入）

## 详细语法

interval值可以使用下列详细语法书写：

```sql
[@] quantity unit [quantity unit...] [direction]
```

说明：

- quantity：数字，可带符号。
- unit：microsecond、millisecond、second、minute、hour、day、week、month、year、decade、century、millennium 及其缩写或复数。
- direction：ago 或空。
- @ 是可选噪声。
- ago 会把所有字段取反。
- 如果 IntervalStyle = postgres_verbose，输出也使用这种语法。

简写：

```sql
'1 12:59:10'
-- 等价于 '1 day 12 hours 59 min 10 sec'

'200-10'
-- 等价于 '200 years 10 months'
```

## ISO 8601 格式

带标志符格式：

```sql
P quantity unit [ quantity unit ...] [ T [ quantity unit ...]]
```

示例：

```sql
P1Y2M3DT4H5M6S
```

替代格式：

```sql
P [ years-months-days ] [ T hours:minutes:seconds ]
```

示例：

```sql
P0001-02-03T04:05:06
```

ISO 8601 单位缩写如下：

| 缩写 | 含义 |
| --- | --- |
| Y | 年 |
| M | 月（在日期部分中） |
| W | 周 |
| D | 日 |
| H | 小时 |
| M | 分钟（在时间部分中） |
| S | 秒 |

## fields 限制

interval 可以限制存储字段集合：

```text
YEAR
MONTH
DAY
HOUR
MINUTE
SECOND
YEAR TO MONTH
DAY TO HOUR
DAY TO MINUTE
DAY TO SECOND
HOUR TO MINUTE
HOUR TO SECOND
MINUTE TO SECOND
```

示例：

```sql
INTERVAL '1' YEAR
-- 1 年

INTERVAL '1'
-- 1 秒

INTERVAL '1 day 2:03:04' HOUR TO MINUTE
-- 秒字段被丢弃
```

规则：

- 未标记数量的解释取决于 fields。
- 位于 fields 允许的最小字段右侧的字段值会被静默丢弃。
- 同时指定 fields 和 p 时，fields 必须包含 SECOND。

## 符号规则

SQL 标准：

- 一个 interval 值的所有字段必须同号。
- 前导负号作用于所有字段。

PostgreSQL 传统解释：

- 允许各字段不同符号。
- 文本表示中每个字段可带独立符号。

建议：

- 只要有任何字段为负，就为每个字段显式写出符号。
- 如果 IntervalStyle = sql_standard，前导符号可能被视为作用于所有字段。

## 内部存储

interval 内部存储三个整数字段：

- 月
- 日
- 微秒

为什么分开存？

- 一个月天数会变化。
- 涉及夏令时时，一天可能是 23 或 25 小时。

规范化示例：

```sql
SELECT '2 years 15 months 100 weeks 99 hours 123456789 milliseconds'::interval;
```

结果：

```text
3 years 3 mons 700 days 133:17:36.789
```

小数处理：

```sql
'1.5 years'
-- 1 year 6 mons

'1.75 months'
-- 1 mon 22 days 12:00:00
```

只有秒在输出时可能显示为小数。

有效 interval 输入示例：

| 示例                                               | 说明                  |
|----------------------------------------------------|-----------------------|
| 1-2                                                | 1 年 2 个月           |
| 3 4:05:06                                          | 3 日 4 小时 5 分 6 秒 |
| 1 year 2 months 3 days 4 hours 5 minutes 6 seconds | 传统格式              |
| P1Y2M3DT4H5M6S                                     | ISO 8601 带标志符格式 |
| P0001-02-03T04:05:06                               | ISO 8601 替代格式     |

# interval（间隔输出）

PostgreSQL 输出时：

- 月字段除以 12，转换为年和月。
- 日字段按原样显示。
- 微秒字段转换为小时、分钟、秒和小数秒。

因此：

- 月显示值：0 ~ 11
- 分钟显示值：0 ~ 59
- 秒显示值：0 ~ 59
- 年、日、小时可能很大

可以用：

- **[justify_days()](../07.PostgreSQL%20内置函数/010.日期时间函数.md#justify_days)**
- **[justify_hours()](../07.PostgreSQL%20内置函数/010.日期时间函数.md#justify_hours)**

把较大的日数或小时数进位到更高字段。

IntervalStyle 四种风格：

| 风格 | 年-月间隔 | 日-时间间隔 | 混合间隔 |
| --- | --- | --- | --- |
| sql_standard | 1-2 | 3 4:05:06 | -1-2 +3 -4:05:06 |
| postgres | 1 year 2 mons | 3 days 04:05:06 | -1 year -2 mons +3 days -04:05:06 |
| postgres_verbose | @ 1 year 2 mons | @ 3 days 4 hours 5 mins 6 secs | @ 1 year 2 mons -3 days 4 hours 5 mins 6 secs ago |
| iso_8601 | P1Y2M | P3DT4H5M6S | P-1Y-2M3D​T-4H-5M-6S |

默认是 postgres。

设置：

```sql
SET IntervalStyle = 'iso_8601';
```

# 实战速查 SQL

```sql
-- 查看当前日期、时间、时间戳
SELECT CURRENT_DATE;
SELECT CURRENT_TIME;
SELECT CURRENT_TIMESTAMP;
SELECT LOCALTIME;
SELECT LOCALTIMESTAMP;

-- 设置时区
SET TimeZone = 'Asia/Shanghai';

-- 绝对时刻推荐用 timestamptz
SELECT TIMESTAMPTZ '2024-01-01 12:00:00+08';

-- 墙上时间用 timestamp
SELECT TIMESTAMP '2024-01-01 12:00:00';

-- 把墙上时间解释为上海时间
SELECT TIMESTAMP '2024-01-01 12:00:00' AT TIME ZONE 'Asia/Shanghai';

-- 把 timestamptz 转成纽约本地时间
SELECT TIMESTAMPTZ '2024-01-01 12:00:00+08' AT TIME ZONE 'America/New_York';

-- interval 规范化
SELECT '2 years 15 months 100 weeks 99 hours 123456789 milliseconds'::interval;

-- 格式化输出
SELECT to_char(now(), 'YYYY-MM-DD HH24:MI:SS');
```

# 常见踩坑清单

1. TIMESTAMP '...' 默认是 timestamp without time zone，即使字符串里写了 +02，时区也可能被忽略。
2. 要确保是带时区时间戳，显式写 TIMESTAMP WITH TIME ZONE 或 TIMESTAMPTZ。
3. timestamptz 内部只存 UTC，不保留原始时区。
4. timestamptz 输出时按当前 TimeZone 显示。
5. time with time zone 通常不实用，优先用 timestamptz。
6. DateStyle 会影响歧义日期输入和输出，生产环境推荐 ISO。
7. 'now'、'today'、'tomorrow' 在视图、函数、预备语句中可能固化，推荐 SQL 函数。
8. 时区缩写只表示固定偏移，完整时区名才包含夏令时规则。
9. POSIX 时区符号与 ISO 8601 相反。
10. interval 各字段符号在 PostgreSQL 传统解释中可能独立，建议显式写符号。
11. interval 内部存月、日、微秒，月和日不能简单等同于固定天数。
12. 精度 p 只作用于秒，范围 0 ~ 6。

# 总结

- 记日期：date 
- 记本地墙上时间：timestamp 
- 记绝对时刻：timestamptz 
- 记时长：interval 
- 格式化：to_char()
- 时区：TimeZone + AT TIME ZONE 
- 最推荐输入格式：YYYY-MM-DD HH:MM:SS[+时区]
