# 概述

**money** 类型以**固定的小数精度**存储货币金额。小数精度由数据库的 **lc_monetary** 设置决定。下表中显示的范围假定有**两位小数**。

> [!caution]
> **生产环境不推荐用 `money`。** 它的本质是 `int64`，输出格式强依赖区域设置 `lc_monetary`，跨库迁移/不同客户端显示容易出问题。**存金额首选 [`numeric(p, s)`](005.数字类型.md#任意精度数值)**，把 `money` 当作了解即可的历史类型。本章仍完整介绍其行为，便于阅读遗留系统。

- **`money` 存储的是定标整数**（8 字节），默认两位小数，不是真正的小数类型。
- **显示受 `lc_monetary` 控制**：同一值在不同区域设置下输出 `$1,000.00`、`1.000,00 €` 等不同形式。
- **可与 `numeric`/`int`/`bigint` 互转**；与浮点转换需先过 `numeric`。
- **除法会截断**：`money / 整数` 向零取整，需要舍入得先转 `numeric`。

| 名字 | 存储尺寸 | 描述 | 范围 |
| --- | --- | --- | --- |
| money | 8 字节 | 货币额 | -92233720368547758.08 到 +92233720368547758.07 |

# 输入与输出

- 输入支持多种格式
  - 整数字面量
  - 浮点数字面量
  - 典型货币格式，例如 '$1,000.00'
- **输出**通常采用货币格式，但会受到区域设置影响

# 区域设置注意事项

由于 **money** 类型的输出依赖区域设置，因此在 **lc_monetary** 设置不同的数据库之间装入 **money** 数据时，可能无法正常工作。

为避免这类问题，在将转储恢复到新数据库之前，应确保新数据库的 **lc_monetary** 设置与原数据库**相同或等效**。

# 类型转换

- **numeric**、**int** 和 **bigint** 的值可以转换为 **money**
- **real** 和 **double precision** 的转换可以通过先转换为 **numeric** 来实现，例如：
  ```sql
  SELECT '12.34'::float8::numeric::money;
  ```
- 一个 **money** 值可以不损失精度地转换为 **numeric**。
- 转换到其他类型可能会丢失精度，并且必须分两个阶段完成：
  ```sql
  SELECT '52093.89'::money::numeric::float8;
  ```

> [!note]
> 浮点数不应该被用来处理货币，因为浮点数可能会有舍入误差。

# 运算行为

- 一个 **money** 值除以一个整数值时，会朝零方向截去小数部分。
- 要得到舍入后的结果，可以：
  - 除以一个浮点值；或
  - 在除法前先把 **money** 转换为 **numeric**，再在除法后转换回 **money**。
    - 如果要避免精度丢失风险，后一种做法更好。
- 当一个 **money** 值被另一个 **money** 值除时，结果是 **double precision**（即一个纯数字，而不是金额），因为在除法中货币单位被约掉了。

# money 与 numeric 选型对比

| 维度 | `money` | `numeric(p, s)` |
|------|---------|-----------------|
| 底层实现 | 定标 `int64` | 变长精确数值 |
| 小数精度 | 由 `lc_monetary` 决定 | 列定义显式指定 |
| 跨库/跨地区稳定 | 差（依赖区域设置） | **好**（与区域无关） |
| 运算精确度 | 整数运算，除法会截断 | 完全精确 |
| 官方/社区推荐 | 不推荐 | **推荐存金额** |
| 典型场景 | 遗留系统 | 新建项目的金额字段 |

# 实战速查 SQL

```sql
-- 查看/切换货币区域设置
SHOW lc_monetary;
SET lc_monetary = 'en_US.UTF-8';

-- money 输出随区域设置变化
SELECT 1234.56::money;                       -- $1,234.56

-- 与 numeric 互转（money → numeric 不丢精度）
SELECT '52093.89'::money::numeric;            -- 52093.89

-- 浮点转 money 必须先过 numeric
SELECT '12.34'::float8::numeric::money;

-- 除法截断 vs 舍入
SELECT '10.00'::money / 3;                     -- $3.33（向零截断）
SELECT (('10.00'::money::numeric) / 3)::money; -- 可用 numeric 控制精度

-- money ÷ money 得到纯数字
SELECT '10.00'::money / '2.00'::money;         -- 5（double precision）
```

# 最佳实践

1. **新系统存金额一律用 `numeric(p, s)`**，明确精度（如 `numeric(12, 2)`），不要用 `money`。
2. **接手遗留库见到 `money`**：迁移时转成 `numeric` 存储，避免 `lc_monetary` 差异引发的显示/导入错乱。
3. **需要货币符号展示**：在应用层或查询里用 `to_char()` 格式化，而非依赖 `money` 的区域输出。
4. **别把浮点当货币**：无论 `money` 还是 `float`，涉及金额计算都应走 `numeric`。

# 常见坑

1. **跨区域迁移丢数据/报错**：`lc_monetary` 不一致时，转储恢复 `money` 可能失败，务必保证源/目标区域等效。
2. **除法静默截断**：`money / 整数` 直接丢弃小数部分，不报错，账目易对不平。
3. **`money ÷ money` 返回 `double`**：拿它再参与金额运算会引入浮点误差。
4. **输出带符号/千分位**：`money` 直接取字符串是带货币符号的文本，程序解析需先转 `numeric`。

# 总结

- `money` 是**受区域设置影响的定标整数类型**，除展示方便外并无优势。
- **存金额请首选 `numeric(p, s)`**；`money` 仅在阅读/迁移遗留系统时才需要掌握。
