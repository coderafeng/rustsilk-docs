# 概述

- **ENUM** 是一种由**静态有序值集合**构成的数据类型。
- 每个枚举类型都是**独立类型**，不同枚举之间不能直接比较。
- **枚举值的顺序 = 创建类型时列出的顺序**（非字母序）。
- 枚举支持标准比较运算符、`ORDER BY`、`MIN()`、`MAX()` 等。
- 枚举标签**大小写敏感，空白也有意义**。
- 可以**增加新值或重命名值**，但**不能删除值，也不能改变排序顺序**。
- 适合**状态、级别、类型**等稳定且有序的小集合。
- 如果集合**频繁变化**，优先考虑 `CHECK` 约束或查找表 + 外键。

> [!warning]
> 枚举**只能加值/改名，不能删值、不能重排**——一旦建错顺序或需废弃某个值，只能删除重建整个类型并处理依赖。选枚举前先确认值集稳定；否则用 `CHECK` 或查找表。

# 枚举类型速查

| 特性     | 说明                                               |
|----------|----------------------------------------------------|
| 创建语法 | CREATE TYPE 类型名 AS ENUM ('值1', '值2', ...)     |
| 存储     | 每个枚举值占 4 字节                                |
| 标签长度 | 受 NAMEDATALEN 限制，标准编译下最大 63 字节        |
| 排序     | 按创建时列出的顺序                                 |
| 比较     | 支持 =、<>、<、>、<=、>=                           |
| 聚合     | 支持 MIN()、MAX() 等                               |
| 类型安全 | 不同枚举类型不能直接比较                           |
| 大小写   | 敏感，'happy' 与 'HAPPY' 不同                      |
| 空白     | 敏感，标签中的空白有意义                           |
| 修改     | 可 ADD VALUE、RENAME VALUE；不能删除值、不能改顺序 |
| 系统目录 | pg_enum                                            |

# 声明枚举类型

语法：

```sql
CREATE TYPE mood AS ENUM ('sad', 'ok', 'happy');
```

创建后，可以像普通类型一样用于表、函数等：

```sql
CREATE TABLE person
(
    name         text,
    current_mood mood
);
```

插入和查询：

```sql
INSERT INTO person
VALUES ('Moe', 'happy');

SELECT *
FROM person
WHERE current_mood = 'happy';
```

结果：

```text
 name | current_mood
------+--------------
 Moe  | happy
(1 row)
```

# 排序与比较

枚举值的顺序就是创建时列出的顺序：

```sql
CREATE TYPE mood AS ENUM ('sad', 'ok', 'happy');
```

顺序为：

```text
sad < ok < happy
```

示例数据：

```sql
INSERT INTO person
VALUES ('Larry', 'sad');
INSERT INTO person
VALUES ('Curly', 'ok');
```

比较：

```sql
SELECT *
FROM person
WHERE current_mood > 'sad';
```

结果：

```text
 name  | current_mood
-------+--------------
 Moe   | happy
 Curly | ok
(2 rows)
```

排序：

```sql
SELECT *
FROM person
WHERE current_mood > 'sad'
ORDER BY current_mood;
```

结果：

```text
 name  | current_mood
-------+--------------
 Curly | ok
 Moe   | happy
(2 rows)
```

聚合：

```sql
SELECT name
FROM person
WHERE current_mood = (SELECT MIN(current_mood) FROM person);
```

结果：

```text
 name
-------
 Larry
(1 row)
```

要点：

- ORDER BY 按枚举定义顺序，而不是字母顺序。
- MIN () 返回定义顺序中最小的值。
- MAX () 返回定义顺序中最大的值。
- 比较运算符基于定义顺序。

# 类型安全性

每一种枚举数据类型都是独立的，并且不能和其他枚举类型相比较。

示例：

```sql
CREATE TYPE happiness AS ENUM ('happy', 'very happy', 'ecstatic');

CREATE TABLE holidays
(
    num_weeks integer,
    happiness happiness
);

INSERT INTO holidays(num_weeks, happiness)
VALUES (4, 'happy');
INSERT INTO holidays(num_weeks, happiness)
VALUES (6, 'very happy');
INSERT INTO holidays(num_weeks, happiness)
VALUES (8, 'ecstatic');
```

插入时报错：错误：'sad' 不是 happiness 的合法值

```sql
-- 错误：'sad' 不是 happiness 的合法值
INSERT INTO holidays(num_weeks, happiness)
VALUES (2, 'sad');
```

```text
ERROR:  invalid input value for enum happiness: "sad"
```

跨枚举比较报错：

```sql
SELECT person.name, holidays.num_weeks
FROM person,
     holidays
WHERE person.current_mood = holidays.happiness;
```

```text
ERROR:  operator does not exist: mood = happiness
```

如果确实需要比较，可以显式转换为文本：

```sql
SELECT person.name, holidays.num_weeks
FROM person,
     holidays
WHERE person.current_mood::text = holidays.happiness::text;
```

结果：

```text
 name | num_weeks
------+-----------
 Moe  |         4
(1 row)
```

注意：

- 转成 text 后比较的是字符串，不再是枚举顺序。
- 也可以编写自定义操作符，但通常不推荐。
- 更好的设计是避免跨枚举比较，或者统一类型。

# 实现细节

- 枚举标签大小写敏感：
    - 'happy' 与 'HAPPY' 是不同的值。
- 标签中的空白也有意义：
    - 'happy' 与 ' happy' 不同。
- 每个枚举值在磁盘上占 4 字节。
- 文本标签长度受 NAMEDATALEN 限制。
    - 标准编译下最大 63 字节。
- 枚举值到文本标签的映射保存在系统目录 pg_enum 中。
- 可以直接查询 pg_enum 查看枚举定义：
  ```sql
  SELECT * FROM pg_enum;
  ```
  或按类型查询：

  ```sql
  SELECT enumlabel
  FROM pg_enum
  WHERE enumtypid = 'mood'::regtype
  ORDER BY enumsortorder;
  ```

# 修改枚举类型

可以增加新值：

```sql
ALTER TYPE mood ADD VALUE 'ecstatic';
```

可以重命名值：

```sql
ALTER TYPE mood RENAME VALUE 'ok' TO 'fine';
```

不能删除现有值：

```sql
-- 不支持
ALTER TYPE mood DROP VALUE 'sad';
```

不能改变现有值的排序顺序：

```sql
-- 不支持直接调整顺序
```

如果需要删除值或改变顺序：

- 只能删除并重建枚举类型。
- 重建前需要处理依赖，例如列类型、默认值、索引、视图、函数等。

注意事项：

- ADD VALUE 在旧版本 PostgreSQL 中有事务限制，现代版本已支持在事务中执行，但仍有细节限制。
- 生产环境修改枚举前，先在测试环境验证依赖。

# ENUM vs CHECK vs 查找表

| 方案          | 优点                                   | 缺点                               | 适用场景                 |
|---------------|----------------------------------------|------------------------------------|--------------------------|
| ENUM          | 类型安全、存储紧凑、排序固定、语法简洁 | 修改受限、不能删值、跨枚举不能比较 | 稳定、有序、小集合       |
| CHECK         | 约束	灵活、易修改、可写复杂条件         | 类型安全较弱、排序需额外定义       | 值可能变化、需要复杂约束 |
| 查找表 + 外键 | 可动态增删、可带额外属性、易维护       | 需要 JOIN、存储稍大、排序需字段    | 值经常变化、需要元数据   |

选择建议：

- 状态、级别、优先级等很少变化且有序：用 ENUM。
- 值可能频繁增删，或需要显示名、描述、排序号：用查找表。
- 简单二值或少量固定值：boolean 或 CHECK 可能更合适。

# 最佳实践

1. 用于稳定集合
  - 例如：订单状态、用户角色、星期、优先级。
2. 保持顺序有意义
  - 如果顺序重要，ENUM 很合适。
  - 如果顺序不重要，考虑其他方案。
3. 避免频繁修改
  - ENUM 不适合经常增删值的场景。
4. 统一类型
  - 避免多个枚举表示同一概念，否则跨类型比较很麻烦。
5. 应用层同步
  - 应用代码中的枚举值应与数据库枚举保持一致。
  - 可以使用迁移工具管理。
6. 索引
  - 枚举列可以正常建索引。
  - 低选择性枚举列，普通 B-tree 索引可能效果有限。
  - 可考虑部分索引。
7. 查询时显式转换
  - 如果必须跨枚举比较，显式 ::text，并注意语义变化。
8. 文档化
  - 枚举值含义、顺序、变更历史应记录在文档或迁移脚本中。

# 常见坑

1. **枚举标签大小写敏感**，`'happy'` ≠ `'HAPPY'`。
2. **标签中的空白有意义**。
3. **不同枚举类型不能直接比较**，需显式转 `text`。
4. **`ORDER BY` 按定义顺序**，不是字母顺序。
5. **不能删除枚举值**。
6. **不能直接改变枚举值顺序**。
7. 删除并重建枚举类型**可能影响依赖对象**（列、默认值、索引、视图）。
8. `ADD VALUE` 后，新值默认加在**末尾**（除非用 `BEFORE`/`AFTER` 指定）。
9. **转换为 `text` 后比较，失去枚举顺序语义**（变纯字符串比较）。
10. 枚举值占 **4 字节**，标签长度最大 **63 字节**。
11. `pg_enum` 可直接查询，但**不要随意修改系统目录**。
12. **应用层与数据库枚举不同步会导致插入失败**。

# 速查 SQL

```sql
-- 创建枚举
CREATE TYPE mood AS ENUM ('sad', 'ok', 'happy');

-- 使用枚举
CREATE TABLE person (
    name text,
    current_mood mood
);

INSERT INTO person VALUES
('Moe', 'happy'),
('Larry', 'sad'),
('Curly', 'ok');

-- 查询
SELECT * FROM person WHERE current_mood = 'happy';
SELECT * FROM person WHERE current_mood > 'sad';
SELECT * FROM person ORDER BY current_mood;

-- 聚合
SELECT MIN(current_mood), MAX(current_mood) FROM person;

-- 增加枚举值
ALTER TYPE mood ADD VALUE 'ecstatic';

-- 重命名枚举值
ALTER TYPE mood RENAME VALUE 'ok' TO 'fine';

-- 查看枚举定义
SELECT enumlabel
FROM pg_enum
WHERE enumtypid = 'mood'::regtype
ORDER BY enumsortorder;

-- 跨枚举比较（显式转文本）
SELECT person.name, holidays.num_weeks
FROM person, holidays
WHERE person.current_mood::text = holidays.happiness::text;
```

# 总结

ENUM 适合表示稳定、有序、小规模的固定值集合；它提供类型安全和固定排序，但修改受限。设计时先判断值是否会频繁变化，再决定用 ENUM、CHECK 还是查找表。
