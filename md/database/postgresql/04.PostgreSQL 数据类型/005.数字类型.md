# 概述

所有可用类型如下：

| 名字 | 存储尺寸 | 描述 | 范围 |
| --- | --- | --- | --- |
| `smallint` | 2字节 | 小范围整数 | -32768 到 +32767 |
| `integer` | 4字节 | 整数的典型选择 | -2147483648 到 +2147483647 |
| `bigint` | 8字节 | 大范围整数 | -9223372036854775808 到 +9223372036854775807 |
| `decimal` | 可变 | 用户指定精度，精确 | 最高小数点前131072位，以及小数点后16383位 |
| `numeric` | 可变 | 用户指定精度，精确 | 最高小数点前131072位，以及小数点后16383位 |
| `real` | 4字节 | 可变精度，不精确 | 6位十进制精度 |
| `double precision` | 8字节 | 可变精度，不精确 | 15位十进制精度 |
| `smallserial` | 2字节 | 自动递增的小整数 | 1到32767 |
| `serial` | 4字节 | 自动递增的整数 | 1到2147483647 |
| `bigserial` | 8字节 | 自动递增的大整数 | 1到9223372036854775807 |


# 整数类型

类型 **smallint**、**integer** 和 **bigint** 用于存储不同范围的整数，也就是没有小数部分的数。 试图存储超出允许范围的值会导致错误。

常用的类型是**integer**，因为它提供了在范围、存储空间和性能之间的最佳平衡。一般只有在磁盘空间紧张的时候才使用 **smallint**类型。**bigint**则设计用于**integer**的范围不够的情况。

SQL只规定了整数类型**integer（或int）**、**smallint**和**bigint**。类型**int2**、**int4**和**int8**都是扩展，也在某些其他SQL数据库系统中使用。

# 任意精度数值

## 了解

**numeric** 可以存储非常多位数字，特别适合货币金额以及其他要求精确计算的数量。其加法、减法、乘法在可能情况下会得到精确结果；但 **numeric** 上的算术运算比整数类型或浮点数类型慢很多。

## 精度与小数位数

- **精度（precision）** ：是一个 **numeric** 值中有效数字的总位数，也就是小数点两侧数字的总数。 
- **小数位数（scale）** ：是小数部分中位于小数点 右侧的十进制位数。

因此，数值 **23.5141** 的精度为 **6**，小数位数为 **4**。 

**整数**可以认为其小数位数为 **0**。

## 声明语法

```sql
NUMERIC(precision, scale)
NUMERIC(precision)
NUMERIC
```

| 写法                                                 | 含义                                         |
|------------------------------------------------------|----------------------------------------------|
| NUMERIC(precision, scale)	                            | 指定精度和小数位数                           |
| NUMERIC(precision)                                   | 小数位数为 0                                 |
| NUMERIC | 无约束 numeric，可存任意长度数值直到实现限制 |

说明：

- **precision** 必须为正数。
- **scale** 可以为正数、负数或零。
- **NUMERIC** 不写精度和小数位数时，创建 **“无约束 numeric”** 列：
- 可存储任意长度数值，直到达到实现限制；
- 不会把输入值强制到特定小数位数。
- 声明了小数位数的 **numeric** 列会把输入值强制到该小数位数。
- SQL 标准要求默认小数位数为 **0**，即强制整数精度；PostgreSQL 未采用此行为。若关心可移植性，应始终显式指定精度和小数位数。

> [!note]
> **numeric** 类型声明中可显式指定的最大精度为 **1000**。 无约束的 **numeric** 列受 **[概述](#概述)** 中的表格所述限制的约束。

## 舍入与范围限制

如果要存储的值的小数位数大于该列声明的小数位数，系统会把该值 舍入到指定的小数位数。然后，如果小数点左侧的位数超过了 **precision - scale**，就会报错。

```sql
NUMERIC(3, 1)
```

该列会把值舍入到 1 位小数，并且可以存储 **-99.9** 到 **99.9** 之间（含边界）的值。

从PostgreSQL 15 开始，允许声明带有 负小数位数的 **numeric** 列。此时，值会在小数点左侧 舍入。精度仍表示未被舍入的数字的最大位数。因此，声明为

```sql
NUMERIC(2, -3)
```

该列会把值舍入到最接近的千位，并且可以存储 **-99000** 到 **99000** 之间（含边界）的值。

也允许声明比声明精度更大的小数位数。 这种列只能保存纯小数值，并且要求小数点右侧紧邻的小数位中， 至少有 **scale - precision** 个 0。例如，声明为

```sql
NUMERIC(3, 5)
```

列会把值舍入到 5 位小数，并且可以存储 **-0.00999** 到 **0.00999** 之间（含边界）的值。

> [!note]
> PostgreSQL允许在 **numeric** 类型声明中把小数位数指定为 **-1000** 到 **1000** 范围内的任意值。 但 SQL 标准要求小数位数位于 **0** 到 **precision** 之间。使用超出该范围的 小数位数，在其他数据库系统中可能不可移植。

## 存储方式

数值在物理上存储时不会保留多余的前导零或尾随零。因此，列上 声明的精度和小数位数只是最大值，而不是固定分配的空间。从这个意义上说，**numeric** 更像 **varchar(n)**，而不像 **char(n)**。

实际存储需求：每四个十进制数字组占两个字节，再加上 3 到 8 字节的开销。

## 特殊值

除了普通数值之外，**numeric** 类型还有如下几个特殊值：

```text
Infinity
-Infinity
NaN
```

这些值改编自 IEEE 754 标准，分别表示“无穷大”、 “负无穷大”和“非数字”。

在 SQL 命令中把这些值写成常量时，必须将它们用引号括起来，例如：

```sql
UPDATE table SET x = '-Infinity'
```

输入时， 这些字符串按大小写不敏感方式识别。无穷大值也可以写作 **inf** 和 **-inf**。

无穷大值的行为符合数学预期：例如，

- Infinity 加上任何有限值都等于Infinity
- Infinity + Infinity = Infinity
- Infinity - Infinity = NaN，因为它没有良好定义的解释

请注意：无穷大只能存储在 无约束的 **numeric** 列中，因为它在概念上超出了任何有限精度限制。

**NaN（非数字）** 用于表示未定义的计算结果。 一般来说，任何带有 **NaN** 输入的运算都会产生 另一个 **NaN**。唯一的例外是：如果把 **NaN** 替换成任意有限或无限数值，运算都会得到 同一个结果，那么该结果对 **NaN** 也成立。例如：NaN 的 0 次方等于 1。

> [!note]
> 在大多数“非数字”概念的实现中，**NaN** 都被认为不等于任何其他数值（包括 **NaN** 本身）。 为了让 **numeric** 值能够排序并用于基于树的索引， PostgreSQL 将 **NaN** 值视为彼此相等，并且大于所有非 **NaN** 值。

## 与 decimal 的关系

类型 **decimal** 和 **numeric** 是等效的。两种类型都是SQL标准的一部分。

## 舍入差异

进行舍入时：

- **numeric** 类型在遇到恰好处于中间的值时， 会朝远离零的方向舍入
- **real** 和 **double precision** 类型，在大多数机器上会把这类值舍入到最近的偶数。

例如：

```sql
SELECT x,
  round(x::numeric) AS num_round,
  round(x::double precision) AS dbl_round
FROM generate_series(-3.5, 3.5, 1) as x;
```

```text
  x   | num_round | dbl_round
------+-----------+-----------
 -3.5 |        -4 |        -4
 -2.5 |        -3 |        -2
 -1.5 |        -2 |        -2
 -0.5 |        -1 |        -0
  0.5 |         1 |         0
  1.5 |         2 |         2
  2.5 |         3 |         2
  3.5 |         4 |         4
(8 rows)
```

# 浮点类型

## 了解

数据类型 **real** 和 **double precision** 是 **不精确的**、**变精度**的数字类型。在当前所有受支持的平台上，只要底层 处理器、操作系统和编译器提供支持，这两种类型都实现了 IEEE 754 二进制浮点算术标准 （分别对应单精度和双精度）。

所谓**不精确**，是指某些值无法被精确转换为内部格式，只能以近似值存储，因此存储并再取出一个值时，可能会看到轻微差异。如何处理 这类误差以及它们在计算中如何传播，是数学和计算机科学中的一个 **独立领域**，这里不再展开，只强调以下几点：

- 如果你要求准确的存储和计算（例如计算货币金额），应使用 **[numeric](#任意精度数值)** 类型。
- 如果你想用这些类型进行任何重要的复杂计算，尤其是依赖边界情形 （无穷大、下溢）特定行为的计算，那么应该仔细评估其实现。
- 比较两个浮点值是否相等，未必总能得到符合预期的结果。

## 精度与范围

| 类型 | 范围（约）       | 精度（至少） | 对应 IEEE 754 |
| --- |------------------| --- | --- |
| real	| 1E-37 到 1E+37   | 6 位十进制数字	| 单精度 |
| double precision	| 1E-307 到 1E+308	 | 15 位十进制数字	| 双精度 |

- 过大或过小的值都会导致错误。
- 如果输入数字的精度过高，可能会发生舍入。
- 过于接近零且无法区别于零的数值，会导致下溢错误。

## 输出格式

默认情况下，浮点值会以最短且精确的十进制表示形式输出。所生成的十进制值与实际存储的二进制值之间的距离，小于它与任何其他可用相同二进制精度表示的值之间的距离。

为了避免输入例程普遍存在的一个错误——即未能正确遵守舍入到最近偶数规则——当前输出值绝不会恰好位于两个可表示值的正中间。

- 对于 **float8**（即 double precision）值，最多使用 17 位有效十进制数字。
- 对于 **float4**（即 real）值，最多使用 9 位有效十进制数字。

> [!note]
> 生成这种最短且精确的输出格式，比历史上的舍入格式要快得多。

## extra_float_digits 参数

为了兼容旧版本 PostgreSQL 生成的输出， 并允许降低输出精度，可以使用 **extra_float_digits** 参数改为选择舍入后的十进制输出。

| 参数值                      | 行为                                                                  |
|-----------------------------|-----------------------------------------------------------------------|
| 0                           | 恢复旧默认行为：float4 舍入为 6 位，float8 舍入为 15 位有效十进制数字 |
| 负值                        | 进一步减少位数；例如 -2 会把输出分别舍入到 4 位或 13 位数字           |
| 大于 0 | 选择最短且精确的格式                                                  |   

> [!note]
> 过去那些需要精确值的应用，必须把 **extra_float_digits** 设置为 **3** 才能获得它们。 为了在版本之间获得最大兼容性，这类应用应继续这样做。

## 特殊值

除了普通的数字值之外，浮点类型还有几个特殊值：

```text
Infinity
-Infinity
NaN
```

这些分别表示 IEEE 754 的特殊值“无穷大”、 “负无穷大”和“非数字”。

如果在 SQL 命令里把这些值写成常量，必须用单引号将它们括起来，例如：

```sql
UPDATE table SET x = '-Infinity'
```

输入时， 这些字符串按大小写不敏感的方式识别。无穷大值也可以写作 **inf** 和 **-inf**。

> [!note]
> IEEE 754 规定，**NaN** 不应与任何其他浮点值 （包括 **NaN** ）相等。为了允许浮点值被排序， 并可用于基于树的索引，PostgreSQL 将 **NaN** 视为彼此相等，并且大于所有非 **NaN** 值。

## float 记法

PostgreSQL 也支持 SQL 标准记法 **float** 和 **float(p)** 来指定不精确数值类型。这里，**p** 指定可接受的最小二进制精度位数。 

| 写法 | 含义 |
| --- | --- |
| float(1) 到 float(24)	| 选择 real 类型 |
| float(25) 到 float(53)	| 选择 double precision |
| float（未指定精度）	| 视为 double precision |

- p 超出允许范围会报错。

# serial类型

## 了解

**smallserial**、**serial** 和 **bigserial** 并不是真正的数据类型，它们只是为了创建 唯一标识符列而提供的记法便利（类似于其他一些数据库支持的 **AUTO_INCREMENT** 属性）。在当前实现中，下列语句：

## 等价语法

在当前实现中，下列语句：

```sql
CREATE TABLE tablename (
    colname SERIAL
);
```

等价于以下语句：

```sql
CREATE SEQUENCE tablename_colname_seq AS integer;
CREATE TABLE tablename (
    colname integer NOT NULL DEFAULT nextval('tablename_colname_seq')
);
ALTER SEQUENCE tablename_colname_seq OWNED BY tablename.colname;
```

说明：

- 创建一个整数列，并把它的默认值设置为从序列生成器中取值
- 同时还会加上**NOT NULL**约束，以确保不能插入空值
- 在大多数情况下，你可能还会希望再加上 **UNIQUE** 或 **PRIMARY KEY** 约束，以防意外插入重复值，但这**不会自动发生**
- 最后，该序列会被标记为“属于”该列， 这样当列或表被删除时，序列也会随之删除

> [!note]
> 因为 **smallserial**、**serial** 和 **bigserial** 是用序列实现的，所以即使没有删除任何行，列中出现的值序列也可能存在“空洞”或缺口。 
> 即使包含该值的行从未成功插入表中，从序列分配出去的值仍会被 视为“已使用”。例如，如果插入事务回滚，就会 发生这种情况。详细信息见 **[nextval()](../07.PostgreSQL%20内置函数/030.序列操作函数.md#nextval)**。

## 插入默认值

要向 **serial** 列插入序列中的下一个值，应指定让**serial**列 使用其默认值。这可以通过以下两种方式实现：

- 在 **[INSERT](../02.PostgreSQL%20基础/130.INSERT%20插入新行.md#概述)** 语句的列表中省略该列
- 使用 **DEFAULT** 关键字

## 类型别名

| 类型名 | 等价于 | 创建的列类型 |
| --- | --- | --- |
| serial | serial4 | integer |
| bigserial | serial8 | bigint |
| smallserial | serial2 | smallint |

- 如果预计表在其生命周期内会使用超过 **2^31** 个标识符，就应使用 **bigserial**。

## 序列生命周期

- 为 **serial** 列创建的序列会在其所属列被删除时自动删除。
- 你也可以在不删除该列的情况下删除该序列，但这会强制移除该列的默认值表达式。
