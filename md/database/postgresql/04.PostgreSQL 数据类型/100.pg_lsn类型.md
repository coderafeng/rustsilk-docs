# 概述

- **pg_lsn**（PostgreSQL Log Sequence Number）用于表示 **WAL（预写式日志）中的某个位置**，是一个 64 位字节偏移。
- 主要用途：**复制监控与运维**——记录主库写到哪里、备库回放到哪里、两者差多少、某个 checkpoint/还原点在哪。
- 文本形式：`文件号/段内偏移`，两段都是**十六进制**，例如 `0/16B3178`。
- 比较运算按内部 64 位整数序，**“LSN 越大越新”**，因此 `> < =` 直接可用。
- 计算两个 LSN 之间的字节差用 **`pg_wal_lsn_diff(a, b)`**，返回 double precision（字节）。
- 普通业务表**基本不会用到 pg_lsn**，它是 DBA/复制/ PITR 场景的类型。

# 类型速查表

| 维度       | 说明                                                     |
|------------|----------------------------------------------------------|
| 大小       | 8 字节（64 位）                                          |
| 显示格式   | `<hex>/<hex>`，如 `0/2A18E7`、`1/9F45678`                |
| 输入       | 接受带/不带空白，大小写不敏感                             |
| 比较       | 按 64 位整数序，越大越新                                  |
| 差值       | `pg_wal_lsn_diff(a,b)` → 字节数（a-b）                   |
| 典型来源   | `pg_current_wal_lsn()`、复制视图、checkpoint 记录         |

# 输入与输出

外部文本是 `高位/低位` 两段十六进制：

```sql
SELECT '0/16B3178'::pg_lsn;
```

输出：

```text
 pg_lsn
---------
 0/16B3178
```

- 输入时数字部分可带空白、大小写均可。
- 输出始终以标准形式显示。

# 比较与差值

pg_lsn 支持 `= < > <= >= <>`，语义即 WAL 位置先后：

```sql
SELECT '0/16B3178'::pg_lsn < '1/0'::pg_lsn;   -- true
```

计算两位置之间字节距离用 `pg_wal_lsn_diff`：

```sql
-- 当前 WAL 写入位置
SELECT pg_current_wal_lsn();

-- 主库当前 LSN 与备库回放 LSN 的差距（复制延迟，字节）
SELECT pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS lag_bytes
FROM pg_stat_replication;
```

> [!tip]
> 想把字节差换算成人类可读大小，可 `pg_size_pretty(pg_wal_lsn_diff(a,b)::bigint)`。

# 常见来源函数

pg_lsn 常和这些系统/管理函数一起出现：

| 函数                                | 作用                                    |
|-------------------------------------|-----------------------------------------|
| `pg_current_wal_lsn()`              | 主库当前 WAL 写入位置                   |
| `pg_last_committed_lsn()` 等         | 相关提交位置（视版本）                  |
| `pg_wal_lsn_diff(a, b)`             | 两 LSN 的字节差                         |
| `pg_create_restore_point(name)`     | 创建一个还原点，返回其 pg_lsn           |
| `pg_replication_origin_progress()`  | 复制进度（返回 pg_lsn）                 |

`sent_lsn`、`write_lsn`、`flush_lsn`、`replay_lsn`（`pg_stat_replication` 列）、`restart_lsn`（`pg_replication_slots` 列）、`checkpoint_lsn`（`pg_control_system()`）等都是 pg_lsn 类型。

相关函数详见 **[系统管理函数](../07.PostgreSQL%20内置函数/090.系统管理函数.md#概述)** 与 **[系统信息函数](../07.PostgreSQL%20内置函数/085.系统信息函数.md#概述)**。

# 实战 SQL

```sql
-- 1) 看主库当前 WAL 位置
SELECT pg_current_wal_lsn() AS current_lsn;

-- 2) 监控每个备库的复制延迟（字节）
SELECT client_addr, state,
       pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS replay_lag_bytes,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn)) AS lag
FROM pg_stat_replication;

-- 3) 复制槽保留了多久没被消费的 WAL
SELECT slot_name,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS retained
FROM pg_replication_slots;

-- 4) 创建一个 PITR 还原点并记下 LSN
SELECT pg_create_restore_point('before_migration') AS lsn;
-- 之后按 'recovery_target_time' 或 recovery_target_lsn 恢复到该点
```

# 最佳实践

1. **pg_lsn 只用于复制/监控/恢复运维场景**，别放进业务表当普通字段。
2. **算延迟统一用 `pg_wal_lsn_diff()`**，不要自己拆十六进制做算术。
3. **展示延迟用 `pg_size_pretty()` 包一层**，字节数对人不可读。
4. **复制槽 `restart_lsn` 与当前 LSN 差距过大要告警**，说明 WAL 堆积、磁盘风险。
5. **PITR 记还原点时把返回的 LSN 存到运维记录**，恢复时用 `recovery_target_lsn` 精确定位。

# 常见坑

1. **显示是两段十六进制 `/` 分隔**，别按十进制直接字符串比较（要先 `::pg_lsn`）。
2. **`pg_wal_lsn_diff(a,b)` 返回 double**，极大差值时精度有限，一般监控够用。
3. **“LSN 越大越新”依赖单调递增**，跨时间线（promote/failover 后 timeline 变化）不能只看 LSN，需结合 **timeline id**。
4. **pg_lsn 不是时间点/时间戳**，它是 WAL 字节位置，别拿它直接算“延迟秒数”（那是 `pg_last_wal_replay_lsn` + 时间戳或 `replay_lag`）。
5. **旧版本函数名不同**：PG10 前是 `pg_current_xlog_location()`、`pg_xlog_location_diff()`，升级到 `*_wal_*` 命名后要改。
6. 复制视图里 `replay_lsn` 可能为 **NULL**（备库未连/未开始回放），做 diff 前先判空。

# 总结

- pg_lsn 是 8 字节的 WAL 日志序列号，文本形如 `0/16B3178`，**越大越新**，用于复制监控与 PITR。
- 算位置差用 `pg_wal_lsn_diff()`，配 `pg_size_pretty()` 看延迟；数据来自 `pg_current_wal_lsn()`、`pg_stat_replication`、复制槽等。
- 它是运维/复制专用类型，业务建模几乎用不到；跨 timeline 场景要结合 timeline id 判断先后。
