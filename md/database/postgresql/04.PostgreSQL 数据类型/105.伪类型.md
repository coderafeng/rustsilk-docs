# 概述

- **伪类型（pseudo-type）** 是一类“**只能出现在函数签名里、不能用来定义表列**”的特殊类型占位符。
- 作用：让一个 C/内部函数能接受或返回“**任意某种类型**”的值——例如 `anyelement` 表示“任意具体类型的一个元素”，`anyarray` 表示“任意数组”。
- 核心价值：**多态函数（polymorphic function）**。同一函数定义能适配多种入参类型，PostgreSQL 在调用时按实际参数推断具体类型。
- 你日常其实一直在用：`array_length(anyarray, int)`、`num_nonnulls(VARIADIC "any")`、触发器函数返回 `trigger`、`COALESCE` 背后的 `anyelement` 等。
- 常见认知误区：**“anyelement/record 是能用在建表里的类型”——不是**，它们是伪类型，只能用于函数参数/返回。

# 为什么需要伪类型

假设要实现一个“把任意数组元素用逗号连接成字符串”的函数，你不想为 `int[]`、`text[]`、`date[]` 各写一份。伪类型 `anyarray` 让一份签名搞定：

```sql
-- 声明层面（示意）：f(anyarray) -> text
SELECT array_to_string(ARRAY[1,2,3], ',');   -- 传 int[]
SELECT array_to_string(ARRAY['a','b'], ','); -- 传 text[]
```

调用时 PostgreSQL 把 `anyarray` 绑定到实参的具体类型，检查一致性后再执行。这就是“参数多态”。

# 伪类型速查表

| 伪类型            | 匹配范围                                             |
|-------------------|------------------------------------------------------|
| anyelement        | 任意**非数组、非复合**的具体类型的一个值             |
| anyarray          | 任意**数组**类型；与 anyelement 联动（元素即其类型） |
| anynonarray       | 任意**非数组**类型（用于与 anyarray 区分重载）       |
| anyenum           | 任意**枚举**类型值                                   |
| anyrange          | 任意**范围**类型值                                   |
| anymultirange     | 任意**多范围**类型值                                 |
| anycompatible     | 任意兼容类型（见“anycpatible 家族”）                 |
| anycompatiblearray| 与 anycompatible 元素类型兼容的数组                  |
| anycompatiblenonarray | 兼容的非数组类型                                |
| anycompatiblerange| 与 anycompatible 兼容的范围                          |
| anycompatiblemultirange | 与 anycompatible 兼容的多范围                   |
| any               | （历史遗留）任意类型，**已不推荐**，改用上面具体族   |
| cstring           | C 字符串（`char *`），仅用于 C 接口函数              |
| internal          | 不透明指针，仅内部函数使用                           |
| record            | 一段行结构（复合值），可用于函数参数/返回            |
| trigger           | 触发器信息，仅触发器函数用                           |
| event_trigger     | 事件触发器信息，仅事件触发器函数用                   |
| pg_ddl_command    | DDL 命令信息，仅事件触发器相关                       |
| language_handler  | 过程语言处理器，仅语言 handler 函数用                |
| fdw_handler       | 外部数据包装器 handler，仅 FDW 函数用                |
| table             | 用于 `RETURNS TABLE`，表示一个“表结构”返回值          |
| void              | “什么都不返回”，函数不想有返回值时用                 |
| unknown           | 未解析类型的字面量（多在内部/调试见到）              |

> 并非所有 PostgreSQL 版本都包含全部条目（如 `anymultirange`、`anycpatible*` 系列是较新版本引入）。以目标版本文档为准，具体内部函数参见 **[系统信息函数](../07.PostgreSQL%20内置函数/085.系统信息函数.md#概述)**。

# 使用伪类型写多态函数

`anyelement` / `anyarray` 是最常用的一对。它们的绑定规则：**同一签名里的所有 `anyelement` 必须解析为同一具体类型；`anyarray` 的元素类型必须与之匹配。**

```sql
-- 返回任意两元素中的较大者（示意，实际有 greater(a,b)）
CREATE FUNCTION my_greatest(anyelement, anyelement)
RETURNS anyelement
LANGUAGE sql AS
$$ SELECT CASE WHEN $1 > $2 THEN $1 ELSE $2 END $$;

SELECT my_greatest(3, 7);            -- int
SELECT my_greatest('a'::text,'b');   -- text
```

`anyarray` + `anyelement` 组合，能表达“数组 + 其元素类型”的关联：

```sql
CREATE FUNCTION elem_at_1(arr anyarray) RETURNS anyelement
LANGUAGE sql AS $$ SELECT arr[1] $$;

SELECT elem_at_1(ARRAY[10,20,30]);   -- int 10
```

# anycompatible 家族

`anycpatible*` 家族是为**放宽多态约束**引入的：同一签名里的多个 `anycpatible` 参数**不必完全同类型**，只要彼此**兼容**（存在共同的可选中类型）即可，由系统隐式统一到该中类型。

```sql
CREATE FUNCTION pair(a anycompatible, b anycompatible)
RETURNS anycompatible LANGUAGE sql AS
$$ SELECT COALESCE(a, b) $$;

-- int 与 bigint 兼容，被提升到更宽类型
SELECT pair(1::int, 2::bigint);
```

对比：`anyelement` 要求严格同类型（`pair(1::int, 2::text)` 会报“无法确定兼容类型”），`anycpatible` 更宽松，写通用聚合/比较函数时更实用。

# record 与复合返回

`record` 是一个“**结构尚未定型的复合值**”伪类型，常用于返回列不固定的函数，调用方在用 `AS (...)` 指定实际列结构：

```sql
CREATE FUNCTION get_user(int) RETURNS record AS $$
    SELECT name, age FROM users WHERE id = $1;
$$ LANGUAGE sql;

-- 调用时必须声明列名与类型
SELECT * FROM get_user(1) AS u(name text, age int);
```

若返回类型固定，优先用 `RETURNS TABLE(...)` 或具体复合类型，比 `record` 更好用、更不易错。`SETOF record` 则用于返回多行且列结构由调用方指定。

# VARIADIC "any" 与 anynonarray

- `VARIADIC "any"` 让函数接受**任意数量、任意类型**的参数，`COALESCE`、`num_nonnulls`、`concat` 等就靠它。
- `anynonarray` 用于“**只要非数组**”的场景，常与 `anyarray` 一起区分重载，避免歧义。

# 常见坑

1. **伪类型不能用作表列类型**：`CREATE TABLE t (c anyelement);` 会报错——只能出现在函数参数/返回。
2. **`any`（裸）已废弃/不推荐**，它太宽泛、多态解析规则不清晰；新代码用 `anyelement`/`anycpatible` 等具体族。
3. **同签名的 `anyelement` 必须解析为同一类型**，传 `f(1, 'a')` 会因无法统一而报错，需要就改用 `anycpatible`。
4. **`record` 返回时调用方必须显式 `AS (...)` 声明列结构**，否则列名列类型未知、难以使用。
5. **`trigger` / `event_trigger` / `internal` / `cstring` 等有严格使用限定**：只能用于相应类型的函数（触发器函数、C 内部函数），普通 SQL 函数别乱写。
6. **`void` 不是“返回 NULL”**，而是明确表示无返回值；把它当“有返回”用会误解。
7. **多态函数必须有“输入”伪类型才能解析返回**：`RETURNS anyelement` 却没有任何 `any*` 参数，创建时会报错。
8. `anycpatible*` 家族在旧版本不存在，跨版本迁移前确认最低支持版本。

# 最佳实践

1. **写“类型无关”的工具函数就用 `anyelement`/`anyarray`**，享受类型安全的多态。
2. **需要多参数类型可不同但可统一时，用 `anycpatible` 家族**，别硬用 `anyelement` 逼调用方先转换。
3. **列结构固定就别用 `record`**，改 `RETURNS TABLE(...)` 或具体复合类型，调用更省心。
4. **能用具体类型就不用伪类型**：伪类型是为通用性服务，牺牲了部分清晰度。
5. **理解各伪类型的适用限定**（handler/trigger/internal 等），只在设计对应扩展/触发器时使用。

# 总结

- 伪类型是**只服务于函数签名的占位类型**，不能定义表列；它让 PostgreSQL 支持参数多态。
- 常用族：`anyelement`/`anyarray`（严格同类型多态）、`anycpatible*`（兼容即可的宽松多态）、`record`（不定形复合返回）、`VARIADIC "any"`（不定参），以及 `trigger`/`internal`/`void` 等专用占位。
- 记住三条：不能建列、`anyelement` 要严格同类型、裸 `any` 已不推荐——就避开了大部分坑。
