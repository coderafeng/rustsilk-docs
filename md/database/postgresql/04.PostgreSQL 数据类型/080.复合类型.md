# 概述

- **复合类型（row/record type）** 相当于一条“结构体记录”：把若干命名字段（可各有类型）组合成一个值。
- 两种来源：
    - **`CREATE TYPE ... AS (...)`** 显式定义的复合类型。
    - **每张表/视图自动拥有一个同名的复合类型**（字段=列），可直接当类型用。
- 复合值可以整体传参、返回（函数返回多列时常用复合类型），也可用 `(col).*` 展开成列。
- **字段访问用点号 `.`**，取整个复合值用括号包裹（`(col).*` 而非 `col.*` 有歧义场景）。
- 与 JSON 的区别：复合类型是**强类型、字段固定、schema 驱动**；结构会变、字段稀疏时更适合 JSONB。
- 经验：复合类型适合“函数返回多列”“轻量结构打包传参”，但**不适合当可变 schema 的存储格式**——改字段要 `ALTER TYPE`，且被表依赖时受限。

# 速查表

| 操作         | 写法                                             |
|--------------|--------------------------------------------------|
| 定义类型     | `CREATE TYPE name AS (a int, b text);`           |
| 构造值       | `ROW(1, 'x')` / `(1, 'x')` / `'ROW(1,x)'::ct`    |
| 建表用复合列 | `CREATE TABLE t (c ct);`                         |
| 访问字段     | `c.a` / `(c).* ` 展开                            |
| 整体比较     | `c = (1,'x')::ct`（按字段逐个比）                |
| 忽略字段     | 定义时可用 `FOR` 引用表结构派生                  |
| 修改         | `UPDATE t SET c = ROW(...);` 或 `SET c.a = ...`  |

# 复合类型的声明

用 `CREATE TYPE` 定义一个复合类型，指定字段名与类型：

```sql
CREATE TYPE complex AS (
    r       double precision,
    i       double precision
);
```

如前所述，**创建表或视图时，每个都会自动得到一个与其相关的复合类型**。例如建表 `inventory_items`，就自动有一个同名复合类型，字段与列一致。这个类型可直接用在需要复合类型的地方，例如函数返回该表的一行：

```sql
CREATE FUNCTION get_item(int) RETURNS inventory_items AS ...
```

> [!note]
> 复合类型的字段可以本身又是数组或另一个复合类型（嵌套）。但不建议在复合类型里放 `oid` 等系统内部类型字段——后续 `ALTER` 时这类字段有限制。

# 构造复合值

可以用构造器表达式 `ROW(...)` 或简写的圆括号列表构造：

```sql
SELECT ROW(1, 2.5, 'this is a test')::some_type;
SELECT (1, 2.5, 'this is a test');
```

也可以写一个文本形式的复合值再转换。复合值的外部文本是**圆括号包围、逗号分隔的字段列表**：

```sql
SELECT '(1,2.5,"this is a test")'::complex;
```

- 字段值里含逗号、引号、括号、空白等，需要用**双引号**括起该字段，内部双引号再写成 `""`。
- 空字段（两个逗号之间什么都没有）表示 **NULL**；想要空字符串必须写 `""`。

# 访问复合类型

用点号 `.` 访问字段：

```sql
CREATE TABLE on_hand (
    item      complex,
    quantity  integer
);
INSERT INTO on_hand VALUES (ROW(1, 2), 100);

SELECT item.r FROM on_hand;          -- 取字段 r
SELECT (item).* FROM on_hand;        -- 展开成多列 r, i
```

> [!caution]
> `(item).*` 外面的**括号不可省**。写成 `item.*` 会被解析成“表 item 的所有列”，而不是“复合值 item 的所有字段”。

复合值也能作为参数传给函数、或整体比较：

```sql
SELECT * FROM on_hand WHERE item = (1, 2);
```

`=` 会**逐个字段比较**（按各字段类型的比较规则）。注意 `<>` 不等价于对 `=` 取反——只要有一个字段两侧都非 NULL 且不相等即为真，含 NULL 字段时结果可能为 NULL。

# 修改复合类型

整体替换：

```sql
UPDATE on_hand SET item = ROW(3, 4) WHERE quantity > 50;
```

只改其中一个字段（PostgreSQL 支持直接对字段赋值，无需先取出再整体写回）：

```sql
UPDATE on_hand SET item.r = 5 WHERE quantity > 50;
```

> [!warning]
> 无论整体还是单字段更新，**存储上都会重写整个复合值**。复合值很大、又只改一个小字段时，要意识到这是整值替换，不是原地改。

# 在查询中使用复合类型

复合类型可作为函数返回类型，一次返回“一行多列”：

```sql
CREATE TYPE emp_name_sal AS (name text, salary numeric);

CREATE FUNCTION get_name_sal(eid int) RETURNS emp_name_sal AS $$
    SELECT name, salary FROM emp WHERE empno = eid;
$$ LANGUAGE sql;

SELECT (get_name_sal(1)).*;    -- 注意展开也要括号
```

也可在 `FROM` 里把函数返回的复合/集合当表用：

```sql
SELECT x.* FROM get_name_sal(1) x;
```

把整行当复合值：`SELECT t FROM tbl t;` 返回每行的复合值；`SELECT t.* ...` 返回展开的列。给 `COUNT(*)`、`ROW(...)` 或作函数参数时，常用整行复合值。

# 复合类型的输入和输出语法

复合值的外部文本形式是圆括号里的逗号分隔字段列表，字段按其自身类型的 I/O 规则解释。规则要点：

- 除非是数字且无特殊字符，字段可加双引号；含逗号、引号、括号、连字符开头的负数、前后空白等情况下，建议加双引号，内部双引号 `""` 转义。
- **空字段视为 NULL**；想要空字符串必须显式写 `""`。
- 输出时，PostgreSQL 只在字段确实需要时才加引号，因此显示形式可能与输入不完全一致。
- 因为外层是圆括号，`SELECT` 出的整行文本形如 `(1,2.5,"this is a test")`。

# 最佳实践

1. **函数要返回多列时优先用复合类型或 `RETURNS TABLE(...)`**，比返回 JSON 更有类型约束、调用方更好用。
2. **字段固定的轻量结构**用复合类型；**结构会变、字段稀疏**用 JSONB。
3. **展开字段记得加括号** `(col).*`，与整表 `t.*` 区分。
4. **整体比较用 `=`，但要清楚含 NULL 字段的三值逻辑**，别假设 `a = b` 与 `a <> b` 互补。
5. **改单个字段可直接 `SET col.field = ...`**，代码更清晰，但知道底层是整值重写。
6. **不要在复合类型里放 `oid` 等内部类型字段**，避免 `ALTER TYPE` 受限。
7. **被表列依赖的复合类型改动要谨慎**：删/改字段可能因依赖而失败，先在测试环境验证。

# 常见坑

1. `col.*` 不加括号会被当成“表的所有列”，展开复合字段必须写 `(col).*`。
2. 复合文本里**空字段是 NULL**，想要空串必须写 `""`。
3. 含逗号/引号/括号的字段不加双引号会导致解析错乱。
4. `=` 逐字段比较，含 NULL 字段可能返回 NULL；`<>` 不满足 `NOT(a=b)`。
5. 只改一个字段也会**重写整个复合值**，大复合值频繁局部更新代价高。
6. 每张表自动有同名复合类型，别误以为只有 `CREATE TYPE` 才算复合类型。
7. 复合类型字段类型/名字被表依赖时，`ALTER TYPE` 受限，改动前需处理依赖。
8. 把整行 `SELECT t` 和展开列 `SELECT t.*` 混用，返回结构不同，客户端处理要注意。
9. 复合值作为函数参数时，若参数是复合类型，必须整体传入，不能直接传字段。

# 总结

- 复合类型是强类型的“记录结构”，可显式 `CREATE TYPE` 定义，也可复用表/视图自动生成的类型。
- 用 `ROW(...)` 或圆括号文本构造，用 `col.field` 访问、`(col).*` 展开；`=` 逐字段比较。
- 适合函数返回多列、打包传参；结构易变请用 JSONB，字段含 NULL 时注意比较与整值重写。
