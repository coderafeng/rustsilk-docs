# 概述

- **范围类型（range type）** 表示某种元素类型的一段区间，如“[今天, 明天)”的时间段、价格区间、版本区间。
- 一个范围值携带**上下界 + 每个边界是包含还是排除 + 是否为空**三层信息，天生适合“一段时间/一段区间是否重叠、是否包含”的语义。
- **多范围（multirange）** 是若干不重叠范围的集合（PG14+），可存“离散的多段区间”。
- 最大实用价值：配合 **GiST 索引 + `EXCLUDE USING gist` 约束**，一行代码就能实现“同一资源的时间段不能重叠”（会议室排期、预约系统）。
- 默认边界语义是 **左闭右开 `[)`**，这点对连续类型很自然，对整数等离散类型要注意（详见“离散范围类型”）。

# 内置范围类型和多范围类型

| 范围类型    | 元素类型      | 对应多范围类型       |
|-------------|---------------|----------------------|
| int4range   | integer       | int4multirange       |
| int8range   | bigint        | int8multirange       |
| numrange    | numeric       | nummultirange        |
| tsrange     | timestamp     | tsmultirange         |
| tstzrange   | timestamptz   | tstzmultirange       |
| daterange   | date          | datemultirange       |

自定义类型可派生新的范围/多范围类型。注意：`text`、`bytea` 等**没有合适的离散“下一个值”概念**，官方未内置其范围类型，一般用离散类型或自定义 canonical。

# 包含界限与排除界限

每个边界可以是**包含（inclusive，`[` / `]`）** 或 **排除（exclusive，`(` / `)`）**：

```text
[low,high)   左闭右开（默认）
[low,high]   双闭
(low,high)   双开
(low,high]   左开右闭
```

为什么默认左闭右开 `[)`：

- 便于**相邻区间无缝拼接**、不重叠：`[1,10)` 和 `[10,20)` 正好相接。
- 空区间长度直观：`[5,5)` 是空，元素个数 = 上界 - 下界。

用 `lower_inc()` / `upper_inc()` 判断某端是否包含：

```sql
SELECT lower_inc('[1,10)'::int4range), upper_inc('[1,10)'::int4range);
-- true | false
```

# 无限（无界）范围

任何一侧边界都可以省略，表示**无界**（正/负无穷方向）：

```sql
SELECT '(-infinity,100)'::numrange;   -- 上界 100，下方向无界
SELECT '[5,)'::int4range;             -- 下界 5，上方向无界
SELECT '(,)'::int4range;              -- 全区间（两端无界）
```

- 数值/日期时间范围用 `-infinity` / `infinity` 关键字，或直接把边界留空。
- 用 `lower_inf()` / `upper_inf()` 判断某端是否无界。

# 空范围

范围可以**为空**（不含任何点）。空范围用字面量 `empty` 表示，且所有空范围彼此相等：

```sql
SELECT 'empty'::int4range;
SELECT isempty('empty'::int4range);        -- true
SELECT isempty('[5,3)'::int4range);         -- true（下界>上界会规范化为空）
```

空范围的上下界都是 NULL，`lower()`/`upper()` 返回 NULL。

# 范围输入/输出

外部文本形式：`[下界,上界)` 之类，边界值按元素类型的 I/O 规则解释，含特殊字符时给边界加双引号。例如：

```sql
SELECT '[3,4)'::int4range;
SELECT '("[a,b)", date, 2012-01-01]'::text; -- 具体转义视元素类型
```

输出时 PostgreSQL 会按默认 `[)` 规范化显示（若原本是双闭/双开且能等价表示，可能改写）。

# 构造范围和多范围

用 `range()` / 特定 `numrange()` 等构造函数：

```sql
SELECT range(1, 10);              -- [1,10)（通用 range()，PG14+，按参数推断类型）
SELECT int4range(1, 10);         -- [1,10)
SELECT numrange(1.1, 2.2, '[]');  -- 指定双闭
SELECT range(NULL, 100);         -- 下界无界
```

多范围用 `multirange()` 或 `'{...}'::int4multirange`：

```sql
SELECT multirange(int4range(1,5), int4range(10,15));  -- {[1,5),[10,15)}
-- 重叠的部分会自动合并
SELECT '{[1,3),[2,5)}'::int4multirange;   -- {[1,5)}
```

# 离散范围类型

整数、date 等是**离散**类型（相邻值之间有确定的“下一个”），而 numeric/timestamp 是**连续**的。离散范围有一个重要行为：

- PostgreSQL 会把**排除边界规范转换成等价的包含边界**表示。比如 int4range 的 `[1,10)` 会被规范化为 `[1,11]`？实际存储仍是等价形式，`lower`/`upper` 查询返回规范化后的值。
- 关键：对离散类型，`(1,10)`（双开）会被规范化为 `[2,10)` 等整数可表示的形式。
- 自定义离散范围类型应提供一个 **canonical 函数**，把任意边界组合规范化成统一形式，否则等值比较、索引去重会出现“语义相同但表示不同”。

```sql
-- 离散：[1,10) 实际包含整数 1..9
SELECT int4range(1, 10) @> 5;     -- true
SELECT int4range(1, 10) @> 10;    -- false（右开）
```

# 自定义范围：定义新的范围类型

用 `CREATE TYPE ... AS RANGE`，指定 `SUBTYPE`（元素类型）及可选边界包含默认、canonical：

```sql
CREATE TYPE floatrange AS RANGE (
    subtype = float8,
    subtype_diff = float8mi
);

SELECT '[1.23, 2.34]'::floatrange;
```

- `subtype_diff` 用于估算范围“大小”（影响并行扫描分片）。
- 离散类型可加 `canonical = ...` 指定规范化函数。

# 索引

- 范围类型可用 **GiST**（最常用，支持重叠/包含查询）、也支持 btree（按边界排序，用途有限）。
- 重叠、包含类查询走 GiST 才高效：

```sql
CREATE INDEX idx_booking ON booking USING GIST (during);

SELECT * FROM booking
WHERE during && tstzrange('2026-01-01', '2026-01-02');  -- 与某天有重叠
```

# 范围上的约束

范围最有杀伤力的用法：用 **`EXCLUDE USING gist`** 保证任意两行的范围**不重叠**：

```sql
CREATE TABLE booking (
    room    int,
    during  tstzrange,
    EXCLUDE USING gist (room WITH =, during WITH &&)
    -- 同一 room 的 during 不允许重叠
);
```

插入会重叠的时间段会直接报冲突。这是排期/预约/会议系统防双订的官方推荐做法，比在应用层加锁可靠得多。

也常用范围做 **CHECK 约束**：如版本号区间不得为空、必须左闭右开等。

# 常用操作符与函数

| 操作符/函数            | 含义                                |
|------------------------|-------------------------------------|
| `@>` / `<@`            | 包含（范围含值/范围，或范围含范围） |
| `&&`                   | 两范围是否重叠                      |
| `<<` / `>>`            | 严格在左 / 严格在右（不相邻也可）   |
| `&<` / `&>`            | 不向右/向左超过（重叠或在左/右）    |
| `-\|-`                 | 两范围是否相邻（不重叠但相接）      |
| `lower()`/`upper()`    | 取下界/上界                         |
| `lower_inc()`/...      | 边界是否包含                        |
| `lower_inf()`/...      | 边界是否无界                        |
| `isempty()`            | 是否为空范围                        |
| `range_merge()`        | 包含两范围的最小范围                |
| `lshift()`/`lsub()` 等 | 集合运算（差、并、交，多范围尤用）  |

具体函数参见 **[范围函数](../07.PostgreSQL%20内置函数/045.范围函数.md#概述)**。

# 实战 SQL

```sql
-- 预约表：时间段 + 防重叠
CREATE TABLE appointment (
    id      serial PRIMARY KEY,
    doctor  int NOT NULL,
    during  tstzrange NOT NULL,
    EXCLUDE USING gist (doctor WITH =, during WITH &&)
);

INSERT INTO appointment (doctor, during)
VALUES (1, tstzrange('2026-09-01 09:00', '2026-09-01 10:00'));

-- 查询某医生某天所有空闲：用多范围/求补集思路
SELECT lower(during) AS start, upper(during) AS end
FROM appointment
WHERE during @> tstzrange('2026-09-01 09:30', '2026-09-01 09:30');

-- 版本兼容范围：某配置适用的 [起始版本, 结束版本)
CREATE TABLE feature_flag (
    name       text,
    ver_range  int4range      -- 如 [20000, 24000) 表示 2.0.0 到 2.4.0 之前
);
SELECT * FROM feature_flag WHERE ver_range @> 22000;
```

# 最佳实践

1. **默认用左闭右开 `[)`** 表达区间，相邻拼接不重不漏。
2. **排期/预约防冲突直接用 `EXCLUDE USING gist (col WITH =, during WITH &&)`**，别在应用层拼 SQL 检查。
3. **时间范围优先 `tstzrange`（带时区）**，避免时区歧义。
4. **离散类型（整数）注意规范化行为**，做等值比较/索引时理解 `[1,10)` 与 `[1,11)` 的差异。
5. **自定义离散范围提供 canonical 函数**，保证语义相同的范围表示一致。
6. **多段不连续区间用多范围（multirange）**，而不是存多个范围行，天然去重叠、支持集合运算。
7. **重叠/包含查询列建 GiST 索引**，否则大表全扫。

# 常见坑

1. 默认 `[)` **右开**：`int4range(1,10) @> 10` 为 **false**，别按闭区间直觉判断。
2. 离散范围会**规范化边界表示**，`[1,10)` 与 `[1,11)` 在 int4range 下**不相等**（后者多含整数 10）。
3. 下界 > 上界的非空写法会被规范化为 **empty**，别以为存了个“反向区间”。
4. 空范围上下界都是 **NULL**，对 `lower()` 结果直接算术要小心 NULL 传染。
5. 无内置 `text`/`bytea` 范围类型——字符串“范围”多用于排序场景，一般不适合当区间。
6. **`EXCLUDE USING gist` 需要 GiST 索引支持**，元素类型得有对应 opclass，否则建表失败。
7. 多范围插入重叠区间会**自动合并**，若你本意是保留两段会被“吃掉”。
8. btree 对范围只按边界排序，**不能高效回答重叠查询**，别拿它代替 GiST。
9. 连续类型（numeric/timestamp）无 canonical 规范化，跨端包含/排除的等值比较要显式统一写法。

# 总结

- 范围类型表达“一段区间”，携带边界包含性与空/无界信息，默认左闭右开 `[)`。
- 杀手级用法：`EXCLUDE USING gist ... WITH &&` 一行防重叠，配 GiST 索引做重叠/包含检索。
- 离散类型注意边界规范化，多段区间用多范围；时间一律优先带时区的 `tstzrange`。
