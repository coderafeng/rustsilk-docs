# 概述

- PostgreSQL 支持把列定义为**变长多维数组**，元素可以是基础类型、枚举、复合类型、范围类型或域。
- 声明方式两种：`类型[]`（PostgreSQL 风格，如 `integer[]`）或 `ARRAY` 语法（SQL 标准，仅一维）。
- 声明里写的**大小和维度数会被忽略**，不影响运行时行为，仅作文档说明——同种元素类型的数组一律视为同一类型。
- 数组下标**默认从 1 开始**（不是 0！），支持切片 `lower:upper`。
- 两种写法构造值：字面量 `'{1,2,3}'` 和构造器 `ARRAY[1,2,3]`。
- **数组不是集合**：为搜索单个元素而反复拆数组，往往是数据库设计不当的信号，很多场景应改用关联表。

# 速查表

| 操作       | 写法                                              |
|------------|---------------------------------------------------|
| 声明列     | `pay integer[]` / `sched text[][]`                |
| 字面量     | 一维 `'{1,2,3}'`；二维见下文示例                    |
| 构造器     | `ARRAY[1,2,3]` / `ARRAY[['a','b'],['c','d']]`     |
| 取元素     | `arr[1]`（下标从 1 起）                           |
| 取切片     | `arr[1:2]`（含端点）                              |
| 拼接       | `ARRAY[1,2] \|\| ARRAY[3,4]`                       |
| 判包含     | `10000 = ANY (arr)` / `... = ALL (arr)`           |
| 判重叠     | `arr && ARRAY[10000]`                             |
| 展平       | `unnest(arr)`                                     |
| 聚合为数组 | `array_agg(col)`                                  |
| 维度信息   | `array_dims` / `array_length` / `cardinality`     |

# 数组类型的声明

```sql
CREATE TABLE sal_emp (
    name            text,
    pay_by_quarter  integer[],   -- 一维整数数组
    schedule        text[][]     -- 二维文本数组
);
```

在元素类型名后加 `[]` 即为数组。也可以声明大小：

```sql
CREATE TABLE tictactoe (
    squares integer[3][3]
);
```

> [!warning]
> 当前实现**忽略**任何大小和维度限制，行为等同于不写长度。声明里写 `integer[4]` 不会限制只能存 4 个元素。

符合 SQL 标准的 `ARRAY` 语法（仅一维）：

```sql
pay_by_quarter  integer ARRAY[4],   -- 大小仍被忽略
pay_by_quarter  integer ARRAY,      -- 不限长度
```

# 数组值输入

字面常量把元素放进花括号、逗号分隔（一般规则，`box` 用分号）：

```sql
'{{1,2,3},{4,5,6},{7,8,9}}'   -- 3x3 二维数组
```

元素设为 NULL 就写 `NULL`（任意大小写）；想要真正的字符串 `"NULL"` 必须加双引号。

```sql
INSERT INTO sal_emp VALUES ('Bill',
    '{10000, 10000, 10000, 10000}',
    '{{"meeting", "lunch"}, {"training", "presentation"}}');
```

也可用 `ARRAY` 构造器，元素是普通 SQL 常量/表达式（字符串用**单引号**）：

```sql
INSERT INTO sal_emp VALUES ('Bill',
    ARRAY[10000, 10000, 10000, 10000],
    ARRAY[['meeting', 'lunch'], ['training', 'presentation']]);
```

多维数组各子数组在每个维度上**长度必须匹配**，否则报 `malformed array literal`。

# 访问数组

单元素访问，下标写在方括号内，默认从 1 开始：

```sql
SELECT name FROM sal_emp WHERE pay_by_quarter[1] <> pay_by_quarter[2];

SELECT pay_by_quarter[3] FROM sal_emp;
```

子数组用切片 `lower-bound:upper-bound`：

```sql
SELECT schedule[1:2][1:1] FROM sal_emp WHERE name = 'Bill';
        schedule
------------------------
 {{meeting},{training}}
```

> [!caution]
> 只要**任一维度**写成切片（含冒号），**所有维度**都按切片处理——只写单个数字的维度会被当作 `1..该数字`。例如 `schedule[1:2][2]` 实际取的是 `[1:2][1:2]`。为避免混淆，建议所有维度都显式写切片。

- 边界可省略：`schedule[:2][2:]`，缺失边界用该维度下界/上界代替。
- 数组本身或任一下标为 NULL → 返回 NULL；**下标越界也返回 NULL 而非报错**。
- 切片越界返回空（零维）数组而非 NULL；部分重叠会静默缩到重叠区。

维度信息：

```sql
SELECT array_dims(schedule);     -- '[1:2][1:2]' 文本，便于人读
SELECT array_upper(schedule,1);  -- 某维上界
SELECT array_length(schedule,1); -- 某维长度
SELECT cardinality(schedule);    -- 所有维度元素总数（= unnest 行数）
```

# 修改数组

整体替换：

```sql
UPDATE sal_emp SET pay_by_quarter = '{25000,25000,27000,27000}' WHERE name = 'Carol';
UPDATE sal_emp SET pay_by_quarter = ARRAY[25000,25000,27000,27000] WHERE name = 'Carol';
```

改单个元素 / 改切片：

```sql
UPDATE sal_emp SET pay_by_quarter[4] = 15000 WHERE name = 'Bill';
UPDATE sal_emp SET pay_by_quarter[1:2] = '{27000,27000}' WHERE name = 'Carol';
```

给不存在的元素赋值会**扩展数组**，中间位置用 NULL 填充（扩展仅支持一维）；带下标赋值还能创建非 1 起始下标的数组（如 `myarray[-2:7]`）。

# 数组拼接

用 `||` 构造新数组：

```sql
SELECT ARRAY[1,2] || ARRAY[3,4];              -- {1,2,3,4}
SELECT ARRAY[5,6] || ARRAY[[1,2],[3,4]];      -- {{5,6},{1,2},{3,4}}
```

也可用函数 `array_prepend`（头插，仅一维）、`array_append`（尾插，仅一维）、`array_cat`（数组并接，支持多维）。

> [!warning]
> `||` 被重载，遇到未定类型字面量时解析器会假定它是**另一侧类型（数组）**，从而当 array_cat 处理，产生意外结果：
> ```sql
> SELECT ARRAY[1,2] || '7';    -- ERROR: malformed array literal
> SELECT ARRAY[1,2] || NULL;   -- {1,2}（NULL 被当空数组，而非追加一个 NULL）
> SELECT array_append(ARRAY[1,2], NULL);  -- {1,2,NULL} 这才是想要的
> ```
> 想追加单元素时，显式用 `array_append`/`array_prepend` 更安全。

# 在数组中搜索

已知大小可逐元素判断，但大数组应改用集合谓词：

```sql
-- 任一元素等于（存在）
SELECT * FROM sal_emp WHERE 10000 = ANY (pay_by_quarter);
-- 所有元素都等于
SELECT * FROM sal_emp WHERE 10000 = ALL (pay_by_quarter);
-- 重叠（&& 检查左右是否有公共元素）
SELECT * FROM sal_emp WHERE pay_by_quarter && ARRAY[10000];
-- 位置：首次出现下标 / 所有出现下标
SELECT array_position(ARRAY['sun','mon','tue'], 'mon');   -- 2
SELECT array_positions(ARRAY[1,4,3,1,3,4,2,1], 1);         -- {1,4,8}
```

`generate_subscripts` / `unnest` 可把数组按下标或元素展开成行，配合 WHERE 精确检索。

> [!note]
> 数组不是集合。若你经常需要搜索单个数组元素，这是**设计不当的信号**——通常应改用一个子表，让每个元素各占一行，检索更容易、可伸缩性更好。

# 数组输入和输出语法

- 外部文本表示 = 元素按各自类型的 I/O 规则 + 花括号 `{}` + 分隔符（默认逗号，由元素类型 `typdelim` 决定）。
- 元素值若为空串、含花括号/分隔符/双引号/反斜线/空白、或等于单词 `NULL`，输出时会被加双引号，内部引号/反斜线用 `\` 转义。
- 默认各维下界为 1；要表示其他下界，可在内容前写维度修饰 `[下界:上界]=...`：

```sql
SELECT '[1:1][-2:-1][3:5]={{{1,2,3},{4,5,6}}}'::int[] AS f1;
```

- 只有下界不都为 1 时，输出才带显式维度信息。
- `array_nulls` 设为 off 可禁止把 `NULL` 识别为 NULL（向后兼容 8.2 前）。

更多数组函数参见 **[数组函数](../07.PostgreSQL%20内置函数/020.数组函数.md#概述)**。

# 实战 SQL

```sql
-- 建表 + 构造
CREATE TABLE tags_demo (id serial, tags text[]);
INSERT INTO tags_demo (tags) VALUES (ARRAY['db','sql','pg']);
INSERT INTO tags_demo (tags) VALUES ('{java,kotlin}');

-- 是否包含某标签
SELECT * FROM tags_demo WHERE 'sql' = ANY (tags);

-- 两数组是否有交集
SELECT * FROM tags_demo WHERE tags && ARRAY['go','pg'];

-- 展平：每个标签一行
SELECT id, unnest(tags) AS tag FROM tags_demo;

-- 反向聚合：把多行聚成一个数组
SELECT array_agg(DISTINCT tags) FROM tags_demo;

-- 去重/排序元素
SELECT id, (SELECT array_agg(t ORDER BY t) FROM unnest(tags) t) FROM tags_demo;

-- 数组转文本便于展示
SELECT id, array_to_string(tags, ', ') FROM tags_demo;
```

# 最佳实践

1. **优先考虑关系模型**：需要频繁检索/连接的元素，用子表比数组更好扩展。
2. **数组适合“整体读、少按元素查”** 的固定小集合（如标签快照、坐标点）。
3. **构造值优先用 `ARRAY[...]` 构造器**，比手拼花括号字符串更不易错（尤其含特殊字符）。
4. **切片一律显式写 `1:2` 形式**，避免“单数字维度被当切片范围”的坑。
5. **给数组列检索建 GIN 索引**（`CREATE INDEX ... USING GIN (col)`，配合 `array_ops`），加速 `@>`/`&&`。
6. **需要半结构化又可能要按元素查询时，考虑 JSONB**，它常有更好的工具链。
7. **用 `cardinality`/`array_length` 判长度**，别用文本 `length()`。

# 常见坑

1. 声明里的**大小/维度限制不生效**，`integer[4]` 能存任意长度。
2. 数组下标**从 1 开始，不是 0**（jsonpath/其他语言的 0 基在这里不适用）。
3. 任一维度用切片会让**所有维度**变切片，`arr[1:2][2]` 里 `[2]` 被当 `[1:2]`。
4. **下标越界返回 NULL 不报错**，切片越界返回空数组，行为不一致（历史原因）。
5. 多维数组子数组维度不匹配会报 `malformed array literal`。
6. 元素里含逗号/花括号/引号/空白/等于 `NULL`，字面量必须加双引号转义。
7. `ARRAY[..] || NULL` 会把 NULL 当空数组，追加单个 NULL 元素要用 `array_append`。
8. `||` 对未定类型字面量的推断容易把“追加元素”误解成“拼接数组”。
9. 数组列不建合适的 GIN 索引，按元素检索会全表扫描。
10. 更新数组任意元素都会**重写整个数组值/整行**，频繁局部改大数组开销大。
11. 把数组当集合频繁搜索，是可伸缩性差的信号，应改子表。
12. `box` 等少数类型分隔符是分号 `;` 不是逗号，拼字面量时注意。

# 总结

- 数组支持变长多维，声明用 `类型[]`，构造优先 `ARRAY[...]`，下标从 1 起、支持切片。
- 大小/维度声明不强制；越界返回 NULL；切片会“传染”所有维度——这些是最常见的坑。
- 检索用 `ANY`/`ALL`/`&&`/`array_position` 并配 GIN 索引；但真要按元素频繁查询，优先考虑子表或 JSONB。
