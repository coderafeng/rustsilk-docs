# 概述

- PostgreSQL 内置了全文检索能力，核心是两个专用数据类型：
    - **tsvector**：以经过正规化、排序去重的“词位（lexeme）”形式表示**文档**。
    - **tsquery**：以布尔/邻近表达式形式表示**查询**。
- 全文检索的目标：在一堆自然语言文档中，找出最匹配某个查询的文档，并按相关度排序。
- tsvector/tsquery 只是**存储结构**，本身不做分词和正规化；真正把原始文本变成可检索数据，靠的是 `to_tsvector()`、`to_tsquery()` 等函数。
- 典型链路：原始文本 → `to_tsvector()` 正规化 → 存进 `tsvector` 列 → 用 `tsquery` 做 `@@` 匹配 → 用 `ts_rank()` 排序 → 用 `ts_headline()` 高亮。
- 中文场景原生支持较弱（默认按空格/标点切词），生产上常配合 `zhparser`、`pg_jieba` 等分词插件，或直接用 `pg_trgm` 做模糊匹配。

# 类型速查表

| 类型     | 表示对象 | 内部形式                       | 关键能力                         |
|----------|----------|--------------------------------|----------------------------------|
| tsvector | 文档     | 排序去重的词位 + 可选位置/权重 | 存储已正规化的可检索文档         |
| tsquery  | 查询     | 词位 + 布尔/邻近/前缀/权重操作 | 表达检索条件，与 tsvector 做 @@  |

一句话理解：

- tsvector 是“被搜的东西”，tsquery 是“搜的东西”。
- 两者用匹配操作符 `@@` 连接，返回 boolean。

# tsvector

tsvector 值是一个**排好序且互不重复**的词位列表。词位已经过正规化，以便把同一单词的不同变体合并。排序和去重在输入时自动完成：

```sql
SELECT 'a fat cat sat on a mat and ate a fat rat'::tsvector;
```

结果：

```text
                      tsvector
----------------------------------------------------
 'a' 'and' 'ate' 'cat' 'fat' 'mat' 'on' 'rat' 'sat'
```

注意：输入被当作**已经切好词**的词位序列，用空白分隔。若词位包含空白或标点，需用引号括起来：

```sql
SELECT $$the lexeme '    ' contains spaces$$::tsvector;
```

结果：

```text
                 tsvector
-------------------------------------------
 '    ' 'contains' 'lexeme' 'spaces' 'the'
```

这里用美元引用（`$$...$$`）只是为了避免在字符串里再套单引号。嵌入的引号和反斜线必须双写：

```sql
SELECT $$the lexeme 'Joe''s' contains a quote$$::tsvector;
```

结果：

```text
                    tsvector
------------------------------------------------
 'Joe''s' 'a' 'contains' 'lexeme' 'quote' 'the'
```

## 位置与权重

可以为词位附加整数形式的**位置**，用于邻近度匹配和排序：

```sql
SELECT 'a:1 fat:2 cat:3 sat:4 on:5 a:6 mat:7 and:8 ate:9 a:10 fat:11 rat:12'::tsvector;
```

结果：

```text
                                  tsvector
-------------------------------------------------------------------
 'a':1,6,10 'and':8 'ate':9 'cat':3 'fat':2,11 'mat':7 'on':5 'rat':12 'sat':4
```

规则：

- 位置取值范围 1 ~ 16383；更大的值会被静默设为 16383。
- 同一词位的重复位置会被丢弃。
- 带位置的词位还能附加权重标签 A、B、C、D，默认 D 不显示：

```sql
SELECT 'a:1A fat:2B,4C cat:5D'::tsvector;
```

结果：

```text
          tsvector
----------------------------
 'a':1A 'cat':5 'fat':2B,4C
```

权重通常用于反映文档结构，例如把**标题**里的词和**正文**里的词区分开，排序函数可给不同权重不同优先级。

## tsvector 不做正规化

必须认识到，tsvector 类型本身**不会执行任何词语正规化**，它假定输入词位已经按应用需求正规化：

```sql
SELECT 'The Fat Rats'::tsvector;
```

结果：

```text
      tsvector
--------------------
 'Fat' 'Rats' 'The'
```

对多数英文检索应用，上面的词还没小写化、没词干提取，但 tsvector 并不在意。原始文本通常应先经过 `to_tsvector()` 正规化：

```sql
SELECT to_tsvector('english', 'The Fat Rats');
```

结果：

```text
   to_tsvector
-----------------
 'fat':2 'rat':3
```

`to_tsvector` 会做：转小写 → 按词典切词 → 词干化（Rats→rat）→ 去停用词 → 记录位置和权重。

# tsquery

tsquery 存储要搜索的词位，并用操作符组合：

| 操作符     | 含义             | 说明                                    |
|------------|------------------|-----------------------------------------|
| `&`        | AND              | 同时包含                                |
| `\|`       | OR               | 包含其一                                |
| `!`        | NOT              | 排除                                    |
| `<->`      | FOLLOWED BY      | 相邻，等价 `<1>`                        |
| `<N>`      | FOLLOWED BY N    | 两词位之间距离为 N                      |
| `:*`       | 前缀匹配         | 词位后加 `*`，匹配以该前缀开头的词      |
| 权重字母   | 权重限制         | 如 `fat:ab`，只匹配 tsvector 中对应权重 |

绑定优先级（从高到低）：`!` → `<->`/`<N>` → `&` → `|`。可用圆括号强制分组。

示例：

```sql
SELECT 'fat & rat'::tsquery;
     tsquery
------------------
 'fat' & 'rat'

SELECT 'fat & (rat | cat)'::tsquery;
          tsquery
---------------------------
 'fat' & ( 'rat' | 'cat' )

SELECT 'fat & rat & ! cat'::tsquery;
        tsquery
------------------------
 'fat' & 'rat' & !'cat'
```

词位可带权重标签，限制只匹配 tsvector 中对应权重的词位：

```sql
SELECT 'fat:ab & cat'::tsquery;
     tsquery
------------------
 'fat':AB & 'cat'
```

词位可带 `*` 做前缀匹配：

```sql
SELECT 'super:*'::tsquery;
  tsquery
-----------
 'super':*
```

该查询会匹配 tsvector 中任何以 “super” 开头的词位。

## 用 to_tsquery 正规化查询

和 tsvector 一样，tsquery 需要的词语正规化必须在转成 tsquery 之前完成，`to_tsquery()` 正适合：

```sql
SELECT to_tsquery('Fat:ab & Cats');
    to_tsquery
------------------
 'fat':AB & 'cat'
```

`to_tsquery` 会像处理其他词一样对前缀词做词干化，因此下面比较返回真：

```sql
SELECT to_tsvector( 'postgraduate' ) @@ to_tsquery( 'postgres:*' );
 ?column?
----------
 t
```

因为 postgres 会被词干化为 postgr：

```sql
SELECT to_tsvector( 'postgraduate' ), to_tsquery( 'postgres:*' );
  to_tsvector  | to_tsquery
---------------+------------
 'postgradu':1 | 'postgr':*
```

因而它能匹配 postgraduate 词干化后的形式。

> [!warning]
> `to_tsquery` 要求输入是**严格合法**的查询语法，用户随手输入的关键词很可能触发语法错误。面向终端搜索框，应优先用 `plainto_tsquery()`（把普通文本按 AND 组合）或 `websearch_to_tsquery()`（支持引号短语、`or`、`-排除`，最贴近搜索引擎习惯）。

# 常用函数与操作符

| 函数/操作符                | 作用                                                       |
|----------------------------|------------------------------------------------------------|
| `to_tsvector(cfg, text)`   | 按全文检索配置把原始文本正规化为 tsvector                  |
| `to_tsquery(cfg, text)`    | 把严格查询语法解析为 tsquery（含正规化）                   |
| `plainto_tsquery()`        | 把普通文本按 AND 组合成 tsquery，容错性好                  |
| `phraseto_tsquery()`       | 把普通文本转成相邻（`<->`）匹配的 tsquery                  |
| `websearch_to_tsquery()`   | 支持引号短语、or、`-` 排除，适合搜索框输入                 |
| `@@`                       | tsvector 匹配 tsquery，返回 boolean                        |
| `@@@`                      | 与 `@@` 语义相同，但保证走索引（用于索引扫描约束）         |
| `ts_rank(tsvector,tsquery)`| 计算相关度得分（考虑词频、位置、权重）                     |
| `ts_rank_cd()`             | 覆盖密度（coverage density）排名，考虑词位邻近             |
| `ts_headline()`            | 在原文中高亮命中的词位                                     |
| `setweight()`              | 给 tsvector 的某部分设置权重，用于拼接标题/正文            |
| `length()` / `numnode()`   | tsvector 词位数 / tsquery 节点数                           |

具体函数细节参见 **[文本检索函数](../07.PostgreSQL%20内置函数/075.文本检索函数.md#概述)**。

# 实战 SQL

## 建表与检索配置

```sql
-- 查看系统内置的全文检索配置
SELECT cfgname FROM pg_ts_config;

-- 建一张文章表，用 tsvector 存检索向量
CREATE TABLE articles (
    id       serial PRIMARY KEY,
    title    text,
    body     text,
    -- 检索向量：标题用权重 A，正文用权重 B
    tsv tsvector GENERATED ALWAYS AS (
        setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
        setweight(to_tsvector('english', coalesce(body,   '')), 'B')
    ) STORED
);
```

## 写入与匹配

```sql
INSERT INTO articles(title, body) VALUES
('PostgreSQL indexing', 'PostgreSQL supports B-tree, GIN and GiST index types.');

-- 找出同时提到 postgresql 和 index 的文章
SELECT id, title
FROM articles
WHERE tsv @@ to_tsquery('english', 'postgres & index');
```

## 相关度排序 + 高亮

```sql
SELECT
    id,
    ts_rank(tsv, q)        AS rank,
    ts_headline('english', body, q) AS snippet
FROM articles, to_tsquery('english', 'index') q
WHERE tsv @@ q
ORDER BY rank DESC
LIMIT 10;
```

## 给检索列建 GIN 索引

```sql
CREATE INDEX idx_articles_tsv ON articles USING GIN (tsv);

-- 前缀/词频类查询可用 GIN；如需用 <2> 邻近操作符，需建 GiST 或带 tovector 的 GIN
```

> [!tip]
> 把 tsvector 直接建成 `GENERATED ... STORED` 列（如上面示例）或触发器维护的列，检索时才能命中索引；如果每次查询都现场 `to_tsvector(body)`，则无法用普通索引加速（只能建表达式索引）。

# 最佳实践

1. **文档列存 tsvector，而不是每次现算**。用生成列或触发器维护，配合 GIN 索引，检索才快。
2. **标题/正文分权重**。用 `setweight()` 把标题设为 A、正文设 B，让标题命中的文档排更前。
3. **搜索框入口用 `websearch_to_tsquery()`**，别用 `to_tsquery()`——后者对非法语法直接报错。
4. **合理选择 `ts_rank` 还是 `ts_rank_cd`**：关心词位邻近度用 `ts_rank_cd`。
5. **检索配置（regconfig）要和建库时一致**，写入用 `'english'`，查询也得用 `'english'`，否则词干化对不上。
6. **用生成列/触发器时把 NULL/空串 `coalesce` 兜底**，避免整个向量变 NULL。
7. **中文检索优先评估插件**（zhparser/pg_jieba），或用 `pg_trgm` + GIN 做相似度搜索，别硬用默认 parser。
8. **大文本考虑 `ts_headline(min_words, ...)` 控制片段长度**，避免高亮整篇拖慢响应。

# 常见坑

1. tsvector 直接输入 `'The Fat Rats'` **不会**小写/词干化，正规化必须靠 `to_tsvector()`。
2. `to_tsvector()` 会丢弃停用词（the/a 等），所以搜 “the” 往往命中为空，属正常。
3. `to_tsquery()` 语法严格，用户输入的 `&`、`!`、括号不配对会直接抛错。
4. 位置上限是 **16383**，超长文档超出部分位置被截断。
5. 权重字母 **D 是默认值，输出时不显示**，别误以为丢了权重。
6. 前缀匹配 `super:*` 的词也会先被词干化，`postgres:*` 实际匹配的是 `postgr:*`。
7. 没建 GIN/GiST 索引的大表做全文检索会**全表扫描**，性能极差。
8. 写入用一种 regconfig、查询用另一种，会出现“看着一样的词却搜不到”。
9. 邻近操作符 `<N>` 在部分索引类型下不被支持，需要 GiST 或特定 GIN 配置。
10. 默认 parser 对中文不分词，中文全文检索不能想当然直接用。
11. 用 `to_tsvector('english', col)` 现场计算做 WHERE，普通索引命中不了，得建表达式索引。
12. `@@` 与 `@@@` 混用：需要强制走索引扫描的场景才用 `@@@`，一般检索用 `@@`。

# 总结

- **tsvector 存文档、tsquery 存查询**，用 `@@` 做匹配。
- 类型本身不做正规化，正规化交给 `to_tsvector()` / `to_tsquery()`。
- 生产检索务必把向量落到 tsvector 列并建 **GIN 索引**，配合 `ts_rank` 排序、`ts_headline` 高亮。
- 面向用户输入用 `websearch_to_tsquery()`，中文场景优先评估分词插件或 `pg_trgm`。
