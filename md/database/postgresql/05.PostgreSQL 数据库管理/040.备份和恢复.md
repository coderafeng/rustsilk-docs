# 概述

备份与恢复是数据库管理中最关键的能力。PostgreSQL 的备份分为两大类：

- **逻辑备份**：把数据库对象与数据"翻译"成 SQL 语句（或可再解析的归档文件），与版本/平台解耦，可恢复到不同机器。工具：**pg_dump**（单库）、**pg_dumpall**（整个实例）。恢复用 **psql**（纯文本）或 **pg_restore**（归档）。
- **物理备份（基础备份）**：直接复制数据库的数据目录文件，速度快、可做时间点恢复（PITR），但与版本强相关。工具：**pg_basebackup**。

本章重点讲解最常用的逻辑备份三件套。

# pg_dump：导出单个数据库

**pg_dump** 把一个数据库的内容导出为转储文件，运行在操作系统 Shell 中：

```bash
# 导出为纯文本 SQL 脚本
pg_dump -U postgres sakila > sakila.sql

# 导出为自定义压缩归档（-F c），供 pg_restore 使用
pg_dump -U postgres -Fc sakila > sakila.dump
```

常用选项：

| 选项                  | 作用                                       |
|-----------------------|--------------------------------------------|
| **-h / -p / -U / -d** | 连接参数（同 psql）                        |
| **-F f**              | 纯文本格式（默认）                         |
| **-F c**              | 自定义二进制归档格式（压缩、可选择性恢复） |
| **-F d**              | 目录格式（并行恢复友好）                   |
| **-t 表名**           | 只导出指定表                               |
| **-n 架构名**         | 只导出指定 schema                          |
| **-f 文件**           | 输出到文件（代替重定向）                   |
| **--no-owner**        | 不导出 owner 信息（恢复到不同用户时常用）  |
| **--schema-only**     | 只导出结构不导数据                         |
| **--data-only**       | 只导出数据不导结构                         |

导出单张表：

```bash
pg_dump -U postgres -t film sakila > film_only.sql
```

# 恢复逻辑备份

## 恢复纯文本（psql）

纯文本转储（**-F f**）就是 SQL 脚本，直接用 **psql** 执行恢复：

```bash
# 先建目标库
psql -U postgres -c "CREATE DATABASE sakila_restored;"
# 导入
psql -U postgres -d sakila_restored -f sakila.sql
```

## 恢复归档（pg_restore）

自定义/目录格式（**-F c / -F d**）必须用 **pg_restore** 恢复：

```bash
pg_restore -U postgres -d sakila_restored sakila.dump
```

**pg_restore** 的常用选项：

| 选项                                | 作用                            |
|-------------------------------------|---------------------------------|
| **-d 数据库**                       | 直接恢复到指定库                |
| **-j 数量**                         | 并行恢复，加速                  |
| **-t 表名**                         | 只恢复指定表（选择性恢复）      |
| **--schema-only** / **--data-only** | 只恢复结构 / 数据               |
| **-l** / **-L**                     | 列出归档内容 / 按清单选择性恢复 |

先查看归档里都有什么，再决定恢复哪些对象：

```bash
pg_restore -l sakila.dump
```

# pg_dumpall：导出整个实例

**pg_dump** 只处理单个库，而实例级的**全局对象**（角色、表空间）以及所有数据库，需要用 **pg_dumpall**：

```bash
# 导出所有数据库 + 角色 + 表空间
pg_dumpall -U postgres > full_backup.sql
```

恢复整个实例（通常服务器为空时）：

```bash
psql -U postgres -f full_backup.sql
```

常见组合：**pg_dumpall --globals-only** 单独导出角色/权限，配合各库的 **pg_dump -Fc** 分别导出，兼顾灵活性与完整性。

# pg_basebackup：物理基础备份

物理备份直接复制数据文件，是**持续归档 / 时间点恢复（PITR）**和**搭建流复制副本**的基础。前提：服务器开启 **wal_level=replica** 且配置了相应 **pg_hba.conf** 复制权限。

```bash
pg_basebackup -U postgres -D /backup/base -Ft -z -Xs -P
```

选项含义：**-D** 输出目录，**-Ft** tar 格式，**-z** gzip 压缩，**-Xs** 一并流式拉取 WAL 日志，**-P** 显示进度。恢复时把备份解压回数据目录、配合 WAL 重放即可回到备份时刻（或结合归档恢复到任意时间点）。

方式对比：

| 维度             | 逻辑备份（pg_dump） | 物理备份（pg_basebackup） |
|------------------|---------------------|---------------------------|
| 内容             | SQL / 归档          | 数据目录文件              |
| 粒度             | 可选单表/单库       | 整个集群                  |
| 跨版本/平台      | 可以                | 不可以                    |
| 恢复灵活性       | 可选择性恢复        | 整库 + PITR               |
| 速度（大数据量） | 较慢                | 快                        |

# 实践建议

- **定期 + 自动化**：用 cron / 计划任务定时执行 pg_dump 或 pg_basebackup，并保留多份历史。
- **异地保存**：备份文件拷到与服务器不同的机器/对象存储。
- **验证可恢复**：定期在测试环境实际恢复一遍，未经演练的备份不可信。
- **配合 WAL 归档**：需要 PITR（恢复到任意时刻）时，配置 **archive_command** 做持续 WAL 归档。

# 总结

日常最常用的是逻辑备份：**pg_dump** 导出单库（纯文本用 **psql** 恢复，**-Fc** 归档用 **pg_restore** 恢复，可选择性/并行恢复），**pg_dumpall** 导出实例级全局对象与所有库；需要快速整库备份与时间点恢复时使用物理备份 **pg_basebackup**。生产环境务必做到定期、异地、并定期演练恢复。
