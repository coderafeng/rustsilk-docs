# 概述

除了对库内对象的操作，管理一个 PostgreSQL 实例还包括：**启停服务器进程**、**查看与修改运行参数**、以及理解几个关键配置文件。本篇介绍这些"实例级"管理动作（安装过程见 **[01.PostgreSQL 起步](../01.PostgreSQL%20起步/02.Windows系统安装PostgreSQL.md)**）。

# 数据目录与配置文件

一个 PostgreSQL **实例（cluster）** 由一个**数据目录**（**$PGDATA**）承载，其中既有数据文件，也有核心配置：

| 文件                                | 作用                                                 |
|-------------------------------------|------------------------------------------------------|
| **postgresql.conf**                 | 服务器主配置（内存、连接、WAL、autovacuum 等参数）   |
| **pg_hba.conf**                     | 客户端认证规则（谁能从哪、用什么方式连）             |
| **pg_ident.conf**                   | 操作系统用户到数据库角色的映射（配合 peer/map 认证） |
| **base/**、**global/**、**pg_wal/** | 数据库文件、全局对象、WAL 预写日志                   |

用 SQL 快速定位路径与关键文件位置：

```sql
SHOW data_directory;
SHOW config_file;
SHOW hba_file;
SHOW port;
```

# 启动与停止服务器

命令行工具 **pg_ctl** 用于手动管理服务器（需 **postgres** 系统用户、指定 **-D 数据目录**）：

```bash
# 启动（-l 日志文件，-w 等待完成）
pg_ctl -D /var/lib/pgsql/18/data -l server.log start

# 平滑关闭：等待客户端断开
pg_ctl -D .../data -m fast stop

# 立即关闭（可能触发崩溃恢复，慎用）
pg_ctl -D .../data -m immediate stop

# 查看状态 / 重启 / 重载配置
pg_ctl -D .../data status
pg_ctl -D .../data restart
pg_ctl -D .../data reload
```

关闭模式（**-m**）：**smart**（等所有连接自然结束）、**fast**（回滚活动事务后快速退出，最常用）、**immediate**（立刻中止，下次启动做恢复）。

生产环境通常交给系统服务管理：

```bash
# Linux（systemd）
systemctl start  postgresql-18
systemctl status postgresql-18
systemctl reload postgresql-18     # 重载配置，不中断连接

# Windows
net start  "postgresql-x64-18"
net stop   "postgresql-x64-18"
```

# 查看与修改运行参数

PostgreSQL 有大量运行时参数（GUC）。查看单个参数当前值：

```sql
SHOW shared_buffers;
SHOW work_mem;

-- 或查系统视图，附带来源、单位、是否可重载等信息
SELECT name, setting, unit, context, source
FROM pg_settings
WHERE name IN ('shared_buffers', 'max_connections', 'work_mem');
```

## 修改参数的三个层级

| 手段                          | 生效范围                                         | 是否持久 | 是否需要重启                                                    |
|-------------------------------|--------------------------------------------------|----------|-----------------------------------------------------------------|
| **postgresql.conf** + reload  | 整个实例                                         | 是       | 视参数而定（**sighup** 类只需 reload，**postmaster** 类需重启） |
| **ALTER SYSTEM SET**          | 整个实例（写入 postgresql.auto.conf，覆盖 conf） | 是       | 同上                                                            |
| **ALTER ROLE / DATABASE SET** | 某角色 / 某库                                    | 是       | 下次会话生效                                                    |
| **SET**（会话/事务级）        | 当前会话或事务                                   | 否       | 立即                                                            |

示例：

```sql
-- 实例级（写入 auto.conf，需 reload/重启才全面生效）
ALTER SYSTEM SET work_mem = '16MB';
SELECT pg_reload_conf();          -- 触发对 sighup 类参数的重载

-- 只让某库使用不同的维护内存
ALTER DATABASE sakila SET maintenance_work_mem = '512MB';

-- 当前会话临时调整，便于一次大批量操作
SET work_mem = '64MB';
```

判断参数改后是否需要重启，看 **pg_settings.context**：**postmaster** = 必须重启；**sighup** = reload 即可；**superuser/backend/user** = 会话级 **SET** 或新连接生效。

# 重载 vs 重启

- **reload（重载）**：不中断现有连接，让大部分参数重新读取。**pg_ctl reload**、**systemctl reload**、或 SQL **SELECT pg_reload_conf();** 效果一致。
- **restart（重启）**：真正关闭再启动，用于 **postmaster** 上下文参数（如 **shared_buffers**、**port**、**max_connections**）。

修改 **pg_hba.conf**（认证规则）后同样只需 **reload** 即可生效（见 **[重置密码](./050.重置密码.md)** 的认证说明）。

# 版本与运行状态

```sql
SELECT version();                       -- 完整版本信息
SHOW server_version;                     -- 语义化版本号
SELECT pg_is_in_recovery();              -- 是否处于恢复/只读副本状态
SELECT pg_postmaster_start_time();       -- 本次启动时间
SELECT now() - pg_postmaster_start_time() AS uptime;   -- 运行时长
```

# 大版本升级（pg_upgrade）

日常参数调整不涉及升级，但当需要从旧大版本（如 15）迁移到新版（如 18）时，因**系统目录/物理文件格式跨大版本不兼容**，不能只换二进制，必须做**升级迁移**。有两条路：

- **逻辑升级**：用 **[备份和恢复](./040.备份和恢复.md)** 的 **pg_dumpall / pg_dump** 从旧库导出，再导入新库。简单、可跨平台，但大数据量耗时较长。
- **原地升级**：用 **pg_upgrade** 直接复用旧数据文件，停机时间短（**--link** 模式几乎秒级完成，但要求新旧集群同一文件系统、且升级后不可回退旧库）。

**pg_upgrade** 典型流程：

```bash
# 1. 停新旧服务，确认新集群已用新二进制 initdb 初始化
# 2. 先跑 --check 做只读校验，不真正迁移
pg_upgrade --old-datadir /pg/15/data --new-datadir /pg/18/data \
           --old-bindir /usr/pgsql-15/bin --new-bindir /usr/pgsql-18/bin \
           --jobs 4 --link --check
# 3. 校验通过后去掉 --check 正式执行
pg_upgrade --old-datadir /pg/15/data --new-datadir /pg/18/data \
           --old-bindir /usr/pgsql-15/bin --new-bindir /usr/pgsql-18/bin \
           --jobs 4 --link
```

升级后按提示执行 **analyze_new_cluster.sh** 更新新库统计信息（否则计划不优），验证无误后执行 **delete_old_cluster.sh** 清理旧集群。务必先**完整备份**、在测试环境演练、关注扩展（如 PostGIS）是否有对应新版本。

# 总结

实例级管理围绕**数据目录**展开：**postgresql.conf / pg_hba.conf** 分别管参数与认证。用 **pg_ctl** 或系统服务（systemd / Windows 服务）启停，注意 smart/fast/immediate 三种关闭模式。参数用 **SHOW / pg_settings** 查看，按 **postgresql.conf、ALTER SYSTEM、ALTER ROLE/DATABASE、SET** 四个层级修改——**sighup** 类改后 **reload** 即可，**postmaster** 类需**重启**（由 **pg_settings.context** 判断）。
