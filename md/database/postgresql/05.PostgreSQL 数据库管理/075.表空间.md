# 概述

PostgreSQL 默认把所有数据文件存放在安装时指定的**数据目录（$PGDATA）**下。**表空间（tablespace）** 允许你把这个"存放位置"改到数据目录之外的任意磁盘目录，从而：

- 把大表 / 索引放到**更快（SSD / NVMe）或更大**的磁盘上；
- 把冷数据放到**廉价大盘**，做成本分层；
- 避免单个分区被数据撑满。

一个表空间只是一个"带路径的逻辑名字"，数据库、表、索引、大对象等都可以在创建时指定它。

# 内置表空间

每个实例默认有两个系统表空间：

| 名称           | 作用                                                                          |
|----------------|-------------------------------------------------------------------------------|
| **pg_default** | 未显式指定表空间时对象的默认落盘位置（模板库 **template0/template1** 也用它） |
| **pg_global**  | 存放跨库共享的系统目录（如 **pg_database**、**pg_authid** 等）                |

用 psql 元命令 **\db** 或查询 **pg_tablespace** 查看：

```text
postgres=# \db
             List of tablespaces
    Name    |  Owner   |    Location
------------+----------+----------------
 pg_default | postgres |
 pg_global  | postgres |
(2 rows)
```

# 创建表空间

```sql
CREATE TABLESPACE fastssd LOCATION '/data/pg_tbs/fastssd';
```

前置要求（否则会报错）：

- 路径必须是**已存在的绝对路径**（Windows 上是带盘符的绝对路径，且用正斜杠 `/` 或双反斜杠），并且 PostgreSQL **服务进程的运行用户**对该目录有读写权限。
- 该目录最好**为空**（新建的空目录即可，PostgreSQL 会在其下写入 `PG_VERSION` 等）。
- 创建者需**超级用户**，或拥有该位置的权限。

指定属主：

```sql
CREATE TABLESPACE slowdisk OWNER bob LOCATION '/data/pg_tbs/slowdisk';
```

授予使用权限（非属主默认不能用）：

```sql
GRANT CREATE ON TABLESPACE slowdisk TO alice;
```

# 使用表空间

创建对象时用 **TABLESPACE** 子句指定：

```sql
-- 整个库默认放 fastssd（新建表不加指定就落这里）
CREATE DATABASE appdb TABLESPACE fastssd;

-- 单表 / 索引单独指定
CREATE TABLE logs_2026 (...) TABLESPACE slowdisk;
CREATE INDEX idx_logs_ts ON logs_2026 (ts) TABLESPACE fastssd;
```

把已有对象移入表空间（会重写数据、持有锁，宜在维护窗口执行，参考 **[日常维护](./065.日常维护.md)**）：

```sql
ALTER TABLE logs_2026 SET TABLESPACE slowdisk;
ALTER INDEX idx_logs_ts SET TABLESPACE fastssd;   -- 索引移动代价小
```

改库默认表空间：

```sql
ALTER DATABASE appdb SET TABLESPACE fastssd;
```

> 注意：**移动分区表的父表**不会自动移动其分区子表，需逐个分区执行 **SET TABLESPACE**。

# 查看对象所在表空间

```sql
SELECT
    c.relname,
    t.spcname AS tablespace
FROM pg_class c
LEFT JOIN pg_tablespace t ON t.oid = c.reltablespace
WHERE c.relname = 'logs_2026';
```

- **reltablespace** 为 **NULL/0** 表示对象落在其**所属数据库的默认表空间**，而非"什么都没有"。
- **\d 表名** 的信息里也会显示索引/TOAST 的表空间；**\db+** 列出表空间及其大小、选项。

查看某表空间实际落盘路径（含 PostgreSQL 为其分配的编号子目录）：

```sql
SELECT pg_tablespace_location('fastssd');
```

# 删除表空间

```sql
DROP TABLESPACE slowdisk;
```

删除前必须保证：

- 该表空间中**没有任何数据库或对象**（否则报 `cannot drop tablespace because other objects depend on it`，先把它们 **SET TABLESPACE** 移走）。
- 没有数据库把它作为默认表空间。

DROP 只删除逻辑定义，**磁盘上 PostgreSQL 自建的那层带编号子目录会被清空**，但你手动创建的外层父目录不会被自动删除，需自行到 OS 层清理。

# 使用建议

- 表空间是**物理布局优化**手段，不是逻辑分区；只在确有 IO/容量分层需求时才引入，否则默认的 **pg_default** 足够。
- 备份/迁移时注意：**逻辑备份（pg_dump）** 会记录表空间名，恢复到没有同名表空间的实例时需映射（**pg_restore --tablespace** 或先建同名表空间）；**物理备份** 则必须保证路径一致。
- 复制（流复制）环境下，表空间的**物理路径在主备两侧都必须存在**，见 **[复制与高可用](./085.复制与高可用.md)**。

# 总结

表空间把数据库对象的存放位置从默认数据目录扩展到指定磁盘目录，用于性能与容量分层。核心操作：**CREATE TABLESPACE ... LOCATION**（路径须绝对、可写、属主权限）、建库/建表/建索引时用 **TABLESPACE** 指定、**ALTER ... SET TABLESPACE** 迁移已有对象、**DROP TABLESPACE** 前须清空对象。查看用 **\db** / **pg_tablespace** / **pg_tablespace_location()**。它是物理布局工具，跨环境备份恢复与复制时需保证路径/名称一致。
