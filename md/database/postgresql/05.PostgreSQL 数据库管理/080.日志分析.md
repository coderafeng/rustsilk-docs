# 概述

服务器日志是排查错误、审计访问、发现慢查询的第一手资料。PostgreSQL 的日志默认只记录错误与严重事件，**慢查询、连接、检查点等需要有意识地开启**。本篇讲清楚日志写到哪、用什么格式、以及运维最该关注的几个日志参数。

# 日志写到哪

关键参数（都在 **postgresql.conf**，改后按 **[服务器启停与配置](./070.服务器启停与配置.md)** 的方式 reload/重启）：

| 参数                         | 默认                           | 作用                                                                                       |
|------------------------------|--------------------------------|--------------------------------------------------------------------------------------------|
| **logging_collector**        | off                            | 是否由服务器进程收集日志到文件（开启后才能用下面基于文件的设置）                           |
| **log_destination**          | stderr                         | 输出目标：**stderr**、**csvlog**、**jsonlog**、**syslog**、**eventlog**（Windows），可组合 |
| **log_directory**            | log                            | 日志目录（相对 $PGDATA 或绝对路径）                                                        |
| **log_filename**             | postgresql-%Y-%m-%d_%H%M%S.log | 文件名模板，含时间宏，配合轮转生成新文件                                                   |
| **log_truncate_on_rotation** | off                            | 轮转时是否覆盖同名文件                                                                     |
| **log_rotation_age**         | 1d                             | 到时间就轮转（0 关闭）                                                                     |
| **log_rotation_size**        | 10MB                           | 到大小就轮转（0 关闭）                                                                     |

典型的生产配置——开启文件收集、按天轮转、保留固定文件名便于切割：

```ini
logging_collector = on
log_destination = 'csvlog'
log_directory = 'log'
log_filename = 'postgresql-%a.log'      # %a = 星期缩写，7 个文件循环
log_truncate_on_rotation = on
log_rotation_age = 1d
log_rotation_size = 0
```

> **stderr** 灵活但需自行收集；**csvlog / jsonlog** 结构化、便于程序解析；**syslog / eventlog** 交给系统统一日志管理。

# 记录什么：最该关注的日志参数

| 参数                                         | 建议值         | 作用                                                                  |
|----------------------------------------------|----------------|-----------------------------------------------------------------------|
| **log_min_duration_statement**               | `1000`（毫秒） | 记录执行超过该时长的语句；**0** 记录全部、**-1** 关闭 —— 抓慢查询首选 |
| **log_statement**                            | `ddl`          | 记录哪类语句：**none / ddl / mod / all**；审计建表/改结构用 **ddl**   |
| **log_checkpoints**                          | on             | 记录检查点，排查 IO 抖动很有用                                        |
| **log_lock_waits**                           | on             | 等待锁超时（**deadlock_timeout**）后记录，定位阻塞                    |
| **log_connections** / **log_disconnections** | on             | 记录连接/断开，审计与安全分析                                         |
| **log_line_prefix**                          | 见下           | 每行日志的前缀字段                                                    |

## log_line_prefix

控制每行日志携带的上下文，常用宏：

```ini
log_line_prefix = '%m [%p] %q%u@%d '
```

- **%m**：带毫秒的时间戳；**%p**：进程号；**%u**：用户名；**%d**：数据库名；**%r**：客户端地址与端口；**%q**：仅后台进程输出分隔（不产生额外字符）。

# 查看与分析日志

## 在 SQL 里读取当前日志

**pg_current_logfile()** 返回当前正在写的日志文件路径：

```sql
SELECT pg_current_logfile();
SELECT pg_current_logfile('stderr');   -- 指定 log_destination
```

## 用扩展表函数读取日志文件

开启 **file_fdw** 后，可把 **csvlog** 当表来 SQL 查询（详见生态/扩展章节）；或简单些——用 **pg_read_file()** / **pg_read_binary_file()**（仅超级用户）读取 **log_directory** 下的文件：

```sql
-- 读当前日志最后若干行做快速巡检
SELECT pg_read_file(pg_current_logfile()) IS NOT NULL AS log_readable;
```

## 用 psql 抓慢查询

开启 **log_min_duration_statement** 后，慢语句会连同耗时写入日志，直接到 **log/** 目录里检索：

```bash
grep -i "duration:" log/postgresql-*.log | sort -t: -k2 -n | tail
```

日志里典型的一行：

```text
2026-09-23 10:12:33.482 UTC [5140] LOG:  duration: 4823.117 ms  statement: SELECT ...
```

# 自动记录执行计划：auto_explain

想看慢查询**实际走了什么计划**，加载 **auto_explain** 扩展（需在 **shared_preload_libraries** 中预加载，改后重启）：

```ini
shared_preload_libraries = 'auto_explain'
auto_explain.log_min_duration = '1s'    # 超 1s 的语句自动 EXPLAIN 到日志
auto_explain.log_analyze = on           # 含实际执行统计（有额外开销，谨慎）
```

之后每条超时语句的执行计划会被写入日志，与 **[EXPLAIN](./045.EXPLAIN.md)** 联动定位问题。

# 总结

生产环境应先开启 **logging_collector** 并选定 **log_destination**（文件类用 csvlog/jsonlog 便于解析），再按需要调低 **log_min_duration_statement** 抓慢查询、**log_statement=ddl** 审计结构变更、打开 **log_checkpoints / log_lock_waits / log_connections** 辅助排障，并用 **log_line_prefix** 带上时间/用户/库上下文。巡检时用 **pg_current_logfile()** 定位文件、`grep "duration:"` 找慢语句；要自动落执行计划则预加载 **auto_explain**。
