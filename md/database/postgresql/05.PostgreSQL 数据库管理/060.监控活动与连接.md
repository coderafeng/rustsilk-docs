# 概述

运行中的 PostgreSQL 会维护一批**统计与活动视图**，让管理员能实时看到：谁连接了、在跑什么 SQL、是否卡住或在等锁、事务持续多久等。核心的动态系统视图是 **pg_stat_activity**。配合 **pg_cancel_backend()** / **pg_terminate_backend()** 还能取消或切断问题连接。

# pg_stat_activity：当前连接与活动查询

**pg_stat_activity** 每一行代表一个后端进程（连接/服务器进程）。查看当前所有连接：

```sql
SELECT
    pid,
    usename,
    datname,
    state,
    query
FROM pg_stat_activity
ORDER BY backend_start;
```

```text
  pid  |  usename | datname | state     | query
-------+----------+---------+-----------+------------------------------------
  4312 | postgres | postgres| idle      | SELECT 1;
  5021 | alice    | sakila  | active    | SELECT * FROM film WHERE title = 'X';
  5140 | bob      | sakila  | idle txn  | INSERT INTO rental ...
```

关键字段：

| 字段                             | 含义                                                                                                          |
|----------------------------------|---------------------------------------------------------------------------------------------------------------|
| **pid**                          | 后端进程号，取消/终止连接时用它                                                                               |
| **usename / datname**            | 登录用户 / 目标数据库                                                                                         |
| **state**                        | 连接状态：**active**（执行中）、**idle**（空闲）、**idle in transaction**（开着事务）、**idle in timeout** 等 |
| **query**                        | 当前（或最后一条）SQL                                                                                         |
| **query_start**                  | 当前语句开始时间                                                                                              |
| **xact_start**                   | 当前事务开始时间                                                                                              |
| **wait_event_type / wait_event** | 正在等待的事件（锁、IO 等）                                                                                   |
| **backend_type**                 | 进程类型：**client backend**、**autovacuum worker**、**checkpointer** 等                                      |

> **idle in transaction** 长期存在往往意味着应用忘记提交/回滚事务，会导致膨胀与锁持有，需要重点排查。

# 排查慢查询与长事务

找出执行超过某时长、仍在 active 的查询：

```sql
SELECT
    pid,
    usename,
    now() - query_start  AS running_for,
    state,
    query
FROM pg_stat_activity
WHERE state = 'active'
  AND now() - query_start > interval '5 seconds'
  AND pid <> pg_backend_pid()      -- 排除自己
ORDER BY running_for DESC;
```

查找长时间未提交的空闲事务：

```sql
SELECT pid, usename, now() - xact_start AS xact_age, query
FROM pg_stat_activity
WHERE state = 'idle in transaction'
  AND now() - xact_start > interval '10 minutes'
ORDER BY xact_age DESC;
```

# 取消与终止连接

| 函数                          | 作用                                         |
|-------------------------------|----------------------------------------------|
| **pg_cancel_backend(pid)**    | 取消该后端**当前正在执行的查询**，但保留连接 |
| **pg_terminate_backend(pid)** | 直接**终止整个连接**（后端进程退出）         |

```sql
-- 先礼貌取消
SELECT pg_cancel_backend(5021);

-- 仍不响应则强制断开
SELECT pg_terminate_backend(5021);
```

批量踢掉某库的所有非本会话连接（例如删库/维护前）：

```sql
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE datname = 'sakila'
  AND pid <> pg_backend_pid();
```

> 需要超级用户或同角色成员权限才能取消/终止他人会话；对本会话自己随时可用。

# 锁与阻塞排查

当查询卡在 **active** 且 **wait_event_type = 'Lock'** 时，多半是被别的会话阻塞。用 **pg_locks** 关联定位等待链：

```sql
SELECT
    blocked.pid                       AS blocked_pid,
    blocked.query                     AS blocked_query,
    blocking.pid                      AS blocking_pid,
    blocking.query                    AS blocking_query
FROM pg_stat_activity blocked
JOIN pg_locks   bl ON bl.pid      = blocked.pid AND NOT bl.granted
JOIN pg_locks   gl ON gl.locktype = bl.locktype
                  AND gl.database IS NOT DISTINCT FROM bl.database
                  AND gl.relation IS NOT DISTINCT FROM bl.relation
                  AND gl.pid <> bl.pid AND gl.granted
JOIN pg_stat_activity blocking ON blocking.pid = gl.pid;
```

找到 **blocking_pid** 后，若确认是可牺牲的会话，用 **pg_terminate_backend(blocking_pid)** 解除阻塞。更细的锁与事务隔离原理见 **[事务](../03.PostgreSQL%20数据库和表/115.事务.md)**。

# 其它常用统计视图

| 视图                                              | 用途                                                                                            |
|---------------------------------------------------|-------------------------------------------------------------------------------------------------|
| **pg_stat_database**                              | 每库的提交/回滚数、死锁数、块读写、临时文件等累计统计                                           |
| **pg_stat_user_tables** / **pg_stat_all_tables**  | 每表的读写、顺序/索引扫描、死元组、上次 autovacuum 时间（见 **[查看空间](./020.查看空间.md)**） |
| **pg_stat_activity**                              | 实时连接与活动（本篇）                                                                          |
| **pg_stat_progress_copy / create_index / vacuum** | 长任务（导入、建索引、清理）的进度                                                              |

查看某库累计统计（自上次重置以来）：

```sql
SELECT datname, xact_commit, xact_rollback, deadlocks, temp_files
FROM pg_stat_database
WHERE datname = 'sakila';
```

用 **pg_stat_reset()** 或 **pg_stat_reset_shared('database')** 可清零统计，便于观测一段时间内的增量。

# 总结

**pg_stat_activity** 是运行期观测的核心：看谁连了、在跑什么、事务开了多久、卡在哪个等待事件。用 **query_start / xact_start** 定位慢查询与长事务，用 **pg_cancel_backend()** / **pg_terminate_backend()** 处置问题会话，用 **pg_locks** 关联找出阻塞源。配合 **pg_stat_database**、**pg_stat_user_tables** 等累计统计视图，即可覆盖日常连接与活动监控需求。
