# 概述

监控数据库和表占用的磁盘空间，是容量规划、性能排查和清理膨胀的常见需求。PostgreSQL 提供了一组 **空间管理函数**（以 `pg_size_*` 系列和 **pg_relation_size** 为代表）来查询这些信息。

由于这些函数返回的是**字节数（bigint）**，可读性差，通常需要配合 **pg_size_pretty()** 把字节数转换为人类可读的 **kB / MB / GB** 形式。

# pg_size_pretty 函数

**pg_size_pretty(bytes)** 把一个字节数转换成带单位的字符串：

```sql
SELECT pg_size_pretty(123456789);
```

```text
 pg_size_pretty
----------------
 120 MB
(1 row)
```

它本身不查询任何对象，只负责"格式化"。真正取大小要靠下面的函数。

# 查看数据库大小

**pg_database_size(数据库名)** 返回整个数据库占用的字节数：

```sql
SELECT
    datname,
    pg_size_pretty(pg_database_size(datname)) AS size
FROM pg_database
ORDER BY pg_database_size(datname) DESC;
```

```text
  datname  |  size
-----------+---------
 sakila    | 33 MB
 postgres  | 7976 kB
 template1 | 7976 kB
 template0 | 7920 kB
(4 rows)
```

也可以使用 **pg_database_size(current_database())** 查看当前连接的数据库大小。

# 查看表 / 索引大小

针对单个关系（表、索引、TOAST 等），PostgreSQL 提供粒度不同的几个函数：

| 函数                            | 返回内容                                                            |
|---------------------------------|---------------------------------------------------------------------|
| **pg_relation_size(rel)**       | 表**主数据文件**本身的大小（不含索引、TOAST）                       |
| **pg_total_relation_size(rel)** | 表的**总大小** = 主数据 + 所有索引 + TOAST（含 TOAST 索引），最常用 |
| **pg_indexes_size(rel)**        | 表上所有索引的总大小                                                |
| **pg_table_size(rel)**          | 表大小（含 TOAST，不含索引）                                        |

查看 **film** 表的数据大小与总大小：

```sql
SELECT
    pg_size_pretty(pg_relation_size('film')) AS data_size,
    pg_size_pretty(pg_total_relation_size('film')) AS total_size;
```

```text
 data_size | total_size
-----------+------------
 448 kB    | 536 kB
(1 row)
```

# 列出所有表的大小

把 **pg_class** 系统目录与大小函数结合，可列出当前库中占用空间最大的表：

```sql
SELECT
    relname AS table_name,
    pg_size_pretty(pg_total_relation_size(relid)) AS total_size
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC
LIMIT 10;
```

```text
   table_name   | total_size
----------------+------------
 rental         | 2680 kB
 payment_p2007_ | ...
 film           | 536 kB
 customer       | 240 kB
 ...
(10 rows)
```

> **pg_statio_user_tables** 是一个视图，只包含当前用户拥有的普通表。若要包含所有 schema 的表，可用 **pg_stat_user_tables** 或 **pg_class** 加过滤条件。

# 使用 \dt+ 快速查看

psql 元命令 **\dt+** 会在列出表的同时，显示每张表（含索引与 TOAST）的大小、描述等信息，是最省事的查看方式：

```text
sakila=# \dt+
                                        List of relations
 Schema |    Name     | Type  |  Owner   | Persistence | Access method |  Size   | Description
--------+-------------+-------+----------+-------------+---------------+---------+-------------
 public | actor       | table | postgres | permanent   | heap          | 48 kB   |
 public | film        | table | postgres | permanent   | heap          | 536 kB  |
 public | inventory   | table | postgres | permanent   | heap          | 16 kB   |
 public | rental      | table | postgres | permanent   | heap          | 128 kB  |
 ...
```

对应的，**\l+** 显示各数据库大小，**\di+** 显示各索引大小。

# 排查表膨胀

频繁 **UPDATE** / **DELETE** 会产生死元组（dead tuples），使表文件比实际数据大（**膨胀**）。可通过对比总大小与估算的"净"数据，或查看死元组统计来判断：

```sql
SELECT
    relname,
    n_live_tup,
    n_dead_tup,
    last_autovacuum
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC
LIMIT 5;
```

当 **n_dead_tup** 很高时，可执行 **VACUUM (FULL, ANALYZE) 表名;** 回收空间（**FULL** 会重写表并持有排他锁，需在维护窗口执行），普通 **VACUUM** 只标记可复用而不缩小文件。有关事务与 **VACUUM** 的更多细节见 **[事务](../03.PostgreSQL%20数据库和表/115.事务.md)**。

# 总结

查看空间的核心是 **pg_size_pretty()** 配合 **pg_database_size()**（整库）、**pg_relation_size()**（表数据）、**pg_total_relation_size()**（表总量含索引）。快速场景可直接用 **\l+** / **\dt+** / **\di+** 元命令。结合 **pg_stat_user_tables** 的死元组统计，还能进一步定位表膨胀问题。
