# 概述

PostgreSQL 用 **角色（role）** 这一个概念同时表示"用户"和"组"：能用于登录的角色称为**用户**，不能登录、仅用于聚合权限的角色称为**组（group）**。**用户与权限管理**就是围绕角色的创建/删除，以及权限的授予（**GRANT**）/ 回收（**REVOKE**）展开。

> 与 **[重置密码](./050.重置密码.md)** 的关系：本篇管理"账号本身与能做什么"，密码只是角色的一个属性，改密见重置密码篇。

# 角色与用户

在 PostgreSQL 中，**CREATE USER** 等价于 **CREATE ROLE ... LOGIN**，**DROP USER** 等价于 **DROP ROLE**。两者的唯一区别就是是否默认带 **LOGIN** 属性。

## 创建角色 / 用户

```sql
-- 创建一个可登录、带密码的用户
CREATE ROLE alice LOGIN PASSWORD 'Alice#2026';

-- 等价写法
CREATE USER bob WITH PASSWORD 'Bob#2026' VALID UNTIL '2027-06-30';
```

常用属性：

| 属性                              | 含义                           |
|-----------------------------------|--------------------------------|
| **LOGIN** / **NOLOGIN**           | 是否允许登录（组通常 NOLOGIN） |
| **SUPERUSER** / **NOSUPERUSER**   | 是否超级用户（谨慎授予）       |
| **CREATEDB** / **NOCREATEDB**     | 是否可创建数据库               |
| **CREATEROLE** / **NOCREATEROLE** | 是否可创建/管理其他角色        |
| **REPLICATION**                   | 是否可发起流复制               |
| **CONNECTION LIMIT n**            | 最大并发连接数（-1 不限）      |
| **VALID UNTIL 'ts'**              | 密码/登录有效期                |
| **INHERIT** / **NOINHERIT**       | 是否自动继承所属组的权限       |

## 修改与删除

```sql
ALTER ROLE alice CREATEDB;            -- 追加重命名/改属性
ALTER ROLE bob WITH CONNECTION LIMIT 5;
DROP ROLE carol;                       -- 删除角色（需先处理其拥有的对象与默认权限）
```

## 查看现有角色

psql 元命令 **\du** 或查询 **pg_roles**：

```text
postgres=# \du
                             List of roles
 Role name |                         Attributes
-----------+------------------------------------------------------------
 alice     |
 bob       | CreateDB
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
```

# 权限 GRANT / REVOKE

对象（库、schema、表、序列、函数等）的权限通过 **GRANT** 授予、**REVOKE** 回收。

## 表级权限

表级常用权限有 **SELECT、INSERT、UPDATE、DELETE、TRUNCATE、REFERENCES、TRIGGER**。

```sql
-- 把 film 表的查询权限授予 alice
GRANT SELECT ON TABLE film TO alice;

-- 把多个权限授予某个组
GRANT SELECT, INSERT, UPDATE ON rental TO hr_group;

-- 回收
REVOKE INSERT, UPDATE ON rental FROM hr_group;

-- 授予 schema 内所有未来建的表（默认权限）
ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT SELECT ON TABLES TO readonly_group;
```

## 其它对象层级

| 对象        | 可授予的典型权限               | 示例                                                  |
|-------------|--------------------------------|-------------------------------------------------------|
| 数据库      | **CONNECT、CREATE、TEMPORARY** | `GRANT CONNECT ON DATABASE sakila TO alice;`          |
| 架构 schema | **CREATE、USAGE**              | `GRANT USAGE ON SCHEMA public TO bob;`                |
| 序列        | **USAGE、SELECT、UPDATE**      | `GRANT USAGE, SELECT ON SEQUENCE film_id_seq TO bob;` |
| 函数        | **EXECUTE**                    | `GRANT EXECUTE ON FUNCTION f_x() TO bob;`             |

## 授予与继承

把角色作为成员加入组（组通常 **NOLOGIN**）：

```sql
GRANT readonly_group TO alice;   -- alice 成为 readonly_group 成员
```

若成员带 **INHERIT**（默认），会自动继承所属组被授予的权限；否则需 **SET ROLE** 显式切换。

# 查看权限

- psql 元命令：**\dp**（列出表/视图/序列的权限）、**\du+**（角色属性）。
- SQL 查询标准视图 **information_schema.table_privileges**：

```sql
SELECT grantee, privilege_type
FROM information_schema.table_privileges
WHERE table_name = 'film';
```

- 系统函数 **has_table_privilege(角色, 表, 权限)** 返回布尔，便于程序判断：

```sql
SELECT has_table_privilege('alice', 'film', 'SELECT');
```

```text
 has_table_privilege
---------------------
 t
(1 row)
```

# 最小权限实践

- 用**组**统一管理权限，把用户加入组，而非逐个用户授权。
- 生产账号遵循**最小权限**：只读报表账号仅授 **SELECT**，不授 SUPERUSER。
- 谨慎使用 **GRANT ALL**，尤其对 **public** 角色（默认对新对象开放部分权限，可用 **REVOKE ALL ON SCHEMA public FROM PUBLIC** 收紧）。
- **WITH GRANT OPTION** 允许被授权者再转授，慎用。

# 总结

PostgreSQL 用 **角色（role）** 统一表示用户与组，**CREATE USER = CREATE ROLE LOGIN**。权限用 **GRANT / REVOKE** 在数据库、schema、表、序列、函数等层级授予或回收，把角色作成员授予可实现基于组的授权，**INHERIT** 决定是否自动继承。查看权限用 **\dp** / **\du** 或 **information_schema.table_privileges**、**has_table_privilege()**。生产环境应遵循最小权限与基于组的授权原则。
