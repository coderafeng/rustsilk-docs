# 概述

PostgreSQL 用 **角色（role）** 统一管理用户与权限，登录密码就是角色的一项属性。**重置密码**（修改用户登录密码）有两种主流方式：psql 元命令 **\password**（交互式、加密更安全）和 SQL 语句 **ALTER ROLE ... PASSWORD**。

# 使用 \password（推荐）

**\password 角色名** 是 psql 元命令，会提示你**两次输入新密码**，输入过程不回显，并由客户端用当前推荐的加密方式（如 **scram-sha-256**）哈希后再发送到服务器：

```text
postgres=# \password alice
Enter new password:
Enter it again:
postgres=#
```

优点：

- 密码不会以明文出现在屏幕、命令历史或日志里。
- 加密方式跟随服务器参数 **password_encryption**，自动采用安全算法。

# 使用 ALTER ROLE ... PASSWORD

用 SQL 语句直接设置密码：

```sql
ALTER ROLE alice PASSWORD 'NewSecret123';
```

对已登录用户本人，也可用 **CURRENT_USER**：

```sql
ALTER ROLE CURRENT_USER PASSWORD 'MyNewPass';
```

执行改密的主体必须是该角色的 owner，或拥有 **CREATEROLE** / 超级用户权限。

> 安全提示：**ALTER ROLE ... PASSWORD '明文'** 会把明文写在命令行里，可能残留在 Shell 历史、服务器日志、**pg_stat_activity** 的当前查询中。**ALTER ROLE** 的明文密码在语句执行时会被服务器按 **password_encryption** 设定的算法（现代默认 **scram-sha-256**）加密后再存入目录，数据库里存的是哈希，但**语句传输与记录环节仍有明文风险**。因此交互式改密优先用 **\password**。

# CREATE ROLE 时设置密码

创建新角色时可直接指定密码：

```sql
CREATE ROLE bob LOGIN PASSWORD 'BobPass123';
```

其中 **LOGIN** 表示该角色可用于登录（相当于"用户"）。关于角色的更多权限属性，见 **[架构](../03.PostgreSQL%20数据库和表/120.架构.md)** 与用户/权限相关章节。

# 查看与验证

密码本身以哈希存储，无法查看明文。只有超级用户能查询系统表 **pg_authid** 确认某角色是否设置了密码及其哈希前缀（据此判断加密方式）：

```sql
SELECT rolname,
       CASE WHEN passwd IS NULL THEN 'no password'
            WHEN passwd LIKE 'SCRAM%' THEN 'scram-sha-256'
            WHEN passwd LIKE 'md5%'   THEN 'md5'
            ELSE 'other' END AS password_type
FROM pg_authid
WHERE rolname = 'alice';
```

> **pg_roles** 视图出于安全会隐去密码列；只有 **pg_authid** 保存 **passwd** 哈希，且仅超级用户可读。普通用户验证改密是否生效，最直接的办法是**断开后用新密码重连**。

实际验证改密是否生效：断开后用新密码重新连接：

```bash
psql -U alice -d sakila -W
```

**-W** 强制提示输入密码，能连上即说明新密码生效。

# 关联：认证方式（pg_hba.conf）

密码改对仍连不上，往往是**服务端认证方式**问题。**pg_hba.conf** 决定连接采用 **md5**、**scram-sha-256**、**trust**、**password**（明文）等哪种方式。若服务器配置为 **scram-sha-256** 而旧密码以 **md5** 存储，需重新设置一次密码让新哈希生效（用 **\password** 或 **ALTER ROLE** 重设即可）。

修改 **pg_hba.conf** 后需重载配置：

```sql
SELECT pg_reload_conf();
```

# 总结

重置密码优先用交互式 **\password 角色名**（明文不落历史、自动采用安全加密），脚本或建角色时用 **ALTER ROLE ... PASSWORD** / **CREATE ROLE ... PASSWORD**。密码在库中以哈希保存、不可查看，改密后应重连验证；若认证失败还需检查 **pg_hba.conf** 的认证方式是否匹配。
